## Apply and test

From a clean checkout at the pinned revision, with `PACKAGE` pointing to the
extracted delivery:

```sh
git apply --check "$PACKAGE/integration.patch"
git apply "$PACKAGE/integration.patch"
cd Topology/UnknotRecognition/fast
python -B -m unittest discover -s tests -p 'test_sector_envelope*.py' -v
```

The focused suite contains 24 tests and needs only Python's standard library.
The broader repository suite can be run with:

```sh
python -B -m unittest discover -s tests -v
```

Some broader tests require optional dependencies and the full repository
reference assets. The retained broad run passed 1,334 tests before the last
three focused tests were added. The final focused run passed all 24 tests;
the two counts overlap.

Before integration, `python reproduce.py` in the extracted delivery provides
a quicker independent check without changing a repository. Its additional
audit and benchmark flags write fresh files under `reproduction/`.

## API examples

For complete enumeration without a portable coverage certificate:

```python
from fastunknot.normal_sector import enumerate_sector

rays, stats = enumerate_sector(
    triangulation,
    allowed_types,
    phase="standard",
    method="envelope",
    max_bases=None,
)
```

`allowed_types` contains at most one pair `(tetrahedron, quadrilateral_type)`
per tetrahedron. The matching kernel after those restrictions must have
dimension at most two. The feasible nonnegative cone may nevertheless be
empty or one-dimensional; both cases are supported.

To produce and independently replay a complete-enumeration certificate:

```python
from fastunknot.sector_envelope_certificate import certify_sector_enumeration
from fastunknot.sector_envelope_verify import verify_sector_envelope_certificate

answer = certify_sector_enumeration(
    triangulation, allowed_types, max_rays=None
)
if answer["status"] == "COMPLETE":
    assert verify_sector_envelope_certificate(
        triangulation, answer["certificate"]
    )
    rays = answer["coordinates"]
```

The low-level `sector_envelope_plan` exposes the exact affine section and
minimum switches for research use. It is a producer, not an independent
verifier. The coverage verifier reconstructs matching data and checks the
supplied dimension, section, slope brackets, envelope pieces and full ray
list without importing the sector/envelope producers.

For a supplied-sector disc query using the new enumeration path:

```python
from fastunknot.normal_sector import discover_in_sector

answer = discover_in_sector(
    triangulation,
    allowed_types,
    phase="standard",
    method="envelope",
)
```

That interface retains its existing topology and restricted-exhaustion
semantics. Positive Euler characteristic alone is never an essential-disc
verdict. A failure to find a disc in the supplied sector is not a knot
verdict.

## Limits and certificate semantics

The `envelope` method applies only to `phase='standard'`; the quadrilateral
phase and the previous automatic method selection retain their existing
behavior. Higher matching nullity raises `ValueError` rather than silently
switching to an unproved approximation.

For the ray iterator, `max_bases` counts begun candidate lifts. The new path
has one such candidate per actual output ray. Exhaustion raises
`SearchLimit`. Callers must discard any completeness interpretation of a
partial iteration. For the certificate producer, `max_rays` exhaustion
returns `INCONCLUSIVE` with no partial completeness certificate. These
allowances do not count bit operations or guarantee a wall-clock deadline;
use the cooperative `check` callback where cancellation is needed.

The certificate concerns the exact supplied triangulation and compatible
quadrilateral sector. It proves the complete nonlink standard-ray list in
that sector. It does not itself prove surface connectedness, essentiality,
the origin of the triangulation from a diagram, or a global unknot verdict.
The additional essential-disc example is checked with the maintained
independent normal-disc certificate verifier.

All new geometry interfaces share the maintained finite-manifold and
normal-coordinate validator. The envelope verifier deliberately uses its
own uncontracted matching-graph model. These are executable certificates
and written mathematical proofs, not a proof-assistant formalization.
