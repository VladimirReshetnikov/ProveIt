# Integration gate

Recommended target: a new research-report directory under `Topology/UnknotRecognition/reports/`, with a report number assigned during intake. Do not overwrite maintained modules with this package. The exact source pin is in `SOURCE_AUDIT.md`.

## What the adapter does

`native_adapter.py` contains a tested record translator and an **unexecuted native end-to-end seam**. `propose_geometry` is intended for an already source-authenticated normal-cut geometry. With both this package and the native `Topology/UnknotRecognition/fast` directory on `PYTHONPATH`, it imports the existing native functions, authenticates baseline dual endpoint records through native replay, fixes the native zero/one forest, builds unsigned counts, searches for a tree, and sends the proposed native v1 dual proof to the independent native replayer.

It returns `local-yes` only with replayer-produced reduced geometry. This still does not replace core, port, passive-pattern, or whole-cut verification. A successful raw core schedule may change the surviving disk system. The maintained source-derived matrix illustrates this explicitly: the delivered pivot schedule leaves source column 7; another recorded valid schedule leaves column 5.

`local-no` is not a topology verdict. `unknown` is the safe result when search is capped or a native prerequisite cannot be validated. Resource callback exceptions propagate. The branch cap does not bound parsing or every preprocessing instruction.

## Required native work before a default change

Reconcile this article with the two incoming dual-forest reports. Import the record translator on the actual pinned source core outputs. Run the full maintained unit suite and all old proof replay, not only new fixtures. Export real `(matrix, dual_endpoints)` data and record the exceptional row count `b`. Compare identical complete source queries, including passive witness behavior, native source checking, certificate bytes or semantic equivalence, and fallback behavior.

Keep a successful existing route first. On a tiny dual graph, bounded literal trials can be faster than the general FPT solver. The supplied benchmark's five-row source matrix makes this a measured issue, not speculation. The polynomial pair-column case is the natural first opt-in target. A general FPT route should remain explicitly budgeted until native query distributions are measured.

No native patch is auto-applied. The surrounding native package was not present for runtime validation here. Record-level tests are in `tests/test_adapter.py`; they do not claim a simulated record is an authenticated manifold source.
