# Data and measurement provenance

The article's performance tables and plots are generated by
`../tools/render_results.py` from the following authoritative records:

| Record | Used for |
|---|---|
| `paired_benchmarks.json` | Original factorization A/A/B/B experiment; only its factorization rows are used in the final article |
| `paired_benchmarks_final.json` | Final sparse Alexander and full-pipeline experiments after resource/counter audit fixes |
| `reduced_benchmark_final.json` | Final direct reduced versus ordinary scanning experiment, with exact pre-run snapshots |
| `benchmark_summary.csv` | Convenient generated summary of those selected results |

`reduced_benchmark.json` is the earlier prototype measurement. It records that
the prototype was not snapshotted before that original run and that individual
randomized job orders were not retained. Its original result rows and raw
timings are preserved. The final run removes the source-version ambiguity.

The other non-factorization rows in `paired_benchmarks.json` are retained
initial results. The later sparse/pipeline run supersedes them for display
because the audit changed a counter and resource handling. Its package source
hashes were captured before timing; copies were preserved afterward by
matching those hashes. `benchmark_sources/` contains the relevant source
snapshots. Baseline source is separately preserved in `../baseline/fast/`.

The final paired block ratio uses arithmetic arm means, while the pointed
block ratio uses geometric arm means. Read each file's protocol. A/A controls
and raw samples are retained; uncertainty intervals are conditional on the
stated measurement assumptions and fixed inputs.

## Correctness records

- `factorization_validation.json` combines the initial exhaustive exploration
  with a rerun of the integrated factorization. Its embedded exploratory
  timing section is explicitly labeled exploratory and is not the source
  of the article's paired factorization timings.
- `reduced_validation.json` records independent dense-cube comparison,
  basepoint/order variations, decision checks, and cache comparisons.
- `frontier_counterexamples.json` retains the exact matching supports,
  Laurent coefficients, modular specializations, and independent gluing checks.
- `hierarchy_budget_audit.json` records finite directed-graph and sequence
  audits of the sharp suffix-work formula.
- `unit_tests.txt` and `unit_test_summary.json` record the final complete
  69-test regression run.
- `cli_validation.json` records eight integration cases and package metadata.
- `article_validation.json` records the final PDF/LaTeX checks.
- `package_verification.json` records archived-source and isolated-patch checks.
- `upstream_files.json` lists all 40 byte-verified archived Git blobs.

Diagram counts are not counts of distinct knot types. Scan variants overlap;
for example the 5,052 basepoint/order scans are included in the total 8,002
rank scans. Some cache comparisons reuse already counted scans.

Regeneration commands in the top-level README use `reproduced_*` filenames
to preserve the published records. The `SHA256SUMS` manifest describes the
delivered files, so intentionally editing or rebuilding a file can change
its delivery hash without implying a mathematical error.
