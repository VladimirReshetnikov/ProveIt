# Integration proposal

## Suggested first landing

Keep the package initially under
`Topology/UnknotRecognition/fast/nonlinear_activation_research/`, preserving its
standalone imports and reproduction entry point. The article can become a new
numbered report after maintainer review. This avoids changing the maintained
recognizer's semantics as a side effect of importing research artifacts.

The primitive consumes the same finite sparse graph/matrix schema as the
incoming dual-forest research. The relevant eventual call site follows
`normal_cut_parallelity` geometry and the fixed lower forest, with data derived
from `fastunknot.core_handlebody`, the incoming source cap compiler, and
`bundle_boundary_kernel`'s complete finite boundary relations.

## Source adapter obligations

1. Reconstruct the authenticated triangulation/normal cut and record the lower
   forest. The theorem does not optimize that lower forest.
2. Assign one dense row per original surviving two-handle and added finite
   annular relation. Retain the inverse map to native IDs.
3. Use the actual two cap ends, including the exterior root. Keep a loop as
   a loop; use `None` for an unavailable interface row. Never invent a cap for
   an annular relation.
4. Keep actual unsigned occurrence counts. Do not replace them with exponent
   sums or cap them before input authentication and parity checking.
5. Include every finite boundary relation in the intended completion criterion.
   A source-core-only result is weaker than a whole-boundary result.
6. Call the chosen producer, then its independent verifier. Map a verified tree
   to a rooted top cancellation order and the trace to native leaf pivots.
7. Replay through the geometric source-relative checker and retain all required
   marked boundary data before the hierarchy uses the result.

The source data and relative charts, not the finite matrix alone, establish
the topological meaning of these moves.

## Dispatch and statuses

The paired benchmark favors keeping inexpensive native BFS/maximum-weight
choices and the incumbent stopping search. `bounded_prefix.py` supplies a
concrete alternative once the finite matrix is available: at most `m+1`
incumbent nodes, then output-only FPT. Each node has polynomial work, so this
prefix preserves the proved FPT bound. This allowance is an initial design
choice, not a performance optimum.

`verify_prefix.py` checks the outer original-count digest and dispatches the
nested complete result to an independent checker. A consumer must explicitly
call it; the producer does not validate itself. The wrapper makes no
wall-time speedup claim.

- `SUCCESS`: use only after both finite replay and the relevant source-relative
  geometric replay.
- `NO_FOREST`: close this fixed raw search route. Continue other legitimate
  recognition or hierarchy routes.
- `INCONCLUSIVE`: continue according to the existing resource/refusal semantics.

The unbounded mathematical decision algorithm is complete. A Python recursion
limit or supplied work cap can make a concrete run inconclusive.

## Adoption gates

The delivered finite checks and saved-certificate replay are complete. Before
changing maintained defaults, review the row/port adapter on current source
charts, run the existing whole-cut/marked-boundary gates, and benchmark the
bounded dispatcher on a wider independently selected corpus. The current
corpus supplies no evidence of new knot-recognition coverage.

The weighted theorem is ready for a separate implementation project. Prefer
an objective with a proved relationship to transport work; raw passage count
is only a surrogate. Single-exponential parameter dependence, certified
matroidal closure, joint lower/upper forest optimization, and geometric
control of residual nonlinear columns are further research targets.
