# Integration and acceptance gates

## Placement and files

This is an additive report package, not a patch to maintained runtime modules.
Follow the repository's current `docs/incoming/README.md` convention: strip the
archive wrapper when appropriate, place it under the next report number, retain
LF endings, and add the report index entry. The delivery does not guess the next
number in a changing repository. No checksum-only manifest is included.

The reference module name is `signed_continuations`. Its public entry points are
in `core.py`, `verify.py`, `patchwork.py`, and `codec.py`. The typed mesh problem is
specified in the article and in `PatchSystem` / `SeamPair`. It does not import
Regina or the maintained `fast` tree.

## What the existing source already supplies

At the inspected pin, synthesis chapters describe source-checked canonical
compact exteriors, weighted component / compressing-disk queries, and a
restricted primitive-cocycle seed family. Preserve these results and their
independent source checks. The new code does not replace them and does not claim
to have rerun their evidence.

## Required source adapter contract

Before forming a candidate row from a native object, independently establish:

1. Every declared seam is a homogeneous connected arc or circle in one surface
   component, with a well-defined transported local orientation frame.
2. Every component that may matter to future assembly has a live seam; components
   closing off are either rejected or handled by a separate proved terminal rule.
3. Every witness is source-bound to the intended validated knot exterior, and
   Euler charges and any torus boundary charges have unique cell ownership.
4. All candidates in one geometry key have exactly the same legal continuations,
   including quadrilateral compatibility, cyclic embedding data, seam maps and
   boundary restrictions not expressed by the signed state.
5. The retained family is a subset of actual admissible witnesses. Linear row
   combinations are certificates of representation, not geometric sum surfaces.

A sparse component-incidence histogram alone is insufficient. One old interval
port may meet many components; a signature with one label per port requires a
homogeneity/refinement theorem. Refinement size must enter the cost bound.

## A safe native rollout

Start with an opt-in stage on a source-certified restricted input class. Preserve
the existing exact fallback. Independently replay returned positive witnesses
using native source binding and the essential-boundary test. A failure to obtain
a disk in an incomplete candidate family is inconclusive about the knot, never
`KNOTTED`. Resource exceptions are likewise inconclusive.

A complete negative-answer certificate needs the complete source option system,
its coverage proof and the complete representative computation. The supplied
`verify_witness` only verifies one chosen assembly; it deliberately does not
certify absence from the input family.

## Acceptance experiments not executed in this delivery

Compare both routes on actual source-bound normal fragments, including one-sided
controls, cyclic-order changes, inessential disks, cancelling boundary classes,
huge normal multiplicities and known primitive-cocycle misses. Then compare full
recognition calls with all source construction, option generation, geometry,
row preprocessing, witness replay and fallback costs included. Run the current
maintained suite, not an old README test count, against the integration commit.

A general complexity claim additionally needs a complete production theorem and
bounds on the total input systems, geometry keys, numerical bits and live width.
The paper's composition theorem identifies these obligations explicitly.
