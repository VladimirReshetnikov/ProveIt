# Unknot recognition: exact baseline and partial hierarchy kernels

**The requested `n^O(log n)` worst-case guarantee is NOT established by this
archive.** This is a partial implementation effort, not a completed implementation
of Lackenby's quasipolynomial algorithm. Its complete recognition engine is an
exact **exponential-time** reduced-Khovanov algorithm. Every recognition result
includes `"quasipolynomial_guarantee": false`.

The archive contains usable code, not pseudocode with unimplemented topology
oracles. The mathematical report explains correctness of the implemented parts,
their actual complexity, the relationship to the supplied slides, and the
specific geometric constructions still needed.

## Run immediately

Python 3.10 or later; no third-party runtime or test dependencies. Tested here
with Python 3.13.5 on Linux. From the extracted directory:

```sh
python -m unknot_recognition recognize examples/trefoil.json
python -m unknot_recognition recognize examples/torus_3_5.json --check-d2
python -m unknot_recognition recognize examples/hard_unknot.json --check-d2
python -m unittest discover -s tests -v
```

The examples give `NONTRIVIAL`, `NONTRIVIAL`, and `UNKNOT`, respectively. The
second has determinant one and therefore exercises the complete homology
fallback. The third does not simplify completely using the implemented local
moves. Its independent braid-theoretic unknot proof is in the report.

Optional conventional installation:

```sh
python -m pip install .
unknot-recognition recognize examples/figure_eight.json
```

The build uses setuptools. Running directly with `python -m` needs neither
installation nor network access.

## Recognition API and guarantees

```python
from unknot_recognition import braid_closure, recognize

knot = braid_closure(3, [1, 2] * 5)
answer = recognize(knot, check_d_squared=True)
assert answer["status"] == "NONTRIVIAL"
assert answer["determinant"] == 1
assert answer["khovanov"]["total_rank"] == 7
assert answer["quasipolynomial_guarantee"] is False
```

The default pipeline validates a **classical one-component** diagram, performs
checked crossing-decreasing Reidemeister I/II moves, rejects determinant values
other than one, and otherwise computes total reduced Khovanov homology over F2.
The final step is a decision procedure, using the Kronheimer–Mrowka
unknot-detection theorem and the universal coefficient theorem. It does not
assume that the determinant or Jones polynomial detects the unknot.

With no resource caps, the mathematical algorithm terminates on every valid
finite knot diagram. Its general bound is `2^O(n)` bit operations and exponential
memory, after input normalization. It will be impractical for sufficiently large
or difficult diagrams. It is not designed as a high-performance replacement for
established topology software. Optional limits return **UNKNOWN**, never an
inferred knot verdict:

```sh
python -m unknot_recognition recognize examples/torus_3_5.json --max-resolutions 16
```

Exit codes: `0` for a completed result, including either knot verdict; `2` for
invalid input or an I/O failure; `3` for a resource-limited `UNKNOWN`; `4` for a
failed internal mathematical consistency check. A memory failure is not a
nontriviality certificate. User interrupts are not converted to decisions.

`--no-reduce --no-determinant` bypasses preprocessing. `--check-d2` exhaustively
checks the complex identity `d*d=0`, at additional computational cost.
`--output result.json` saves the complete result. A filename of `-` reads JSON
from standard input.

## Input conventions

Braid input uses Artin generators. Positive `i` means the left strand crosses
**over** the right strand at positions `i,i+1`:

```json
{"braid": {"strands": 2, "word": [1, 1, 1]}}
```

Alternatively, a planar diagram has one four-entry row per crossing:

```json
{"pd": [[0, 1, 2, 3], [3, 2, 4, 5], [5, 4, 1, 0]]}
```

Each row is counterclockwise. Positions **0 and 2 are under**; positions **1 and
3 are over**. Each integer edge label occurs exactly twice. Labels are normalized
internally. The rotation system, rather than only the abstract graph, must be
spherical. The diagram must have exactly one link component. An empty `pd` means
**one crossing-free unknot**, not the empty link. Do not import PD data with a
different crossing convention without converting it. `examples/trefoil_pd.json`
is generated by the included braid converter and is a canonical test input.

The interface does not read images, Gauss words, DT codes, links, or virtual knots.
For a knot braid closure the number of strands is at most the word length plus
one; impossible large empty braid declarations are rejected before allocation.

## Hierarchy components

These are independent kernels, **not** a complete hierarchy recognizer:

```sh
python -m unknot_recognition pattern examples/pattern_tetrahedron.json
python -m unknot_recognition pattern examples/pattern_prism.json
python -m unknot_recognition normal examples/solid_torus.json
```

`pattern.py` decides essentiality of a spherical cubic multigraph pattern on
the boundary of a **known 3-ball**. It handles loops, parallel edges, disconnected
components, and vertex-free circle components. It enumerates bonds of size at
most three in polynomial time and returns a checked dual-cycle witness when
applicable. It neither recognizes balls nor validates an entire three-dimensional
hierarchy. A pattern graph by itself proves nothing about an arbitrary knot.

`normal.py` validates ordinary finite simplicial orientable 3-manifolds, computes
a rational H1/cohomology dimension and an integral representative basis for H^1,
and constructs cocycle-dual normal coordinates without expanding the disks. It
checks matching and quadrilateral equations and computes Euler characteristic.
It does **not** claim an integral lattice basis, connected surfaces, a bounded
genus, a diagram-to-exterior conversion, generalized/ideal triangulation support,
or a compressed cutting/normalization algorithm. Connectedness is explicitly
reported as not computed.

`accounting.py` checks the finite-digit hierarchy potential and the numerical
Cheeger inequality. These numerical checks do not construct Cheeger regions or
prove a depth bound for actual hierarchies.

## Traces, tests, and evidence

Reidemeister reductions are independently replayable by the local-move verifier:

```sh
python -m unknot_recognition recognize examples/curl.json --output result.json
python -m unknot_recognition verify-reductions examples/curl.json result.json
```

This verifies only the reduction trace, not all fields in a saved JSON document.
Homology ranks can be recomputed but are not packaged as a separate succinct
proof certificate. No Lean formalization or external knot-package comparison
was performed.

`results/tests.txt` records **58 passing test methods**. They include 50 seeded
random braid cases, `d*d=0`, mirror/basepoint/Markov/braid-relation checks, exact
linear algebra comparisons, illegal input rejection, false-certificate rejection,
resource limits, boundary patterns, and normal-coordinate consistency.

The additional experiment exhausts **682** two-strand words of odd length at
most nine. Their closures are determined independently by their exponent sums.
It also constructs normal coordinates representing `3 * 2^400` disks using only
1263 coordinate payload bits. No disk expansion or connectedness test is used.

```sh
python scripts/experiments.py
```

This regenerates `results/experiments.json` and takes roughly 25 seconds in the
tested environment. Timings are illustrative, not evidence of a quasipolynomial
bound. The report contains the precise mathematical complexity argument.

## Contents and remaining work

`docs/report.pdf` and `docs/report.tex` contain the mathematical implementation
report. `docs/notes_audit.md` maps the slides to implemented and missing work.
`docs/SOURCES.md` gives primary-source references, including the July 2026
hierarchy paper checked during this task. `examples/` and `results/` contain
runnable inputs and actual outputs.

The missing parts include the compressed patterned-handle representation and
cutting operations, bounded-complexity hierarchical multi-surfaces, geometric
Cheeger-region processing, Haken/weak-reduction routines, and the combined
bit-complexity proof. Neither an exponential fallback, a user-supplied depth
number, nor a time cap fills these gaps.
