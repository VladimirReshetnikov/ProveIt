# Presentations, early rank certificates, and suffix responses

This research continuation starts from ProveIt commit
`1be2abc8cc743c1a3b5cb7fdfeb650697f8e2d5b`. It adds three optional research
interfaces and one inherited subprocess correction. The existing recognizer
does not automatically select the new interfaces. A general quasi-polynomial
unknot recognition bound remains unproved.

The companion article, **Toward Quasi-Polynomial Unknot Recognition:
Presentation Complexity, Early Certificates, and Streaming Responses**,
contains the complete proofs, literature comparisons, measured results, and
research questions. The distribution places its source and PDF
in `article/`. For repository integration, copy that directory's contents to
`Topology/UnknotRecognition/research/presentations_early_certificates/`.
The main source is `unknot_presentations_and_early_certificates.tex`.

The integrated test run completed **728 tests in 125.353 seconds, with three
optional tests skipped**. After the public generic-presentation interface was
hardened, all ten SU(2) tests were rerun and passed. The distribution includes
the original logs and environment record. Older counts below the notice in
the main README describe earlier continuations.

## What is new

| Area | Mathematical result | Implementation and scope |
| --- | --- | --- |
| SU(2) presentations | Explicit presentation complexity `poly(N+r) * (L+2)^{O(r+N/L)}`, optimized to `poly(N+r) * (2+N/r)^{O(r)}`; a corresponding cut-and-degree bound for compressed word circuits | Exact integer polynomial compilers, checked diagram-derived presentations, and an optional exact real solver |
| First jets | A two-layer binary matrix obtains the post-cancellation multiplicity before executing scalar Gaussian elimination; multiplicity one has the required all-classical-completion rank equivalence | A bounded observer inside a separate raw, total-rank-only scanner; selected examples reject earlier, while many cases incur overhead |
| Reverse suffix responses | Every suffix response can be prepared in `O(n * (W+1)^2)` field operations for maximum dart frontier `W`, including signed and singular interiors | A standalone iterator and collecting API with exact modular queries and explicit geometric checks; no knot verdict is produced |

The article distinguishes proved parameterized bounds from implementation
timings. In particular, the optional NLSAT backend is not claimed to attain
the stated asymptotic real-algebraic decision bound. Low-width Gaussian
elimination is established prior work; the suffix contribution is its
singular-safe use with the changing black-face geometry and retained responses.

## SU(2): representation queries and knot decisions

`fastunknot.su2` supports explicit relator chunks and compressed word circuits.
For `r` generators and total explicit relator length `N`, increasing the chunk
size reduces auxiliary quaternion variables and increases polynomial degree.
The article accounts for dense construction cost and coefficient heights. For
a supplied circuit cut retaining `t` gates and expanded degree at most `d`, the
bound is `poly(input size) * (d+2)^{O(r+t)}`. A verified polynomial-size
presentation and cut satisfying `(r+t) * log(d+2) = O(log(n)^2)` would therefore
give quasi-polynomial recognition on that family. No universal presentation
or cut construction is proved. The article also gives knot-group rank
obstructions to universal compression of the entire group.

The generic public constructor always uses the commutator inequality. It
accepts an arbitrary finite group presentation and returns a representation
query. Unequal images of arbitrary generators do not certify nonabelianity.
Only constructors deriving consistently oriented conjugate meridians from a
validated diagram use the lower-degree meridional condition and common trace.
There is no public `meridional=True` switch on `compile_presentation`.

```python
from fastunknot.su2 import compile_presentation, solve_formula

# The trefoil relation aba = bab, supplied only as a group presentation.
formula = compile_presentation(
    [1, 2], [(1, 2, 1, -2, -1, -2)], chunk_size=3
)
print(formula.summary())
query = solve_formula(formula, seconds=1.0)
print(query["status"])  # NONABELIAN, NO_NONABELIAN, or INCONCLUSIVE
```

The validated diagram interface supplies the provenance needed for a knot
decision:

```python
from fastunknot.diagram import Diagram
from fastunknot.su2 import su2_decide

diagram = Diagram.from_braid(3, [1, -2, 1, -2])
answer = su2_decide(
    diagram, presentation="tietze", seconds=1.0, trace_zero_probe=True
)
print(answer["status"])  # KNOTTED, UNKNOT, or INCONCLUSIVE
```

The `presentation` choices are `bridge`, `tietze`, and `wirtinger`.
The compiler has `max_terms`, `max_work`, and a cooperative `check` callback;
`su2_decide` returns `INCONCLUSIVE` on its local resource exhaustion.
`compile_slp` accepts a `WordArena`, relator roots, and an `inline_degree`
threshold for retaining product gates. Generic circuit queries also carry
no automatic knot provenance.

The optional backend is Z3 NLSAT using exact real algebra. Missing Z3,
timeouts, and unknown solver results are unresolved. The trace-zero flag is
implemented as a one-sided witness probe: if it fails, the complete formula
still runs within the remaining allowance. SAT models retain exact algebraic
expressions and are checked using the same backend; UNSAT is a trusted solver
result, with no independent proof checker supplied. The stronger fixed-meridian
specialization proved in the article is not installed by this flag.

The standalone CLI accepts `--presentation`, `--chunk-size`, `--seconds`,
`--trace-zero-probe`, `--smt2`, and `--compile-only`:

```bash
python3 -m fastunknot.su2 input.json --presentation tietze \
  --smt2 query.smt2 --compile-only
```

The recorded randomized audit has 96 solver queries on 48 sampled entries
(38 distinct PD diagrams): 90 complete, correct answers and six unresolved
queries. Independent finite-group counts agree across the three presentations
on 36 sampled entries (26 distinct PD diagrams). These are finite cross-checks,
not an independent UNSAT proof system or a full-recognizer performance claim.

## First jets: bounded observation before cancellation

For a bounded free same-matching block with `N` objects, let `A` be its scalar
differential and `B` its total linear dot coefficient over the binary field.
The observer computes

```text
t     = N - 2 * rank(A)
kappa = N - rank([[A, 0], [B, A]])
```

The calculation leaves the state intact. The proofs establish contractibility
for `kappa = 0`, primitive interval rigidity and all-classical-completion rank
equivalence for `kappa = 1`, and the appropriate rank multiplier for an actual
knot completion. Applicability requires the algebraic and geometric contracts
in the article; an arbitrary linear quiver or an arbitrary terminal partition
does not supply all of them.

```python
from fastunknot.first_jet_scan import first_jet_khovanov_decide
from fastunknot.geometry import ScanLimit

try:
    answer = first_jet_khovanov_decide(
        diagram.pd, seconds=2.0, max_objects=50_000,
        first_jet_max_work=1_000_000
    )
except ScanLimit:
    answer = {"status": "INCONCLUSIVE"}
print(answer["status"])
```

The raw API validates the PD. A local observation budget exhausts by
discarding uninstalled proposals, disabling further observation, and returning
to ordinary cancellation on the intact state. A global `ScanLimit` propagates
and must be treated as unresolved by callers. Each crossing is fully allocated
before observation, so the object cap also covers that temporary state.
`replacements=False` and `closure_bounds=False` expose the measured ablations;
`check_d_squared` and `audit_jets` provide additional research checks.

The interface returns a capped total rank and decision statistics. Replacement
degree counts must not be reported as the original bigraded Khovanov homology.
The conditional scan bound depends both on frontier width and the maximum
gap between one-object checkpoints, including allocation before observation.

The discovery run examined 360 scans of 180 knots and 2,898 stages. Its 117
eligible components contained 633 objects and 237 scalar pairs. Every observed
eligible block had `kappa = t`; 96 had value one and 21 had larger value. The
flat-origin parity theorem explains why a general `t > kappa` gain cannot be
assumed for actual minimal cube blocks. On the selected 22-crossing Conway sum,
the observer rejects after crossing 11, reducing scalar compositions from
3,324 to 39. The paired standard/observer timing ratio is 3.367 on that case;
many other cases are slower, including measured replacement cases. The optional
observer is consequently not enabled by default.

## Reverse suffix determinant responses

`fastunknot.streaming_response` prepares every suffix of a fixed validated
diagram and crossing order. It retains interior elimination while black-face
fragments join and boundary terminals become interior. Singular radical
directions and a permanent grounding anchor are preserved. When a protected
interior nullvector implies that every admissible future response is zero,
the compiler enters an absorbing zero state. The proof includes the geometric
condition forbidding future identification of already eliminated interiors.

```python
from fastunknot.streaming_response import compile_suffix_responses

responses = compile_suffix_responses(
    diagram.pd, order=list(range(diagram.crossings)), prime=101,
    max_boundary=100, max_stored_elements=1_000_000
)
closed = responses[0].query(())
print(closed["value_i"])  # formal Gaussian pair modulo the checked prime
```

`responses[stage].query(pairs)` checks that a matching covers the correct
boundary, respects inherited coloring, and meets the spherical Euler
condition. Incompatible inputs raise `ValueError` and provide no invariant.
The lower-level `responses[stage].response.query(partition)` is an algebraic
terminal quotient and does not itself certify a classical completion.

`iter_suffix_responses` yields immutable snapshots in descending stage order;
the collecting API returns a tuple in ascending stage order. The iterator
uses `O((W+1)^2)` field storage plus `O(n)` source geometry unless the caller
retains its outputs. All-suffix collection stores `O(n*(W+1)^2)` field entries.
Response queries cost `O((W+1)^3)` field operations.

Both APIs accept `max_boundary` and a cooperative `check` callback. The
collector also accepts `max_stored_elements`. Exhaustion raises
`ResponseBudget`; the storage cap counts retained matrix entries and excludes
source metadata and the current temporary matrix. It is not a hard process
memory cap. Arithmetic supports checked primes below `2**31`, including 2.
Residue-four Jones inference requires odd moduli and is not implemented here.
A modular zero does not certify an integer zero, and this interface returns
no knot or unknot verdict.

The independently reconstructed integer-cofactor audit made 19,520 comparisons
with zero mismatches, including exceptional-prime singular states. On the
256-crossing natural order of `T(3,128)`, median all-suffix setup is 14.061 ms
versus 3,615.101 ms for independent dense setup: a ratio of 257.10. Each dense
arm performs 23,789,518 elimination updates, compared with 928 for streaming.
A separate 8,192-crossing streaming run takes 0.415494 seconds; no dense timing
is claimed for that size. These isolate response preparation, including source
geometry. Existing filters readily decide the torus family, and eager suffix
preparation can be wasteful when a recognizer stops early. These measurements
do not demonstrate an end-to-end unknot recognition speedup.

## Inherited subprocess correction and integration

`fastunknot/normal_surface.py` incorporates a correction from the preceding
research continuation. Repeated `communicate(None)` calls after a timeout can
lose an incompletely sent input payload on the supported Python path. The
worker now calls `communicate(payload)` exactly once in a thread, polls under
the cooperative deadline, and kills, reaps, and joins on interruption. This
resolves the existing `test_communication_retains_input_across_polls` regression.
It is an inherited integration correction, not a new mathematical result or
new recognition performance claim.

The distribution's `integration/unknot_research.patch` applies from the root
of the pinned repository. `integration/tree/` contains only the new and changed
fast files; `snapshot/` contains the runnable source and required report
references. The article is copied separately to the research directory above.
See `integration/README.md` in the distribution for the clean-apply and target
byte verification record. Original source manifests, selected-source Git blob
SHA validation, test logs, and `environment.json` are included under
`provenance/`. Applying the patch does not install an external solver or change
the recognizer's backend selection policy.
