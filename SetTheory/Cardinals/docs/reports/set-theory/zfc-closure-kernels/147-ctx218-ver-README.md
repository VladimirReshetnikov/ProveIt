# Verification evidence and scope

The primary self-contained replay is `portable/reproduce.py`. Default mode
freshly regenerates all K218 generic symbolic runtime derivations while
replaying inherited construction/calibration with stored ancestral runtime
certificates. Quick mode is explicitly different: it audits stored final
runtime evidence after fresh reconstruction and startup.

`certificates/source/` contains the all-natural source bisimulation receipt
and every ordinal's complete correspondence. `certificates/runtime/` contains
the complete fresh physical run evidence and its portable integrity audit.
`runtime_origin.json` distinguishes the original independent research checker
from the explicit-path portable adaptation. The symbolic engine/helper and
runtime/case mathematics are unchanged. The adaptation also strengthens
stored startup verification to compare the complete tape support, physical
registers, header and gap.

The root independent-fact, whole-blank, prefix-contract, runtime-evidence and
provenance receipts are independent audits of the same exact machine/source
inputs. Their original scripts, latest receipts and construction logs are
preserved under `historical_audits/`. Those scripts use research-checkout paths;
they are clearly labeled historical evidence, not the portable entrypoint.
They do not replace the release's self-contained fresh replay. The runtime
research audit binds the original checker; the release audit separately binds
the actual distributed portable checker and rewritten integrity receipt.

`portable/lineage/lineage_rebuilt/lineage.json` and its isolated receipt are
historical deterministic construction evidence. The default driver reexecutes
the entire seven-stage lineage from the actual pinned upstream archive. Its
redundant direct188 basis is checked against the reconstructed stage and is
not an extra mathematical premise.

The thirteen negative controls reject changed source operations/arguments,
missing or duplicated source leaves/cases, nonpositive runtime, invalid block
and row coverage, wrong startup duration or tape support, and optimized Python
execution of the proof entrypoints. They test checker boundaries and are not
substitutes for the unbounded source/runtime arguments.

The baseline full-replay, runtime-audit and intake receipts concern the exact
unchanged upstream K219 packet, not the new machine. Historical development
receipts inside the vendor ZIP may bind earlier intermediate artifacts; current
inheritance uses the operative manifests and recursive construction/calibration
replay. Fresh and historical evidence are not conflated.

The isolated default release audit can begin from a computationally frozen
snapshot before the explanatory report and final audit receipts are added.
Its final binding verifies that every executed script, source recipe, table
and vendor input is unchanged. The deterministic ZIP audit binds the final
complete inventory; it is external to avoid self-referential archive hashing.

No finite-only discovery run is promoted to a proof. These are ordinary
executable mathematical certificates, not a new exact-byte proof-assistant
endpoint. They do not prove consistency, unconditional nonhalting or minimality.

`preseal/` preserves the independent isolated default replay, its phase logs,
and the second fresh runtime summary/integrity pair. Its common cases, full
startup and canonical bytes are byte-identical to `certificates/runtime/`;
`preseal/isolated_fresh_runtime/binding.json` records that precise identity.
The final 12-page report review is in `report_review.json`. The preseal receipt
records the two evidence-only checker-hash updates and unchanged computational
payload explicitly.
