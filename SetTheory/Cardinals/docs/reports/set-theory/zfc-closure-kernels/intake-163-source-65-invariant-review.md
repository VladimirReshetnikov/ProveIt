The exact source and data pins are in `review-65-invariant.json`; the arrival is `8e012a51d6e7fdad4d903089536427a813009a4f`.

The reviewer-owned static comparison matched all 6,459 literal `Prog254.v` rows, in order, against the maintained Lean `Prog254.lean` under constructor renaming. No supplied Python module was imported or executed. The verifier's counter operations also agree with the maintained `RegisterPath` definitions: increment retains the cleared suffix, break strips zero occurrences before incrementing, and continue strips one occurrences. Decoding uses zero padding and rejects any nonzero discarded suffix. This is compatible with the existing generic no-stray-bits result; that result needs no initial register-value restriction.

The product certificate's initial masks `[7,1,1,7,7,1,7,7,7]` mean that `N,A,D,X,Y,L` are arbitrary naturals and `T=W=H=0`. The category images for increment and both decrement branches are sound for every represented natural value. For each feasible guarded edge, the checker verifies that its image is contained in the destination masks. Initial inclusion and closure therefore suffice for ordinary induction over every finite execution length, without a bound on register values. The six excluded indices are `8202,8203,8204,8358,8359,8360`.

The relational certificate has a narrower starting family: `N,D≥2`, with the other seven fields zero. It contains the exact `N=D=3` root. The base-three vector encoding, padding checks, and the two possible outputs of decrementing category ≥2 are consistent. Its checks likewise establish closure and initial inclusion. They do not establish that the supplied set is the least abstract fixed point, nor that each admitted vector has a concrete reachable representative. The manuscript and README explicitly preserve these limitations. Names such as `reachable_abstract_vectors` in the result file should be read as certificate-admitted configurations when citing what the independent verifier alone establishes.

The included result reports 6,456 admitted sites, 8,385 feasible guards and 8,384 nonhalting edges for the product certificate; the relational certificate reports 7,725,633 admitted site/vector pairs and 8,669,994 successor edges. The halting guard being admitted does not prove halting. The numerical checker does not verify the separate claim that the same 472 binary transition pairs remain used after excluding six guards; that requires the affine audit. Larger cutoff experiments remain diagnostics because their certificates were not retained here.

A useful formalization would start with the small product certificate: prove category-transfer soundness, check its finite closure table, then use `RegisterPath` induction to export the six exclusions for every generic six-numerical root. Formalizing the large relational certificate would currently yield the same exclusions. Neither certificate itself removes a transition row or establishes a machine below 246, a state lower bound, or a PA endpoint.
