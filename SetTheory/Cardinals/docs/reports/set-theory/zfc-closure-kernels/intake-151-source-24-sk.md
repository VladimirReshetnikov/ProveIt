## Concrete generic-input qualification

`parse_tm` validates transition sources and targets as nonnegative, but does not validate the declared start. It accepts:

```text
#! start -1
1 0 0 R 1
1 1 1 R 1
```

The direct native step from(-1,[],0,[]) is halt/None. `compile_machine` uses `states[start]`; Python interprets states[-1] as the last valid encoded state, here1. The compiled first step is therefore(1,[0],0,[]), and the compiled machine follows state1's nonhalting rightward loop. This refutes the unrestricted implementation wording “every table accepted by the parser.” Reproducible evidence is in negative_start_repro.py, negative-start.tm and negative-start-evidence.json. The remedy is rejecting start<0 or explicitly restricting the compiler's domain to validated nonnegative state labels. The frozen253 input and its reproduced payloads are unaffected.
