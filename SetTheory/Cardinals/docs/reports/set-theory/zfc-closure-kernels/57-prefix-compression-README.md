# Compression experiments and their limits

This directory records additional searches around the pinned permutation252
machine, the MP source variant, and the new prefix-right decrement engine.
**None of these searches produced a verified machine with fewer than 252
working states.** The positive result of the investigation is the changed
252-state arithmetic engine described in the main report, together with its
phase-qualified macro proof and clean blank initialization. These experiments
locate obstructions to particular ways of compressing that engine.

`final_summary.json` collects the exact results and evidence paths. Individual
JSON summaries remain the primary records; their timings are observations from
one run and are not performance guarantees. Optional `.jsonl.gz` files preserve
the corresponding per-recipe or per-deletion ledgers without retaining large
uncompressed duplicates in the archive.

## What the diagnostics establish

The strict executors represent a free gap by an affine run of length `n+c`,
where `n` ranges over all natural numbers. Register files are opaque boxes
governed by explicit macro contracts. A successful complete guard audit is an
ordinary, conditional verification for all represented register values and
gaps. It is not a finite sampling argument. The C++ ports are not new
proof-assistant developments.

**A diagnostic rejection is not a proof that two machines are semantically
inequivalent.** Rejection can mean symbolic fuel exhaustion, a configuration
outside the rules supported by the executor, an unavailable macro premise, a
missing row, or inability to reach the required canonical output. A different
simulation relation or macro invariant can turn such a rejection into a valid
implementation. No lower bound or minimality theorem follows from the number of
rejected recipes.

The strict symbolic fuel limit is 1,000 rule applications. The prefix route
literal screen instead uses 10,000 literal transitions, an explicitly finite
tape window, and concrete initial data. Its evidence is only a concrete-screen
result. The baseline traces fit inside that window and pass all samples.

Most searches freeze the 55 inherited box-support rows. They also preserve the
fixed dispatcher identity and initial-state identity, and exclude deletions
that would require rewriting a protected target. They do not freeze every
incoming transition to dispatcher96. The exact family is generated by the
associated program, not by an informal description of "all folds."

Before the native searches, every retained baseline guard must succeed. The
original and MP native drivers compare both the exact symbolic rule count and
the complete set of table lookups with independently generated Python data.
The prefix local driver does the same with the changed macro. This is a useful
cross-check of the port; it is not an independent proof of the macro lemmas.

### The changed prefix contract

`prefix_decrement_input.py` produces a standalone copy of the symbolic executor
with only `run`, `oracle`, and their helpers. The unrelated upstream `audit` and
`main` entry points, including their old unchanged-support assertions, are
deliberately removed.

For positive decrement at state 43 with a marked physical register, the new
oracle returns the old exit state 63 for slot 0, or 48 for a later slot, and
prepends one 1 to the left zipper. The selected value decreases by one and no
spare block is appended. The new contract requires the left context, in zipper
order, to be `1^k 00 L` for some `k >= 1`. This premise is checked before every
new oracle invocation. The generated affine target gives positive decrement
one extra gap cell, in addition to the usual possible program-counter overflow.

The source guard suite has 8,366 cases, including 1,925 positive-decrement
invocations. The independent review in sibling `logic_audit/` verifies all
phase assertions; the leading1-run has constant part at least 9 and the following
0-run has length at least 3. The unbounded tape proof is in the main proof notes.

### Two incoming rows and conflict pruning

Deleting a 252-state table label leaves251 working targets plus halt, giving
`2 * 2 * 252 = 1008` possible actions at an editable incoming row. The original
family contains 46 eligible deleted states of incoming degree 2, and the MP
family contains 47. Their complete recipe counts are consequently
`46 * 1008^2` and `47 * 1008^2`.

The native executors assign an incoming action only when execution first reads
that row. A failed trace is unaffected by values of rows it did not read, so
all extensions of that partial assignment can be rejected by the same
diagnostic. `native_learned_entry.cpp` additionally records which assigned rows
were read: a child conflict that omits the current variable can be returned to
an earlier branch without trying the other values of that variable. This is
ordinary deterministic conflict pruning, not a theorem that failed symbolic
executions denote different mathematical computations.

The original completed run visits 2,995,822 search nodes and performs 5,888,482
guard checks. The MP completed degree 2 run visits 3,065,375 nodes and performs
5,940,526 checks. Their compact per-deletion records are `native_groups.jsonl`
and `mp_native/native_groups.jsonl`.

### One extra row after three near folds

The chosen original folds are 204→252,113→23, and 34→68. The script first obtains
a failed guard and its lookup set. Any one-row repair that can change that
deterministic failure must edit a row in that set. It tests all allowed new
actions at those rows. The128,896 resulting recipes required167,269 checks and
had no survivor. This scope concerns those three folds and one extra row only.

### Uniform and directed mixed-row recipes

Each local run contains 55,471 uniform target substitutions and 98,265 directed
mixed recipes, totaling153,736. A mixed recipe redirects all incoming edges
of the removed state to an existing target and copies one selected outgoing
row of the removed state onto that target. It omits a copy already identical
to the current row. It does **not** identify every symmetric or isomorphic
duplicate. In particular, its 98,265 count should not be compared as a count of
unique machines with the pinned source's symmetry-reduced mixed-row census.

The MP local runs cover free gap `n+40` and `n+43`, both with all 8,366 guards
and with the three source-excluded guards removed. The stronger box run keeps
all nine net register offsets instead of permitting only one effect, and uses
source-local interval/constant facts to justify additional register tests. It
allows cancellation of repeated updates and ignores additional zero spare
blocks under an existential all-zero spare-suffix invariant. An unresolved
alternate register zero test is rejected; no unsound branch guess is made.
This enlarged diagnostic still yields no local survivor.

The two prefix local runs use the preceding prefix contract with its explicit
phase premise. Both freeze the changed support rows. They therefore cannot
discover a valid mutation of the scanner that the oracle itself hides.

### Context-dependent reuse of state 2

This separate family attempts to reuse an inherited protected state, rather
than freezing it. State2 already has the zero-scan row needed by new state 85.
The proposed fixed changes are:

```text
delete old85
75/read1 -> (1,L,2)
2/read1  -> (1,L,97)
0/read1  -> (0,L,4)
42/read1 -> (1,L,6)
```

The mark change at 0/read 1 is justified locally. After it moves left, the
current delimiter is0 and its predecessor is1. The old sequence through
2/read 0 and 2/read 1 and the new sequence through 4/read 0 and 6/read 1 write the
same cells and reach the same state 4 configuration. For physical slot 0 the
macro can now stop in state 6 on the header1, instead of old state 2; state 6/read 1
has the old state 2/read 1 action. The modified mark oracle returns state 6 for
every physical slot. The new positive scanner is a literal relabeling85→2.

The remaining three decoder incoming rows20/read 0,20/read 1,143/read 1 are
assigned arbitrary write/move/target actions. State42/read 1 is fixed to the
listed proposed repair; it is not treated as a freely editable fourth row.
The complete family has `1008^3 = 1,024,192,512` recipes.

The target-only subfamily has no survivor. A first full-action run reached its
2,000,000-node cap and was partial. A subsequent run that moves a failing guard
to the front completed the full family in 2,087,569 nodes and 2,087,581 guard
checks. Its first failures are source guard 2 (`CB` at path`001`) and guard 31
(`CC` at path`10111`). The obstacle in this family therefore arises already in
program-counter control contexts. The final result is
`prefix_best_native/context_reuse_adaptive_summary.json`; the earlier capped
record is retained and explicitly labeled partial.

## Source invariants

`mp_phase.py` propagates per-register masks `{0,1,>=2}` from the zero root.
`mp_dirty_phase.py` starts from the earlier MP bootstrap's actual logical
vector `(0,0,0,0,1,1,0,0,0)`. Both check a finite post-fixpoint and exclude exactly
guard indices 8202,8203,8204 in the modified8,366-case indexing. This is ordinary
source analysis, not a binary startup certificate or a proof-assistant result.

`mp_affine_invariants.py` computes exact affine subspaces over the rationals,
using lifted points `(1,x_0,...,x_8)`. `mp_affine_nonnegative.py` adds sound
nonnegative cancellation against the finite masks. Their joins and post-fixpoint
checks use exact `Fraction` arithmetic. Both obtain the same three excluded
guards; neither establishes additional branch elimination. The full exact
spaces are saved in the compressed `*_spaces.json.gz` files.

The original source phase exclusion has six indices,
`8202,8203,8204,8358,8359,8360`, in the original 8,391-case indexing. Those are
used only by the explicitly original-source experiments. The modified MP
program has different indexing and cannot inherit that six-element list.

## Reproduction

Run commands from the archive root, where `compression/`, `source/`,
`redesign/`, and `bootstrap/` are siblings. Python dependencies are from the
standard library. Use a GCC or Clang C++20 compiler for the native programs;
the large recipe counts also use the supported `unsigned __int128` extension.

The primary research verifier described in the archive's top-level README is
the appropriate entry point for the successful252-state engine. The commands
below reproduce optional searches. They overwrite their own result files.

Each native input directory contains three plain text files that should remain
in the archive. `native_table.txt` lists `state read write move target` rows.
`native_cases.txt` lists case index, PC word, guarded physical register (or-1),
zero-guard value (or-1), next PC (or`-`), overflow flag, effect code (-1 none,
0 increment,1 decrement), affected register (or-1), halt flag, and baseline
symbolic rule count. `native_usage.txt` maps each observed `(state,read)` row to
the comma-separated baseline case indices that access it. The C++ drivers use
the final cost field and lookup mapping to check agreement with Python before
searching. `metadata.json` records permutation and gap conventions. The richer
box directory also needs `native_bounds.txt`, with nine lower/upper bound
pairs per guard. A missing upper bound is-1.

tables in the **old** fixed-label, old-box, gap40 interface. It is not the
checker for the changed prefix routine and does not verify blank startup.

## Unmeasured program-counter encoding direction

The rejected250-state shared scanner loses one bit of zero/positive return
information. Repairing the exact old `brk1` successor at all costs may be an
unnecessarily narrow interface. A future search could inventory alternative
uniform program-counter operations that a smaller shared return routine
actually realizes, and then recompile the finite source tree for that interface.

For example, if a changed conditional instruction realizes `brk2` on zero and
ordinary increment on positive, an original leaf at path`p` can be represented
by a node with that instruction at`p0` and `CB0` at`p1`:
`brk2(p0) = brk1(p)`, while positive execution first reaches`p1` and its `CB0`
reaches`inc(p)`. Similarly an increment instruction whose new control operation
is `brk1` can be placed at`p0`, because `brk1(p0) = inc(p)`. These identities are
about the finite control-word operations; they do not provide a machine, a
wrapper state count, or an initialization proof. No implementation of this
direction is claimed here. Any wrapper cost and unused-branch behavior must be
included in a concrete state count.
