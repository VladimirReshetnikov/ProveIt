\section{Reproduction, exact artifacts, and incorporation}

The ZIP is a self-contained research packet. Its top-level
\code{verify.py} requires Python 3.10 or later and only the standard
library. It requires assertions to be enabled and deliberately rejects
\code{python -O}. It performs no network request and does not invoke
Lean, Rocq, or a theorem-prover kernel. Run from the unpacked directory:
\begin{lstlisting}
python3 -B verify.py --output /tmp/zfc-layout-verification.json
\end{lstlisting}
The optional output path prevents a replay from overwriting the frozen
verification record. With the archive's manifest present, it also checks
the exact delivered bytes. The pristine reference contains its own
105-entry integrity manifest, checked separately.

The positive replay independently parses the pinned literal source;
reconstructs all five source27 rotation options; compares source sites
and finite maps; reruns all 8,391 universal instruction cases per layout;
reruns four block inductions, three arithmetic macros, and nine selectors;
checks every pruned literal row and target; and verifies all 492 table
rows lie in the union of macro and instruction proof support. It then
replays the two complete blank prefixes with a sparse infinite-tape
representation and compares canonical table bytes and renumberings.
The delivered run passes all five runtime checks and both complete
initializations. It took about 15.5 seconds on the preparation host;
this timing is an observation, not a required reproduction bound.

Large generated finite fixtures and compiled executables are omitted when
they can be regenerated exactly. Their generators, settings, relevant
hashes, and compact results are retained. The runtime and fusion READMEs
give the separate C++17 build and replay commands; these broader searches
are not rerun by the default positive verifier. This distinction keeps
the universal theorem checks separate from optimization effort.

The completed layout experiment can be reproduced independently of the
original wall-clock cutoff using:
\begin{lstlisting}
python3 -B code/grammar/plateau_search.py \
  --ceiling 247 --seconds 2147483647 --max-nodes 10000 \
  --output /tmp/zfc-layout-247
python3 -B code/grammar/plateau_search.py \
  --ceiling 248 --seconds 2147483647 --max-nodes 991 \
  --output /tmp/zfc-layout-248-prefix
\end{lstlisting}
The first run exhausts its queue. The second intentionally reproduces
only the saved prefix of the unfinished 248-gated search. The historical
JSON key \code{best_graph_quotient} means the charged metric $c(T)$ defined
in Section~\ref{sec:search}; it should not be read as full minimization of
every graph. Elapsed times need not match.

Rebuild the report with two ordinary LaTeX passes:
\begin{lstlisting}
pdflatex -interaction=nonstopmode -halt-on-error report.tex
pdflatex -interaction=nonstopmode -halt-on-error report.tex
\end{lstlisting}
The source requires common packages included in a standard TeX Live
installation. The delivered PDF was rendered and visually checked after
compilation. Full machine tables are also supplied as plain text, so
reproduction does not depend on transcribing the PDF.

The literal format is \code{state read write move target}; the header
declares the blank start. The canonical working states are 0 through
245, and 246 is the only halt label. Original labels such as 255--260
in the research tables are names, not additional states beyond the
explicit retained set. The provided renumberings make that accounting
checkable.

For incorporation, retain this packet as research and verification
material. The two complete layouts may be added alongside Context246
as alternate 246-state candidates. The three bootless layouts and all
source-specialization attempts should retain their stated experimental
status. This work supplies neither a 245-state record claim nor a change
to the maintained 252-state Lean endpoint. A future smaller machine
should enter through its own complete table, positive certificates,
exact initializer, and explicitly calibrated theorem.
