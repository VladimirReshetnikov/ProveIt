The scheduler is the genuinely useful next implementation. CofinalScheduler.Dynamics retains each client's exact step and run functions, with equations for zero and successor. Its Halts means a finite successful run reaches a state with no next step. The separate Laws record asks only that a successful boundary step increments index by one, while a successful active step strictly decreases pending rank and preserves index. It imposes no bound on the rank loaded at a boundary, no candidate encoding injectivity and no time budget. This is a smaller hypothesis boundary than special-purpose arithmetic scheduler proofs.

The main proof uses lexicographic induction on `(target - index s, pending s)` while retaining `index s ≤ target`. At a boundary already at the target, zero steps suffice. A failed step gives halting. At a successful boundary below the target, the first component decreases; the newly loaded rank may be arbitrary. At a successful active step, index stays fixed and the second component decreases. Prepending the successful step preserves the reached-boundary or halting witness. The subtraction measure is safe precisely because the bound is retained in each recursive call. No fairness premise is silently assumed in addition to the two progress laws.

`complete_at` fixes one target before quantifying over every reachable state at that target boundary. It asks for halting only from those reachable boundary payloads, then composes runs. The stronger uniform cofinal condition is a possible corollary; it is not built into the Lean record. The Rocq companion provides that corollary explicitly. Keeping dynamics separate from rank laws also lets run composition and invariant preservation be shared without unnecessary scheduling assumptions.

The EnumPerm adapter chooses one target using the existing cofinal encoding bound and a command word beginning `AX(0;1,Y)`, with Y equal to the initial candidate index. The existing `program_none` contract accepts every working payload after the prefix; it need not reset every register to a fixed value. Therefore the chosen candidate works uniformly at the boundary actually reached. The new `complete_any` removes the initial pending-list-zero premise even for an active candidate. `halts_iff_any` still requires `Inv (toW s)` for soundness. The finite counterexample precisely identifies the dangerous quantifier change. States `(k,b)` advance to `(k+1,!b)` exactly when b matches the parity of k; otherwise they halt. Every state is a boundary. For each fixed payload b and lower bound N, either N or N+1 halts with that payload. The actual aligned trajectory always changes payload to the next matching parity and never halts. Thus `∀b ∀N ∃K≥N` with payload-specific success does not justify the fixed-target reachable-payload condition. The source proves the aligned run equation, nonhalting and absence of a uniform immediate halting candidate without axioms in its submitted reports. This does not undermine the maintained compiler: its reset word has the stronger uniform contract. Arbitrary-state completeness already has antecedents such as EnumSafeStart254; the novelty here is the reusable implementation and concrete multi-client integration, not discovery of tail universality.
