\section{Reproduction, evidence, and incorporation}
\label{sec:reproduction}

The archive contains the complete mathematical report and editable
LaTeX, both table labelings, the exact source, the new checkers and
receipts, and the selected inherited files needed for offline
reproduction. The Python checks require Python 3.10 or later and its
standard library. Assertions must remain enabled: do not use
\file{-O} or \file{-OO}, and leave \file{PYTHONOPTIMIZE} unset.

\subsection{One command for the principal result}

From the extracted archive root, run
\begin{verbatim}
python3 -B reproduce.py --output /tmp/zfc238-replay
\end{verbatim}
Choose a new or empty output directory. The driver checks the manifest
when present, copies the bundle to temporary storage, and preserves the
delivered artifacts. It reconstructs the inherited boundary239 table,
constructs final 238, checks its canonical bytes and complete startup,
replays the exact source certificate and source/seed identification,
checks the independent local composition, and runs the complete
8,386-case final 238 runtime proof. It also checks the supplementary
logical matrices and source-association certificates. All JSON statuses
are checked explicitly; process exit zero by itself is insufficient.

For the additional, separately sufficient local-guard route, use
\begin{verbatim}
python3 -B reproduce.py --with-guard --output /tmp/zfc238-guard
\end{verbatim}
This repeats the full unbounded selector proof for exact boundary239
and its changed source. It uses the exact attributed engine bytes
recorded in the original fresh guard receipt. The default direct
final-table runtime proof does not need this guard as a premise.

A quick packaging and finite-certificate check is available:
\begin{verbatim}
python3 -B reproduce.py --quick --output /tmp/zfc238-quick
\end{verbatim}
Its result is explicitly labeled as omitting the unbounded replay.
It must not be described as a fresh complete runtime proof. The full
runtime and guard runs performed during this investigation are preserved
separately, with their exact table, source, checker, and engine hashes.
The quick assembled-package replay verifies the integration of the
portable paths and freshly reconstructs the complete machine.

The recorded direct final runtime took about 220 seconds and the
separate guard replay about 302 seconds in the preparation environment.
These are timings of proof construction by Python. They do not
measure the transition count of a hypothetical halting run of $M_{238}$.
