# Boundary source audit and clean-frame composition

## Finding

The boundary reparenthesization is a valid source transformation. The clean
binary runtime interface composes across its successor paths. I found no flaw
in either interface after inspecting the actual definitions, replaying the
inherited complete source certificate, replaying the pinned Lean source and
seed extraction, and independently checking every control edge by a different
integer-interval method.

This finding applies to the source identified by SHA-256
`7fd152d1f5371d2a561d4ad1870d241683b010ce7b7a27399b95363a4537cfb6`.
It does not by itself certify a binary table. A proposed binary table still
needs its own complete runtime proof and blank initialization proof.

## Exact semantic comparison

The inspected `semantic_interface/RegisterPath.lean` defines paths as lists
of bits with absent bits equal to false. The decoder walks from the root,
with false selecting the first child and true the second, until it encounters
an instruction leaf at depth `d`. The executor consumes precisely
`(P ++ List.replicate d false).take d` before doing path arithmetic. Hence
its arithmetic operates on the encountered leaf path, including when the
input pointer is shorter or longer than that path.

Increment is fixed-length binary increment with all-ones rollover; increment
of the empty path remains empty. A break strips through its requested number
of zero bits from the right and increments the remaining prefix. A continue
strips through its requested number of one bits. Strip exhaustion gives the
empty path. Decrement is exactly the split used by the checker: on a positive
register it subtracts one and increments the path; on zero it leaves registers
unchanged and performs break 1. Explicit break and continue each take one
source instruction step. A literal halt leaf supplies halting; exhausted
decoder fuel alone does not.

The input DAG has decreasing internal child indices, root 202, declared
storage bound 203, and maximum leaf depth 51. Its supplied fuel 204 is more
than enough to encounter every leaf. The boundary tree has maximum depth 48
and is checked as a complete finite binary tree. Thus neither source graph
hides a nonhalting or stuck decoder path.

## Why the independent checker is a complete proof check

For a binary word `p` of length at most 64, let

`x(p) = value(p) * 2^(64 - length(p))`.

A leaf at `p` denotes the half-open dyadic interval

`[x(p), x(p) + 2^(64 - length(p)))`.

The checker verifies that the ordered leaf intervals partition `[0,2^64)`
without overlap or gaps. This is equivalent to a full prefix-free binary
tree at the observed maximum depth. The zero-padded source pointer `P` locates
the unique interval containing `x(P)`. Binary search in these intervals
therefore gives the same leaf as the original tree walk, for every finite
pointer generated by this source. This method uses a different implementation
from the inherited recursive tree walk.

The checker computes all instruction successors by integer increment and
indexed occurrences of the stripped bit. It compares the complete descriptor
array with the baseline after each transformation. The rotations themselves
are replayed as direct simultaneous prefix substitutions, rather than through
the original recursive subtree-rotation function. For a left rotation the
relative prefixes `0,10,11` become `00,01,1`; a right rotation uses the inverse
substitution. All three component subtrees must be nonempty and simultaneous
targets must be disjoint.

No register values are sampled. Equal descriptors prove a bisimulation for
every natural register vector: the selected operation is the same, the same
register is incremented or decremented, equal registers select the same
decrement branch, and the successor leaf index agrees. Induction gives equal
register vectors and corresponding source instructions at every source step.
Both programs reach their unique halt instruction together. The exact control
graph digest is

`ae7f12f37306b86e5f70469210fd2a8d68b6f9df094bf659abc6b4a56714f1fd`.

The last two rotations cross a trailing explicit break. There is no reliance
on a general assertion that arbitrary source sequencing is associative.
Every control edge after each such rotation is checked. The explanatory
closed-chunk/break lemma helps describe the construction but is unnecessary
as an extra trusted premise of the complete graph certificate.

## Clean-frame lemma

Fix a head location `h`, gap `g >= 0`, logical registers `R`, and nonempty
finite spare list `A`. Write `F(P,R,A,g,h)` for the binary frame with marker
at `h-1`, the one bits of `P` beginning at `h`, a header at `h+64+g`, and the
unary register and spare blocks after the header. Every exterior cell is
zero. Suppose `P` and `p` have length at most 64 and

`P 0^omega = p 0^omega`.

Then `F(P,R,A,g,h) = F(p,R,A,g,h)` as complete Turing configurations:
the control state and head are identical; the one bits of the pointer are
identical; and the marker, header, register blocks, spare blocks, and zero
exterior are identical. This is equality of the whole tape, not only equality
of decoded values. It is independent of all register magnitudes, the amount
of additional gap, and the spare-list length.

For each source-generated successor `P`, let `p` be the encountered leaf
path. The dyadic checker requires `x(P) = x(p)`, rather than only requiring
the weaker fact that `x(P)` belongs to `p`'s interval. This proves the infinite
zero-padding identity. It also directly compares the finite supports of the
one bits in the two words. All 8,385 successor edges satisfy it. The initial
empty pointer has the same padded word as the first leaf, which is all zeros.

Consequently a binary runtime proof formulated only at exact leaf paths is
enough. Its initial clean frame is literally the appropriate first-leaf
frame. After each nonhalting instruction, the proven output frame at a
successor `P` is literally the next leaf's input frame. No extra binary
transition, decoder assumption, or equality merely up to interpretation is
inserted between instruction derivations.

## Unbounded composition theorem

Assume a literal binary table has:

1. A proved finite blank prefix ending in the above clean frame for the
   logical seed and empty pointer.
2. For every leaf and each decrement guard, a whole-tape runtime derivation
   from `F(p,R,A,g,h)` to the specified successor frame, for all admitted
   natural values and every nonempty finite spare list.
3. Positive finite binary duration for every such derivation and a literal
   binary halt for the source halt leaf.

Then its blank execution halts exactly when the boundary source from the
logical seed halts. The proof is induction over the source instruction
number, using the clean-frame lemma between successive derivations. The
gap remains natural; positive decrement increases it by one; pointer
rollover adds its accounted displacement; all existing spares are retained;
and increment appends a value-1 spare, so nonemptiness remains true. No source
instruction addresses the spare list because all register operands are in
`0..8`; the logical register tail may consistently remain zero.

Every block is finite and has positive duration. Thus a finite source halt
produces a finite binary halt. An infinite source execution gives infinitely
many distinct successive binary checkpoint times, ruling out a hidden finite
binary halt. No nonhalting assumption is used. Composing this theorem with
the proved source graph bisimulation and the pinned logical calibration
transfers the consistency biconditional to that exact binary table.

The independent runtime engine's unbounded rules are consistent with this
contract: literal steps, natural-number induction for self-loop unary scans,
and structural induction for list traversals whose one-block schemas are
rederived on the supplied table. Its positive affine duration check prevents
zero-time collapse. Its proof-construction step cap bounds attempts to find
a derivation, not the admitted register values or machine runtime.

## Remaining trust boundary

These are ordinary mathematical proofs with finite executable certificates.
The source extraction script identifies concrete data in pinned Lean files;
it is not a Lean elaborator. Neither fresh source checker is a new Lean or
Rocq kernel theorem. The final deliverable should retain that distinction.
The arithmetic internalization of finite source certificates and inductions
is routine, but this audit does not claim to supply a serialized derivation
inside ZFC or PA. The logical calibration and the final binary table's
runtime/initialization remain separately named proof obligations.

## Reproduction

From the original boundary239 package directory, the inherited checks are:

```sh
python3 -B formalism/extra/check_rotation_certificate.py --report source_certificate_replay.json
python3 -B source_interface/check_source_interface.py --output source_interface_replay.json
```

The independent check is:

```sh
python3 -B check_source_intervals.py \
  --baseline formalism/extra/baseline_sites.json \
  --rotations formalism/extra/rotation_certificate.json \
  --candidate candidate239/sites_logical.json \
  --output source_intervals_audit.json
```

The command paths may be redirected when these files are incorporated into
a new package. All three input byte hashes are pinned inside the independent
checker, so relocation does not weaken its identity checks.
