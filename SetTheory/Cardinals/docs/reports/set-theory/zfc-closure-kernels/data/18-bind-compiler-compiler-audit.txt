A source-to-machine pitfall: destructive parameter acquisition
------------------------------------------------------------
The original Lukasiewicz row is
  ((c -> u) -> a) -> ((a -> c) -> (b -> c)).
Its parameter multiplicities are a:2, b:1, c:3, u:1. In the edited emitter,
emit(u) is not a read of a persistent variable. It pushes zero, destructively
reads the next parameter field from prooflist, then moves it into topwff.
Therefore an arbitrary bijection on the four schema parameters need not
preserve what the emitted register program computes.

For the unchanged emitter, exactly12 of24 parameter permutations keep u in
a once-occurring slot (original b or original u). Assigning u to original a
causes two distinct reads, yielding in effect
  ((c -> d) -> u1) -> ((u2 -> c) -> (b -> c)).
Take c=false, b=true, u1=true, u2=false. This formula is false, regardless of d.
Thus an optimization justified only by abstract schema bijectivity can emit
a non-tautological logical axiom. The actual acquisition count and contracts
must also be preserved. The supplied248 generator correctly checks one
fourth-parameter read; no defect in that generator is asserted.

The exploratory sweep that allowed inadmissible permutations was discarded.
A corrected2048-trial sweep enforces exactly one fourth-parameter read and
reaches269 states, reproducing rather than improving the established control.
