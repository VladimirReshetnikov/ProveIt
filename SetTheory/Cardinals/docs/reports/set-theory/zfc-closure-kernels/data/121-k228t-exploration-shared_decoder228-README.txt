A shared-decoder alternative to the transferred K228 machine
==========================================================

Status
------
This supplement provides a SECOND rigorously checked 228-state machine. It
has the same state count as the main transferred K228 construction. It is
not a 227-state result. It is useful as a structurally different starting
point for further source optimization.

K230 input repository:
  https://github.com/elliotglazer/k230-rocq
Pinned commit:

The parent construction transfers the older boundary-helper fold and
copy-loop fold to K230, yielding the supplied input with states
{0,...,229} minus {79,140}. Its start state is 0 and halt outcome is 230.
This supplement makes nine further row edits and retains all 228 states.

Method
------
State 85 originally decodes (A,(B,C)), using state 65 for (B,C), with
A represented by state 19, B by 114, and C by 12. All these chunks are
closed. Left reassociation creates ((A,B),C), where the new (A,B) decoder
is identical to existing state 98. Merging the duplicate frees label 65.

That immediate one-state deletion is NOT a valid finished optimization:
its source has a seven-zero run, and changing 85 also changes a projection
borrowed by hardware state 175 through state 76. A source-CFG certificate
and a successful blank bootstrap alone do not discharge binary runtime.

The finished alternative repairs both issues. It simultaneously performs
right reassociations at the two source parents 76 and 155 of the shared
node. The reclaimed label 65 supplies the second required right child.
Finally, state175/0 is redirected from 76 to 85. On either preceding bit,
this last change preserves the exact three-step projection to state 19 or
90. The old and new paths read only cells -1 and 0, preserve their bits,
and finish one cell to the right.

The final table changes are, in K230's original state labels:

  65/0   0 R 12       65/1   1 R 175
  76/0   0 R 98       76/1   1 R 85
  85/0   0 R 12       85/1   1 R 86
 155/0   0 R 98      155/1   1 R 65
 175/0   0 L 85

This moves a shared decoder through two parents while compensating an
entry used by the arithmetic hardware. It cannot be generated by a
rotation routine requiring the inner state to have only one incoming
transition. The coordinated construction has 212 source DAG nodes, 5121
operation occurrences, depth 39, and maximum zero-run length 6.

Completed checks
----------------
1. Exact source control-flow graph: all 5121 operations and 6656 guarded
   cases preserve their operations, register operands, successors, and
   starting operation.
2. Two symbolic local projection cases, quantifying over arbitrary
   exterior tape.
3. All 409836 blank-bootstrap checkpoints match, through 409835 steps.
   No changed row is visited. The endpoint is state 84, head -5, with
   exactly 351 one-cells; the complete support is in construction.json.
4. A freshly constructed universal runtime certificate passes all 6656
   source guards. It uses 1614367 symbolic rules, at most 415 per case;
   minimum actual instruction duration is 13. All 456 transition rows
   are covered. Natural register values, the gap, and the spare list are
   unbounded. The 4000-rule limit bounds certificate construction only.

These are ordinary mathematical proofs implemented by exact finite
checkers and unary/list induction. No newly compiled Rocq endpoint for
this alternative is claimed. Its ZFC calibration is inherited through
the main K228 source and K230 theorem chain.

Reproduction (Python 3.10+, assertions enabled)
-----------------------------------------------
From this supplement directory:

  python3 -B build_shared228.py --output-dir replay-new

This reconstructs the literal table and source, proves the source and
projection identities, and checks the full bootstrap. It verifies the
pinned input and output hashes.

To reconstruct the independent unbounded runtime certificate:

  python3 -B code/verify_runtime_k.py \
    --table machines/k228_shared.tm \
    --source source/sites_shared.json \
    --output replay-new/runtime.json

This takes roughly 2-3 minutes on the research environment. Compare its
case array with evidence/k228_shared85_runtime_cases.json. No network or
third-party Python packages are required.

Restricted searches and remaining lead
---------------------------------------
No further state saving was found in the following completed searches:

  K230: plain local folds and folds with one neutral helper.
  Main K228: plain local folds, one neutral helper, head offsets +/-2.
  Shared-decoder K228: the same searches, plus incoming one-bit tags.

These local searches used inductively reachable 11-cell windows and
positive old/new trace prefixes of at most 65 steps, staying in the
represented window. They establish no lower bound on machine size.
The corresponding concise execution logs are in evidence/.

The final source walk started from this verified shared-decoder layout.
It sampled 35000 proposals, accepted 27190 rotations, and examined 26226
unique tables. General reassociations, both-neighbor fold signatures,
and temporary seven-zero layouts were enabled; final candidates required
at most six zeros. It found zero 227-state candidates. Seed 22885065,
log and receipt are preserved. This is discovery evidence, not a
completeness statement about the optimization space.

A useful next step is to extend the source optimizer's neighborhood with
coordinated changes at all parents of a shared node and explicit repair
of borrowed entry contexts. The construction here supplies a working
example with full runtime proof; it does not by itself save a third state
from K230.
