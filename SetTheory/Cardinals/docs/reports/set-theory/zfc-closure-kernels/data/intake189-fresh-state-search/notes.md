## Rho6 is an exact-theory reparameterization

The retained row is `D(i,A) = Ex_i(Q_i A) → A`. Only its emitted operands
change, from D(a,c) to D(a,b). The axiom ranges are literally equal because
the three natural inputs range independently. The explicit original-to-new
translation sends `(a,b,c)` to `(a,c,0)`; the reverse sends it to `(a,0,b)`.
These translations affect an individual *ungated* rho6 use, not an entire AX
batch. All other rows, the bundle gate, proof rules and falsity remain exact.
There is consequently no illicit transfer of a gate or an assumed equality
of enumeration indices or runtimes.

At source level, both original c-pushes are complete, closed, halt-free
26-leaf subtrees. Their replacements are exactly the existing b-push subtree,
including relative binary shape. Changed primitive ordinals are 966, 971,
1144 and 1149: two CD3 and two CI3 become CD5 and CI5. The complete primitive
control topology is unchanged. The source has 206 DAG nodes, 4,744 leaves,
depth 38 and maximum zero run six. The only native row changes are
`199/1: 1R166→1R12` and `206/0: 0R186→0R76`.

The new native/source SHA-256 values are respectively
`031394d436b6b80708dcfb9e1b31938012c31aad94790bb3060ea63eae015f3b`

## The inert insertion is a seed-relative source equivalence

The source inserts six instructions at half-open interval [4597,4603):
CD7, CI6, CC2, CD4, CI5, CC2. Removing this interval recovers the exact old
primitive word. The tree is also reassociated, so the proof additionally
compares both complete guarded control-flow graphs and an exact contraction.

The finite zero/positive abstract interpretation starts at the actual seed
`[3,0,0,0,3,0,0,0,0]`, computes 19,820 work items and rechecks post-fixpoint
closure for every admitted edge. Its transfers conservatively cover all
natural values, including positive decrement yielding either zero or positive.
Registers 7 and 4 are zero at the two entered nodes 4597 and 4600; the other
four inserted nodes are unreachable. These two zero steps preserve registers.
All 6,166 original guarded edges contract exactly, and no infinite execution
can remain inside the inserted finite block. This is equivalence from the
specified seed, not an unconditional no-op on arbitrary register files.

The source has 206 DAG nodes, 4,750 leaves, depth 37 and maximum zero run six.
Its table has 38 literal row changes against K219, without changing the state
set. Native/source hashes are respectively

and `4d09638d564a350bb7fe97a893bcd22dd6bc902d3f63ff674821aa1e87feb803`.

alone is not an accepted runtime or state-saving result. No stacked table
is claimed by this review.

## Direct execution boundary

The original wrapper main is not invoked: it includes archive extraction and
a manifest loop that are outside the selected replay. The own `direct.py`
imports only its already reviewed, side-effect-free leaf definitions, then
calls source_rho6/source_nop, boot and runtime_check on explicitly bound
inputs. The independent closed-subtree checker runs unchanged.

The baseline machine/source and five runtime files are copied from the exact
already recovered intake188 inputs; no predecessor verification is repeated.
The two supplied native tables are checked against explicit hashes; rho6's
literal two-row patch is reconstructed and the inert table's exact 38-row
diff is recorded. Both decoder bindings and complete canonical bijections
are checked. Each blank startup uses two independent sparse/dense simulators
and checks the complete expected tape after 312,617 transitions.

There are five selected jobs: independent rho6 closure, two combined
source/binding/startup jobs and two complete symbolic-runtime jobs. Small
jobs have a 60-second process cap; each runtime has 240 seconds. Assertions
are enabled and processes are serial. Every original input and raw log is
preserved. The runtime covers both guards, even the source-invariant-dead
positive guards; exact ordered case arrays are compared with the delivered
records. The driver does not expose its accumulated row-use set, so this
review does not invent an all-438-rows coverage claim.

Actual status is recorded separately in `execution/result.json`; this note
does not treat supplied records as fresh execution. No wrapper, manifest
suite, ancestor suite, Rocq/Coq/Lean compilation or broad search is run.
