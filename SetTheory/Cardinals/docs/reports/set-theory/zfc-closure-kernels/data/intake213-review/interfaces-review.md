## Archive01: generic scheduling and fixed decoder routes

The scheduler proposition is sound. Strong induction on the remaining program code uses only strict decrease on successful nonboundary steps, preservation of the candidate index during that drain, and the retained possibility of early halting. Boundary induction then uses the index increment followed by another finite drain. It does not need a uniform bound on the next program code. The completeness application additionally needs the concrete boundary-fetch/command-list execution correspondence and a cofinal padded program that halts from every payload. The report explicitly leaves those obligations in the concrete adapter; the two abstract scheduler laws alone would not establish them.

The claimed 44 scheduler duplicate lines concern Enum222/EnumDom and are maintenance-wide evidence, not a measured saving in today's selected endpoint. The current197-provider selection contains EnumPerm and Enum254, not Enum222 or EnumDom. A primary proof simplification should therefore first compare the EnumPerm/Enum254 scheduling clients and keep their state/step definitions unchanged. A new generic module plus wrappers may cost more than it removes unless several clients use it. I did not revalidate the supplied duplicate-line census as a new numerical result.

The tape-independent route proposal is stronger than the current prefix theorem and appears sound. In DecoderPaths.source_path_chain_routed the internal rule selects a literal block and adds its fixed `steps`; the primitive case uses zero internal steps. None of those choices needs the tape. Moving the existential route/port/clock outside `∀ a t` should remove the sample execution at gap0/registers[] and the subsequent port-uniqueness transport in entry_uniform. It must be proved from SourcePath plus the checked role/block data, not from the weaker FullEntry premise alone. Full consumed paths, the final bit, Before/Reads guards, all-cell restoration and the primitive-entry stopping point remain necessary. A proposition-valued existential theorem is sufficient; no elimination from arbitrary Prop proofs into a computational clock is needed.

The Rocq reachable-suffix induction proposal is a reasonable generic replacement for an auxiliary bounded-halting family. Its exact-equality proof uses determinism and absence of outgoing transitions at halts. In the pointwise-register-equality variant, extensional stability of halt and source-step predicates must be supplied by that concrete semantics; it does not follow merely from the exact-equality proposition. The report identifies source-step transport and the zero-step equivalence issue. This is not a current Lean adoption or a proved net saving.

## Archive07: direct full seed on the original model

The decisive present API really does have the stated strength. KEind222.c222_complete takes derivability of `enc (th f)` but hands its model continuation satisfaction of the ORIGINAL named f, whose equality atom is literal equality. It does not merely supply Sat(th f). Its imports do not depend on the seed or indiscernibility modules, so the suggested use introduces no circular completeness argument.

For arbitrary named ψ, let p=¬¬ψ and c=enc(th p). The required support induction is valid: Free(i,f) implies i<enc(f), and Free(i,f) implies Free(i,th f). In the equality case the auxiliary binder x+y+1 differs from both argument names, preserving those free names; outer quantification keeps its original binder. Thus c cannot be free in p. Double negation makes c>1, enabling the exact private-label gate at public roles0/1. The native decoded-zero alias causes no issue in this argument: named falsity is False and the selected matrix code is strictly above1.

`th(bundleNF a b c p)=bundleNF a b c (th p)` holds syntactically because all extra atoms in the bundle are membership atoms. Therefore enc(th(bundleNF0 1 c p)) is the literal enabled native bundle2220 1 c. This derivability fact is separate from the subsequent semantic calculation. The model satisfies the original bundle with matrix p; no assumption Sat(th p)↔Sat(p) is used.

The named request/closure normalization also checks out. The container update commutes past the distinct public-role updates; `sat_ext` removes it from the matrix using free-name freshness. The subset's all-c binder scopes only its membership comparison, not the adjacent request matrix. The outer positive membership-vacuity gate is true at these distinct labels, and classical normalization of the two negative universals yields exactly the root request and closure in SeedProp (with conjunction order swapped). Named falsity needs no irreflexivity premise. FullSeed still includes irreflexivity, and the numerical upper-chain bundle theorem must retain its existing irreflexivity and coincident-role cases.

This can replace the first quotient: fullSeed_direct_of_derivable would yield FullSeed mem, allowing KEndpoint's witness to be e0 instead of mk mem(e0). Current KLowerSeed uses the FullSeed interface without quotient-specific definitions. Ordinary Tarski completeness and all later tagged/bisimulation quotients, well-founded/model construction and endpoint assumptions remain. The current151-line KIndisc222 implementation is a potential deletion cone, not151 lines of established net savings: support and named-semantics proofs must be added first. Sharing the existing update/negation normalization rather than duplicating it is the main implementation opportunity.

## Residual runtime and structural interfaces

All ten runtime reference Lean files in archive07 are byte-identical to the current maintained files (own literal comparison recorded separately). Its source/control bindings therefore still target the current prefix/Home/stepper interfaces. The delivered residual records have exactly the ordered6,176 guards for4,751 source leaves; own JSON arithmetic agrees with926,351 full and705,880 residual abstract iterations, with residual lengths1..207. The proposed residual checker correctly initializes progress=false, preserves the entire consumed PC, retains length/register/branch guards and the existing final target frames, and rejects `.node`. Its q must be tied to the separately proved RoutedEntry, not merely a physical state. Prefix Reach followed by residual Reach1 supplies positive progress even if the prefix has zero duration. The packet correctly identifies the remaining gap: current Covered is defined using old Boolean checkEdge, and semantic prefix+residual success does not imply that a particular fuel-limited old evaluator succeeds. The balanced-lookup membership argument is sound and already exemplified in maintained Lean RMNormalizedBisim. Consumed-path normalization is essential before increment/break. The proposed Rocq extraction and direct tree adapter are uncompiled references, not a reason to alter current Rocq sources. The further endpoint-comparator parameterization could share literal and normalized finite front ends, but requires preserving any clients of their exact relation/checker APIs.
