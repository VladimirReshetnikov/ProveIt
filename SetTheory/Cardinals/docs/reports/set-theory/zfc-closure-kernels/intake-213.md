## Second priority: use one implication basis

Sources 185 and 187 reuse the stronger generic dominated proof for unrestricted implication. The maintained [DominatedImplication.lean:19](../../../../../../Computability/BusyBeaver/Lean/BusyBeaver/ZFC/DominatedImplication.lean#L19) requires a relation with `refl`, `grow_left` and `grow_right`; setting that relation to metalanguage `True` satisfies these laws. The unrestricted rho8 axiom supplies its restricted-row field. This assumes no falsity/truth element, coding injectivity, order transitivity or classical completeness.

The existing core already has K, Peirce, evaluation and the needed composition schema. Given a proved `a → (b → c)`, let `D = (b → c) → c`. Two applications of composition and one final MP yield `b → (a → c)`. Two further MP applications, followed by this exchange, derive S from the existing schemas. This does not assume S or a deduction theorem to obtain S. The preserved Tarski tail still uses rho6 for explosion; unrestricted rho8 alone is not credited with ex falso.

Source 185 puts the pure adapters in `ImplicationalBasis`, leaving a **45-line Lukasiewicz bridge**. That is not the size of the complete proof: its delivered core, basis and bridge total **18,668 bytes / 426 lines**. Source 187's two-file layout totals **19,674 bytes / 435 lines**. Their common comparison pair is 42,715 bytes / 819 lines and includes the raw 58-step predecessor, not our current inlined core. The proposed shared count is 63 MP steps versus 164 across the two independent derivations, excluding the unchanged `lift_right` application on both sides; these are schema/source counts, not expanded proof-term or optimality claims. A maintained successor must retain the phase-eleven inlinings, public `rho8_all`, `composition` and `lift_right`, the numeric adapter and Tarski tail, and synchronize the strict producer.

The separately received `e79d52decb`/`88c8114d21` 56-step Lukasiewicz proof is a legitimate independent alternative, with 15,764 bytes / 314 lines and unchanged public headers. ## Third priority: a semantic coverage interface with exact ports

Sources 181, 183, 185 and 187 preserve the old executable KSim definitions and expose a common semantic simulation. The present boundary is explicit: [KSim.lean:184–185](../../../../../../Computability/BusyBeaver/Lean/BusyBeaver/ZFC/KSim.lean#L184) defines `Covered` using `checkEdge M (consume P d) e = true`. A successful semantic prefix followed by a residual run does not imply that this particular fuel-limited Boolean evaluator returns true. The useful refactor makes both the old checker and a new composed proof producers of one semantic contract.

Source 187 gives the cleanest interface: `SiteContract M entry Q e` separates the complete physical entry from the full consumed source word, and `SiteSpec` stores the path bound once. A six-case `prepend` lemma composes a restoring prefix with the positive residual run, or with halting. The other packets contribute a mixed Boolean/semantic selector and an exact-leaf constructor; adopting all four APIs side by side would repeat the simulation proof.

Every returning contract must quantify over **all natural gap values and all register lists satisfying `Valid`**, retain the full consumed word including implicit zero padding, and reach exactly the old target frame. Increment's spare extension, both decrement branches, path update, gap, growth and overflow remain explicit. Internal `.node` is not executable. The old length-at-most-48 and register-below-nine conditions remain. [KSim.lean:111](../../../../../../Computability/BusyBeaver/Lean/BusyBeaver/ZFC/KSim.lean#L111) returns `Reach1`, not merely `Reach`: positive complete-edge progress is essential when reverse simulation decreases physical halting time. Source 185's zero-step counterexample correctly explains this necessity. A prefix may take zero steps if its suffix supplies positive progress.

The halt interfaces differ legitimately. Sources 181/185 reach an exact state-230 port; Sources 183/187 promise halting conditional on both state-230 rows being absent. They are not definitionally interchangeable for arbitrary tables, although both serve the retained endpoint with that terminal-state premise.

Source 181 supplies a real `000`/CD8 example: the exact two-step prefix `84 → 95 → 27`, followed by both suffix branches, using the actual fast table. This closes **two of 6,176 branch cases** in its submitted component checks. The general `CheckedLeafSuffixes` and source-totality premises remain unproved. Source 184's guarded CB1 pilot and the held phase-nine CB1 idea similarly require exact consumed-word/return guards and the length premise that makes saturated-padding arithmetic valid; no complete 86-contract family or endpoint follows here. The intake does not rerun their compiler records.

Source 186 reads the same ten current runtime-reference files. Its supplied JSON records cover the ordered 6,176 guards and 4,751 leaves, with 926,351 full versus 705,880 residual abstract iterations and residual lengths 1–207. Our own reader confirms this arithmetic and ordering, not execution, compiler speed or universal primitive correctness. Complete suffix coverage, including box behavior and exact return frames, is still missing. None of these proposals permits dropping a current leaf/branch check merely because a selector names it.

## Stronger routes, scheduling and full named seeds

Source 180 proposes choosing the decoder route and its clock independently of the tape. The maintained [KDecoderPrefix215.lean:190–195](../../../../../../Computability/BusyBeaver/Lean/BusyBeaver/ZFC/KDecoderPrefix215.lean#L190) already chooses one `pre bit q op arg` before all input frames, but then states `∀ n vs, ∃ steps`. In `source_path_chain_routed`, each internal source edge chooses a fixed checked block with fixed duration. An induction can move the existential clock outside the tape quantifiers, removing sample-frame selection and subsequent port transport. It must use the exact `SourcePath` and role/block binding, preserve `Before`/`Reads`, the whole consumed path and final bit, restore every tape cell, and stop before the primitive's terminal action. The weaker existing entry proposition alone does not supply this stronger uniform clock.

The scheduler argument uses strong induction on the decreasing residual program code and then boundary induction on the candidate index. It retains early halting and needs no uniform bound on the next candidate's code. Completeness additionally requires the concrete fetch/list-execution correspondence and cofinal padded programs that halt from every payload. Its claimed 44 duplicate lines concern legacy `Enum222`/`EnumDom`; at the review cutoff, the primary selection used `EnumPerm` and `Enum254`. This maintenance-wide count is not a measured primary saving. Source 182's general option-composition and finite-search lemmas are sound on source review but still need their concrete instantiations. Source 180's pointwise-register Rocq variant also needs extensional transport of step/halting, beyond the exact-equality theorem.

Source 186's direct full-seed route uses a stronger existing model interface than the current equality-free bridge. [KEind222.lean:305–307](../../../../../../Computability/BusyBeaver/Lean/BusyBeaver/ZFC/KEind222.lean#L305) assumes derivability of `enc (th f)` but gives its model continuation `Tarski.Sat mem e f` for the **original named formula**, with literal equality. It does not give only satisfaction of `th f`. This completeness theorem imports neither the seed nor indiscernibility module, so the suggested application is not circular.

For arbitrary named ψ, take `p = ¬¬ψ` and `c = enc (th p)`. The needed support inductions say that a free name i is below `enc f` and remains free in `th f`. The equality translation's auxiliary binder `x+y+1` differs from both argument names. Hence c is not free in p, while c>1 keeps it distinct from public names 0 and 1. The bundle's other atoms are membership atoms, so `th (bundleNF a b c p) = bundleNF a b c (th p)` syntactically; its encoding is the literal enabled native bundle. The semantic continuation satisfies the original bundle with matrix p. No unproved equivalence between `Sat (th p)` and `Sat p` is used.

The request/closure normalization must preserve the private binder's exact scope: its subset quantifier binds the membership comparison, not the adjacent matrix. Freshness removes only the container update from that matrix. Literal named falsity and classical double-negation normalization yield the desired `SeedProp`; the existing upper numerical-bundle theorem still needs irreflexivity and its separate coincident-public-role case. By comparison, [KSeedModel222.lean:81](../../../../../../Computability/BusyBeaver/Lean/BusyBeaver/ZFC/KSeedModel222.lean#L81) currently requires `hψ : EqFree ψ`. A direct full seed could remove the first indiscernibility quotient, while retaining ordinary completeness, all later model/tagged-quotient constructions and the endpoint assumptions. The 151-line `KIndisc222` is a possible deletion cone, not a net saving before the new support and named-semantics lemmas are built.

## Retained limitations and next checks

It does not refute the growth-closed restricted interface, the unrestricted `True` adapter, numerical calibration or ZFC, and it does not prove each growth axiom independently necessary. Balanced certificate lookup is already present in maintained Lean; the packets' Rocq storage and reachable-suffix proposals are retained research, not a new Lean saving or a new Rocq endpoint.

The preserved dossiers cover all eight ordinary manuscripts and their selected proof bodies. They keep inherited notices, failed attempts, bounded negative results and the distinction between delivered compiler logs, own finite readers, and later selected kernel checks. No smaller machine, changed binary table, unconditional nonhalting claim or new internal PA/ZFC derivation follows. The next adoption gates are exact producer/source synchronization and current dependency/typed-endpoint checks for imports and shared logic; runtime adoption additionally needs complete positive suffix contracts. Those gates are separate from this completed written reconciliation.
