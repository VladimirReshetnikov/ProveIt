# Computational supplement to Report241

## The mathematical boundary

The article's exact family count, run-set upper bound, and uniform inequalities
prove its asymptotic result for all sufficiently large lengths. The programs below test finite
instances and reproduce the deliverables. No numerical extrapolation is used
to claim an exponent, root constant, prefactor, or asymptotic error certificate.
The operational code cutoffs are not hypotheses of the theorem. The
non-P-recursiveness corollary is a self-contained analytic proof using a
radial differential-system bound and Cauchy coefficient estimates; no finite
code test is represented as certifying that corollary.

## Counts from independent routes

`code/exact_counts.py` implements the two source recurrences in Sections 2.3
and 2.4 of Conway et al. (2022), also transcribed in the article. The initial
state for 100 is f(n-1,0,0,0); for 110 it is f(n-1,0,0,{0}). Empty words count
once. Both prefixes are recomputed through n=15 against the source-linked
fixture `code/source_prefixes.json`. These compressed-state recurrences are
not used to generate the construction or to prove its validity.

An independent recursion generates every ordinary ascent sequence through
n=9 directly from the defining prefix bound. It checks the new letter before
adding the rise into it. On every one of the resulting 37,883 words (summed
over lengths zero through nine), all index triples are tested literally for
000, 100, and 110, and compared with the independent linear-time detectors.
The single-class counts are compared with the source recurrence fixture and
the common-class counts with the published triple-class fixture.

The linear-time detectors have the following invariants:

- 000: a label cannot occur a third time
- 100: a label occurring after a larger earlier value becomes blocked from
  reappearing; an earlier occurrence before that larger value is harmless
- 110: once a label repeats, every later letter must be at least that label;
  the largest repeated label is the strongest current threshold

A separate common-class recursion extends valid prefixes and checks every
pair of earlier indices against the proposed new last letter. It does not
use the linear detector or either source recurrence to prune. It reproduces
n=0..11, including the eleven positive-length terms of Callan-Mansour Table 2,
Class 36. Its n=0 value is the independently supplied empty-word convention.

## Exact construction and padding

`code/construction.py` implements the doubled-seed family only. Starting at
k_0=m, it uses k_(j+1)=k_j-ceil(k_j/b). Each block's positions are divided into
chunks of size b, with a shorter final chunk if needed; labels within each
chunk increase. The block count is exactly

    H_b(k)=k!/[(b!)^floor(k/b) (k mod b)!].

Permutations are generated by recursively choosing the label subset of each
ordered chunk and sorting it. An independent filter over all permutations
checks this generator and the multinomial count for k=0..7 and b=2..8
(56 parameter pairs). The empty-block test uses H_b(0)=1.

For every m=1..7 and b=2..8 (49 pairs), the verifier enumerates the complete
family, compares its cardinality and distinct-word set with the product of
H_b(k_j), and checks the deterministic length. It recovers each block and
record from its fixed positions, thereby testing the stated inverse map.
These 49 families contain 3,116 distinct words in total (counted separately
for each parameter pair). Each word is checked by a prefix-by-prefix
recomputation of ascent legality,
literal forbidden triples, the independent linear predicates, and the final
maximum/ascent invariant. Fresh-record padding lengths 0, 1, 2, and 7 are
checked literally, giving 12,464 word/padding checks. At padding length 7
the full distinct padded set is also
compared with the exact cardinality.

Larger finite tests use m in {1,2,50,100,1000}, b in {2,7,20,50}, five fixed
pseudorandom seeds per pair, and 30 fresh-record padding letters. They check
legality, all three linear avoidance predicates, and the final invariant.
The maximum padded sample length is 47,830. These 100 deterministic samples
are supplementary finite tests, not random
proofs. Receipts record all parameters, lengths, and hashes of the ordered
sample words. No random source is consulted at build time.

The exact telescoping inequality

    bm-(b-1)T <= sum(k_j) <= bm

is checked for every m=1..64 and b=2..128 (8,128 pairs). The analytic entropy
estimate and the choice b=ceil(log n) are proved in the article, not certified
by floating arithmetic here. Empty-word record padding to (0,1,2) is a
separate boundary test.

## Independent occurrence encoding reconstruction

`code/upper_bound.py` checks the finite upper-bound encoding for both classes.
For 110 it marks non-first occurrences; for 100 it marks non-last occurrences.
Its immutable code contains the word length, marked positions and their
weakly increasing labels, the increasing-run lengths, and the retained-label
set in each run. Decoding fills marked positions from the skeleton and assigns
the sorted retained set to the other positions, validating legality and the
claimed first/last occurrence statuses.

For all raw ascent words through n=9, literal forbidden triples select each
class independently. This yields 24,363 class-word encodings in total, 99,665
run candidate checks, and 15,276 distinct skeletons. Words belonging to both
classes are checked once with each distinct marking convention. Every code
must reconstruct exactly its input, and no two selected words may have the
same code for a fixed pattern and length.

At each run the code checks unseen-candidate counts. For 100 it separately
tracks unfinished labels and compares that set with the literal intersection
of past and future labels in the original word; its size must be at most
r-q, where r is total repetition count and q is repeats in the decoded prefix.
Both candidate unions must have at most r+ell+1 elements. All labels and
prefix ascent bounds are checked during reconstruction. The number of runs
is at most r+1, and retained labels follow the prescribed increasing order.

The exact product of binomial run bounds is compared with the Vandermonde
bound and with binom(n+(r+1)^2,n-r). Grouping every tested word by skeleton
checks that the observed branching count is below the product bound. The
finite skeleton count and total bound

    16^n sum_{r=0}^{n-1} binom(n+(r+1)^2,n-r)

are checked with exact integers. Empty-word behavior is a separate convention.
The script does not numerically optimize the binomial coefficient or infer
an asymptotic theorem from the tested lengths.

## Public finite bounds

All exported computational helpers validate integer types explicitly and
reject bool where an integer is required. Words must be lists or tuples of
nonnegative integer labels, with length and label values at most 100,000.
Literal triple testing is limited to length 80; raw ascent generation to
n=0..9; source recurrence counts to n=0..15; common-class generation to
n=0..11. Each recurrence call has a 1,000,000-state and 12,000,000-transition
budget. The common-class recursion has a 2,000,000-transition budget.

Construction stage specifications allow m=1..2000 and b=2..128, subject to
constructed length at most 100,000. Exact product counts allow m=1..64;
individual block counts allow k=0..128. The enumerated family allows m=1..7
and at most 25,000 words; the block generator allows at most eight distinct
labels. Padding checks the final length and label bound. Deterministic
sample seeds are integers from 0 through 2^32-1. The upper-bound encoder, decoder, finite binomial bound, and Vandermonde
helper allow total length at most 64; the exhaustive reconstruction verifier
allows lengths zero through nine. Encodings must be finite tuples of the
specified shape and every label, run length, marking and status is validated.
CLI parameters have the same
bounded domains and are checked before expensive work or output creation.

Each process enforces Python's integer decimal conversion limit of 640
digits. Child command lines explicitly use `-B` and
`-X int_max_str_digits=640`; environment variables repeat these settings.
Checks use explicit exceptions and remain active under `python -O`.

## Immutable build and archive replay

`build.py` requires a complete manifest match: file hashes, names, and implied
directories. Symlinks, special entries, unexpected files or directories,
malformed manifest entries, and package files outside the public allowlist
are rejected. The inventory is bounded to 500 files, 1,000 entries, and
32 MiB; the manifest is at most 128 KiB. Public source names are the listed
required files plus section TeX files. No third-party research inputs can
silently enter a manifested build.

A new external output directory is required. Outputs cannot be placed inside
the source package, under a live or dangling symlink ancestor, through dot
or dot-dot path components, or in an existing directory. Each created file
uses exclusive creation. These checks do not defend against a hostile process
racing filesystem operations.

The builder checks four frozen receipts, compiles a disposable copy of the
TeX sources inside the validated external logs directory, using a private
format/cache and three passes, with shell escape
disabled and restrictive TeX file-access settings. It rejects missing glyphs,
undefined references, and overfull boxes. Dates and trailer identifiers are
fixed in TeX. SOURCE_DATE_EPOCH is 1791158400 (5 October 2026, UTC), and
LC_ALL and timezone are fixed. Individual build children have a 180-second
timeout; archive replay allows 900 seconds for each complete child build,
and guard probes allow 30 seconds.

The PDF must match the included frozen PDF byte for byte. Source hashes are
checked before and after the complete build and archive assembly. The ZIP
uses a single Report241/ prefix, sorted members, uncompressed storage,
5 October 2026 00:00:00 timestamps, and Unix regular-file mode 100644. It
includes the PDF, receipts, and manifest, but never itself or build logs.

`code/reproduce_zip.py` checks the actual supplied ZIP against the trusted
package, extracts independent normal and optimized source copies, runs both
builders, and compares every member byte and metadata field, full ZIP bytes,
PDFs, all four mathematical/guard receipts, and build-check output. It also
requires source-tree and input-archive immutability. A source hash inventory
is an integrity record, not evidence of authorship or an external review.

Guard fixtures use checked external /tmp rather than ambient TMPDIR/TEMP/TMP.
The package includes bounded negative tests for public API/CLI errors,
assertion-free validation, conversion caps, enumeration budgets, output
paths, manifests, and ZIP integrity. The frozen guard receipt gives the exact
cases tested (409 cases in this revision). These are regression tests, not a general security proof.

## Running the checks

```sh
python -B code/exact_counts.py
python -B code/construction.py
python -B code/upper_bound.py
python -B code/guard_tests.py
python -B -O code/guard_tests.py
```

The default outputs are the four included receipts. Output files, if
requested, must be new and outside the frozen package. The README gives the
full build and actual-archive replay commands. Reproducibility is verified
on the toolchain recorded by the external build receipt; a different TeX
installation can change PDF bytes while leaving the proof unchanged.

## Recorded validation toolchain

Python 3.12.14; pdfTeX 1.40.26 (TeX Live 2025/dev/Debian). In the authoring
environment, count checks took about one second, construction checks about
seven seconds, upper-bound reconstruction about three seconds, and guards
about one to two seconds. Timings are descriptive,
not performance guarantees and are excluded from the deterministic receipts.
