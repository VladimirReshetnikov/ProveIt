# Report203: fat-tree reproducibility programs

This directory contains deterministic code and generated data supporting the
fat-tree report for [OEIS A055779](https://oeis.org/A055779). The mathematical
proof is in the report. Finite exact tests and symbolic algebra check stated
identities and implementations; numerical diagnostics do not prove an
asymptotic theorem, uniformity, a remainder constant, an onset, or a unique
rounding rule at sequence thresholds.

## Toolchain and quick start

The reference replay uses **CPython 3.12.14**, **SymPy 1.14.0**, and
**mpmath 1.3.0**. The Python version is recorded in `.python-version`, and the
third-party versions are pinned in `requirements.txt`. Exact checks and their
runner use only Python's standard library. Third-party scripts reject versions
other than the pinned ones. The programs have no network, private-directory,
source-PDF, image, TeX, or external-data dependency. No local absolute pathname
is embedded in an output.

From this directory:

```sh
python check.py --exact
python -m pip install -r requirements.txt
python check.py --all
```

To retain verified regenerated JSON in a fresh directory outside this code tree:

```sh
python check.py --all --output ../replayed-code
```

The runner executes every selected program normally and under `python -O`,
checks byte-for-byte equality between modes and against `expected/*.json`, and
prints a JSON replay receipt. With `--output NEW_DIR`, it then writes the freshly
recomputed bytes to `NEW_DIR/expected/*.json`; the directory must not already
exist. The receipt is stdout, so a calling build can capture it where desired.
No maintained source or fixture is overwritten. Bytecode writing is disabled
both in the programs and in the subprocess environment. Every check uses an
explicit exception, and the runner also rejects `assert` statements in the
selected source files.

Each computational program writes its sole result to stdout. For an individual
replay, redirect it to a separate file and compare rather than replacing the
fixture:

```sh
python exact_checks.py > /tmp/report203-exact.json
cmp expected/exact_checks.json /tmp/report203-exact.json
python -O symbolic_checks.py > /tmp/report203-symbolic-optimized.json
cmp expected/symbolic_checks.json /tmp/report203-symbolic-optimized.json
```

The fixture files were generated by these programs, then verified through the
normal/optimized replay. They are expected outputs, not independent empirical
data or premises of the proof. Hashes in the replay receipt are calculated
from the actual regenerated bytes. A deliberate program/formula change requires
reviewing and explicitly regenerating the corresponding fixture; the checker
never silently blesses changes.

## Files and implementation provenance

- `coefficients.py`: adapts the report producer's original polynomial-recurrence
  generator. It emits angular cumulants through index 8 and the expanded exact
  rational formulas for c1, c2, and d2
- `exact_checks.py`: adapts the separately written mathematical audit's exact
  implementation, with an added general finite-order inverse recursion and
  a composition-based check of that recursion
- `symbolic_checks.py`: adapts the audit's independent fixed-M differentiation
  and formal exponential-recurrence implementation; it reads only the expected
  coefficient JSON, not the producer's program
- `numerical_diagnostics.py`: adapts the audit's mpmath diagnostics and imports
  the released exact coefficient engine. Its output is explicitly labelled
  `DIAGNOSTICS ONLY`, with `interval_certificate: false`
- `check.py`: release replay interface; standard library only
- `expected/coefficients.json`, `expected/exact_checks.json`,
  `expected/symbolic_checks.json`, `expected/numerical_diagnostics.json`:
  committed expected stdout, including one terminal newline

The producer and audit implementations were originally developed separately;
this release reuses and adapts both. It does **not** present copied audit code as
a fresh independent implementation. Distinct algorithmic routes are identified
below, including shared components. Code provenance is separate from priority
for the mathematics. The exact model and formulas are existing material; this
package makes no originality or absence-of-prior-art claim.

## Exact finite coverage

`exact_checks.py` uses `fractions.Fraction`, integers, and the standard library.
Its counters record executed checks, with the following scopes:

1. The first 17 reference A055779 terms are compared to the rooted-assembly
   recurrence
2. The k-sum and labelled rooted-block recurrence agree for n=1,...,40 and
   M in {1/10, 1/2, 1, 3/2, 2, 10, 1000}: 280 comparisons. The recurrence
   keeps v=nM fixed throughout each calculation. At these same 280 points it
   checks the monotonicity inequality and exact deficit normalization
3. Actual original-vertex edge sets are enumerated for every set partition
   through n=6. This examines 278 partitions and 42,238 candidate edge sets;
   each partition is checked separately against the weighted-Cayley count,
   and six aggregate M-polynomials are checked against the k-sum. Distinct
   original edges retain their multiplicities even when their contracted block
   endpoints coincide. The enumerator uses neither a Pruefer sequence nor the
   Cayley formula to construct its count; union/find rejects quotient cycles
4. The direct multi-index saddle recipe and formal exponential differential
   recurrence agree through order 6 at seven rational r values:
   0, 1/1000000, 1/20, 1/10, 1/4, 2/5, 4/9. Both engines share exact cumulants
   computed by formal composition. The value 4/9 is an algebraic test slightly
   beyond r(1), not an extension of the M>=1 theorem. The endpoint test checks
   the single vector c0,...,c6=(1,0,...,0), hence six positive-order cancellations.
   Additional calls give 43 odd-Gaussian cancellation checks in total
5. Exact bisection checks 288 threshold cases at, below, and above A_n(M):
   n=2,...,25 and M in {1, 3/2, 2, 10}. The displacement is one third of the
   smaller adjacent exact gap, so each expected integer inverse is
   unambiguous. Four further cases check y=1. These tests concern the actual
   integer sequence, not rounding of an asymptotic center
6. `inverse_coefficients(L,B,ds,J)` implements the fixed-M formal inverse rule
   for arbitrary prescribed finite J, with rational inputs and nonzero L.
   `ds[0]` is unused and `ds[j]` is d_j. The test uses six rational (L,B)
   pairs through p8, checking 54 coefficients of a separately composed formal
   log/geometric-series residual and 48 instances of the linear coefficient L.
   It also checks p0, p1, p2 at all six pairs. These are formal algebra tests,
   not a uniform-in-M inverse claim. Testing through p8 does not prove every
   order; the report supplies the inductive argument
7. Both elementary finite-n Bonferroni bounds are checked on 3,240 pairs each:
   n=1,...,40 and d=0,...,80. Fixed-order remainder bounds for J=0,...,5
   give another 19,440 checks, including d>=n and n=1
8. Negative controls distinguish omission of M, omission of n squared, and
   the incorrect sign on the squared-third-cumulant contribution

Counter totals count operations, not independent theorems. For example,
`endpoint_stirling_cancellation` is one vector comparison, and each
`saddle_engines_through_order_6` check compares seven coefficients.

## Symbolic checks and coefficient generation

`coefficients.py` applies P_(j+1)=(1+r)P_j+rP'_j, then the explicit saddle
terms and Stirling convolution. `symbolic_checks.py` instead differentiates
M z exp(z) with M fixed and substitutes the saddle relation afterward. It
expands the nonquadratic exponential by its differential recurrence and
checks c1, c2, d2 against the generated coefficient fixture as symbolic
identities, not sampled evaluations.

The symbolic checks also cancel the inverse recursion through p4, verify the
printed p0/p1/p2 formulas and fixed-M bounded-p0 identity, generate elementary
factor-list polynomials and their Poisson expectations through order 6, check
15 literal integer factor lists, and reconcile the p/r prefactor and q/M
parameter identities. `derived.p1_to_p4` uses P=p0=B/L; this avoids needlessly
expanding B/L inside long expressions. The Poisson coefficients are the
coefficients of exp(-lambda) R_n(lambda), with their alternating signs already
included. All-order existence remains a proof statement in the report.

## Separately labelled numerical diagnostics

`numerical_diagnostics.py` uses 100-decimal mpmath working precision and prints
35 significant digits. No rounding is outward-certified. It evaluates:

- 24 asymptotic samples: n in {20, 80, 320, 640}, with fixed M=1,2,10,10^12
  and moving M=n,n^2; scaled remainders are given for J=0,1,2,3
- 12 fixed-M inverse samples, M=1,2,10, at the actual A_n thresholds; the
  residual centers X0,X1,X2 do not imply a guaranteed ceiling rule
- 12 Poisson-window samples, lambda=0.1,1,4, including the Poisson tail beyond
  the deficit support in the total-variation calculation

The moving-M diagnostics apply only to the uniform forward expansion. The
inverse diagnostics keep M fixed. Reported bounds in the Poisson table are
numerical evaluations of an analytically proved inequality; neither those
values nor the asymptotic samples are certified intervals. Finite diagnostics
cannot determine a sharp Poisson regime or prove a general error bound.
