Report216
Fixed slope partition extremes and inverse asymptotics
4 October 2026

RESULT AND SCOPE
For fixed integers k>=2 and b>=0, E counts nonempty partitions with largest
part M=kL+b, and T counts M>=kL+b, where L is the number of parts. The report
proves an exact finite-product sieve, every fixed half-power asymptotic order,
and a Lambert W_{-1} inverse with a shrinking two-ceiling threshold bracket.
E(2,0) is A237753; T(2,1) is A237751. Kotěšovec's 2024 leading equality law
is credited. There is no global historical novelty, k=1, growing-parameter,
growing-order, effective-constant, or resummation claim.

QUICK EXACT CHECKS (STANDARD LIBRARY ONLY)
From the Report216 directory:
    python -B code/reproduce.py --exact --check
    python -B -O code/reproduce.py --exact --check
    python -B test_package_guards.py
    python -B -O test_package_guards.py

Python 3.10 or later is needed; saved receipts record Python 3.12.14.
The exact calculations require no third-party Python package. They compare
98 count cases through n=160 against a separate bounded-part/exact-length DP,
72 algebra cases through order6, Q through ell=20, and 690 depth checks.
Twenty-three mathematical-input and 26 package-input rejection controls use
explicit exceptions that remain active under -O. The algebraically distinct
checking paths do not constitute a separate analytic proof or a security audit.

NUMERICAL DIAGNOSTICS (OPTIONAL)
    python -B code/reproduce.py --diagnostics --check

This additionally requires mpmath 1.3.0 (see requirements.txt). It freshly
recomputes the integer arrays through n=10001, then uses 80 decimal digits for
16 selected forward/inverse comparisons. The full arrays are not distributed.
Each target y=X(n) is checked against every preceding exact count, so nu(y)=n
for those examples is verified by finite arithmetic.

These floating-point approximations are NON-CERTIFIED diagnostics. They are
not interval bounds, do not determine a valid asymptotic O-constant or onset,
and do not justify an unconditional ceiling of an inverse center. Higher
truncation order can be substantially worse at a fixed moderate index.

FULL OFFLINE REBUILD
Needs Python with mpmath, and a working TeX distribution providing pdftex,
pdflatex, kpsewhich, the LaTeX article/AMS packages, hyperref, geometry,
microtype, fancyhdr, booktabs, and Latin Modern fonts. The distributed PDF was
built with pdfTeX 1.40.26 (TeX Live 2025/dev/Debian). No network is used.
Run from Report216, choosing an output directory that does not yet exist:
    python -B reproduce.py --out /tmp/report216-rebuilt

If the original ZIP is available, verify its actual member bytes as well:
    python -B reproduce.py --out /tmp/report216-rebuilt-with-zip \
        --reference-zip /path/to/Report216-reproducibility.zip

Repeat with python -B -O for an optimized outer invocation if desired.
The output parent directory must exist; the target must be new and outside
the source tree. The command does not overwrite the supplied package. It:
- validates a strict manifest and source inventory
- regenerates all exact receipts in both normal and optimized Python
- regenerates all optional diagnostics, large counts, and both TeX tables
- runs package rejection controls in both modes
- builds a private TeX format and font map in the output directory
- reaches PDF byte stability, with no overfull boxes or unresolved references
- compares all generated bytes with the provided baselines
- writes and verifies a fixed-timestamp ZIP and its member bytes

The new directory contains Report216/, Report216-reproducibility.zip,
REPRODUCTION.json, and local logs/fresh output. Logs, private TeX formats,
page renders, and other build intermediates are not part of the public ZIP.
The --initialize option is only for authoring a new baseline and bypasses
baseline manifest comparison; ordinary verification must not use it.

MANIFEST AND BYTE REPRODUCIBILITY
MANIFEST.json lists SHA-256 digests of every public package file except the
manifest itself. SOURCE_FILES.txt is the explicit archive inventory excluding
Report216.pdf and MANIFEST.json. The build uses ZIP_STORED, fixed 2026-10-04
member timestamps, fixed permissions, sorted entries, and deterministic PDF
metadata. On the same recorded toolchain the PDF and ZIP reproduce byte for
byte. Different Python versions change recorded provenance, and different
TeX/font or mpmath versions can change bytes. That is not a mathematical
failure; use code/reproduce.py --exact --out /tmp/new-results to inspect a
fresh exact result on a different interpreter rather than treating a changed
provenance string as an identity failure.

The hashes detect accidental modification relative to the supplied package;
they are not an external authenticity signature. The guard tests are practical
input checks and not a comprehensive security assessment.

No publication, repository modification, external upload, or OEIS edit is
performed by the reproduction commands.
