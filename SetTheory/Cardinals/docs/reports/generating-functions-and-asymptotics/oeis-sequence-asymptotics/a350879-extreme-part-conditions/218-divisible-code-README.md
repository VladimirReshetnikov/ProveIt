# Exact reproduction: partitions with divisible extrema

This directory is the complete public computational source for the report. It
uses Python 3.10 or later and the standard library only. It reads no saved
receipts, count tables, private notes, source papers, or network resources.

From the extracted report directory:

```sh
python code/reproduce.py --output ../report218-exact --N 1000
python code/test_reproduce.py
```

The substantial count mode is:

```sh
python code/reproduce.py --output ../report218-exact-4000 --N 4000
```

The inner reproduction script creates its output directory if needed and replaces
its named generated files when that directory already exists. Use a fresh output
directory to preserve prior results. The top-level `rebuild.py` is stricter: it
requires a new or empty destination and never overwrites its input bundle.

`--N` must be at least 1000 because every reproduction includes the finite
certificate at index 1000. Increasing it extends the original extrema count,
unrestricted partition cross-check, exact sandwich, and CSV. The independent
conjugate comparison remains through 220. The original counting program has
cubic-scale running time; 4000 is substantially slower than 1000. The conjugate
DP uses quadratic storage and is deliberately run at its separate, stated
verification depth.

## Outputs and semantics

- `receipt.json`: deterministic, machine-readable exact results and check ranges
- `exact_values.csv`: columns `n,p,a117086,deficit`, from 0 through `N`
- `radial_coefficients.tex`: tabular fragment giving `g_1` through `g_12`
- `forward_coefficients.tex`: tabular fragment giving `c_0` through `c_5`
- `exact_counts.tex`: selected exact count tabular fragment
- `finite_enclosure.tex`: certified bound and exact-value tabular fragment
- `verification_summary.tex`: ranges and counts of computational checks

The report directly inputs the count, radial, enclosure, and verification tables;
the forward-coefficient table is an additional reusable fragment. `receipt.json` additionally
contains all radial coefficients through degree 20, all derivative polynomials
through index 20, the exact rational polynomials `c_0,...,c_12` in `A^-1`, and the
40 inverse-specialization coefficient lists. Large integers and rationals are
stored as decimal strings or `numerator/denominator` strings. A polynomial in
`A^-1` is a map from its nonnegative exponent to its rational coefficient.
The version-2 receipt also includes 19 exact rational endpoint comparisons for
the uniform reciprocal-minimum error bound valid for every `n>=90`.

All outputs regenerate from the code. There are no timestamps, running times,
absolute paths, random seeds, Python optimization-mode fields, or platform
identifiers in the receipts. Their CSV SHA-256 covers generated bytes, not a
precomputed reference file. The normal and optimized interpreter modes produce
byte-identical files for the same `--N`; for example:

```sh
python code/reproduce.py --output /tmp/deficit-normal --N 1000
python -O code/reproduce.py --output /tmp/deficit-optimized --N 1000
diff -r /tmp/deficit-normal /tmp/deficit-optimized
```

At zero, the bookkeeping conventions are `p(0)=1`, `a(0)=0`, and `D(0)=0`.
The mathematical definition `D(n)=p(n)-a(n)` is used only for `n>=1`.

## Checks and genuine independence

1. **Unrestricted partitions.** Euler's pentagonal recurrence is compared with
   an unrestricted-part knapsack DP through `N`.
2. **Original divisible-extrema counts.** The minimum/maximum double sum removes
   one copy of each extreme. A bounded-part DP handles what remains. Singletons
   are added separately, including the equal-extreme case correctly.
3. **Conjugate interpretation.** A distinct two-dimensional DP counts partitions
   by total size and length before adding their maximum `M`. If `j` copies of
   `M` are added, the admissibility condition is that `j` divide the previous
   length. Under conjugation this is the original divisibility condition. This
   algorithm does not reuse or re-index the original extrema DP. Both counts
   agree through 220, and its unrestricted totals also agree with `p(n)`.
4. **Direct enumeration.** A third route generates every partition of each
   positive integer through 35, then tests its actual extrema.
5. **Fourier identity.** Direct minimum/maximum-residue counts are compared with
   the polynomial identity, including its finite correction, in the exact group
   ring `Z[z]/(z^m-1)`. There are 49 pairs (`1<=k<=7`, `2<=m<=8`), each tested at
   every index 0 through 70. No approximate roots of unity are used.
6. **Radial coefficients.** One route multiplies truncated exponential series
   in the telescoped formula. The other forms the finite original
   minimum-weight polynomial in `q` and takes its exact power moments. They
   agree through degree 20. These are different finite computations, though
   both implement identities proved in the article.
7. **Derivative and forward coefficients.** The differentiation recurrence for
   `Q_l` is checked against its factorial formula through 20. The generator for
   `c_0,...,c_12` is checked a second time with moment-derived radial
   coefficients and the factorial derivative formula.
8. **Inverse series.** For each statistic, the logarithmic equation is solved
   triangularly through degree 12. Every triangular coefficient and its
   cancellation are checked. A separately evaluated multiplicative equation,
   using an exponential series instead of a logarithm, must also have zero
   residual through degree 12. The displayed first three generic formulas are
   checked at each specialization. The 20 positive rational values of `A` are
   recorded in the receipt. These specialization tests support implementation
   correctness; the formal all-order proof is in the article.
9. **Exact threshold shortcut.** All partition and `a` breakpoints from indices
   1 through 219, and the half-integers immediately following them, are checked
   against `nu_p(y)<=nu_a(y)<=nu_p(y)+1` for `y>1`.
10. **Finite certificate.** The specific rational enclosure described below is
    regenerated and compared with the freshly computed exact deficit.
11. **Certified inverse shortcut.** Complementing the deficit enclosure bounds
    `a(m)` from below and above. At `m=nu_p(y)=1000`, eight rational endpoint and
    adjacent-half-integer tests verify the inclusive lower-bound decision, the
    strict upper-bound decision, and exact-count fallback. Each decision is
    compared with the regenerated value of `a(1000)`; the exact sandwich then
    establishes whether the threshold is 1000 or 1001. In particular equality
    at the upper bound does not incorrectly select 1001.
12. **Uniform reciprocal-minimum error.** `uniform_certificates.py` derives strict
    rational enclosures for pi using Machin's identity and alternating arctangent
    sums, and for e using its positive series and a geometric tail. Its 19 exact
    endpoint comparisons certify the onset before 90, the lower bounds for `w`
    and `p/B`, the eta-product bound, the growing-cutoff endpoint inequalities,
    and the cubes of both terms bounding `delta/L`. These are finite rational
    checks, not samples of `D` or `W`. The article's analytic identities and
    monotonicity arguments extend them to every parameter in the stated range.

Every mathematical public entry point rejects inappropriate types and domain
values. Integer parameters exclude `bool`, and rational inputs accept only
`int` or `fractions.Fraction`, also excluding `bool`. All correctness guards use
explicit exceptions, not `assert`, so `python -O` cannot disable them. Invalid
input probes and a deliberately failing runtime-guard probe run in every
reproduction. `test_reproduce.py` supplies additional boundary and regression
checks independently of saved output files.

## Certified finite enclosure

For `n=1000`, `K=3`, `r=24/25`, rational arithmetic gives

```
472725439956575758375747068463 <= D(1000)
                             <= 481748117158362419220289068699
D(1000) = 479221051806021018167049012329.
```

The product bound uses 1771 factors. Its finite product is rounded upward after
each multiplication on a 100-decimal-place rational grid. With
`delta=r^(J+1)/((1-r)(1-r^(J+1)))<10^-30`, the omitted logarithmic tail is bounded
by `delta`, and `exp(delta)<=1/(1-delta)` supplies a rational multiplier. The
receipt contains the exact product upper bound and exact logarithmic-tail
bound.

For each positive rational exponential argument `x`, the Fourier error uses
`exp(-x)<=1/sum_{j=0}^140 x^j/j!`. The exact shifted-partition expressions for
`s_K(1000)` and `u_K(1000)` and an integer upper bound on the Fourier error are
also recorded. The returned bounds use an outward integer ceiling/floor. All
cosine gaps for `K<=4` are exact rational numbers; the public enclosure function
rejects larger `K` rather than silently approximate them.

The enclosure validates this finite numerical instance. It does not certify
asymptotic remainder constants, onset, floating-point errors, or a universal
rounding rule for smooth inverse centers. No floating-point diagnostics are
part of this package.

## Importable functions

Import `reproduce.py` directly for `partition_numbers(N)`,
`partition_numbers_knapsack(N)`, `divisible_counts(N)`,
`conjugate_counts(N)` (counts and unrestricted totals),
`enumerate_partitions(n, maximum=None)`, `radial_coefficients(L)`,
`radial_moments(L)`, `derivative_polynomials(L)`,
`correction_coefficients(R)`, `fixed_minimum_residues(N,k,m)`,
`fourier_reduction(N,k,m)`, `inverse_coefficients(beta,d,M)`,
`partition_product_upper(r,places=100)`, `exp_negative_upper(x,terms=140)`,
and `finite_enclosure(n,K,r,p)`. Underscore-prefixed helpers are internal.

`derivative_polynomials(L)` returns coefficients in `x=t/A`, so its `ell`th
list represents `Q_ell(t)`. `inverse_coefficients` accepts
`d=[1,d_1,...,d_M]` and returns `[v_1,...,v_M]`.
`finite_enclosure` revalidates its supplied partition table by regeneration.

## Uniform-bound endpoint module

`uniform_certificates.py` can be run separately; it prints deterministic JSON:

```sh
python code/uniform_certificates.py
python -O code/uniform_certificates.py
```

The same result is included automatically in every main `receipt.json`. It uses
no floating-point arithmetic, third-party packages, or saved inputs. Its public
functions are `arctan_bounds(x,terms)` for rational `0<x<1` and positive integer
`terms`, `e_bounds(degree=6)` for positive integer `degree`, and
`endpoint_certificates()`. Integer and rational parameters exclude `bool`;
incorrect types or domains raise explicit exceptions. Eighteen invalid-input
probes and a caught false-condition guard probe run with the certificates.

For a process-level negative control, both following commands must fail with
exit status 1 and `RuntimeError: Certificate failed: deliberate false-check
negative probe`. They deliberately fail before computing any true certificate:

```sh
python code/uniform_certificates.py --negative-probe
python -O code/uniform_certificates.py --negative-probe
```

Optimization cannot remove any certificate guard. The module does not evaluate
the transcendental error bound numerically or claim that a first passing
pointwise epsilon comparison establishes an onset for all larger integers.
