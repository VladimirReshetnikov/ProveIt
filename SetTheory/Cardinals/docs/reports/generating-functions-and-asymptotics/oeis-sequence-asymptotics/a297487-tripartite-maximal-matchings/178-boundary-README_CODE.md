# Exact verification code

## Core arithmetic

`code/verify.py` uses `fractions.Fraction`, integers and a three-coordinate field
implementation for `Q(a)` with `a^3=1/4`. Field multiplication reduces the cubic
relation, and inversion solves a three-by-three rational linear system. No
floating-point arithmetic or external symbolic package is used by the core.

Bernoulli numbers are generated recursively with `B1=-1/2`; the Faulhaber
polynomial is checked at 81 integer arguments. Sparse Laurent powers in `q`
have polynomial coefficients in `y`. The finite formal phase prescription keeps
all falling-factorial terms `m <= M+2` and Stirling terms `4r-2 <= M`. Gaussian
moments, exponential-series coefficients and normalized inserted moments are
then generated by recurrences. The `phase`, `coefficients` and `exterior`
functions accept any prescribed nonnegative integer order; their runtime grows
with that order. The standard verification run checks six boundary orders.

The boundary generator and moving generator are separate implementations of
their displayed formal phase expressions. Their coefficients agree on exact
specialization. Orders five and six additionally agree with the independent
SymPy calculation recorded in `optional/boundary/coefficients_order6.txt`. Order
six exercises the additional `B4` Stirling correction. This finite verification
is not a claim that the all-order series converges.

The certificate represents a field element as `[r0,r1,r2]`, meaning
`r0+r1*a+r2*a^2`; each `ri` is a canonical rational string. Rational points are
also canonical strings. Integer graph counts are JSON integers. The verifier
recomputes every field and uses recursive type-strict equality: booleans cannot
masquerade as integers, equivalent noncanonical fractions are rejected, and
missing or additional keys are rejected. Duplicate JSON keys and NaN/Infinity
are rejected before comparison. Inputs must be regular, non-symlink files with
non-symlink directory components.

## Independent finite checks

- A cached distinguished-vertex graph recurrence counts labeled maximal
  matchings. It allows unmatched vertices only in one part. It does not call the
  factorial-sum routine. Validation occurs before cache lookup, including after
  caches are warm
- Full exact three-branch sums allow every feasible unmatched count, obey parity,
  and subtract two duplicates of a feasible perfect matching. Every factorial
  quotient is checked for integral divisibility
- The explicit large-branch sum is separately compared with its branch in the
  full sum. For `d>=0` it must equal the full count exactly
- Boundary count, logarithmic, mean and variance coefficients are compared with
  the displayed values. The `+1/(24n)` factorial correction to `log A_n` is checked
- Moving `c1`, `ell2`, `m0` and `v1` are checked at eight rational `u` values,
  including independent first/second phase polynomials and Gaussian
  integration-by-parts moment formulas. The finite sampling does not prove the
  rational-function identities. The algebraic boundary specialization is exact
- Exterior finite-product logarithms are generated through second order at six
  positive rational `c`; their values are compared with direct fixed-`j` sums for
  `j=0,...,8`, then averaged using exact Poisson moments. The first count
  correction is checked against `-(c^-4+2c^-5+3c^-3)`
- The manuscript prefix is parsed only between unique named comment delimiters.
  Eleven nonnegative integer literals are required; arithmetic expressions,
  decimals, macros, missing values and altered values are rejected

All finite checks are deliberately separated from the manuscript's analytic
proofs of localization, branch dominance, uniform remainders and limit laws.

## Guards and reproducibility

`guard_tests.py` runs the verifier in normal and optimized modes, compares their
positive outputs, and deliberately mutates count, phase, coefficient, moment,
scope and structural data. It also tests damaged manuscript prefixes, missing
files, symlinks, regeneration consistency and refusal to overwrite outputs.

`test_build.py` checks path, manifest, archive, environment, no-shell subprocess,
TeX-log and exclusive-publication behavior using synthetic TeX results. It never
invokes TeX. The actual builder separately runs real TeX with shell escape
disabled, fixed metadata and private caches.

`verify_manifest.py` scans the complete package rather than accepting only the
paths listed in a manifest. Every ordinary file is required to have exactly one
matching SHA-256 entry, except the manifest itself. Extra/empty directories,
links, cache files and special files are refused. The manifest is not its own
hash entry and is not an authenticity signature.

`code/regenerate.py` recomputes the complete certificate and can compare it with
an existing one and/or write a new file. It will not replace an existing file or
follow an output-directory symlink. Temporary work and generated verification
receipts are created outside the source directory; the builder's ZIP inventory
is explicit and contains no caches or unrelated source files.
