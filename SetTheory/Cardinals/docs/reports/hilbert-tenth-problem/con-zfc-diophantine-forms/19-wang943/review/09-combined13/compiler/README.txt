Neighborhood coefficient compilers for the blank K215 language
=============================================================

Run from the archive root:

    python3 verify_compiler.py

Only Python 3 and its standard library are required. The runner compares all
four saved receipts exactly. It verifies the actual K215 table hash and the
three inherited checker hashes, directly compares the category counts with
the local predicates, checks control tableaux and mutated periodic planes,
and repeats the sparse compiler/support/congruence checks.

The recommended four-site recipe is tshape_constants.json, generated by
tshape_compiler_constants.py. Its predicate is tshape_helical.py. The cross
recipe is an independently auditable intermediate reduction with five
payload positions, saved in cross_constants.json.

Both export precisely four fixed arithmetic ports:

    Bm1 = B-1
    Kconstant = DC+B*DR
    MC = the native low mask
    MF = the native high mask + B-1

MF is the shifted source port. It must not be confused with the native
high mask. Arithmetic sources may use beta,K0,MC,MF or m,K,MC,MF as the
corresponding names. Select one complete coefficient recipe, including its
window enumeration; ports from different recipes must not be mixed.

The formulas specify exact, finite integers. No giant alphabet or coefficient
expansion is materialized. In the four-site recipe, B-1 has 5^28 binary digits.
In the cross recipe it has 5^36 binary digits. The proof is in
../proofs/COEFFICIENT_REDUCTION_PROOF.md. The compiler and signed-domain audit
notes are beside that proof. Imported mathematical sources and a pinned
source map are under ../upstream/compiler/.

These finite checks support the general mathematical proof; they are not a
Lean/Rocq formalization and do not decide Con(ZFC) or exhibit a halting K215 run.
