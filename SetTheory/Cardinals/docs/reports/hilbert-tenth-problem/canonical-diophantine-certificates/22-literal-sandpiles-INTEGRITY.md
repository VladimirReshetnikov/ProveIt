# Report35 integrity and replay

## Trust boundary

Use an independently received ZIP SHA256 or release-manifest SHA256 as the authenticity anchor. No self-contained mutable program can authenticate a coordinated replacement of itself and all of its data. Within that boundary, `verify_release.py` pins `MANIFEST.json` in a constant; the manifest pins all payloads, including the verifier with that one constant normalized to zeros. `SHA256SUMS` additionally records the byte-exact final verifier digest. Changing the expected manifest alone, or changing it together with ordinary checksums, is rejected.

The manifest inventories every regular file, its byte count, SHA256 and mode. Exact directory and file sets are checked; unlisted files, empty extra directories, symlinks and special files are rejected. The original approved loader manifest and independent audit have separate fixed pins. `verification/source-lineage.json` preserves original-to-packaged identities. No upstream code, upstream PDF, image, cache or author-private absolute path is included.

## Commands

Use Python3, standard library only, from any working directory:

    python verify_release.py --verify-only
    python -O verify_release.py --verify-only
    python verify_release.py --self-test-types
    python verify_release.py --replay
    python -O verify_release.py --replay
    python tamper_regression.py

Each full replay first verifies the release, then makes and re-verifies fresh external copies. It runs the frozen replay plan under normal and optimized Python, with isolated imports and bytecode writing disabled. Scripts that produce JSON files may overwrite only these disposable copies. A receipt is removed before its producer runs, so a stale expected output cannot masquerade as a newly generated result. After every producer, the entire copied inventory is reverified before any later producer runs. The wrapper checks its regenerated bytes and recursively checks every JSON type, key, list position and value against the frozen structured expectation. Boolean values are not integers; unknown keys are not ignored. Duplicate JSON keys, malformed syntax, nonfinite values and numeric overflow are rejected. The original release's bytes, modes and nanosecond modification times, including directories, must remain unchanged.

The proof documents establish the unbounded mathematical claims. The executable evidence is finite and the integrity wrapper is not a theorem prover.

## Rebuild the article

A local TeX Live installation is needed:

    python build_pdf.py --output ../report35-new-pdf-build

The destination must be new or empty and outside the release. The builder copies `Research_Report35.tex` (and `certificate_section.tex` if present), disables shell escape, fixes the source-date epoch and PDF trailer-ID policy, builds three passes, and keeps every TeX cache/log outside the release. Its receipt reports the resulting PDF digest and whether it matches the packaged PDF. It never overwrites the packaged PDF.

## Deterministic ZIP and safe extraction

    python archive_release.py --create ../Research_Report35.zip
    python archive_release.py --check ../Research_Report35.zip --sha256 EXTERNALLY_RECEIVED_SHA256 --replay
    python archive_regression.py --archive ../Research_Report35.zip --sha256 EXTERNALLY_RECEIVED_SHA256

Creation refuses an existing destination and uses a stable root name, sorted members, fixed timestamps, fixed regular-file modes and fixed compression parameters. Verification checks the independently supplied archive digest, duplicate names, path traversal, absolute paths, encryption, symlinks, special files, member sizes and exact bytes against the identity-checked release. It writes only individually validated regular-file bytes, never using unrestricted extraction. The moved extraction is reverified in normal and optimized Python; `--replay` also runs its evidence.

`seal_release.py` is a maintainer utility, not a validation step. Running it replaces the expected identities and destroys the meaning of comparison to an earlier release. Recipients should not reseal a received package.
