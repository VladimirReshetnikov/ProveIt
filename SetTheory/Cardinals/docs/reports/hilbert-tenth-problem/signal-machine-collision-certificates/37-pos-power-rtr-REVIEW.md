## Completed independent checks

`INDEPENDENT_RECEIPT.json` contains 75 passing check records. These include successful operations and targeted rejection probes, rather than 75 distinct security properties. Supplemental receipts contain four independent first-pass/no-shell-escape operations, three archive-boundary probes and six corrected-candidate replay operations. The separately identified author-owned selftest also completed all 39 checks; its result is corroborating selftest evidence, not independent review.

1. **Paths and preservation.** Canonical absolute/fresh outputs were required. Relative paths, `..`, double-leading slash, existing outputs, release overlap, original-source overlap and symlink ancestors were rejected. Descendant bytes, extra/missing files, empty directories, file and directory mode changes, and one-nanosecond file/directory timestamp changes were rejected. Symlinks, hard links and a FIFO were rejected. Fixed input-pin replacement failed even when supplied as a new coherent JSON object.
2. **Manifest schema.** Duplicate JSON keys; traversal/alias/control/backslash names; boolean sizes; negative times; special mode bits; uppercase hashes; extra fields; missing/extraneous directories; file/directory collision; and self-reference were rejected. Exact extraction inventory was independently compared against the externally pinned candidate manifest.
3. **Flattening.** The fixed eight-module sequence flattened to exactly the packaged standalone TeX and pinned manuscript map. Reviewed manuscript pins authenticate the actual manuscript; generic TeX content is not claimed to be a sandbox.
4. **Build isolation.** Original and corrected complete articles each built in a fresh external work directory with a newly generated format and font map, no shell escape, and three passes. An independent synthetic manuscript checked the actual `pdfshellescape` value is zero. A hostile inherited environment containing `TMPDIR`, `TEMP`, `TMP`, `HOME`, TeX search/configuration variables, hostile `PATH`, Python variables, date variables and permissive shell/input/output settings still produced the original PDF exactly without changing the source.
5. **Dependency completeness.** The full article lock contains 279 system input records and seven named executable/interpreter records. The retained format and compilation receipts contain respectively 64, 217, 215 and 215 system inputs. Their hashes and recorded input sets were independently re-derived. The entire union plus selected map files matches the lock. The synthetic `ifthen.sty` dependency appears only in pass 1, remains in the union, and causes refusal when removed from a freshly pinned test lock. Stale executable and system hashes fail before output creation. An unused but valid system input added to a coherent lock passes byte preflight but fails exact post-build union equality.
6. **PDF and rasters.** Both full article versions were reproduced byte-for-byte against their packaged PDFs; corrected full and relocated builds additionally have identical page-raster inventories. All pages passed signature/chunk/CRC/order/decompression/raster-size/filter checks. Independent Pillow decoding found all 24 corrected RGB pages at 1020 x 1320 with nonempty visible content. Malformed PNG probes covered truncation, CRC corruption, trailing data, invalid row filter, wrong decompressed size, extra zlib stream, grayscale, zero dimension, interlace and missing IEND.
7. **Archives and relocation.** Repeated original and corrected archive creation was byte-identical. The sorted member list, Unix regular-file metadata, fixed creation timestamps and deflate creation mode were inspected. Extraction restored every authenticated descendant's bytes, mode and nanosecond mtime, and a 0700 new root. Relocated verification and complete locked rebuild passed for both candidates. 8. **Adversarial archives.** Traversal, duplicate/extra members, payload tampering, altered payload modes, symlink entries, wrong manifest, wrong member order, bad CRC and malformed ZIP were refused before creating the extraction output. ## Contract and limitations

- An external manifest digest remains necessary. Hashing an internal manifest alone is not authentication.
- The release manifest covers descendants, not its own filesystem metadata or the top-level release root metadata. Operation snapshots nevertheless preserve current roots.
- ZIP container timestamps, compression choice and comments are outside extraction authentication. Authenticated descendant times are restored from the manifest.
- The toolchain scope is executable/interpreter bytes and recorded system TeX/font inputs plus selected maps. Shared libraries, Python's standard library and the operating system are not inventoried. No broader hermeticity claim is made.
- Preflight bootstrap and locked replay are distinct. The article acceptance here rests on locked exact replays, not bootstrap receipts.
- Tests are finite probes, not an exhaustive concurrency or hostile-host security proof.
- The corrected README still accurately calls the release reviews pending at that snapshot. The author should update status, include completed dossiers, then seal the actual final release and repeat final verification. This dossier's candidate pins do not anticipate that final inventory.
