# Portable independent audit and external-output checker

The reviewed source is frozen under proof SHA-256 `233b0f67ce13e81a41132017214db5b34d10c965cd9a3ef56d1cbc9d280ac33c` and manifest SHA-256 `cc8a653802570dac6744cc00d490213f34d0d6604a1bd74588173724895a7a55`.

Read `AUDIT.md` for the source-bound verdict, full argument checks, preprocessing boundary, and limitations. The audit found no mathematical defect in the claims as stated.

## Requirements and safe scope

Python 3.8 or newer, standard library only. No installation, network, source import, counter interpreter, physical simulator, saved schedule, or Lean build is needed. The checker only constructs/evaluates polynomials and reads declared JSON tables. Resource use grows with N=(T+1)²; this is not a constant-time or polynomial-in-log(T) verifier.

The included example candidates were generated by this independent checker. They demonstrate the exchange format and positive checks, not independent third-party provenance.

## Commands

```sh
# Check the exact original packet, without executing it
python check_external.py verify-source /path/to/three-witness-bounded-halting-20261004

# Rerun fresh finite algebra checks; output path must be outside the frozen packet
python check_external.py selftest --output rerun_results.json

# Check a data-only polynomial emitted by another implementation
python check_external.py check candidate.json

# Also bind the check to the actual source packet bytes
python check_external.py check candidate.json --source-directory /path/to/three-witness-bounded-halting-20261004

# Produce an illustrative native exchange file
python check_external.py export --T 1 --accepted 1,3 --output native.json

# Produce an illustrative full native-gap exchange file
python check_external.py export --T 0 --accepted 1 --kind gap --output gap.json
```

Every mismatch exits nonzero with `FAIL`. Successful coefficient matching does not authenticate a declared acceptance table as the table of a particular machine: doing that requires separate bounded-machine semantics evidence. No table entry is a witness or free input of the checked polynomial.

## JSON exchange format

The object has exactly these required fields:

- `schema`: `three-witness-polynomial-v1`
- `source_proof_sha256`: the exact proof hash above
- `kind`: `native` or `gap`
- `T`: a nonnegative integer, excluding Boolean values
- `accepted`: a sorted, duplicate-free list of integer nodes in `[1,(T+1)^2]`
- `variable_order`: the exact variable order below
- `polynomial`: a list of nonzero monomial records

One optional field is permitted: `residuals`, a list of six native or 38 gap monomial lists in the proof's presentation order. Empty lists represent identically zero residual slots, which are retained.

Each monomial record contains exactly `exponents` and `coefficient`. `exponents` is a list of nonnegative integers, one for each variable. `coefficient` is a canonical, nonzero signed decimal integer string: no leading zeros, no plus sign, and no `-0`. Duplicate monomials are rejected. Term order does not matter. Zero coefficients must be omitted.

Native variable order is `["A","B","j","r","s"]`.

Gap order is `g1,g2,g3`, followed by the five native names, then `pa_` applied to every module name below, then `pb_` applied to every module name below:

```text
o,w,M,g,x,y,u,v,z,t,qb,qv,J,
alpha_plus,beta_plus,
dwb,dwk,dyk,a1,a2,s1,s2,t1,t2,rho1,rho2
```

The full gap order has 60 names. Within each module `x,y,u,v,z,t` denote the proof's `x_p,y_p,u_p,v_p,s_p,t_p`; `z` is only a variable-name choice, not another leaf. `J` denotes `J_p`. The eleven final names represent positive leaves whose natural aliases subtract one. `alpha_plus` and `beta_plus` are positive leaves whose alpha/beta expressions add one. Output `pa_o` is p and `pb_o` is q. Thus there are exactly 57 positive witnesses, not 59.

The checker verifies the exact presentation, not arbitrary polynomial equivalence under variable renaming, rescaling, or a different sum-of-squares representation. Such alternatives need their own declared correspondence.

## Files

- `AUDIT.md`: independent, source-bound mathematical assessment
- `check_external.py`: portable checker and exact polynomial reconstructor
- `independent_results.json`: completed fresh finite-check evidence
- `source_verification.json`: source manifest/pin verification
- `source_before.json`, `source_after.json`, `source_preservation.json`: source preservation evidence
- `example_native.json`, `example_gap.json`: valid format examples
- `example_native_check.json`, `example_gap_check.json`: completed external-interface checks
- `MANIFEST.json`: audit-artifact hashes; not the original packet's manifest

The complete polynomial family changes with T. The checker does not turn it into an unbounded-halting polynomial or establish single-fold MRDP.
