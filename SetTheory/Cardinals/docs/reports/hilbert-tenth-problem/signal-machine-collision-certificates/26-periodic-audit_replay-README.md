# Report56 release and arithmetic replay tools

These newly authored utilities are separate from the frozen scientific packet and independent audit. No upstream program, saved schedule, repository source program, event-driven physical simulator, or general machine/macro frontend is executed. The four arithmetic programs explicitly listed below were read in full before their first replay execution; their imports, I/O scope, and source hashes are recorded in `executable-inspection.json`.

## Immutable inputs and provenance

- `../science/` is a byte-for-byte, mode-and-mtime-preserving copy of the final author handoff at `/workspace/shared/substrate-semantics56-20261004`.
- `../independent_audit/` is the corresponding copy of `/workspace/shared/periodic-signal-independent-audit-20261004`, including the final `emitted-artifact-audit/` addendum. Original `SHA256SUMS` lists and all original provenance wording are preserved. The parent audit's original hash list intentionally does not cover the later addendum; the addendum has its own original hash list.
- `immutable-inputs.json` is a new explicit exact inventory of every file and directory in both copies. It pins file bytes, SHA-256, POSIX mode, and directory modes, including the original hash lists and final handoff metadata. Its SHA-256 is embedded in `replay_audit.py`, independently of the release seal.
- The reviewed proof is pinned at SHA-256 `df7cefb472a76e6f34ce7fff0b1e8548782a82f4863fac2ecd2d682c69941a77`. Replay requires the audit's reviewed-proof snapshot to equal those exact proof bytes.

Original handoff files may mention their original absolute workspace locations. They remain inert provenance, not executable lookup instructions. Exact inventory enforcement includes unused contextual source documents, empty directories, and non-executable data; no unlisted input file or directory is permitted. The replay program and its embedded pin still need a trusted copy or verification under the separately retained release-manifest digest. A hash printed by an untrusted modified program is not independent authenticity evidence.

## Safe arithmetic replay

From the unpacked release, using a fresh absolute output directory whose parent exists:

    python3 -I audit_replay/replay_audit.py --output /absolute/new/report56-replay

The defaults are this release's `science/` and `independent_audit/`. Relocated external exact copies can be supplied explicitly with `--packet /absolute/science` and `--audit /absolute/audit`. Both inputs must be disjoint. The output must be fresh, external to both inputs and the entire release, and cannot contain any input. Symlinks in input/output path components and anywhere in the input trees are refused. Relative paths and parent traversal are refused. The complete inventory and all byte/mode pins are checked before any output is created or code is executed.

Execution contract, in order:

1. Copy the newly authored `science/check_arithmetic.py` into `author_arithmetic/`; run Python with `-I -B -S` and no arguments. It computes exact rational recurrence/sign/clock regression arithmetic, reads its own bytes for its receipt hash, and prints JSON. Require stdout to equal `science/arithmetic_receipt.json` byte for byte.
2. Copy the newly authored `science/emit_sign_certificate.py` into `literal_sign_emitter/`; run with `--output-dir` pointing only to its fresh `exports/` child. It implements the two literal sign-formula examples, writes exactly the three named export JSON files, and prints its receipt. Require every generated byte and stdout to match the frozen exports exactly. This is a literal sign compiler, not a physical simulator or a general machine/macro parser.
3. Copy `independent_audit/check_exact_algebra.py` into `independent_algebra/`; run with no arguments. This independent exact-rational checker reads no packet files and prints JSON. Require exact equality to `independent_audit/check-results.json`.
4. Copy `independent_audit/emitted-artifact-audit/check_exported_quartics.py` into `independent_emitted_quartics/`; run with `--source-dir` pointing to the fresh emitter execution directory. It hashes the copied emitter source inertly and parses the newly regenerated exported JSON. It never imports or executes that emitter. Require exact stdout equality to the frozen addendum's `receipt.json`.

The launcher refuses `-O` and `-OO`, requires isolated Python, passes only a small fixed subprocess environment, and runs no subprocess with optimized Python. The independent checkers use assertions; optimized execution would invalidate their evidence. No normal-versus-optimized success equivalence is claimed. `-B` prevents bytecode output and `-S` disables site initialization. No source-tree Python module is imported by the launcher.

All executed scripts and writes are in the external output. Complete read-only snapshots of both inputs are retained there. After all subprocesses, replay checks those snapshots, freshly emitted artifacts, and original input bytes, modes, inode identities, and mtimes. Access times are not preserved or checked. The final success marker `replay-receipt.json` is written last, accompanied by an exact output inventory that excludes itself. Failed runs may retain diagnostic partial output but cannot publish this success marker.

These controls are a bounded safe execution contract for inspected, immutable arithmetic programs. They are not a kernel security sandbox or a guarantee against an attacker concurrently replacing filesystem components. Do not modify the trees while a command runs.

Finite arithmetic tests are regression evidence, not a proof of all infinite claims. The independent proof review remains the written audit. The four-signal artifact and the nonsquare-spectrum recurrence diagnostic have different scientific scopes, preserved in their source metadata and addendum.

## PDF, release seal, and deterministic ZIP

`../release.py` requires `python3 -I` without `-O`. It does not execute any scientific code. Paths supplied as outputs must be absolute, fresh, nonsymlink, and disjoint from the release. Verification pins exact inventory and modes, not input mtimes; commands check original bytes/modes/mtimes before and after execution.

Author-time unsealed PDF build:

    python3 -I release.py build-pdf --draft --output /absolute/new/report56-pdf-draft

The source `article/Report56.tex` must be self-contained. Only that source is copied. Installed `pdflatex`, `kpsewhich`, and, when necessary, installed `pdftex` format initialization run with shell escape disabled. An external private home and TeX cache are used; inherited TeX configuration is not propagated. `SOURCE_DATE_EPOCH=1791072000`, `FORCE_SOURCE_DATE=1`, and UTC fix the source date to 2026-10-04. TeX file policies are restrictive (`openin_any=p`, `openout_any=p`). Three compilation passes are required, and unresolved references/citations or overfull boxes fail the build. Exact PDF reproduction also depends on the installed TeX engine/packages/fonts and manuscript PDF metadata settings.

After all review and author-time receipts are final, the report author alone performs:

    python3 -I release.py seal

This creates `MANIFEST.json` once and never overwrites it. Keep the returned trusted manifest SHA-256 separately. The manifest excludes itself and pins every other file, every directory, exact bytes, and modes. Any later change requires a new release, not resealing this directory.

Sealed verification/build/archive:

    python3 -I release.py verify --manifest-sha256 TRUSTED_SHA256
    python3 -I release.py build-pdf --manifest-sha256 TRUSTED_SHA256 --output /absolute/new/report56-pdf
    python3 -I release.py archive --manifest-sha256 TRUSTED_SHA256 --output /absolute/new/Report56.zip

A sealed PDF build requires byte equality with `article/Report56.pdf`. The ZIP uses sorted paths, `ZIP_STORED`, fixed 2026-10-04 00:00:00 member timestamps, no enclosing directory, and pinned Unix modes. It is reopened to verify exact member order, timestamps, modes, compression, CRC, and contents. Original input bytes, modes, and mtimes are checked afterward.

## Tool validation

    python3 -I audit_replay/test_tools.py --output /absolute/new/report56-tool-tests

The newly authored test driver seals only its synthetic external TeX fixture, never the real release. It checks deterministic independent-directory PDF builds and stored ZIPs; refuses seal overwrite, optimized launch, reused outputs, nested outputs, symlink leaves/parents; and rejects modified, missing, extra, mode-changed, symlink, and unreadable input files/directories. Filesystem traversal errors are fatal rather than silently skipped. It also runs all four pinned arithmetic checks and validates original input bytes/modes/mtimes before and after. The real release's author-time receipt is retained as `tools-validation.json`; the exact arithmetic replay receipt is retained as `replay-receipt.json`. The final validation passes 44 tests; `tool-review.json` records the static review closure and confirms real permission-error coverage under a non-root runtime. Full diagnostic execution trees are external to the release.

The tools do not replace manuscript review, proof review, or the final report author's seal. No final release seal is created by this tooling handoff.
