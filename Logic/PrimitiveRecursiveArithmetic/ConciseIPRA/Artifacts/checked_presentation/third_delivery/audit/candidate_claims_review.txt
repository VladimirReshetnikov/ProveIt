THE NEW SOURCE REWRITE

In the exact 240-token control, the retained-clause opener receives

  c(g,s) or k * bool(s or len(a)==2).

In the 239-token profile it receives

  (c(g,s) or s or len(a)==2) and k.

Both evaluate c(g,s) once before consulting its resulting global k.
On every successful return c returns None and decrements k exactly once.
If s is truthy or len(a)==2, both expressions return the resulting integer k.
Otherwise the old expression returns integer 0 and the new one returns False.
Consequently a literal state-identity proof would be incorrect; the precise
invariant uses erasure of False to integer 0 in internal trees.

Let E replace internal False leaves by 0 and preserve integers and array
structure. The opener's scalar comparisons k<=a<d agree on False and 0;
attempted traversal fails on either scalar; list traversal, lengths, truth
values and equality comparisons are preserved. All remaining integer
arithmetic uses the unchanged integer k,d or exact input packet fields.
Thus E commutes with each successful opener call and preserves its failure
status. The two c calls consume the same packets and have the same global
k, with contexts/goals related by E. Induction on a finite successful call
trace gives acceptance preservation in both directions on the canonical
exact-integer/list input contract. The internal Boolean is auxiliary syntax,
not a changed numerical meaning or an extra public literal.

The AST profile makes two additional presentation changes: k=0 moves into
the definition-time default d=(k:=0), and three-field assignment becomes
a JSON array sequence pattern. The initialization is completed before any
checking call. For a three-element JSON array the pattern binds the same
s,u,t,r; a failed pattern leaves local names unbound, and the subsequent
eager leaf expression must consult those names before acceptance. Therefore
malformed array arities cannot silently reach ACCEPT. These techniques
already occur individually in the upstream corpus; their application to
the new selector is a source composition, not a new axiom basis.

LIMITS

The compact programs promise a canonical closed guarded Eq/D public goal,
the exact-integer/list input alphabet, and their JSON Lines protocol. They
do not satisfy the fully validated T contract merely because some malformed
inputs fail. Their numerical reductions must not be compared directly with
G/T control sizes without stating the contract.

The complete corpus fingerprint check establishes absence of an exact
normalized-source duplicate among 1,813 normalized modules. This is not a
claim of mathematical novelty. Existing checker records are upper bounds
on an unknown optimum, not formal lower bounds on every possible theory.
