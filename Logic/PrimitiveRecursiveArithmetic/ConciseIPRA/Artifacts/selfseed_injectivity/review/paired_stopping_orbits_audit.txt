PAIRED STOPPING ORBITS: INDEPENDENT PROOF AUDIT
=============================================

Proposed result: T_F^- proves successor injectivity. Thus the extra
injectivity axiom of the repository's self-seeded theory T_F is redundant.

Status of this audit: I independently checked the proof against the exact
current article's definition of T_F^- and its preceding no-injectivity
lemmas. The argument below is valid as a written intuitionistic proof.
It is not a newly compiled Lean or Rocq formalization.

SOURCE AND DEPENDENCY BOUNDARY

The inspected source is docs/Article/chapters/ch08_seed.tex in the
ConciseIPRA directory of the pinned repository. Definition seed:def:tf
defines T_F^- by ordinary intuitionistic first-order logic with equality,
the Boolean equality axioms and 0 != S0, equation induction with side
assumptions, and

  F(0;v.h) = S(h(0)),
  F(Sn;v.h) = h(F(n;v.h)).

The following source results occur BEFORE the section that assumes
successor injectivity, and their proofs do not use it:

  seed:lem:tf-basic: Sx != 0; Boolean operations; decidable equality;
                    contextual quantifier-free induction.
  seed:lem:tf-nofix: Sx != x.
  seed:thm:tf-acyclic, k=2: S(Sx) != x.
  seed:thm:tf-coverage: x=0 or exists y, x=Sy.
  seed:prop:tf-rigid, k=1: Sx=S0 iff x=0.

Coverage has already been proved using a protected orbit and
quantifier-free induction, without cancelling any successor. The only
special numeral-rigidity instance required here is k=1. Its current
source proof uses only the same no-injectivity lemmas. No predecessor
left-inverse, order, general primitive-recursive compiler, or
bi-interpretation theorem is used in the new derivation.

THE BODY IS AN ACTUAL TERM

Put C(q,v)=F(q;w.v), using a fresh bound w. Then C(0,v)=Sv and
C(Sq,v)=v. In particular, C(1,v)=v. Let OR_B be the Boolean disjunction
term already constructed in seed:lem:tf-basic. Define

  b_a(v) = epsilon(v,0) OR_B epsilon(v,a),
  h_a(v) = C(b_a(v),v),
  A_a(n) = F(n;v.h_a(v)).

These are literal terms of the original language after expanding C and
OR_B. This is essential: seed:lem:tf-cases permits graph-defined functions
in formulas but DOES NOT permit arbitrary graph-defined functions as new
bodies of F. The displayed construction uses no such illicit extension.

The Boolean range and reflection axioms give, intuitionistically,

  h_a(0)=0, h_a(a)=a,
  (v != 0 and v != a) -> h_a(v)=Sv.

Consequently A_a(0)=1 and A_a(Sn)=h_a(A_a(n)).

1. THE STOPPING INVARIANT

For all a,n,

  A_a(n)=Sn OR A_a(n)=a.                         (1)

This is one quantifier-free induction on n. At n=0, A_a(0)=S0.
In the step, if A_a(n)=a, the next state stays a. Otherwise the
induction disjunction gives A_a(n)=Sn. This is nonzero. Decide Sn=a:
if equal, the next state is a; if unequal, it is S(Sn). This is exactly
the next instance of (1). No injectivity is used.

2. DIAGONAL HITTING

For a != 0,

  A_a(a)=a.                                    (2)

By coverage take p with a=Sp. At n=p, BOTH alternatives of (1) give
A_a(p)=a. Therefore A_a(a)=A_a(Sp)=h_a(a)=a. Notice that no bound,
order, predecessor uniqueness, or formula induction beyond (1) occurs.

3. ASSUME A COLLISION WITH DISTINCT PREDECESSORS

Fix a,b and assume Sa=Sb=c and a != b. The k=1 numeral-rigidity lemma
gives a != 0 and b != 0: if a=0, then Sb=1, hence b=0, a contradiction;
the other case is symmetric. Also c != a and c != b by no fixed points.

4. CROSS HITTING

  A_a(b)=a and A_b(a)=b.                        (3)

By (1), A_a(b) is either c or a. Suppose it is c. Since c != 0 and
c != a, A_a(Sb)=h_a(c)=Sc. But Sa=Sb and (2) give
A_a(Sb)=A_a(Sa)=h_a(A_a(a))=h_a(a)=a. Hence a=Sc=S(Sa), contrary to
the no-two-cycle theorem. Thus A_a(b)=a. Exchange a and b for the other
identity. This argument does not cancel S anywhere.

5. THE TWO ORBITS AVOID THE OPPOSITE STOP

For every n,

  A_a(n) != b and A_b(n) != a.                 (4)

Suppose A_a(n)=b. In (1), the second alternative would give a=b;
therefore b=Sn. Recurrence then gives

  A_a(b)=A_a(Sn)=h_a(A_a(n))=h_a(b)=Sb=c,

because b != 0,a. This contradicts (3), which gives A_a(b)=a, and
c != a. The other assertion is symmetric. The universal quantifier is
introduced after a fixed arbitrary n; no quantified induction is used.

6. SYNCHRONIZATION BY EQUATION INDUCTION

Prove the literal equation A_a(n)=A_b(n) by equation induction, with
the fixed side assumptions Sa=Sb and a != b. Both base values equal 1.
In the step let v be their common state. By (4), v != a,b. Thus
h_a(v)=h_b(v): if v=0 both values are 0; otherwise both are Sv.
The split v=0 or v!=0 is justified by decidable equality. Recurrence gives
the next orbit equation.

This is precisely the permitted literal-equation induction rule. The
step uses equality of the two update values only at the common visited
state. It invokes no extensionality axiom for F and no equality of whole
update functions.

At n=a the synchronized equation, (2), and (3) give

  a=A_a(a)=A_b(a)=b,

contradicting a != b. Since equality is decidable, split a=b or a!=b
at the outset: the first branch already proves the desired conclusion,
and the second is contradictory. This is intuitionistically valid;
there is no use of unrestricted double-negation elimination.

CONCLUSION AND EXACT CONSEQUENCE

The argument proves, uniformly with variables a,b,

  T_F^- proves forall a,b (Sa=Sb -> a=b).

Therefore T_F^- and T_F have exactly the same consequences in their
common language: one direction is inclusion of axioms; the other
replaces each use of injectivity by this derived theorem. All existing
T_F interpretations and both round trips can be reused without change.
In particular, the repository's written bi-interpretation with full
first-order iPRA transfers to T_F^-. Both numerical domains, equality,
and numerical comparison maps are unchanged.

This is a genuine mathematical axiom deletion in the self-seeded
presentation. It is independent of any small Python checker refinement.
It does not itself prove that a checker for T_F^- beats the repository's
current compact 240/261/468 coordinate envelope, attained by different
programs and input framings. Those are different questions.
