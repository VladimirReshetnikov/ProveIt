The only change is the first expression in the body of c:

  (i := (lambda ...)) and (i(a) in g or CONTINUATION)

becomes

  (i := (lambda ...))(a) in g or CONTINUATION.

The lambda expression produces an ordinary Python function object, which is
always truthy. Both expressions first evaluate that lambda (including its
default arguments) and assign the same function to the same local cell i.
Both next call the function with the same argument a, perform membership in
the same g, and either return the same Boolean True or evaluate exactly the
same continuation. The function still captures the same mutable k cell; in
particular, it still observes k after the continuation's walrus decrement.
This last point is essential for scope correctness.

All function calls, JSON packet reads, substitutions, arithmetic, membership
tests, and context additions therefore occur in the same order. The returned
value at each c invocation is unchanged: True for a membership success or the
same nonempty one-element continuation list. Any exception arising in lambda
construction, i(a), membership, or the continuation is reached at the same
stage. Induction on the finite dynamic call tree proves equality of every
finite successful execution, packet consumption, and acceptance result.

The source difference does not change the JSON frame, certificate protocol,
public grammar contract, mathematical calculus, or validation boundary.
Memory/time resource limits are operational limits rather than logical
acceptance; the equivalence is stated with sufficient resources. No claim
of a new axiom deletion or global source-size minimum is made.
