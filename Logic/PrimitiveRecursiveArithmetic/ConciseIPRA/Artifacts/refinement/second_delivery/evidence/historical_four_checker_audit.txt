I. BOOLEAN IDENTITY AND ITS DOMAIN
For every nonnegative integer a,
   (not a or a > 1 == a % 2) == (a % 2 == (a > 1)).
At zero both are true, at one both false, and at a>=2 both test oddness.
They can differ on negative even integers, so the phase invariants below
are essential; it would be wrong to assert the identity for all integers.

II. CONTEXT-PHASE PROGRAMS native_size AND strict_size
The initial call has empty g and k=0. The scalar guard first checks k<=a<d,
so an evaluated public-grammar predicate sees a>=0. native_size keeps the
exact-integer test int(a) is a. strict_size's whole-input lexical gate has
already established that every parsed value is an exact integer or a list.
Before any proof continuation or recursively checked major, g has acquired
the neutral entry 0 and is nonempty. The expression `g or predicate` therefore
skips the changed predicate throughout proof checking. The initial phase is
equivalent by I, and the proof phase is literally unchanged. No additional
arithmetic operation can become defined or undefined on arbitrary JSON.

III. native_bytes
The initial grammar traversal has v=1 and k=0; after it, v=0 is assigned
before every proof operation and all recursive calls use v=0. The change is
   int(a) is a and d%2 and (not a or a>1==a%2)
to
   d%2 * (int(a) is a and a%2==(a>1)),
both underneath v <= (...), after the range test.

In validation mode, a is nonnegative when it reaches the changed integer
predicate. Section I applies. The product returns the numerical 0/1 value
of the former short-circuit Boolean expression. In proof mode, negative
even a can change the Boolean predicate but cannot change 0<=B, since
each B is either 0, False, or True. The product may evaluate the parity test
when d is even; this is safe because its own preceding int(a) is a gate
ensures an exact integer, on which modulo and comparison are total.

Changing evaluation order to compute d%2 earlier is harmless: d is always
an integer binder coordinate and modulo 2 is total. int(a) is still evaluated
at every place where it was evaluated before; float and bool fail its identity
test and skip the newly eager parity arithmetic. Malformed nonnumeric values
fail earlier unchanged operations, or the same int conversion. Thus the
whole JSON success language is preserved, not just well-formed goal behavior.

IV. strict_bytes
Here the old and new expressions are
   d%2 and a%2==(a>1)
and
   d%2 * (a%2==(a>1)).
Every scalar reaching this site is an exact integer, guaranteed by the
unchanged whole-input alphabet gate. Since d%2 is 0 or 1, the values are
numerically identical. Eager parity evaluation for even d is total. Invalid
JSON-tree alphabets fail at the identical gate before this code is reached.
