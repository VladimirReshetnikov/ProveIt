PINNED CONCISE iPRA FRONTIER AUDIT
Snapshot: b9aa36102e523213ae956b474ec651bfde3e5665 (12 November 2026).

1. SOURCE SCOPE AND METHOD
The complete ConciseIPRA checkout was inventoried, relevant source contracts
were inspected, and all ten incoming ZIP archives were reviewed. Every archive's exact Git blob SHA1 was recomputed from its bytes
and agrees with the GitHub API tree. archive_audit.json records these hashes,
byte counts, member counts, and SHA256. Programs were parsed and measured with
CPython 3.12.14 using ast.unparse plus one LF. The standalone module, input
driver, and ACCEPT output are all counted. No packed exec/eval source is an
eligible incumbent. The broad census includes ineligible test/mutant sources;
frontier_audit.json lists only the explicitly classified incumbent modules.

Compact token/AST winners use JSON lines rather than the earlier whole-array

same specified guarded theorem set. The public-goal promise and input alphabet
promise remain part of this compact contract; they must not disappear from a
claim of soundness or be confused with validation performed by the program.

3. THE TEN INCOMING PACKAGES
- checked_presentation: JSON-line framing lowers compact profiles to 244 tokens
  and 267 AST nodes; byte profile stays 479. No new logical or arithmetic axiom.
- zero_test_split: byte profile 478; ordinary successor coverage is replaced by
  n=0 or I(n,1;u.0)=0, proved equivalent through an equational predecessor. The
  bit of arithmetic is distinct from the checker header refinement.
- 479_predecessor57: compact479 and native607; a 57-node iterator predecessor
  and literal numeral normalization examples. Strict637 is inherited.
- atomic_seed_refinement: partial zero contraction for atomic normal-form
  seeds, with RAW rule metadata retained; six-family presentation is larger
  than its matched control (1333/1521/5373 vs 1319/1507/5348). Separately native
  public-goal636 and whole-alphabet628 refinements preserve predecessor raw
  acceptance. They do not implement the new atomic-seed theory.
- equation_aliases: Fresh Alias and Back restricted to equations, fixed newest
  parameter specialization; consequence equivalence through an explicit
  compiler. Matched mathematical checker grows. Separate strict implementations
  give 338-token, 386-node, and 633-byte profiles, some now superseded.
- local_introduction: in the raw Alias/Back calculus with matrix-only diagonal
  mode, Close always uses newest outer parameter, or 0 in empty scope. New
  checker 862/1011/3245 vs 870/1022/3274. Compound Back is required.
- alias_back: raw Eq/D calculus using fresh substitutive Alias plus backward
  substitution, with fixed newest parameter Back and Use. Alias derives
  reflexivity; equality transport is derived without arithmetic or induction.
  Equational Back is proved; equational Alias is the later equation_aliases
  contribution. Compact479 is a separate implementation refinement.
- reductions: native620/621 byte refinements; right-inverse/rigidity results
  about successor uniqueness; standard-model classical binder-depth analysis.
- checked_frontier: native622/623 and strict645; implementation refinements,
  with all corresponding token/AST profiles larger than matched controls.
- immediate_opening: earlier independent compact479 implementation refinement;
  no new mathematical global minimum.

4. PITFALLS THAT SHOULD CONSTRAIN NEW WORK
The guarded-root calculus and source-restricted transport do not support every
raw native consequence without their gate translation. The public grammar is
essential. In particular, the initial-floor header shortcut of compact478 is
unsound if generalized to the unrestricted native interface. The package has
a concrete accepted false native formula for that mutation.

The context invariant k=1-|g| holds at recursive call boundaries, not during
all evaluation phases; a blanket inclusive context-length floor is unsound.
The scalar default in the updater is a deliberate invalid scope sentinel.
Replacing it by numerical 0 can turn malformed or escaped syntax into valid
objects. Any change must preserve the exception/rejection behavior or prove
a theorem-set simulation under an explicit narrower certificate promise.

Partial atomic zero normalization does not commute with substituting into an
already normalized body. Raw matrix metadata and normalize-after-substitute
order are necessary in atomic_seed_refinement. Treating the normalized body
as sufficient loses the actual theory.

The local-introduction witness removal needs witness-independent diagonal
mode. Taking the newest parameter while retaining witness==0 progress tests
is not justified. Bi-interpretability must include full formula round trips
and internal numerical identity graphs, not just a shared standard model.

All new incoming mathematics has written proofs plus regression/compiler
evidence. No incoming package claims a newly completed end-to-end Lean/Rocq
verification of its Python checker. The inherited native arithmetic bridge
is attributed, and its current Lean sources are available in the checkout.

5. WHAT WAS NOT CLAIMED BY THIS AUDIT
This is source authentication, exact source-size measurement, and a semantic
contract comparison. It does not certify every historical proof or exhaustively
classify every conceivable checker. Broad census minima alone are invalid:
utilities, malformed mutants, compressed loaders, and partial demonstrations
are smaller files but are not eligible complete standalone iPRA checkers.
