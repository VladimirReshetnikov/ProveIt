CHECKER PRESERVATION AND COMPARISON CONTRACT

The three compact programs implement the same inherited guarded/public
calculus with progressive auxiliary formulas as guarded_source. They are not
new arithmetic axioms and do not establish an absolute minimum. Their three
coordinate records belong to different programs. Public statements are
canonical closed Eq/D formulas with guarded immediate atomic D matrices.
Q triples are administrative resources. Compact programs do not validate
the public grammar. checker_strict.py is a separately counted extension
with exactly the predecessor's public-goal validator; it does not add whole-
certificate exact-type validation.

1. GLOBAL TOKEN LOOP

The old 257-token program has a global fresh-name floor k and tail-recursive
checker c(a,g). Every successful return is None. Replace its top hypothesis
test and return by a while loop that continues exactly while the hypothesis
test fails. At each iteration retain the same instruction pop, elimination
endpoint check, recursive major proof, constructed hypothesis, and decrement
of k. Replace the tail call c(i(a,[k]), g+[i(h,image)]) by updates to a and g.

Contexts are changed uniformly from lists to tuples. A context is internal
checker state, never an input value. There is no context mutation in the old
program; recursive calls receive a fresh concatenated list. In the new
program g += (new_hypothesis,) is tuple concatenation and local rebinding.
It does not modify a caller's context. Using list += here would be unsound:
assumptions acquired while proving the major could leak to the caller.

The simulation relation is: identical pending JSON instructions, identical
current goal and global k, and contexts with identical entries in order.
Membership tests have the same truth value. One failing membership test
causes one identical packet pop. The recursive major calls satisfy the
same relation by induction on their finite successful execution trees.
They leave the same global k and input suffix. The same subsequent decrement
allocates the same fresh name. The two opening calls are pure with respect
to k and the instruction stream. Their evaluation order is reversed in the
loop implementation, but both have the same results whenever they succeed;
if either raises an exception neither complete run accepts. Thus continuation
states satisfy the simulation relation again. A successful membership test
returns None in either version (explicit return versus function fall-through).
This proves equality of the successful finite traces in the ideal unbounded
execution model, not merely equality on the packaged test examples.

Physical Python recursion and memory limits can distinguish sufficiently
large inputs; those limits are already outside the repository's idealized
completeness convention. Removing tail calls decreases stack consumption.
No speed or proof-length optimum is claimed.

2. SCALAR NEUTRAL TRUTH

The byte and AST profiles change only the initial internal neutral formula
from [] to 0. This convention already occurs in the incoming reversal_core
package; it is not new mathematics. Both raw forms decode to 0=0 at formula
sort. Thus the invariant that every retained assumption is justified remains
valid. Every other primitive transition has the same inherited soundness
argument. Completeness uses the existing compiler for canonical native
derivations, changing its administrative neutral major [] to 0. Its actual
object formulas and Q resources are nonempty canonical arrays; no proof of
an arbitrary empty-array public formula is required.

The supplied local certificates are converted only at this administrative
field: an exact four-field instruction with empty first field gets first
field 0. Terms, conclusions, all nonneutral majors, mode/witness data, and
scope coordinates are unchanged. The transformation is not asserted to
preserve every malformed or noncanonical raw certificate. For example the
old raw empty-array public goal is an initial truth spelling whereas the
new initial spelling is scalar zero. Canonical public theorem sets and their
whole-domain interpretations are unchanged.

3. MEASUREMENTS

Charge the complete standalone Python module, including JSON input and the
ACCEPT output. Remove only genuine docstrings, parse and unparse with the
recorded CPython version, append one newline, and count significant tokenize
tokens, all ast.walk nodes, and UTF-8 source bytes. Gzip uses level 9, mtime=0,
and includes the wrapper; it is informational, not an optimization objective.
All outputs are regenerated by tests/reproduce_checkers.py. The checker
source does not import that script, a producer, or a theorem database.

At CPython 3.12.14 the predecessor envelope is 257 tokens / 279 AST / 522
normalized bytes. The new envelope is 256 / 278 / 521. The new standalone
profiles are:
  checker_tokens.py: 256 tokens, 283 AST, 594 bytes, gzip9 346.
  checker_ast.py:    260 tokens, 278 AST, 602 bytes, gzip9 344.
  checker_bytes.py:  263 tokens, 300 AST, 521 bytes, gzip9 327.
The token-optimal program grows in bytes and gzip compared with its own
568-byte predecessor. That tradeoff is retained explicitly in the ledger.
The byte/AST neutral-truth changes do not improve the 257-token minimum by
themselves. The three records must not be reported as one checker.

5. REJECTED SHORTCUT

Replacing the introduction selector by an unconditional length test on the
generated hypothesis would also allow progress introduction at Q-root
matrices. That is not a harmless simplification. For arbitrary P(n), the
closure Q_z gate(z,P(n)) is equivalent to P(n). Induction on those closures
would therefore give induction on arbitrary formulas, beyond the intended
quantifier-free iPRA induction. The working checkers retain the literal-
equation root test and make no such change.
