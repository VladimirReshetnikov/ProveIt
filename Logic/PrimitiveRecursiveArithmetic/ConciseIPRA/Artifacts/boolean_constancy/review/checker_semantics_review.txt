A. Eager any conversion (checker478_any / checker478)

The sole intended replacement is bool(m or 3 % len(a)) by any((m, 3 % len(a))). The unchanged context argument is evaluated before the continuation-goal argument and before the recursive call. The tuple evaluates its second entry even when m is true-valued. Hence it is not a raw-input trace equivalence.

For each terminating execution in which len(a) is defined and positive at a visited replacement site, write r=3 % len(a). The two expressions yield the identical Python bool, because any((m,r)) is true exactly when m or r is true-valued. Here m is a value obtained from ordinary JSON, not an object with effectful __bool__; r is an integer, and len(a) on JSON containers has no side effect. The surrounding k assignment has not moved. Consequently the two executions have identical formula values, contexts, floors, packet consumption and recursive return values on such an execution.

Every successful new execution has satisfied these conditions at all its visited sites, since undefined len or zero length raises before the allocation. Removing the extra eager evaluations gives a successful old execution with the same trace. Thus Acc(new) is a subset of Acc(old) on arbitrary complete JSON stacks (ideal resource bounds). Soundness follows from upstream soundness; no new accepted raw certificate needs a separate interpretation.

Completeness is retained on theorem goals because the upstream compiler can choose native canonical proof traces. At every nonleaf call its goal is an equality (arity 2), Q (arity 3), or D (arity 1); after introduction the opened matrix is again such a formula. The scalar neutral major 0 is retained in the initial context and returns at membership before reaching the replacement. Hence every canonical generated proof uses len only on a nonempty array, and the trace-preservation argument applies. It is not necessary that every raw proof of a theorem survive.

B. Line-oriented stream conversion (checker244 / checker267)

Let an old finite JSON stack be [P0,...,P(n-1),A]. Serialize the new input as one compact JSON value per line, in the order A, P(n-1),...,P0. Compact serialization must escape embedded newlines in strings. Old q() returns the next value from the end; new loads(input()) returns the next line value. At every request they therefore return structurally equal values. By induction on program transitions, goals, contexts, floor values and packet consumption agree. Recursive calls occur at the same sites, so the proof does not assume a particular traversal other than the actual old code. Old unused prefix corresponds to new unread suffix. If the next packet is absent, IndexError and EOFError both reject.

Conversely any successful finite stream run reads only a finite prefix. Reversing the packet part of that prefix, then appending the first (goal) record, gives a finite old stack that has the same execution. Thus accepted theorem sets agree for the declared encoding. This does not equate the languages of physical input strings. In particular the streaming program does not parse unread suffixes, while the old top-level JSON reader parses the complete old array before checking. The claim is a changed framing with a simple certificate bijection on well-formed finite records, and it must be described as such.

from json import * uses the standard json module's exported names; it supplies loads and does not override c, i, k or any builtin used by these kernels. Its source size is charged. No arithmetic rule or kernel branch is changed. No code-execution facility is introduced.

C. Rejected default-argument reorder

Changing the signature from c(g,a,k=0) to c(a,g=[0],k=0) would itself be safe regarding the default list, because the contexts are extended by g+[h] and never mutated. However the candidate also reverses the argument evaluation order. The original context expression proves the major, may assign a to the opened introduction matrix, and allocates the next floor k before the continuation expression is evaluated. The reordered version computes the continuation at the old a and old k. These are observably different transitions, not a safe signature refactor. checker478_default.py and checker477_default_any.py should not be delivered as proved refinements.
