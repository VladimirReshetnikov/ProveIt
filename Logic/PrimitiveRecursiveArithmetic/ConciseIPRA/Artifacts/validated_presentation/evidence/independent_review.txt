1. RAW TYPE VALIDATION

Let S be the character set of the literal '0123456789[], -'. For any finite
value returned by the standard json.load call, repr(value).strip(S) is empty
exactly when value is an integer/list tree with exact built-in integer leaves.

For integers, repr uses decimal digits and possibly a leading minus. For
lists, repr adds only square brackets, commas and spaces around the recursively
computed representations. Hence integer/list trees pass, by structural
induction. Conversely, every other JSON-derived type introduces a forbidden
character: booleans use True or False, null uses None, strings use quotation
marks, dictionaries use braces, and finite floats use a decimal point or an
exponent marker. The parser's accepted nonfinite values have representations
inf, -inf or nan, which also fail. Such a character remains present in the
representation of every containing list. No custom repr methods, subclass
values, cycles, tuples or arbitrary Python objects can be supplied through
this uncustomized JSON parser.

Although strip removes characters only at the ends, it returns the empty
string iff every character belongs to S: if a forbidden character occurs,
the substring from the first to the last forbidden character remains.

The entire parsed value is checked before popping the advertised goal. Thus
unused prefix elements are still validated. The transformation does not
silently weaken the control's whole-certificate type contract. A non-list
top-level integer passes the alphabet filter but fails pop; an empty top-level
list likewise fails pop. Such inputs are rejected by the control as well.

2. SCOPED GOAL VALIDATION

After the raw filter, a is an exact integer or list everywhere. Therefore
the new test a*0 == 0 selects integers exactly, and its other branch selects
lists. Booleans and floats cannot reach this test through input data.

Write V_old(a,D) for the control's validator and V_new(a,d) for the candidate's
scoped validator. For every integer/list tree and d >= 0, the canonical-mode
equivalence is V_new(a,d) iff V_old(a,d+2), where exceptions mean rejection.
The initial old depth is 2 and the new initial depth is 0.

At integer leaves, adding 2 preserves depth parity, and the control's upper
bound a < D-2 becomes a < d. Both accept numerical zero at odd depth and
otherwise require an odd coordinate with 2 < a < d. Formula-position scalar
leaves reject in both.

At lists, the arity conditions depend only on depth parity, so they agree.
Both permit arities 1 and 2+(depth mod 2), plus a diagonal triple for Q.
For each child, the respective depths are increased by the same 5-len(a),
preserving their difference of 2. All successful arities are 1, 2 or 3,
so the old recursive depth cannot fall back into its raw depth-zero mode.
Apply structural induction to the children. Empty malformed arrays can
raise at a[0]; rejection by exception is part of both contracts.

6. LIMITATIONS

The equivalence is a mathematical statement about finite input values with
adequate resources. The new full-tree repr and the old recursive raw validator
have different temporary memory use and recursion behavior. Fixed interpreter
limits can therefore reject different unusually large inputs; identical
resource-exhaustion behavior is not claimed. Neither version is a total
decision procedure for theoremhood, and finite process checks do not prove
the inherited native kernel's universal correctness or its iPRA bridge.

The new code relies on the ordinary representations of built-in JSON-derived
types in the stated Python runtime. It does not evaluate repr as code, import
an external proof oracle, or omit certificate fields from validation.

The original theorem system, both interpretations, whole numerical domains,
actual equality and formula round trips are inherited unchanged. Their
existing proofs remain necessary; this implementation review does not replace
them or constitute a new Lean/Rocq verification of Python.
