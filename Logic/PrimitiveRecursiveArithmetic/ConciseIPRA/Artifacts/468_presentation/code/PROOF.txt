A 468-BYTE PRESENTATION: EXACT RESULT AND PROOF
=============================================

Claim and limitation
--------------------
compact468.py is a new composition of two existing representation changes:
the uniform terminal protocol and the shifted sorted codec. It has 271
significant Python tokens, 305 AST nodes and 468 normalized UTF-8 bytes in
CPython 3.12.14. Its direct matched source control469.py has 272 / 306 / 469.
The inspected all-package coordinate envelope was 241 / 262 / 469, attained
by separate programs. This candidate improves the byte record, and all three
coordinates of its matched byte control, but NOT the token or AST records.
It does not delete an arithmetic or logical axiom, and it does not meet a
requirement that one checker fall below all three independent records.

Contract
--------
Input is one finite JSON array used as a stack. Its last item is [A,0],
where A is a canonical closed guarded Eq/D public formula in the SHIFTED
codec of the existing offset472 package. Every consumed earlier instruction
is [m,s,u,t]. All data are exact integer/list trees; no Boolean/float/string/
object/null promises are implied by the word integer. Unused prefixes are
permitted. Acceptance is normal exit with exactly ACCEPT plus one LF.
This compact program does not validate the promised public grammar or the
whole-input JSON alphabet. Every accepted internal raw integer/list tree is
covered by the inherited shifted sorted-reading soundness proof; internal
canonical syntax is NOT a new assumption.

Reference and the exact transformation
--------------------------------------
The primary mathematical control is offset472.py, from the repository's
incoming ipra_offset472.zip package at the inspected snapshot. Both programs
use the same shifted syntax, the same depth values 2,4,5, the same initial
neutral context [0], and the same recursive nonterminal rule body.

offset472 first checks whether i(a) belongs to g. Only if not does it pop
the next [m,s,u,t] instruction, check a==C(s,u,t), and otherwise recurse.
compact468 first pops the next instruction, then checks i(a) in g+[C(s,u,t)],
and otherwise executes exactly the same recursive nonterminal body.
Here

 C(s,u,t) = [[s and [s],u,t], i(t,[s,u,t],5) if s else u].

Every ideal successful call returns a truthy result in both programs.
offset472's hypothesis terminal returns True, while compact468 returns a
nonempty one-element list; the return value is only observed for truthiness
by the identical nonterminal expression c(g,m,k) and m*3 or (...).

Lemma 1: literal fixedness of successful no-image opening
--------------------------------------------------------
For finite exact integer/list trees a, whenever i(a) with its omitted image
terminates successfully, it returns a literally, not merely an equivalent
decoded formula.

Proof. At an array, the procedure rebuilds the same array shape and applies
the induction hypothesis to every child. At an integer leaf, the accepted
range test returns the original leaf. If the range test fails, Python must
evaluate i(t,d=5) before multiplying by d%2, even when d is even. With omitted
image, t is the checker function c. In the recursive call, c*0 is invalid and
raises TypeError. That branch therefore cannot occur in a successful
no-image opening. The induction proves literal fixedness. The eager
multiplication is essential: the corresponding short-circuit and operation
used in some other profiles only gives a partial retraction, not this lemma.

The same no-image opener is used by offset472. Thus both programs validate
the same a before their first membership comparison.

Lemma 2: a neutral terminal instruction is always safe
-----------------------------------------------------
The instruction [0,0,0,0] constructs C=[[0,0,0],0] without evaluating an
image-opening call: s=0 selects the right-hand side u=0. Therefore it can be
inserted at any successful hypothesis call of offset472 without changing the
goal, context, floor or truthy outcome.

Theorem 1: equality of provable public goals with offset472
----------------------------------------------------------
For every fixed root goal and initial floor allowed by the stated contract,
there is an accepted compact468 certificate iff there is an accepted
offset472 certificate. Both directions preserve the root goal literally.
The statement is about existence of certificates; the same raw packet
sequence need not be accepted by both programs.

Proof from compact468 to offset472. Follow the finite successful recursive
call tree. Every compact468 call pops one packet. If i(a) is in g, remove
exactly that packet at that call: offset472 closes by its hypothesis test
without consuming a packet. Any eager C construction that compact468
performed has no state-changing effect, so deleting it changes no scope or
context. If i(a) is not in g, both programs consume the same packet. By
Lemma 1, the new test i(a)==C is exactly the old test a==C. If it succeeds,
both close by computation. Otherwise their recursive bodies coincide.
Apply the induction hypothesis to the major call and continuation call in
their actual evaluation order. All newly allocated names and all scope
floors agree because terminal branches never allocate a name. Reassemble
the retained packets in stack-consumption order, keeping any unused prefix.
This produces an offset472 certificate for the same goal.

Proof from offset472 to compact468. Follow the successful call tree and
insert [0,0,0,0] precisely at each hypothesis call, in its consumption
position. Lemma 2 ensures the new eager preview succeeds. Every other call
retains its original packet. By Lemma 1, the fused terminal membership test
has the same result as the old computation comparison, and the recursive
bodies agree. Use induction on the two subcalls, again in evaluation order.
There is no name allocation in an inserted terminal, so every subsequent
scope condition and eigenparameter name remains unchanged. The resulting
finite packet stack is accepted by compact468. QED.

Consequences
------------
Theorem 1 imports offset472's full soundness proof for arbitrary internal
integer/list trees and its completeness for canonical guarded public goals.
Those are the same native guarded scalar calculus as the repository's
established presentation. Therefore its ordinary realization has the same
whole numerical domain, actual equality and the same internal identity
comparison graphs x=y in the two bi-interpretations with full iPRA.
These mathematical bridge results are inherited, not newly formalized here.

Relation to the 469-byte matched control
---------------------------------------
control469 is the same uniform-terminal source before the depth shift.
The exact edits producing compact468 are:
  default formula depth 0 becomes 2;
  root term/image depth 3 becomes 5 (both occurrences);
  witness-opening depth 2 becomes 4;
  initial neutral context [[]] becomes [0].
The earlier offset472 proof establishes the associated sorted reading.
Canonical certificates shift every positive bound/hole coordinate by two,
preserve numerical zero and negative eigenparameter names, and change a
neutral empty-list major to scalar zero. This conversion is an untrusted
utility. The raw accepted languages are not claimed identical under a
simple tree-wide recoding. Theorem 1 avoids requiring that false claim.

Verification and its limits
---------------------------
The local executable receipt checks 140 inherited array-profile cases,
including arithmetic and logical positive cases, false-goal mutations,
scope attacks and malformed inputs. After the documented diagnostic
recoding, all expected results agree in ordinary and optimized Python.
Some malformed cases lie outside the formal contract and are included only
as regressions. The universal proof is Theorem 1, not the finite test suite.

No new Lean/Rocq verification or global minimum is claimed. In particular,
the tempting selector 'len(h)>1' is not a valid simplification of the current
raw checker: an introduced auxiliary Q matrix has length three and would
wrongly select progress rather than cases. The public Eq/D restriction does
not forbid Q matrices in internal proofs.
