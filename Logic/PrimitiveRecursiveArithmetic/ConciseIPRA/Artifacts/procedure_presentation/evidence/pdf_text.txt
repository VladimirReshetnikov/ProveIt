1 Result, comparison contract, and provenance
The requested complexity criterion is the size of a complete standalone proof checker. Under that
criterion the new fully validated programs are strictly below the separate minima of their current
comparison class. They read a complete JSON certificate, check the numerical and formula
grammar as specified by that class, and print ACCEPT only on successful verification. They import
no proof library, compressed checker, theorem oracle, or external verification module.
The complete compact companion is smaller in normalized bytes than every compact program
selected by the pinned baseline census. Its public language is connected to full first-order
intuitionistic primitive recursive arithmetic by the inherited interpretations detailed in Section 2.
This is a comparison with measured programs, not with a mathematically proved lower bound
over all possible languages or implementations.

Combining the three inherited bridges gives interpretations of thepublic theory and full first-order

apply σ, the native logical translation ∗, and then T. Equations (8), (10), and (12) prove both

3 The new program transformations
3.1 Verification as a procedure
The latest byte-oriented controls use a lambda whose body is a one-element list comprehension.
Its sole purpose is to unpack one certificate record and run the recursive verification expression.
A successful call always returns a nonempty list. The caller uses only the truth of that result to
sequence the checked major premise with its associated context resource.
Replace that lambda by a function with a statement body: unpack the same record, evaluate
the same checking expression, and return implicitly. A successful call now returns None. At the
recursive major-premise site replace
c(...) and m * 3 by c(...) or m * 3.
The two expressions have exactly the same value after successful verification: m * 3. The order of
allotheroperationsstaysfixed. Inparticularthegoalisvalidatedbeforetheinitialgoal-validation
phase is cleared, and a fresh parameter is allocated before it is substituted into the new local
resource and successor goal.
Theorem 3.1 (Procedure equivalence). Let L be one of the frozen singleton-list controls, and let
P be its procedure version with the single recursive return-value use changed as above. Under ideal
finite execution, L and P accept the same input certificates. Corresponding successful executions
consume the same records and construct the same intermediate formulas, contexts, substitutions,
and scope floors.
Proof. Induct on a successful finite recursive call tree.
In a terminal call, both programs read and unpack the same record, perform the same
opening of the requested formula, construct the same computation preview, and perform the
same membership test. The result of that test terminates the logical work in either program.
The original call returns a singleton list, whereas the procedure returns None.
In a nonterminal call, the major-premise verification is executed first, at the same context
and floor. Apply the induction hypothesis to it. Its successful return is truthy in L and is None
in P. Both revised sequencing expressions therefore evaluate to m * 3. If this value is false,
the same subsequent introduction expression is evaluated in both programs. Every assignment
expression and every opening operation is in the same order, so the generated local resource,
fresh floor and minor goal agree literally. Apply the induction hypothesis to the minor-premise
call.
For the converse, induct on a successful P-call tree in exactly the same way. Each terminal or
recursive phase has a corresponding successful L-phase. A failing comparison, malformed packet,
exhausted input, failed scope check, or other logical failure occurs before any point at which
the differing successful return values could matter. The internal no-image sentinel is a function
object in both versions; it is never serialized into a certificate and fails the same attempted
numerical comparisons. Thus it introduces no additional successful branch.
The theorem concerns the mathematical checking relation. Concrete interpreter recursion
limits need not be identical: removing the comprehension removes execution frames. This
qualification is the same ideal-execution convention used by the baseline.
For the 579-byte native control the result has 573 normalized bytes. For the 606-byte fully
validated control it has 600. Their source modules also include the same output marker and
the same input parsing and validation. Moving the JSON import below the function definition
changes neither its availability at call time nor the validation contract; that placement is reflected
in the normalized measurements.

3.2 A neutral list extension
Two fully validated profiles extend the context by a neutral resource using
g += [0].
At every entry, g is a Python list: the initial context is a list and recursive context construction
produces lists. Consequently this statement can be replaced by
g += b’\x00’.
Iterating the byte string yields precisely the integer 0. Both statements extend the same existing
list object by the same one element. The neutral resource and all aliases of the context therefore
remain identical. This is an ordinary Python representation change, not a new mathematical
axiom or an encoded proof-checking program.
Proposition 3.2 (Neutral-extension equivalence). The two matched token/AST programs pre-
serve every execution state at the changed statement. They accept the same certificates as their
respective controls, with the same input contract.
Proof. The list invariant follows from the initial call and the recursive context constructor. For a
list g, in-place extension by [0] and by the bytes object of length one with value zero has the
same effect on g. No program operation inspects the source iterable after extension. All later
states are therefore identical, by ordinary induction on execution steps.
This reduces the token-oriented profile from 322 to 320 significant tokens and the AST-
oriented profile from 364 to 362 nodes. It does not minimize bytes; the procedure profile supplies
that coordinate. The compactly encoded literal is confined to the measured programs. The
explanatory implementation uses the explicit neutral list.

3.4 Why the boundary checks are preserved
Several short expressions carry mathematical obligations that cannot be deleted merely because
simple examples still pass:
1. The no-image traversal of a goal checks that an eigenparameter has not escaped. With the
eager decoder, successful validation is literal. With the lazy decoder, the general statement
is semantic retraction.
2. The computation preview is not an arbitrary new assumption. In a successor preview that
uses its state, the recursive source is independently opened at term-root depth. That check
prevents capture through dummy slots under the outer successor. If the update does not
use its state, the constant-update case has its own soundness argument.
3. The fully validated program checks its initial public goal before the phase flag is cleared.
Clearing it early would admit formulas outside the promised grammar.
4. Context resources opened under a fresh parameter remain local. A monotone supply of
fresh names alone does not justify leaking their assumptions into another proof branch.
None of the new transformations removes these checks. The written equivalence proofs preserve
them, and the independent tests exercise their boundaries.

6 Scope of the answer
The concrete improvement is a smaller complete implementation of the presented proof relation.
The strongest newly compared family improves all three coordinates within the fully validated
contract, and the compact companion improves the overall compact byte record at the pinned
snapshot. The mathematical axioms, schemas and inference principles remain those specified in
Section 2.
A globally simplest axiomatization is not established. Neither the repository nor this work
supplies a representation-independent lower bound for all theories bi-interpretable with iPRA.
Several seemingly promising new directions were checked against the incoming archives: counter-
aware root-only conversion, fixed-point preservation, and orbit equality already have proposals
there. The scalar root-only conversion route still lacks the needed proof: its tempting two-row
closure packet expresses an implication, while the transport argument needs both equations; the
usual conjunction packet evaluates parity below an iterator counter. This explains why that
route was not substituted for a proved construction.
Accordingly, the deliverable meets the empirical size comparison by explicitly stated imple-
mentation refinements. It records no claim of a new arithmetic principle, an absolute minimum,
or a mathematical breakthrough that the evidence does not establish.
