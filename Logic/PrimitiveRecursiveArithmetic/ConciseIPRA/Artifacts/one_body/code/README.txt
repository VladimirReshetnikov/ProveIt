EXECUTABLE EVIDENCE FOR THE SINGLE-BODY CONTEXT PRESENTATION
==========================================================

Scope and conclusions
---------------------
checker_one_body.py is a complete standalone checker for the proposed raw
single-body context calculus. It uses ordinary atomic reflexivity, the two
established Eval cases, Use, Open, and Intro. Context entries are single
formula bodies B(y), read B(0) -> forall y B(y). An ordinary local assumption
A is represented by the gated body G_y A. No full or partial computation
normalizer is built into syntax, and no generalized reflexivity axiom is
added. Deep reflexivity is a derived rule.

The exact matched ordinary-clause control is checker_clausal_control.py.
Both checkers validate every formula, term, scope, proof tag, and required
proof-field count. Both reject invalid inputs by printing REJECT and exiting
nonzero; valid certificates print ACCEPT and exit zero. Both work under -O.

The single-body change removes an independent antecedent field from the
context language. It does NOT shrink this straightforward checker:

                              Tokens    AST nodes    Normalized bytes
clausal control                 848        986             2999
single-body candidate           901       1041             3130

The extra code performs the gate construction and its capture-free lifting.
These figures are reported rather than hidden in an unmeasured preprocessor.
There is no claim that the new mathematical presentation beats the current
repository under the minimum-checker-size metric or is globally smallest.

A SEPARATE implementation refinement of the existing full native Eq/D
checker is also supplied. It changes no arithmetic or logical rule:

                              Tokens    AST nodes    Normalized bytes
native control                  358        413              788
native refinement (preferred)   357        412              778
native byte-priority variant     357        415              777

The preferred checker_native_pareto.py saves 10 normalized bytes, one token,
and one AST node: a strict improvement in all three coordinates. The
checker_native_refined.py byte-priority variant saves 11 bytes and one token,
but ADDS two AST nodes; it is not a Pareto improvement. Neither is below the 516-byte compact guarded-public-goal profile reproduced
as baseline_compact_516.py. That 516-byte profile has a different input
contract: it does not validate the public-goal grammar. Do not compare the
778-byte full native public-goal interface and 516-byte guarded compact
interface as interchangeable validators. The independent known coordinate
minima 256 tokens / 278 AST nodes / 516 bytes belong to different programs.

Reproduction
------------
Run from this directory, using CPython 3.12.14 for the recorded metrics:

    python3 reproduce.py

This writes metrics.json and results.json. It measures the complete modules
with ast.unparse(ast.parse(source)) plus one trailing LF, without stripping
any source. It runs 34 raw-calculus certificates in ordinary Python and
Python -O (68 processes), and 12 inherited native fixtures under the control
and both refined checkers in both modes (72 processes). There are also 18,882
validator cases, giving 37,764 candidate/control comparisons and 36,462 independent numerical gate/scope checks.

The gate audit is an independent environment evaluator, not a second copy
of the construction under test. It covers zero and positive gate values,
up to three nested D binders, nested iterator binders, and rigid parameters.
Finite checks are implementation evidence; they do not constitute a Lean
or Rocq verification of soundness, completeness, or bi-interpretability.

Example standalone commands:

    python3 checker_one_body.py < examples/one_body/induction_uses_assumption.json
    python3 checker_one_body.py < examples/one_body/nested_d_assumption_extraction.json
    python3 checker_clausal_control.py < examples/control/induction_uses_assumption.json
    python3 checker_native_pareto.py < examples/native/computation_successor_local.json

build_examples.py reconstructs the small raw-calculus certificates. The
inherited native fixtures are frozen inputs and are not regenerated by it.

Raw term and formula syntax
---------------------------
An integer 0 is numerical zero. Negative integers are fresh rigid
parameters: at scope k the available parameters are -1,...,-k. Positive
integers are 1-based de Bruijn indices. Terms are:

    0, an available rigid parameter, a bound index,
    [0, t]                         successor
    [n, a, h]                      I(n,a;u.h)

Only h binds the state variable u. Its newest bound variable is index 1.

Formulas are [s,t] for equality, and [B] for D_{x,y} B. In a D matrix, y
has index 1 and x has index 2. Atoms may occur under arbitrary D nesting.

A one-body context entry B has one extra implicit bound variable y outside
its own formula binders. Gate construction replaces, under d actual bound
formula variables, each equation endpoint t by

    I(y, 0; u.t), with u unused,

represented as [d+1, 0, lift(t)]. Here lift inserts the unused iterator
binder and is implemented by opening(t, None). At gate value zero both
endpoints reduce to zero; at a successor they reduce to the original terms.
The interpreter does NOT silently perform those reductions. They must be
proved using Eval, including in the generated examples.

Certificate packet grammar
--------------------------
The outer JSON object is exactly {'goal': F, 'proof': p}. Proofs are:

    ['r', t]               atomic reflexivity t=t
    ['v', p, q]            the established two-case Eval
    ['u', index, t, p]     prove B(0) using p; conclude B(t)
    ['e', F, p, branch]    prove D_xy B with p; open at fresh x;
                           append B(x,y) to the one-body context;
                           derive F in branch; discharge the parameter
    ['i', F, t, branch]    F must be D_xy B; choose x=t;
                           append G_v B(t,eta) to the context;
                           derive B(t,Sz) in branch; discharge z

In Intro, eta=z exactly if B is an equation and t is literal zero; otherwise
eta=0. This is the inherited witness-based introduction. All fresh-variable
side conditions are checked through the explicit scope counter.

Eval is either:

    s=t, I(0,s;u.h)=r                 gives r=t,
    I(c,a;u.h)=t, I(Sc,a;u.h)=r       gives r=h[t/u].

The ordinary-clause control has exactly the same proof packet grammar. Its
Use proves a stored antecedent A and then returns a stored body B(t). Its
Open appends (B(b,0), B(b,y)); its Intro appends (0=0, B(t,eta)). Thus the
control and candidate differ in exactly the context discipline and the
new gate/lifting support, with the same inherited Eval reduction in both.

The strongest small example
--------------------------
nested_d_assumption_extraction.json proves the closed conditional identity
D_uv A for A = D_xy (I(y,0;u.1)=0). This A is false in the standard model,
so the branch cannot prove A by ignoring its assumption. The new checker
must recover A from its gated one-body assumption: it proves the zero gate,
uses the closure at 1, opens the inner D, converts the inner base, uses the
inner closure, and converts back before closing the D. This exercises real
compound-formula assumption extraction and binder handling.

induction_uses_assumption.json proves

    D_xy (I(y,0;u.Su)=y)

by the progress case, actually obtaining and using the gated equation
induction hypothesis. elimination_uses_closure.json then opens that theorem
and specializes the resulting closure to a nonzero numeral. Other fixtures
cover both Eval cases, the derived root join, derived deep reflexivity,
and malformed goals, proofs, scopes, context indices, and capture attempts.

Native refinement proof
-----------------------
The preferred native source is preserved apart from local validator changes
2--4 below. The byte-priority variant also includes change 1:

1. ([s,u] if s else [t]*3) becomes (s and [s,u] or [t]*3). If s is true,
   [s,u] is a nonempty list and true; otherwise both choose [t]*3.
2. Under the exact-int branch, a==0 becomes not a and a>=3 becomes a>2.
3. The Boolean default False becomes numeric 0; only its truth value,
   addition to 2, and recursive Boolean propagation are used.
4. After excluding exact integers, a*0==[] succeeds exactly for JSON lists.
   Null and dictionaries now raise TypeError instead of returning false;
   both reject before the proof checker is entered. JSON booleans, floats,
   nonfinite constants, and strings fail the test as before.

Thus the accepted certificate relation is unchanged for finite parsed JSON
inputs, abstracting from resource exhaustion. Rejection exception classes
and diagnostics are not claimed identical. No eager tuple equality was
introduced: in particular no new NaN tuple-identity shortcut is used.
