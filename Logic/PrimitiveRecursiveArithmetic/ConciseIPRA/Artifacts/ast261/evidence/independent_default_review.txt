Exact syntactic comparison
--------------------------
Parsed both complete modules. Deleted the baseline's top-level `k = 0`
and replaced only the last default of function i, the literal zero, with
NamedExpr(Name('k', Store()), Constant(0)). The resulting AST, ignoring
source-position attributes, is exactly the candidate AST. No other
function body, call, import, or output instruction differs.

Semantic proof under the standalone checker contract
---------------------------------------------------
The import is the same. In the baseline, top-level `k = 0` binds module k
before i is defined. In the candidate, evaluation of i's default expression
`(k := 0)` binds the same module k to the same exact integer zero and returns
zero as the default of d. This evaluation takes place once, when the def
statement executes, before any certificate input is read or either checker
function is called. The preceding default 0j is a literal with no effect on k.

Thus immediately after the two function definitions, both modules have
k=0, identical function bodies and defaults i.__defaults__ == (0j, 0).
The functions use module k, and i has no closure. The remaining top-level
code is identical. Induction on the ensuing evaluation establishes the
same input-consumption, proof-checking, scope-update, and ACCEPT behavior.
The initialization is not repeated on calls that omit d: defaults store
the already-computed value, so updates to k during a proof are preserved.

The comparison is of checker behavior: normal termination with exactly
ACCEPT followed by LF versus rejection/nonacceptance. Source filenames,
line-number metadata and printed traceback locations are not identical.
The claim is not a statement about custom trace hooks, code-object
introspection, or adversarially modified Python environments. As usual,
the theorem-set comparison uses the unbounded execution idealization;
arbitrary process-resource limits are not a semantics-preservation theorem.

Runtime cross-checks
--------------------
Compiled and executed the module prefix, before any input. It establishes
k=0 and defaults (0j,0). Then set module k=-7 and called i(-1) with omitted
d: the result is -1, k remains -7, and the defaults remain (0j,0).
This specifically tests that the initializer has not become a per-call reset.
The CPython prefix bytecode stores k with STORE_GLOBAL before MAKE_FUNCTION.
