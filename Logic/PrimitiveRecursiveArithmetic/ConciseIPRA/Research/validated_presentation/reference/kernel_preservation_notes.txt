# Independent review of the candidate checker reductions

## Scope and provenance

This review is by a parallel assistant, not an external human review or a proof-assistant verification. It inspects the proposed Python changes and proves their relevant mathematical invariants. Finite test runs are reported separately by the implementing agent.

The inspected repository is VladimirReshetnikov/ProveIt at commit `a4e5e96c456303cf231eab2aeeb3291d8889833f`. All six incoming ZIP files were obtained through GitHub's base64 file interface. Their decoded byte counts and Git blob SHA-1s were recomputed and matched the repository metadata. `reference/source_provenance.json` records every ZIP's repository path, pinned commit, Git blob ID, SHA-256, byte count, and selected extracted checker hashes.

The genuine compact incoming envelope is 257 significant tokens / 279 AST nodes / 522 normalized bytes, attained by three guarded_source programs. It is not the older 259 / 283 / 526 envelope in the main README. The strict full Eq/Q/D typed control is the byte-exact delivered controls/control_shared_typed.py in the incoming reversal package; it is 1049 normalized bytes. This actual delivered control is the primary comparator. The 1000-byte Eq/D typed comparator is a derived matched restriction of that control to the already existing Eq/D public grammar, and is labeled as such.

## Staged validator specialization: sound

Let J(q) assert that every node of the entire JSON input q is an exact Python integer or an exact Python list. Python booleans are deliberately excluded because type(True) is not int. The recursive predicate `type(a) is int or (type(a) is list and all(map(j,a)))` is exactly J on every finite JSON tree. Replacing a generator-based `all(j(b) for b in a)` by `all(map(j,a))` preserves the truth value and traversal order.

Once J(q) has succeeded, every extracted goal and every subtree passed to the public grammar validator is an exact integer or list. Therefore after the branch that handles integers, the remaining object is already known to be a list. Removing the repeated `type(a) is list` guard is sound. No intermediate mutation changes input node types: popping the outer list only removes a reference to an already checked subtree.

On this staged domain, `a * 0 == 0` is true precisely for integers and false for lists; `a * 0 != 0` selects precisely lists. Thus the changed discriminator in the opener and, if used, in the public validator has the same successful behavior as the old `a * 0 == []` list test. Kernel-generated negative labels, numeric zero and any Boolean zero aliases also have the same scalar behavior. The opener's default invalid replacement is a function object: multiplying it by zero raises TypeError under both discriminators, so it cannot cause a new acceptance. The input stage rejects all user supplied floats, booleans, strings, dictionaries and null before the kernel runs.

For exact integer a, `a==0` can be replaced by `not a`, and `3<=a<d` by `2<a<d`. These substitutions preserve the predicate, rather than merely its standard-model meaning.

## Shared arity tests: sound

The public validator uses odd depth for terms and even depth for formulas. Its depth changes by `5-len(a)` on descent. With only Eq/D public formulas:

- At even depth, `len(a) in (1,2+d%2)` means exactly arity 1 or 2.
- At odd depth it means exactly arity 1 or 3.

For full Eq/Q/D formulas, `len(a) in (1,3,2+d%2)` admits exactly the old arity sets. A separate diagonal-triple test is still necessary at even depth.

A shorter equivalent successful-recognition condition is `(len(a) in (1,2+d%2) or a == [a[0]]*3)`. At even depth its second disjunct admits exactly diagonal Q triples. At odd depth every diagonal triple already has the permitted ternary arity. On an empty list the second disjunct may raise IndexError; this is rejection under the explicit checker contract, matching the old validator's False result. If the validator itself is claimed to be a total Boolean predicate, retain an explicit nonempty guard instead. Do not claim total-predicate equality for the partial spelling.

## Single raw/goal validator: sound invariant

The code-sharing design, adopted in the final native checkers, uses one validator. The final actual-source review is in `evidence/mathematical_review.md`. Its mode/depth parameter d has this meaning:

1. d=0: check only raw exact integer/list syntax, recursively preserving d=0.
2. d>0: check canonical syntax at old opener depth d-2; the public formula call is therefore V(goal,2).

The descent `d and d+5-len(a)` keeps raw mode zero and advances canonical mode by exactly the old amount. The parity of d is the parity of d-2. The integer bound becomes `2<a<d-2`, exactly the old `3<=a<old_depth`; numerical zero is unchanged. In raw mode the first `not d` alternative accepts every exact integer and suppresses arity restrictions on lists. The list discriminator still rejects other JSON types. A structural induction establishes both invariants simultaneously.

If V uses `a*0==[]` in place of `type(a) is list`, non-list JSON values either give False or raise before acceptance. In particular bool and float multiply to numeric zero, strings to empty string, neither equal to [], while dictionaries/null raise. Such a version recognizes exactly the desired raw language but is a partial recognizer, not a total predicate on all JSON values.

It is also sound to pop the goal before the typing check and then check V(remaining_packets,0) and V(goal,2): successful canonical goal validation implies raw typing of that goal, so together these checks cover the entire original input, including unused prefix packets. Non-list top-level JSON values fail the argument-free pop. For a fair byte comparison, do not credit arbitrary shortening of error-message text as a mathematical simplification; document any merged diagnostics or keep matched messages.

## Tail-recursive continuation replaced by a loop: sound with immutable context

The original global-floor compact checker recursively calls itself on the continuation after each instruction. Replacing just this tail call by updating the local goal and context and repeating a while loop preserves every idealized finite successful trace. Recursive major-premise checks must remain recursive. Global freshness allocation must stay in the same order.

The retained context must be immutable or rebound. The selected `code/guarded_tokens.py` uses tuples: `g += (resource,)` creates a new tuple bound to the current invocation's local g. The tuple passed to a recursive major check cannot be changed in the caller. This is safe and was independently inspected.

The exploratory `global_loop.py` uses `g += [resource]`, which mutates a shared list and can leak assumptions from a major subproof. That prototype must not be delivered as an accepted checker. Rebinding with `g = g + [resource]` would also be safe. The implementer has confirmed the tuple profile is the selected one.

On finite hardware, loop conversion can avoid RecursionError on proofs for which the old tail-recursive program exhausted its stack. The exact equivalence claim is under the repository's ideal finite-certificate convention, not equality of every machine's resource-failure behavior.

## Neutral truth plus exact-root introduction: sound

The detailed proof is in `evidence/neutral_zero_exact_root.md`. Initial formula truth [] can be replaced by formula truth 0, while dummy computation/introduction majors are changed from [] to 0 in generated certificates. The negative-variable floor and initial context length do not change. Every ordinary packet case remains sound under the guarded auxiliary decoder.

One additional raw case deserves explicit mention: a nonzero scalar major may now normalize to retained truth 0. It cannot equal the list-valued elimination matcher; multiplying it by three exports only another scalar truth. It cannot create an equation or closure. Thus no new canonical public consequence appears. Canonical completeness follows by changing only neutral-major packet fields in the existing compiler. This transfers the existing guarded public bi-interpretation; it does not establish a new full-language auxiliary round trip.

## What may be claimed

These are smaller complete checker implementations of already described presentations. The parser and continuation transformations are proved program refactorings, and the neutral/exact-root composition preserves the inherited canonical guarded consequence relation. They do not supply a new arithmetic foundation, a new proof-assistant verification, a global lower bound, or an absolute simplestness theorem. Distinguish native full Eq/Q/D, native public Eq/D, and guarded compact contracts in every comparison. State that separate profiles attain separate coordinate minima.

The executable core's iPRA bi-interpretability follows from unchanged native consequence relation or from the established guarded public equivalence, as appropriate. Both ordinary numerical domains and equality are unchanged in these transformations. The inherited interpretation proofs are mathematical dependencies, not consequences of finite tests or byte counts.

## Precise acceptance convention

Define V(a,d) to mean that the new call `v(a,d)` returns a truthy value normally. An exception means rejection. This distinction is necessary: for example, the full `v([],2)` reaches `a[0]` and raises, whereas the old goal validator returned false. Likewise `v(None,0)` raises on multiplication, whereas the old exact-type recognizer returned false. Neither difference changes acceptance.

Let J(a) mean that a is a finite tree containing only exact Python integers and lists. Thus externally supplied Boolean, floating-point, string, dictionary and null nodes are excluded. Let P(a,delta) be the previous scoped goal predicate, with delta=0 at a formula root and delta=3 at a numerical root. All equivalences below concern finite JSON values and successful acceptance, apart from ordinary host resource exhaustion.

## Universal validator equivalence

### Generic mode

For every finite JSON value a,

    V(a,0) if and only if J(a).

Proof is by structural induction on the JSON value. At an exact integer, the branch `not d` is true. At a list, `a*0 == []` is true, the local shape condition is true because d=0, and each recursive call receives `d and d+5-len(a)`, which is again zero. Hence the list passes precisely when each child satisfies J.

Every other JSON type either makes `a*0 == []` false or raises before returning truthy. For instance Boolean multiplication produces numeric zero, not the empty list; strings produce the empty string; dictionaries and null raise. This proves the equivalence, not merely one implication.

### Goal mode

For every delta reachable through an allowed goal constructor,

    V(a,delta+2) if and only if J(a) and P(a,delta).

The shift by two preserves parity. For an exact integer, the new test is

    (delta+2) % 2 and
    (not a or (2 < a < delta and a % 2)).

For integers, `not a` is equivalent to a=0 and `2<a` to 3<=a. This is exactly the old test: a scalar occurs only in a numerical position and is zero or an odd protected coordinate below delta.

At a numerical list node, delta is odd, so `len(a) in (1,2+d%2)` permits exactly arities 1 and 3: successor and iterator. In the full validator, the extra triplication disjunct cannot add another arity, because `a == [a[0]]*3` forces arity 3.

At a formula list node, delta is even. The full validator permits arities 1 and 2 directly, denoting D and equality. Its extra disjunct admits exactly the canonical Q arrays with three identical children. This is equivalent to the old test permitting arities 1,2,3 and requiring identical children in the arity-3 case. The Eq/D variant simply lacks that extra disjunct and permits formula arities 1 and 2.

For each permitted arity r, the new child depth is

    (delta+2)+5-r = (delta+5-r)+2,

so the induction hypothesis applies to every child. Starting from delta=0, allowed arities 1,2,3 increase delta by 4,3,2 respectively. Thus goal mode never accidentally enters generic mode d=0. All other shapes reject before any successful recursive traversal can create such a transition.

This establishes the full equivalence by structural induction. It is an unbounded argument for every finite JSON tree, not a finite-test claim.

### Prefix and goal jointly cover the original input

The final program first pops the last array element as the goal a and leaves the preceding certificate packets in q. It accepts the front end precisely when

    V(q,0) and V(a,2).

For a nonempty top-level JSON array, the two preceding equivalences identify this with

    J(q) and J(a) and P(a,0),

which is exactly the old global integer/list check followed by the old goal check. The extracted goal and the remaining prefix partition the original array, so no subtree escapes validation. Every non-array top-level JSON value, and an empty top-level array, rejects before entering the checker. The old interface also rejected these inputs.

The program then takes `q.pop` as its instruction source. No checker action occurs before both validation calls have succeeded.

## Opener invariant and unchanged proof semantics

After the front end succeeds, every input subtree is an exact integer or list. The checker creates only further list/integer data, harmless Boolean zero images, and a missing-image function sentinel that cannot be used successfully as numerical data.

For an integer, `a*0` is numeric zero. For a list, it is the empty list. Thus the new opener test `a*0 != 0` agrees with the old `a*0 == []` on every successful data case. A used function sentinel raises in both versions. No new inference is authorized by this replacement.

The inference engine otherwise retains the matched native calculus and its choice bit for case versus equational-progress introduction. The full strict checker is not the separate guarded deterministic-introduction calculus. In particular, the final full result needs no new guarded/public auxiliary-language bridge.

The inherited arity encoding has dummy numerical slots. Its soundness and completeness statements use the specified sorted decoding and intended encodings. No additional claim that every noncanonical raw alias is interchangeable is needed here: the new front end and the matched control have the same acceptance predicate.

## Immutable continuation loop

The separate compact token profile replaces the final recursive continuation by a loop. The retained context is a tuple. An extension `g += (h,)` rebinds a local variable to a new tuple, so recursively checking a major premise cannot mutate its caller's context. An in-place list extension would not be justified by this argument and could leak local hypotheses.

The loop maintains the same goal, context, instruction-stream position and global fresh-parameter floor as the recursive continuation. Major-premise recursion remains recursive. The fresh floor decreases at the same allocation points and is not restored on return. Reordering the two pure opening computations for the next goal and hypothesis preserves successful results; failure of either prevents acceptance.

This is a control-flow simplification, not a change to freshness, numerical substitution or the theory's induction strength.

## Neutral truth is inherited

The scalar formula representation 0 denotes the closed theorem 0=0. Adding a fixed closed theorem T to every retained context preserves consequence when weakening and assumption cut are admissible:

    Gamma,T |- A if and only if Gamma |- A.

For the restricted-source calculus, 0=0 is already derivable. Put c=I(0,0;u.0). Its computation equation c=0, used as both transport premises with F(v):=(v=0), yields 0=0; c is not the literal zero term. Cut requires no substitution of numerical terms into restricted sources.

This justifies the representation but supplies no new mathematical novelty: scalar truth already occurs in the matched incoming full control.

# Neutral scalar truth with exact-root introduction

## Precisely proposed modification

Start with `ipra_guarded_source_2026-11-11/.../code/checker_bytes.py` and change the initial retained resource from `g=[[]]` to `g=[0]`. In the AST loop profile change `g=([],)` to `g=(0,)`. Keep `len(a)==2`, every normalization bound, the order of major verification, and freshness allocation unchanged. In canonical completeness certificates use major `m=0` for computation and introduction packets formerly using `m=[]`.

This composes two independently delivered changes: exact-root introduction from guarded_source, and scalar administrative truth from reversal_core. It is a new composition of those sources, not a new arithmetic/logical principle. The meanings of public formulas and the canonical public grammar are unchanged.

## Soundness, including additional raw accepted inputs

Use guarded_source's auxiliary reading: atomic equations mean actual equality; Q means anchored closure; D of an equation means existential progressive closure; D of a compound means existential anchored closure. On canonical guarded public formulas this agrees with the ordinary inherited reading. Administrative raw scalars at formula sort and harmless padding formulas denote truth. In particular both raw `0` and raw `[]` at formula sort denote truth; numerical `0` and the contradictory equation `0=S0` are different syntax positions.

The initial context changes one true administrative resource to another. All pre-existing primitive instruction cases and the sanitizer are unchanged. The exact-root test is especially transparent: with no proved major, a literal binary equation matrix gets its predecessor instance; a nonbinary matrix gets its zero instance. Thus an unrestricted compound progressive induction is not introduced.

One new successful raw trace possibility must be checked explicitly. A nonzero scalar major m can now normalize to the retained formula truth 0 and return immediately. This is harmless: the elimination matcher compares m with a nonempty list, so it cannot match such a scalar. Its exported resource is `m*3`, another scalar, hence another administrative truth. It therefore cannot generate an equation or anchored closure. Other positive major cases are exactly the old ones: a unary list D exports the diagonal Q resource; a binary equation or a triple Q exports only a padding list, besides any independently checked elimination; still longer arities export padding. Falsy scalar 0 selects the same computation/introduction cases as empty-list neutral truth did. The bounds/freshness phase is unaffected, because initial contexts still have length one and the same k=0.

Consequently the inherited accepted-trace induction works with initial decoded context {truth}. Every newly accepted canonical public goal is provable in iPRA under its ordinary guarded reading. By the inherited guarded formula round trip and completeness, it was already a canonical consequence of guarded_source. No additional canonical consequences are obtained.

For exact integer/list certificates this is immediate from the displayed decoder. For the compact all-JSON convention, the same noninteger successful-trace restrictions as the parent remain needed; the new scalar-major case cannot pass the list-valued matcher and only exports scalar truth. Do not silently claim strict type validation: the compact modules still have none.

## Completeness

The canonical proof compiler can use the same construction as guarded_source, replacing each administrative dummy major [] by 0. Only that packet field changes; an indiscriminate recursive replacement of all empty arrays is unnecessary. For these generated proofs the two kernel executions correspond at every rule:

- Both neutral majors are falsy and accepted directly from the respective initial contexts.
- Neither matches a nonempty equality or Q major.
- Their threefold products are falsy, so the computation/introduction resource is identical.
- The source classifier and exact-root introduction choice are identical.
- The negative-variable floor and all freshly allocated labels are identical.

Every canonical guarded derivation therefore still has an accepted certificate. Combining completeness and soundness gives exactly the same canonical public consequence relation, so both inherited iPRA interpretations and both formula composites transfer unchanged. This is stronger than mere equiconsistency.
