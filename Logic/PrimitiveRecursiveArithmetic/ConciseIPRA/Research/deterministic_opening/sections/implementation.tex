\section{The executable presentation and its checks}
\label{sec:implementation}

\subsection{Exact certificate interface}

The selected new checker is \path{code/checker_open.py}.  It is a
standalone standard-library Python module.  Its input is one JSON object
with exactly the fields \texttt{goal} and \texttt{proof}.  The goal must
be a closed canonical formula.  Successful checking prints
\texttt{ACCEPT} and exits with status zero.  Exceptions print
\texttt{REJECT} and exit nonzero.  Trust decisions do not use Python
\texttt{assert}, so optimization does not remove them.

The sorted encoding uses integer $0$ for numerical zero, negative integers
for free parameter levels, and positive integers for bound de Bruijn
indices.  A term successor is \texttt{[0,t]}, an iterator is
\texttt{[n,a,h]}, an equation is \texttt{[s,t]}, and a paired formula is
\texttt{[B]}.  The same two-element raw list can therefore encode a
successor or an equation; the syntactic sort distinguishes them.  An
iterator binds only its update body.  A paired formula binds two variables,
with $y$ the innermost coordinate and $x$ the next coordinate.

At numerical scope $n$, fresh parameter $b$ is represented by $-n-1$.
Clause positions are nonnegative actual integers, not Boolean values.
The initial context is the single unconditional reflexivity clause.
The three proof packets are
\begin{verbatim}
["u", clause_index, term, antecedent_proof]
["i", witness, branch_proof]
["e", matrix, major_proof, branch_proof]
\end{verbatim}
An unconditional clause has no antecedent proof; that payload is ignored,
and \texttt{null} is the recommended spelling.  This is a nullary
inference, not acceptance of an unchecked premise.  The Open packet is
shorter than its predecessor's
\begin{verbatim}
["e", matrix, branch_formula, target,
      major_proof, equality_proof, branch_proof]
\end{verbatim}

The shared syntax walker checks sorts, scope, and canonical normal form.
It also implements capture-free normalized substitution.  Open first
checks its major, then probes the matrix at fresh $b$ and at numerical
$1$, chooses the witness by the stated literal test, and adds the clause
at that chosen value.  Its branch is checked against the same outer goal,
in scope $n+1$.  The outer goal has already been checked in scope $n$,
which enforces the eigenvariable condition even when the chosen value
contains $b$.

Because the probe is already known to be a well-formed formula, testing
whether its first child is the integer representing $b$ also establishes
that it is an equation: a $D$ formula has a formula, hence a list, as its
first child.  This implementation fact is not permission to omit the
mathematical requirement that the probe be literally $b=t$.

The zero-row test also uses the checked grammar: \texttt{not any(base)}
is true exactly for the equation \texttt{[0,0]}.  Every nonzero numerical
term is a nonzero integer or a nonempty list; the sole child of a $D$
formula is a nonempty formula list.  No other well-formed formula has
only false-valued immediate children.  The major proof is checked before
this test, so the invariant is already established.  After the successful
left-child test, the equation's right side is safely selected at index
\texttt{1}.

\subsection{Measured effect of the new rule}

The old and new complete modules share the same normalizer, syntax checks,
Use, Introduce, JSON entry point, and verdict convention.  The changed
instruction is Open.  After removing actual docstrings and applying
\texttt{ast.unparse}, with one terminating line feed, the sizes are
\[
\begin{array}{c|rrr}
 &\text{bytes}&\text{significant tokens}&\text{AST nodes}\\\hline
 \text{predecessor}&2273&732&813\\
 \text{automatic opening}&2253&730&809
\end{array}
\]
The measurement is a modest reduction in all three matched source-size
coordinates.  It does not approach the historical compact protocol's byte
count; the two interfaces use substantially different encodings and
validation contracts.  The complete selected source is reproduced in
Appendix~\ref{app:source} and supplied separately for execution.

For completeness the archive retains an intermediate variant that
determines the same equality but substitutes in a supplied branch formula
at export.  It has three instruction families and two proof premises at
discharge, but still requires the intermediate formula.  Its checker is
2,296 bytes, 745 tokens, and 828 AST nodes, so it is not the selected
implementation.  Its proof and tests document the route to the stronger
opening rule; its size is not reported as a record.

\subsection{Executed evidence}

The primary opening suite has 16 accepted and 19 rejected closed
certificates.  Each was run in a fresh ordinary Python process and a fresh
optimized process.  The 16 accepted theorems also have matching proofs
checked by the old checker and independently replayed by a differently
structured inherited kernel.  The suite additionally checks a genuinely
open parameter sequent.  Its examples include symmetry, transitivity,
repeated occurrences in a numerical template, nested iterator congruence,
nested formulas, a used induction hypothesis, default openings, forced
witness selection, and a selected term containing the fresh witness.

The difficult substitution transition also has a direct test. A source
proof whose opening uses the fresh parameter is accepted. Substituting
only its passive parameter makes extraction succeed and leaves an invalid
branch, which is rejected. Instantiating the original smaller branch at
the newly selected witness, exactly as in the substitution theorem, is
accepted. The same three results hold with Python optimization enabled.

The intermediate variant adds 17 accepted and 20 rejected fixtures and a
checked executable translation of its valid fixtures to the predecessor.
Together the two suites and their guard mutants use 222 fresh checker
processes, including optimized runs.  All expected verdicts hold.

The correct checker rejects all three attacks.  These tests matter because
the changed instruction's apparent simplicity depends on those exact
conditions; removing them is not another valid simplification.

For the primary opening system, the executable tests supply matching old
proofs of the tested theorems.  They do not constitute a generic executable
compiler for every opening proof.  The universal translations, including
the strong-substitution construction and its introduction-mode repair,
are the written metatheorems above.  The separate compact refactor's tests
and trace proof are reported in the next section.

\subsection{Reproduction}

The archive has a single top-level reproduction command:
\begin{verbatim}
python3 reproduce.py
\end{verbatim}
It reruns both new-rule suites, the compact matched comparisons, and the
source measurements.  To check an individual new proof, for example:
\begin{verbatim}
python3 code/checker_open.py < examples_open/positive/reflexivity_0.json
\end{verbatim}
The bundled \texttt{build\_report.py} assembles a standalone LaTeX source
from the editable sections and embeds the selected source listings.  Run
it with \texttt{--pdf} to compile the PDF.  LaTeX compilation requires
\texttt{pdflatex} and standard TeX Live packages; the mathematical
certificate programs require only Python's standard library.
