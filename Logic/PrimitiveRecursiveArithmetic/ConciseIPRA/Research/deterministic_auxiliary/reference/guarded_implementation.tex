\section{Executable checker and its exact theorem}
\label{sec:implementation}

\subsection{Statements, certificates, and acceptance}
Each compact checker is one standalone Python file importing only the
standard JSON parser. Input is a JSON array: the encoded goal is last,
and instruction packets precede it in reverse execution order. The
driver pops the goal, then the checker pops the instructions it needs.
Normal exit with exactly \texttt{ACCEPT} is acceptance. An exception,
nonzero exit, timeout, or resource exhaustion is not acceptance.
Unused prefix packets are permitted, as in the reference protocol.

There are three distinct syntactic levels:
\begin{enumerate}
\item The canonical object language is exactly the guarded Eq/$\D$
language of Section~\ref{sec:guarded-core}. Closed canonical goals have
the integer-and-array encoding below.
\item Administrative proof resources additionally contain $\Q$ closures,
unguarded atomic paired formulas, and zero/truth aliases. They have the
mixed reading proved sound above.
\item Arbitrary JSON input may fail during traversal. A successful use of
surplus syntax must have the stated zero or truth meaning; it is never
treated as an unconstrained new arithmetic or logical symbol.
\end{enumerate}
The compact kernel checks proofs relative to this decoding contract.
It is not itself a parser that rejects every noncanonical end statement.
The separately supplied strict profile does enforce a canonical closed
goal at its public boundary.

\subsection{The inherited arity encoding}
The raw shape, rather than a string tag, identifies a constructor. At a
formula position, unary arrays represent $\D$, binary arrays equality,
and ternary arrays administrative $\Q$. Canonical $\Q$ resources use
three copies of the body. At a numerical position, unary arrays are
successors and ternary arrays are iterators. Zero is encoded by the
integer $0$ in canonical terms.

\begin{center}\small
\begin{tabular}{cll}
\toprule
Arity & Numerical meaning & Formula meaning\\
\midrule
0 & zero & $0=0$\\
1 & successor & $\D_{x,y}B$\\
2 & zero annotation & equality\\
3 & iterator & administrative $\Q_yB$\\
$\geq4$ & zero annotation & $0=0$\\
\bottomrule
\end{tabular}
\end{center}
The first two fields of a ternary formula are annotations; the third
is its body. A unary major $[B]$ is exported as $[B,B,B]$ on paired
elimination. Tripling any other nonempty formula array produces only
a truth alias. This is an inherited implementation device, not a new
logical rule.

Bound numerical coordinates have width two. With $p$ protected slots,
formula root depth is $2p$, and numerical root depth is $3+2p$.
Coordinates $0,1,2$ denote zero; $3+2j$ and $4+2j$ name the $j$th
protected slot. Canonical encoding chooses the odd coordinate.
Negative coordinates name rigid parameters admitted by the current
floor. Successor introduces two dummy zero slots; an iterator introduces
one slot, dummy in its counter and initializer and genuine state in
its update. Thus traversal can uniformly increase depth by
\(5-\operatorname{arity}\).

The opener preserves a scalar in the protected interval and substitutes
the supplied numerical image at a relevant unprotected hole. Images are
checked at numerical root depth three. Formula-position scalar padding
is truth. Newly allocated negative names are fresh because earlier
goals and retained resources were checked at the old floor. Fractional
names, if admitted by a compact profile, denote additional fresh
parameters and are never silently identified with the designated
integer eigenparameter. The full inherited proof and alias tables are
in \file{reference/inherited_arity_checker.tex}.

A canonical atomic guard
\(I(y,0;u.h)=I(y,0;u.k)\) immediately beneath $\D_{x,y}$ has each side
encoded as \texttt{[5, 0, body]}. The coordinate 5 names the paired
universal variable after the iterator's dummy slot. This makes the
optional strict goal check a literal structural test; no numerical
evaluation or theorem search is used.

\subsection{The mathematical change in the source}
In the byte reference the continuation image is
\begin{lstlisting}
(m or len(a) % 2 == u) and k
\end{lstlisting}
Here \texttt{u} carries an old introduction choice in the introduction
branch. The guarded checker uses
\begin{lstlisting}
(m or not len(a) % 2) and k
\end{lstlisting}
instead. Among meaningful matrix roots, only equality has even arity.
Its introduction therefore retains the progress instance. A paired or
administrative closure matrix has odd arity and retains its zero
instance. Even surplus roots denote truth, for which induction is
valid. The fourth-field witness and the computational initializer
protocol are unchanged; a falsy field that previously selected case
versus progress no longer makes that choice.

This is not a deletion that preserves arbitrary unguarded native
formulas under their old meanings. The guard restriction, the recovered
equation induction, and the administrative mixed soundness theorem are
what make the change correct.

\subsection{The two further compact profiles}
The byte profile \file{code/checker_bytes.py} moves the major check into
the beginning of the hypothesis-supply expression:
\begin{lstlisting}
h = c(m, g, k) or ...
\end{lstlisting}
A successful call to \texttt{c} always returns \texttt{None}. The major
check is therefore still mandatory, and the supply expression continues
only after success. The earlier endpoint comparison is a pure opener
calculation; it consumes no instructions and changes neither the context
nor the lexical floor. Moving that calculation before the major check
does not change any successful proof. It can change which error occurs
first for an unsuccessful certificate, which has no logical effect.

The AST profile uses the inherited lexical loop and the same composition;
the token profile uses the inherited global-floor prevalidated
elimination protocol. Each profile receives certificates in its own
documented protocol. In particular, global and lexical fresh-name
supplies are not silently interchanged. The named untrusted producer
emits both forms, and the reproduction script selects the appropriate
fixture for each program.

\subsection{Soundness and canonical completeness}
\begin{theorem}[Checker contract]
For every canonical closed guarded formula $A$, there is an accepting
finite certificate with canonical encoded goal $A$ if and only if
$\mathcal G\vdash A$, in the ideal unbounded implementation.
Every accepting administrative certificate has an iPRA-provable mixed
reading. The numerical interpretations are those already proved for
$\mathcal G$; no theorem producer or external database is trusted.
\end{theorem}
\begin{proof}
For soundness, induct on a finite accepting call tree. The opener and
freshness lemmas are unchanged from the inherited arity proof.
Hypothesis closure, numerical transport, closure specialization,
paired elimination, and generated computation supplies have the same
structural verification as before. An atomic paired formula is now read
progressively; its exported $\Q$ clause follows by equation induction in
iPRA. Compound paired formulas keep their ordinary reading.

In an introduction continuation, the parity test now supplies exactly
the root-determined premise. Atomic progress is sound directly for its
progressive administrative reading. Compound case introduction is sound
using numerical coverage. Truth aliases remain harmless. A computation
hypothesis with only a known zero instance is discharged by substituting
zero for its fresh parameters and cutting the computation proof, exactly
as in the inherited zero-supply lemma. The mandatory major verification
and the profile's scope discipline are preserved.

For canonical guarded $A$, the mixed reading is provably equivalent in
iPRA to its uniform ordinary reading. The explicit bi-interpretation of
$\mathcal G$ therefore converts the accepted proof back into a guarded
proof of $A$. This last step is why the soundness theorem remains valid
even if a certificate uses unguarded intermediate resources.

Conversely, encode a finite guarded proof with fresh integer names.
Use the inherited packets for computation, transport, clauses and
elimination. At introduction, a canonical atomic matrix always uses
progress and a compound matrix always uses cases, exactly matching the
new parity test. A restricted computation leaf is repaired as a
standalone equation, preserving its original conclusion by transport;
this does not replace the literal zero initializer inside a canonical
paired guard. When the dispatch interface requires a nonempty witness,
use the computation-backed box $I(0,t;v.0)=t$ for the existential
substitution parameter. This preserves the matrix's fixed guard syntax.
Thus every
canonical guarded proof compiles to a finite accepting certificate.
\end{proof}

This theorem is deliberately not a full formula-composite claim for
every administrative array. The unrestricted raw atomic $\D$ calculus
has two sound standard-number readings that disagree on unguarded
matrices. For example, with unused $x$ and $E(y)\equiv y=1$, its old
conditional reading is true while its progressive reading fails at
$1\to2$. A formula composite through the guarded embedding identifying
this unrestricted binder with its progressive reading would contradict
that model. No impossibility result for every conceivable interpretation
of the administrative theory is asserted.

\subsection{Explicit canonical-goal validation and its cost}
\file{code/strict_checker.py} is also standalone. It validates a closed
integer-and-array Eq/$\D$ goal, admits only the canonical odd bound
coordinates and literal zero, and checks that every atomic paired
matrix has both sides prefixed by \texttt{[5, 0]}. It then runs the
complete direct kernel. It does not restrict administrative intermediate
resources, whose soundness is proved separately. This validates the stated
canonical arity convention, not a unique raw spelling: an allowed odd
coordinate may name a dummy zero slot.

\subsection{Executable evidence}

The canonical examples exercise both computation equations, numerical
transport, guarded introduction and elimination, implication between
equations, and compound case introduction. The nontrivial guarded
induction example compiles to 176 instructions in the lexical protocol;
its progress hypothesis is used through the compound implication and
case construction from the proof of equation induction. The named-proof
audit records 13 atomic paired occurrences in that example, all guarded.

The inherited negative controls check false conclusions, incorrect
computation endpoints, escaping names, leaked contexts, missing packet
fields, and forbidden compound progress. One inherited control changes
only the retired case/progress field; it is intentionally accepted by
the deterministic checker when its atomic progress proof is otherwise
valid. The receipt labels this behavioral change explicitly. All other
expected rejections and the old unguarded case counterexample are
recorded separately.

These checks establish that the supplied programs and certificates behave
as reported. They do not replace the universal soundness, completeness,
and interpretation proofs above. Physical stack and memory limits can
reject a finite proof that would be accepted in the ideal implementation,
as for the reference checkers; resource exhaustion never proves a theorem.
