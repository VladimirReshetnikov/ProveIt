SCOPE AND JUSTIFICATION OF THE CHECKER REFACTORING
================================================

This is an implementation refactoring of the deterministic auxiliary calculus
already present in ProveIt. It is not a new arithmetic axiomatization, a
smaller mathematical rule inventory, or a proof of global minimality.

The inherited bi-interpretation concerns the guarded public Eq/D language.
Intermediate proofs can contain the larger auxiliary Eq/Q/D language.
The compact programs do not check the public-goal grammar; checker_strict.py
does, and also rejects every certificate item other than an integer or list.
The strict parser is inside the measured standalone module. In particular,
the guarded-goal contract is not silently charged as zero bytes.

1. EXACT BOOLEAN DISPATCH REFACTORING

The expression

    [s,u] if s else [t]*3

can be replaced by

    s and [s,u] or [t]*3.

When s is false both expressions return [t]*3. When s is true, [s,u] is a
two-element list and hence true, so both return exactly that list. No field
is traversed or mutated by these list constructions. Both perform the same
truth test on s. This proves equality of the selected value for every JSON
value of s, u and t, not only canonical integer/list data. Nothing else is
changed in checker_exact.py. Its successful traces are those of the frozen
522-byte source, with the same scoped substitution and continuation order.

2. JOINT COMPARISON AND EAGER PREVALIDATION

For integer/list syntax, structural equality of pairs gives

    (m,a) == (expected,i(t,u))

exactly the Boolean value of

    m == expected and i(t,u) == a,

provided the opening i(t,u) is defined. The new condition evaluates i(t,u)
even when m is not the expected major. It cannot turn a rejected integer/list
trace into an accepted trace: if the new computation succeeds, its branch
test equals the old test and every state transition is the old transition.
Extra evaluation failures can only reject additional noncanonical packets.
No all-JSON acceptance equality is claimed. In particular, NaN equality and
Python tuple identity shortcuts are outside this argument; the strict module
rejects them before checking a proof.

Completeness is preserved at the canonical certificate interface. In an
elimination packet, the old checker already evaluated i(t,u). In a computation
packet, t is a numerical update body; in an introduction packet, t is a
numerical witness. A canonical numerical term has only odd list arities
(one for successor, three for iteration). Starting at formula depth zero,
the opener therefore stays at even depth, because every increment 5-r is
even. At an integer leaf it either retains that integer or returns padding
zero. It never opens the proposed image u. Thus i(t,u) is total on these
finite canonical numerical fields, independently of u. In a D-elimination
packet, the fields s,u,t are inert and the compiler may choose zero for all
three. This proves that the ordinary native-rule compiler has the extra
totality needed by eager prevalidation. The idea of prevalidation itself is
already present upstream; the paired comparison is a source refactoring.

3. INTEGER/LIST DISCRIMINATION

On an integer n, n*0 is 0, whereas on a list L, L*0 is []. Consequently

    a*0 == []          and          a*0 != 0

select exactly the same branch for every integer/list tree. The latter
expression saves one token, one AST node, and one normalized byte. It changes
some noncanonical JSON aliases (for example, an empty string can be traversed
as an empty array); no equality of those broader languages is asserted.
The strict integer/list validator makes this discrimination change exact
on every input reaching the proof checker.

4. NEUTRAL ZERO

The root formula padding value 0 and the empty array [] both mean administrative
truth in the inherited sorted interpretation. The initial retained neutral
formula can therefore be 0. Canonical packets then use major 0 in place of
major []. This representation is already used in the upstream reversal_core
programs; it is not claimed as a new idea. For the supplied canonical fixtures,
the conversion changes only the first field of a four-field instruction
when that field is the empty array. It leaves goals and all other fields
unchanged. The mathematical consequence relation on public formulas is
unchanged. The compact zero program and the AST zero program use this convention.

5. THE SCOPE STATE MUST STILL BE UPDATED AT THE RIGHT TIME

At entry to a local checker call, k=1-len(g). Nevertheless this identity does
not justify deleting k from the program. Immediately before opening the
continuation, the original program decrements k while g still has its old
length. The opener closes over the updated k and can therefore validate the
newly allocated eigenparameter. Replacing every read of k by 1-len(g) without
also changing the phase order rejects valid witness-opening proofs.

The finite certificate

    [[[],0,[-1],0],[[],0,0,0],[[[0,5,0],3]]]

is accepted by the frozen checker and the new local compact checkers. It proves
an auxiliary D formula with matrix I(0,y;u.0)=y, by introduction followed by
zero computation. It is rejected by the naive context-length replacement.
None of the distributed checkers makes that invalid replacement.

6. WHAT THE EVIDENCE DOES AND DOES NOT ESTABLISH

The frozen source bytes are checked against their upstream Git blob hashes.
reproduce.py measures complete modules and runs the positive and adversarial
fixtures with ordinary Python and python -O. It additionally checks strict
malformed-data prefixes and the used-fresh-parameter example above.

These are finite implementation checks. The universal arguments above are
written proofs, relative to the inherited calculus and its established
guarded-public-language interpretation. No Lean/Rocq verification or new
proof of the arithmetic bridge is claimed. Byte, token and AST coordinates
for different programs must not be combined into a fictitious single checker.
