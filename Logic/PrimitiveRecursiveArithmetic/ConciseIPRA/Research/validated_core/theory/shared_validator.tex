\subsection{One recursive validator, with a raw mode}

The final programs go further than the staged simplification. They
use one recursive predicate $V(a,d)$ for both input tasks:
\[
 \begin{array}{c|l}
 d=0&\text{validate an arbitrary integer/list certificate tree},\\
 d>0&\text{validate public syntax at the old depth }d-2.
 \end{array}
\]
The public goal starts at $d=2$. Adding two preserves depth parity.
At an integer, the scoped upper bound becomes $d-2$. At a list,
raw mode stays at zero; scoped mode advances to
$d+5-\operatorname{len}(a)$. The arity constraints are active only
in scoped mode.

Here $V$ denotes \emph{normal truthy acceptance} by the validator,
not literal equality of returned Python Boolean values. An exception
denotes rejection.

\begin{lemma}[The two validator invariants]
For every finite JSON value $a$,
\[
 V(a,0)\quad\Longleftrightarrow\quad J(a).
\]
For every old syntax depth $\delta\geq0$,
\[
 V(a,\delta+2)\quad\Longleftrightarrow\quad
 J(a)\ \wedge\ v_{\mathrm{old}}(a,\delta),
\]
where the old predicate is likewise understood as normal truthy
acceptance under the matched public grammar.
\end{lemma}
\begin{proof}
For raw mode, exact integers pass. Among noninteger values furnished
by JSON, only lists satisfy $a*0=[]$; other values either fail that
test or raise. At lists the arity guard is vacuous and all children
remain in raw mode. Structural induction proves the first statement,
including rejection of booleans, nulls, strings, objects, and floats.

In scoped mode an integer is accepted exactly at numerical parity
and at zero or an in-scope positive odd slot. The upper bound $d-2$
is precisely the old upper bound $\delta$. For lists the shared
arity lemma applies. The child depth is
$(\delta+2)+5-\operatorname{len}(a)$, two greater than its old child
depth. The induction hypothesis proves the second statement.
Invalid empty lists may raise instead of returning false; both
are rejections.
\end{proof}

The input flow pops the advertised goal $a$, then validates the
remaining prefix $q$ by $V(q,0)$ and the goal by $V(a,2)$ in one
guard. A root JSON value that is not a list cannot be accepted:
ordinary scalars and strings have no suitable no-argument
\texttt{pop}, and a dictionary's \texttt{pop} requires a key.
An empty list also rejects. For a nonempty list, the two displayed
invariants prove exact equivalence to the old whole-certificate
type check followed by its canonical-goal check. No certificate
subtree is omitted.

This both removes a separate recursive function and avoids a
separate raw-type traversal of the goal. The single diagnostic
states the two requirements together. Of the full checker's
152-byte reduction, 117 bytes are already obtained with two
separate input guards; the last 35 bytes include the shared
input flow and combined rejection message. These are all complete
program sizes, not an attribution of 152 bytes to a new axiom.
