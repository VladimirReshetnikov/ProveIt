3. Canonical syntax and proof type

Module: ConciseIPRA.PR
Namespace: LeanProofs.ConciseIPRA
Path: Logic/PrimitiveRecursiveArithmetic/ConciseIPRA/Lean/ConciseIPRA/PR.lean
Git blob: 3251631592070d9ed3687cc0bf7dbd5eb452e46f

PR : Nat -> Type has constructors zero, succ, proj, comp, prec. In prec the
recursion argument comes first. PTm n has n free natural-number variables.
PRAAx contains projections, composition, zero/successor recursion equations,
successor nonzero/injectivity, and only quantifier-free induction.
A closed theorem goal is:
  ([] : List (Fm PTm 0)) ⊢[PRAAx] sentence
A source-level Nat theorem alone is not such an object proof.

Exact generic induction interface:
  theorem PRA.qfInd (φ : Fm PTm (n + 1)) (hφ : φ.QF)
    (h0 : Γ ⊢[PRAAx] φ.subst (inst zero))
    (hS : φ :: Γ.map Fm.shift ⊢[PRAAx]
      φ.subst (repl (succ (var 0)))) :
    Γ ⊢[PRAAx] Fm.all φ

4. Eight relevant interface groups

Unless otherwise stated the namespace is LeanProofs.IPRA and the module paths

A. Primitive-recursive term compilation
Module IPRADerivations.Core.Definitions
Git blob 0011b086a26c69117fc31a1ef19780e3602197ae
PTm.toPR : PTm k -> PR k compiles a term to a function symbol.
recDef (base : PTm k) (step : PTm (k + 2)) : PR (k + 1)
implements primitive recursion, with rec_zero and rec_succ object derivations.
sumF and prodF build bounded sums/products. This is the appropriate compiler
target for a bounded witness search or a fixed-fuel descent.

B. Bounded search
Module IPRADerivations.Core.Search
Namespace LeanProofs.IPRA.Search
Git blob b6a5e30954ede9dd8751eec9ec6079edd61f2bb2
For a body f : PTm 2, mu f N x searches i<N for f(i,x)=0, returning N on
failure. The function is explicit PR:
  mu(0,x)=0
  mu(N+1,x)=mu(N,x)+eqb(mu(N,x),N)*sg(f(N,x)).
Exact useful endpoint:
  theorem search_found {N i x : PTm n}
    (hf : Γ ⊢[PRAAx] inst2 f i x ≐ zero)
    (hi : Γ ⊢[PRAAx] lt i N) :
    Γ ⊢[PRAAx] lt (mu f N x) N ⋏
      ((inst2 f (mu f N x) x ≐ zero) ⋏ le (mu f N x) i)
search_spec additionally proves total bound and failure/minimality information.
This supports bounded primality, residue-pair search, and final exhaustive
four-square search. Multiple parameters can be paired.

C. Explicit pigeonhole witnesses
Module IPRADerivations.Core.Pigeonhole
Namespace LeanProofs.IPRA.Pigeonhole
Git blob 541c50bcd7027ffbd8f1c84b738e4425c4f3bf67
For S : PTm 2, explicit terms phpI and phpJ are built using bounded counts
and bounded search. Exact endpoint:
  theorem pigeonhole {K x : PTm n}
    (hr : Γ ⊢[PRAAx] Permutation.rangeAll S K x) :
    Γ ⊢[PRAAx] lt (phpI S K x) (phpJ S K x) ⋏
      (le (phpJ S K x) K ⋏
        (inst2 S (phpI S K x) x ≐ inst2 S (phpJ S K x) x))
This expresses collision of K+1 values in K boxes. The premise is a quantified
range assertion; the internal induction formulas are explicitly quantifier
free. The module has more imports than its Core name suggests
(AnalyticNumberTheory.TotientCorollaries and its closure), so a compact standalone
packet should prove its simple counting lemma directly rather than copy an
incomplete import chain.

D. Least prime factor
Module IPRADerivations.AnalyticNumberTheory.Primes
Namespace LeanProofs.IPRA.AnalyticNumberTheory.Primes
Git blob 365d510cf9a77f2fab6e80888f87b14e984c6def
lpfBody := rem (var 1) (succ (succ (var 0))).
lpf z := succ (succ (Search.mu lpfBody z z)).
Exact endpoints:
  theorem lpf_dvd (z' : PTm n) :
    Γ ⊢[PRAAx] dvd (lpf (succ (succ z'))) (succ (succ z')) ⋏
      le (lpf (succ (succ z'))) (succ (succ z'))
  theorem lpf_prime (z' : PTm n) :
    Γ ⊢[PRAAx] prime (lpf (succ (succ z')))
Here prime p is defined as 2<=p and no e with 2<=e<p dividing p.
The absence of an unbounded factorization oracle is explicit: lpf is bounded
search, and the proof uses the factor z itself as an available search witness.

E. Euclid's lemma
Module IPRADerivations.Core.EuclidLemma
Namespace LeanProofs.IPRA
Git blob 2246b0ddb1ba479aedbf8bd077d9b5384100ab1e
Exact endpoint:
  theorem euclid_lemma_at {p a b : PTm n}
    (hp : Γ ⊢[PRAAx] prime p)
    (hab : Γ ⊢[PRAAx] dvd p (a * b)) :
    Γ ⊢[PRAAx] dvd p a ⋎ dvd p b
This is the zero-product fact needed for injectivity of squares on
0,...,(p-1)/2. The source develops the needed gcd/Bézout facts by explicit
arithmetic; it is not an appeal to semantic field structure.

F. Pairing and simultaneous recursion
Module IPRADerivations.Core.Pairing
Namespace LeanProofs.IPRA
Git blob b59607d2b32e684f2e0aa0babb6e2a856a7e33c3
The encoding is pairT a b = (a+b)^2+a, with PR square root projections.
Exact endpoints:
  fst_pair (a b : PTm n) :
    Γ ⊢[PRAAx] fstT (pairT a b) ≐ a
  snd_pair (a b : PTm n) :
    Γ ⊢[PRAAx] sndT (pairT a b) ≐ b
simF, sim₁ and sim₂ give simultaneous recursion on two fields, with
sim₁_zero/sim₂_zero/sim₁_succ/sim₂_succ object equations. Nested pairing
handles a multiplier and four signed coordinates. This pairing need only be
injective with projections on its image; it need not be a bijection onto Nat.

G. Signed integer terms and polynomial identities
Module IPRADerivations.Core.Integers
Namespace LeanProofs.IPRA, then ZT
Git blob 1b7a652f6f901296e029d739d5c1b1ccfc936832
ZT n is a pair {pos : PTm n, neg : PTm n} read as pos-neg.
No canonicality condition is imposed; this is NOT the odd/even sign code.
Operations:
  (a,b)+(c,d)=(a+c,b+d)
  -(a,b)=(b,a)
  (a,b)*(c,d)=(ac+bd,ad+bc)
Equality of (a,b) and (c,d) is the literal natural equation a+d=c+b.
The target ZT.eq is therefore quantifier free. toZ Γ evaluates into the
Grothendieck ring of the quotient of terms by derivable equality.
Exact reflection endpoint:
  theorem ZT.derive {u v : ZT n}
    (h : ZT.toZ Γ u = ZT.toZ Γ v) :
    Γ ⊢[PRAAx] ZT.eq u v
The tactic ipra_ring uses this method to turn polynomial identities into object
proofs. The small example DiophantineNumberTheory/Pell.lean proves:
  brahmagupta :
    ([] : List (Fm PTm 0)) ⊢[PRAAx] univ 10 brahmaguptaFormula
  := closeUniv 10 (by unfold brahmaguptaFormula; ipra_ring)
Euler's four-square identity is a natural analogous target.
A canonical sign/magnitude implementation requires an adapter: normalize
(a,b) to (a∸b,b∸a), prove its difference is unchanged, then encode the
nonzero component and sign. Conversely a sign code decodes to a signed pair.
The paper can use signed pairs in the object formalization while using Python
integers operationally, provided the PR coding bridge is specified.

H. Clocked descent
Module IPRADerivations.Core.ClockedDescent
Namespace LeanProofs.IPRA.ClockedDescent
Git blob 4b41c93d5788694b9989a83c49d1c8acdaf918f6
For P : Fm PTm 1 and D r : PTm 1, Pat P t=P[t] and
orb D k s is the primitive-recursive k-fold iterate of D.
Exact endpoint:
  theorem clocked (hP : P.QF)
    (hstep : ([] : List (Fm PTm 1)) ⊢[PRAAx]
      P ⟶ (Pat P D ⋏ lt (inst1 r D) r)) :
    ([] : List (Fm PTm 0)) ⊢[PRAAx] univ 1 (neg P)
This theorem forbids any state satisfying a QF predicate closed under strict
descent. The proof inducts on the QF invariant
P(s) -> (P(D^k(s)) and r(D^k(s))+k<=r(s)).
For witness production, a directly proved fuel invariant for an absorbing
terminal state is often clearer: the theorem above is refutational by design,
so it should not be described as already producing the final four-square
witness. A bounded final search with decidable failure can also use it.

6. Recommended integration boundary

Keep the delivered mathematical proof self-contained. For eventual integration,
add a dedicated module family under:
  IPRADerivations/DiophantineNumberTheory/FourSquares/
Use Core.Search, Core.Pairing, Core.EuclidLemma, Core.Integers and the relevant
primality modules. Suggested local modules:
  Identity, Seed, Halving, OddDescent, PrimeWitness, Assembly, Statement.
Each public lemma should return an explicit PRAAx derivation. The final object
sentence should existentially bind four Nat variables and state
n=a*a+b*b+c*c+d*d, universally closing n. A stronger witness endpoint uses
four unary PR symbols W_i and proves the universally closed equation.

The report should distinguish (i) the complete mathematical iPRA argument,
(ii) executable exact-arithmetic code, (iii) any checked standalone Lean
fragments, and (iv) the not-yet-assembled object derivation. Importing
Nat.sum_four_squares would only bypass the requested foundational proof.
