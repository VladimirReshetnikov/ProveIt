# Checked finite kernel and specifications

This package is self-contained apart from Lean 4.19.0 and its bundled `Std` library.
It has no Mathlib or ProveIt build dependency. Run:

```sh
./validate.sh
```

The build was run successfully with:

```
Lean (version 4.19.0, x86_64-unknown-linux-gnu, commit 6caaee842e94, Release)
```

`validation.log` records the successful build and the kernel's axiom reports for
representative endpoints. There are **30 proved named theorems**, plus three
closed arithmetic examples, across the two mathematical modules. No source file
contains a `sorry`, `admit`, or new `axiom` declaration. Some proofs depend on
Lean's `propext` and `Quot.sound`; none of the inspected endpoints depends on
`Classical.choice` or `sorryAx`. These Lean metatheorems are **not** claimed to
constitute object-language iPRA derivations.

## What is proved here

| Module | Checked endpoints and role |
|---|---|
| `IPRAProbability/Finite.lean` | `nsum_congr`, `nsum_mono`, `nsum_add`, `nsum_mul_left`, `nsum_mul_right`, `nsum_product`: finite sum algebra with explicit bounds. |
| Same | `mass_mono`, `mass_le_total`, `mass_complement`, `disjoint_additivity`, `intersection_comm`: event algebra. |
| Same | `union_bound`, `finite_union_bound`: finite subadditivity. |
| Same | `moment_add`, `moment_mono`: expectation numerator algebra. |
| Same | `markov_event`, `markov`, `chebyshev`: finite inequalities with all probability denominators cleared. |
| Same | `product_rectangle`, `product_weight_is_intersection`: rectangular factorization of product weights. |
| Same | `event_mass_stability`: absolute difference of event masses is at most the symmetric-difference mass. |
| `IPRAProbability/L1Finite.lean` | `isum_sub`, `abs_sum_bound`, `expectation_stability`, `distance_triangle`: signed finite sum and L1 estimates. |

All finite weights are natural numbers. If `W = nsum n w > 0`, the probability
of event `A` is the rational `mass n w A / W`. A common positive denominator
reduces a rational law to this presentation. The checked Chebyshev statement
is deliberately explicit:

```
t^2 * mass n w (fun i => decide (t ≤ absDiff (d * x i) a))
  ≤ centeredSecond n a d w x
```

For `d > 0` the event is `|x_i - a/d| ≥ t/d`; the bound is valid for any center.
One must supply the mean identity separately to identify the right side as the
variance numerator. This package does not silently treat an arbitrary center
as the mean.

## Compiling continuous-layer interfaces

`IPRAProbability/PRSyntax.lean` defines:

- an arity-indexed syntax `PR n` with zero, successor, projection, composition,
  and primitive recursion;
- a finite derivation relation `Eval`, with the recursion argument ordering
  written explicitly;
- `FixedPRFunction n`, which connects a function to one fixed syntax tree by
  evaluation-graph proofs;
- concrete identity and successor instances.

There is no universal primitive-recursive evaluator. The `Eval` relation is
not declared uniformly total in iPRA.

`IPRAProbability/Specifications.lean` defines:

- rational codes with a positive denominator;
- `qClose k a b`, the finite cross-multiplied inequality `|a-b| ≤ 2^(-k)`;
- rational sequences generated by three fixed PR programs;
- `RegularRealSpec`, with an explicit regularity obligation;
- PR cylinder-event families, prefix refinement, their finite symmetric-
  difference numerator, and `RegularEventSpec`.

These structures are **specification types**, not assertions that all their
instances exist. Their `regular` fields live in Lean's semantic logic. The
remaining embedding must replace such fields by actual iPRA proof objects for
the displayed finite tests, as explained in `ROADMAP.md`. Merely inhabiting
these semantic structures does not certify object-theory derivability.

The finite kernel here is a small independently reproducible specification and
sanity check; it does not replace or claim novelty over those existing
object-language results. The report's new work is the continuous probability
presentation and its explicit interfaces and error budgets.
