| [`Core/Evaluation`](Lean/IPRADerivations/Core/Evaluation.lean) | Numeral completeness for closed PR terms. With the Lean-side evaluator `PR.ev` (and `PTm.ev` for terms under a valuation), every symbol applied to numerals is provably the numeral of its value, `app f (num ∘ a) ≐ num (ev f a)` (`eval_app`, by structural recursion on `f`, unrolling `prec` by meta-level induction with `precZero`/`precSucc`); hence `t[num ∘ ρ] ≐ num (ev t ρ)` (`eval_term`), terms of equal value are provably equal (`eval_eq`), and ground terms in any context equal their values (`eval_closed`, `eval_ground`). Kernel evaluation is practical only for small arithmetic; division and gcd codes are too slow to evaluate this way. |

| [`Core/IntOrder`](Lean/IPRADerivations/Core/IntOrder.lean) | Order on integer terms, `u ≤ v` as `u⁺ + v⁻ ≤ v⁺ + u⁻`, handled through natural-number witnesses (`v = u + D`); `x² = abs(x⁺ − x⁻)²` is a natural number; `S² ≤ T² → S ≤ T` for natural numbers; and, without square roots, the dot-product bound `x₁x₂ + y₁y₂ ≤ ab` and the triangle inequality `(x₁ + x₂)² + (y₁ + y₂)² ≤ (a + b)²` from `x₁² + y₁² ≤ a²`, `x₂² + y₂² ≤ b²`, i.e. `abs(u + v) ≤ abs(u) + abs(v)` for Gaussian integers (the Lagrange identity gives `(ab)² ≥ (x₁x₂ + y₁y₂)²`). Used for the complex estimates of `FTA_iPRA`. |

| [`Core/PolynomialImplications`](Lean/IPRADerivations/Core/PolynomialImplications.lean) | Implications between integer polynomial equations, `h₁ = h₁' → … → c = c'`: expressions `ZExp k` in `k` integer variables (integer variable `i` is the difference of the natural variables `2i`, `2i + 1`), their value `ZExp.eval` in any commutative ring, the formula `ZExp.imp hyps c`, and `ZExp.derive_imp`: a certificate valid in every commutative ring gives `[] ⊢[PRAAx] univ (2k) (imp hyps c)`. The tactic `ipra_poly R ρ h` opens a certificate, to be closed by `ring` or `linear_combination`. `ZExp.Vec3`, `ZExp.Vec2` with dot, cross and determinants. No cancellation of nonzero factors (the ring of differences is not a domain) |

| [`Core/PolynomialInequalities`](Lean/IPRADerivations/Core/PolynomialInequalities.lean) | Implications `r₁ → … → r`, each `r` an equation `a = b` or an inequality `a ≤ b` between integer polynomials (`ZExp.Rel`), from a Positivstellensatz-style certificate: it must hold in every commutative ring with a cone (`Cone R`: contains `0`, `1`, sums, products and all squares), `a ≤ b` read as `b − a ∈ C`. `nn_sq`: every square of the ring of differences is the value of a term, so the values of terms form a cone; `ZExp.leF` is the quantifier-free formula of an integer inequality; `ZExp.derive_rel` gives `[] ⊢[PRAAx] univ (2k) (impR hyps c)`. Tactics `ipra_cone R C ρ h` and `cone_mem`; `Cone.of_eq` closes a certificate by `ring` or `linear_combination`. No case distinction on signs (the cone is not total) |
