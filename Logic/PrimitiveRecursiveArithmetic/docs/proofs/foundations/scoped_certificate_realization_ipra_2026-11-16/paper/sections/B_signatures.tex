\subsection{Suggested structure records}

The following records keep application code explicit while avoiding a large
unverified DSL.

\begin{lstlisting}[language=Lean]
structure ReflectedAtom (n : Nat) where
  formula : Fm PTm n
  bit : PTm n
  qf : formula.QF
  bit_bool : [] |- [PRAAx] bit == zero \/ bit == one
  of_true : bit == one :: [] |- [PRAAx] formula
  to_true : formula :: [] |- [PRAAx] bit == one

structure TraceData (n : Nat) where
  queryArity : Nat
  state : PTm (n + 2)       -- stage, trace, outer parameters
  bad : PTm (n + 2)
  invariant : Fm PTm (n + 2)
  invariantQF : invariant.QF
  state_zero : ...
  state_succ : ...
  bad_zero : ...
  bad_succ : ...

structure ObserverContract (n : Nat) where
  valid : Fm PTm (n + 1)
  observe : PTm (n + 1)
  independent : valid(c) /\ valid(d) |- [PRAAx]
    observe(c) == observe(d)
\end{lstlisting}

The exact arities should be implemented with the repository's \code{inst2},
\code{repl}, and vector notation rather than ad hoc numeral indexing.  The
records should store proof terms, not host propositions asserting that a proof
could be built.

\subsection{Substitution tests}

Every record constructor needs simp lemmas showing that its terms and formulas
commute with simultaneous substitution.  Tests should instantiate:
\begin{itemize}
\item a query variable by a nontrivial sum or product;
\item a trace code by a paired term;
\item a bound by a term containing the induction variable;
\item an observer under two nested existential scopes.
\end{itemize}
These tests catch the most common de Bruijn errors before application proofs
become large.
