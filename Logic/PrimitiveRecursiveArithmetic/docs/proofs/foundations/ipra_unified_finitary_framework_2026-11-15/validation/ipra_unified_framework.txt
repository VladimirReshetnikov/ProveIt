Abstract
The ProveIt repository contains a kernel-checked presentation of intuitionistic primitive
recursive arithmetic and a large collection of research packets that translate classical mathematics
into finite, quantitative forms. The packets repeatedly encounter the same boundaries: bounded
induction is confused with induction over completed infinite objects; ambient Lean theorems are
confused with object-language derivations; exact selectors are requested where only multivalued
approximate data are constructively justified; compactness is used without a finite net or modulus;
and deep finiteness theorems are used without a height bound or certificate producer.
This report develops a single framework addressing these issues. Its first layer is a proofproducing finite-trace compiler: fixed primitive-recursive algorithms, Boolean folds, bounded
searches, and certificate verifiers are translated into actual Prf PRAAx derivations by quantifierfree induction. Its second layer is a finitary relational presentation of mathematical objects.
Instead of forcing a globally chosen representative, a theorem may return a finite family of
compatible approximate answers. A backward viability dynamic program amalgamates finite
witnesses. A new shrinking-viability theorem gives a primitive-recursive coherent name when
a quantitative determinacy modulus is available; without such a modulus the correct output
remains relational.
The report gives complete human proofs of the core compiler, Booleanization, composition,
witness-amalgamation, shrinking-viability, guarded extensionality, finite-net transfer, and heightbound/list equivalence theorems. It then shows how these tools reorganize analysis, algebra,
geometry, topology, number theory, Diophantine geometry, and probability. Exact selection
principles known to imply LLPO/LPO, universal primitive-recursive evaluation, and search
cutoffs from mere cardinality bounds are explicitly retained as barriers rather than hidden
assumptions. The accompanying Lean files give dependency-ordered, source-accurate blueprints
against ProveIt’s ConciseIPRA API; the generic object-language proofs are not claimed kernelchecked in this archive.

1

Executive summary and exact scope

1.1

The problem exposed by the repository

The repository separates two very different achievements. The directory ConciseIPRA contains
a Lean formalization of ordinary first-order intuitionistic primitive recursive arithmetic and its
bi-interpretation with a small native scalar calculus. In particular, the repository provides the
object theory PRAAx, derivations Prf, quantifier-free induction PRA.qfInd, and the transfer theorem
pra_iff_native. By contrast, the theorem packets under docs/proofs are research reports: most
contain mathematical arguments, executable finite checks, and Lean plans, but none is a completed
derivation of its advertised theorem in Prf PRAAx.
The recurring difficulty is therefore not merely “how to code real numbers” or “how to avoid
excluded middle.” It is how to organize a proof so that all of the following are simultaneously
explicit:
(1) the finite information a construction reads;
(2) the primitive-recursive algorithm or certificate checker operating on that information;
(3) a quantifier-free invariant suitable for iPRA’s induction;
(4) the modulus, separation margin, height bound, finite net, or covering data that makes an
apparently infinitary step finite;
(5) the exact object-language formula and derivation to be transported to the native calculus;
(6) the boundary between a completed verifier and an unconstructed producer.
The existing foundation packets already contain many of these ingredients. The present report
unifies them and adds two missing interfaces: a syntactic proof-producing compiler and a relational
refinement layer for non-unique approximate witnesses.

1.2

The proposed architecture

The framework has five layers.
Layer 1: fixed numerical presentations. Every object family is represented by natural-number
parameters and fixed primitive-recursive evaluators. A represented object is not an arbitrary
program supplied at run time. If an external computation is not represented by a fixed evaluator,
its finite trace is supplied as a certificate and checked by a fixed primitive-recursive verifier. This
distinction avoids the false idea of a total universal primitive-recursive evaluator.
Layer 2: Boolean finite contracts. All bounded quantifiers, list checks, finite sums, maxima,
residual tests, and search predicates are compiled to primitive-recursive Boolean functions. Global
name hypotheses remain ordinary assumptions in the context; induction uses only equations saying
that a Boolean accumulator equals one. Precision is kept free during the finite proof and universally
quantified only afterward.

Layer 3: proof-producing traces. A bounded computation is presented by fixed functions
init, step, bound, inv, accept. Given object-language derivations of the base, local step, and final
soundness formulas, a generic theorem constructs an object-language derivation of the whole run.
The construction uses PRA.qfInd, the defining equations of primitive recursion, equality substitution,
and ordinary natural deduction. Thus the result is not merely an ambient theorem about a Lean
function.
Layer 4: finitary relational presentations. A challenge may admit several correct approximate
answers. The framework therefore permits a finite relation Good(p, k, a) rather than insisting on a
single canonical a. A compatibility relation connects answers at adjacent precision levels. Bounded
backward dynamic programming determines which answers can be extended to a finite horizon
and constructs a compatible finite chain whenever one exists. This is enough for all fixed-precision
theorems and avoids a hidden choice principle.
Layer 5: determinization only from quantitative data. When a downstream theorem
genuinely needs one coherent name, it must consume a quantitative determinacy hypothesis.
The shrinking-viability theorem assumes that all candidates viable to a stated horizon lie in a
small observational ball. The least viable candidate then defines a primitive-recursive name, and
the shrinking condition proves regularity. Root separation, strong convexity, isolating intervals,
contraction estimates, or projective gaps are instances of this hypothesis. Qualitative uniqueness
alone is not silently converted into a modulus.

1.3

Principal theorems

The main general results proved in this report are:
T1. Bounded Booleanization. Every fixed bounded formula over primitive-recursive terms
has a Boolean evaluator whose correctness is provable in iPRA.
T2. Finite-trace compiler. Embedded base, step, and final derivations yield an embedded
theorem about the complete bounded run.
T3. Contract composition. Proof-producing transducers compose, including adaptive finite
query trees.
T4. Finite witness amalgamation. A bounded backward viability computation constructs
a compatible chain through finite candidate levels whenever such a chain exists.
T5. Shrinking viability. Finite candidate relations plus a quantitative shrinking horizon
define a coherent primitive-recursive approximate name.
T6. Guarded extensionality. Operations with precision transformers descend to observational setoids, while partial operations are totalized and guarded by explicit domain or
apartness certificates.
T7. Finite-net transfer. A modulus and a finite net turn local rational checks into uniform
conclusions on a represented compact set.
T8. Height bound/list equivalence. For a decidable coded predicate, an explicit height
bound and a complete finite list are constructively interconvertible; a mere cardinality
bound is not enough.

What is and is not resolved

The framework resolves several obstacles at the level at which they are actually logical or architectural. It gives a reusable path from finite algorithms to Prf PRAAx, a correct treatment
of all-precision hypotheses, a generic finite-search library, and a non-choice-based interface for
non-unique approximations. It also gives standard positive replacements for exact sign, root, axis,
pivot, and branch selection.
It does not manufacture missing mathematics. In particular, it does not produce the unknown
or ineffective height bounds needed for general Faltings or Siegel statements, rational covering
representatives for arbitrary Mordell–Weil descent, or all constants in the strongest prime-distribution
claims. Instead, those results are factored into a uniform finite verifier and an explicit producer
obligation. This is progress: the verified downstream arithmetic can be completed once a producer
is supplied, and no search cutoff is smuggled in through a qualitative theorem.
The included Lean files are detailed blueprints against the current repository API. They
contain theorem statements, formula constructors, proof dependency order, and exact points where
PRA.qfInd, Prf.subst, Prf.trans, and pra_iff_native are used. Lean was not available in
the artifact environment, so this archive does not claim that those files have been elaborated or
kernel-checked.

2

Repository audit and diagnosis

2.1

Pinned source snapshot

This report was prepared against the ProveIt main-branch snapshot
b88e843c31b50dfe461bfbd0380166ca422cd3ab.
At that snapshot, Logic/PrimitiveRecursiveArithmetic/README.md distinguishes the checked
ConciseIPRA library from 58 delivered theorem packets under docs/proofs. The repository’s own
index warns that the packets were filed as delivered, were not rerun during intake, and do not
contain completed Prf PRAAx derivations of their advertised results. That warning is foundational
to the present audit: a polished PDF, a passing Python test, a type-correct specification, or an
ambient Lean theorem is not itself an iPRA proof.
The collection spans algebra, real and complex analysis, analytic number theory, combinatorics,
Diophantine number theory, geometry, probability, and topology. Seven foundation packets already
propose finite-contract, finite-observation, certificate, modulus, and evidence-indexed approaches.
Their strongest common conclusions are sound and are retained here. Their main common gap is
also retained: the last step from a generic semantic argument to a constructed derivation in the
actual ConciseIPRA object language is mostly planned rather than implemented.

2.2

Repeated proof-patterns

Across the packets, successful arguments have a remarkably stable shape.
1. A classical object is replaced by a numerical presentation: a finite coefficient list, a fixed
Cauchy evaluator, a rational law, a finite grid, a coded matrix, a bounded trace, or a supplied
certificate.
2. The desired statement is rewritten as a family of finite inequalities, coefficient identities,
residual bounds, parity checks, or finite search assertions, indexed by a requested precision or
bound.

3. Every non-total operation is guarded by a denominator, derivative, separation, pivot, or
compactness margin.
4. A primitive-recursive calculation is justified by a local invariant.
5. The final mathematical statement is recovered by universal introduction over the previously
free precision parameter or by an extensionality theorem for the chosen presentation.
The same pattern appears in the constructive prime number theorem, finite Euler products,
polynomial factorization, exact coordinate geometry, finite-grid topology, rational probability laws,
and bounded Diophantine enumeration. This is evidence that a common framework is appropriate.

2.3

Repeated failure-modes

The difficult packets also repeat a small number of failure-modes.
Ambient proof versus embedded derivation. Many Lean files prove correct facts about Nat,
Rat, arrays, or finite lists. These are useful semantic prototypes, but they do not construct a term of
type Γ ⊢ [PRAAx]φ. The bridge theorem pra_iff_native transports an already constructed iPRA
derivation; it does not synthesize that derivation from an ambient theorem.
Induction over an infinitary interpretation. A represented-real contract may be written as
an assertion quantified over all precisions. Placing that assertion inside the induction predicate
makes the predicate non-quantifier-free and creates the impression that iPRA is too weak. The
correct proof fixes the requested precision, instantiates only the finitely many name facts read by
the computation, and inducts on a Boolean accumulator.
Exact choice at unstable points. Root ordering at collisions, a unit rotation axis at the identity,
exact sign of an arbitrary real, a unique minimizer without a modulus, or a Puiseux branch from
arbitrary Cauchy coefficients can be discontinuous. Several packets correctly identify LLPO/LPO
or computability obstructions. The right repair is a relational or approximate output, or an exact
output under an explicit positive gap.
Compactness without data. Statements such as “take a finite subcover,” “choose a convergent
subsequence,” or “minimize on a compact set” have no direct computational content. In the
successful packets they are replaced by a finite net, a modulus of uniform continuity, a finite cover
certificate, or a nested family of isolating regions.
Finiteness without a cutoff. A proof that a set has at most M elements does not identify
where those elements occur. General Faltings and Siegel packets isolate precisely this gap: bounded
enumeration is straightforward once a height bound is supplied, but cardinality alone does not give a
stopping rule. The same issue appears in rational covering representatives for Mordell–Weil descent.
Arbitrary program codes. A theorem schema may be uniform in the numerical parameters of
one fixed primitive-recursive evaluator. It cannot quantify over arbitrary program codes and then
invoke a total primitive-recursive universal evaluator. A fixed evaluator or a finite trace verifier is
required.

Logical base and the meaning of an embedded proof

3.1

The repository’s ordinary presentation of iPRA

The checked backend uses the following objects.
• PR k is the inductively generated type of primitive-recursive function symbols of arity k, with
zero, successor, projections, composition, and primitive recursion.
• PTm n is the first-order term language with n free variables, formed by variables and applications
of PR symbols.
• PRAAx contains the defining equations for every primitive-recursive symbol, successor separation
and injectivity, and induction for quantifier-free formulas.
• Prf PRAAx Γ φ, written Γ ⊢ [PRAAx]φ, is intuitionistic natural deduction with equality, substitution, and open axioms.
The crucial repository theorem is
(Γ ⊢ [PRAAx]φ)

⇐⇒

NPrf(Γnat , φnat ),

implemented as pra_iff_native. It is a faithful transport theorem, not a reflection principle from
arbitrary Lean propositions.

3.2

Schemas versus single first-order theorems

A fixed primitive-recursive evaluator a : Nr+1 → N can be represented by one fixed PR symbol. A
theorem may then be uniform in its ordinary numerical parameter p and precision k:
∀p ∀k Φa (p, k).
This is a single first-order theorem for that fixed symbol. A Lean theorem polymorphic in a
meta-level value a : PR (r+1) is instead a schema generator: for each fixed symbol it produces a
first-order formula and proof. The distinction is benign and should be explicit.
What is not legitimate is to quantify over arbitrary program codes e and pretend that there is a
total primitive-recursive function U (e, x) evaluating every primitive-recursive program. The diagonal
argument in section 15 rules this out. A theorem about an external algorithm must therefore use
one of two interfaces:
1. its evaluator is fixed in the theorem’s language; or
2. a finite computation trace is supplied and checked by a fixed verifier.

3.3

Definitional extensions are harmless when fixed

The usual mathematical presentation of iPRA has a function symbol for every primitive-recursive
function. The repository instead represents these symbols by syntax trees in PR, with defining
equations in PRAAx. This means that introducing a named helper such as pairing, list lookup, integer
addition, rational comparison, bounded maximum, or a particular trace runner is not an additional
axiom. One defines a fixed PR term and uses its generated defining equations.

3.4

Quantifier-free induction with quantified context

A frequent misunderstanding is that quantifier-free induction forbids the use of represented-object
hypotheses containing quantifiers. It does not. The restriction applies to the induction formula, not
to the surrounding context. For example, suppose the context contains a regularity hypothesis
H(p) :≡ ∀k ∀ℓ dist(a(p, k), a(p, ℓ)) ≤ 2−k + 2−ℓ .
Inside the successor step one may instantiate H(p) at primitive-recursive terms computed from the
current finite state. The induction predicate itself can remain the equation
accumulator(i, p) = 1.
Thus a global quantified contract may be consumed stage by stage while the formula on which
induction acts is quantifier free.
This observation is the logical basis of the finite query-table discipline. A computation declares
or records every sample it reads. The global contract is instantiated only at those samples, and the
resulting finite facts are folded into a Boolean table. The induction invariant says that the prefix of
the table already constructed is valid.

4.1

write

4.2

For a Boolean predicate b(i, x̄), define
Allb (0, x̄) = 1,
Allb (n + 1, x̄) = Allb (n, x̄) ∧ b(n, x̄),
Anyb (0, x̄) = 0,
Anyb (n + 1, x̄) = Anyb (n, x̄) ∨ b(n, x̄).
Both are primitive recursive. Define a first-witness search Searchb (n, x̄) that returns the least i < n
with b(i, x̄) = 1, and returns n when no such witness exists. It can be computed by a primitive
recursion carrying the current candidate and a found bit.
Theorem 4.1 (Correctness of Boolean folds). For every fixed Boolean predicate b, iPRA proves:
Allb (n, x̄) = 1 ↔ ∀i (i < n → b(i, x̄) = 1),
Anyb (n, x̄) = 1 ↔ ∃i (i < n ∧ b(i, x̄) = 1),

Proof. We spell out the proof because it illustrates the permitted use of quantifier-free induction.
For the forward direction of the universal fold, keep i free and induct on n with the quantifier-free
formula
i < n ∧ Allb (n, x̄) = 1 → b(i, x̄) = 1.
The relation i < n and the Boolean equation are atomic equations between primitive-recursive terms.
At zero the antecedent is false. At a successor, if i < n + 1, numerical case analysis gives either
i < n, where the induction hypothesis applies to the prefix fold, or i = n, where the last Boolean
factor gives b(n, x̄) = 1. Universal introduction over i is performed after the induction.
For the reverse direction, place H := ∀i(i < n → b(i, x̄) = 1) in the context and induct on the
fold length m ≤ n with the quantifier-free formula Allb (m, x̄) = 1. The step specializes H to m, uses
the recursion equation of Allb , and the Boolean truth table for conjunction. Equivalently, one may
prove the open theorem with n as induction variable, keeping ∀i(i < n → · · · ) outside the induction
predicate and using its successor decomposition in the context.
The existential fold is dual. For the forward direction, induction on n examines whether the last
disjunct is true; the result is either the last index or a witness obtained from the prefix induction
hypothesis. For the reverse direction, a supplied witness i < n is propagated through the fold by
quantifier-free induction on the difference between i + 1 and n.
For first-witness search, the invariant states that either the found bit is zero and every earlier
predicate value is zero, or the found bit is one, the stored index is below the current length, its
predicate value is one, and all smaller indices fail. Every clause is a Boolean equation or bounded
comparison, hence quantifier free. At termination, an existential premise excludes the no-witness
branch. The minimality clause is read directly from the invariant.

Bounded minimization

5.6

The exact compiler boundary

The trace compiler is a disciplined boundary between semantic mathematics and formal arithmetic.
• Outside the boundary one proves local rational inequalities, coefficient identities, error budgets,
and invariant preservation.
• At the boundary each local theorem is expressed as a formula of Fm PTm and supplied as a
Prf PRAAx derivation.
• Inside the boundary generic code combines those derivations into the complete bounded-run
theorem.
• Only after that theorem exists is pra_iff_native applied.
This organization makes missing work visible. A semantic Lean theorem can be used as a guide
for constructing a local derivation, but it cannot be inserted as an unexamined premise. Conversely,
once the local obligations are embedded, the generic control-flow proof should not be repeated
theorem by theorem.

6.1

Why single-valued names are sometimes the wrong interface

Many constructive failures arise because a theorem is asked to return one exactly selected representative when the mathematics only determines a finite family of approximations.
• A polynomial with colliding roots has an unambiguous root multiset but no stable ordering of
individual roots.
• A real rotation near the identity has stable quaternion or approximate axis data, but no
continuous choice of a unit axis at the identity.
• A minimization problem may have several nearly minimizing grid points, even though the
minimum value is stable.
• Local analytic charts can overlap, while an exact chart selector at a boundary is discontinuous.
• A finite proof may establish a compatible witness at every requested depth without supplying
one globally chosen infinite branch.
Forcing a function in these situations either adds a separation hypothesis, imports a choice
principle, or makes the theorem false as a uniform computational statement. The framework
therefore treats relations as a first-class output type.

Definition of a finitary relational presentation

Definition 6.1 (Finitary relational presentation). A finitary relational presentation X consists of
fixed primitive-recursive data:
1. a parameter-domain Boolean DomX (p);
2. a challenge-domain Boolean ChalX (p, q);
3. a finite answer bound BX (p, q);
4. an answer verifier GoodX (p, q, a) ∈ {0, 1}, with the convention that valid answers satisfy
a < BX (p, q);
5. a refinement or compatibility verifier CompatX (p, q, a, q ′ , a′ ) ∈ {0, 1}; and
6. optional observation and error decoders used to interpret an answer.
All data are fixed symbols, not arbitrary run-time programs.
The challenge q need not be a scalar precision. It may encode a region, derivative order, finite
test function, matrix entry, truncation length, or a bundle of such requests. This makes the interface
broad enough for analysis, probability, topology, and algebra without pretending that every object
is merely a Cauchy sequence.
A parameter p is finitely inhabited to depth h when every challenge in the finite schedule up to h
has an acceptable answer and the answers can be connected by the required compatibility edges.
The exact schedule is theorem-specific and primitive recursive.

Relational transducers

Definition 6.2 (Relational transducer). A finitary relational transducer F : X ⇝ Y consists of:
1. a primitive-recursive finite query strategy. Given an input parameter p, output challenge r,
and current finite state, it either asks for an X-answer to a challenge q or halts;
2. a primitive-recursive output-answer bound and candidate generator;
3. a Boolean trace invariant and acceptance predicate; and
4. an embedded soundness derivation saying that any finite family of valid, mutually compatible
input answers accepted by the trace yields a valid Y -answer.

6.6

Three levels of output strength

A theorem should state the weakest output that supports its applications.
Relational output.
For every requested finite challenge, return a nonempty finite set of correct
answers plus compatibility information. This needs no global selector.
Approximate functional output.
Return one answer at each precision, with a regularity theorem. This requires
a shrinking or determinacy modulus as in section 8.
Exact selected output.
Return a distinguished exact representative, such as an ordered root, exact
sign, normalized eigenvector, or branch. This requires a canonical algebraic
normalization or a positive separation promise. Without it the request may be
obstructed.
The relational form is not a consolation prize. Many classical theorems are naturally invariant
under permutations, signs, projective scaling, or chart choices. Stating the theorem at that invariant
level often removes a constructive obstruction while preserving all mathematically meaningful
content.

6.7

Challenge trees rather than fixed tables

An adaptive algorithm does not know its full input demand in advance. Its finite demand is a tree:
a rational comparison at one stage selects the next query. A certificate can include one realized

branch, while a uniform soundness theorem verifies every branch. The trace state contains the

If the theorem must be robust under approximate comparisons, branch guards must overlap. For

6.8

Extensional interpretation

A relational presentation represents mathematical content through the family of accepted finite
observations, not through the raw parameter code. Two parameters are observationally equivalent
when every accepted answer for one can be matched, at the requested precision, by an accepted
answer for the other and conversely. This is a finite Hausdorff-style relation at each precision.
Equality of represented objects is the universal closure over precisions.
Operations should therefore be proved extensional: matched input observations at the precision
requested by a modulus produce matched output observations. Section 9 gives the generic proof
pattern.

7.7

Object-language implementation

There are two efficient implementations, both suitable for the trace compiler.
Path-code checker. Bound a path code, search over all codes, and verify range, goodness,

Dynamic-programming table. Build the forward reachable table and backward viable table,

the local recurrence; the generic trace theorem then supplies the global soundness derivation.

The remaining coherence problem

one infinite coherent branch. Nor should it: an infinite finitely branching tree can have paths of

computational strength, depending on how the tree is presented.

8.7

What happens without shrinking

If (SV3) is unavailable, the framework still yields strong conclusions. For every requested finite
collection of precisions, finite amalgamation produces a compatible family. Downstream theorems
that are stable under all such families can consume the relation directly. Examples include:
• existence of a root cluster meeting a residual bound;
• the minimum value of a function without a selected minimizer;
• approximate rotation data without a convergent axis;
• a finite cover or parity witness in topology;
• all representatives passing a finite test suite.
The absence of a coherent selector is then a property of the statement, not a failure of the
encoding. This distinction prevents hidden uses of choice, LLPO, or discontinuous branch selection.

9.7

Normalization is a theorem, not an identity assumption

Codes for rationals, polynomials, projective points, matrices, and finite sets often admit multiple
representations. The framework uses one of two safe patterns:
1. choose a primitive-recursive canonical normalization and prove that it preserves observations;
or
2. retain non-canonical codes and prove every operation respects the observational relation.
The first pattern is convenient for signed integers and positive-denominator rationals. The
second is often better for projective or clustered data, where canonical choice would require unstable
comparisons. In neither pattern is code equality confused with mathematical equality.

Finite-net transfer

Let K(p) be a represented compact domain only in the following concrete sense: for each rational
radius ρ, a primitive-recursive function returns a finite list N (p, ρ), and a certificate proves
∀x ∈ K(p) ∃y ∈ N (p, ρ) d(x, y) ≤ ρ.
The quantifiers over represented points are interpreted through the finite presentation used by the
theorem; in a fully embedded statement, coverage is a certificate-relative first-order formula.
Let f have a modulus ω: if d(x, y) ≤ ρ, then |f (x) − f (y)| ≤ ω(ρ).
Theorem 10.2 (Finite-net transfer). If N is a ρ-net, f (y) ≥ L for every y ∈ N , and ω(ρ) ≤ η,
then f (x) ≥ L − η throughout the represented domain. Likewise, a grid point whose value is within
η of the finite grid minimum is within 2η of the global infimum.
Proof. For an arbitrary represented x, the finite coverage certificate and bounded search give a net
point y with d(x, y) ≤ ρ. The modulus gives f (x) ≥ f (y) − η ≥ L − η. For minimization, compare
the selected grid point to a net point near an arbitrary x, then take the finite minimum using
bounded search. No abstract compactness or completed infimum object is used.
The minimum value needs no unique minimizer. A coherent minimizer name requires a quantitative uniqueness or shrinking-viability hypothesis.

10.5

Riemann sums and integration

An integral theorem is represented by a quadrature algorithm plus two finite contracts:
1. a modulus controlling the change of the integrand within each cell; and
2. a tail or truncation estimate if the interval or series is unbounded.
For a bounded interval and a mesh of width ρ, upper and lower rational sums differ by at most
interval length times ω(ρ). The trace computes the finite sum, while the invariant accumulates
rounding and mesh errors. Additivity, linearity, and change of variables for explicitly monotone
rational maps reduce to finite sum rearrangements and modulus bounds.
The fundamental theorem of calculus should therefore be split into finite statements. For the
derivative-to-integral direction, telescope finite increments and control each local remainder. For
the integral-to-derivative direction, compare a difference quotient to cell averages using a continuity
modulus. A theorem packet that states merely that a derivative is continuous has not yet supplied
the numerical input required by the iPRA proof.

10.7

Approximate extrema

For a finite rational grid, bounded search returns a least residual or least value point. Let mk denote
the finite minimum. The finite-net theorem turns mk into a name for the infimum value. To obtain
a point:
• retain the relation of all ηk -near-minimizers; or
• provide a quantitative uniqueness estimate, such as strong convexity, and apply shrinking
viability.
This resolves a common constructive mismatch. The operation “take the infimum value” is often
stable, while “take the unique point where it is attained” needs more data.

10.8

Finite probability laws

A finite rational law is a list of outcomes and nonnegative rational weights summing to one.
Expectation, variance, characteristic functions at rational arguments, convolution, and distribution
values at rational thresholds are finite sums. Approximation of an unbounded or continuous law
requires explicit tail and quantization moduli. Approximation of a discontinuous CDF at a threshold
additionally requires an anti-concentration or boundary-mass bound.
Thus a constructive central-limit statement has a transparent shape: finite rational laws, a finite
convolution or characteristic-function trace, a quantitative error estimate, and a rational threshold
protected by a boundary budget. Higher-type measures are unnecessary unless they are given
through a fixed finite-observation evaluator with the corresponding moduli.

Domain libraries built on the common kernel

The framework is useful only if domain proofs share substantial infrastructure. This section gives
the intended library boundaries and the preferred statement forms for the main areas represented in
the repository.

11.1

Exact finite algebra

Polynomial and matrix identities should be proved first over coded coefficient rings by finite sums
and products. A polynomial is a bounded coefficient list; addition, multiplication, derivative,
composition, and evaluation are primitive-recursive list operations. Equality is coefficientwise
equality, checked by a finite fold.
The generic matrix layer contains dimensions, entry lookup, matrix products, permutation or
fraction-free determinants, minors, and polynomial matrices. Cayley–Hamilton is best stated as
a uniform finite identity for the generic matrix, then specialized by coefficient substitution. This
avoids analytic or field assumptions. Trace identities, adjugate formulas, and finite linear recurrences
can use the same coefficientwise kernel.
Factorizations and radical expressions are certificate-relative unless a producer has been formalized. A factorization certificate consists of a finite factor list, degree and leading-coefficient
data, and a coefficientwise product identity. Its verifier is small and uniform. Irreducibility and
Galois-theoretic impossibility results need finite permutation/group certificates plus a fully specified
arithmetization; a semantic field-theory proof in ambient Lean is not yet an iPRA derivation.

11.2

Roots, branches, and algebraic functions

For approximate roots, the stable primary output is one of:
1. a finite multiset of isolating boxes with multiplicities;
2. a root cluster whose residual and diameter meet a requested budget;
3. a relational family of approximate roots; or
4. an individual root name under a separation or simple-root certificate.
Ordering roots is deferred until a positive separation witness is available. Local implicit or
inverse functions consume a derivative gap, a rational box, and a contraction or majorant certificate.
Puiseux expansions from exact algebraic coefficient codes may use finite Newton-polygon and
splitting certificates. The stronger demand for exact Puiseux coefficients from arbitrary Cauchy
coefficient names is not a library goal; the repository contains a computability obstruction even for
a fixed evaluator family.

11.3

Number theory and combinatorics

Divisibility, primality below a bound, valuations, finite divisor sums, Möbius inversion, totients,
von Mangoldt weights, binomial coefficients, Bell recurrences, and congruences are all exact finite
arithmetic. Their preferred proofs use Boolean divisibility predicates and double-counting bijections
between bounded coded sets.

Asymptotic statements are expressed by explicit inequalities with a free numerical parameter
and a displayed threshold function. A proof of f (n) ∼ g(n) becomes

Analytic number theory should separate a uniform finite verifier from the producer of difficult
constants. Zero-free regions, exceptional-zero data, contour bounds, and explicit estimates can be
represented by rational tables whose checker verifies all local inequalities. This does not solve the
problem of producing effective constants in results where current proofs are ineffective; it makes the
residual obligation exact.

11.4

Diophantine geometry

A rational point is encoded by a normalized integer tuple with a height. Polynomial satisfaction is
decidable after clearing denominators. Once a height bound H is supplied, complete enumeration is
a bounded search. Conversely, from a complete finite list one obtains a height bound by taking a
finite maximum.
Theorem 11.1 (Height bound–complete list equivalence). For every fixed primitive-recursive point
predicate P (p, x) and height function h(x), iPRA proves:
1. a bound H satisfying P (p, x) → h(x) ≤ H yields a complete finite list of all points by bounded
enumeration; and
2. a complete finite list yields the height bound equal to the maximum height of its members.
Proof. For the first direction, enumerate every normalized code of height at most H, retain exactly
those passing the Boolean predicate, and prove completeness by specializing the bound hypothesis.
For the second, compute the finite maximum. If P (p, x), list completeness gives an index at
which x occurs, so its height is below the maximum. Both directions are finite folds and bounded
searches.
This theorem sharpens the boundary in the Faltings, Siegel, and Mordell–Weil packets. A verifier
and enumerator can be completed independently of the deep theorem that produces the height
bound, finite cover, or rational covering representatives. A cardinality bound alone supplies neither.
Descent arguments should be packaged as a well-founded numerical measure, a primitive-recursive
descent step, and a proof that every nonterminal state strictly decreases. Primitive-recursive descent
then yields the terminal certificate. Covering descents are relational when several next coverings are
possible; backward viability handles finite compatibility constraints.

11.5

Geometry

Coordinate geometry is naturally finite. Points, lines, circles, conics, and projective incidences are
coded by rational or represented coordinates. Determinantal incidence identities, Ceva–Menelaustype products, power of a point, and many triangle formulas reduce to polynomial identities plus
nondegeneracy guards.
Angle-based theorems require more care. Prefer dot products, determinants, complex phases,
quaternions, or sine/cosine pairs to a globally chosen angle. Normalization needs a positive norm

gap. For rotations, exact quaternion data can remain meaningful when the vector part vanishes,
whereas a unit axis at the identity is discontinuous. Approximate axes may be returned relationally;
exact axes require separation from the identity or a supplied nonzero vector.
Spherical and trigonometric identities should be split into exact polynomial identities in sine/cosine variables and analytic existence/branch statements. The first belong to the algebraic checker.
The second consume quadrant, nonvanishing, or interval certificates. This avoids importing classical
inverse-function conventions into the algebraic part.

11.6

Topology

Abstract compactness is replaced by finite combinatorics. A quantitative Jordan or invariance-ofdimension theorem should specify:
• a rational grid scale obtained from a continuity and separation modulus;
• a finite cell or cubical complex;
• a Boolean labeling rule;
• a local parity or Sperner invariant; and
• a finite path, chain, or parity certificate producing the conclusion.
The global proof is quantifier-free induction over cells or a finite trace. Refinement from one grid
to the next is a relational presentation; a coherent geometric point is extracted only when nested
cells shrink quantitatively.

11.7

Analysis and special functions

Calculus, Gamma and zeta identities, residues, and asymptotics should be organized around finite
sums, rational contours or meshes, and explicit remainders. A complex contour is a finite polygonal
path or a fixed evaluator with a modulus. Cauchy and residue statements become finite telescoping
identities plus bounds on local approximation errors. Winding and zero counts are exact only under
a boundary-apartness certificate.
Special functions are best given by a fixed family of finite approximants and one or more
interchangeable certificates: series tails, product tails, integral quadrature errors, or functionalequation residuals. Identities are proved at finite precision through whichever representation has the
easiest error ledger. Extensionality then shows that the alternatives describe the same represented
value.

11.8

Probability

The base probability library consists of finite rational laws, products, convolutions, moments, and
rational test functions. Limit theorems are quantitative approximation theorems. Tail truncation,
lattice spacing, variance lower bounds, third-moment bounds, and anti-concentration are explicit
inputs or derived certificates. Multivariate laws use finite rational vectors and finite nets of test
directions. Martingale statements use bounded finite filtrations and transition tables.
This formulation captures the effective finite content of central-limit arguments while avoiding
an unsupported higher-type measure object. A more general represented measure can be added
later as an FRP whose challenges are finite rational test functions and whose answers are certified
approximate integrals.

A uniform package boundary

Every domain theorem should be split into four files or namespaces:
1. Data: codes, guards, evaluators, candidate bounds, and challenges;
2. Finite kernel: Boolean folds, arithmetic identities, local invariants, and certificate checking;
3. Producer: optional algorithm constructing the certificate or viable relation; and
4. Export: the exact Prf PRAAx theorem and its transport by pra_iff_native.
A packet may honestly complete the finite kernel while leaving the producer open. This is
materially stronger and more reusable than an all-or-nothing outline, provided the status is stated
explicitly.

12.1

Status

Three kinds of residual work

After applying the framework, every remaining gap should fall into one of three categories.
Finite-kernel engineering. The required theorem is elementary and finitary, but the objectlanguage library for tuples, rationals, finite folds, or error arithmetic has not yet been implemented.
This is substantial formalization work, but its statement and induction invariant are known.
Quantitative mathematical estimate. The representation is adequate, but a theorem-specific
modulus, separation bound, zero-free estimate, contraction constant, or combinatorial invariant is
missing. This is the genuine mathematics of the application.
Producer problem. A small checker is complete, but no uniform primitive-recursive procedure
is known for producing the accepted certificate. Height bounds, rational covering representatives,
effective analytic constants, and singular branch data often live here. The packet should expose this
producer as a separate theorem rather than weakening the verifier’s status.
This classification is itself useful: it prevents a missing library lemma from being described as a
foundational obstruction, and prevents a deep ineffective theorem from being described as routine
encoding.

Bounded rational points

Let Fp (X, Y ) ∈ Z[X, Y ] be a fixed primitive-recursive coefficient family. A normalized rational pair
of height at most H is coded by integers (a, b, c) with c > 0, bounded absolute values, and the
selected gcd/sign normalization. The equation Fp (a/c, b/c) = 0 becomes an exact integer equation
after multiplying by a fixed power of c.
The finite enumerator loops over the bounded box, retains normalized solutions, and removes
duplicates by code equality. Its invariant says that the current list contains exactly the solutions
among the first j candidate codes. The trace compiler proves soundness and completeness below H.
A separate height certificate

turns this bounded list into the complete list. Without the certificate, the same executable search is
only a list below a cutoff. This is the precise status distinction needed in the Faltings and Siegel
settings.

A finite-net minimum

Let f : [0, 1]d → R have a supplied rational modulus. At requested precision k, choose a rational
grid fine enough that variation inside a cell is at most 2−k−2 . Evaluate f at the grid points to error
2−k−2 , and return the least point with minimum approximate value. Finite search proves that its
displayed value is within 2−k of the infimum.
If there may be several minimizers, the point itself remains a relation of near-minimizers. If a
strong-convexity certificate gives

shrink, so the least full-viable grid point is a coherent name for x∗ . The value theorem and point
theorem are thereby cleanly separated.

Retained barriers and impossibility results

A general framework is credible only if it states what encoding cannot repair. The following
barriers explain why the positive interfaces in earlier sections are deliberately guarded, relational, or
certificate-relative.

No total universal primitive-recursive evaluator

Theorem 15.1 (Diagonal barrier). There is no binary primitive-recursive function U (e, x) such
that every unary primitive-recursive function f has an index e with f (x) = U (e, x) for all x.
Proof. If such U existed, then

g(x) = U (x, x) + 1

would be primitive recursive. By universality, g(x) = U (e, x) for some e. Substitution of x = e gives
U (e, e) + 1 = g(e) = U (e, e),
a contradiction.
This does not prevent a syntax of primitive-recursive programs with a partial, clocked, or
complexity-bounded interpreter. It prevents one fixed total primitive-recursive evaluator from
uniformly evaluating every such program. Therefore the framework uses fixed evaluator schemas or
finite traces whose individual steps are checked.

15.2

A cardinality bound is not a search cutoff

Let T (e, t) be the primitive-recursive predicate saying that machine e halts for the first time at
exactly stage t. For each e, at most one t satisfies T (e, t). Thus the solution set has the uniform
cardinality bound one.
Theorem 15.2 (No uniform cutoff from cardinality). There is no total computable function H(e)
such that
T (e, t) → t ≤ H(e)
for every e, t.
Proof. Given such H, simulate machine e for H(e) stages. If it halts, answer yes. If it has not
halted, it can never halt later, because its first halting stage would exceed the promised bound.
This decides the halting problem.
Consequently, a theorem proving that a curve has at most N rational points does not give
a height bound, an enumeration stopping rule, or the points themselves. Additional arithmetic
structure may produce a height bound, but cardinality alone cannot.

Qualitative uniqueness is not a quantitative selector

A statement that exactly one mathematical object satisfies a predicate does not automatically
give a primitive-recursive rate at which finite candidate clouds shrink. The unique object may be
encoded by a computation whose convergence has no computable modulus. To construct a name,
the framework requires an isolation radius, strong-convexity constant, residual-to-distance bound,
contraction factor, or equivalent quantitative determinacy data.
This is why the report distinguishes:
1. uniqueness as a logical proposition;
2. finite near-uniqueness at a requested scale; and
3. a primitive-recursive modulus witnessing how the scale improves.
Only the third supports a uniform coherent-name constructor.

15.7

A semantic Lean proof does not automatically reflect into iPRA

Lean can prove an ambient theorem about a recursive function using induction, quotients, classical
choice, algebraic hierarchies, or library facts. There is no general reflection principle turning an
arbitrary such theorem into a term of Prf PRAAx. A soundness theorem goes in the other direction:
an object-language proof has a semantic interpretation.
The positive solution is deliberately smaller. For the restricted DSL of Boolean folds, bounded
traces, and certified arithmetic transducers, define a syntax-directed compiler that constructs the
object-language proof from local object-language obligations. This is feasible because every proof
step and induction invariant is exposed. It is not a universal reflection theorem for Lean.

15.8

Boundary summary

The framework does not claim:
• a universal total primitive-recursive evaluator;
• exact discontinuous selectors from arbitrary Cauchy names;
• height cutoffs from cardinality bounds;
• a Cauchy rate from metastability alone;
• quantitative isolation from qualitative uniqueness alone; or
• automatic reflection of arbitrary semantic Lean proofs.
Each refused claim has a positive replacement: fixed evaluators or trace certificates, relational
output or positive gaps, explicit height producers, finite-window theorems or tail moduli, shrinking
certificates, and a restricted proof-producing compiler.

The framework turns a diffuse collection of difficulties into a relatively small implementation and

Kernel and compiler questions

A minimal proof-producing DSL. What is the smallest finite-program language whose certified
compiler covers most theorem packets? The language should support primitive recursion, bounded
folds, adaptive queries, finite search, guarded branching, and phase composition, while producing
compact Prf PRAAx terms. It would be valuable to compare direct proofs in ordinary iPRA with
proofs compiled first to the native scalar or clause calculi.
Proof-size control. Naïvely expanding Boolean folds and rational arithmetic may create enormous
proof terms. Which derived rules, sharing mechanisms, or certificate languages minimize proof
size without enlarging the trusted kernel? Can a small native certificate be checked by a proved
object-language verifier and then reflected to the ordinary presentation?
Verified code generation. Can the Python-style exact checkers already present in many packets
be replaced by a restricted source language with a verified compiler to PR syntax, trace invariants,
and proof obligations? The trusted output should remain a Lean derivation, not the external
compiler’s assertion of correctness.

16.2

Relational mathematics questions

General finite diagrams. The report treats layered paths. Many applications naturally form
finite DAGs, trees, or hypergraphs of compatibility constraints. Develop a generic bounded CSP
library and identify the weakest local consistency conditions that permit efficient proof-producing
amalgamation.
Quantitative determinacy extractors. Build reusable theorems that derive viable-cloud
diameter bounds from: strong convexity, inverse-function estimates, algebraic separation, Rouché
bounds, contraction mappings, monotone brackets, and projective spectral gaps. This would make
shrinking viability a practical bridge rather than a manual argument in each packet.
Multiset and cluster representations. Design one canonical finite representation for approximate multisets with multiplicity, Hausdorff matching, and cluster refinement. Prove that polynomial
root sets, eigenvalue sets, and finite zero sets are extensional in this representation, including collision
points.

16.3

Analysis library questions

A common error-budget algebra. Formalize rational error expressions, monotone precision
transformers, and automatic composition. Can a small verified normalizer discharge the routine
linear and polynomial inequalities generated by finite sums, products, quadrature, and series tails?
Contour and zero-count certificates. Develop a finite polygonal-contour library with boundary
apartness, winding, argument increments, Cauchy estimates, and Rouché certificates. This would
connect the zeta, residue, FTA, and analytic-branch packets through one kernel.
Represented measures by finite tests. Extend FRPs so that challenges are bounded rational
test functions and answers are approximate integrals. Determine which probability results need
only finite laws plus approximation moduli and which benefit from the more general interface.

Number-theoretic and geometric producer questions

Height-bound producers. For each constructive special case of Siegel, Faltings, or Mordell–Weil
in the repository, isolate the exact numerical theorem that produces a height bound or covering
representatives. Can power-gap, Runge, descent, and local-height arguments be factored into a

Effective analytic constants. For prime-distribution packets, specify machine-checkable constant

Projective and quaternionic geometry. Develop projective points, lines, eigenvectors, axes,

Repository migration questions

Packet triage. For each of the 58 delivered packets, fill a uniform schema containing its codes,
finite observations, guards, precision ledger, trace system, object-language target, and missing
producers. This would replace prose-only status with a machine-readable dependency graph.
Reference vertical slices. Three migrations would exercise most of the architecture:
1. an exact finite identity package, such as a divisor or trigonometric polynomial identity;
2. an analytic approximation package, such as Stirling or a finite Gamma-product theorem; and
3. a relational package, such as polynomial root clusters or rotation quaternions/axes.
Each should end in a kernel-checked Prf PRAAx theorem and native export.
Status automation. Can continuous integration verify that every public claim has a corresponding
Lean declaration, that all intended declarations build, that no placeholder axioms are introduced,
that PDFs rebuild, and that executable examples agree with the formal definitions? A theorem
ledger should fail closed: an absent proof remains visibly absent.

16.6

Conceptual question

The broadest question is whether a substantial portion of effective mathematics admits a small
common language of finite observations, relational witnesses, quantitative determinacy, and proofproducing traces. The present report gives evidence for an affirmative answer, while retaining precise
boundaries where deep producer theorems or constructive obstructions remain. Completing the
compiler and two or three representative migrations would test that claim much more decisively
than adding further prose-only theorem packets.

What is new in this report

The following synthesis is not copied as a theorem from one prior packet:
1. a precise proof-producing interface in which the base, step, and final trace obligations are
themselves Prf PRAAx terms and the generic compiler is a Lean function returning the completed
derivation;
2. the integration of relational finite outputs with two-sided full-horizon viability;
3. the shrinking-viability theorem, which chooses the least full-viable candidate at changing finite
horizons and proves coherence from cloud diameter and edge-tail bounds, without selecting
one infinite branch;
4. a unified migration boundary separating finite kernel, certificate producer, object-language
endpoint, and native export; and
5. a dependency-ordered implementation program against the exact current ConciseIPRA API.
The report makes no claim that these additions have already been kernel-checked in Lean. The
human proofs are intended to guide that implementation, and the accompanying exact Python
examples validate finite definitions only.
