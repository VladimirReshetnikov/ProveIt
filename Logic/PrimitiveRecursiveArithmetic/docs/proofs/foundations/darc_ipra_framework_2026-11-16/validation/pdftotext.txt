Abstract
This report develops a general method for translating fixed, finite, quantitative mathematical
arguments into the ordinary object-theory judgment Prf PRAAx Γ φ used by the ProveIt
formalization of intuitionistic primitive recursive arithmetic. The central device is a single
finite product-lattice analysis whose least prefixed point records, at once, which certificate
fields must escape local scope, which approximation precisions are demanded, which guards or
apartness margins are necessary, and which unproved quantitative producers must remain as
explicit residual hypotheses. This demand state prunes and specializes the proof graph before
object-proof assembly. Local noncanonical witnesses are eliminated by existential elimination;
public named witnesses are canonicalized only when needed, using checked bounded search; fixed
bounded formulas are compiled to primitive-recursive truth bits and finite strategy certificates;
loops are normalized to quantifier-free trace invariants; and finite relational witness problems are
solved by backward viability rather than incompatible independent choices.
The report proves stabilization and leastness of the demand analysis, the opencontract/sequent equivalence, certificate escape and residualization theorems, bounded
reflection and strategy soundness schemas, trace and viability schemas, and a global conditional
compilation theorem. It also isolates genuine barriers: no total universal evaluator is assumed,
no infinite path follows from horizonwise existence, no regular name follows without a tail
modulus, and no ordered root or eigenvector is selected through collisions. A source-oriented
Lean kernel, dependency-ordered Lean blueprints, exact finite reference algorithms, tests, and a
machine-readable plan schema accompany the paper. No new Lean-kernel-checked theorem is
claimed by this artifact.

Verification status. The mathematical arguments below are complete at the human-proof
level for the stated generic conditional schemas. The small Lean structural kernel has no
placeholders but was not elaborated in this runtime. The larger Lean files are blueprints
with explicit milestones. Python tests validate finite metalevel algorithms only; they are not
proofs in iPRA.

1

Demand-aware proof compilation

Executive overview

The working problem is not merely to encode one more theorem in arithmetic. It is to build a
reusable route from a broad class of mathematical arguments to a literal derivation in the ordinary
ProveIt judgment
Γ ⊢PRAAx φ,
while respecting the severe but mathematically useful discipline of intuitionistic primitive recursive
arithmetic. In particular, every function used in the object language must be primitive recursive,
induction is available only for quantifier-free formulas, and existential information must be handled
constructively rather than extracted by an unrestricted appeal to choice.
The repository already contains many of the ingredients needed for such a route. The ordinary
calculus has substitution, weakening, simultaneous cut, existential elimination, equality transport,
and quantifier-free induction. The checked arithmetic library contains order, bounded search, pairing,
simultaneous recursion, finite sums and products, division with remainder, gcd, and several higherlevel proof patterns. The checked bridge transports closed and open sequents to the Foundation
presentation used by several applications. The difficult part is now architectural: how should a
large, heterogeneous, partly quantitative proof be organized so that only the resources genuinely
needed by a requested conclusion survive into the final theorem?

1.1

The new organizing invariant

DARC answers this question by assigning each fixed proof plan a finite product of chains

The coordinates are not all of one kind. They include:
1. public query coordinates, indicating which outputs are requested;
2. certificate-liveness coordinates, indicating which fields of an internal witness must escape its
local existential scope;
3. precision coordinates, recording the finite accuracy required from approximation subroutines;
4. guard coordinates, such as denominator apartness, root separation, a spectral gap, or finite-net

and must therefore remain hypotheses of the compiled endpoint;
6. optional backend coordinates, when a consumer requires a translated vocabulary or a particular
published presentation.
Each local proof node contributes a monotone backward transfer rule. Starting from the public
query, DARC iterates

Because the lattice is a finite product of chains, every strict step increases the sum of the coordinates.

Hence the process stabilizes after at most r cr strict steps. Its value is the least prefixed point
above the query seed. The word “least” is relative to the declared transfer summaries: DARC does
not claim that no cleverer proof could use fewer resources. It does prove that no state satisfying
those summaries can omit a resource retained by the analysis.

This one invariant subsumes several analyses that otherwise tend to drift apart. A branch label
is retained exactly when the public result names that branch. A tail modulus is exposed exactly
when the requested precision reaches a node whose proof needs it. A quantitative nonzero margin
is requested only when a live operation divides or pivots. A height bound is absent from a purely
observational theorem but appears if the theorem asks for a complete list of witnesses. Dead nodes
and dead certificate fields are erased before proof assembly.

1.2

Compilation in two levels

The framework deliberately separates two levels.
Metalevel specialization. Lean or another trusted generator traverses one fixed finite proof plan,
computes its demand closure, specializes every fixed bounded formula to concrete primitive-recursive
symbols, and constructs an explicit derivation term. This traversal may recurse on the plan’s syntax
because it happens in the metatheory.
Object-level proof. The generated theorem is an ordinary Prf PRAAx derivation. It does not
quantify over proof plans, program codes, or formula syntax. It uses only the specific primitiverecursive symbols generated for that plan, their defining equations, successor axioms, intuitionistic
logic, and quantifier-free induction.
This distinction is the clean resolution of the universal-evaluator problem. There is no primitiverecursive total evaluator for all primitive-recursive programs with their unbounded running time.
DARC needs none. It produces a new fixed symbol for each fixed program, exactly as the ordinary
iPRA language permits.

1.3

Three certificate export modes

Every internal certificate is classified after demand closure.
Sealed. The public result is independent of the certificate. A local producer Γ ⊢ ∃c V (c) and
a consumer V (c), Γ ⊢ Φ are joined by existential elimination. No canonical certificate is
constructed.
Observed. The result depends only on an invariant observation O(c), and the proof establishes
that all valid certificates yield the same observation, or yield observations related by a specified
tolerance. The certificate remains hidden; only the stable observation escapes.
Named. The public statement really names a witness or code. DARC requires a finite search
bound and a primitive-recursive validity bit, then uses the checked least-search theorem to
select the least valid code. The expense and additional hypotheses of canonicalization occur
only in this mode.
This trichotomy prevents a common source of unnecessary strength: choosing a canonical representative merely because an external proof assistant happens to store one.

1.4

The main conditional theorem

Informally, the global theorem proved in section 13 is the following.
8

Demand-aware proof compilation

Theorem 1.1 (DARC compilation, informal). Let P be a fixed finite proof plan whose cyclic
computational components have been isolated as bounded loop blocks. Suppose that:
1. every demand transfer is monotone and sound for its local node;
2. every active acyclic node has an ordinary open derivation from the conclusions of its dependencies
and the residual formulas selected by the final demand;
3. every loop block has a quantifier-free invariant with base and step derivations;
4. every retained named certificate has a finite bound and a reflected validity bit;
5. every retained residual formula is either left as a hypothesis or is supplied by an ordinary
derivation.
Then the DARC algorithm terminates and constructs an ordinary derivation
Res(P, d∗ ) ⊢PRAAx ΦP ,
where d∗ is the least demand state above the public query. Supplying any subset of the residual
producers eliminates the corresponding hypotheses by simultaneous cut. Dead certificates, guards,
precisions, and proof nodes do not occur in the generated endpoint.
The theorem is conditional in the right way. It does not hide deep mathematics inside a compiler.
For example, a general effective height bound for a Diophantine problem remains a producer theorem.
Once such a theorem is provided, the same compiler can use it; until then, the endpoint states it
exactly as a residual.

1.5

What the framework resolves and what it refuses to blur

DARC resolves the routine but pervasive difficulties of context management, finite bounded quantification, proof-local witness handling, precision bookkeeping, and finite relational compatibility. It
also makes several negative results operational:
• finite-horizon compatible paths do not by themselves produce an infinite path;
• metastable finite windows do not by themselves produce a convergence rate;
• a coherent approximation chain is not automatically a regular real name without a tail modulus;
• a multiset of colliding roots does not support continuous ordered labels without a separation
condition;
• qualitative finiteness does not produce an effective search cutoff.
Instead of treating these as failures, the framework turns the missing data into typed residual
interfaces. This is essential for trustworthy use of a weak constructive arithmetic.

2.1

Demand-aware proof compilation

The canonical endpoint is ordinary Prf PRAAx

The directory Logic/PrimitiveRecursiveArithmetic separates four roles.
1. ConciseIPRA contains checked presentations and proves their relation to ordinary iPRA.
2. Derivations contains actual Lean-kernel-checked object derivations whose theorem types are
explicit judgments Γ ⊢PRAAx φ.
3. Bridge transports closed and open derivations between the ordinary presentation and the
Foundation presentation used by other projects.
4. docs/proofs stores delivered research packets. These are valuable mathematical design inputs,

The unification plan explicitly selects ordinary Prf PRAAx as the shared interface for new portable

every local node and the global result to target the ordinary judgment.

2.2

Checked structural and arithmetic support

The ordinary deduction file supplies precisely the structural operations needed for compositional
proof generation:
• Prf.substWeaken, combining substitution and weakening;
• Prf.subst and Prf.weaken;
• Prf.trans, a simultaneous-cut theorem replacing every hypothesis by a derivation of it;
• Prf.exE, the primitive operation for sealing local existential certificates;
• equality congruence and substitution;
• introduction and elimination rules for the intuitionistic connectives and quantifiers.
The ordinary arithmetic theory supplies a symbol for every primitive-recursive definition, defining
equations for projection, composition and primitive recursion, successor separation and injectivity,
and quantifier-free induction. The reusable derivation library builds semiring laws, order, pairing,
bounded sums and products, simultaneous recursion, finite descent, division, gcd, Bezout, and
bounded least search on this foundation.
Two checked interfaces are especially important.
Open induction. The helper IPRA.ind packages quantifier-free induction for an open formula
with parameters in scope. DARC’s loop reflection theorem is designed to reduce to this exact shape.
Bounded least search. For a fixed binary primitive-recursive body f (i, x), the checked search

2.4

Prior framework packets and the remaining gap

Several recent packets identify the right components:
• open context-polymorphic contracts equivalent to sequents;
• finite interaction programs and bounded strategy certificates;
• least finite demand closures, including cyclic monotone demands;
• certificate escape analysis and existential sealing;
• normalized trace reflection;

Their exact status is also important. The generic mathematics is often written in detail, and small

and the packages do not claim new kernel-checked main theorems. The ideas also remain partly
orthogonal: one analysis decides precision, another decides certificate escape, and another tracks
residuals. A proof generator can become inconsistent if those analyses disagree about which node is
live.
DARC’s distinctive step is to put all four decisions in one least finite state. A single transfer network
answers:
What must be true, how accurately must it be true, which local data must be public,
and which producer hypotheses remain, in order to answer this exact query?
The pruned proof schedule is then derived from that same state. This avoids a class of mismatches
in which, for example, a precision pass removes a branch but a witness pass still tries to name it, or
a residual producer is declared unnecessary even though a retained guard depends on it.

2.5

The audit yields the following nonnegotiable criteria.
1. The final theorem type is literally an ordinary Prf PRAAx sequent.
2. Metalevel code is evidence about the compiler, not a replacement for an object derivation.
3. Every fixed formula or algorithm is statically specialized; no total object-level universal evaluator
is postulated.

3

Formal setting: ordinary intuitionistic primitive recursive arithmetic

This section fixes the proof-theoretic target and clarifies which constructions belong to the object
theory and which belong to the metatheory.

3.1

Terms, formulas, and axioms

For each arity k, let PRk be the inductively generated class of primitive-recursive function symbols:
zero, successor, projections, composition, and primitive recursion. A term over n free variables
is a variable or an application of one such symbol. The formula language is ordinary first-order
intuitionistic logic with equality over these terms.
The axiom family PRAAx contains:
1. defining equations for projections, composition, and primitive recursion;
2. Sx ̸= 0 and injectivity of successor;
3. induction for every quantifier-free formula, with arbitrary free parameters.
A derivation is written

Γ ⊢PRAAx φ.

In Lean this is a proposition whose inhabitants are derivation trees. The metatheory may use
ordinary mathematics to construct such a tree. Soundness of the final mathematical statement
comes from the fact that the tree uses only the constructors of the embedded calculus and instances
of PRAAx.

3.2

The object/metalevel separation

The same word “primitive recursive” appears at two levels, and confusing those levels causes
overclaims.
Object level. A concrete symbol f ∈ PRk occurs in a term and has defining axioms. The object
theory can reason about f (⃗x), prove its equations, and apply quantifier-free induction to formulas
mentioning it.

12

DARC-iPRA

Demand-aware proof compilation

Metalevel. Lean can inspect a finite syntax tree describing a formula, proof plan, or primitiverecursive definition and produce a concrete symbol or derivation. This inspection need not itself be
represented by one total object-language function. Each generated result is finite and fixed.
The framework uses metalevel recursion on plans and formulas, but the emitted proof contains only
concrete object-level symbols. Thus a theorem schema of the form “for each fixed bounded formula
A, there is a bit bA and a derivation of A ↔ bA = 1” does not assert an object theorem about a
universal formula evaluator.

3.3

Open sequents as the unit of reuse

A reusable theorem should usually remain open. For example, cancellation is most useful in the
form
a + b = a + c ⊢PRAAx b = c
with a, b, c arbitrary terms under an arbitrary surrounding context. If one closes the theorem too
early by universal quantification and implications, then every downstream use must repeatedly
instantiate and reopen it. The ordinary deduction API already supports the cleaner open form
through substitution and weakening.
DARC therefore treats an open sequent as the basic node interface. A local node has:
• a finite list of dependency formulas Av ;
• a finite list of residual boundary formulas Bv (d) selected by demand d;
• a conclusion ϕv (d);
• a derivation Av , Bv (d) ⊢PRAAx ϕv (d).
The same local derivation can be specialized at arbitrary terms and inserted into any larger context.

3.4

Structural lemmas used by the compiler

We record the logical facts on which proof assembly depends.
Lemma 3.1 (Substitution). If Γ ⊢ φ over n free variables and σ maps those variables to terms
over m variables, then
Γ[σ] ⊢ φ[σ].
Lemma 3.2 (Weakening). If Γ ⊢ φ and every member of Γ occurs in ∆, then ∆ ⊢ φ.
Lemma 3.3 (Simultaneous cut). If Γ ⊢ φ and, for every ψ ∈ Γ, ∆ ⊢ ψ, then ∆ ⊢ φ.
Proof. The checked proof proceeds by induction on the list Γ. For the empty list, weaken the
closed derivation to ∆. For Γ = ψ :: Γ′ , introduce ψ as an implication in the given derivation,
apply the induction hypothesis to replace all assumptions in Γ′ , then use modus ponens with the
supplied derivation of ψ. No cut rule is added to the calculus; the lemma is derived from implication
introduction and elimination.
Lemma 3.4 (Existential sealing). If
Γ ⊢ ∃c V (c)

and

V (c), Γ+ ⊢ Φ+ ,

where + denotes the standard shift under the binder and Φ does not contain c, then Γ ⊢ Φ.

Proof. This is exactly existential elimination. The freshness condition is enforced by the scoped
representation of formulas: V lives over one more variable, while Φ lives in the outer scope.
Lemma 3.5 (Quantifier-free induction interface). Let I(t, ⃗x) be quantifier-free. If
⊢ I(0, ⃗x)

and

merely semantically bounded.

3.5

A note on metatheoretic classical axioms

The existing Lean developments may report standard Lean axioms such as propositional extensionality, quotient soundness, or choice in the metatheory. This does not add those principles to iPRA.
The object proof remains a finite value of the inductive type Prf PRAAx. DARC’s claim ledger
therefore distinguishes:
1. which object axioms a derivation uses;
2. which Lean axioms were used while constructing or representing the derivation;
3. which mathematical producer lemmas remain assumptions of the object endpoint.
This separation is necessary for an honest strength audit.

4

The fixed proof-plan language

DARC compiles one fixed finite plan at a time. The plan language is broad enough to organize proofs
from discrete mathematics, algebra, bounded number theory, effective analysis, and finite geometry,
but deliberately small enough that every construct has a direct ordinary-iPRA interpretation.

4.1

Nodes and interfaces

A plan consists of a finite directed graph G = (V, E), a public query node q, and declarations for
resources and local proof interfaces. Nodes have one of the following roles.
Producer. Establishes an input theorem, modulus, bound, finite net, apartness margin, or
certificate-existence formula. A producer may be proved, supplied as a hypothesis, or classified
as an open residual.
Compute. Applies a fixed primitive-recursive transformation and exposes its defining equations.
Examples are polynomial evaluation, bounded sums, a recurrence step, code projections, and
rational arithmetic.
Verify. Checks a fixed decidable relation through a characteristic bit and an object-level reflection
theorem.
Case or bounded-formula node. Compiles finite conjunction, disjunction, implication under
decidability, and bounded quantifier alternation to truth bits or strategy certificates.

14

DARC-iPRA

Demand-aware proof compilation

Loop. Encapsulates a bounded iteration with a fixed state type, primitive-recursive step, and
quantifier-free invariant.
Relation. Represents a finite cloud of possible witnesses and a compatibility relation between
adjacent layers. It is compiled by backward viability.
Observer. Maps a possibly nonunique local witness to the public data that actually matter. Its
contract includes exact, quotient, or metric compatibility.
Bridge. Translates a completed ordinary sequent to a client presentation and proves comparison
lemmas for the client’s symbols.
Every node v has a conclusion formula ϕv , dependency list dep(v), and local contract
ϕu : u ∈ dep(v) , Bv (d) ⊢PRAAx ϕv ,


where Bv (d) is the list of boundary formulas demanded at state d. A node is active only if its output
or one of its resource effects is demanded. The graph is a proof graph, not an execution graph: a
compute node denotes a proved equation for a fixed primitive-recursive symbol, and a loop node
denotes an induction proof.

4.4

Plan normalization

Before demand analysis, a plan is normalized as follows.
1. Inline purely definitional aliases so each compute node has one fixed symbol and explicit
equations.
2. Replace each fixed bounded formula by a node that will generate its truth bit and reflection
derivation.

precision or liveness is not a runtime loop; it remains in the monotone transfer network.
4. Group mutually recursive finite witness choices into one relation node rather than choosing
each witness independently.
5. Attach every partial operation to a guard formula.
6. Attach every unproved quantitative input to a producer node and a residual coordinate.
7. Compute the strongly connected components of the remaining proof graph. After loop extraction,
the condensation graph used for simultaneous-cut assembly must be acyclic.
The normalization does not prove local mathematics. It makes proof obligations explicit and puts
them in forms supported by the checked library.

5.3

Cycles are harmless when they are monotone

Precision dependencies often contain cycles. For instance, evaluating a root may require an integral
approximation, while the certified integration bound may itself use a rough root bound. Suppose
y ≥ 1 ⇒ x ≥ 2,

x ≥ 2 ⇒ y ≥ 4,

y ≥ 4 ⇒ x ≥ 5.

Starting from a query demanding y ≥ 1, the iteration obtains the finite closure x = 5, y = 4. No
recursive theorem is being assumed. The cycle occurs in the finite resource analysis and terminates
by rank.
This distinction is important:
• a cycle in the demand network is solved by finite monotone closure;
• a cycle in mathematical execution is extracted as a loop node and proved by quantifier-free
induction;
• a cycle in witness compatibility is treated as a finite relational problem or requires an explicit
extension producer.
Conflating these three kinds of cycles produces either an unnecessary fixed point inside arithmetic
or an unjustified infinite-choice step.

5.6

Compositionality of demand analyses

Suppose plans P and Q have disjoint internal coordinates and share an explicit interface. Their
combined transfer is the join of the extended transfers FP and FQ . Monotonicity is preserved. The
least closure of the composite may be computed globally or by iterating the two component closures
to mutual stability. This supports modular compilation: a library lemma can publish a compact
transfer summary along with its open theorem, without exposing its internal proof graph.
One should not, however, publish a summary that forgets a hidden residual. A summary is part of
the trusted mathematical interface in the same sense as a modulus: an understated requirement can
make the generated theorem false. The intended Lean representation therefore couples summaries
with proofs of local contracts, while the Python reference implementation is only an audit model.

Static specialization and the universal-evaluator barrier

A general proof framework naturally tempts one to define an object-language function that interprets
arbitrary formulas, proof plans, or primitive-recursive programs. In iPRA, that temptation must be
resisted. DARC obtains generality by a family of specialized compilers, not by one total universal
evaluator inside the object theory.

6.1

Why a total universal evaluator is the wrong target

Primitive-recursive functions are closed under a finite syntax of composition and primitive recursion,
but there is no primitive-recursive function that, for every code of a primitive-recursive program
and every input, returns that program’s value. A diagonal argument explains the obstruction. If
U (e, x) were primitive recursive and evaluated every unary primitive-recursive function fe , then
g(e) = U (e, e) + 1
would itself be primitive recursive and hence equal to some fk . But then g(k) = U (k, k) + 1 =
fk (k) + 1 = g(k) + 1, a contradiction.
Clocked evaluators for a fixed instruction set and fixed fuel are primitive recursive. Partial universal
evaluators can also be represented by step relations. Neither gives a total evaluator for arbitrary
primitive-recursive programs. Therefore a framework that silently introduces such an evaluator has
strengthened or changed the theory.

6.2

Specialization theorem schema

DARC uses the following metatheoretic schema.
Theorem 6.1 (Fixed-plan specialization). For each fixed finite DARC plan P , one can effectively
construct:
1. a finite list of concrete primitive-recursive symbols used by P ;
2. their defining equations as instances of PRAAx;
3. fixed truth-bit, strategy-checker, trace, and viability symbols for the bounded substructures
appearing in P ;
4. a finite Lean term whose target is the ordinary compiled sequent, provided the declared local
proof obligations are supplied.
No object-language variable ranges over plans or program codes.
Proof. Proceed by external structural recursion on the finite plan. A producer node contributes a
formula and either a derivation parameter or a residual. A compute node contributes the concrete
PR syntax for its fixed function. A bounded-formula node is compiled by recursion on that fixed
formula, producing finite folds. A loop node contributes a fixed primitive recursion or simultaneous
recursion for its state. A relation node contributes a finite backward recursion over its fixed horizon.
A proof node contributes a call to a local theorem and simultaneous cut. Since the plan is finite, the
construction terminates and outputs finite syntax. The output contains no interpreter; it contains
the syntax generated for this P .

DARC-iPRA

Demand-aware proof compilation

The phrase “effectively construct” belongs to the metatheory. Once the construction is run, the
resulting theorem is a specific ordinary derivation.

6.3

Fixed instruction sets and clocked traces

There is still an important place for interpreters. A theorem about a particular Turing machine,
register machine, recurrence language, or algebraic rewriting system may use a fixed primitiverecursive step function stepP and a clocked iteration runP (t, x). These are concrete symbols
generated from P . DARC permits:
runP (0, x) = x,

runP (St, x) = stepP (runP (t, x)).

What is prohibited is replacing the subscript P by an arbitrary code and claiming total evaluation
for all such codes.
This policy aligns with existing exact machine proofs in the repository. A literal table or fixed
equation is bound to a concrete endpoint; provenance and byte-level identity are preserved. Generality
comes from reusable proof patterns around that concrete object, not from erasing its identity.

6.4

Specialization of bounded formulas

A fixed bounded formula

∀i < N (x) ∃j < M (i, x) R(i, j, x)

is compiled to concrete primitive-recursive folds and strategy functions. The compiler may recurse
on the displayed syntax to generate a bit bA (x). The object theorem is the particular formula
bA (x) = 1 ↔ A(x).
It is not

∀e, x EvalFormula(e, x) = 1 ↔ Sat(e, x)



for a total arbitrary-formula evaluator. This distinction also keeps the induction matrix quantifierfree: the matrix mentions only the generated bit.

6.5

Specialization cache and theorem reuse

Static specialization need not duplicate proofs uncontrollably. A practical implementation should
hash a normalized fixed definition and reuse:
• the same generated PR symbol for identical bodies;
• the same reflection theorem for identical bounded formulas;
• the same transfer summary and local theorem for a reusable library component;
• theorem instantiation through Prf.subst rather than rebuilding a closed derivation.
The cache is an engineering optimization outside the trusted core. A cache hit is accepted only after
Lean checks the reused declaration at its exact type.

What is and is not uniform

DARC is uniform in a metamathematical sense: one generator handles a class of finite plans. It
is nonuniform in the object language: each output theorem contains symbols specialized to one
plan. This is not a weakness. It is the natural form of a theory whose language already contains a
function symbol for every primitive-recursive definition.
Uniform object theorems are still possible when their parameters are ordinary numbers or terms.
For example, one symbol can compute a finite sum up to a variable bound, and one open derivation
can prove its recurrence for all bounds. The boundary is syntax and unbounded program behavior,
not numerical parameters.

7.2

Substitution and context independence

A local theorem may be proved once with formal parameters x1 , . . . , xn . At a call site, the compiler

Certificate scope, observers, and canonical export

Certificates are unavoidable in constructive mathematics: factorizations, paths, finite covers, branch
choices, approximation traces, and bounded-search witnesses all carry information. The mistake is
to make every internal certificate part of the public theorem. DARC performs certificate escape
analysis within the same demand lattice used for precision and residuals.

8.1

Scoped certificates

A scoped certificate contract over an outer context Γ and public goal Φ consists of:
1. a validity formula V (c) in a scope with one additional variable;
2. a consumer derivation V (c), Γ+ ⊢ Φ+ .
A producer proves Γ ⊢ ∃c V (c). By theorem 3.4, the certificate is sealed.
Theorem 8.1 (Local certificate erasure). If no demanded public formula or live observer contains
the certificate variable, then a valid local certificate can be eliminated without selecting a canonical
code.
Proof. The demand condition ensures that all active uses of the certificate occur inside its consumer
subgraph and that the subgraph’s exported conclusion is in the outer scope. Compile that subgraph
to V (c), Γ+ ⊢ Φ+ , then apply existential elimination to the producer. Since the conclusion is scoped
outside the binder, the certificate cannot occur in it.

8.2

Observed certificates

Sometimes the public result depends on an observation O(c) but not on the full certificate. There
are three common compatibility modes.
Exact stability. For all valid c, c′ , prove O(c) = O(c′ ). One may seal a local certificate, define
the public value by any valid witness inside the proof, and use stability to show independence.
Quotient stability. Prove an explicit equivalence relation E(O(c), O(c′ )). The public theorem
states a quotient-invariant property or uses a canonical finite code for the equivalence class only
when such a code has a bounded constructive normalization.
Metric stability. At requested precision p, prove dist(O(c), O(c′ )) ≤ 2−p or another explicit
tolerance. The observation is then well-defined at that finite precision. A global exact object requires
additional coherence and a tail modulus; DARC does not infer one automatically.

1. Γ ⊢ ∃c V (c);
2. V (c), Γ+ ⊢ P (O(c));
3. the public conclusion is invariant under the chosen exact, quotient, or finite-precision compatibility relation.
Then the certificate may remain scoped, and only the observation contract is exported.
Proof. Open the existential certificate. Derive the observed property from the local consumer.
Use the compatibility theorem whenever the public statement compares this observation with one
obtained through another local witness. Finally close the existential. No representative is selected

The theorem is a schema because the exact public formula differs by compatibility mode. Its logical
core is always existential elimination plus an ordinary compatibility derivation.

Fixed bounded formulas, truth bits, and finite strategies

Bounded quantifiers are mathematically finite, but they are still quantifiers. They therefore cannot
appear directly in an induction matrix restricted to quantifier-free formulas. DARC removes them
before induction by compiling each fixed bounded formula to a primitive-recursive truth bit. When
a proof needs witness information rather than truth alone, the same syntax generates finite strategy
certificates.

9.1

Reflected atoms

An atomic interface consists of:
1. a formula A(⃗x);
2. a primitive-recursive bit χA (⃗x) ∈ {0, 1};
3. ordinary derivations of bit range and reflection:
⊢ χA (⃗x) = 0 ∨ χA (⃗x) = 1,

⊢ A(⃗x) ↔ χA (⃗x) = 1.

Equality of terms, order, divisibility with a fixed convention, finite code membership, and transition
relations are typical reflected atoms. The atom interface is theorem-specific: DARC does not assert
that every arbitrary formula has a characteristic bit.

9.2

Boolean operations

Assume a, b ∈ {0, 1}. Primitive-recursive arithmetic can realize:
a ∧ b := ab,
a ∨ b := sg(a + b),
¬a := 1 −̇ a,
a ⇒ b := sg((1 −̇ a) + b),
where −̇ is truncated subtraction and sg(z) = 0 iff z = 0, otherwise 1. On bits, the truth tables are
proved by the decidable zero/successor decomposition available in the arithmetic library.
The implication clause deserves comment. Intuitionistically, (P → Q) ↔ (¬P ∨ Q) is not valid for
arbitrary P . It is valid when P is decidable. The reflected bit gives precisely that decidability. Thus
the compiler may support implication in bounded formulas without importing unrestricted excluded
middle.

Normalized traces and quantifier-free loop reflection

Many mathematical proofs are finite algorithms with an invariant: Euclid’s algorithm, Gaussian
elimination under pivots, recurrence evaluation, finite search, interval refinement, dynamic programming, and certificate checking. The obstacle in iPRA is not iteration itself—primitive recursion
is available—but keeping the induction matrix quantifier-free. DARC therefore normalizes each
bounded loop to explicit state registers and reflected bits.

10.1

Trace normal form

A normalized loop block consists of:
1. a finite tuple of state terms s = (s1 , . . . , sk );
2. concrete primitive-recursive initial values s0j (⃗x);
3. concrete primitive-recursive step terms Tj (s1 , . . . , sk , ⃗x);
4. a quantifier-free invariant I(s, ⃗x);
5. an optional quantifier-free exit/output relation.
The trace functions Sj (t, ⃗x) are generated by simultaneous primitive recursion. If the library’s
simultaneous recursion is binary, larger tuples are encoded by checked pairing and projections. Their
defining equations are proved at arbitrary arguments:
Sj (0, ⃗x) = s0j (⃗x),
Sj (St, ⃗x) = Tj (S1 (t, ⃗x), . . . , Sk (t, ⃗x), ⃗x).

Removing bounded formulas from invariants

Suppose an informal invariant contains ∀i < n P (i, s). Before loop reflection, compile this bounded

a bounded existential is replaced by its finite disjunction bit, and a finite data-structure validity
condition is replaced by a reflected checker bit. The resulting formula is syntactically quantifier-free.

induction axiom is syntax-sensitive; only the explicit bit equality qualifies.

An external proof may arrive with a list of all states. DARC distinguishes two uses.
Recomputation. When the step is deterministic and cheap, define the trace by primitive recursion

Prec(x + y) ≥ p =⇒ Prec(x) ≥ p + 1,

Prec(y) ≥ p + 1.

The same applies to subtraction. In integer-scaled encodings, the proof is a finite inequality after
clearing powers of two. A sharper local theorem may reduce the one-bit slack, but the transfer must
match the theorem actually formalized.

12.3

Multiplication and magnitude bounds

Multiplication needs magnitude information. With |x|, |y| ≤ M , |x − a| ≤ δ, and |y − b| ≤ δ, one has
|xy − ab| ≤ |x| |y − b| + |b| |x − a|.
Since |b| ≤ M + δ, it suffices to choose δ from an explicit function of p and a bound code for M .
Accordingly, a multiplication node transfers output precision to:
• higher input precisions;
• magnitude-bound resources for both inputs;
• any arithmetic overflow or denominator conventions used by the code.
A magnitude bound is not silently inferred from existence of the numbers. It is a producer theorem
or part of the representation contract.

Roots, branches, and collisions

Ordered root labels are discontinuous at collisions. A finite approximation proof should therefore
export one of:
1. symmetric polynomial observations;
2. a multiset or cluster code;
3. a labeled root under an explicit separation guard;
4. a local branch continued along a finite path with compatibility and margin certificates.
A value query for a symmetric observable need not activate branch labels or a separation guard. A
query that names “the third root” must activate both. This is a canonical example of the benefit of
joint certificate/guard demand analysis.
Spectral theory has the same shape. At repeated eigenvalues, invariant subspaces or projectors are
stable; individual eigenvectors require a gap, normalization, and often an orientation convention.
DARC’s resource transfer makes the stronger assumptions appear only for the stronger output.

12.6

Finite nets instead of abstract compactness

When an argument uses compactness to select finite data, the constructive interface is:
1. a primitive-recursive finite net at requested scale;
2. a coverage theorem;
3. a modulus transferring local estimates from net points to the whole domain;
4. a finite verification of the desired property on the net.
The net and coverage theorem are producer nodes. If the repository packet has only an abstract
compactness argument, DARC leaves the effective net or coverage modulus residual instead of
presenting the finite check as a complete proof.

12.7

Series, integrals, and tail moduli

A finite partial sum identity is often easy in iPRA. An analytic value requires a tail theorem. Let
SN be a primitive-recursive partial sum and suppose a producer gives
N ≥ M (p, ⃗u) =⇒ |SN − L| ≤ 2−p .
Then the requested precision transfers to a cutoff M (p, ⃗u) and the arithmetic proof verifies the finite
sum. If M is not proved, the final endpoint remains conditional on the exact tail formula. It is
incorrect to replace a convergence assertion by a host-language numerical experiment.
For integration, the same pattern uses a quadrature rule, mesh modulus, finite error estimate, and
endpoint/magnitude guards. For special functions, one should separate exact algebraic identities of
finite truncations from analytic continuation and asymptotic remainder producers.

12.8

Metastability versus convergence rates

A metastable theorem has finite form
∀p, g ∃N ≤ B(p, g) ∀i, j ∈ [N, N + g(N )] d(xi , xj ) ≤ 2−p .

For fixed bounds this can be compiled to a bounded strategy theorem. It does not imply a global
Cauchy modulus M (p). DARC keeps the finite-window endpoint unless a separate tail argument
produces M . The demand system must not add a fictitious rate coordinate merely because repeated
finite queries are available.

12.9

Diophantine finiteness and height bounds

A theorem that a set of solutions is finite does not provide a number H such that every solution has
height below H. A complete enumeration or least-solution search requires such a cutoff. DARC
splits the task into:
1. a primitive-recursive verifier for a proposed solution;
2. finite enumeration below a supplied height;
3. a producer theorem asserting completeness of that height.
The first two can be fully compiled. The third remains residual for general Faltings-, Siegel-, or
Mordell–Weil-type applications unless an effective bound is actually available.

12.10

Quantitative transfer as an auditable interface

Each quantitative node should publish:
1. the representation and error predicate;
2. a monotone resource transfer;
3. an ordinary local derivation proving that the transferred resources suffice;
4. the conventions at singular or failed cases;
5. a status for each producer theorem.
This interface is analogous to a function type with preconditions and a modulus. It is the main
mechanism by which DARC turns informal analytic reasoning into a sequence of finite proof
obligations.

The global DARC compilation theorem

We now assemble the preceding components into one conditional theorem. The statement is deliberately explicit about the boundary between generic compilation and theorem-specific mathematics.

13.1

Well-formed plans

A normalized fixed plan P is well formed when the following data and proofs are supplied.
1. A finite resource shape LP , a query seed qP , and a monotone transfer FP : LP → LP .
2. A finite proof graph whose condensation after explicit loop extraction is acyclic.
3. For each demand state d and each node active at d, an ordinary local contract from active
dependencies and selected boundary formulas to the node conclusion.
4. For each loop node, concrete trace symbols, defining equations, a quantifier-free invariant, and
base/step derivations.

5. For each bounded-formula node, reflected atoms and the generated fixed-formula reflection
derivation.
6. For each relation node, finite bounds and reflected edge/terminal bits.
7. For each scoped certificate, a local producer and consumer, or an exact producer formula placed
in the residual boundary.
8. For each named certificate, a finite bound, validity bit, reflection theorem, and a proof that
some valid code lies below the bound.
9. For each quantitative operation, a sound transfer theorem connecting requested output resources
to input precisions, guards, and residuals.
10. For each backend export, checked vocabulary comparisons and a Bridge theorem preserving
the required open or closed sequent.
The plan may contain open residual producers. Well-formedness requires that they be named by
exact formulas; it does not require derivations of them.

Soundness alone would allow the compiler to retain every conceivable hypothesis. Demand leastness

Thus asking for more outputs cannot reduce the declared resource demand. A value-only query may

Proof. Induct simultaneously over the inflationary iterations from q and q ′ . The base inequality is

Plan composition

Let P compile a conclusion used as an input producer of Q. Form the composite by identifying that
interface formula, extending each resource shape with zeros for the other component, and joining
transfer maps. The global compiler may inline both schedules or retain the theorem boundary and
use simultaneous cut. The latter is preferable when P is a stable library component.
Proposition 13.4 (Compositional soundness). If P and Q are well formed and their shared formulas

Proof. Monotonicity is preserved by extending and joining the transfers. The combined graph is

13.7

Backend preservation

After obtaining (13.1), an application may request a Foundation sequent. The checked open Bridge
translates the context and conclusion under an explicit assignment. Symbol-comparison theorems
rewrite the generic arithmetic vocabulary to the client’s existing codes. DARC treats this as a final
node so that backend requirements do not contaminate the mathematical core.
No theorem is identified merely because two Lean functions compute the same standard naturalnumber function. The bridge requires an object-level comparison or an exact syntax round trip.
This preserves the theory and encoding stated by each endpoint.

A value query with a dead branch witness

certificate producer is opened locally; the symmetric-observer theorem derives the value; existential

Bounded alternation

Consider the finite statement
∀i < I ∃j < J R(i, j).
A direct nested proof can be awkward because the existential witness depends on i. DARC generates

Three public endpoints are possible:
1. seal the strategy and prove only the bounded formula;
2. observe a stable aggregate, such as a finite sum of costs;
3. name the least valid strategy code under a finite code bound.
The reference artifact instantiates this with parity and verifies the finite certificate.

Finite compatible approximation clouds

14.6

Special functions and analytic packets

A special-function packet typically mixes four levels:
1. exact identities of finite products, recurrences, or coefficients;
2. formal power-series identities at a fixed truncation;
3. effective convergence inside a guarded domain;
4. continuation, branch selection, asymptotics, or special values.
DARC separates these levels. Exact finite identities often compile with no residual. A truncation
theorem requests a finite coefficient bound. An analytic value query activates a convergence or tail
modulus and domain margins. A branch-specific query additionally activates a path and separation
guards. A continuation theorem beyond the formalized domain remains residual.
This prevents an exact coefficient proof from being overstated as a complete theorem about a global
analytic function, while maximizing the portion that can be checked in iPRA.

14.7

Diophantine enumeration

Suppose R(x, y) = 0 is a concrete polynomial or primitive-recursive relation. The verifier is
straightforward. Given a height H, bounded search can enumerate all solutions with code below H,
prove soundness of the list, and prove completeness below H. To claim global completeness, the
plan needs
R(x, y) = 0 =⇒ height(x, y) < H.
If no effective height producer is known, DARC emits a conditional theorem with that formula as the
sole deep residual. This is more informative than marking the whole application “unformalizable”:
the verifier, enumeration, and downstream finite reasoning can still be completed.

14.8

Geometry and finite nets

For a compact-domain geometric inequality, a DARC plan can contain:
1. a rational mesh generator at scale p;

The requested final slack determines mesh precision. Degenerate configurations activate separate

14.9

Busy Beaver and exact coded endpoints

Machine and consistency applications demand exact provenance. A plan should bind the literal table,
blank-start convention, proof predicate, and object theory at producer nodes. Generic arithmetic
lemmas can be imported through ordinary open sequents; a final bridge node translates to the
published Foundation endpoint. DARC does not identify two machines because their external
simulations agree, nor does it replace a conditional object theorem by a stronger semantic statement.
The endpoint inventory remains the source of truth.

The global plan exists in Lean metatheory and stores local theorem values. Because theorem types
depend on node formulas, a fully generic dependent graph can become cumbersome. A practical
staged implementation is:
1. generate one Lean module per concrete plan;
2. declare node formulas and local proof constants in that module;
3. generate the topological schedule as ordinary Lean code using Prf.trans;
4. use a generic metatheoretic demand library to decide which declarations are emitted;
5. only later abstract common dependent graph machinery.
This route gives checked application pilots sooner and avoids spending months formalizing a universal
compiler representation before validating the local interfaces.
The blueprint lean/DARC/CompilerBlueprint.lean states the ideal generic theorem, but the
generated-module approach is an equally valid path to a complete checked result.

17.6

Conclusion

DARC turns the broad question “can this mathematics be expressed in iPRA?” into a sequence of
reviewable obligations:
1. What is the exact finite public query?
2. Which witnesses, precisions, guards, and producers does it force?
3. Which bounded formulas must be reflected to bits?
4. Which cycles are finite demand cycles, which are induction loops, and which require a genuine
extension theorem?
5. Which local results are ordinary open derivations?
6. Which deep quantitative inputs remain residual?
The least demand state provides one answer shared by proof scheduling, certificate escape, precision
propagation, and residual exposure. The final object is not a semantic promise but an ordinary
Prf PRAAx derivation. That combination gives a plausible path from the repository’s many rich
proof outlines to a smaller number of reusable, checked, and accurately scoped formal theorems.

Reference algorithms and worked finite instance

This appendix describes the exact finite algorithms in the artifact. They are included for reproducibility and testing, not as a substitute for the Lean formalization.

A.1

Demand closure pseudocode

def close(seed, transfer, capacity_sum):
d = seed
history = [d]
for _ in range(capacity_sum + 1):
nxt = join(d, transfer(d))
if nxt == d:
return d, history
assert rank(nxt) > rank(d)
d = nxt
history.append(d)
raise Error("rank bound violated")

The implementation validates coordinate names and levels. For small shapes it exhaustively checks
every admissible candidate to verify leastness. It checks monotonicity on every comparable pair when
that set is below a configurable limit; threshold-rule monotonicity is otherwise justified symbolically
by the form of the rules.

Strategy checker pseudocode

For a positive bounded formula:
check(atom A, c, env) = (c.tag == atom and A(env))
check(P and Q, c, env) =
c.tag == and and check(P,c.left,env) and check(Q,c.right,env)
check(P or Q, c, env) =
c.side selects a branch whose subcertificate checks
check(exists i<N. P, c, env) =
0 <= c.witness < N and check(P,c.sub,env[i := c.witness])
check(forall i<N. P, c, env) =
c has N branches and each branch i checks under env[i := i]

The builder chooses the leftmost true disjunct and least true existential witness. These canonical
choices model the object-level bounded-search plan.

viable[H] = terminal layer

B

Application proof-obligation template

A new application should fill the following checklist. It is designed to keep mathematical status and
compiler status separate.

B.1

Public theorem

1. State the exact ordinary iPRA formula, including free parameters, coding conventions, and
requested precision.
2. State whether the endpoint is an open sequent, closed sentence, or a backend translation.
3. Identify every public witness or code that must be named.

B.2

Representations

For each mathematical object:
1. give its numerical code and primitive-recursive operations;
2. give validity and equality/compatibility formulas;
3. specify failed or singular-case conventions;
4. list checked upstream symbols that are reused;
5. provide reflection theorems for every atom used in bounded formulas.

B.3

Plan nodes

For each node record:

1. node identifier and kind;
2. dependency formulas;
3. output formula;
4. local Prf PRAAx theorem name or explicit residual status;
5. certificate scope: none, local, observed, or named;
6. transfer summary with a human proof of soundness;
7. imports and replay command.

B.4

Loops and relations

For every loop:
1. list state registers and step terms;
2. display the quantifier-free invariant after Boolean compilation;
3. provide base and step derivations;
4. provide a fuel or termination-bound theorem.
For every relational cloud:
1. state layer bounds and edge bits;
2. state terminal acceptance;
3. decide whether the path is local, observed, or named;
4. state any extension or tail producer separately from finite viability.

Quantitative producers

For every approximation operation:
1. state the error predicate;
2. prove the precision transfer and its monotonicity;
3. state magnitude, apartness, gap, coverage, and tail requirements;
4. classify each requirement as checked, to be proved, or residual.

Compilation audit

The generated record should include:
1. resource shape, query seed, fixed point, and iteration history;
2. monotonicity evidence for every transfer;
3. retained and pruned nodes;
4. final residual formulas;
5. exact ordinary endpoint;
6. theorem names used in the simultaneous-cut schedule;

8. backend symbol comparisons and translated endpoint, if any.

Status vocabulary

Use only the following status labels:
Checked upstream. A declaration was built and audited in the pinned repository or a recorded
compatible baseline.
Checked in application. A new declaration was built and audited by the application replay.
Human proof. A complete nonformal argument is supplied but no Lean elaboration is claimed.
Source candidate. A no-placeholder source file exists but has not been elaborated in the recorded
environment.
Lean blueprint. Signatures and proof plan exist with explicit milestones.
Executable finite test. Host code verifies finite examples only.
Residual. The exact producer theorem remains an assumption.
This vocabulary prevents a compiled PDF, passing Python test, or no-placeholder text file from
being mistaken for a kernel-checked object theorem.
