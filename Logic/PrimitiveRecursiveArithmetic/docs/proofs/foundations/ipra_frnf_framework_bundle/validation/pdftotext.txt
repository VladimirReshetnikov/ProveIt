Finitary Realizer Normal Form
A proof-producing framework for embedding mathematics into
intuitionistic primitive recursive arithmetic
Research report prepared for the ProveIt iPRA development
16 November 2026

Abstract
The ProveIt repository contains a growing collection of finitary reconstructions of
classical theorems, together with a checked core of ordinary intuitionistic primitive
recursive arithmetic and many reports identifying recurring obstructions. The collection
already exhibits a remarkably stable pattern: exact finite arithmetic is straightforward,
while the difficult passages concern represented infinite objects, adaptive precision,
nonunique witnesses, compactness, branch selection, and the gap between a hostlanguage theorem and an object-language derivation.
This report isolates that pattern as a common intermediate language, the Finitary
Realizer Normal Form (FRNF). An FRNF proof is a fixed finite graph of statically specialized primitive-recursive transducers, bounded searches, clocked loops with
quantifier-free invariants, finite relational witness clouds, stable observers, and explicit
producer boundaries. Every edge carries two primitive- recursive moduli: a computation
horizon, recording which input rows are read, and a usually larger justification horizon,
recording which input contracts are required to prove the output correct. A reverse
demand pass is run before any induction. The resulting finite table is Booleanized, one
clocked trace is verified by quantifier-free induction, and the local embedded derivations
are composed by simultaneous cut into a term of type Prf PRAAx. Nonunique approximate witnesses are not prematurely forced into exact selectors: backward viability
gives finite coherent paths, stable observables erase internal choices, and exact branch
labels are recovered only from explicit separation data.
The report gives complete human proofs of bounded-formula Booleanization, least
bounded search, dual-horizon composition, reverse demand closure, trace internalization, backward viability, shrinking finite-horizon coherence, majorized descent, finite-net
minimization, and guarded inversion. It proves two representation barriers—there is
no total primitive-recursive universal evaluator, and a uniform cardinality-to-cutoff
operator would decide the halting problem—and uses them to separate genuine mathematical inputs from mere formalization work. This resolves a large class of reported
difficulties and gives exact conditional endpoints for the remaining ones, including
arbitrary Cauchy Puiseux data and general Siegel/Faltings height bounds.
The accompanying artifacts include exact-arithmetic Python reference algorithms
with eleven regression tests, a repository-aligned Lean module containing the logical
Prf PRAAx combinators, explicit Lean targets for the remaining arithmetic compiler,
machine-readable theorem and obstacle ledgers, and this source. The Lean files have not
been compiled in the artifact environment; visible placeholders are retained precisely
where object-level implementation remains.

1

Scope, contribution, and claim discipline

1.1

What problem is being solved?

6

The intended target is not the informal statement that “ordinary mathematics can be
encoded in arithmetic.” Such a statement is too coarse to guide a formalization. A usable
framework must answer five concrete questions for every theorem.
Q1. What finite numerical data represent each mathematical object at the precision
actually consumed by the proof?
Q2. Which primitive-recursive programs compute the finite outputs, and how are their
adaptive queries bounded before induction begins?
Q3. Which formulas express correctness in the first-order language of iPRA, and which
of those formulas are quantifier-free induction invariants?
Q4. How are local correctness derivations composed into an actual object-theory proof,
rather than merely a theorem about the intended standard model?
Q5. Which pieces of data are generated by a primitive-recursive producer, and which
remain explicit mathematical assumptions such as a modulus, a height bound, or a
separation constant?
The existing ProveIt packets repeatedly answer subsets of these questions [6]. The
checked Derivations library shows that substantial exact mathematics can be carried all
the way to terms of type
([] : List(Fm PTm 0)) ⊢PRAAx φ.
The unverified packet corpus contains many sophisticated quantitative proofs and several
overlapping general frameworks. The bottleneck is therefore not a shortage of high-level
ideas. It is the absence of one normal form that is simultaneously mathematically expressive,
honest about representation barriers, and designed to emit embedded derivations.

1.2

The proposed normal form

We call the normal form developed here Finitary Realizer Normal Form, abbreviated
FRNF. Its central design decision is that a proof is compiled twice.
First, at the semantic compilation level, the proof is specialized to the fixed primitiverecursive routines that occur in the theorem. Higher-type language is eliminated in favor
of explicit finite observations, moduli, bounds, and relations. All adaptive behavior is
defunctionalized into a finite state machine with an explicit clock. The compiler computes
a finite closure of every row of every input name that is needed either for computation or
for justification.
Second, at the object-proof compilation level, the closed demand table is represented
by primitive-recursive symbols and first-order formulas. Bounded conditions are replaced
by characteristic terms. A single quantifier-free invariant tracks the clocked trace. Local
derivations are then assembled in topological order. The final output is not a Boolean test,
a Python success message, or a Lean theorem about natural numbers. It is an inhabitant
of Prf PRAAx for the intended formula.

What is new in the synthesis?

Several ingredients have precedents in the repository and in proof theory. Bounded search,
primitive-recursive coding, proof interpretations, moduli, and finite nets are standard tools.
The contribution here is their organization around four requirements that are easy to state
but rarely enforced together.
(i) Dual horizons. Every interface distinguishes the input rows needed to compute an
answer from the input rows needed to prove the answer valid. Composition propagates
the second quantity, not merely the first.
(ii) Relational intermediate values. Approximation, branch ambiguity, and collisions
are represented by finite candidate relations. Deterministic selection is introduced
only when the theorem proves that the observable is choice-independent or an explicit
gap isolates a branch.
(iii) A formula firewall. Host-language semantics and object-language provability are
separate fields of every interface. There is no coercion from a Lean proposition to
Prf PRAAx.
(iv) Boundary preservation. A finite verifier is never advertised as a producer of
a height bound, modulus, zero-free region, or exact algebraic splitting. Such data
remain visible hypotheses until a primitive-recursive producer and its object proof
have themselves been supplied.
The dual-horizon requirement is especially important. In a represented proof, the
program may read a row a(r(d)) to produce output precision d, while the proof that this
row is correct may require coherence comparisons at a(j(d)) with j(d) > r(d). Collapsing
these into one “use” bound is safe only if the bound is defined to dominate both. Many
informal formalization plans silently track the first and need the second.

1.4

Claim classes

To keep the package auditable, every result belongs to one of the following classes.
Mathematical theorem.
A complete ordinary proof is given in this report.
Executable finite check.
The standard-library Python reference implementation runs and its regression test
passes. This validates the finite algorithm on the test cases, not its object-theory
proof.
Host-checked Lean theorem.
Lean accepts a theorem in its own metatheory. No such claim is made here because
Lean was not installed in the artifact runtime.
Object-checked theorem.
Lean accepts a declaration whose conclusion is an embedded Prf PRAAx derivation, and
an axiom audit has been inspected. This status belongs to the upstream Derivations
results that we reuse; it is not claimed for the new generic compiler.

Blueprint target.
The exact statement, definitions, dependencies, and proof route are supplied, but

Boundary or obstruction.
The framework proves that an input cannot be generated by the proposed generic

This discipline matters because an executable checker and an object proof answer
different questions. The former asks whether a concrete finite certificate passes a program.
The latter asks whether the correctness of that program has been derived using only the
axioms and induction allowed by iPRA.

1.5

Relation to proof interpretations

The guiding philosophy is compatible with Gödel’s functional interpretation and its modern
proof-mining descendants: apparently infinitary assertions are transformed into finite
computational data and quantitative bounds [2, 3]. The present goal is narrower and more
syntactic. We do not provide a global interpretation of a strong ambient theory. Instead,
we give a compositional target language for hand-developed finitary proofs and a route
from that language to the particular embedded calculus used by ProveIt. One may view
FRNF as a proof- engineering normal form informed by proof interpretation rather than
as a new conservation theorem.

1.6

The main theorem in informal form

The report culminates in the following schema, made precise in section 18.
Schema 1.1 (FRNF compilation, informal). Fix a finite acyclic graph whose nodes are
statically specialized primitive-recursive transducers, bounded searches, clocked loops, finite
relational witnesses, stable observers, or explicit boundary assumptions. Suppose every
edge has primitive- recursive computation and justification horizons, every loop has a
quantifier-free invariant with embedded base and step derivations, and every node has an
embedded local correctness derivation from its declared predecessors. Then for every fixed
final demand the graph compiles to an embedded iPRA derivation of the final contract. The
only mathematical assumptions in the result are the boundary formulas explicitly listed by
the graph.
The theorem is deliberately a schema over fixed syntax. It does not quantify inside iPRA
over arbitrary primitive-recursive program codes. Section 6 proves why that restriction is
essential rather than cosmetic.

2

The target theory and the standard of success

2.1

Working presentation of iPRA

For this report, iPRA is first-order intuitionistic arithmetic with equality, a function symbol
for every primitive-recursive function and its defining equations, successor axioms, and
induction restricted to quantifier-free formulas. This is the presentation implemented by
the ProveIt type Prf PRAAx. The exact choice of a primitive-recursive basis is immaterial
up to definitional extension, but it is not immaterial to a formalization: every algorithm

mentioned in a proof must eventually be represented by a fixed symbol or a term assembled
from such symbols.
The restriction to quantifier-free induction does not make the theory incapable of proving
quantified theorems. It constrains the induction invariant. A typical proof first encodes
a finite computation, proves a quantifier-free invariant for the encoded state, specializes
the invariant at a primitive-recursive clock, and only then uses ordinary intuitionistic
introduction and elimination rules to derive the final quantified statement.
The repository supplies two complementary targets.
• ConciseIPRA formalizes ordinary iPRA, a very small native scalar calculus, and translations between them. Its theorem pra_iff_native exports an ordinary embedded
derivation to the native core.
• IPRADerivations develops arithmetic directly in Prf PRAAx: semiring identities,
order, truncated subtraction, pairing, simultaneous recursion, bounded sums and
search, division, gcd, Bézout, descent, and other reusable components.
The framework below is therefore not a replacement foundation. It is a compiler front
end whose output is designed to enter this checked library.

2.2

Object theory versus metatheory

We use three levels of assertion. Confusing them is the single most damaging source of
false completion claims.
Level 0: executable mathematics. A primitive-recursive algorithm is described
extensionally and may be run in Python, Lean, or another language. One can test examples
and inspect traces. This level is useful for finding off-by-one errors and validating finite
combinatorics.
Level 1: host semantics. Lean proves a theorem such as
∀x : N,

run(x) satisfies Spec(x).

This theorem lives in Lean’s dependent type theory and may use host induction, quotients,

2.4

Uniformity and schemas

There are two legitimate forms of uniformity.
(a) A single primitive-recursive symbol may accept numerical parameters such as a
matrix size, polynomial degree, requested precision, or finite graph code, provided its
algorithm is itself fixed.
(b) A metatheoretic schema may associate a different primitive-recursive symbol and
derivation to each externally fixed program or theorem instance.
What is not generally available is a total primitive-recursive evaluator U (e, x) whose
numerical code e ranges over all primitive-recursive programs and which returns the value
of every such program. The diagonal argument in section 6 rules this out. Thus, “uniform
over the degree” can be a genuine single theorem, while “uniform over an arbitrary code of
a primitive-recursive coefficient evaluator” must be interpreted as a static metatheoretic
schema or be restricted to a fixed, bounded interpreter.

The formula firewall and the four-part interface

3.1

Why an interface needs four parts

A reusable component is often described by only a program and a semantic theorem. That
is sufficient in an ordinary programming library but insufficient for an embedded weak
theory. We require four distinct fields.
Definition 3.1 (FRNF component). An FRNF component from input presentation X to
output presentation Y consists of:
(i) fixed primitive-recursive symbols computing finite output observations;
(ii) an object-language formula CX→Y expressing the component contract;
(iii) a constructor that, from embedded derivations of declared input contracts, returns
an embedded derivation of CX→Y ; and
(iv) an optional host-semantic theorem identifying the numerical contract with its intended
mathematical meaning.
The first three fields are the kernel-facing interface. The fourth is the semantic interpretation.
The separation between (iii) and (iv) is the formula firewall. It may feel redundant
when the host theorem is elementary, but it allows components to be combined without
accidentally importing a strong metatheory into the object proof.

Exact contracts

Relational contracts

Bounded searches over coded tuples

Pairing and simultaneous recursion allow a search over any fixed finite product to be

the search space may be enormous; iPRA is concerned with primitive recursiveness and
proof, not practical efficiency. Nevertheless, the normal form encourages structured loops
and dynamic programming when they yield smaller invariants.

5.4

The selector/finality distinction

Suppose a finite cloud Cd (x) contains several valid approximations at precision d. Bounded
search yields the least valid code cd . This proves existence of a primitive-recursive selector
for each finite level. It does not prove that (cd )d is coherent, convergent, or presentation
invariant. Those are separate statements about compatibility edges, diameter bounds, and
motion budgets. We will therefore use bounded search in two roles:
(a) as an exact selector when equality and ordering of candidates have mathematical
meaning; and
(b) as a deterministic implementation detail inside backward viability, followed by a proof
that the final observable does not depend on that detail.
This distinction prevents a finite-choice theorem from being silently upgraded to a
choice principle for infinite represented objects.

6.2

Three admissible representation patterns

Definition 6.2 (Static specialization). A fixed primitive-recursive evaluator f is represented
in the object theory by its own function symbol, defining equations, and derived contract.
A metatheoretic compiler may map the external description of f to this syntax, but the
object program does not receive the description as data.
This yields three sound patterns.
Fixed evaluator. A theorem is uniform in numerical inputs and precision but uses one
externally fixed coefficient-name evaluator, oracle, or transition function. The compiler
generates a symbol for that evaluator. This is the strongest and simplest pattern.
Finite table. For a fixed final demand, the reverse horizon pass determines a finite set
of required queries. Their answers are supplied as a coded table satisfying a finite validity
formula. The theorem never evaluates a program code at all. This pattern is particularly
useful for extensional composition: only the rows actually consumed by the proof are
exposed.
Restricted interpreter. A fixed syntax class with an explicit structural or numerical
fuel is interpreted by a primitive-recursive evaluator. The contract includes a proof that the
supplied code belongs to the class and that the fuel suffices. Examples include straight-line
arithmetic expressions of bounded depth, fixed-order recurrences, or a bounded instruction
machine.

6.3

object formula Ce , and a derivation ⊢PRAAx Ce .
This is a computable metatheoretic transformation if the compiler itself terminates. It
is not the same as one object formula quantifying over e and invoking a universal U (e, x).

necessarily so—than an internal total evaluator for all primitive-recursive codes.

(3) the object contract formula; and

Proof horizons as a noninterference theorem

The justification horizon has a useful extensional reading. If two input presentations agree

the finitely many input contract instances. No global object representing the entire infinite
name need occur inside the induction.

7.5

Adaptive queries

If the next query index depends on previous answers, a simple syntactic scan does not
produce a fixed list. The solution is to bound the adaptive computation by a clock and
compute a worst-case demand transformer. Let a state contain the current query index,
answer table, and remaining fuel. A primitive-recursive majorant H(d, t) bounds all queries
reachable in t steps from final demand d. The dual horizon is the prefix maximum of this
majorant over the clock, with a separate recurrence for proof queries. The finite trace then
records the actual path, while the precomputed horizon makes the induction independent
of an infinite oracle.

8.2

Why closure precedes induction

The demand pass is run in the metatheory or as a preliminary primitive-recursive computation, before the main correctness induction. Its output is a finite vector of bounds. The
proof then materializes exactly the table rows and contract instances within those bounds.
This order avoids an illegal invariant saying “for every future precision, all needed rows are
valid.”
In an object implementation, the demand pass itself is a bounded loop and may be
verified by quantifier-free induction. The main trace uses its completed table as fixed input.
Nested uses of quantifier-free induction are harmless: each invariant is finite and explicit.

8.3

Shared dependencies and proof reuse

If two nodes depend on the same source, the closure takes the maximum of their demands.
The source table is computed once. Likewise, its validity derivations may be stored once in

common-subexpression elimination.
A graph representation is therefore not merely convenient notation. It can reduce proof
terms and makes dependency auditing possible. Each node declares exactly which earlier
formulas its local proof uses; undeclared global assumptions cannot enter silently.

8.4

Cycles and feedback

A genuine cyclic dependency cannot be handled by a topological pass. In practice one of
three situations occurs.
(i) The apparent cycle is a bounded iteration. Collapse it into one clocked loop node
whose state contains all mutually recursive values.
(ii) The cycle is a fixed-point specification with a contraction modulus. Replace it by a
finite Picard iteration whose clock is derived from the modulus.
(iii) The cycle expresses an infinitary or impredicative construction with no supplied
majorant. It lies outside the unconditional FRNF interface and must remain a
boundary.
Simultaneous primitive recursion, already available in the checked repository library, is
the standard implementation of the first case.

8.5

Object encoding

For a fixed small graph, the cleanest formalization generates one tuple of demand terms
per node and proves the closure equations directly. For a graph supplied as finite data,
encode:
• the node count and topological order;
• edge offsets in a flattened adjacency table;
• codes selecting from a fixed finite family of demand transformers;
• an active bit distinguishing bottom from the genuine numerical demand zero; and
• the read/justification arrays updated by primitive recursion.
The interpreter is admissible because the family of node and edge operations is fixed and
finite; it is not a universal evaluator for arbitrary primitive-recursive syntax. The object
theorem demandClosure_correct in the Lean roadmap is the intended closed derivation
of this finite table algorithm.

9.4

Local reflection versus global semantics

The trace theorem requires embedded proofs of the base and step equations. A host proof
that the transition is correct can guide these derivations but cannot replace them. In
practice the object step proof is assembled from:
(i) defining equations for the primitive-recursive transition;
(ii) Booleanization lemmas for branch guards;
(iii) arithmetic library lemmas for the updated fields; and
(iv) local component contracts already present in the proof schedule.
This decomposition is favorable to automation. The transition itself is fixed and finite;
the compiler can generate the formula and most congruence steps. Domain lemmas remain
explicit.

9.5

Variable-length recursion

A loop whose length is a numerical input is not a schema of separate finite proofs. It is one
primitive recursion and one induction on the clock. The final theorem may therefore be
genuinely uniform in a matrix size, polynomial degree, path length, or search bound. The
restriction is that the transition and invariant must be fixed primitive-recursive syntax.
This is how variable-degree constructions avoid the universal-evaluator barrier.

9.6

Nested finite loops

Nested loops can be flattened into one state machine by storing both counters, or formalized
modularly as components whose local contracts are composed. Flattening uses one induction
but may produce a large invariant; modularization creates smaller proofs but requires a
proof schedule. FRNF supports both. The preferred choice is to isolate mathematically
meaningful subroutines and flatten only tightly coupled adaptive loops.

11.3

Why no infinite choice is used

The theorem is finite for each requested horizon. It does not appeal to König’s lemma,
dependent choice, or an infinite branch through the layered graph. This is crucial. Many
applications consume only a finite horizon, and stable-observer arguments can show that
the final result is independent of which finite path is used. When an actual represented
limit is required, coherence is proved quantitatively from shrinking diameters and motion
budgets, as in section 12; it is not obtained by selecting an abstract infinite branch.

11.4

Relational composition

Suppose a producer returns a finite relation R(x, a), while a consumer at state s may
accept several answers and move to s′ = T (s, a). A locally valid answer can lead to a
dead end at a later stage. Backward viability solves this global finite constraint problem:
candidate (s, a) is retained only when it has a compatible continuation to the fixed final
horizon. The forward selector then produces a successful interaction trace.
This is the correct finite replacement for a higher-type oracle strategy. The entire
answer tree is finite after the final demand and clock are fixed. The backward pass computes
a winning region; the forward pass selects one witness. If the consumer’s observable is
stable over all winning traces, the internal selection is erased.

11.5

Applications

The same recurrence covers several apparently different situations.
• Root clouds. Candidates are rational disks or boxes with residual certificates; edges
express overlap or controlled movement.
• Charted geometry. Candidates are local charts or transition branches; edges
express overlap compatibility.
• Simplicial observation. Candidates are vertices in a carrier cloud; edges express
admissible selections.
• Approximate minimizers. Candidates are net points within a tolerance; edges
enforce motion between refinements.
• Finite gluing. Candidates are local sections; compatibility is equality or witnessed
equality on overlaps.
• Adaptive proof search. Candidates are local certificates; edges express that the
next verifier state accepts them.
The domain-specific work lies in defining validity and compatibility and proving
nonemptiness. The viability compiler is generic.

Descent proofs of impossibility

Infinite descent arguments can be compiled in two related ways.

(ii) A solution-count function below rank N is shown to vanish by induction on N : a

The repository’s generic descent modules implement both styles. FRNF treats them as
reusable nodes rather than rebuilding descent for each theorem.

is another instance of producer/verifier separation: a step checker does not produce a

Totalized guarded functions

Every primitive-recursive symbol must be total. Define a totalized reciprocal approximator

Pole clearing and algebraic reformulation

Sometimes the guard can be avoided by changing the observable. Instead of proving

identity. Instead of selecting a normalized eigenvector, prove a statement about the rankone projector after clearing a norm denominator, or about the invariant subspace. Monic
polynomial presentations similarly avoid division by a leading coefficient.

finite-algebra certificates are often the intrinsic content of a theorem, while a normalized
representative is an additional choice requiring apartness.

15.5

Branches and exact discrete data

Square roots, arguments, logarithms, and Puiseux leading terms combine continuous
approximation with discrete branch data. A branch interface must include one of:
(i) an exact algebraic presentation that determines the branch;
(ii) a rational region separated from every branch boundary;
(iii) overlapping relational branches with a stable downstream observable; or
(iv) an explicit boundary assumption supplying rank, sign, or monodromy data.
An arbitrary Cauchy name does not generally determine exact discrete information
by a uniform finite procedure. The obstruction is addressed explicitly in section 16; the
correct response is to strengthen the presentation, not to hide an undecidable comparison
inside a selector.

Exact barriers and honest unresolved inputs

A general framework is useful only if it distinguishes formalization problems from missing
mathematics and from impossible interfaces. This section records the most important
boundaries. None of them says that the associated theorem is unprovable in iPRA; each
says that a particular generic route cannot supply the required data.

16.1

Cardinality does not uniformly produce a cutoff

Suppose Pe (n) is a decidable family with at most one solution. It is tempting to expect a
uniform algorithm that, from e and the cardinality bound, returns B(e) such that every
solution is below B(e). This is impossible.
Barrier 16.1 (No computable cardinality-to-cutoff operator). There is no total computable
operator which, given a code for a decidable predicate P (n) together with a valid certificate
that P has at most one solution, always returns a bound B such that
P (n)

=⇒

n < B.

In particular, no primitive-recursive operator has this property.
Proof. Let Me be the Turing machine with code e. Define the decidable predicate
Pe (n) :⇐⇒ Me halts for the first time after exactly n steps.
Bounded simulation makes Pe primitive recursive in (e, n). It has at most one solution,
and the proof of that fact is uniform: a deterministic machine cannot have two distinct
first halting times.
Apply the hypothetical operator to obtain B(e). Simulate Me for B(e) steps. If it halts,
answer yes. If it does not halt, it can never halt later, because a later first halting time
n ≥ B(e) would be a solution of Pe outside the promised cutoff. This decides the halting
problem, a contradiction.
Thus a finiteness or cardinality theorem is not enough for complete enumeration. A
height bound, search cutoff, or complete-list certificate is genuinely additional data. This
is the precise issue in generic forms of Siegel, Faltings, and Mordell–Weil enumeration.

16.2

Exact zero tests from approximate names

Barrier 16.2 (No finite-use exact zero test). There is no extensional finite-use procedure
that, from an arbitrary regular Cauchy name of a real number known only to be dyadic
rational, always returns the exact bit [x = 0].
Proof. Run the supposed procedure on a regular name for zero. Because the output is
a finite computation, it reads only rows through some horizon H. Choose a positive
dyadic δ = 2−M with M so large that a regular name for δ may output zero on every row
through H and switch to sufficiently accurate approximations to δ later. For example, take
M > H + 2; the discrepancy from zero at the early rows is below their allowed error. The
two names are indistinguishable to the procedure, so it returns the same bit, although one
value is zero and the other is not. Contradiction.

Promises about the abstract value do not repair the information interface. Saying “the

16.3

No universal primitive-recursive evaluator

The diagonal proof in theorem 6.1 blocks another common shortcut. A code for an arbitrary
primitive-recursive function is not automatically executable by a total primitive-recursive
universal semantics. Static specialization, finite query tables, or a restricted fuel-bounded
interpreter are the admissible alternatives.

16.4

Metastability does not imply a tail rate

Finite-window stability is compatible with arbitrarily late future oscillations. A uniform
conversion from every metastability bound to a Cauchy modulus would therefore supply
information not present in the premise. In applications, a metastable theorem is often
exactly what a finite consumer needs, and it should be retained as such. A limit name
requires a separate tail modulus, summable motion estimate, monotonicity argument, or
other global input.

16.5

Negative nonzeroness does not supply positive separation

The guarded reciprocal theorem shows what division needs: a rational lower bound λ. The
proposition x ̸= 0 alone gives no algorithm for finding λ from an arbitrary Cauchy name.
This is another discontinuity at zero. Accordingly, every inverse, normalization, pivot, or
branch-isolation interface lists its apartness data explicitly.

16.6

Qualitative compactness does not supply a net

A theorem that a space is compact in a strong ambient theory may have no primitiverecursive finite-net producer with a modulus usable in iPRA. The FRNF compactness
interface is conditional on such data. For boxes, simplices, finite complexes, rational
polytopes, and many explicitly presented compact spaces, the data are easy to construct.
For an arbitrary quotient or function space, they may be the main mathematical theorem.

16.7

Deep analytic and arithmetic producers

Finite contour integration, exact rational linear algebra, and bounded enumeration can
formalize the consequences of a zero-free region, exceptional-zero separation, height bound,
or covering list. They do not manufacture those inputs. In particular:
• stronger prime-number-theorem rates require correspondingly strong zero-free regions
and growth estimates;
• Siegel–Walfisz and Bombieri–Vinogradov uniformity require substantive control of
exceptional characters/zeros, not merely better bookkeeping;

• general Chebotarev needs effective field algorithms and analytic estimates with field

• general Siegel and Faltings enumeration needs an effective height producer; and

16.8

Effectivity obstacles are not independence proofs

Failure of a generic producer does not prove that no iPRA proof of a particular closed
theorem exists. A theorem may have a special argument, a nonuniform constant, or a
certificate discovered by external mathematics and then verified in iPRA. The barriers
above justify exact claim wording:
“The finite verifier and conditional implication are formalized; the required
producer is not supplied by this framework.”
They do not justify the stronger wording “the theorem is unprovable in iPRA” without
a separate proof-theoretic argument.

17.1

Finite algebra and combinatorics

Exact finite algebra is the easiest case. Encode tuples, lists, matrices, polynomials,
permutations, graphs, and finite sets by natural numbers. Operations are primitive
recursive, and identities are equations or bounded formulas. The standard recipe is:
1. choose a canonical code or a proof-relevant equality certificate;
2. define operations by fixed primitive recursion;
3. prove defining equations and congruence in Prf PRAAx;
4. Booleanize bounded side conditions;
5. prove the main invariant by QF induction on size, degree, or a loop clock; and
6. use the proof schedule to compose algebraic subroutines.
Determinants by Laplace expansion, adjugates, bounded sums/products, Bell recurrences, finite group actions, and combinatorial bijections fit directly. Symbolic polynomial
identities may be proved in a host ring and reflected through a checked object-level ring
lemma, as the repository’s ipra\_ring tactic already demonstrates.

Complex analysis and contour methods

Contours are finite polygonal or rational parametrized paths with derivative and clearance

Analytic number theory

Dirichlet polynomials, finite Euler products, summatory functions, and truncated integrals
are finite arithmetic. The difficult inputs are explicit analytic estimates. An FRNF theorem
should state them as contracts with all dependencies visible: modulus, conductor, field
discriminant, strip, height, or zero-free-region parameters. The finite compiler then:
(i) selects truncation and contour parameters;
(ii) allocates precision backward through the finite expression graph;
(iii) verifies rational/complex approximations and denominator guards;
(iv) carries error numerators by QF induction; and
(v) emits the final explicit inequality.
This architecture can strengthen reliability and reuse without pretending to improve
the underlying zero-free region.

Probability

Finite rational probability laws are exact tables. Expectations, moments, convolutions,

Topology

The Finitary Realizer Normal Form compilation theorem

We now collect the preceding constructions into one theorem schema. The statement is
metatheoretic: it takes fixed object syntax and local embedded derivations and returns a
new embedded derivation. It does not assert that iPRA internally quantifies over all such
graphs.

18.1

FRNF graph

Definition 18.1 (Certified FRNF graph). A certified FRNF graph consists of the following
finite data.
G1. A finite acyclic directed graph with a designated final node and fixed topological
order.
G2. For each input, a finite-observation presentation: exact data, regular names, finite
clouds, finite nets, or certified setoids.
G3. For every edge, primitive-recursive computation and justification horizon transformers with an embedded proof that read demand is bounded by justification
demand.
G4. For every node, fixed primitive-recursive syntax and an object contract formula.
G5. Each computational node is one of: exact transducer, bounded search, clocked
loop, finite relational viability pass, stable observer, gap collapse, boundary node,
or finalizer. Compound domain routines are expanded into these forms.
G6. Every clocked loop has a bounded/QF invariant and embedded base, step, and
finish derivations.
G7. Every bounded formula occurring in a local invariant has a characteristic term and
the embedded Booleanization derivations of theorem 4.2.
G8. Every node has an embedded local derivation of its contract from its declared
predecessor contracts and permanent boundary formulas.
G9. Every relational output consumed deterministically is either internal to a finite
viability computation or followed by an embedded stability/gap derivation.
G10. Every non-finite mathematical input—modulus, height bound, separation, finite
net, zero-free estimate, covering list—is either produced by a preceding certified
node or appears explicitly among the boundary formulas.
The definition is intentionally syntactic. Host-semantic theorems may accompany the
graph, but they are not among the premises needed to construct the object proof.

(i) primitive-recursive terms coding the least dual-horizon demand closure of (G, d);

1. Static specialization. Replace every externally fixed routine by concrete primitiverecursive syntax and its defining equations. If a routine was supplied as a finite table or

become bounded-product equations. Thus all loop invariants are quantifier-free.

18.3

Relative expressiveness

The theorem is not a completeness theorem for all constructive mathematics. It is a
normal-form theorem for proofs already equipped with primitive-recursive finite realizers
and quantitative interfaces. Within that class, the node vocabulary is broad: every fixed
primitive recursion is a clocked loop; every bounded existential is least search; every finite
nondeterministic process is a layered relation; every finite DAG composes by the schedule.
Thus the remaining expressiveness questions are mainly about whether the mathematics
supplies finite bounds and stable representations.

18.4

Conservativity of the compiler

The compiler adds no axioms to iPRA. Its generic Lean definitions live in the metatheory
and build terms of the inductive relation Prf PRAAx. Trust rests on the Lean kernel, the
definition of Prf, and the audited local constructors. A future executable compiler may be
large or use sophisticated metaprogramming without changing the object-theory theorem,
provided the generated proof term checks.

18.5

The main engineering gap

The logical schedule and QF loop combinators are short. The substantial remaining
implementation is a reusable object arithmetic layer for:
• generic bounded-formula reification and substitution;
• encoded arrays and finite folds;
• graph demand tables;
• viability masks and path extraction; and
• rational error budgets and metric inequalities.
The checked IPRADerivations library already contains most low-level ingredients. The
task is integration and abstraction, not a new foundational theory.

20.3

Formula generation versus opaque declarations

The roadmap file in this package uses opaque formulas to make endpoints unambiguous.
The completed implementation must replace every opaque endpoint with an explicit Fm
expression assembled from the actual PR symbols. Otherwise a proof of the opaque formula
would not establish the intended theorem.
A useful discipline is to define each object formula immediately next to a human prettyprinter and a host evaluation theorem. The pretty-printer assists review; the host theorem
assists debugging; only the explicit object formula and its embedded proof establish the
iPRA result.

Given a fixed two-stage transducer with distinct computation and justification

one clocked loop, and return a closed Prf PRAAx derivation; then export it

Approximate minimum on a rational interval

Let f : [−1, 1] → R be represented by a sampler with evaluation error η(k) and a Lipschitz
bound L. Use the dyadic net
Nk = {−1 + i2−k : 0 ≤ i ≤ 2k+1 },
with radius δ(k) = 2−k and modulus ω(k) = L2−k . Evaluate every point at error η(k),
choose the least sample minimum, and apply theorem 14.1. The selected point pk satisfies
f (pk ) ≤ f (x) + L2−k + 2η(k) for every x ∈ [−1, 1].
For f (x) = (x − 1/3)2 , the exact reference implementation on the quarter-grid chooses
1/4. An object proof need not mention the real infimum. It proves the finite comparison
against any rational input carrying a nearest-grid witness; the semantic corollary follows
from the sampler interpretation.
If one additionally proves strong convexity, the approximate minimizer clouds have a
shrinking diameter, and theorem 12.2 yields a coherent name for the unique minimizer.
Without uniqueness, only the value and approximate cloud are canonical.

21.3

Polynomial roots through a collision

Consider a monic polynomial family Pt (z) and a finite root routine that returns rational
disks covering all complex roots with multiplicity. At a parameter where two roots collide,
no continuous exact ordering of the individual roots is expected. The FRNF presentation
stores:
• the disk cloud and multiplicity/count certificates;
• compatibility edges between overlapping refined disks;
• a movement bound between refinements; and
• coefficient reconstruction bounds for the product of the disk centers.
Backward viability chooses finite compatible refinements. The elementary symmetric
functions of any valid root multiset are stable because they reconstruct the coefficients.
Thus the theorem about the factorization identity is exact even though internal labels are
not. If a disk is isolated from all others by a rational gap, theorem 12.3 recovers an exact
branch label for that isolated cluster.
The lesson is that collision is not a failure of the root theorem. It is a failure of an
overstrong output type.

21.4

Variable-degree deflation with dual horizons

Suppose a fixed coefficient evaluator gives approximations to a monic polynomial of
numerical degree n. A one-root routine at output precision t reads coefficient rows through
U (n, M, t). Deflating by the approximate root shifts coefficient precision and the residual
proof requires comparisons through a larger bound V (n, M, t). Repeating the routine n
times creates a changing parameter chain.
Compile it as follows.
1. Define the stage state: remaining degree, normalized coefficient table, roots already
found, and error budget.

2. Compute all later verification demands backward from the final coefficient identity.
At each stage propagate V , not only U .
3. Materialize the original coefficient name only through the resulting maximum.
4. Run deflation forward for exactly n stages.
5. Prove by QF induction a telescoping coefficient identity and accumulated error bound.
The degree is ordinary data, so this is one primitive recursion uniform in n. The
coefficient evaluator is statically fixed, respecting the no-universal-evaluator barrier.

21.5

Stable simplicial maps

Let a represented map between compact spaces induce, at finite observation levels, a carrier
cloud: each source vertex maps to a nonempty set of target vertices contained in one
simplex. Any selection gives a simplicial map. Any two selections are contiguous, so the
explicit prism operator supplies a chain homotopy. Therefore the induced homology map
is independent of tie-breaking.
This is a stable observer in algebraic form. The internal vertex choices are relational;
the homology map is exact and branch-independent. A proof requires only finite complexes,
bounded matrix operations over a finite ring, the carrier certificate, and the prism identity.
No exact continuous selector is needed.

21.6

Height bound implies complete Diophantine list

Let Fp (⃗x) = 0 be a polynomial family and suppose a boundary formula supplies
Fp (⃗x) = 0

=⇒

H(⃗x) ≤ B(p).

Enumerate every canonical rational/integer tuple of height at most B(p), evaluate Fp
exactly, and retain the zeros. Soundness is immediate from exact evaluation. Completeness
follows by the height formula and coverage of the enumeration. All loops are bounded by a
primitive-recursive function of p and B(p).
The resulting theorem is
HeightBound(p, B(p)) −→ CompleteZeroList(p, L(p)).
For a special curve family, a descent theorem may provide the height bound and close the
schedule. For general Siegel or Faltings, the finite compiler is still complete as a conditional
result, while the deep producer remains visible.

23

Conclusion and research program

The recurring difficulty in embedding mathematics into iPRA is not the finiteness of the
final calculation. It is the disciplined exposure of all information that the calculation and
its proof consume. The Finitary Realizer Normal Form makes this exposure explicit.
A proof in FRNF has a static finite program graph; distinct computation and justification horizons; a reverse closure pass; finite tables rather than hidden higher-type
oracles; Booleanized bounded conditions; clocked loops with QF invariants; relational
witnesses rather than unjustified selectors; stable observers and gap certificates; and visible
mathematical producer boundaries. The final logical step is a proof schedule whose output
is an actual embedded derivation.
This architecture resolves the broad family of formal difficulties caused by precisiondependent induction, adaptive finite use, branch ambiguity, finite compactness, and
host/object confusion. It also sharpens the negative conclusions. There is no universal primitive-recursive evaluator, no generic cardinality-to-cutoff operator, and no finite-use
exact zero test for arbitrary approximate names. These are not reasons to abandon the
program. They tell us which representations and theorem statements are mathematically
honest.
The immediate research program is concrete.
1. Complete and kernel-check bounded Booleanization and encoded finite tables in the
existing IPRADerivations library.
2. Kernel-check dual-horizon demand closure and backward viability.
3. Migrate one analytic and one relational theorem end to end, producing Prf PRAAx
and native-core endpoints.
4. Build a small code generator that emits formulas, local theorem stubs, proof schedules,
and status manifests for a static graph.
5. Develop a library of producer interfaces—finite nets, apartness, height bounds, root
clouds, simplicial carriers—with exact conditional endpoints.
Research package, 16 November 2026

Finitary Realizer Normal Form for iPRA

57

6. Revisit the unresolved packets only after their missing producer is isolated in this
form; then mathematical effort can focus on the genuine estimate rather than on
repeated encoding infrastructure.
The strongest expected payoff is cumulative. Once a component has fixed syntax,
explicit horizons, and an embedded contract, every later theorem can reuse it by cut. The
growing body of iPRA mathematics then becomes not a collection of isolated proof outlines,
but a proof-producing library of certified finitary interfaces.

Checklist for converting a proof to FRNF
1. State the exact object theorem. Write the intended closed or conditional
first-order formula, including every modulus, bound, gap, and presentation validity
hypothesis.
2. Classify outputs. Is each output exact, an approximate name, a finite cloud, a
stable observable, or an exact label under separation? Do not use one type for all
of them.
3. Fix program syntax. Replace arbitrary program parameters by static specialization, finite tables, or a restricted interpreter with fuel.
Research package, 16 November 2026

Finitary Realizer Normal Form for iPRA

58

4. List primitive-recursive symbols. Give arities, recurrences, defining equations,
and required arithmetic lemmas.
5. Derive dual horizons. For every input edge, compute both read and justification
bounds. Apply prefix closure.
6. Build the demand graph. Topologically order components and propagate final
demands backward. Check shared dependencies and changing parameters.
7. Materialize finite observations. Replace global name properties by the finite
row instances used within the justification closure.
8. Booleanize bounded assertions. Generate characteristic terms and prove the
truth equivalences and substitution laws.
9. Clock adaptive routines. Supply fuel or a decreasing rank. Freeze terminal
states.
10. Write QF invariants. Include all accumulator equations, range bounds, validity
bits, and error budgets needed by the successor proof.
11. Keep ambiguity relational. Define candidate validity and compatibility; use
backward viability. Add stability or a gap theorem before deterministic exposure.
12. Separate producers from verifiers. Mark finite nets, height bounds, apartness,
zero-free regions, and covering lists as generated nodes or boundary formulas.
13. Construct local object proofs. Each theorem must conclude Prf PRAAx; a host
semantic theorem is not a substitute.
14. Compose by schedule. Declare exact dependencies and apply simultaneous cut
in topological order.
15. Audit. Build in the pinned toolchain, search for placeholders, print axioms, run
executable tests, and compare the final formula with the human statement.
16. Export. Apply the ordinary-to-native transfer only after the ordinary object proof
is complete.
