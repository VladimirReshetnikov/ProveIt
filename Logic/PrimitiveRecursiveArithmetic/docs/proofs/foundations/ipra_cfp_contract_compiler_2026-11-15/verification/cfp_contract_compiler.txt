Certified Finitary Presentations and a Contract-DAG
Compiler
A compositional framework for embedding mathematics into intuitionistic primitive recursive
arithmetic
Research report and Lean formalization blueprint
15 November 2026

Abstract
The ProveIt repository contains a kernel-checked presentation of intuitionistic primitive recursive
arithmetic and a large collection of research packets that recast classical mathematics in finite,
quantitative form. The packets also expose recurring failures: induction hypotheses that quantify
over unbounded precision, discontinuous exact choices from Cauchy data, compactness arguments
without finite nets, finiteness statements without search cutoffs, and ambient Lean proofs that do
not yet produce object-language derivations.
This report develops a common framework, called a certified finitary presentation (CFP), and
extends the repository’s existing CFP work by giving a contract-DAG calculus with reverse precision
propagation. A finite acyclic network of primitive-recursive nodes, each equipped with a quantifierfree local contract, compiles into one bounded trace, one quantifier-free invariant, and therefore
one reusable PRAAx proof obligation. The report proves the finite-trace theorem, the contract-DAG
composition theorem, finite-horizon coherent selection for relational outputs, exact branch collapse
under a positive gap, backward precision budgeting, bounded enumeration from height certificates,
and the separation between cardinality and height bounds.
The framework does not claim general effective Faltings, Siegel, Bombieri–Vinogradov, or
a uniform exact Puiseux selector. It identifies the missing producer in each case and supplies
the verifier, composition law, and formalization route around it. A complete worked benchmark
constructs the unique root of y 3 + y = x for rational 0 ≤ x ≤ 1 by an exact bisection certificate.
Lean files in the archive give all central definitions, a semantic prototype, and a dependency-ordered
blueprint for constructing Prf PRAAx terms using the repository’s actual PR, PTm, PRA.qfInd, and
pra_iff_native interfaces.

1.1

The checked core and the research layer

In particular, no packet currently supplies a completed derivation of its main mathematical theorem
in the object type
Γ ⊢ [PRAAx] φ.
This report takes that distinction as a design constraint, not as a clerical detail.
The object language actually available in the repository is unusually useful for this project. The
inductive type PR k contains zero, successor, projections, composition, and primitive recursion. Terms
PTm n are applications of those symbols to variables. The axiom family PRAAx contains the defining
equations, successor separation and injectivity, and induction for quantifier-free formulas. The theorem
PRA.qfInd is therefore the principal internal engine. The theorem pra_iff_native transports an
already completed PRAAx derivation to the tiny native calculus; it is not a device for turning an
arbitrary semantic Lean proof into such a derivation.

1.2

What “embedding mathematics in iPRA” means

A mathematically serious claim of an iPRA proof should contain four separate objects.
(1) A finite numerical presentation of the input, including every modulus, separation constant, height
cutoff, chart, or cover used by the proof.
(2) Fixed primitive-recursive algorithms for the finite computations. “Fixed” matters: a universal
evaluator taking an arbitrary PR program code as data is not itself primitive recursive.
(3) A quantifier-free invariant and an object-language derivation from PRAAx. A native theorem
about Lean’s Nat, even a constructive one, is only a semantic lemma until this derivation is built.
(4) An external interpretation theorem connecting the numerical presentation to the familiar mathematical statement.
The order is important. One proves the arithmetic certificate first and transports it through the
repository’s bi-interpretation only afterward. This prevents three common category errors: treating
type checking of a goal as a proof, treating a finite test run as a universal theorem, and treating a
classical existence theorem as if it supplied a primitive-recursive witness.

1.4

Contribution of this report

The current repository already contains several compatible frameworks: certificate-and-modulus
interfaces, finite observations, evidence-indexed outputs, uniform certificates, and the newly placed
Certified Finitary Presentation report. The present contribution is an integration layer.
• A contract-DAG packages a whole proof as a fixed finite acyclic network of local certified transducers.
• A reverse pass computes all precision and observation demands.
• A forward bounded trace evaluates the nodes.
• One quantifier-free trace invariant composes the local proof objects.
• Relational outputs are handled by a finite-horizon compatibility theorem rather than by hidden
choice.
• A packet-conversion protocol identifies, for every theorem, the exact missing producer and the
exact reusable verifier.
The result is deliberately modular. It does not make the general Faltings or Siegel theorem effective,
does not manufacture the missing constants in ineffective prime-distribution estimates, and does not

Numerical encodings and bounded formulas

Everything in iPRA ultimately lives in one numerical sort. This section fixes explicit encodings so
that later statements do not hide higher-type or set-theoretic data.

2.1

Pairs, finite sequences, and tables

A convenient primitive-recursive pairing is
⟨a, b⟩ = 2a (2b + 1) − 1.
For n = ⟨a, b⟩, the first projection is the exponent of 2 in n + 1, and the second is
(n + 1)/2a − 1
.
2
The exponent is found by a bounded loop of length n + 1, so both projections are primitive recursive.
A finite sequence (x0 , . . . , xℓ−1 ) is coded recursively: set Lℓ = 0, set Li = ⟨xi , Li+1 ⟩ for i < ℓ, and use
⟨ℓ, L0 ⟩ as the sequence code. Length, lookup with a default value, update, append, and bounded folds
are primitive recursive. The exact pairing is not mathematically important; the availability of proved
projection equations is.
A finite table is a sequence whose indices are node numbers or query numbers. Every algorithm in
the report is first described with ordinary arrays and then understood through this code. No appeal is
made to an unbounded finite map.

2.2

Booleans and bounded quantifiers

Booleans are represented by 0, 1. We totalize every Boolean operation:
not(b) = 1 − min(1, b),

b ∧ c = min(1, b) min(1, c),

b ∨ c = min(1, b + c).

For a primitive-recursive Boolean P (d, i), define
AllP (d, 0) = 1,

AllP (d, n + 1) = AllP (d, n) ∧ P (d, n),

AnyP (d, 0) = 0, AnyP (d, n + 1) = AnyP (d, n) ∨ P (d, n).
These are primitive recursions. Quantifier-free induction proves
AllP (d, n) = 1 ←→ P (d, i) = 1 for every i < n,
AnyP (d, n) = 1 ←→ P (d, i) = 1 for some i < n.
The right-hand descriptions are expository abbreviations. Inside the object theory, the bounded
quantifiers are represented by the left-hand primitive-recursive terms. Thus a bounded formula is
compiled to a quantifier-free equality.
Lemma 2.1 (Bounded witness extraction). Let P (d, i) ∈ {0, 1} and B(d) be primitive recursive.
There is a primitive recursive function firstP (d) ≤ B(d) such that
firstP (d) < B(d) ⇐⇒ AnyP (d, B(d)) = 1,
and, whenever firstP (d) < B(d), P (d, firstP (d)) = 1.

2.3

Integers and rationals

An integer is represented by a pair (p, m) with value p − m. We do not require a canonical sign
representation. Addition and multiplication are implemented by
(p, m) + (q, n) = (p + q, m + n),

(p, m)(q, n) = (pq + mn, pn + mq).

Equality is p + n = m + q, and order is a natural-number cross inequality.
A rational is a triple (p, m, d), representing
p−m
.
d+1
The positive denominator avoids partiality. Equality and order are reduced to integer cross-products.
All field operations are totalized: a reciprocal routine returns a default value when the numerator is
zero, while a separate Boolean domain guard records that the intended input is apart from zero. This
“operation plus guard” discipline is essential. A partial operation hidden in the metalanguage cannot
be used as a PR symbol.
Dyadic errors are represented without division by the relation
|r| ≤ 2−k

⇐⇒

2k |num(r)| ≤ den(r).

Every inequality in the later error calculus can therefore be checked using natural addition, multiplication, exponentiation, and order.

2.4

Primitive-recursive formulas

For a fixed primitive-recursive code f : PR k, an application to terms is a PTm. Atomic assertions
are equalities of such terms. Boolean predicates are represented by a term that is proved to take
values in {0, 1}; the assertion that the predicate holds is equality to 1. Conjunction, disjunction, and
implication are formulas in the intuitionistic natural-deduction layer. A loop invariant is designed so
that its matrix is quantifier-free, allowing direct use of PRA.qfInd.
A useful engineering rule is:
Every phrase “for all entries of this finite object” should have a named Boolean fold, a
defining recursion, and a correctness lemma.
This rule turns many apparently bounded-quantifier-heavy proofs into ordinary equational induction.

3

Certified finitary presentations

3.1

Request-indexed observations

The central representation is not an completed infinite object but the finite information needed to
answer one finite request.
Definition 3.1 (Certified finitary presentation). A certified finitary presentation X consists of fixed
primitive-recursive data:
WFX (x),

BX (x, q),

ObsX (x, q, o),

Ref X (x, q, o, q ′ , o′ ),

where x is an input code, q is a request, and o ≤ BX (x, q) is a finite observation. The intended
contracts are:
(i) WFX (x) = 1 implies that every requested observation can be constructed or found within the
stated bound;
(ii) ObsX (x, q, o) = 1 is an exact, decidable verifier;
(iii) when q ′ refines q, Ref X certifies compatibility of the two observations.
The coverage and refinement properties must be accompanied by object-language proofs, not merely
asserted in the semantic interpretation.
The request may be a precision, a finite list of test functions, a grid scale, a degree bound, a
desired residual, or a tuple of these. The observation may be a rational interval, a finite root cover, a
truncated series, a path in a finite graph, a list of points below a height, or a proof certificate.

3.2

Three output modes

Definition 3.2 (Deterministic presentation). A deterministic presentation has a primitive-recursive
constructor aX (x, q) and proves
WFX (x) = 1 =⇒ ObsX (x, q, aX (x, q)) = 1.
Definition 3.3 (Finite relational presentation). A relational presentation returns a finite coded list
CX (x, q). It proves nonemptiness, verifies every member, and states the coverage property of the whole
list. It does not assert that a distinguished exact member can be chosen continuously.
Definition 3.4 (Evidence-indexed presentation). An evidence-indexed presentation accepts an additional finite certificate e. A Boolean guard Guard(x, e) is verified first; stronger operations may
then be used. Typical evidence is a lower bound δ > 0 on a denominator, derivative, discriminant,
singular-value gap, or distance from a branch boundary.
These modes should not be collapsed. An approximate finite root set can be uniform even when an
exact root branch is not. A projective eigenline can be uniform even when a signed unit eigenvector is
not. A bounded enumeration can be complete relative to a height certificate even when no uniform
producer of that certificate is known.

3.4

Higher-type data without a universal evaluator

A theorem may be uniform over a fixed evaluator schema F (p, n, k), where p is ordinary numerical
input. This gives a family of PR functions while staying within one PR term. What is unavailable is a
total primitive-recursive function U (e, x) evaluating every unary primitive-recursive program code e.
Proposition 3.5 (No universal PR evaluator). There is no primitive-recursive U : N2 → N such that
for every unary primitive-recursive f there is e with U (e, x) = f (x) for all x.
Proof. If such U existed, then g(x) = U (x, x) + 1 would be primitive recursive. Choose e coding g.
Then g(e) = U (e, e) + 1 = g(e) + 1, a contradiction.
Thus a packet may quantify over numerical parameters of a fixed algorithm, finite tables, or
bounded traces. It may not silently turn arbitrary source code into input for a universal unclocked
interpreter. A clocked evaluator is harmless: evaluation for exactly t steps is primitive recursive and
its finite trace can be verified.

Local certified transducers

Definition 4.1 (Contract node). A contract node v has:
(a) a fixed list of parent nodes par(v);
(b) a request code rv ;

Relational outputs and finite coherent selection

Many constructive failures arise from asking for a single exact output where the mathematics supplies
only a finite family of locally valid outputs. Relational presentations make this explicit.

5.1

Finite candidate systems

Fix a requested final depth K. For each level k ≤ K, let Cand(k) be a finite coded list, and
let Compat(k, c, d) ∈ {0, 1} mean that the level-k + 1 candidate d refines the level-k candidate c.
Membership and compatibility are primitive-recursive, and all list lengths have primitive-recursive
bounds.
There are two useful hypotheses.
Strong seriality.
Every candidate in Cand(k) has a compatible successor in Cand(k + 1).
Rooted viability.
At least one candidate in Cand(0) extends through level K, but dead-end candidates may also
be present.
Strong seriality permits greedy forward selection. Rooted viability is strictly more general and is
handled by backward dynamic programming.

5.3

Compatibility as the semantic output

Suppose a mathematical object x is represented at level k by a finite family of regions R(k, c). A
candidate list is correct when the union of those regions covers every object satisfying the input
contract. A compatibility witness says that R(k + 1, d) ⊆ R(k, c), or more generally that the two
observations describe the same object to the stated tolerances.
This is often the right final theorem. Examples include:
• finite disks covering all polynomial roots, with multiplicity data;
• the two unit quaternions q, −q representing one rotation;
• a projective line rather than a signed unit eigenvector;
• a finite set of local analytic charts;
• several nearly minimizing grid cells rather than an exact minimizer.
The framework never discards the relation and silently picks a member. A later consumer either
accepts relational input, or supplies enough evidence to collapse the relation.

Definition 5.3 (Isolation certificate). At level k, an isolation certificate for a candidate c consists of
a positive rational δ and a proof that:
(i) the region R(k, c) contains an intended solution;
(ii) every distinct candidate region is at distance at least δ;
(iii) future approximation error is less than δ/3.

7.1

Overlapping branches

Exact comparison of a represented real with zero is generally discontinuous. A robust program replaces
a partition by an overlap. Suppose a rational approximation a satisfies |x − a| ≤ η. Define:
L(a) : a ≤ η,

R(a) : a ≥ −η.

At least one branch holds, and both may hold in the overlap [−η, η]. A node contract must prove that
either branch gives an acceptable output when its guard holds. The constructor may choose the first
passing guard by bounded Boolean search.
Lemma 7.1 (Overlapping-branch soundness). If |x − a| ≤ η, L(a) implies x ≤ 2η, and R(a) implies
x ≥ −2η. Moreover L(a) ∨ R(a) is decidable and always true.
Proof. The first two claims are triangle inequalities. For coverage, if a ≤ η then L holds. Otherwise
the decidable rational inequality gives a > η ≥ −η, so R holds. This is a case split on an exact rational
Boolean.
This suffices whenever the two branch outputs agree up to the allowed error on the overlap. It is
the constructive analogue of a stable conditional.

8.1

Complete bounded enumeration

Let P (d, x) ∈ {0, 1} be a primitive-recursive predicate, and let H(d) be a primitive-recursive bound.
Construction 8.1 (Bounded enumerator). Scan x = 0, . . . , H(d). Append x exactly when P (d, x) = 1.
Call the resulting coded list L(d, H).
Theorem 8.2 (Bounded enumeration). The list L(d, H) is sound: every listed member satisfies P .
It is complete below H: if x ≤ H(d) and P (d, x) = 1, then x occurs in the list. Both claims have

strictly increasing order. “Contains exactly” is represented by two Boolean folds: every listed entry is
below t and satisfies P , and for every x < t, P (d, x) = 1 implies a bounded membership test succeeds.

invariant by a decidable test of P (d, t).

8.4

Producer–verifier factorization

For Diophantine and analytic number-theoretic packets, every claimed result should be split into two
modules.
Certificate producer.
The deep mathematical theorem computes a height, cover, zero-free region, exceptional modulus,
or numerical constant.
Certificate verifier.
Finite arithmetic checks the certificate and derives the desired bounded conclusion.
The verifier is often readily formalizable in iPRA even when the producer is unknown, ineffective, or
stronger than current mathematics. This split is a positive result: it preserves all finitary consequences
of a future producer and prevents the packet from disguising the missing theorem as an implementation
detail.
For general Faltings and Siegel targets, the framework supplies the exact bounded enumerator
and the equivalence between height bounds and complete lists. It does not supply the general height
producer. For prime distribution, a certificate may contain explicit constants and verified finite
exceptional cases; the verifier proves the stated range once these are present, but does not make an

10.1

Algebraic equations and Puiseux expansions

For a polynomial with exact rational or exact algebraic coefficient codes, finite algebraic operations,

The repair is one of:
(a) exact algebraic coefficient presentations with decidable zero and certified splitting;
(b) a finite family of truncated approximate branches with residual and coverage bounds;
(c) a theorem conditional on a simple-root or discriminant gap.
The contract-DAG compiler handles the coefficient recursion once the branch guard is legitimate; it
does not create the missing exact equality oracle.

10.2

Euler–Rodrigues, eigenvectors, and projective geometry

Rodrigues’ formula for a supplied axis and angle is a polynomial/trigonometric error-contract problem.
Exact Euler-axis selection for an arbitrary represented rotation is discontinuous at the identity and
can encode LLPO. The stable outputs are:
• a unit quaternion modulo q ∼ −q;
• a projective axis or finite approximate axis set;
• an exact axis under a supplied lower bound separating the rotation from the identity;
• rational exact axes for rational proper orthogonal matrices.

Certified finitary presentations in iPRA

22

The same projective-first discipline applies to eigenvectors. Use a projector, kernel certificate, or finite
set of charts; normalize only under a nonzero coordinate or singular-value gap.
Many Euclidean and projective geometry theorems become polynomial identities after homogeneous
coordinates are introduced. Denominators should not be cancelled silently. Either clear them and
retain nondegeneracy guards, or work entirely with cross-products and determinants. A finite incidence
certificate then fits directly into the contract calculus.

10.3

Analysis and special functions

A valid analysis node has:
approximant,

cutoff,

tail/error verifier,

precision demand.

For a series, the producer supplies N (k, d) and a rational proof that the tail after N is at most 2−k .
For an integral, it supplies a mesh and local oscillation modulus. For analytic continuation, it supplies
a finite chain of overlapping disks and derivative bounds. The compiler adds the budgets and verifies
the finite chain.
This resolves a common formal difficulty in trigonometric, Gamma, zeta, and residue packets: one
never inducts on a completed real identity. One proves a rational inequality at arbitrary requested
precision. It does not, by itself, prove a missing global zero-free region or manufacture an effective
constant from an ineffective theorem.

10.4

Probability

Finite probability laws are rational mass arrays with a Boolean check that masses are nonnegative
and sum to one. Convolution, moments, and characteristic-function samples are exact finite sums. A
constructive CLT packet should separate:
(i) the exact finite convolution engine;
(ii) moment and variance guards;
(iii) a finite-grid comparison or characteristic-function approximation;
(iv) the analytic smoothing and tail estimates with explicit constants.
The first three are generic contract nodes. The fourth is the substantive analytic producer.

10.5

Topology

For Jordan-curve and invariance-of-dimension arguments, use finite grids, rational boxes, adjacency
graphs, parity or degree certificates, and explicit separation margins. A finite grid calculation at a few
scales is evidence, not a proof for every scale. The reusable theorem must show that the quantifier-free
grid invariant is preserved under refinement.
Degenerate boundary cases should be handled by overlap: several adjacent cells may be valid. A
positive distance from the boundary collapses the finite relation to one cell. This is the topological
instance of the same branching theorem used for roots and axes.

Diophantine geometry

Runge-type arguments often do produce explicit polynomial identities and height inequalities. These
are ideal evidence-indexed nodes: verify the identity, derive the bound, then enumerate. The general
Siegel and Faltings packets correctly identify the missing general height producer. The framework
contributes:
• exact encodings of rational and integral points;
• complete bounded enumeration;
• conversion between a verified bound and a complete list;
• finite-cover and finite-algebra verifiers;
• a precise interface for any future height or covering theorem.
A cardinality theorem, even a strong one, cannot be plugged into the height input slot.

10.7

Analytic number theory

Prime-distribution statements must expose all dependencies: modulus range, exceptional characters,
zero-free constants, conductor cutoff, density estimate, and finite small cases. A certificate verifier can
check the finite exceptional list and derive a claimed numerical range from explicit inequalities. The
quantifier order is crucial:
∃C ∀x ≥ X(C) Φ(C, x)
is useful only when C is produced or supplied. A proof of mere existence in a stronger classical theory
does not automatically yield a PR constant in iPRA. The framework therefore records “analytic
constant producer” as a first-class dependency rather than burying it in a phrase such as “take x
sufficiently large.”

Reflection versus theorem generation

There are two complementary strategies.
Concrete certificate reflection. For one closed input and one requested precision, a small verified
checker can reduce the certificate to computation. A checker soundness theorem then converts successful
evaluation into a proof.
Uniform theorem generation. For all inputs, finite computation is not enough. The generated
proof must contain the base case, step case, and quantifier-free induction. A meta-level compiler may
construct these proof terms from a graph descriptor, but the resulting terms are checked by Lean’s
kernel against the PRAAx rules.
The second strategy is the long-term goal. It avoids trusting a large tactic: the compiler may be
untrusted because it emits explicit Prf objects.

The Lean sources supplied here are a detailed blueprint and semantic prototype. Lean 4.32.0 was not

A conversion workflow for existing proof packets

The repository’s packets differ greatly in maturity. The following workflow turns each into a comparable,
auditable artifact.

12.1

Step 1: state the constructive theorem

Replace a classical slogan by an explicit input/output contract. State: the numerical input code,
well-formedness test, request, output relation, error metric, and every extra evidence item. Separate
unconditional approximate output from gap-conditioned exact output.

12.2

Step 2: classify every dependency

Each dependency receives one of five labels:
PR
LOCAL
CERT
PRODUCER
BARRIER

fixed primitive-recursive computation,
proved finite arithmetic contract,
supplied finite certificate with verifier,
theorem that constructs such a certificate,
interface ruled out or known to require stronger data.

This prevents a missing producer from being mistaken for a coding problem.

12.3

Step 3: build the contract graph

Make each substantive lemma a node. Edges record both mathematical dependence and precision
demand. Common nodes—rational arithmetic, polynomial evaluation, finite sums, bounded search,
interval refinement, finite nets—should point to shared libraries rather than being copied.

Certified finitary presentations in iPRA

12.4

27

Step 4: totalize operations

Every operation must be total on all number codes. Division, normalization, chart inversion, and array
access return a harmless default outside their domain. A Boolean guard is carried in the invariant and
proves that the default branch is never used in a valid run.

12.5

Step 5: compute reverse demands

Starting from the theorem’s requested output precision, compute every upstream precision, grid scale,
cutoff, and iteration count. Record these functions explicitly. Phrases such as “take N large enough”
are not accepted as a contract.

12.6

Step 6: isolate discontinuities

For every exact branch ask:
(a) Can the output be quotient-invariant or relational?
(b) Can overlapping guards make the approximate theorem uniform?
(c) Which positive gap would make the exact branch decidable?
(d) Is the requested selector contradicted by a known computability or constructive-logic reduction?

12.7

Step 7: define the finite trace invariant

The invariant must mention only: loop counters, coded states, Boolean verifiers, bounds, and finite
folds. If it contains “for every precision” or quantification over a function, the proof has not yet been
compiled to the correct level.

12.8

Step 8: prove semantic algorithms

Implement exact reference code and ordinary Lean definitions. Test malformed inputs and boundary
cases. These artifacts discover mistakes, but their status is explicitly “semantic”, not “embedded”.

12.9

Step 9: construct object proofs

Translate each fixed algorithm to PR; prove defining equations; construct local Prf PRAAx contracts;
use the generic trace theorem. Record the remaining sorry count and axiom audit. A file containing
only proposition definitions belongs in the “targets” category.

12.10

Step 10: transport and interpret

After the PRAAx proof exists, transport it to the native core if desired. Then prove an external
interpretation theorem connecting the codes to the ordinary theorem. This last theorem may use a
richer Lean mathematics library without changing what was proved internally.

12.11

Recommended machine-readable status

Every packet should contain a ledger with fields:

a barrier explaining why the stronger interface requires additional data.

13.5

Conclusion

The right general framework for mathematics in iPRA is not a library of completed infinite objects.
It is a calculus of finite observations, explicit demands, guarded operations, relational outputs, and
bounded proof traces. The contract-DAG theorem gives these ingredients a compositional form. It
makes successful packet proofs reusable and failed packet proofs diagnosable: every gap appears as a
missing producer, missing verifier, missing quantitative margin, or impossible selector. That is enough
to move from isolated outlines toward a genuine formal library.

Reverse demands

For topologically numbered nodes:
req = external_requests[:]
for v in reversed(range(number_of_nodes)):
for u, demand in parents[v]:

In a formal packet, the graph and demand functions are fixed data. The Python function accepts

Backward viability

viable[K] = set(candidates[K])
for k in reversed(range(K)):

c for c in candidates[k]
if any(compat(k, c, d) and d in viable[k + 1]

each set by a Boolean table bounded by the candidate-list length.
