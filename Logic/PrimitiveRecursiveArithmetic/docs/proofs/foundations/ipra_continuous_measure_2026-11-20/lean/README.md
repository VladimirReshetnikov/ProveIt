# Checked finite measure kernel and completion interfaces

The project builds with **Lean 4.32.0**, using only its `Std` and `Init`
libraries. It contains 58 named proved theorems and two additional definitions
whose quantitative contract fields are proved. `Audit.lean` reports the axiom
dependencies of all of them, and `Examples.lean` checks four exact-rational
instances, including a counterexample to the older Vitali proof step.

These are **host Lean theorems**. They do not construct new proof values of
type `Prf PRAAx`. The ordinary iPRA translation is a separate task, explained
in the report. The audit uses the standard Lean axioms `propext`,
`Classical.choice`, and `Quot.sound`; there are no admitted proofs or new
correctness axioms. In particular, the entire development should not be
described as an axiom-free or choice-free Lean formalization of analysis.

## Modules and exact scope

| Module | Checked mathematical content |
|---|---|
| `ContinuousMeasure/FiniteMeasure.lean` | Variable-length rational sums, exact Fubini exchange, positivity, monotonicity, weighted expectation error, probability nonexpansiveness, and simultaneous perturbation of samples and mass vectors. |
| `ContinuousMeasure/Truncation.lean` | Rational clipping, nonexpansiveness, the continuous tail identity, tail nonexpansiveness, the scalar and finite weighted Vitali inequalities, and a three-term precision budget. |
| `ContinuousMeasure/Presentations.lean` | Actual finite probability arrays and refinement maps, exact preservation of integral/L1 distance/bounded measure distance/clipping tails under certified refinement, finite L1 pseudometric laws, and fully typed tower/name/action interfaces. |
| `ContinuousMeasure/ActionCompletion.lean` | An explicit gain-dependent sampling schedule, a construction of regular L1 output names, preservation of the same-name condition, and composition of dense actions with product gain. |
| `ContinuousMeasure/VitaliBlueprint.lean` | Typechecked definitions of the rho-Cauchy input, uniform-integrability data, bounded binary-ceiling search, the explicit output sample program, and its regularity/convergence/inherited-tail goals. These goals are not asserted as theorems. |

Finite sums and elementary probability identities are reusable mathematics,
already present in stronger object-iPRA form in the inspected ProveIt
`IPRADerivations.Probability` library. Their standalone implementation here
keeps the new clipping and represented-space development reproducible without
downloading Mathlib or an entire repository. No novelty claim is made for
those elementary facts.

The main checked estimate is

```text
integral |f-g| <= integral tail_K(f) + integral tail_K(g)
                 + 2*K * integral min(1, |f-g|),     K >= 1.
```

Here `tail K x = abs(x - clip K x) = max(abs(x)-K,0)`. This estimate uses
continuous Lipschitz tests; it does not require deciding an event involving
an arbitrary represented real number.

All finite row lengths are numerical parameters of the theorems. A theorem
for `n` is not generated by externally unrolling a separate proof for each
row length. The ordinary Lean induction used here is nevertheless a host
proof: the later iPRA proof must explicitly construct the denominator-cleared
quantifier-free invariant rather than appeal to Lean induction directly.

## Presentation details and remaining targets

`FiniteProbability` stores an `Array Rat` and its nonnegativity and total-mass
proofs. `Refinement` stores an `Array Nat` parent map and exact mass equations,
including zero-mass cells. `ProbabilityTower` supplies coherent refinements;
`SimpleTable` is a finite array at a selected level. All comparison functions
are explicit finite sums on a common refinement. `RegularL1Name` stores a
sequence of these finite tables and the symmetric dyadic Cauchy estimate.

`UniformTailControl`, `TailControl`, and `InMeasureRate` state the exact
quantitative inputs for a completed-name Vitali theorem.
`VitaliConvergenceGoal` is a **defined target, not a proved theorem**. The
remaining work includes the completed-name assembly, equality/setoid laws on
names, probability-algebra semantic identification, and the object-iPRA
translation. The finite Vitali inequality and finite refinement identities
needed by this assembly are proved.

The stronger limit-producing version is specified in `VitaliBlueprint`:
`VitaliData` assumes only a uniformly integrable family and a rho-Cauchy rate,
`vitaliSample` implements the displayed diagonal construction, and
`VitaliLiftingGoal` states regularity and the exact convergence estimate.
It takes no integrable limit as input. `VitaliInheritedTailGoal` states the
tail bound for the constructed name. These targets are fully typed and
remain proof obligations.

`DenseAction` is an interface with an explicit gain and stability contract;
these are hypotheses that an application must discharge. The construction
`mapName` and theorem `mapName_respects` are proved from them.
`composeDenseAction` has a fully proved stability field. The implementation
uses a simple precision offset based on an integer gain bound. A binary-length
offset is faster and can replace it after proving the same scalar gain
inequality.

The host interfaces accept Lean functions on numerical codes. To obtain a
first-order iPRA instance, fix primitive-recursive programs for every stage,
refinement, sample, cutoff, rate, and action, then produce their object
contracts. The project does not postulate a total primitive-recursive
evaluator for all primitive-recursive program codes.

## Replay

With the pinned toolchain installed through Elan:

```bash
cd lean
bash replay.sh
```

With a standalone distribution:

```bash
LEAN_LAKE_BIN=/path/to/lean-4.32.0-linux/bin/lake bash replay.sh
```

The script builds the project, audits every named theorem and the two
contract-bearing constructors, and checks the four examples. The recorded
successful run is `../validation/lean_replay.log`. `../validation/lean_status.json`
records compiler identity, source hashes, theorem count, and the actual axiom
union. Build caches and downloaded toolchain binaries are excluded from the
deliverable.
