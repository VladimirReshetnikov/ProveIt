                                                    Abstract
         The ProveIt repository now contains a checked ordinary presentation of intuitionistic primi-
     tive recursive arithmetic, an extensive arithmetic library, open-sequent transport, and a large
     collection of research packets based on finite certificates, demand propagation, traces, and stable
     observations. The remaining obstacle is not a lack of high-level ideas. It is the gap between
     an abstract statement such as “store a strategy for every adversarial reply” and a concrete
     object-language term, checker, and derivation in Prf PRAAx Γ φ.
         This report develops STRIVE-iPRA, a realization layer for that gap. For each fixed bounded
     formula built from reflected primitive-recursive atoms, conjunction, disjunction, and bounded
     quantifiers, a metalevel compiler produces concrete primitive-recursive functions for its Boolean
     value, positive and negative certificate bounds, canonical signed strategy codes, and certificate
     checkers. Variable-length tables are represented by one natural number using heterogeneous
     mixed-radix notation. Positive and negative certificates are dual: a certificate chooses one child
     at nodes controlled by its side and contains a table of certificates at nodes controlled by the other
     side. We prove, constructively and by finite structural specialization, that accepted positive codes
     imply the formula, accepted negative codes imply its intuitionistic negation, and the canonical
     code for the computed side is accepted.
         The strategy compiler is embedded in a broader boundary-aware framework. Proof-local
     certificates are eliminated by existential elimination; noncanonical certificates expose only exact,
     quotient, or metric-stable observations; and a least code is named only when the public theorem
     actually requires one. Finite monotone demand closure converts cyclic precision requirements into
     a clocked schedule. Missing height bounds, moduli, separation estimates, finite-cover certificates,
     or producer theorems are not hidden: they remain exact residual formulas in an open PRAAx
     sequent. This discipline resolves many recurring formalization difficulties while making clear
     which obstacles are genuinely theorem-specific.
         The packet includes full human proofs, a tested Python reference implementation, JSON
     fixtures, a no-placeholder structural Lean candidate, and source-oriented Lean blueprints for
     the arithmetic and compiler layers. Since Lean was unavailable in the artifact runtime, no new
     kernel-checked result is claimed.

1     Repository baseline and the actual formal target
1.1    Why another abstract calculus would be a mistake
The central design decision is to use the repository’s ordinary iPRA calculus as the public interface.
In the pinned tree, primitive-recursive symbols are generated by zero, successor, projections,
composition, and primitive recursion; terms are applications of those symbols to finitely scoped
variables; and PRAAx consists of the defining equations, the successor axioms, and induction for
quantifier-free formulas. Derivability is the intuitionistic natural-deduction relation

                  Prf PRAAx Γ φ,      written in Lean as Gamma |- [PRAAx] phi.

The existing derivation library already proves substantial arithmetic in this judgment. The bridge
transports closed and open sequents to the Foundation presentation. Consequently a new framework
should compile into this judgment, not ask downstream developments to adopt another proof system.
   There are three different levels that must not be conflated.

 1. A semantic metaprogram is an ordinary Lean or Python function which evaluates a finite object
    on the host natural numbers. It is useful for generating symbols and tests, but its correctness is
    not an iPRA theorem.
 2. A proof-producing metacompiler generates a finite Lean expression whose type is a Prf PRAAx
    judgment. The generator is untrusted; the Lean kernel checks its output.
 3. An object-language universal interpreter is a primitive-recursive program inside iPRA that
    consumes a code of an arbitrary formula or proof. That is a much stronger and more cumbersome
    construction. STRIVE does not need it.

   The framework therefore specializes a fixed mathematical interface at the metalevel. If a theorem
contains seven bounded quantifier nodes, the compiler emits seven finite constructor applications.
The only object-level recursion is over numerical bounds, traces, or table lengths. This fixed-program
principle is what keeps every invariant quantifier-free.

1.3   Status separation
A recurring source of confusion in research packets is the phrase “formalizable in iPRA.” It may
mean any of the following:

• the mathematical argument is finitary;
• a host-language program has been tested;
• Lean definitions have been written but contain placeholders;
• a Lean theorem about N has been proved;
• an actual Prf PRAAx derivation has been checked;
• that derivation has additionally been exported to a second presentation.

   STRIVE records these statuses separately. The present report supplies complete human proofs
and executable finite tests. The small structural kernel is a no-placeholder source candidate. The
arithmetic and compiler modules expose all unfinished proof obligations as visible sorry milestones.
No new kernel-checked theorem is asserted.

1.4   The main unresolved engineering boundary
Earlier framework packets already explain how to use finite queries, traces, backward viability,
stable observations, and residual producer assumptions. Their most persistent unformalized step is
a phrase of the form

      At a universally controlled node, store a certificate for every response; at an existentially
      controlled node, store one successful response.

  For a paper proof this is enough. For PRAAx, four additional questions must be answered.

 1. What is the primitive-recursive bound on the whole certificate code?
 2. How is a variable-length table represented by one natural number?
 3. How does the checker recover the i-th subcertificate with equations available in the object
    theory?

 4. Which quantifier-free invariant proves that the checker has inspected all required entries?

2     The STRIVE architecture
2.1   Finite observations as the common language
Many mathematical objects are infinitary when presented extensionally: a real number has arbitrarily
accurate rational approximations, a continuous function has values at infinitely many inputs, an
algebraic branch has infinitely many compatible truncations, and a model or strategy may respond
to every possible challenge. A finite proof does not consume the entire object. It asks finitely many
questions and uses finitely many answers.
   STRIVE represents a concept by a finite observation interface. For an input parameter a, a query
q, and a certificate c, the interface contains primitive-recursive data

                           B(a, q),     C(a, q, c) ∈ {0, 1},       O(a, q, c),

where c < B(a, q) is the declared finite code range, C = 1 means that the certificate answers the
query correctly, and O is the part of the answer visible to the consumer. The producer contract is a
formula such as
                               ∀q < Q(a) ∃c < B(a, q) C(a, q, c) = 1.
A theorem-specific proof may establish this contract outright. If it cannot, the contract remains an
explicit residual hypothesis.
  This interface covers several familiar situations.

• For an exact finite object, q may be trivial and O = c.
• For a real number, q is a requested precision and O is a rational interval or approximation.
• For a root of a polynomial, c may contain a box and a local verification trace, while O is a
  symmetric polynomial of all roots in the box.
• For a bounded game, q identifies a node and c is a signed strategy code.

2.3   Two kinds of compilation
The word “compiler” is used in two related senses.
   First, the formula compiler is structural. Given a fixed bounded formula, it constructs the value
and signed-certificate package. Its metatheoretic recursion follows the syntax tree.
   Second, the contract compiler is graph based. Given finitely many local lemmas and data
dependencies, it determines which queries are demanded, instantiates local results, and composes
their derivations. Its object-level work is a clocked recurrence or a finite sequence of cuts.
   The two compilers meet at a simple interface: every local finite claim can be turned into a
Boolean reflected atom or a bounded formula, and every unresolved local producer is retained as
a boundary formula. This separation prevents a large monolithic universal checker. It also lets
arithmetic lemmas be checked and reused independently of any particular application.

2.4   Why signed certificates are preferable to truth values alone
A Boolean evaluator answers whether a finite statement is true. A proof compiler needs more.
• When the value is one, it needs enough information to introduce every existential and disjunction
  and to answer every universal or conjunction challenge.
• When the value is zero, it needs enough information to prove an intuitionistic negation. A bare
  zero is not a proof of failure; a counterstrategy is.
• For diagnosis, a negative certificate identifies a least failing query or contains a table closing
  every attempted witness.
• For composition, the checker can consume an externally supplied certificate without trusting
  the producer that constructed it.
   The positive and negative code spaces are therefore first-class and generally have different sizes.
Their recurrences are not implementation accidents; they are the numerical reflection of intuitionistic
introduction and elimination behavior.


3     Boundary-aware contracts and proof composition
3.1   Open sequents are the correct output format
A framework theorem should not silently assume that every mathematical producer is available.
Suppose a finite argument needs a height bound, a finite cover, a local root-separation estimate,
and an arithmetic lemma. The right endpoint is
                               H(a), K(a), S(a), Γ(a) ⊢PRAAx Φ(a),
not a closed theorem whose prose says that these inputs are “standard.” Each boundary is an
ordinary formula in the same finite variable scope as the goal. The existing structural rule Prf.trans
then replaces every boundary by a derivation of it.
Theorem 3.1 (Boundary composition). Let Γ = [B1 , . . . , Br ] and suppose Γ ⊢PRAAx A. If a context
∆ derives each Bi , then ∆ ⊢PRAAx A.

Proof. The natural-deduction derivation may use a hypothesis rule at any occurrence of some Bi .
Simultaneous cut replaces that occurrence by the supplied derivation. Formally this is exactly the
checked theorem h.trans(supply). It is proved in the repository by induction over the hypothesis
list, repeatedly introducing an implication and applying modus ponens. No classical principle is
involved.

   This theorem gives contract graphs a simple semantics. A node is not a new logical connective. It
is an ordinary derivation under a list of formulas. Graph composition is simultaneous cut; parameter
instantiation is Prf.subst; and graph reuse under more assumptions is weakening.

3.2   Proof-local certificates
The most common certificate should never cross a public boundary. Let V (⃗a, c) mean that c is a
valid certificate and suppose the consumer has a derivation
                                    V (⃗a, c), Γ(⃗a) ⊢PRAAx A(⃗a),

                                                  5
STRIVE-iPRA                                                            Finite strategy-table realization in iPRA


where the goal does not contain the bound certificate variable. If the producer proves

                                           Γ(⃗a) ⊢PRAAx ∃c V (⃗a, c),

then existential elimination gives Γ ⊢ A.

Theorem 3.2 (Local certificate sealing). A proof-local certificate requires neither a canonical choice
nor a least search. Existential production and a certificate-parametric consumer suffice.

Proof. Open the producer’s existential with a fresh variable c, apply the consumer, and close the
existential elimination. The eigenvariable condition is exactly that A and the outer context are
shifted from the smaller scope and hence do not mention c. This is the checked Prf.exE rule.

   This observation removes a great deal of unnecessary canonicalization. A proof that merely needs
a local path, basis, chart, root box, or finite cover may consume whichever valid certificate the
producer supplies.

3.3    Exact residuals
If the producer is not known, the same consumer gives the conditional theorem

                                        Γ ⊢PRAAx (∃c V (⃗a, c)) → A(⃗a).

This formula is an exact residual: it states precisely what remains to be proved, in the object
language and at the correct scope. Exact residuals are preferable to labels such as “compactness” or
“effective finiteness.” They reveal whether the missing input is

 • a numerical bound;
 • a finite list or table satisfying a checker;
 • a local implication used at each index;
 • a modulus mapping requested output precision to input precision;
 • a separation or lower-bound estimate;
 • or an actual unbounded theorem.

  The distinction matters. A checker for a proposed height bound may be fully formalized even
when no theorem produces such a bound in general. The framework can therefore finish the verifier
and every downstream consequence without pretending to solve the producer theorem.

3.4    Contract normal form
For practical composition, normalize every local component to the following shape.

Contract 3.3 (Finite contract node). A node with parameters ⃗a consists of:
 1. a finite list of prerequisite formulas R1 (⃗a), . . . , Rs (⃗a);
 2. a bounded certificate predicate C(⃗a, c) = 1, optionally with an explicit code bound c < B(⃗a);
 3. a local derivation from the prerequisites and certificate validity to a postcondition P (⃗a, c);


                                                         6
STRIVE-iPRA                                                Finite strategy-table realization in iPRA


 4. an escape declaration saying whether c is local, observed, or named.

   A node with no certificate is the special case B = 1 and c = 0. A node with a table certificate
uses the mixed-radix layer. A node with an unresolved producer includes ∃c < B C = 1 among its
residuals.

3.5   Acyclic composition
If the dependency graph is acyclic, order its nodes topologically. Start with the derivation of the
final node under all residuals. Replace each internal postcondition assumption by the derivation
exported from its producer node. Proof-local certificates are sealed as soon as the last consumer
in their scope has been processed. The result is one ordinary open sequent under only external
residuals.
   There is no need to internalize the graph structure in iPRA. The graph is metalevel compilation
data. The generated proof term is a finite nest of trans, substitution, implication, and existential-
elimination steps. Cyclic numerical demand dependencies are handled separately by finite closure
and a clock, not by circular proof terms.

3.6   Scope discipline
Several subtle errors are prevented by requiring a scope annotation on every contract.

 1. A certificate variable opened by existential elimination is fresh and cannot occur in the outer
    goal.
 2. A quantified body lives in scope n + 1, while its bound lives in scope n. Substitution uses the
    repository’s inst and shift operations rather than informal renaming.
 3. A formula transported through the Foundation bridge is first proved in a common finite
    ConciseIPRA scope. Distinct free variables are not collapsed by an accidental assignment.
 4. A metalevel callback is never inserted as though it were a P R symbol. Every generated evaluator,
    bound, and checker has a concrete primitive- recursive definition.

  The supplied Kernel.lean packages the first layer of this discipline in small source-compatible
declarations. The larger compiler must preserve the same explicit scoping throughout.

5     Bounded formulas as signed finite games
5.1   Formula grammar
Fix a finite formula schema with free parameter tuple ⃗a. Its atoms are reflected primitive-recursive
relations. The grammar is

                    A ::= R(⃗t) | A ∧ A | A ∨ A | ∃x < b(⃗a, ⃗z) A | ∀x < b(⃗a, ⃗z) A.

The bound may depend on parameters and variables chosen by earlier quantifiers, but not on the
variable it bounds. The formula tree is fixed in the metatheory. All numerical bounds may vary
with the input.
   An atom is represented by a Boolean term r(⃗a) ∈ {0, 1} and checked derivations

                                         r = 1 → R,         r = 0 → ¬R.

Equivalently one may supply r = 1 ↔ R together with Booleanity. The negative direction is
constructively available because the atom is decidable. Negation need not be pushed through the
entire formula: the signed compiler directly constructs a proof of ¬A from a negative strategy.

5.2   Game reading
Read a positive certificate as a strategy for the prover and a negative certificate as a strategy for
the refuter.

does not use unrestricted excluded middle, countable choice, dependent choice, or a global selection

7.2   Closure does not prove feasibility
Demand closure computes the least precision request consistent with local rules. It does not by
itself prove that every requested producer exists. A coordinate may saturate at its capacity while a
local error target still fails. STRIVE records this as a failed local checker or as a residual producer
formula. This distinction is essential: a terminating scheduler is not a mathematical existence proof.

7.3   From closure to a clocked schedule
Once demands are fixed, replace the cyclic graph by a finite schedule. Each node receives its
stabilized query, and a topological order is chosen for the actual producers. When a producer is
relational rather than functional, use a state machine whose state stores the finite information
accumulated so far.
   A deterministic trace machine has primitive-recursive terms

                                 s0 = init(a),        st+1 = step(t, st , a).

Together with a quantifier-free invariant I(t, st , a). If iPRA derives the base and step implications,
quantifier-free induction derives I(T, sT , a) at every finite clock T . The final checker converts the
invariant into the desired postcondition.
   The same pattern works for a normalized trace certificate supplied externally. The checker verifies
the initial row, every step equation, and the terminal condition. Soundness follows by induction
over the row index. An external program may generate the trace efficiently, but the proof trusts
only the checker.

7.5     Relation to signed formula certificates
A fixed-horizon interaction is a bounded formula with alternation, so it can be compiled directly by
the signed strategy theorem. Conversely, the formula compiler may be implemented as a specialized
backward game evaluator. STRIVE keeps both interfaces because their engineering uses differ:

• formula syntax is convenient for theorem statements and direct proof composition;
• a state machine is convenient for long traces, shared subcomputations, and generated certificates;
• viability is convenient when local witnesses must be compatible;
• independent stable observers are cheaper when compatibility is irrelevant to the final observation.

  No logical strength is gained by choosing one representation. The choice is a normalization
decision made before proof generation.


8     Certificate escape analysis and stable observers
8.1     Three escape modes
Every certificate-producing node receives one of three explicit modes.

Local        The public conclusion does not mention the certificate. Use existential elimination and
             erase it immediately.

Observed The public conclusion depends only on O(c), and all accepted certificates have the
         same observation, equivalent observations, or observations within a specified diameter.
         Expose the observation contract, not the raw code.

Named        The public theorem genuinely requires a particular numerical code. Prove a finite
             bound and existence, then define the least accepted code by bounded search.

   This classification is more than documentation. It determines the required proof obligations and
prevents accidental global choice.

8.2     Exact observers
Let C(a, c) = 1 be a certificate checker and O(a, c) an observation term. Assume pairwise stability:

                          C(a, c) = 1 ∧ C(a, c′ ) = 1 −→ O(a, c) = O(a, c′ ).

Theorem 8.1 (Exact observation erasure). Suppose ∃c < B(a) C(a, c) = 1. Then there exists an
observation o realized by an accepted certificate, and any two such observations are equal. Any
downstream formula congruent under equality of o can be proved without naming a certificate.



                                                   18
STRIVE-iPRA                                                  Finite strategy-table realization in iPRA


Proof. Open the producer existential. Introduce o = O(a, c) and prove the downstream property
from the local certificate. Close the existential elimination; the raw certificate disappears. For
uniqueness, open two certificates and apply pairwise stability. A downstream predicate is transported
by equality using the calculus’s simultaneous Leibniz rule. At no point is a selector over all inputs
constructed.

   If a concrete term for o must appear outside an existential, one may use the least accepted
certificate. The point is that naming is an additional public requirement, not a prerequisite for
ordinary proof composition.

8.3   Quotient observers without quotient types
Exact equality is often too strong. Bases differ by a change-of-basis matrix, root lists differ by
permutation, paths differ by stuttering, and local charts differ on overlap. Let E(x, y) = 1 be a
reflected equivalence relation and assume

                      C(a, c) = 1 ∧ C(a, c′ ) = 1 −→ E(O(a, c), O(a, c′ )) = 1.

A consumer supplies an E-congruence theorem for its predicate. This is enough; no quotient type
need be constructed inside arithmetic.
Proposition 8.2 (Quotient observation principle). If P (x) is stable under E, then proving P (O(a, c))
from one accepted certificate proves an invariant public statement independent of the certificate
representation.

Proof. Given any other accepted c′ , observer stability gives E(O(c), O(c′ )). The consumer’s congru-
ence implication transports P to O(c′ ). Because the original certificate remains under existential
elimination, the public statement is the invariant property, not a chosen equivalence class object.

  This is particularly useful for unordered root clusters, finite sets represented by duplicate-
permitting lists, and geometric objects represented in overlapping coordinate patches.

8.4   Metric observers
Approximation problems rarely have exact certificate independence. Let d(x, y) be a primitive-
recursive rational pseudo-distance and let ε(a, q) be an explicit error bound. Assume

               C(a, q, c) = 1 ∧ C(a, q, c′ ) = 1 −→ d(O(a, q, c), O(a, q, c′ )) ≤ ε(a, q).

Then any selected observation is representative up to the declared diameter. If a consumer is
L-Lipschitz, certificate choice contributes at most Lε to the output error.
  The key discipline is that ε is data, not a slogan such as “sufficiently close.” Its derivation may
depend on separation, a modulus, or a finite-cover certificate, each retained as a residual when
unavailable.

8.5   Independent certificates versus compatible paths
There are two distinct ways to use a family of certificates.
 1. If later stages require the actual state produced earlier, use relational viability and a compatible
    replay.

                                                   19
STRIVE-iPRA                                                   Finite strategy-table realization in iPRA


 2. If the final output is stable across all accepted certificates at each query, select certificates
    independently. Compatibility is unnecessary.

   The second method can be much cheaper. For example, to approximate a symmetric polynomial
of all roots in a cluster, each precision may use a different list ordering or a different isolating box.
Stable observation proves that the symmetric output is consistent. Constructing an infinite coherent
branch would solve a harder problem with no benefit to the requested theorem.

8.6      Least naming
Suppose a public API demands a code-valued function. Given

                                        ∃c < B(a) C(a, c) = 1,

define
                                 µ(a) = min{c < B(a) : C(a, c) = 1}.
The existing bounded-search theorem yields

                                  µ(a) < B(a),          C(a, µ(a)) = 1,

and minimality. This produces a canonical total primitive-recursive term under the existence
hypothesis.
  A least code is representation dependent. It should not be confused with a mathematically
canonical object. Observer theorems ensure that public invariant outputs do not depend on arbitrary
details of the code ordering.

8.7      Branch labels and discontinuity
A uniform exact label for a root, eigenvector, or analytic branch may be discontinuous at collisions
or symmetries. STRIVE does not force such a label. It offers three safer interfaces:

• return the whole finite cluster;
• return a symmetric or quotient-invariant observation;
• return an approximate branch only under an explicit separation certificate.

   When separation is supplied, finite search can select the unique isolated candidate and the
observer becomes exact. Without it, the residual accurately records the missing mathematical
resource.


9     Embedding quantitative and analytic mathematics
9.1      Rational coding and error predicates
The native domain is N, so signed integers, rationals, finite vectors, and matrices are represented by
primitive-recursive codes. A rational may be a pair (z, d) with a signed-integer code z and positive
denominator d + 1. Equality can be checked by cross multiplication, and order by the corresponding
signed comparison. Approximation statements use integer-scaled inequalities, avoiding division in
the proposition itself.

                                                   20
STRIVE-iPRA                                                     Finite strategy-table realization in iPRA


   For example, the assertion that rational code r approximates a real-like object x within 2−n is
represented by a certificate predicate

                                        Approx(x, n, r, c) = 1,

where c contains the finite evidence appropriate to the chosen representation. The framework never
quantifies over a completed real number as a set of rationals. It reasons about finite observations at
requested precisions.

9.2   Finite-use real interfaces
A real-like object is supplied through a query contract

                             ∀n < N ∃c < B(x, n) Approx(x, n, c) = 1.

For a theorem with an arbitrary precision parameter N , the theorem is proved uniformly in N , but
each instance uses finitely many queries. A reverse demand pass computes how accurate each input
observation must be to obtain the requested output precision.
   This resolves a common apparent conflict: iPRA can prove a formula for every natural precision
parameter without constructing an infinitary object. What it cannot do automatically is derive the
modulus that tells the finite algorithm which input precision suffices. The modulus is a primitive-
recursive producer and must be proved from theorem-specific estimates.

9.3   Reverse error-demand propagation
Consider a fixed finite computation graph. Each node v has an output error budget ev , and each
edge carries a monotone local demand transformer Du←v (ev ). Starting from the requested final
budget, propagate requirements backward and take coordinatewise maxima. If dependencies are
acyclic, one reverse traversal suffices. If they are cyclic but bounded and monotone, use the finite
closure theorem of Section 7.
   The forward proof then checks a local estimate at every node. Typical local contracts are

                             |x + y − (x̃ + ỹ)| ≤ ex + ey ,
                                     |xy − x̃ỹ| ≤ Mx ey + My ex + ex ey ,
                                 |f (x) − f (x̃)| ≤ ωf (ex ),
                                d(O(c), O(c′ )) ≤ ε.

All quantities are rational codes, and inequalities are reduced to natural arithmetic. Magnitude
bounds Mx , My and moduli ωf are explicit inputs or derived local lemmas.

9.4   Division and apartness
A bare negated equality is usually not a usable numerical resource for approximate inversion.
Knowing x ̸= 0 does not provide a rational λ > 0 with |x| ≥ λ. Without such a lower bound, an
error in x can be amplified arbitrarily by inversion.

Contract 9.1 (Approximate inverse). To compute an inverse with output error ε, require:
 1. an approximation x̃ to x;


                                                    21
STRIVE-iPRA                                                  Finite strategy-table realization in iPRA


 2. a positive rational lower bound λ ≤ |x|;
 3. input error small enough, for example |x − x̃| ≤ λ/2.
Then |x̃| ≥ λ/2, and elementary rational algebra gives an explicit inverse error bound.

   This requirement is not a weakness of iPRA; it is the constructive content of numerical inversion.
In a discrete bounded natural-number problem the situation is different. If d < M and d ̸= 0, finite
numerical case analysis yields 1 ≤ d, which is a usable lower bound. STRIVE keeps these cases
separate.

9.5   Finite nets instead of abstract compactness
An abstract compactness theorem is not directly a primitive-recursive algorithm. The useful finite
contract is a net certificate:
                                     Cover(X, n, L) = 1,
where L is a finite list of sample points and every admissible input is within radius 2−n of some
member. If a function has a supplied modulus of continuity, evaluate it on the net, choose a least
finite optimum, and add the modulus error.

Theorem 9.2 (Finite-net optimization schema). Assume a checked δ-net L for a domain, a bounded
evaluator for f on members of L, and a modulus proving d(x, y) ≤ δ → |f (x) − f (y)| ≤ ε. Then
finite search returns a sample whose value is within the evaluation error plus ε of the global optimum.

Proof. Let x∗ be an arbitrary admissible point. Coverage supplies a sample y ∈ L within δ. The
modulus compares f (x∗ ) and f (y). The selected finite optimum is no worse than y, up to its verified
evaluation error. Combining the inequalities yields the stated bound. The sample selection and its
failure alternative are instances of the signed bounded-formula compiler. If the theorem does not
already provide a net or modulus, those remain residuals.

9.6   Metastability and finite windows
A full convergence modulus may not exist or may be hard to obtain. Many finite uses need only a
metastable window:

                     ∀g < G ∃n < N (g, k) ∀i, j ∈ [n, n + g(n)] d(xi , xj ) ≤ 2−k .

When g, k, and a rank bound are finite-coded, this is a bounded formula and receives positive
or negative strategy certificates. A positive strategy returns a stable window for each bounded
challenge. A negative strategy identifies a challenge and closes every candidate window with a
violating pair. This is a genuine constructive result even when no tail convergence rate is claimed.

9.7   Algebraic branches and clusters
Exact branch selection is replaced by a hierarchy of finite contracts.

 1. A local root certificate verifies that a finite box contains the claimed number of roots or that a
    sign/argument condition holds.
 2. A cluster observer returns symmetric data, such as coefficient approximations or power sums,
    invariant under permutation.

                                                  22
STRIVE-iPRA                                                 Finite strategy-table realization in iPRA


 3. A separation certificate upgrades the cluster to uniquely labeled branches.
 4. A compatibility trace is used only when a downstream theorem needs the same branch across
    several precisions.

   The framework can verify and compose all these certificates. It does not produce a global
separation theorem from the mere existence of roots.

9.8    Diophantine enumeration
Given a polynomial equation and a height cutoff H, enumeration of all integer tuples of height below
H is a fixed bounded search. STRIVE produces both a solution certificate and a counterstrategy
showing that every bounded candidate fails. What it cannot infer is a cutoff containing all solutions
from a non-effective finiteness assertion.
   Thus the generic theorem has the conditional form

                      AllSolutionsBelow(H) −→ EnumerationComplete(H, L).

The verifier and every consequence of a supplied H can be fully formalized. The height producer is
an exact, theorem-specific residual.


10     Resolution of recurring difficulty reports
This section turns the recurring obstacles in the repository into explicit interfaces. “Resolved” means
that the generic logical or coding obstacle has a finite construction. It does not mean that every
theorem-specific producer has been proved.

10.1    All-precision hypotheses
Problem. An informal proof assumes a coherent approximation at every precision and then uses
only a few of them. Direct formalization appears to require an infinite choice sequence.

Resolution. Compile the consumer first. Its reverse demand pass yields a finite set or a finite
adaptive tree of queries. Ask the producer only for those queries and keep each answer under
existential elimination. If queries depend on earlier answers, compile the finite interaction as a
signed game or a viable trace. No infinite selector is constructed.

Boundary. A theorem asserting a single total approximation function for all precisions requires a
named producer and is stronger than a finite-use conclusion.

10.2    Variable-length evidence and alternating quantifiers
Problem. Abstract packets say that a strategy stores one answer at existential nodes and all
answers at universal nodes, but do not provide a concrete object code.

Resolution. Use disjoint prefix sums for one selected child and heterogeneous mixed-radix prefix
products for tables. The exact positive and negative code bounds are computed structurally. The
signed checker proves both success and failure.

                                                  23
STRIVE-iPRA                                              Finite strategy-table realization in iPRA


Boundary. The formula is fixed at compilation time. STRIVE does not yet internalize a universal
syntax code and evaluator.

10.3   Semantic Lean theorems versus Prf PRAAx
Problem. A host theorem about N can be mistaken for a formalized iPRA theorem.

Resolution. Every reusable package is a structure whose proof fields have literal Prf PRAAx
types. Metalevel semantic code is used only to generate and test definitions. The bridge and native
transfer are post-processing steps, not substitutes for the ordinary derivation.

Boundary. The larger STRIVE Lean modules remain blueprints until their placeholders are
removed and the repository axiom audit passes.

10.4   Nonunique witnesses
Problem. A mathematical object may have many encodings or local witnesses, while the informal
proof silently treats a selected representative as canonical.

Resolution. Use certificate escape analysis. Erase local witnesses; expose an exact, quotient, or
metric-stable observer; name a least code only if the public interface truly requires it. Pairwise
observer stability replaces global choice.

Boundary. An exact label can remain unavailable or discontinuous at symmetries. The framework
returns a cluster or invariant output unless separation data is supplied.

10.5   Compatible paths
Problem. Pointwise witnesses at each layer need not form a compatible run.

Resolution. Compute backward viability within explicit finite state and answer bounds, then
replay the least viable transition. If compatibility is irrelevant to a stable observation, select
independently instead.

Boundary. State and horizon bounds are required. An unbounded path theorem is not obtained
from finite viability.

10.6   Cyclic precision requirements
Problem. Backward error demands form a cycle, so a simple topological pass is impossible.

Resolution. Place each demand in a finite chain, iterate d 7→ d ∨ F (d), and use the coordinate-
sum rank to prove stabilization and leastness. Compile the stable demands into a clocked forward
schedule.




                                                24
STRIVE-iPRA                                               Finite strategy-table realization in iPRA


Boundary. The transfer must be monotone and bounded. Saturation may reveal an impossible
requested accuracy rather than prove feasibility.

10.7    Division from nonzero
Problem. An informal analysis proof divides by a quantity known only to be nonzero.

Resolution. Require an apartness resource: a positive rational lower bound, or in a finite discrete
domain a bounded case analysis deriving a numerical lower bound. Use that resource in the
inverse-error calculation.

Boundary.     A bare intuitionistic negation x ̸= 0 does not in general contain a usable magnitude
bound.

10.8    Compactness
Problem. An abstract compactness argument selects a finite cover without a code or coverage
proof.

Resolution. Use a finite-net certificate with a primitive-recursive coverage checker and an explicit
modulus for the consumer. Search and optimize on the finite net.

Boundary. The framework does not turn arbitrary compactness into an effective net. The cover
producer is theorem-specific.

10.9    Metastability
Problem. A proof requires finite stabilization but no computable tail rate is known.

Resolution. State the finite challenge as a bounded formula and compile a positive stable window
or a negative counterchallenge. Ranked descent often supplies a bound on the window search.

Boundary.     A metastable theorem is not automatically a convergence modulus.

10.10    Puiseux series, roots, and branches
Problem. Exact root or branch labels collide, permute, or require separation not present in the
hypotheses.

Resolution. Represent finite clusters, verify local boxes, and expose symmetric or quotient
observations. Use compatibility traces only when a branch must persist across queries. Upgrade to
exact labels under a separation certificate.

Boundary. Uniform exact selection may be mathematically discontinuous. STRIVE does not
assert it without extra data.



                                                25
STRIVE-iPRA                                                  Finite strategy-table realization in iPRA


10.11      Diophantine finiteness
Problem. A qualitative theorem says there are finitely many solutions, but a bounded search
needs a height cutoff.

Resolution. Separate the producer from the verifier. Given a cutoff, enumeration, checking,
completeness relative to the cutoff, and a failure certificate are all finite and compilable.

Boundary. Cardinality finiteness alone does not yield an effective bound. The height producer
remains open unless supplied by additional mathematics.

10.12      Verifier versus producer
Problem. An executable checker is presented as if it proved that an accepted object exists.

Resolution. Maintain separate theorems:

                 Check(c) = 1 → Claim,        ProducerHypothesis → ∃c Check(c) = 1.

The canonical strategy theorem is a producer only for the fixed bounded formula value computed
by the compiler. For external mathematical objects, existence is a separate residual.

10.13      Precision bookkeeping
Problem. A proof contains many occurrences of “choose sufficiently accurate” with no consistent
global budget.

Resolution. Compile local quantitative estimates to monotone demand transformers, compute
the least finite closure, and check the forward error trace. Every rounding, observer diameter, and
evaluator error appears in the final rational budget.

Boundary. Local moduli and magnitude bounds must be proved. The scheduler cannot invent an
analytic estimate.

11.5    Finite maximum on a certified net
Suppose a domain certificate lists y0 , . . . , yN −1 and proves that every admissible x lies within δ of
some yi . Suppose each value f (yi ) is approximated by a rational ri within η, and a modulus proves
d(x, y) ≤ δ → |f (x) − f (y)| ≤ ε.
   A bounded formula compares the rational codes and chooses the least index i∗ maximizing ri .
Its positive strategy certifies every comparison used by the finite argmax. For arbitrary admissible
x, choose a covered yj . Then

                                           f (x) ≤ f (yj ) + ε
                                                 ≤ rj + η + ε
                                                 ≤ ri∗ + η + ε
                                                 ≤ f (yi∗ ) + 2η + ε.

Thus the selected sample is within 2η + ε of the supremal value. The cover and modulus are explicit
residual producers. The finite comparison, argmax, and failure explanation are generic STRIVE
components.

11.6    Approximate reciprocal
Let rational observations satisfy

                               |x − x̃| ≤ δ,        |x| ≥ λ > 0,          δ ≤ λ/2.

Then |x̃| ≥ λ/2, and
                                           1   1   |x − x̃|   2δ
                                             −   =           ≤ 2.
                                           x x̃     |x| |x̃|  λ
All operations can be expressed by cross-multiplied integer inequalities. A reverse demand trans-
former chooses δ so that 2δ/λ2 ≤ 2−n . The lower bound λ is the crucial producer; x ̸= 0 alone is
not substituted for it.

11.7    Bounded Diophantine completeness
Let p(⃗x) = 0 be a fixed polynomial and suppose a residual theorem gives |xi | ≤ H for every solution.
Encode signed integers by naturals and enumerate the finite box. A positive certificate for “⃗x is a
solution” is just the arithmetic evaluation trace. A negative table proves that every nonlisted tuple
fails. The output list is complete relative to the height theorem.
   This example isolates the genuine bottleneck. The strategy compiler solves bounded enumeration
and completeness checking. It does not derive H from a statement that the solution set is finite.

12.1    Public theorem shape

13     Limits, nonclaims, and open research
13.1    No universal formula evaluator is claimed
The compiler is uniform as a metalevel algorithm over fixed syntax trees, but the generated
iPRA theorem is specialized. Internalizing arbitrary formula codes would require syntax coding,
substitution, a universal evaluator for primitive-recursive symbols, and a proof of its reflection. That
may be useful for metamathematics, but it is not required for the mathematical embedding program
and would greatly enlarge the trusted development.

13.2    No hidden infinitary choice
The framework constructs only finite strategies under explicit bounds. A family of theorems indexed
by every n does not automatically yield one function choosing compatible witnesses for all n. Such a
function may be available as a separately proved primitive-recursive producer, but it is not extracted
merely from pointwise existential proofs.



                                                  32
STRIVE-iPRA                                                 Finite strategy-table realization in iPRA


13.3    No global height bound from finiteness
A qualitative finiteness theorem does not generally contain a primitive- recursive cutoff. STRIVE
can verify a proposed cutoff and compile every bounded consequence. It does not turn the assertion
“there are finitely many solutions” into a search bound.

13.4    No convergence modulus from convergence alone
Similarly, a convergence proof may not provide a usable modulus in the chosen base theory. The
framework supports an explicit modulus, a ranked descent bound, or a metastable finite-window
statement. It does not silently upgrade one form to another.

13.5    No exact branch selector without separation
At collisions, exact labels may be unstable or discontinuous. The generic output is a cluster,
equivalence class represented by an observer, or bounded- diameter approximation. A unique branch
term requires a separation producer.

13.6    No quantitative inverse from bare negation
The formula x ̸= 0 is propositionally useful but usually insufficient for a numerical reciprocal error
bound. Approximate inversion requires explicit apartness. Any report that replaces this lower
bound by a bare negation risks smuggling in a classical or nonuniform principle.

13.7    No producer theorem from a checker
A verified checker establishes Check(c) = 1 → Claim. It does not establish ∃c Check(c) = 1. The
signed compiler supplies a canonical producer for its own computed finite game, but external covers,
moduli, separation estimates, and height bounds retain separate producer obligations.

13.8    Potential extensions
The following directions appear both feasible and useful.

 1. Tight generated Lean code. Complete mixed-radix arithmetic and measure proof-term
    growth for nested alternation.
 2. DAG sharing. Compile repeated subformulas once and use trace states rather than duplicate
    syntax trees.
 3. Proof-carrying optimization. Allow an external tool to minimize code bounds or strategy
    tables while Lean checks an equivalence certificate.
 4. Observer algebra. Develop reusable combinators showing that exact, quotient, and metric
    observers are closed under products, composition, and finite folds.
 5. Residual synthesis. Generate human-readable statements of the weakest missing producer
    and counterchallenge data from a failed contract compilation.
 6. Complexity accounting. Track code bounds, recursion depth, proof size, and maximum
    numeral growth alongside theorem status.


                                                 33
STRIVE-iPRA                                                  Finite strategy-table realization in iPRA


 7. Certified front end. Build a small typed DSL whose elaborator emits only the fixed constructor
    family, reducing generator complexity.
 8. Bridge regression suite. Transport generated open sequents to Foundation iPRA and
    round-trip them at representative scopes.

13.9    A criterion for genuine progress
A future packet advances this program when it does at least one of the following:

• removes a visible sorry from a reusable object-theory module;
• supplies a previously missing quantitative producer;
• weakens a residual hypothesis while preserving a checked endpoint;
• turns an abstract certificate into a concrete bounded code and checker;
• proves a new observer invariance or compatibility theorem;
• or demonstrates a substantial mathematical application through the ordinary PRAAx interface.

  Renaming the same finite-certificate idea without crossing one of these boundaries is not progress.
STRIVE is designed to make those boundaries machine visible.


14     Conclusion
The current iPRA repository already contains the logical kernel, substantial arithmetic, open-
sequent transport, and several mature high-level finite frameworks. The most productive next step
is therefore not another semantic layer. It is a concrete realization of the finite evidence those
frameworks assume.
   STRIVE supplies that realization for fixed bounded formulas. One-child proof choices are
encoded by disjoint prefix sums. All-child obligations are encoded by heterogeneous mixed-radix
tables. Positive and negative certificate spaces are generated together, so failure is an auditable
counterstrategy rather than an opaque Boolean. The compiler’s proofs follow the introduction
and elimination rules of intuitionistic logic, while all numerical loops use primitive recursion and
quantifier-free induction.
   The same framework clarifies the embedding of broader mathematics. A theorem is presented as
a finite observation contract, a demand computation, a certificate or trace checker, an observer, and
an open list of exact residual producers. Local certificates are erased, noncanonical witnesses are
observed only through stable outputs, and named choices are introduced only by bounded least
search. Cyclic finite dependencies are solved by least monotone closure; compatible runs are solved
by backward viability. Missing moduli, height bounds, separation estimates, and finite covers remain
visible rather than being attributed to the proof checker.
   The result is a framework that is general without being vague. It has a small kernel-facing interface,
a complete mathematical proof of its central compiler theorem, executable reference algorithms, and
a dependency-ordered Lean route. Its limitations are equally explicit. Completing the mixed-radix
and bounded- quantifier modules as checked Prf PRAAx derivations would convert a large class of
existing research packets from architectural proposals into reusable formal infrastructure.
