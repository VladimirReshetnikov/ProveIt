\subsection{Variable order}

The proposed Lean library should fix conventions globally:
\begin{itemize}
  \item loop formulas: variable \(0\) is time/state focus, followed by state components and external parameters;
  \item relation formulas: variable \(0\) is the current candidate, variable \(1\) the next or comparison candidate, followed by query and parameters;
  \item observer formulas: two candidate blocks first, then query and parameters;
  \item rational metric formulas: numerator/denominator components are grouped and accessed through named substitutions.
\end{itemize}
Named substitution helpers should be proved once.  Ad hoc \texttt{Fin.cases} expressions are a major source of binder errors.

\subsection{Rational codes}

A convenient exact rational code is a signed integer numerator and a positive natural denominator.  Normalization is optional for arithmetic, but equality is cross multiplication.  Every theorem that divides by a denominator carries its positivity proof.  Dyadic codes may use a signed numerator and exponent; comparisons are reduced to a common exponent.

\subsection{Bounds}

All bounds are exclusive unless explicitly stated.  ``Search below \(B\)'' means candidates \(0,\ldots,B-1\).  A finite relation may totalize invalid out-of-range cells as false.  This convention simplifies rectangular table encoding.
