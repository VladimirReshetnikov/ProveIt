FIBER-iPRA
A Fibered Interface Calculus for Compiling Finitary Mathematics into Intuitionistic
Primitive Recursive Arithmetic
Research report prepared for the ProveIt repository
16 November 2026
Repository baseline: 58627ed89814ba122e1f0f012f1aba103cda267b

Abstract
The ProveIt repository contains a checked ordinary presentation of intuitionistic primitive
recursive arithmetic, a substantial checked arithmetic library, a bridge to the Foundation
presentation, and more than one hundred research packets that reformulate mathematics in
finite quantitative terms. The recurring gap is no longer the absence of isolated encodings.
It is the absence of one compositional interface that distinguishes object-theory derivations
from host computations, controls the scope of finite certificates, turns bounded quantifiers into
quantifier-free loop invariants, and records genuinely missing effective information as explicit
residual assumptions.
This report develops FIBER-iPRA (Finite-query Interfaces with Bounded Evidence and
Realizers). A mathematical object is represented by a family of finite certificate spaces indexed
by a query. A morphism carries an explicit finite demand map, a certificate transformer, an
observation map, and a derivation in the literal judgment Prf PRAAx Γ φ. Local certificates are
eliminated by existential elimination; least bounded search is used only when a public result
must name a canonical code. Composition is proved by substitution and simultaneous cut.
Cyclic resource requirements are resolved by a finite monotone closure theorem. Fixed bounded
quantifier alternations are handled by finite strategy certificates. Missing constants, cutoffs,
moduli, and representatives are exposed as residual producer formulas, with a precise hierarchy
of cases in which the residual can be eliminated inside iPRA.
The framework is applied to several difficulties reported in the repository. We give constructive
proofs of a dyadic adjacent-motion theorem that upgrades compatible approximants to a Cauchy
name, a finite-net lifting theorem replacing abstract compactness, guarded exact branch selection,
stable cluster-valued observations at collisions, finite master-certificate formation without hidden
choice, and bounded-game realization. We also prove two useful impossibility results: there is
no primitive-recursive universal evaluator for all primitive-recursive functions, and no finite-use
exact sign or branch selector can work on arbitrary Cauchy names without a separation guard. A
dependency-ordered Lean plan and source-oriented Lean modules use the current ConciseIPRA,
IPRADerivations, and IPRABridge interfaces. No new kernel-checked theorem is claimed by
this archive; the report states exactly which declarations must be completed and how each
reduces to existing checked infrastructure.

Verification status. The mathematical arguments in this report are human proofs. The Python
reference implementation and tests exercise only finite algorithms. The Lean files are an integration
blueprint tied to the current repository API; Lean was unavailable in the artifact runtime, so those
files were not elaborated. A theorem is counted as formally established only when the repository
contains a compiled declaration of literal type Prf PRAAx ... and its axiom audit passes.

1.2

What the existing foundation packets already solve

The most recent foundation packets converge on a strong common picture. Finite-query normal
form packs all evidence for a fixed query into one bounded certificate. KIFC-R and FINER add
explicit residual producers and finite demand closure. CBIP isolates bounded interaction programs
and finite strategy certificates. Scoped Certificate Realization observes that most certificates should
remain local and be eliminated by existential elimination. The observation-algebra packets replace
discontinuous labels by stable invariants or guarded labels. These are genuine advances, and the
present work deliberately reuses them rather than renaming them.
Their recurring unresolved obligations are also remarkably stable:

The current repository already contains the arithmetic ingredients needed for most of the finite
part: arbitrary-term defining equations, quantifier-free induction, substitution, simultaneous cut,
order, bounded search, pairing, simultaneous recursion, bounded sums and products, and finite
linear algebra. The missing shared layer is therefore not a larger arithmetic library. It is a disciplined
compiler interface connecting a finite mathematical argument to those checked derivations.

1.3

Why another framework is justified

A new framework is useful only if it removes a repeated source of work rather than adding another
vocabulary. FIBER-iPRA makes three changes.
First, interfaces are query-indexed and typed. A “real number”, “root”, “finite cover”, or
“cohomology class” is not represented by one global code. It is represented by what can be verified
at a requested precision, degree, horizon, mesh, or finite diagram. The certificate space is allowed to
vary with that query. This makes resource flow explicit and prevents a proof at one precision from
being confused with a coherent name at every precision.
Second, composition is an object-theory theorem. Every reusable node comes with a local
derivation. The compiler specializes these derivations, substitutes actual terms, and composes them
using the checked Prf.subst, Prf.weaken, Prf.exE, and Prf.trans operations. “The checker is
correct” is not left as an informal bridge from executable truth to iPRA.
Third, residuals have a calculus. A missing producer is neither concealed nor automatically
fatal. It is a formula in the final sequent. The report classifies when it can be eliminated by bounded
search, master-certificate formation, finite-net construction, adjacent-motion estimates, or finite
strategy realization. Residuals that encode genuinely unavailable effective mathematics remain
explicit.

Conservative design rule

FIBER-iPRA does not add axioms to iPRA and does not propose an internal universal interpreter.
A fixed external source generator produces fixed primitive-recursive symbols, formulas, and proof
terms. Lean checks the resulting derivations. This is exactly the same trusted-boundary pattern
used successfully by the checked arithmetic library: metatheory may help construct a proof, but the
object theorem is accepted only through the inductive Prf datatype.

2

The formal boundary: ordinary iPRA and finite specialization

2.1

The object theory used in the report

We use the ordinary presentation already selected by the repository unification plan. Its terms are
built from a symbol for every primitive recursive function. Its formulas use intuitionistic first-order
logic with equality. The theory PRAAx contains the defining equations for primitive recursive
symbols, the successor axioms, and induction for quantifier-free formulas. In Lean the central
judgment is
Prf PRAAx Γ φ,
with notation Γ ⊢PRAAx φ.
The checked deduction layer provides, among other rules:
• substitution of arbitrary terms for free variables;
• weakening of the hypothesis list;
• simultaneous cut, called Prf.trans;
• universal and existential introduction and elimination;
• simultaneous equality substitution;
• quantifier-free induction through PRA.qfInd;
• the convenient open induction wrapper LeanProofs.IPRA.ind;
• instantiation of closed derivations at arbitrary terms through LeanProofs.IPRA.inst.
The framework never reasons by saying that a primitive recursive function has the intended
standard value and then applying a semantic completeness principle. Instead, every use of a program
is mediated by its defining equations and an object derivation.

2.2

Four levels that must not be conflated

For a fixed algorithm f , formula A, and certificate c, there are four different statements.
1. Host computation: a Python or Lean evaluator returns a value.
2. Host theorem: Lean proves a proposition about the standard natural-number interpretation
of f .
3. Object equation: iPRA derives the defining or correctness equation for the term denoting f .
4. Object conclusion: iPRA derives A, perhaps after eliminating the certificate and discharging
residual assumptions.
Levels 1 and 2 are useful for discovering invariants and regression testing, but only levels 3 and
4 prove the requested theorem. FIBER metadata records all four separately.

Why the compiler is specialized

One might try to internalize the entire framework by adding a primitive-recursive universal evaluator
U (e, x) for codes of arbitrary primitive-recursive functions. This cannot work.
Theorem 2.1 (No primitive-recursive universal evaluator). There is no binary primitive-recursive
function U such that for every unary primitive-recursive function f there is an index e satisfying
U (e, x) = f (x) for every x.
Proof. If such U existed, the diagonal function
g(x) = U (x, x) + 1
would be primitive recursive. Hence g(x) = U (e, x) for some e. Setting x = e gives U (e, e) + 1 =
U (e, e), impossible. The argument is constructive and uses only closure of primitive recursive
functions under composition and successor.
Consequently a framework that quantifies internally over all primitive recursive source programs
is asking for the wrong interface. FIBER uses metalevel specialization: a finite source description is
compiled to specific PR terms, specific formulas, and a specific proof term. For a bounded dynamic
trace, the trace checker itself is a fixed primitive recursive symbol. The generated proof is then
checked by Lean’s kernel.

2.4

Finite-use discipline

A proof of a fixed finite-query conclusion can inspect only finitely much source data. FIBER makes
that finite use explicit through a demand map. This is not merely an implementation optimization.
It is the logical reason that objects such as Cauchy reals, analytic functions, compact spaces, and
quotient objects can be handled in weak arithmetic: the theorem does not need the completed
infinitary object; it needs a finite observation and a proof that this observation is stable under the
chosen representation.
The discipline has two forms.
Static finite use. The compiler knows a finite list of source queries from the target query.
Adaptive finite use. A bounded interaction program chooses its next query from previous answers,
but a primitive-recursive fuel or a finite monotone closure bounds the complete trace.
Both forms produce one finite master certificate. No appeal to countable choice or bar induction
is needed for the compiled theorem.

2.5

Portable versus backend-specific statements

The canonical portable conclusion is an ordinary Prf PRAAx sequent. When an application is stated
in the Foundation syntax, the checked bridge transports the resulting open or closed sequent. This
separation avoids two common mistakes:
1. proving the right mathematics in a nonportable host representation and never obtaining an
object theorem;
2. rebuilding arithmetic inside every application-specific Foundation development.
The framework therefore compiles first to the ordinary calculus, imports the checked arithmetic
library, and translates only at the application boundary.

3

Fibered finite-query interfaces

3.1

Encoded finite data

All finite collections are represented by natural numbers using a fixed primitive-recursive sequence
coding. We write Seq(C, i) for the i-th entry and ℓ(C) for the declared length. A code is accepted
only under an explicit bound. The concrete implementation may use the pairing and simultaneousrecursion infrastructure already checked in IPRADerivations.Core.Pairing, or mixed-radix coding
when component bounds are known. The mathematical statements below are independent of that
choice.
Every Boolean predicate is represented by a primitive-recursive bit. Thus b(⃗x) = 1 is an
atomic equality in the object language. A checker is never trusted merely because it executes; it is
accompanied by a reflection or soundness derivation.

It also contains object-theory derivations for verifier soundness, observational equivalence, and
congruence of every exported operation.
The certificate fiber over q is the finite set
CertX (p, q) = {c < BX (p, q) : VX (p, q, c) = 1}.
The point of the word “fiber” is that both the admissible evidence and its bound may depend on
the query. A degree-d polynomial calculation, a precision-n approximation, and a horizon-T trace
need not share a single global witness.
Definition 3.2 (Validity and totality). The interface formula
ValidX (p, q, c) :≡ c < BX (p, q) ∧ VX (p, q, c) = 1
is quantifier-free. The totality formula is
TotalX (p, q) :≡ ∃c ValidX (p, q, c).
Totality may be a theorem, a hypothesis inherited from another interface, or an explicit residual
producer.
Definition 3.3 (Certificate-independent observation). An observation is certificate-independent
when iPRA derives
ValidX (p, q, c) ∧ ValidX (p, q, c′ ) −→ EX (p, q, OX (p, q, c), OX (p, q, c′ )) = 1.
For a metric interface one may instead derive a discrepancy bound depending only on the query.
This weaker notion is often exactly what mathematics supplies. Different root isolations may
yield the same cluster, different finite covers may yield the same stable count, and different cocycle
representatives may yield the same finite invariant. Code equality is neither required nor desirable.

Realizers and demand

Definition 3.4 (FIBER realizer). A realizer R : X → Y consists of:
1. a primitive-recursive demand list demR (p, q) of X-queries needed to answer the Y -query q;
2. a primitive-recursive bound for a master input certificate;
3. a master verifier asserting that every demanded query has a valid certificate;
4. a certificate transformer TR (p, q, C) producing a Y -certificate;
5. an observation transformer, when the public output is an observation;
6. a literal object derivation of the local soundness sequent;
7. extensionality or stability derivations showing that equivalent input observations give equivalent
output observations;
8. a list of residual producer formulas not supplied by X.
The local soundness sequent has the schematic form

3.4

Local, public, and residual evidence

The interface records the escape class of each witness.
Local. The witness is introduced to prove an intermediate statement and eliminated before the
node returns. It is never named by a public term.
Observational. The code may vary, but all valid codes yield equivalent or quantitatively close
observations. The code is eliminated; only the observation class escapes.
Canonical. A downstream theorem genuinely needs one code. A least valid code is selected by
bounded search, after totality has been proved.
Residual. Existence of the witness is not established by the current finite library. Its exact producer
formula remains in the final sequent.
This classification prevents a subtle but frequent strengthening. From ∀q ∃c V (q, c) one may
use c locally for a fixed q. One may not silently obtain a global function q 7→ cq . FIBER obtains
such a function only when the verifier is bounded and decidable, so checked least search defines it
primitively recursively.

3.6

Metric and quotient fibers

Two especially useful interface flavors are built into the framework.
Metric fibers. For precision query n, valid certificates yield observations within an explicit error
ϵ(n). Composition adds or otherwise transforms the errors. No equality of approximants is expected.
Quotient fibers. An equivalence bit EX is reflexive, symmetric, transitive, and respected by
exported operations, all by object derivations. Public statements are phrased in terms of invariant
observations. A global quotient type need not be constructed inside iPRA.
These two forms cover many apparent obstacles involving real numbers, projective directions,
unordered roots, eigenspaces, local coordinates, finite covers, and cohomology classes.

3.7

A schematic example: rational root clusters

Let p code a monic rational polynomial and let the query q = (N, r) request information about roots
in a rational box at mesh 2−N , with multiplicity cutoff r. A certificate can contain a list of rational
boxes, Sturm or resultant signs, and multiplicities. The verifier checks coverage, disjointness at
the requested mesh, and the coefficient identities. The observation is the multiset of boxes and
multiplicities, or the first r elementary symmetric functions. At a collision there is no exact ordered
root label, but the multiset observation remains stable. Under an additional separation residual,
the same interface refines to ordered labels. Nothing in the representation requires a discontinuous
global branch selector.

Composition

Theorem 5.2 (Compositionality). If R : X → Y and S : Y → Z are FIBER realizers, then there

bundles the resulting Y -certificates, and then runs TS . Bounds and all operations are primitive

or metric stability composes by transitivity or the triangle inequality. Local certificates are sealed.

make associativity hold only up to a provable coding equality, but the exported observation is
unchanged; normalizing all flattened demands to one canonical sequence code makes composition
strictly associative at the metadata level.
Corollary 5.3 (Reuse under arbitrary terms and contexts). A compiled closed interface theorem
can be specialized at arbitrary object terms and used under arbitrary client hypotheses.
Proof. Apply LeanProofs.IPRA.inst to substitute the terms and then Prf.ofNil or weakening
to add the client context. This is why reusable lemmas should be stated either at arbitrary terms or
in an explicitly universally closed form.

5.5

Soundness versus completeness

The compilation theorem is a soundness theorem: every accepted program yields an iPRA derivation
from its explicit residuals. It does not assert that every iPRA theorem has a convenient FIBER
presentation, nor that every classical proof can be mined automatically. This asymmetry is intentional.
The source language is a disciplined fragment optimized for finite, quantitative mathematics and
auditability.

5.6

Why the framework is not merely a checker generator

A checker alone proves only a conditional statement of the form “if this finite code verifies, then the
local conclusion holds.” The compiler also tracks:

6.5

Residual factoring

Residuals should be factored at the lowest reusable level. For example, a “root branch theorem”
may appear to require one monolithic residual, but it usually decomposes into:
1. exact coefficient presentation;
2. a rational isolating box;
3. a derivative or resultant separation margin;
4. a polynomial interval-evaluation certificate;
5. and a requested precision.
The last three may be bounded decidable data once the first two are supplied. Factoring lets
a later theorem discharge only the genuinely new producer and reuse the finite checker. The
same principle applies to analytic constants, finite covers, representatives of descent classes, and
topological carriers.

6.6

Non-eliminable examples

The framework does not manufacture missing effective mathematics. In particular:
• Finiteness of a Diophantine set does not supply a computable height cutoff. A complete
bounded enumeration requires an effective height theorem or a complete list theorem.
• Finiteness of a Selmer set does not supply rational points representing all locally soluble
covering classes. Representative production and compatibility remain separate formulas.
• Compactness in an abstract completed space does not supply a finite net in the chosen coding.
A net and a coverage modulus must be produced.
• Metastability for every control function does not by itself give a Cauchy rate. A tail modulus
or summable adjacent-motion estimate is new data.
• A classical proof of ¬¬∃xA(x) does not yield a witness unless the conclusion is stable, bounded
decidable, or accompanied by a producer.
In each case FIBER still contributes something useful: it turns the remainder of the proof into a
verified finite consumer and states the missing theorem in a form that can be attacked independently.

Metastability is a separate interface

data, such as a summable adjacent-motion estimate or an independently supplied tail modulus.

7.5

Guarded partial operations

A statement such as d ̸= 0 is generally too weak for stable numerical division. The useful interface
is a positive apartness margin:
|d| ≥ η > 0.
At target precision n, the demand transformer requests enough precision on d and the numerator
to keep interval error below a fixed fraction of η. Interval or Newton certificates then verify the
reciprocal and the quotient. The same pattern applies to pivots, logarithms, square roots away from
zero, normalized eigenvectors, and branch labels. The guard is a residual if no effective lower bound
is known.

Worked analytic pattern: certified bisection

For a rational polynomial p, an interval [l0 , r0 ], and a target precision n, a certificate contains the
bisection trace (lk , rk )k≤n . The verifier checks:
p(lk ) ≤ 0 ≤ p(rk ),

rk − lk = 2−k (r0 − l0 ),

and verifies that (lk+1 , rk+1 ) is the half selected by the exact rational sign of the midpoint. These
are finite polynomial and order calculations. A uniqueness claim additionally requires a guard: for
example, a certificate that
p(y) − p(x) = (y − x)Q(x, y)

and Q(x, y) ≥ λ > 0

throughout the interval. Then two zeros satisfy (y − x)Q(x, y) = 0, and positive cancellation gives
x = y. This avoids an appeal to the classical mean-value theorem and fits the checked ring/order
library.

8

Algebraic objects, branches, and stable observations

Several packet difficulties are caused not by weak arithmetic but by asking for a discontinuous name.
Ordered roots at a collision, a normalized eigenvector for a repeated eigenvalue, a rotation axis at
the identity, and an exact sign for an arbitrary Cauchy real are not stable observations. FIBER
separates the finite relation from a guarded label.

8.1

A finite-use obstruction to exact sign

Theorem 8.1 (No unguarded finite-use exact sign selector). No deterministic procedure that, on
each input Cauchy name, inspects only finitely many approximants can return the exact trichotomy
−1, 0, +1 correctly for every real represented by an arbitrary rapidly convergent rational name.
Proof. Run the procedure on the zero name. During this computation it inspects a finite set of
indices; let N exceed all of them. Construct a valid name for the positive real 2−N −3 whose first N
queried approximants are identical to those of the zero name and whose later approximants converge
with the required rate. The procedure follows the same finite computation and returns the same
output on both names, so it is wrong on one of them. The same argument works for a negative
perturbation.
The theorem is a continuity argument about representations, not a statement that signs can
never be decided. A positive separation witness |x| ≥ 2−k makes the sign decidable from sufficiently
precise approximants. Therefore the correct interface is
Sign(x, k, s) : |x| ≥ 2−k −→ s = sign(x),
or a relational output “x lies in this interval” when no gap is known.

8.2

Root clusters instead of global labels

Let P (T ) be a monic polynomial of fixed degree d. The coefficient vector is stable under perturbation;
an ordered list of roots is not stable at collisions. FIBER therefore uses one of three outputs.
Symmetric observation. Elementary symmetric functions, power sums, resultants, or the companion matrix. These remain exact at collisions.

Cluster observation. A finite list of disjoint boxes with multiplicities and a coverage verifier. The
ordering of boxes is irrelevant.
Guarded labels. Under a positive separation residual between clusters, a canonical ordering and
individual root names can be selected.
Theorem 8.2 (Stable cluster transport). Suppose two valid certificates for a polynomial at mesh ϵ
give cluster families C and C ′ . If both certificates prove complete coverage with multiplicity and every
cluster has diameter at most ϵ, then the bipartite overlap relation has a finite multiplicity-preserving
matching after clusters within distance 2ϵ are merged. Every symmetric or 2ϵ-stable observation
therefore agrees.
Proof. Form the finite incidence graph whose vertices are clusters from the two certificates and
whose edges record nonempty overlap of their inflated boxes. A root counted by one complete
certificate must be counted by the other, and multiplicity is conserved on each connected component.
The component totals therefore agree. Merging each component gives a common coarsening with
the same multiplicities. A stable observation changes by at most the prescribed modulus under the
diameter and inflation bounds. The graph, component labels, and multiplicity equations are finite
objects; a certificate can contain a spanning forest and the checker can verify every equation.
This theorem is deliberately relational. It does not construct a globally ordered root list at a
collision.

8.3

Guarded exact labels

Proposition 8.3 (Gap-guarded labeling). Suppose a cluster certificate gives d singleton clusters
and a rational gap η > 0 such that distinct clusters are separated by at least η. At any precision
finer than η/4, lexicographic ordering of the rational boxes is independent of the valid certificate.
Hence individual labels are certificate-independent and may be exported.
Proof. Two valid boxes for the same root overlap after inflation by their error radius. Boxes for
different roots cannot cross or exchange order because the total uncertainty is less than half the
certified gap. Thus the overlap matching is unique and preserves lexicographic order. The proof
consists of rational order inequalities and finite matching verification.
The same pattern applies to eigenvalues. Without a gap, export the characteristic polynomial,
spectral clusters, or projectors onto a cluster. With a gap and a normalization guard, export a
labeled eigenvector. For rotations, export a unit quaternion modulo sign or a projective axis relation;
only away from the identity should an exact axis label be requested.

Theorem 8.4 (Finite-algebra observation). From such a certificate, multiplication by each xi is
represented by a D × D matrix. Every polynomial observation is represented by a matrix polynomial.

functorial observations. If the certificate is transported under a coefficient substitution or quotient

8.5

Exact versus approximate Puiseux output

A uniform exact Puiseux branch selector from arbitrary Cauchy coefficient names is obstructed
for the same reason as exact sign: arbitrarily small coefficient perturbations can split or permute
branches. Three corrected interfaces are available.
1. With exact algebraic or splitting data, output a finite list of Puiseux expansions and a
permutation-invariant certificate.
2. With approximate coefficients, output clusters of truncated expansions and residual bounds.
3. Under a discriminant or resultant separation guard, refine clusters to labeled branches.
At each finite truncation the Newton polygon, coefficient equations, and residual checks are
finite. What fails without additional data is not the finite algebra; it is stable global naming.

8.6

Descent and representative relations

Arithmetic geometry often produces a finite class set but then informally chooses rational representatives. FIBER uses a relation R(c, w) between a class code and a representative witness. A finite
strategy or viability certificate verifies compatibility along the proof graph. Public conclusions that
depend only on the class seal the witness. Conclusions that require an actual rational point retain
∃w R(c, w) as a residual unless a representative producer is proved. This prevents Selmer classes
from being silently identified with rational covering points.

Combinatorics and finite algebra

Finite identities, recurrences, and inequalities are the easiest class. A proof normally needs:
1. a primitive-recursive symbol for the sequence or finite object;
2. defining equations at arbitrary object terms;
3. a quantifier-free induction invariant;
4. a ring, order, finite-sum, or bounded-search derivation;
5. an explicitly universally closed endpoint.
The checked library already supplies most of this. FIBER adds value when a packet uses a large
finite certificate or several independently generated witnesses. The certificate is encoded, its checker
reflected, and local witnesses sealed. Examples include finite graph colorings, tiling boundary checks,
coefficient identities, truncated series, recurrence tables, and finite matrix calculations.

9.2

Real and complex analysis

An analytic object is represented by a family of finite queries. A typical interface contains:
• a precision or derivative-order query;
• rational or dyadic approximation data;
• a residual, interval, or coefficient verifier;
• a local modulus or tail bound;
• an observation relation identifying independent valid certificates;
• guarded operations for division, logarithms, branches, and inverses.
The compiler never assumes that a pointwise family is coherent. Coherence is proved by adjacent
motion, a summable tail, nested intervals, or a viable path. Finite-net lifting replaces compactness.
Contour and quadrature arguments are finite polygonal or mesh calculations plus explicit local error
bounds. Analytic continuation is represented by a finite chain of overlapping discs, with transition
certificates and a spanning-tree compatibility proof.
For special functions, identities divide into three layers:
Exact finite algebra. Coefficient recurrences, truncated products, differential equations after
coefficient comparison, and polynomial transformations. These should be the first objecttheory milestones.
Effective local analysis. Convergence in a guarded domain, with a displayed majorant and tail
modulus.
Global continuation or asymptotics. A finite path/sector certificate plus effective constants.
Missing constants remain residuals rather than being imported as opaque host data.
This layering gives a realistic route for the Gamma, Beta, Barnes G, hypergeometric, Meijer G,
Lambert W, and normal-distribution packets. It also prevents a successful finite-series check from
being reported as a complete object proof of the analytic function.

9.4

Topology and geometry

Completed spaces are replaced by finite carriers:
• simplicial or cubical complexes;
• rational polygonal curves;
• finite covers and nerves;
• grid approximations with refinement maps;
• crossing, orientation, or winding certificates;
• local chart tuples with overlap checks.
A topology theorem at a fixed query becomes a finite combinatorial theorem plus an approximation producer. For example, a Jordan-curve query may request a grid fine enough relative to a
separation modulus; a flood-fill certificate then proves the finite inside/outside claim. Invariance under refinement is an observation theorem. The existence of the required separation or approximation
modulus is a distinct producer.
Finite gluing does not require a global sheaf object. Given local data on a finite cover and
equality or error certificates on overlaps, choose a spanning tree of the overlap graph. Transport
observations to a root along the tree. Exact cocycle compatibility gives equality; metric edge errors
add along the path. Remaining cycle edges are consistency checks. This is the “observational
descent” principle in a form directly compilable by FIBER.

9.5

Diophantine and arithmetic geometry

A bounded search can verify all solutions below a supplied height. It cannot prove that there are no
larger solutions without an effective height or complete-list theorem. The correct interface has two
parts:
1. a finite enumerator and verifier parameterized by a bound H;
2. a residual producer asserting that every relevant solution has height at most H, or that a
supplied list is complete.

FIBER-iPRA

Once the producer is available, least search and master-certificate formation can construct
canonical lists, counts, and finite invariants. Without it, the finite consumer is still reusable and the
missing arithmetic theorem is isolated exactly.
For descent methods, class codes and rational representatives are separated. A finite relation
records which representatives realize which class. A backward viability certificate chooses a
compatible path through a finite relation only when every node has a certified continuation.
This resolves nonunique local witnesses; it does not prove that every abstract class has a rational
representative.

9.6

Prime distribution and ineffective constants

An asymptotic theorem used at a concrete input should expose:
• the threshold N0 ;
• all constants in the error bound;
• the range of moduli or parameters;
• and the arithmetic checker for the final inequality.
If a classical proof establishes existence of constants but gives no primitive-recursive producer
or bound, those constants are residuals. A finite computation that finds plausible constants for a
range is evidence for an instance, not a uniform proof. When a verified explicit estimate is available,
its constants become ordinary input terms and the downstream argument is compiled by order and
bounded-sum lemmas.

9.7

Computability and proof coding

The checked bridge and endpoint inventory already emphasize exact theories, exact formulas, literal
tables, and replay provenance. FIBER applies the same discipline to proof-coding reductions:
1. keep the exact outer theory in the theorem type;
2. separate semantic equivalence from an object-theory derivation;
3. treat a machine table, polynomial, or proof predicate as pinned data;
4. prove local arithmetic in the ordinary portable calculus;
5. translate at the Foundation or application boundary;
6. record directions, premises, and double-negation strength exactly.
A semantic Lean theorem about a machine and an iPRA proof of a coded nonhalting statement
are different endpoints. The framework does not merge them in a status ledger.

9.8

Classical arguments

FIBER supports three constructive replacements for classical reasoning.
1. Reflected bounded cases. A decidable finite atom yields an object proof of the finite
disjunction; branches are joined by orE.
2. Finite strategy certificates. Fixed bounded alternation is realized by theorem 4.11.

10.10

Compiler implementation strategy

There are two reasonable stages.
Stage A: trusted Lean generator. Represent a well-formed finite program as an inductive Lean
datatype whose constructors contain the local Prf proofs. Define compile by recursion, returning
a Prf term. Lean’s kernel checks the result; the generator itself need not be verified as an object
program.
Stage B: certificate-producing external frontend. A Python or Lean elaborator may parse
JSON metadata, synthesize primitive recursive terms, and emit Lean source. Its output is still
checked by Lean. The external tool is not in the trusted base. Keep generated formulas and node
IDs deterministic so proof artifacts can be diffed and replayed.
Do not begin with an internal self-interpreter. The diagonal obstruction and the size of syntaxsubstitution proofs make that interface both impossible in the strongest form and unnecessary for
the repository’s goals.

Required checks

11.4

Research boundaries not removed by the framework

FIBER resolves representational and compositional obstacles. It does not by itself prove:
• general effective Faltings, Siegel, Roth, or Mordell–Weil generation;
• effective Chebotarev, Siegel–Walfisz, or Bombieri–Vinogradov constants beyond what is
explicitly supplied;
• a finite presentation or modulus for every abstract compact space;
• a Cauchy rate from metastability alone;
• an exact branch, sign, eigenvector, or axis selector at degeneracy;
• rational representatives for arbitrary abstract descent classes;
• a universal primitive-recursive evaluator;
• or automatic extraction from every classical proof.
For each boundary the framework gives either a corrected theorem or an exact producer formula.

12

Conclusion

The ProveIt iPRA development has reached a point where the central problem is architectural
rather than foundational. The ordinary calculus, its small native core, a bridge to Foundation, and
a substantial object arithmetic library already exist. The proof packets show that a large range of
mathematics can be reorganized into finite quantitative claims. What is needed is a reliable path
from those claims to literal object derivations.
FIBER-iPRA supplies that path in a deliberately conservative form. Queries index finite
certificate fibers. Demand maps expose finite use. Local certificates are sealed. Public codes are
selected only by proved bounded search. Noncanonical objects export stable observations rather than
impossible labels. Bounded loops use quantifier-free state invariants. Composition is substitution
and simultaneous cut, not semantic wishful thinking. Missing effective information is a formula, not
an unstated host parameter.
The framework also clarifies why several difficult-looking requests should be reformulated. A
global exact branch at a collision, a Cauchy rate from mere metastability, a height cutoff from abstract
finiteness, and an internal universal primitive-recursive evaluator are not reasonable implementation
milestones. Cluster observations, summable-tail contracts, explicit height producers, and metalevel
specialization are the correct replacements.
The next decisive step is not another broad packet. It is a small checked kernel: search adaptation,
finite certificate bundling, demand closure, and the dyadic coherence theorem, all as Prf PRAAx.
Once these are in place, the repository’s many finite proof plans can share one audited compilation
route, and the remaining deep residuals will stand out as the mathematics they genuinely are.

A.4

Compilation judgment

The compiler returns

where πP is a Lean value whose type is the appropriate Prf PRAAx sequent. The correctness theorem
is therefore intrinsic: there is no separate untrusted claim that the generated proof is valid. Lean
accepts or rejects πP .

A.5

Operational reference semantics

A standard natural-number evaluator is useful for tests. It maps a query and certificate to either
rejection or an observation. The evaluator has no logical authority. The object soundness theorem
is generated independently from local derivations. Keeping the executable semantics and proof
compiler separate makes it easier to detect a checker whose host behavior is correct but whose
object reflection theorem is missing.
