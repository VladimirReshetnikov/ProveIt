## 2. The precise `Term 0` correspondence

README 326–335 and article 170 correctly identify the counted syntax with intrinsically scoped de Bruijn terms. Here “exactly the set” is understood as a canonical bijection, not literal definitional equality between a named-term quotient and a Lean inductive type. A closed alpha-class has an ordered unary/binary syntax tree, and each variable leaf selects one enclosing abstraction. Number enclosing binders from the nearest outward: at depth `d` this gives an element of `Fin d`. Preserve application order and turn each abstraction into `Term.lam`; recursively this constructs `Term 0`. Conversely, traverse a `Term 0` with a stack of fresh binder names and interpret each `Fin d` index by its stack entry. Different choices of fresh names are alpha-equivalent, and the two constructions recover the original binding tree and indices. There is no index-length weight or quotient by beta reduction.

In an outer context of size `m`, the three constructor cases give `m` variable choices, one extra available binder under abstraction, and an ordered pair of terms under application. This is precisely `T_m=m+z*T_(m+1)+x*T_m^2`. For the report's size grading, count each application and abstraction once and each variable `s` times. This preserves `u+b+s(b+1)` under the syntax correspondence. For the Rocq representation, choose `V=Empty_set` for closed terms and interpret successive `option` layers as the binder stack; `term V` for arbitrary nonempty `V` includes free variables.

This hand correspondence is not a new Lean/Rocq theorem or build. The cited Lean source still provides weak contextual beta: root contraction and both application contexts, with no reduction beneath a lambda. Counts by syntax size and maximum unary depth do not give a duration, chosen strategy, acceptance predicate or paid arithmetic compiler. The prior scope review's semantic/arithmetic bridge remains open.
