## 2. Literal spelling, names and event schema

A positive integer is a generator ID, a negative integer its formal inverse. IDs are allocated consecutively from 1; each name is `operation_label/private_role`. Inversion reverses a word and negates its letters. Integer powers repeat the word or its literal inverse. Concatenation appends tuples. Conjugation is exactly

    conjugate(word, by) = inverse(by) + word + by.

There is no free reduction, commutation, cyclic normalization, group equality test, subgroup-membership test or word-problem computation. Even adjacent inverse letters remain in the emitted word. The empty word is an empty array. Exact tuple equality in the syntax guards checks only spelling.

Each relator record stores its zero-based index, operation-event ID, family/slot string, singleton stable letter, source word, target word and the complete relation word

    inverse(stable) + source + stable + inverse(target).

A fixing relation has identical source and target strings. In rho's direct product, old generator x and fresh generator y contribute `x^-1 y x y^-1`, using x as the stable-field spelling; that field does not claim x was newly adjoined at that row. The relator merely imposes commutation. Generator records include their ID, unique name, event and the number of previously emitted relators at declaration.

Every event records its operation kind and inputs, exact before/after counts and marker/A/shift words, cache fingerprints in creation order, newly allocated generator IDs, a half-open relator interval, selected cache name and any checkpoint. A new cache entry is preserved as a literal birth snapshot in that event. Wrapper details record the role-alias maps, exact auxiliary base lists and extraction data. A marker-changing event additionally records its fresh transport letter and every cache name transported. These data, together with final full lists, permit an independent constructor to check every intermediate transformation. Hashing is byte/string metadata, not group evaluation.
