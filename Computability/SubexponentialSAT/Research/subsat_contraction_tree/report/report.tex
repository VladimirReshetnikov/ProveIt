\begin{abstract}
We review fifteen refinement packets through the closing snapshot
\nolinkurl{ProveIt@474ddba696a5d385c091c23fb2995f69edd13e00}.
The initial snapshot contained seven placed packets and seven incoming archives; a final
placement check added one matching-based packet without changing the frontier.
Their ingredients compose: full-orientation Cauchy modes, asymmetric packet balancing,
sharp Hermite precision, and cached mode-graph evaluation give a substantially stronger
baseline than any standalone report indicates. We obtain two further results.
First, constructing cached group tables by a binary contraction tree, and implementing
fast matrix multiplication through exact integer-coordinate lifts, gives a relative
contraction certificate
\[
 T(s,\mathcal L)\le\poly(s+\mathcal L)
 2^{(35.3545880584\ldots+o(1))s/\sqrt{\log_2s}},
\]
with space coefficient $34.2748030050\ldots$ on the same scale, under the common
high-degree network interface. The proof pays for every recursive child and for exact
arithmetic over the two-adic coefficient ring; it does not posit a free group oracle.
Second, a constant-storage recurrence reduces the generation of $B$ Cauchy features
at $P$ ports from $O(L+PB^2)$ to $O(L+PB)$ ring operations at unchanged precision.
A matched modular implementation gives a measured $101.95$-fold local speedup for
one $B=512$, 128-bit fixture, with identical outputs. The report gives complete proofs
of the new components, exact finite checks, paired benchmark data, and integration notes.
The general SAT logarithmic order is unchanged. The numerical constants count network
wires, not SAT variables, and the asymptotic result retains the stated upstream
contraction and reduction dependencies. No complete SAT solver or new Lean/Rocq
certificate is claimed.
\end{abstract}

\section{Results and the comparison that matters}
\label{sec:results}
The requested comparison is with an upper bound incorporating all the existing proposals.
It is therefore insufficient to compare only with the original preprint or with the
smallest number printed in an individual report. We explicitly compose compatible
improvements and retain separate time--space regimes.

\subsection{Two concrete advances}
The new asymptotic component changes how the cached mode graph is evaluated. A cached
function for a subset of groups has only the indices crossing that subset as arguments.
Joining two disjoint subsets is a rectangular matrix multiplication: the shared internal
indices are summed out, and their external indices form the output table. Constructing
larger block tables this way avoids the earlier exhaustive enumeration of every incident
index in a block. A fixed field matrix multiplication exponent below $12/5$ is a classical
available ingredient \cite{mm2024}; an explicit lifting argument makes it safe for the
actual quotient rings used by the SAT framework.

The new implemented component reuses the prefix products in the full-orientation Cauchy
basis. It preserves the mode weights, exact target/source features, and working precision.
Its operation-count improvement is unconditional for the specified kernel, and it can be
used in both polynomial-space streaming and cached contraction variants.

The final row implies the simple eventual bounds
\[
 T\le\poly(s+\mathcal L)2^{35.36s/\sqrt{\log_2s}},\qquad
 S\le\poly(s+\mathcal L)2^{34.28s/\sqrt{\log_2s}}
\]
for all sufficiently large admissible inputs. The $35.36$ and $34.28$ are rounded
\emph{upward} after absorbing the vanishing errors. This improves an explicit exponent
coefficient, not the power of the logarithm. An improvement of upper bounds alone is
not a measured ratio of SAT running times.

\subsection{What can and cannot be compared numerically}
The size $s$ is the number of Boolean network wires. A general-density SAT reduction
uses $s=O_k(n\log\log n)$; density-sensitive variants use fewer wires in intermediate
regimes. The constants hidden in that reduction must be tracked before placing a numerical
coefficient on a formula in $n$. In particular, $35.354588$ must not be substituted for
the hidden constant in the general SAT bound.

The separate manuscript credited to Claude states the same relevant logarithmic order
with unspecified comparable constants \cite{claude}. No numerical dominance over that
unspecified constant follows. Likewise, conditional proposals involving an unconstructed
summation or compression algorithm cannot be treated as already implemented algorithms.
Our result neither disproves those targets nor establishes them.

A safe portfolio statement is useful. Retain all admissible existing algorithms and add
the new cached variant; choose using certified bounds, or dovetail the fixed collection.
Up to a fixed overhead, its time is bounded by the minimum of their guarantees. Thus
special lower-degree regimes and any separately superior construction remain available.
The mathematical result here is a new explicit certificate and a cheaper compatible
subroutine, rather than a claim of an optimal SAT algorithm.

\section{The combined baseline and a replacement guarantee}
\label{sec:baseline}
At an active call, let $M$ be the wire count, $L=2^a$ the packet length, $i$ a retained
valuation, $D=L/2^i$, $r$ the grouping alphabet, and $u$ the taper length.
Near-unit padding has total mass $(1+o(1))M$. The inherited exact recovery analysis gives
\[
 p_t\le (6+o(1))\frac{MD}{u}.
\]
For each directed pair of distinct groups there are at most
$(2+o(1))M/(r^2D)$ mode variables of each index $q$. The full-orientation weights are
\[
 w_q=a+1-i+4q-2s_2(q).
\]
Every mode has exactly one source group and one target group, so replacing its basis
does not add wires or enlarge packet-vertex degrees \cite{joint}.

Partition mode tuples by the exact weight assigned to each directed pair. There are
polynomially many such arrays because $r$ is fixed and $p_t$ is polynomial in $s$.
Each pair's list can be indexed by the ordinary unbounded-knapsack recurrence
$D(j,b)=D(j-1,b)+D(j,b-w_j)$, with exact integers of polynomial bit length.
For an allocated array, let $h_e$ be the logarithm base two of a pair-list length.
The inherited weighted entropy estimate, with the improved padding constant, is
\begin{equation}\label{eq:weighted}
 \sum_e t_e h_e\le\left(\frac{\sqrt{\sum_e t_e^2}}r+o(1)\right)K(M,u),
 \qquad K(M,u)=\frac{\pi\sqrt2}{\ln2}\frac{M}{\sqrt u},
\end{equation}
for any fixed nonnegative weights $t_e$. This bound is uniform even for small or zero
pair budgets; it follows from a common generating-function parameter, not an invalid
large-budget approximation on each edge separately.

\subsection{Reconstructing the existing 16-group cached bound}
The asymmetric supplied schedule has
$u_0\sim\lambda/81$ and $u_d\sim\lambda/(108\,4^{d-1})$ for $d\ge1$, with
$M_d\le(1+o(1))s/8^d$. The full-mode polynomial-space sum therefore has coefficient
\[
 \frac{\pi\sqrt{15/8}}{\ln2}(9+\sqrt3)
 =66.6051434076\ldots.
\]
For the prior cached method, partition the 16 groups into sizes $5,5,6$ and put
$\omega_S=\log_2 7$. The star-cache, naive block construction, multiplication, and
boundary storage factors are respectively
\[
 a_0=\frac{\sqrt{30}}{16},\quad a_B=\frac{\sqrt{150}}{16},\quad
 b_S=\frac{\sqrt{120+50(\omega_S-2)^2}}{16},\quad
 j_B=\frac{\sqrt{120}}{16}.
\]
The root $K$ coefficient is $9\pi\sqrt2/\ln2$. Since the fully charged tail is smaller
than the root multiplication term, the existing composition has time coefficient
$44.5375718550\ldots$ and space coefficient $39.4959495337\ldots$.
This also shows why a new polynomial-space coefficient of 50 or 60, by itself, would
not improve the unrestricted-time frontier.

\subsection{Why the replacement preserves the matched bound}
For a block $U$ of $k$ groups, the old construction enumerates all its incident directed
pair axes, whose number is $2k(r-k)+k(k-1)$. If $U=A\sqcup B$, with $|A|=a$ and
$|B|=b$, the new merge has only its $2k(r-k)$ boundary axes and the $2ab$ shared axes.
Since
\[
 2ab\le k(k-1)\qquad(a,b\ge1),
\]
even the straightforward merge has no larger entropy certificate than that block's
old exhaustive construction. Every intermediate subset has its incident axes contained
in those of the final block. Fixed $r$ means there are only a constant number of merges.
A faster matrix multiplication backend further lowers the merging bound; it also
lowers the final three-block multiplication bound relative to Strassen. The star-cache
cost and recursive child oracles are unchanged.

For the storage comparison, require each top-level block to contain at most $r/2$
groups. Its intermediate subsets then have no larger boundary-table envelope, since
$2j(r-j)$ increases for $j\le r/2$. Thus, for \emph{every fixed admissible schedule
and three-block partition satisfying this block-size condition}, the new local time
envelope is no larger and storage retains the old boundary-table envelope. All balanced
partitions used here satisfy the condition. The old builder may be retained for more
imbalanced partitions. Recurrence monotonicity carries the replacement through the recursion. It need not give a strict leading gain on a schedule whose child
cache cost is already the bottleneck. The explicit schedule proved next makes the gain
strict. This pointwise replacement statement is stronger and more informative than
claiming that one arbitrary old parameter choice was globally optimal.

\paragraph{A matched ablation of the two changes.}
Use exactly the new strict root/tail schedule below for all three variants. The earlier
flat block builder with Strassen has coefficient $38.4844959057$. Giving that same flat
builder the faster exponent-$12/5$ backend reduces the coefficient to $37.5461655198$;
its root table-building term is $(3/4)K_0^*$. Replacing flat construction by the binary
tree reduces it further to $35.3545880584$, a $5.84\%$ coefficient decrease from that
already strengthened control. These are analytical upper-bound comparisons at matched
parameters. The improvements are not inferred from a search for an optimal old schedule.

\section{Executable evidence and reproducibility}
\label{sec:evidence}
The code consists of local exact kernels and finite proof checks. It does not invoke a
SAT solver and does not implement the full asymptotic matrix multiplication algorithm.
The fast-backend theorem imports an established algebraic algorithm; the executable CRT
checks test the ring interface and reconstruction independently of that asymptotic backend.

\subsection{Exact checks}
The prefix verifier uses an independent direct product control in the same modular ring,
and optionally loads the unchanged supplied rational implementation from the pinned
incoming archive. The recorded normal and optimized-Python runs agree. They check:
\begin{itemize}[leftmargin=1.5em]
\item 69 parameter cases and 8,564 target/source feature values against the direct
modular control;
\item 3,124 feature values against the unchanged rational baseline;
\item 2,112 reconstructed crossing-matrix entries against direct evaluation;
\item 11 zero-prefactor fixtures, invalid parameter rejection, and a deliberately
incorrect valuation normalization that the checker detects.
\end{itemize}
These checks include non-prime-subring interpolation values in the unramified quadratic
ring $(\mathbb Z/2^p\mathbb Z)[U]/(U^2+U+1)$. The proof applies to arbitrary finite
unramified extensions, but that general extension-degree implementation is not included.

An independent cached-table checker verifies 48 small networks, 144 binary merges,
14,448 table entries, and 48 three-block contractions. It also verifies 72 rectangular
CRT products and 486 product entries, both over $\mathbb Z/2^p\mathbb Z$ and over a
ring with $U^2+U+1=0$ and $V^2=0$, for $p\in\{1,3,7\}$. Two deliberate corruptions
are detected. This independently exercises nilpotents, negative structure constants,
index bookkeeping, and exact reconstruction. Schedule arithmetic checks validate the
rational budget, strict exponent margins, recurrence constants, and merge counts.
Finite fixtures support the implementation and bookkeeping; the all-size theorem rests
on the proofs and their explicitly named imports.

\section{SAT consequences, integration, and remaining questions}
\label{sec:consequences}
The strongest density-sensitive order claimed by the reviewed reductions remains
\begin{equation}\label{eq:sat-envelope}
 \poly_k(n,m)\,
 2^{O_k\!\left(\frac{n}{\sqrt{\log n}}
       \min\{\log(2+m/n),\log\log n\}\right)}.
\end{equation}
At fixed density this is $\poly_k(n,m)2^{O_k(n/\sqrt{\log n})}$.
At $m=\Theta(n\log\log n)$, the numerator can be
$n\log\log\log n$. Neither new component changes these logarithmic orders.
The cached variant uses subexponential space; it must not inherit a polynomial-space
label from the underlying streamed algorithm.

The full construction is conditional only in the explicit, ordinary sense of importing
the source framework and established algebraic results. Its new table construction,
ring reduction, and schedule do not assume the unprovided mode-summation oracle from
the stronger earlier conjectures. Still, the review did not certify the complete ETH
claim from first principles, compile its formal development, or produce a full solver.
The corpus-level trust status should remain unchanged until those larger tasks are done.

\subsection{Integration plan}
Keep the immutable tensor-description and creation-precision conventions. At each call,
use the improved pair balancing and full-orientation Cauchy modes. Form exact-weight
pair lists, pay for each cached group value through the existing child contraction, and
then build the three boundary tables via the specified binary trees. Use the exact
coordinate/CRT wrapper for the fast field backend. The implementation can choose
Strassen or direct multiplication at small sizes without affecting the asymptotic theorem.

For the working prototype, replace the repeated-product feature evaluator with
\nolinkurl{PrefixKernel.features}. If a generalized extension-ring implementation already
exists, the same valuation/unit recurrence can be ported into that arithmetic layer.
Do not obtain normalized features by dividing a reduced residue by a power of two;
that would lose information. Track the power separately from the outset.

An appropriate integration location is a new research directory beneath
\nolinkurl{Computability/SubexponentialSAT/Research}. Add a row describing the exact theorem
and the local benchmark scope. Keep the new report, scripts, recorded results, and
source manifest together. This archive does not modify the remote repository.

\subsection{Further research questions}
\begin{enumerate}[leftmargin=1.6em]
\item \textbf{Can cached contraction exploit the observed pair entropies?}
The bound uses a worst-case Cauchy--Schwarz estimate for edge classes. For a particular
exact-weight array, its actual list lengths may favor a different split tree or a
rectangular multiplication routine. An optimizer over the fixed group set is feasible;
proving a uniformly smaller coefficient requires analyzing all budget distributions.
\item \textbf{Can a smaller-space algorithm obtain the same time coefficient?}
Recomputation, separator schedules, or batched boundary slices may interpolate between
polynomial space and full caching. The cost of reconstructing a group value must remain
explicit. A memory reduction without paying its repeated oracle calls would be spurious.
\item \textbf{Can actual sparse port sets beat the padded Smith profile?}
The slope-four invariant factors are optimal for the complete padded crossing block
under invertible integral basis changes. They do not constrain a submatrix with many
missing real ports. An instance-sensitive pivot order could reduce finite mode lists;
the cost of finding it must be included.
\item \textbf{Can the $O(L)$ common prefactor and remaining inversions be reduced?}
The prefix recurrence removes quadratic repetition. Product trees, denominator reuse,
or batch unit inversion could improve further constants, with a controlled memory
tradeoff. A fair benchmark should keep both precision and arithmetic representation fixed.
\item \textbf{Can the logarithmic order be improved?}
The existing linear mode-weight growth and retained-level packing budget still yield
$M/\sqrt{\log s}$. A faster summation theorem or a smaller valid SAT-to-network encoding
would be needed for a different order. The proposed $n/\log n$ interfaces remain open.
\item \textbf{Can the pipeline become an executable, formally checked counter?}
The next substantial engineering step is a complete exact contraction engine with
canonical precision tags, entry oracles, interpolation, group caching, and certified
cost accounting. This would enable meaningful SAT benchmarks and provide clear targets
for Lean or Rocq verification.
\end{enumerate}

\section{Evidence ledger and limitations}
The package separates three types of evidence. Mathematical proofs establish the new
all-size statements relative to their named imports. Deterministic exact checks exercise
the finite identities and implementations. Timings measure only the supplied local
kernel under the recorded environment. None of these categories substitutes for the others.

The source pin freezes the review while the repository continues to evolve. A later
commit may contain another improvement; the recorded path history and digests make this
comparison reproducible. The report does not claim a lower bound on any old algorithm's
actual running time, a globally optimal coefficient, or a priority result beyond the
reviewed corpus. The very small positive packing margins imply potentially enormous
asymptotic crossover sizes. The prefix benchmark is the concrete practical result that
can be reproduced immediately.
