# Source dependency map and reconstruction boundary

The exact new finite reconstruction begins from `parent.json` and
`domain.json`. They are immutable literal data, bound by SHA-256 to the
round-14 incoming archive in `../SOURCE_LEDGER.json`. The new builder,
both independent checkers and the evaluator require no omitted files,
network, old archive tree or proof-assistant installation.

The mathematical interpretation invokes inherited ordinary theorems. Their
immediate proof texts are retained as follows:

| Mathematical dependency | Local preserved source |
|---|---|
| Signed power compiler, source Horn factorization, direct C222 endpoint | `inherited_signed_proof.tex` |
| Derived label range and small factorial horizon | `DERIVED_LABEL_RANGE_PROOF.md` |
| Pairwise-coprime factorial label carrier and unordered Horn-flow soundness/completeness | `FACTORIAL_CARRIER_PROOF.md` |
| Reciprocal prime-power CRT and noncircular digit order | `HYBRID_PROOF.md` |
| Self-bounding factorial lemma, including its two directions | `shared_radius_proof.md`, Section 1 |

| Amplified range decoding and precision needed for CRT completeness | `AMPLIFIED_CRT_PROOF.md` |
| Signed comparison coordinates and signed comparison base | `signed_comparison_index_proof.md`, `signed_comparison_base_proof.md` |
| Earlier Horn-flow/calculus bridge | `calibration/COMMUTATIVE_CERTIFICATES.md`, `calibration/inherited_onestack_section.tex` |
| Named logical endpoint interfaces | `calibration/KEndpoint.lean`, `calibration/ConstructibleChoice.lean` |

The new proofs are `../PROOF.md` and the accompanying report section.
The independently authored review is `../INDEPENDENT_MATHEMATICAL_REVIEW.md`.
They explicitly distinguish the earlier signed-comparison theorem and the
inherited arithmetic/calculus bridge from the present factorial bootstrap,
deferred signs, coupled guard and mixed frame.

The preserved source files intentionally keep their historical endpoint
counts, directory references and reproduction commands. Those references
resolve inside the exact original archives listed in the ledger; they are
not new executable entry points in this component. In particular, this
component does not rerun the old compiler that produced `parent.json`, nor
rebuild a complete transitive Lean development. The old factorization
certificate is retained as provenance; its older input system is not a
runtime input of the new reconstruction. Its mathematical identity is
proved in the retained signed source text.

All new finite transformations from the pinned literal parent through the
final residuals and collected polynomial are checked locally and exactly.
That is the portable reconstruction claim. The new package does not claim
to close every upstream Lean import, supply a sealed object-ZFC proof,
prove consistency, decide root existence, or establish global optimality.
