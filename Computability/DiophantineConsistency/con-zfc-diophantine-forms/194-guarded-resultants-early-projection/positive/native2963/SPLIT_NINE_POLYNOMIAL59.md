# A literal split116 nine-variable polynomial

[`SplitNinePolynomial59.lean`](Lean/DiophantineConsistency/SplitNinePolynomial59.lean)
defines a ring-parametric arithmetic recipe and its ordinary integer polynomial
`polynomial ports a : MvPolynomial (Fin 9) Int`. All exponents in the recipe
are fixed natural numbers. The four native coefficient ports remain supplied
integer parameters.

The evaluator uses the complete delivered kernel tables: 7 coefficients in
`D0`, 39 in `D1`, and 43 in `D2`. Their finite sums are proved equal to
evaluation of the checked univariate kernels. For base `B`, the outer data are

```
ell = sum_i B^weights_i
u = ell+g
high = 2*(D2(B)*u^2+D1(B)*u+D0(B))+sum_j B^targets_j
S = g+B^117*high
T = B^117-1-(b-1)*ell+B^117*(B-2)*sum_j B^targets_j
L = b*B^2279
R = L*(S+T+1)-S-1.
```

The base is `B=4096*2^a*b^2`, and the ratio threshold is
`N=2^(8*a+85)*b*B^1201`. These feed the literal free-carrier ratio and its
checked final norm. The mixed-coordinate order is
`b,g,h,s,w,C,i,internal_j,n`. The polynomial uses natural coordinates by
adding one to every input except `internal_j`. Consequently it has exactly
nine available variables and preserves the absorbed index value zero.

`map_value` proves compatibility with every homomorphism of commutative
rings. `eval_polynomial` then proves that multivariate polynomial evaluation
is the literal scalar recipe. `value_eq_naturalValue` proves equality with
`SplitNineSource59.naturalValue` on every natural tuple satisfying the supplied
kernel/geometry bounds. The conversion of source words and rank to integers
holds before any equation zero or weak cap is known, so no truncated natural
subtraction or `toNat` occurs inside the polynomial data.

`exists_natural_zero_iff_source` proves equivalence with the authoritative
31-variable shifted source rows. `exists_natural_zero_iff_source_portBounds`
replaces the kernel premise with the four published port boxes; the
`compact54` specialization uses the sharper exponent `a=864014`. The
corresponding no-zero theorem negates this equivalence. These statements
do not assert native machine or ZFC calibration of the supplied ports.

The ring evaluator is executable arithmetic. The `noncomputable` marker on
the actual `MvPolynomial` comes from its imported finite-support polynomial
operations, not a choice of coefficients. The finite coefficient-map proofs
are generated by
[`generate_split_nine_polynomial59_maps.py`](tools/generate_split_nine_polynomial59_maps.py)
from a SHA-recorded Lean table. Lean checks every generated equality against
that table; the generator is outside the mathematical trust boundary.

The finite-sum recipe does not carry a 473-operation or exact-degree claim.
Those measurements belong to a separate literal circuit and require its
own formal identity with this evaluator. Regression checks cover zero-base
kernel values, the internal index boundary, the exact witness order, and
the ratio interface. Audited declarations use only Lean's standard axioms.
