# Cache-free packaging recheck

The original mathematical audit remains valid for the unchanged equations and
proof. A subsequent clean release replay exposed a separate portability
defect: active SOURCE_PINS.json required
vendor/__pycache__/terminal_elimination.cpython-312.pyc, although the release
inventory correctly omitted generated bytecode. Local verification passed
only because that cache happened to exist in the producer workspace.

The correction removes this non-source dependency. The builder now explicitly
rejects __pycache__, .pyc and .pyo dependencies. Reproduction copies the input
tree without caches, executes only from that clean copy, sets Python -B and
PYTHONDONTWRITEBYTECODE=1, and uses cache-excluding inventories. The new sealing
utility applies the same exclusion to source pins and release inventories,
while checking all surviving authentic source pins before regenerating them.
These changes do not modify the mathematical construction.

The independent checker also rejects cache dependencies before attempting
their reads. Three dedicated regressions cover a nested __pycache__ entry,
a direct .pyc entry, and a direct .pyo entry. These are separate from the eight
existing mathematical malformed-artifact controls. All complete finite checks
are rerun in both normal and optimized Python with bytecode disabled.

The final recheck additionally copies only manifest-listed files into a fresh
directory beneath the review area, requires the copied tree to contain no
cache files or directories, and runs the independently authored checker on
that copy. It imports no producer or downloaded implementation. Exact equality
of its receipt with the ordinary workspace receipt checks that no omitted
workspace file is needed by this independent verification path. The producer
and release packager separately perform full clean-copy generation replays.

PRE_CACHE_FIX_FINAL_SEAL.json and PRE_CACHE_FIX_FINAL_REVIEW.json retain the
superseded packaging acceptance for an explicit audit trail. FINAL_SEAL.json
and FINAL_REVIEW.json, after this recheck, are the authoritative current
acceptance. Their source and endpoint hashes determine the precise scope;
no consistency or new complete proof-assistant verification claim is added.
