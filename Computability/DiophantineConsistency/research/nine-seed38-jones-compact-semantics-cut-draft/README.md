# Macro-DAG semantic proof: proposed cut lemmas

The target is the generated `Norm38MacroRecipe.SemanticTarget`: for every commutative ring and every nine-tuple, the last macro-DAG value equals the checked `Norm38IPRAEndpoint.expression.evalRing`. The [checked `Norm38NamedFormula.eval_current`](../nine-seed38-jones-named-formula-check/README.md) already gives an exact symbolic ring expression for that endpoint. The remaining Lean proof must link the DAG evaluator to that checked right-hand side; it must not infer equality from the independent manual JSON review or the separate boolean scope theorem.

[`Norm38MacroCuts.lean`](Norm38MacroCuts.lean) is a **source-only, uncompiled** first client. It proposes generic facts that `Dag.snoc` retains prior entries and computes its last entry, and that the range and star macros evaluate to the corresponding symbolic finite sums. It uses the successfully compiled `Norm38MacroLanguage`, without importing or reducing the 45-node recipe, giant coefficient recipes, or concrete sum ranges. All four requested axiom reports remain unobserved until a bounded Lean check succeeds.

A practical subsequent proof split is to define transparent named prefixes matching the generated telescope, certify each prefix against the corresponding recipe prefix, and establish node-value equations in small groups using these cut lemmas and already proved earlier nodes. Carry `z`, `y`, `codingStar`, `pCoefficient`, and both finite sums as symbolic terms; do not unfold them into huge literals or enumerate the geometric range. Establish separately that the seed's exact current ports and nine-coordinate `Fin.cons` mapping match the checked evaluator, then combine the named node identities with `Norm38NamedFormula.eval_current`. Prefix definitions and their relationship to the generated `recipe` are not yet implemented; the semantic target is not yet proved.

The separately checked axiom-free scopedness fact only checks binder flags. The source-level JSON-to-Lean quote remains an ordinary unverified translator, and Lean does not read the reviewed Markdown formula. The intended theorem would certify the generated Lean data, not by itself verify those external byte boundaries. Any check of this new client needs a separate authenticated provider/runner, independent review, slot coordination and actual terminal audit.
