\subsection{What to use from the new archive}

\begin{itemize}
\item \pathcode{report/}: this editable TeX source, PDF, build script and QA record.
\item \pathcode{annotated/}, \pathcode{current/}, \pathcode{wang/},
\pathcode{supplemental/}: complete uncompiled candidates, exact patches where
available, explanations and reproducible source-text measurements.
\item \pathcode{incoming_audit/}: exclusion catalog, explicit novelty decisions,
archive identities and audit results, without repackaging the old reports as new work.
\item \pathcode{provenance/}, \pathcode{sources/}, \pathcode{supplemental/evidence/}:
immutable source anchors, byte manifests, recent-commit evidence and selected
source material. Archive contents are evidence, not a replacement checkout.
\item \pathcode{validation/}: future replay plan, non-vacuous endpoint/axiom
checks and static validation tools. Read its instructions before running it.
\end{itemize}

\subsection{Decisions that remain after compilation}

Start with C4, S1, C1 and C2. Then evaluate A2, and A1 if its existing
bounded-decoder dependency is acceptable. C3 requires the correct import
placement. W1 and S2 are optional maintenance choices: compilation alone
does not make their abstraction worthwhile.

Before adoption, establish that the candidates elaborate under the pinned
dependencies, public types and axiom sets meet project policy, and the edits
improve readability. Novelty is relative to the six reviewed packets, not a
claim of global originality. No accepted simplification or performance result
is asserted before that replay.
