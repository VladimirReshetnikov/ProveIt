## Final candidate verdicts

### 1. Supplied-code PR dependency reversal: WITHDRAW

This is now an exact earlier proposal in the new `ProveIt_Proof_Simplification_Review` packet, section A, report lines 90–159. Its patch `patches/01-certificate-dependency.patch` creates `EnumeratorSemantics`, routes `Computability` through `DirectScalarEnumerator`, derives the PR endpoint from the supplied realizer and removes 32 private PR declarations. It even makes the same distinction from prior `fun_prop` automation. The fact that our implementation has additional fresh checks does not restore novelty. Any checked work must be labelled excluded comparative evidence, not a new recommendation.

### 2. Verified whole-list accumulator evaluator: RETAIN, narrowly framed

No new packet proposes the actual evaluator traversal change. The closest new note is Shape/Windows/Growth `audit/prior_art_notes.md` line 113 and `growth/numeric_notes.md` lines 80–81: it discusses affine-monoid **chunk assembly** and rejects mere repackaging of finite-block certificates. That rejected idea is now part of the exclusion baseline too.

The retained contribution must therefore be the proved computational replacement of the power-and-tail-length evaluator by a whole-list accumulator, enabling removal of the *remaining* block certificates and append/length scaffolding after common-modulus reduction. It is not a new common modulus, new chunk monoid, or merely a different wrapper around the same block certificates. The concrete complete-list kernel check and helper-inclusive file reduction establish the residual obligation that disappears.

The source refresh independently confirms that the closing maintained `CurrentKernelResidues2011.lean` is byte-identical to zn's 426-line candidate. Its SHA-256 is `f16f792f4449e423bfa6165f81a6b6e3d8c872531b4e428aaf0bebafd178a659`. The common-modulus stage is now the actual maintained baseline, not merely a hypothetical assumed one. The old 843-line file is obsolete as a savings baseline.

### 3. Direct signed rank prefix residue: RETAIN as a smaller interface strengthening

No exact proposal was found in the 50-package corpus for obtaining `windowRank ≡ -1 mod 2^k` directly from the full low-mask prefix and `2^k | q`, with arbitrary signed F and MF, without the natural packing range/balance hypotheses. The new rank packets establish upper/lower **inequalities**, not this modular interface. Old o's reflected-parity exclusion concerns normalized carry digits. Old zb's affine rank form is an available algebraic predecessor.

The maintained `fourBlocks_mod_four` already contains the bitmask deduction that `(C-1)%4=0`; do not claim that deduction as new. The residual is the direct ring-valued rank conclusion and its weaker dependencies, which avoid transporting through `fourBlocks_cast`. It should remain explicitly smaller than the evaluator change, and should not be credited with a net source reduction without a complete client migration and helper accounting.

### 4. Tag-only Option equality after the earlier PR migration: RETAIN a checked nine-line residual

The new PR packet explicitly retains `stateEquiv`, private `Primcodable St` and `DecidableEq St` in its extracted semantic module (report line 131; candidate `reference/certificate-migration/EnumeratorSemantics.lean` lines 16–23). It explains this as conservative preservation of decision/encoding data. No proposal to remove that scaffold, use `Option.decidableEqNone`, or reduce the decision to the Option constructor tag was located in prior reports/notes/candidate code.
