\section{S Normalize the two Sidon injectivity endpoints}
\refs\ \src{SidonPositions.lean}{94}{100} and \src{SidonPositions.lean}{151}{162}. This proposal consumes the unchanged statement of \code{weight_sum_eq_iff}. The earlier moment-polarization simplification of that theorem is already assumed applied.

\subsection{Use a diagonal pair rather than a distinguished zero}
The original proof adds \code{weight m 0} to both sides, then treats direct and swapped unordered-pair cases differently. Instead, add each weight to itself:
\begin{Lean}
theorem weight_injective (m : ℕ) : Function.Injective (weight m) := by
  intro i j h
  rcases (weight_sum_eq_iff i i j j).mp
    (congrArg (fun n => n + n) h) with h | h <;>
    exact h.1
\end{Lean}
Both disjuncts now have the identical first component $i=j$. No property of the zero position is used. The literal supplied patch is two lines shorter than the original body.

\subsection{Let ordered endpoints discharge the swapped case}
For canonical pairs $p=(a,b)$ and $q=(c,d)$, the retained subtype hypotheses give $a\le b$ and $c\le d$. In the swapped case the Sidon theorem gives $a=d$ and $b=c$. Hence $a\le b=c\le d=a$, so both pairs are equal. The explicit chain of two rewrites, antisymmetry, and transitivity can be replaced by linear arithmetic after extensionality:
\begin{Lean}
theorem pairWeight_injective (m : ℕ) :
    Function.Injective (pairWeight (m := m)) := by
  intro p q h
  rcases (weight_sum_eq_iff p.val.1 p.val.2 q.val.1 q.val.2).mp h with
    ⟨h1, h2⟩ | ⟨h1, h2⟩
  · exact Subtype.ext (Prod.ext h1 h2)
  · have hp := p.property
    have hq := q.property
    apply Subtype.ext
    apply Prod.ext <;> apply Fin.ext <;> omega
\end{Lean}

\textbf{Accounting and compatibility.} These are one endpoint-normalization family, with four new lines removed in total. The pinned complete file is $168\to164$. The actual earlier moment-polarization patch composes in either order, without fuzz, to the same bytes: $161\to157$ relative to the assumed-applied baseline. Neither its imports nor its seven-line reduction is counted again. The pair encoding, repeated-index cases, and quadratic coefficient theorem remain unchanged.

\risk\ The mathematics is elementary, but the last line relies on Lean's \code{omega} preprocessing of finite indices and equalities. That exact elaboration is not tested here. If it needs explicit \code{congrArg Fin.val} facts, include those lines in a revised count rather than retaining the advertised four-line saving. Finite counterexample controls show why both ordering hypotheses matter; they do not certify the tactic script.

\section{O Reuse exact order at exponent zero}
\refs\ \src{CurrentPowerCoordinates2011.lean}{46}{67}; the imported exact-order family in \src{CurrentAuxiliaryOrder2011.lean}{52}{60}.
The two generator identities at the first prime-power level are already consequences of stronger exact-order theorems. At exponent zero the stated order is $p^0=1$, so the existing \code{orderOf_eq_one_iff} API returns the identity element directly.
\begin{Lean}
theorem generator_cast_auxiliary :
    (B : ZMod auxiliary)^(auxiliary-1) = 1 := by
  apply orderOf_eq_one_iff.mp
  simpa only [Nat.zero_add, pow_one, pow_zero] using generator_order_succ 0

theorem generator_cast_C0 :
    (B : ZMod (d*auxiliary))^(auxiliary-1) = 1 := by
  apply orderOf_eq_one_iff.mp
  simpa only [Nat.zero_add, pow_one, pow_zero] using full_order 0
\end{Lean}
The first avoids an independent modular cast calculation; the second avoids recomputing the CRT product order at the base case. The complete file goes from 105 to 102 lines, with no new helper or import.

\textbf{Dependency direction matters.} \code{generator_order_succ} is imported from the auxiliary-order file. \code{full_order} occurs before \code{generator_cast_C0}; its proof uses \code{generator_cast_fixed} and \code{generator_order_succ}, not \code{generator_cast_auxiliary}. Thus the proposed reuse is acyclic. Both public base-case theorems are retained even though the second no longer needs the first. This does not replace or weaken the nontrivial prime-square lift needed for exact higher order. The first endpoint now depends on that stronger exact-order argument rather than only the elementary residue calculation. This is a maintenance option, not dependency minimization; no axiom-footprint or runtime improvement is asserted.

\section{D Close a definitional depth equality directly}
\refs\ \src{IterationSize.lean}{68}{74}.
The existing proof first establishes equality of the two expressions by \code{rfl}, then applies \code{congrArg Expr.depth}. But depth is already the same expression projection on both sides. The proposed complete theorem is:
\begin{Lean}
theorem iterate_depth {f : ℕ → ℕ} (p : R f) (initial : ℕ) :
    (DirectGraphEnumerator.iterate p initial).depth =
      (rows p initial).depth := rfl
\end{Lean}
This removes two physical lines in the supplied file, $163\to161$. It changes no expression, proof-bearing representation, iterator, or witness allocation. It is a small definitional-equality cleanup, not a new metadata abstraction.

\textbf{Novelty boundary.} Earlier work moves witness-count projections before their users and factors depth-budget arguments; those outcomes are granted. This proposal only deletes the remaining congruence proof after a definitional equality. If a future refactor makes the projections opaque or not definitionally equal, keep the previous proof or update this candidate; no performance advantage is asserted.
