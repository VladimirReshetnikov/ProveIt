# Compact rank-window kernel-reduction diagnostic

The [compact02](../p64-qcube72-actual-rank-window-compact-attempt02/README.md) and [compact03](../p64-qcube72-actual-rank-window-compact-attempt03/README.md) Lean checks failed at the theorem declaration with `(kernel) excessive memory consumption detected` under `-M2400`; the latter had an empty proof-progress log apart from that error and completed in 5.22 seconds. The diagnostic does **not** identify the exact reduction responsible. The earlier monolithic and compact01 tests instead hit the external 3.5-GiB RSS guard with empty logs. None establishes a compact theorem.

Existing compact endpoint code uses a symbolic port wrapper, marks `betaNat`, `lowNat`, `highNat`, `Nat.ofDigits` and underlying digit/mask definitions locally irreducible, and rewrites pointwise with the preproved `CompactGenericPortProjections.at_zero/at_two/at_three` lemmas. See `CompactSymbolicPortProjections.lean` and `IPRAPositive73.lean`. The captured provider includes `CompactGenericPortProjections.olean` and `CompactSymbolicMaskData.olean`.

[`FreeMainActualRankWindowCompact.lean`](FreeMainActualRankWindowCompact.lean) is an **unchecked source-only diagnostic** applying that pattern: it packages the actual fixed compact44 tuple behind `compactPorts`, reuses the preproved compact mask inequalities, and unfolds only the wrapper and rewrites projections. It is intended to establish the actual fixed-tuple conclusion, not merely restate the generic inequalities. No Lean run has tested it; loading both captured providers may still exhaust the same kernel budget, and the projection rewrites may fail. Any test requires explicit coordination and a fresh output path; no resource limit has been increased.

The [guarded diagnostic attempt01](observations/attempt01/observation.json) actually exited 1 after 2.37 seconds, without a resource stop. It avoided the previous kernel-memory failure but failed because `dsimp only [p,compactPorts]` left the locally irreducible `compactPorts` wrapper folded, so the generic projection rewrites did not match. Its axiom report contains `sorryAx`; no theorem passed. A source revision can prove and use wrapper-specific projection lemmas before marking the wrapper irreducible, but that remains to be checked.
