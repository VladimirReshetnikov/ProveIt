# Conditional 85-operation gap-coordinate candidate

This is a candidate, not yet a proved Con(ZFC) equation. The pinned 86-operation parent's positive coordinate `alpha` occurs only in `C = q - F - alpha` and in the rank seed `G = alpha + (q-F)*(q-1)`. Replace `alpha` with a new positive coordinate `C` and rewrite the rank seed as `G = (q-F)*q - C`. This removes one graph operation, producing a live 85-operation circuit with the same 13 positive coordinates and four fixed ports. The 85-row `candidate.json` and `AUDIT.json` are generated by `audit.py`.

`audit.py` checks the exact sparse integer-polynomial identities under the signed substitution `alpha = q-F-C` and verifies the other graph rows remain structurally identical. It checks all 85 operations, all 13 witnesses and all four ports are live. The graph count is 47 multiplications, 20 additions and 18 subtractions. Reproduce from the repository root with `python3 Computability/DiophantineConsistency/research/adaptive-gap85/audit.py`. These checks are not a Lean binding or a degree/minimality certificate.

Positive witnesses are the unresolved issue. An actual positive 86 zero has `F+alpha<q` by `AdaptiveDirectOrdinate86Transport.expressionAt_transport_positive86`, so its new gap `C=q-(F+alpha)` is positive. Conversely, an 85 zero would recover positive `alpha=q-(F+C)` only if `F+C<q`; that inequality has **not** been established from the new equation. Until both actual-literal zero directions are checked over all required models, including this reverse bound, there is no unqualified 85-equation zero-set, machine, HA, or Con(ZFC) claim. No counterexample to the reverse bound is claimed either.
