# Proposed iPRA endpoint for the 92-operation candidate (unchecked draft)

`QCube92IPRAEndpoint.lean` proposes clients that instantiate the author-checked
92-operation positive model-halt equivalence for the symbolic ports and their
closed Lean byte recipes, then apply the separately checked generic standard
and equality-only iPRA adapters. The proposed no-zero sentence uses the
adaptive `x+1` substitution; the 92-operation count is for the original
positive-coordinate evaluator before those substitutions.

**This source has not been compiled.** The existing compact model and generic
iPRA providers have conflicting selected project objects. The ongoing
425-module expanded-cone rebuild is intended to resolve that particular
selected-project mismatch, but its completion alone will not automatically
compile this newer client or prove its entire dependency ancestry. The 92
model endpoint and adapter must be rebuilt or otherwise validated in one
coherent provider, and this client then needs its own guarded check. This
draft is not evidence that these declarations elaborate, that an iPRA proof
exists for the 92-operation expression, or that external JSON, gzip,
filesystem, TeX or PDF bytes are formally bound to it.
