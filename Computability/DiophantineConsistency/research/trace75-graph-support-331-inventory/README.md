# Captured 331-module source and receipt inventory

This is a **read-only assessment**, not a source-current rebuild or an authentication of the full endpoint. It starts from the 331 reverse-reachable project modules in the [28-source plan](../trace75-graph-support-replay-plan/README.md), using the serialized direct headers and selected object bundles of the captured trace75 fixed-port assembly. A deterministic topological ordering of that captured graph contains 331 nodes and 635 internal edges. Its direct boundary consists of 71 distinct project modules and four outside names: `Init`, `Mathlib.Data.List.GetD`, `Mathlib.Tactic.FinCases`, and `Mathlib.Tactic.ReduceModChar`. The output records the boundary, graph, order and selected bundle hashes. Current resolved bytes of the 406 cone and direct-boundary bundles agree with that capture. This is not a claim about dependencies outside that one-step boundary or about dynamic/package ancestry.

The source evidence has three distinct strengths:

* **28 overlay roots:** reuse the separately documented weaker source candidates and session observations. Current candidate source bytes match those in the pinned plan; this does not establish that the selected objects were compiled from those sources.
* **80 other nodes:** the selected `.olean` recorded realpath and hash match an output in one of six pinned successful rebuild records. Their copied source and stdout/stderr bytes currently match the stage-recorded hashes: 56 direct-BFS stages, 19 compatible-forward stages, two compatible-reverse stages and three final-assembly stages. These are evidence for the recorded stage and direct object selection, not proof of unrestricted historical transitive or package provenance.
* **223 remaining nodes:** a bounded current-workspace search, excluding `reviews/` and `observations/`, selects same-basename `.lean` files whose line-oriented direct `import` names match the captured serialized header after removing `Init` and duplicates. It yields one candidate for 218 modules, two for each of three modules (the two candidates in each pair currently have the same SHA-256), and none for two modules. This heuristic is not a Lean parser and the result is a *candidate*, not a producer source.

For the two unmatched names, separately retained temporary source files currently match differently named workspace source bytes: `CompactRankVariationRetry` matches `compact44-conditional-rank-variation-prototype/CompactRankVariation.lean`; `OldWordIdentification` matches `compact44-local-compact-word-prototype/OldWordIdentification-DRAFT.lean`. Equal bytes do not connect either source to its selected object. The inventory also reports 18 historical candidate receipt records for 18 of the 223 modules from the pinned serialized-audit index; current receipt bytes match the indexed hashes. A candidate receipt is not classified here as the selected object's producer. The other 205 have no candidate receipt in that particular index; the search was not exhaustive.

For the 71 direct project boundary inputs, the same six recorded rebuilds contain eight exact selected realpath-and-hash stage matches; their copied source and stage stdout/stderr currently match the recorded hashes. The same bounded basename/header heuristic yields one candidate for 59 inputs, two for 11, and none for `DiophantineConsistency.CompactWordCellClient`. Four of the 11 pairs have different source hashes. The pinned historical receipt index lists 17 candidate receipts for 17 boundary modules, including three of the eight exact stage matches. These counts overlap and are not an authentication of the remaining inputs. The four outside inputs are only inventoried as selected bundles, not source-authenticated.

`check.py` pins the eight inputs listed in its source, captures workspace HEAD and the sorted candidate file-list digest before and after the scan, checks the current root-source and selected-bundle bytes, and records exact selected stage and candidate receipt observations. It uses a deterministic topological sort and makes no Lean invocation. It does not pin every candidate file *before* selection, prevent concurrent non-HEAD file changes, establish that basename/header matching is complete, or infer a source/object relationship from matching bytes. The full source identification, warning baselines, direct provider selection and upstream ancestry must be resolved before any source-current replay could authenticate this endpoint.
