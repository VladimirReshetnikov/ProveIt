# Plan for composing the checked local node identities

The checked generic `PrefixPath.lookup` transports every entry of a prefix along a typed path. The newly checked `d18 → d45` path and recipe lookup transport the first 18 entries to the compiled Lean recipe, using `recipe_eq_named`. They do not transport entries born after d18, substitute their named values, or identify the recipe output with `Norm38NamedFormula.eval_current`.

One bounded continuation is to construct additional shared paths from d27, d34 and d41 to their later checkpoints and ultimately d45, in chunks comparable to the successful seven-snoc clients. Each path provides a lookup for **all** earlier indices in that prefix. The existing d18 path covers entries 0–17; the d27, d34 and d41 paths would cover later births in successive blocks. Local node equations are at their birth prefix and must also be transported to a suitable checkpoint; paths between a node's birth and the next checkpoint, or already checked specific carries, are still required. A full d18 lookup alone cannot establish any later-node value.

At each checkpoint, derive named value lemmas in dependency order from the checked `snoc_last` equations and transported predecessor values. Keep `rankCode`, the three finite sums, fixed coefficient functions and huge exponents opaque. A candidate representation is one Lean definition per named value with explicit dependencies; this may avoid repeatedly unfolding the entire 45-node telescope. Its statements, provider union and resource behavior need checking. Where definitions are introduced, their mapping to the existing checked named formula needs a separate Lean equality; matching names or the external JSON alone is insufficient.

The final proof would use the checked local d45 output equation, the required d44 predecessor values, and bounded substitutions to reach the right-hand side of `Norm38NamedFormula.eval_current`, then compose with that checked theorem and `recipe_eq_named`. A sensible test is to build one small checkpoint path and one named-value substitution first, with exact `Fin` index normalization and resource evidence, before generating a large proof. The current results do not establish that this approach fits the existing limits. Separately, the independently checked ordinary-Python transcription of JSON to Lean source is not a verified JSON parser and does not bind the human Markdown/PDF bytes.
