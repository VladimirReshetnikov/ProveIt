# Bounded exact-target replacement screen for the 61-row graph

The pinned 10-variable/61-operation [relaxed two-norm graph](../ordinary10-two-norm-divisible61/README.md)
has no gate-saving **exact-target** replacement in the finite class below.
This result does not establish a global operation lower bound, exclude a
zero-preserving witness change, or prove anything about the original parent.
No smaller equivalent equation is claimed.

For each of the 61 live target rows, the checker considers replacing that
row by either an alias or one binary addition, subtraction or multiplication.
Operands may be any witness, fixed port, literal from −1 through 4, or graph
row appearing earlier than the target. It keeps the rest of the DAG unchanged
and uses a backward liveness traversal, counting an alias as zero operations.
The search covers 3,050 aliases and 345,870 binary expressions; commutative
pairs are counted once.

Every replacement in that finite class which would leave fewer than 61 live
operations disagrees with its target at one of four explicit modular input
assignments. Inputs are independently generated by the recorded SHA-256 rule
and evaluated modulo the prime 1,000,000,007. Polynomial identity would imply
agreement at **every** field assignment, so any observed disagreement is an
exact counterexample to that target identity. There are 70 four-assignment
matches overall; none gives a gate saving. A match is not treated as a proof
of identity, and only the zero saving-match result is used.

The conclusion is deliberately narrow. It concerns one exact target at a time,
treats the four ports as independent symbolic inputs, and permits only the
listed operations, literals and earlier operands. It does not exclude
multi-row rewrites, different constants, equality only at the fixed compact
ports, replacements whose *final output* agrees despite a different target,
zero-set equivalences, or changes of natural witnesses. The separate
[tau-offset note](../ordinary10-divisible61-tau-offset-obstacle/README.md)
documents one tested witness reparameterization; it also does not prove a
lower bound.

From `Computability/DiophantineConsistency`, reproduce the finite enumeration
and receipt with:

```sh
python3 -I -S -B research/ordinary10-divisible61-one-gate-replacement-screen/check.py | cmp - research/ordinary10-divisible61-one-gate-replacement-screen/receipt.json
```

The checker pins the literal graph and first verifies all 61 rows are live.
No Lean, build, staging, provider audit, model proof or iPRA result is used.
