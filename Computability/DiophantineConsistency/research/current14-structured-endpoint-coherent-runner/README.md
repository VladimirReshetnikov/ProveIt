`extension_supervisor.py` independently observes the actual v2 coordinator child exit. Before creating anything it authenticates the pinned coordinator and its base preflight and checks the Lean slot. On launch it records the command, full process log, child exit, interruptions, supervisor/code hashes and coordinator-state digest in `/tmp/current14-printed-port-coordinator-supervisor-20261104/receipt.json`. An interruption prevents a PASS even if the child later succeeds; it continues to wait for that specific child rather than kill its separately sessioned descendants. A forced supervisor death, child/session escape, OS failure, or a permanently failing wait remain outside this guarantee. The coordinator itself records the extension driver's actual exit; an unobserved timeout is never an exit. The supervisor's own session exit must still be observed separately.

`runner.py` requires the supervisor receipt and reauthenticates the coordinator terminal state, reviewed v2 pins, 61-row terminal verification, base, source snapshots, providers and guards before it creates its own output. A successful preflight also requires an idle Lean slot. It stages the exact two pinned source files into a fresh root, puts their private object root before the single authenticated extension overlay and guarded package root, checks compiler-reported direct imports and producer companions, and builds `Current14LiteralPorts` followed by `StructuredEndpoint`. It checks the five named assembly axiom reports and the one endpoint report, allowing only `propext`, `Classical.choice`, and `Quot.sound`; it rejects warnings, error and `sorry` patterns in client logs. The endpoint says a tuple exists in Lean and has the required iPRA derivation; it does not place that existential quantifier inside iPRA.

Each client command uses one low-priority owned session, with a 600-second time limit, `-M6000` for compilation, and sampled session RSS below 7 GiB, `MemAvailable` at least 10 GiB, and disk free at least 4 GB. Owned-session code is adapted from the reviewed extension helper to take PID-aware samples. If monitoring fails it waits passively for its direct child and all visible same-session processes to finish before reaping; this can wait indefinitely. The sampling limits do not cover between-sample peaks, descendants that escape their session, forced Python termination, full transitive/dynamic ancestry or transient input mutation. No kill should target an unrelated process; that claim and the new helper require independent review.

`controls-observation.json` captures a successful no-Lean owned-child fixture and targeted checks for axiom names, nonwhitelisted axioms, warnings, wait retry and refusal while the base is live. These are limited controls: they do not exercise a successful real base/extension gate, actual Lean clients, positive dependency routing, resource-triggered termination or all failure races. No positive extension or client path has run. A separate independent terminal audit and actual outer session exit are required even after any future `PASS` state. Memory/kernel exhaustion or source elaboration failure remain possible; preserve any failure rather than presenting it as proof.

Only after all prerequisites and review: run the existing v2 coordinator `--check`, then start the supervisor as an observed session. After a supervisor PASS and independent extension audit, run `runner.py` without arguments for preflight and then with `--run` as an observed session.
