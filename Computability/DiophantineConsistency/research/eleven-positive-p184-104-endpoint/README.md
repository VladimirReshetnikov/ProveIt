# iPRA endpoints for package 184's eleven-positive 104/174 constant-dilation circuit

Package 184 (`con-zfc-diophantine-forms/184-pell-growth-210`) supplies, in
`compact11/`, the circuit `constant_dilation11.json` (104 operations, exact
degree 174, eleven positive unknowns `J, F, α, i, T, w, s, n, η, ζ, κ`; proof:
`compact11/PROOF_constant_dilation.md` §§1–5). Relative to package 172's 87/214
free-inverse circuit (record `research/ten-positive-p172-87-endpoint`) it

* replaces the variable Pell dilation `λ = q` by the constant `λ = 210`:
  `A - 1 = 210 (X s + s)`, `v0 = X s²`, Pell parameter `v = 44100 v0`
  (`ell = 44100 v0 k`), free strip `c = k s + η`, `X = q w`, transport base `w`;
* replaces the first-order inverse offset `6 (e - q⁴ s) - v k (k² - 4)` by the
  integral third-order inverse `e* - q⁴ s`, `e* = T3(k, v0) - R - 1`,
  `T3(k, x) = k - x k (k² - 4) (x (5672362500 x (675 k⁴ - 324 k² + 160) -
  5402250 (27 k² + 8)) + 7350)` (the 44100-dilated coefficients of package
  184 §2, with the denominators `6`, `360`, `15120` cleared by `λ = 210`);
* uses `D = q⁷`, `M = h D` and the carrier `Z = M (n + κ - L B) - (D B + h ec)`
  (no `H` in the denominator), with output `(3 N + 1) (P0 + 1) - 1`,
  `P0 = Q (Z² - M² G V²) + (M² G - Z²)`, `N = K - κ H`.

The `coefficient_binding` has the same `ports` and `tuple` as the 75/402
graph's (`path` and an extra `endianness: little` field differ): the
direct-BFS943 tuple, K0 raw `0a86821a…`, MC `6007cabd…`, MF `48333b0d…`,
β `0664a868…`.

The Lean endpoints are in `Lean/DiophantineConsistency/BFS943/IPRATrace104.lean`
(namespace `DiophantineConsistency.IPRATrace104`): `positiveBridge`,
`native_equivalence`, `standard_equivalence`, `reference_equivalence`,

Each depends only on `propext`, `Classical.choice`, `Quot.sound`.
`IPRAOrdinary12.PositiveModelBridge` is arity-generic, so eleven unknowns need
no new iPRA wrapper.

## Route

The circuit is neither an `n`-shift nor a rescaling of a proved form: its Pell
dilation is the constant 210, so no existing chain applies to it (all of
`Trace87*`, `Trace87Shift*`, `Centred87*`, `Scaled87*`, `Trace97/111/118*`
fix `Y = q s`), and `FixedSource` is reached by a fresh copy of the 87 chain
at `Y = 210 s` (`Trace104*`), with three genuinely new layers.

**The unit factor and κ** (`Trace104Regs`, `Trace104ModelIff`). The core
register map `regs` (first ten unknowns) is the JSON's rows in their own
shape, with the 87-shaped carrier `Zcore = h D [H (n - b V B) + K] - H [D B + h ec]`
and `Mcore = h D H`. Identically `Zcore = H Z₁₀₄ + h D N` and `Mcore = H M₁₀₄`
(`core_Z`), so at `N = 0` the core norm is `H² P0` (`core_norm`).
`Trace104ModelIff.unit_split`: in the difference ring `(3N + 1)(P0 + 1) = 1`
forces `N = 0` and `P0 = 0` (both factors are units; `3N + 1 = -1` is
impossible). So a positive literal zero gives a positive *core zero* (the core
norm vanishes) together with `K = H κ`, i.e. `H ∣ K` — this is exactly the
integral projector quotient of package 184 §4; no coprimality of `q` and `H`
is used anywhere. Conversely a core zero with a positive `κ = K / H` gives a
literal zero (`H ≠ 0` because `K > 0`).

**The integral third-order inverse** (`InverseLucasThird`, reusable).
`third_order`: at base `b + 2 = 2P + 1`, by internal `Σ₁` induction,
`x_n = 1 + 2P n² + P² a₂ + P³ a₃ + P⁴ W`, `y_n = n + P c₁ + P² c₂ + P³ c₃ + P⁴ Z`
with `3 c₁ = 2(n³ - n)`, `15 c₂ = 2(n⁵ - 5n³ + 4n)`,
`315 c₃ = 4(n⁷ - 14n⁵ + 49n³ - 36n)` (the step relations are explicit integer
combinations). `t3_congr` (any commutative ring): these give
`x⁴ ∣ T3(2y, x) - 2n` at `P = 44100 x` — package 184's identity (2). The low
coefficients are explicit integer combinations of the three relations; the
quotient by `x⁴` is the explicit polynomial `Wq` (21 coefficient definitions
`wc0 … wc20`, generated by exact symbolic expansion and checked by Lean's
`linear_combination`); the high part `T3(k) - T3(κ₀)` is divisible by
`k - κ₀ = 2 (44100 x)⁴ Z` through `sub_dvd_pow_sub_pow`. `corr_nonneg` is the
sign bound (3) (`T3(k, x) ≤ k` for `k ≥ 2`, `x ≥ 1`); `corr_le` is a crude
upper bound for completeness.

**The new size bound** (`Trace104NormRank.two_q4_lt_c`, package 184 (5)).
The 87 proof of `2 q⁴ < c` used `A ≥ q²`, false here. The new proof uses only
the norm: with the main index `r ≥ 3` and `β = A + 1 ≥ 2q`, if `r ≥ 5` then
`c ≥ ψ_β(5) ≥ β⁴ ≥ 16 q⁴`; if `r = 3` then `c + 1 = 4β²`, the first index `m`
cannot be `≥ 3` (`k ≥ 2 ψ(3) ≥ 2c`), so `m = 2`, `k = 8v + 4`, and
`4β² ≤ c + 1 ≤ k (s + 1)` forces `X ≤ 2s` (a polynomial inequality checked in
the difference ring), hence `c ≥ 4 (210 s X)² ≥ 44100 X⁴ > 2 q⁴`. With it the
87 rank window and exact main index go through unchanged (`2R < c`).

**Transport, first index** (`Trace104Transport.graph_zero_data`). `B ≥ 0` by
the generic carrier contradiction (`TenPositiveCarrierTransport`) with
`2 ec ≤ 2 (e - q⁴ s) < b V q⁷` (`corr ≥ 0`). With `K = H κ` the core carrier
gives `H (h D (n - L B + κ - z) - D B - h ec) = 0`, so `q⁷ ∣ h ec` and, as
`h ≡ -1 (mod q)`, `q⁷ ∣ ec`. `pell_t3_congr` at the first index `n` gives
`v0⁴ ∣ ec - (2n - R - 1) + q⁴ s`; `q ∣ v0` gives `q⁴ ∣ 2n - R - 1`, and the 87
offset lemma (`Trace104NormOffset`) gives `2n = R + 1`.

**Projection, power, integrality** (`Trace104Projection`,
`Trace104VariableHeight`, `Trace104GraphPower`, `Trace104Integral`). `H ∣ K`
is given, so the whole-product projection is immediate (the 87 multiplier
`6 h X` is kept, so the 87 power proof and
`Trace87ProductPower.whole_product_lt_power_cube` apply verbatim): `X = 2^R`.
Then `q` is a power of two and `R ≥ q² - 1 ≥ 7q` gives `q⁷ ≤ 2^{7q} ≤ X`, so
`q⁷ ∣ X ∣ v0`; with `2n = R + 1`, `v0⁴ ∣ ec + q⁴ s`, hence `q⁷ ∣ q⁴ s` and
`q³ ∣ s` (`Trace104Integral.q7_dvd`). `ec = q⁷ ρ` and `H ∣ K` in the carrier give
`h ∣ B` (`TenPositiveTransportIntegral.transport_divisor`), the natural
transport `(K0 + w) C = F + h t`.

**Soundness = FixedSource** (`Trace104Sandwich`, `Trace104Source`): both scaled
Pell sandwiches at scale `S = 210 s` (the scaled sandwich lemmas take the
scale and strip separately), `ScaledPellRounding.extract` and the
half-binomial population bound, at
`sourceVal = ![J, F, α, 1, 1, w, 1, 1, 1, 1]`; then
`FixedSourceHalt.source_halts`. No 75 or 87 zero is constructed.

**Completeness** (`Trace104ReverseData`, `Trace104ParentMap`,
`Trace104ReverseGraph`, `Trace104HaltGraph`, package 184 §5). The halting
packing gives `q = 2^{uN} ≥ 8`, `X = q w = 2^R`, `s = q³ s_Y` and an unscaled
strip at `(X, s)`. `TenPositiveScaledReverseStart.scaled_start` at the
constant scale `μ = 210` gives the fresh Pell data and the positive projection
quotient `κ` (`X (3C - 2X) + 2 = H κ`). `pell_t3_congr` at the first index
`r + 1` and `q⁷ ∣ X` give `ec = q⁷ ρ` with integral `ρ`, and
`-ρ ≤ q⁴ s + v0 K³ (3828844687500 v0² K⁴ + 7350)` (`corr_le`). The auxiliary
seed is chosen cofinally (`scaled_auxiliary` with `L = κ +` that bound; this is
the package's "choose the period multiple large enough", the small-correction
bound of an arbitrary seed is not used), so `n = τ f y + (1 + bL) t + ρ - κ > 0`;
the parent map moves only `T` and keeps `K` and `H`. The literal zero is
`(J, F, α, i, T, w, s, n, η', ζ', κ)`.

`Trace104ModelIff.positive_model_iff` joins both directions; the iPRA wrappers
are those of `IPRATrace75`.

## Binding check

`check_lean_graph.py` (run `py -I -X utf8 -B check_lean_graph.py`) pins the
104 JSON (`ef8ee046…`), the 75 JSON (port binding) and the 87 record's checker,
whose interned normalizer it imports. It checks the graph metadata (eleven
witnesses in order, `lambda: 210`, 104 operations, degree 174, output `P`, no
dead rows) and the port binding; parses every `let` row and the record of
`regs`, the standalone `ecl` and the body of `value104` into the same interned
DAG as the JSON rows and compares after exact commutative-ring structural
normalization (no distribution): the output `P` and the rows `X`, `c`, `Am1`,
`Delta`, `H`, `E`, `R`, `B`, `Q`, `V`, `K`, `q7`, `G`, `ec` (both the record's
internal row and `ecl`), `M`, `Z`, `P0`, `N`. It rejects 16 mutations of the
Lean text (dilation 1, `44100 → 210`, each of the five inverse coefficients,
correction sign, `q⁴ s` sign, `q³ s` offset, denominator `q⁶`, `n - κ`,
carrier sign, `N = K + κ H`, factor `2N + 1`, multiplier `h D H`), and checks
the literal, `core`, endpoint and `expression_def` definitions verbatim and that
`fixedPorts` is textually the `IPRATrace75` one, so
`reviews/bfs943-source-promotion/tools/check_ports.py` covers this circuit.
Output: `check-output.json`. These are finite external checks, not Lean
theorems about files.

## Scope and non-claims

The endpoints are about the Lean literal at the symbolic direct-BFS943 ports;
the JSON correspondence and the port hashes are the finite external checks
above. Package 184's exact-degree certificate (§6), its 208-mutation verifier,
the comparison with source 115 and the rejected ten-variable shortcut (§7) are
not formalized. The Lean proof follows package 184's ordinary proof in
structure but bounds the literal registers directly where only crude bounds are
needed (e.g. `-ρ ≤ q⁴ s + v0 K³ (…)` instead of `|ρ| + κ + σ < g`). It proves
nothing about global minimality or priority.

`maxHeartbeats` raises: `InverseLucasThird.t3_congr` and `third_order`
(2000000 each), `Trace104ReverseData.reverse_data` (1000000), and the inherited
file-level/`in` settings of the copied 87 modules (`Trace104Factors` 8000000,
`Trace104Transport.graph_zero_data` 4000000, `Trace104HaltGraph` 4000000,
`Trace104ModelIff` 4000000). None is `0`.
