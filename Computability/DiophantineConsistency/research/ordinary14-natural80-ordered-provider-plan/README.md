# Natural-80 combined overlay: ordered lexical provider plan

This is a **source-level candidate order**, not a Lean build, coherent-provider
certificate or launch-ready runner. The read-only `check.py` pins the reviewed
[natural-80 combined overlay](../ordinary14-natural80-combined-slim-overlay/README.md)
and [qualified-provider cut](../ordinary14-natural80-qualified-provider-cut/README.md),
then records one concrete 189-stage order in `plan.json`: five qualified source
candidates followed by all 184 inert overlay drafts, ending with
`Natural80Endpoint`. Each row records source path, SHA-256, simple lexical
imports and an **unreserved output name**. No source is materialized and no
new output root is selected or created.

An [independent source review](../../reviews/ordinary14-natural80-ordered-provider-plan-independent/README.md)
checks the ordering, observed frontier objects and bounded collision scan;
it does not establish actual Lean resolution or provider closure.

The five qualified candidate stages come first in this topological order:

1. `DiophantineConsistency.DiscreteOrderedRingFacts`.
2. `DiophantineConsistency.Compact44.FreeJ13`.
3. `DiophantineConsistency.Compact44.FreeJ13Halt` (imports stage 2).
4. `DiophantineConsistency.BFS943.Direct80IndexOne`.
5. `DiophantineConsistency.HAExpressionNoZeroEquiv`.

Their complete source paths, pinned hashes and direct imports are in the
receipt. The order is valid **only against the inspected initial source
headers and the observed cut**. The 184 draft rows retain their combined
source-overlay topological order and byte hashes, including the two inert
`partialValuation` name alternatives, predecessor-order alternatives and the
six inherited slim refactors. Those versions are source drafts and have not
been elaborated. A missing selected object and an available source file do not
by themselves prove that compiling that file suffices.

## What the checker verifies

The checker reads and hashes the five candidate source files, all 184 inert
overlay snapshots and the current source for each frontier object. It parses
their initial simple `import` lines and checks that each recorded import is an
earlier candidate stage or one of the selected frontier names. It rechecks
the recorded path, resolved path, symlink status and SHA-256 of all **40
selected-P72 project objects** and **four guarded-package Mathlib objects**.
It repeats the qualified-provider cut's bounded output-name scan: 189 names,
eight specified existing roots and 13 recorded suffixes. At the sampled state,
the only two hits are `DiscreteOrderedRingFacts.olean` paths in the captured
endpoint and failed Carrier65 roots, as described in the provider-cut packet.
They are observations of existing alternate files, not authorized providers;
the selected P72/base route lacks all five candidate outputs. No future output
root or all possible alternate paths have been checked.

The five candidate sources and 184 snapshots are lexical inputs. The 40
frontier paths can resolve through retained links into the recorded fresh base;
the recorded path/target/object hashes are compared to the pinned cut, not to
a complete independent historical producer audit. The guarded-package and
selected toolchain roots, complete transitive source and compiled-object
imports, `Init`, private/server/IR/other companions, and dynamic/runtime
inputs are not resolved or authenticated by this plan. Existing different
same-name objects in alternate roots must not be silently mixed into the
selected route. Matching bytes or paths alone do not establish compatibility.

## Remaining work before a guarded build

A future build must first independently review its exact materialization and
ordered search paths, all provider and companion ancestry, implicit and runtime
imports, source identities and output collisions. It must protect or
revalidate immutable inputs, use an enforceable exclusive Lean slot and the
existing resource guards, and reject changed or unexplained dependencies or
outputs. It must run guarded `lean --deps` and compile each stage with exact
recorded inputs, preserve the complete evidence, execute and inspect the
requested endpoint axiom reports, and obtain independent postflight review.
The current filesystem was below the established strict 5,100,000,000-byte
build floor when this plan was prepared. A later free-space sample is required;
no space is reserved here.

Filesystem reads are non-atomic and retained `/tmp` roots can change or
vanish. A reproduced receipt is a point-in-time observation, not an assurance
of future immutability. The header parser recognizes only the observed simple
initial import form and is not Lean's parser or resolver. This packet does not
establish an iPRA derivation or a connection to physical coefficient bytes or
the different displayed Carrier65 PDF.
