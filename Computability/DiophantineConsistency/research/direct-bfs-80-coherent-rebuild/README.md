# Held direct-BFS 80 coherent union replay

`run.py` and `run-outer.py` are a **held, unlaunched draft** for independent review. They consume the separately audited 65-stage capture-relative plan, the accepted 127-stage rebuilt-80 capture/replay, and the fixed BFS selected-header capture. The intended run creates a fresh single project union from the 1,765 rebuilt-80 objects and 101 other captured BFS supplements, compiles the 65 affected source snapshots in captured dependency order, and then rereads the actual entire selected serialized closure from `DirectBFS80FixedIPRA`. It never replaces objects in either captured provider. The 101 supplements and the prior 127 replay remain inherited baselines; this is not a full source rebuild or package-transitive/dynamic ancestry proof.

The draft pins input captures, the Lean binary and all planned source snapshots and producer receipts; verifies source import order and all initial object/companion hashes and resolved link targets; refuses outside/project namespace shadowing, project fallback, unexpected source/import changes, unbuilt affected imports, warnings/errors and `sorryAx`; records direct dependencies before and after each stage; rechecks prior outputs, sources, union links and outside objects; requires four endpoint axiom reports restricted to `propext`, `Classical.choice`, and `Quot.sound`; and checks final selected closure membership, serialized imports, object/companion hashes and outside records. Each Lean subprocess is guarded by at least 8 GiB available and fewer than two existing Lean processes, with runtime monitoring. The nonblocking lock prevents concurrent invocations of this runner. Fresh attempt and output paths are mandatory. `run-outer.py` records the actual inner runner exit and result hash; it returns success only if the inner process exits 0 and its result says `PASS`.

Its author-observed outer exit was 0; no separate preflight outer receipt was produced. Do not infer a passed rebuild, external JSON/gzip binding, or complete historical source-to-object/package/dynamic provenance from this draft or preflight. An independent review must precede any launch; an eventual successful run requires independent receipt/closure review.

## Held v2 for independent review

`run-v2.py` and `run-v2-outer.py` are a separately frozen revision; v1 and its preflight are retained. V2 rejects dangling and non-regular entries, treats every present output companion as a collision, checks each selected direct project dependency against its captured initial or built companion hashes and resolved targets at both stage boundaries, requires initial union entries to stay symlinks and built outputs to remain regular files at their fresh-union paths, and repeats these checks at final guards. The outer wrapper pins v2's exact runner SHA before and after its subprocess. The wrapper's own SHA must be checked against the independently reviewed bytes at launch.

`check-v2-policy.py` extracts the actual runner helper functions without executing the runner and tests diagnostics, the four endpoint reports, changed link targets, file-type substitutions, companion changes, dangling links, directories and collisions. Its result is `observations/policy-v2/result.json`. `observations/preflight02/` records a fresh read-only subprocess exit 0 and its stdout/stderr hashes. Neither check ran Lean or proves the rebuild. The pending independent review must approve the exact v2 bytes before a launch.

The replay would still inherit the prior 127-stage provider, 101 selected supplements and outside packages; it does not authenticate all their historical sources, package-transitive or dynamic ancestry. External graph/JSON/PDF binding remains separate.
