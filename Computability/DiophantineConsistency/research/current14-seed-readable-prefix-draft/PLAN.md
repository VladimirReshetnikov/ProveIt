# Restricted arithmetic text to numeral-derived iPRA syntax

Scope: quote an independently transcribed, normalized prefix rendering of the 22 named arithmetic abbreviations and `P Q U W Z - Delta` from the displayed current-14 page. The quotation is Lean data. It is not the actual TeX/PDF byte stream and is not claimed to implement TeX, Unicode mathematics or PDF rendering.

The restricted grammar is whitespace-delimited prefix: binary `+`, `-`, `*`; unary `sq` and `cube`; decimal literals `1`, `2`, `3`, `4`; and identifiers in a finite environment. Each declaration has `identifier = expression`. The initial environment maps the 14 positive-coordinate names to their `Fin 14` syntax variables and `beta`, `K`, `mu`, `omega` to the four integer port leaves. Later declarations may refer only to earlier names; duplicates, unknown names, leftover tokens, malformed declarations and exhausted parser fuel are rejected. Every operation builds the existing integer `Expr` syntax; powers use its existing fixed-power constructor.

Proposed proof: (1) kernel-check decoding of the 23 quoted lines to the named 14-coordinate syntax at arbitrary ports, using bounded/staged helpers if direct reduction is too large; (2) instantiate the audited numeral-derived `linePorts` and transport the existing standard-iPRA endpoint through the resulting expression equality. Separately compare the quote against the displayed TeX/PDF via independent source audit, recording exact conventions and negative controls; that I/O check is external evidence, not a Lean proof about PDF bytes. The theorem is still proof existence in the selected iPRA/predicate, not an explicit proof certificate or proof of either side separately.

The direct preliminary transcription is handwritten from the displayed equations, not emitted from `CurrentEquationSyntax2011.lean`. Prelaunch review must compare every declaration and parenthesization independently against the page, the 14-coordinate and four-port maps, parser rejection behavior and captured provider/guards. The 65-operation and degree-150 claims are separate unless separately checked. No Lean result is asserted by this plan.

The source draft represents the quotation as a list of token lines, so each string is already a token: it does not yet prove a raw whitespace lexer. The syntax is prefix rather than TeX infix. Its formulas were transcribed independently from `equation.tex`; no automated extraction or PDF formalization is claimed.
