# Source-only named-prefix factoring

The [first-node `rfl` check](../nine-seed38-jones-compact-first-node-check/README.md) was terminated by the sampled 4-GiB session-RSS guard and proved nothing. The retained failure does not identify the exact internal reduction responsible. This separate draft tries a materially different factoring while retaining the same limits: `split.py` reads the pinned original 45-node Lean telescope and rewrites its 46 local definitions (`d0` through `d45`) as separately named Lean definitions. It preserves every textual node body and order; its no-Lean `--check` exited 0. The number 46 includes the empty prefix and is not an operation count.

[`Norm38MacroPrefixes.lean`](Norm38MacroPrefixes.lean) asks Lean to prove `Norm38MacroRecipe.recipe = d45` by `rfl` without evaluating any node. [`Norm38MacroPrefixFirst.lean`](Norm38MacroPrefixFirst.lean) separately proposes the value of the short `d1` prefix, using the already checked generic `snoc_last` lemma while keeping the closed `indexY` coefficient symbolic. Both sources are **uncompiled**. The second proposed lemma is a value of `d1` only; it does not yet prove the value of entry zero of the full recipe. A further proof must combine the recipe identity and the generic prior-entry preservation lemma, without forcing unused terms, to make that connection.

Separately named definitions may limit reduction but do not by themselves establish improved resource behavior; either proposed check may still fail. A future guarded runner must authenticate the actual recipe and generic-cut producer sources, objects, logs, direct guards and overlay paths, preserve the failed attempt, use a fresh output, and receive independent prelaunch review and explicit slot coordination. No giant coefficient or finite sum has been evaluated here. No recipe semantic equality, verified JSON/document binding, iPRA theorem, or operation count is asserted by this draft.
