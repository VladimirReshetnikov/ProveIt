# Direct plan for a BFS-compatible trace75 forward replay

`plan.py` inventories the 21 previously checked forward-client modules from `Trace75FixedSlots` through `Trace75BFSModelHalt` against the terminal 31-stage BFS-compatible provider. The result pins the parent result, outer receipt, independent parent post-audit and historical model-halt receipt; for each stage it records its source and matching snapshot, accepted historical receipt and logs, ordered direct imports and historical selected object. The proposed order follows the reverse of the original model-halt search path, and every stage import is earlier in that order.

The read-only `observations/plan-attempt01/result.json` has 21 stages and 42 distinct non-stage direct imports. All 42 currently selected object hashes match their historical first selections; none of the direct outside names lies outside the captured 80-object BFS outside baseline. This does not establish source coherence or equality of all transitive selected dependencies: the new parent rebuilt 31 trace modules to preserve BFS ancestors, and the four retained baseline modules continue to have inherited source/object ancestry limits.

This is a direct-import and source/receipt plan only. It runs no Lean, proves no transitive closure or new client, and does not establish model iff, iPRA or external-file binding. A future replay needs full parent bundle/inventory verification, source snapshot checks, exact reports, output/closure checks, outside companion monitoring, an exit-capturing wrapper and independent prelaunch review. It should preserve the captured BFS halt-seed and band-carry closures and pin the four inherited baseline objects explicitly.

For final assembly, the intended replay base is the completed 13-stage reverse union, once that replay passes and is audited, rather than a separately extended 31-stage parent. A static name comparison finds no collision between the 13 reverse and 21 forward stage names and no forward non-stage direct import named by a reverse stage. The 42 direct selections and companion bundles must still be re-resolved against the actual final reverse union before a forward run; the present plan does not inspect a live reverse output.
