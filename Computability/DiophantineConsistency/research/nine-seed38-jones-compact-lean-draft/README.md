# Source-only compact macro evaluator and theorem targets

This packet drafts a Lean interpretation of the separately reviewed-plan [45-node JSON recipe](../nine-seed38-jones-compact-macro-prototype/README.md). It does **not** contain a checked theorem, a Lean build, or a verified JSON parser. The number 45 counts named nodes in the prototype and is not an arithmetic operation count. No large sums or fixed coefficient integers are evaluated by the source-generation steps.

[`Norm38MacroLanguage.lean`](Norm38MacroLanguage.lean) proposes two typed macro languages. `NExpr` contains natural constants, the current finite-range index, `codingExpo 38 4`, addition, `Nat.sub`, multiplication, and power. `Term n` contains ring constants, the nine ring-valued inputs, `Fin n` references to earlier nodes, casts of exact `indexZ`/`indexY` and `pCoefficient` values, ring arithmetic, powers, finite-range sums and the `codingStar 38 4` sum. `Dag` is an indexed telescope: a term with `Fin n` references can only refer to the `n` earlier entries. Boolean scope checks distinguish valid uses of the range and star binders. `Term.eval` states the intended evaluator over any `CommRing R`, leaving `Finset.range`, `codingStar`, `indexZ`, `indexY`, and coefficients symbolic.

[`quote.py`](quote.py) validates the pinned JSON using the prototype's structural checker and emits [`Norm38MacroRecipe.lean`](Norm38MacroRecipe.lean) as an indexed 45-entry Lean telescope. `--check` reproduced the generated bytes with exit 0. Its two declarations `WellScopedTarget` and `SemanticTarget` are **open propositions, not theorems or proofs**. The semantic target states, for every commutative ring and nine-tuple, that evaluating the last graph entry equals `Norm38IPRAEndpoint.expression.evalRing`. The generator is an ordinary Python program: equality of its output to the JSON is supported by reproducible generation and independent source comparison, not by a verified Lean parser or serializer.

The [independent source review](../../reviews/nine-seed38-jones-compact-lean-draft-frontier-independent/README.md) compared all 45 generated nodes to the JSON. It does not prove the target equality or verify a Lean parser/serializer.

The next source-level proof must establish `WellScopedTarget` and `SemanticTarget`, using the checked `Norm38NamedFormula.eval_current` and the named `rankCode`, `RingVars`, and `RefinedPair.value` definitions. It should preserve the giant `indexZ`, `indexY`, finite sums and powers as symbolic atoms, factor equalities at graph nodes where useful, and avoid normalizing coefficients. This is a proof plan, not a completed proof. In particular, elaboration, structural-recursion acceptance for sums, dependent `Fin.snoc` indexing, binder behavior, and resource use of these files are all untested. A guarded Lean attempt requires exact source/provider/overlay authentication, independent prelaunch review, slot coordination and retained outer exit. To bind the JSON bytes to the quoted Lean data without trusting the Python translator, separately prove a Lean parser/serializer or formally audit that boundary; Lean does not read the human Markdown/PDF.
