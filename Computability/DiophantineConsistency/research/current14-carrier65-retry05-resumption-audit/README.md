## Resumption is not supported by the retained runner

The retry05 runner hard-codes `/tmp/current14-coherent490-refactor-retry05-20261110`, requires that output path not exist in its run preflight, creates an exclusive fresh output tree, initializes an empty completed-module map, snapshots all selected sources, and starts its stage loop at zero. That retained path now exists and contains failed-run evidence. Running that same program again is not a continuation, and deleting or replacing the existing root would destroy evidence. Its postflight validates all outputs and reports only after the entire fresh run succeeds.

There are two engineering possibilities, neither currently supplied as an independently reviewed, launch-ready runner:

1. Prepare and independently review a new fresh-output runner for the same selected plan and refactors. Reauthenticate sources, the original 1,000-module base and its companions, external direct providers, the chosen toolchain and search paths; reject drift, output collisions and unknown routes. Build the whole guarded sequence, capture its child results and final three axiom reports, then independently review the postflight. A fresh output may require considerable space; exceeding the floor at launch is only a necessary sampled condition, not a space reservation or guarantee of completion.
2. Design a separate fail-closed continuation that keeps retry05 immutable, revalidates each completed prefix source, object, companion, log, direct dependency route, base link and guard observation, and accounts for all pending stage-240 state and output names before starting in a distinct output/state arrangement. It must prove that any reused prefix remains a coherent provider closure and validate the same final postflight and axioms. No such continuation runner, atomic reservation or complete transitive-ancestry certification is provided here. A mere count of 239 successful stages is insufficient to justify reuse.

Both paths require an independently reviewed prelaunch, an exclusive Lean slot, and the established runtime guards: disk strictly above 5,100,000,000 bytes, at least 10 GiB available host memory, sampled session RSS below 4 GiB, `-M3600 -j1 -DElab.async=false`, at most 180 seconds per child and a six-hour global trigger. Stop and preserve evidence on any guard, dependency, collision or output mismatch. A full fresh route uses proof-refactored sources, not byte-identical originals, and may hit resource limits in later stages. Current free space must be sampled at launch; it was below the disk floor when this audit was prepared.
