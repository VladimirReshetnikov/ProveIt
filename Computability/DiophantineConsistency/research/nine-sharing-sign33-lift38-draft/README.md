# Candidate lift from 33 to 38 natural witnesses

`Sign33Lift38.lean` is uncompiled source for a 38-coordinate lift and five named signed ring values. Its output `Fin 38` uses zero-based indices; source `v : Fin 34 → V` uses full indices, with 0 the distinguished input. Equivalently, after `Fin.cons` adds any distinguished input to the lift, full output positions 1–26 copy source 1–26, while full positions 27–38 are `0,v27,0,v28,v29,0,v30,0,v31,v32,0,v33`. Thus the first four signed pairs use `(value,0)` and the fifth uses `(0,value)` for the negative orientation y²−V². The signed-value theorem is an uncompiled direct extraction from `AllCuts`; it does not prove any 38-gate relation.

`check.py` externally compares the frozen 33- and 38-witness JSON candidate gate records: same source graph hash, same port order and shift, all 60 matching gate operators and operands, and all 19 materialized cuts under the indicated coordinate mapping and signs. Its result is a syntax/coordinate comparison, not a Lean proof of gate semantics, norms, positivity, source zero or iPRA. It does not compare all residual expressions or establish an equivalence.

The mapped canonical signed pairs do not generally satisfy `NormAssignment38.gatesHold`: that predicate requires each positive and negative component to match separately, while `AllCuts` constrains their difference. At gate 48 the computed negative component is typically nonzero although the lift assigns its negative component zero. A possible route is to prove a weaker ring-value gate condition and ring-level fixed-point lemma, then use the checked generic topology and terminal fields; that implication and exact provider compatibility remain unproved. Conversely, source-zero-to-33 witnesses still needs a forward construction using the five checked source-derived representatives, a coherent assignment for positive cuts, and any required current-port casts. Only these completed directions plus Jones/iPRA composition could yield a sign33 endpoint.
