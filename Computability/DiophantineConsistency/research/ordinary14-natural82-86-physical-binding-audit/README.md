# Physical coefficient and PDF binding for natural-82 and natural-86

The natural-82 and natural-86 endpoint drafts use the **compact P72** symbolic port tuple. The existing displayed `equation.tex`/`equation.pdf` describes the **current Carrier65** equation with a different graph and different beta. Therefore the missing connection is not just a hash or serialization check: the currently displayed page is not a literal transcription of either natural-input graph. To relate their no-solution statements, one needs a separate checked equivalence between the corresponding encoded sentences, or can display a separately constructed page for one of the new candidates. This audit neither proves nor disproves that their zero-existence statements are equivalent.

At the pinned source snapshot, the compact symbolic beta is `2^(67*8807)-1`, whereas the canonical TeX defines `rho=2^47`, `B=rho^2011`, `beta=B-1`. These betas have respectively 590,069 and 94,517 bits and are unequal. The canonical metadata identifies 14 positive inputs, 65 operations and degree 150; the external natural-82 and natural-86 graphs have 14 natural inputs and respectively 82 and 86 operations. These facts distinguish the recorded artifacts, but do not by themselves decide whether their no-zero statements are logically equivalent. The PDF hash is checked against `CURRENT_EQUATION.json`; this is not a parser, visual inspection, or a proof that its rendered formula faithfully represents the TeX.

## Existing bridges and their limits

The source declarations `CompactFourPortByteAssembly2.decode_ports` and `CompactBytePortsModelIff.byteP_eq` state that four closed **Lean** lists decoded by `Nat.ofDigits 256` give the compact symbolic tuple `[betaNat, paramKernel rho, lowNat, betaNat+highNat]`. The fourth port already contains one beta shift. Earlier bounded author runs are recorded for the [four-port assembly](../ordinary12-ipra-bridge/compact44-four-port-byte-assembly2/README.md) and [byte-port model bridge](../ordinary12-ipra-bridge/compact44-byte-ports-model-iff-prototype/README.md); those historical observations do not establish a coherent replay for the new endpoint chain.

The [natural86 recipe-port source adapter](../ordinary14-natural86-recipe-port-bridge-draft/README.md) proposes rewriting its expression from the symbolic tuple to `byteP` via `byteP_eq`, then transporting its model bridge and iPRA declarations. The adapter and natural86 endpoint are unelaborated. The natural82 endpoint currently uses the same `CompactSymbolicModelIff.p`, but does not itself import or instantiate a recipe-port adapter; a corresponding source adapter could rewrite its expression using the same equality, subject to an actual coherent Lean build and proof check.

Separate Python checks and recorded author runs compare transcriptions of the beta, K0, MC and MF byte recipes with the retained payloads; for example see the [beta](../ordinary12-ipra-bridge/compact44-retained-beta-byte-prototype/README.md), [kernel](../ordinary12-ipra-bridge/compact44-k-byte-recipe-prototype/README.md), [MC data generator](../ordinary12-ipra-bridge/compact44-low-byte-complete-recipe/README.md), and [shifted MF](../ordinary12-ipra-bridge/compact44-mf-byte-assembly-prototype/README.md) packets. These are useful provenance evidence, not Lean theorems equating files or Python calculations to Lean lists. The natural82 and natural86 graph source checkers separately compare proposed Lean source rows to their JSON graphs; those are source-level checks, not Lean parser/evaluation theorems.

This audit independently rehashes and decompresses all four P72 payloads against the pinned P72 and P115 binding records. The raw values are **minimal unsigned little-endian**; MF is already shifted. It verifies the beta bytes have the compact beta pattern and value, and checks the pinned source and canonical page identities described above. These point-in-time Python/OS observations do not prove any Lean/file equality. It does not recompute all four Lean byte recipes, inspect the PDF rendering, resolve transitive providers, or run Lean.

An [independent review](../../reviews/ordinary14-natural82-86-physical-binding-independent/README.md)
checks the beta distinction, recipe-source declarations and payload hashes,
without asserting PDF semantics or an equivalence between the equations.

## Concrete path to a stronger end-to-end association

1. Complete and independently audit the natural82/natural86 source chains and their intended iPRA endpoint declarations with coherent Lean providers. For a recipe-based formulation, elaborate the natural86 adapter and a corresponding natural82 adapter using `byteP_eq`; record axiom reports and assumptions. A symbolic or recipe expression remains a mathematical Lean object.
2. Freeze a specific external payload snapshot with an explicit byte order and lengths. For a kernel-level statement, represent the chosen bytes as finite Lean data and prove, for each port, equality to the corresponding closed Lean recipe or equality of its decoded value. Avoid silently shifting MF again. If gzip and hash verification is to be inside the theorem, formalize and verify those operations on embedded bytes as well. An external guard can associate a frozen file snapshot with embedded data, but the association to a mutable filesystem is build provenance outside a pure Lean theorem.
3. Bind each chosen JSON graph to the Lean expression: embed or otherwise fix the graph data, give a total semantics for its operations and input/port order, and prove the resulting expression or its evaluation equals the endpoint expression. Alternatively, make a checked generator and independent source review an explicitly external part of the trust boundary. Neither a 82/86 operation count nor external source comparison alone is that theorem.
4. For a new rendered page of a natural82 or natural86 equation, specify and check its own graph, domain, port recipes, rendering and displayed text, then connect that representation to the Lean graph and frozen bytes. A SHA-256 digest identifies bytes; it does not by itself establish the formula's interpretation or the reliability of a renderer.
5. For the **existing** Carrier65 page, separately formalize and check its own source/port-to-page association and its iPRA endpoint. If both endpoint theorems establish equivalence to the same precisely matched consistency/refutation sentence in the same iPRA presentation, compose them there to relate no-zero claims. If their encodings or theories differ, first prove the necessary translation. Do not assert literal equality of the distinct beta numerals, graphs, or variable domains.
