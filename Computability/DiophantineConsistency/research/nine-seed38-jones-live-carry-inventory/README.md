# External liveness inventory and generic lookup plan

The [deterministic checker](check.py) pins the 45-node macro JSON, the named-prefix Lean source, and the independent ordinary-Python source-transcription checker and receipt. It reruns that checker, rejects malformed or forward references, and lists each named entry's distinct consumer prefixes and last consumer. The [result](result.json) reports 89 distinct named reference edges and 403 single-snoc preservation steps for one hypothetical strategy: create one fresh, shared consecutive carry chain per entry from its birth prefix up to the prefix immediately preceding its last consumer. It does **not** subtract already checked carry lemmas. These are graph-planning figures, not a minimum, count of future Lean proofs, arithmetic-operation count, exact polynomial degree, or Lean theorem. The ordinary-Python JSON-to-Lean source comparison is not a verified parser or a binding of the human document.

The checker was observed to complete synchronously with exit 0 using `python3 -I -S -B .../check.py`, and its output is retained as `result.json`. Its source facts rely on the pinned independent transcription audit, not on Lean verifying the JSON bytes. The [independent inventory review](../../reviews/nine-seed38-jones-live-carry-inventory-frontier-independent/README.md) separately reproduced the edges and counts.

A possible Lean reduction in repeated proof text is a generic typed prefix-embedding witness: a relation from `Dag m` to `Dag n` carries a function `Fin m → Fin n`, has an identity constructor, and extends an existing witness by appending a `Term` and composing its index map with `Fin.castSucc`. Induction on that witness should derive preservation of `Dag.values` using the already checked `Norm38MacroCuts.snoc_previous`; a separate composition lemma could share witnesses across chosen boundaries. This is a source-level design, not yet a defined or compiled Lean lemma. Its elaboration cost, index normalization and actual memory behavior remain to be tested.

One feasible continuation is to certify a small set of shared prefix witnesses (for example around d18, d27, d34, d39 and d45), then state each node's value using the appropriate generic lookup and its already checked local equation. Follow dependencies in order and retain rank, finite sums, coefficients and powers as symbolic terms. Existing checked carry lemmas should be reused where their endpoints fit. Even if each carry succeeds, further Lean work must assemble the `d45` output into the checked `Norm38NamedFormula.eval_current` RHS and use the checked `recipe_eq_named`; the current local-node checks do not do that. A verified JSON/text binding would still be a separate task.
