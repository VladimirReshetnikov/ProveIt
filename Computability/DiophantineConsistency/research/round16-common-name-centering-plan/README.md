## Universal ordinary proof and composition

Write the complete raw residuals as r_j(x), with unrestricted integer
coordinates x. Let delta be the stated integer vector and put
t_j(z)=r_j(z+delta). The maps x=z+delta and z=x-delta are inverse
bijections on the entire integer coordinate space. For every assignment,

    Q_delta(z) = sum_j t_j(z)^2 = Q_raw(z+delta).

Thus both complete zero sets correspond, including all graph witnesses
and signed private coordinates. No positivity of translated t0, x,
shared.A or any translated Pell ordinate is required. Every source sign
argument is applied only after undoing the translation.

Substitution by integer constants preserves integral coefficients and
the degree-at-most-two residual bound. The degree-four homogeneous part
of the complete SOS is unchanged, so the parent's exact degree four is
preserved. The coordinate and row lists are unchanged. Height, term
count and lower-degree cancellations require a fresh whole calculation.

The composed inverse first adds delta to recover the actual new raw
projected tuple. It then applies that profile's actual retained/free
partition and reverse monic rules, with arbitrary initialization of the
actual83 free factored coordinates, followed by the mandatory original
Horn private overwrites and the sealed source's ordinary witness maps.
The current parent has204 plain/203 weighted monic restorations; no old
147-step or old free-two interface is substituted for them. Forward
existence uses the accepted source construction, fresh Horn private
coordinates and actual raw projection, then subtracts delta.

This uses the accepted new complete source calibration. It does not
reprove the original native compiler, identify old/new Horn private
tuples, preserve stale interval triples across the source repairs or
claim any identity with the old327-coordinate polynomial.

## Minimal future implementation and verification boundary

The exact reviewed `translate_coordinates.translate(e,shifts)` routine
can perform the fixed literal substitutions using the already accepted
terminal-elimination polynomial utilities. Its command-line default
policy must not be used: it shifts t0 by-1, whereas this table uses-17.
The independent accepted `check_direct.translation(src,dst,cert)`
reconstructs every row with a separate collector, and
`check_direct.literal(dst)` collects the complete SOS independently of
the producer's `terminal_elimination.expand(dst)`.

The translation routine deliberately removes exactly the cached
`metrics` and `elimination` fields and appends only
`:integral_translation` to `variant`; all other metadata is copied.
The proposed policy name belongs in certificate metadata. An additional
equation-variant suffix would require a separately reviewed checker
adaptation, rather than an undocumented deviation from the adopted API.

This needs only a small newly reviewed wrapper, the exact32-line
translation module, the already reviewed260-line polynomial module and
the407-line independent verifier, plus the standard library. The old
`center_integer.py` coordinate search and its `build_residue` import
are unnecessary. No source, Horn factorizer, optimizer, old centered
producer, original incoming application or native program needs to run.
The literal raw equations and their accepted complete composed maps
remain input artifacts rather than being regenerated by an implicit
runtime closure.

Each future certificate must bind the new whole input and output hashes,
all58 exact integer shifts, the complete name/index table, convention
and both inverse formulas. It must not copy the old input/output hashes,
old search history, old scores or its `:finite_centering` suffix. An
honest new provenance tag may record this fixed-table policy.
The future wrapper must explicitly validate the certificate's exact
schema, convention, inverse, name/index association and forbidden
search-history fields: `check_direct.translation` alone checks endpoint
hashes, integer shifts and the reconstructed equation, not all of those
policy claims.

Future independent checks must authenticate the final whole raw parent,
the old whole recipe parent and all adopted runtime bytes before import;
reconstruct every output row and unchanged metadata field; recollect
every SOS coefficient including constants and mixed terms; verify the
whole degree/live-variable/height/row-height census; and exercise the
full inverse order. Reverse whole-polynomial substitution by -delta is
an additional exact check. Both pure normal/-O rebuilds must compare
every generated artifact byte. No omitted-row or top-term sample is a
substitute for these complete comparisons.

Actual-artifact controls should include changed shift sign, duplicate
shift, omitted or wrong common-name association, stale old input hash,
changed constant/mixed SOS coefficient, skipped residual, wrong inverse
convention, stale old monic/free map, and an injected old search-history
claim. Controls must refresh endpoint hashes where appropriate and
reach semantic checks beyond authentication. Valid reordered-term and
canceling-term controls can exercise the independent polynomial collector.

This ordinary plan authorizes no execution. Any future wrapper, checker and
adopted closure require their own complete static reviews and a separate
root release. The first result could improve or worsen height and term
count; the present deliverable is only a fixed finite recipe, its exact
integer inverse and a bounded complete-verification plan.
