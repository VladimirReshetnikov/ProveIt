# Provider composition for the 87-gate HA endpoint

The existing 14-variable equation's HA proof-existence theorem is a separate completed result on its previously checked source snapshot. This note concerns the smaller 87-gate candidate. An unconditional all-IΣ₁-model no-zero/machine equivalence has been independently replayed within the adaptive provider's recorded boundaries, including the finite local-normalization lemma. `HAExpressionAssembly.ha_equivalence` has also been independently replayed: it constructs an actual HA equivalence from an explicit all-model machine bridge, but its direct HA imports and their transitive closure are inherited historical objects. The source `HAAdaptiveFactor87.lean` composes those theorems for the exact 87-gate expression, but it is not yet a checked endpoint.

The two independently replayed providers cannot simply be stacked. An initial scan found 119 common object paths and 118 byte differences, but it did not traverse seven HA namespace-directory symlinks. A subsequent source-directed comparison that follows those symlinks found 187 shared project-module objects in the unconditional adaptive source graph, 181 with different bytes. Object-byte differences do not establish semantic incompatibility, but they do prevent assuming that independent compiled proof chains form a coherent combined environment.

A source-import graph resolved through the repository's current Lake `srcDir` entries has 506 project modules in the generic HA assembler's source closure and 267 in the unconditional adaptive bridge's source closure, with a union of 722 before adding the new endpoint/check modules. These counts are a current-source dependency observation, not proof that historical objects match those sources. The full project graph includes ZFCinPA and BusyBeaver source dependencies; Foundation, Mathlib and other package internals remain separate inherited boundaries. The conservative ZFC receipt index in `reviews/adaptive-zfc-replay-index-author.md` is evidence for locating earlier receipts, not an authentication of the full closure.

## Provisional integration

The focused build preserves the complete historical HA project-object provider as an indivisible hashed boundary and selects its object on all 187 shared paths. It compiles the 75 affected adaptive descendants that are absent from that boundary, in source-import order, before compiling the exact 87-gate HA endpoint and checks. It snapshots all 267 current adaptive sources and all 506 current HA-closure sources, but **does not assert that the historical HA objects were produced from those HA snapshots**. It guards the HA object boundary, the adaptive peer anchors and each compiled source, saves complete logs and a failure status, and can resume an unchanged completed prefix. Package internals and remaining adaptive objects are inherited as recorded. The run compiled 32 modules and then failed on `ArithmeticAdaptivePopulation2011`: the preserved historical `ArithmeticHalfBinomial` object lacks two lemmas needed by the current adaptive source. The complete terminal evidence is frozen in `reviews/ha87-focused-post-zfc-merge-live`. An additive support module containing separately checked proofs of those two lemmas is under investigation; an alternative is to rebuild the affected shared graph coherently. Silently replacing the historical object would break this boundary. No 87-gate HA endpoint has been compiled.

Two earlier runs were stopped before any module compiled: the first would have rebuilt four shared byte-identical objects, violating the indivisible HA-boundary requirement; the corrected second was stopped when a new ZFC source merge was announced. Their actual terminal states and drivers are preserved in `reviews/ha87-focused-preauth-stops`. The post-merge source audit found unchanged module sets and direct import edges, and no changes to the 269 adaptive/endpoint source hashes in that stopped run; the HA source snapshots are refreshed for the new run.

## Rigorous source-current goal

A full source-current proof chain requires independent source/object provenance for the complete project closure, either through authenticated existing build receipts with their own checked transitive ancestry or by rebuilding the missing portions in dependency order. A 75-module provisional integration and unchanged historical object hashes alone cannot establish that provenance. Any full build must also account for future source merges, preserve successful prefix evidence, and recompile descendants when their source or authenticated imported objects change. The historical HA result, the new candidate's model result, provisional integration, and fully source-current result must remain separately qualified.

`research/ha87_full_source_rebuild.py` is a prepared (not yet full-run) topological project-source driver. It records current source snapshots and direct imported-object hashes, emits per-attempt complete logs and terminal failures, and supports unchanged-graph resume or a source/dependency-hash-checked rebase from a verified prior author prefix. It preserves ordinary warnings in logs, rejects errors and `sorryAx`, and checks the endpoint's reported axioms against the standard Lean allowlist. A package-only mirror keeps project namespaces out of `LEAN_PATH`; direct external package objects are hashed while their transitive package closure remains inherited. The independent long-lived `ArithmeticWangTable` worker is detected and left untouched: the default is an isolated build with its own output path, while `--wait-existing-wang` is an explicit resource-conservative option. A prior object is not reused unless its source and all direct dependency hashes match a verified recorded prefix. The first audit-only attempt failed before compilation because its initial Lake path lacked a direct Foundation object; that terminal state and driver are preserved in `reviews/ha87-full-source-audit-attempt1`. A revised package-only audit is still required, and no full source build has been started.
