# Retained-program interpreter: bounded attempts, no equality theorem

`FreeJRetainedProgram.lean` is a proposed closed list of 95 typed
instructions, generated by `generate.py` from the pinned
`positive12_95_degree70.json` (SHA-256
`2348183cb8e366433f668cdcc9d77ca9c7e2d0c55b7b630bda39bd8db7506d22`).
Each operand is a variable, port, integer literal or earlier gate; an array
interpreter constructs an `Expr (Fin 12)`. The attempted theorem would say
that this interpreted expression equals `Ordinary12FreeJ.literal p` for
arbitrary integer ports. File-to-table identity would still be an external
generator/provenance boundary even if the theorem were proved.

**No such interpreter equality has been proved in this prototype.**
Attempt01 checked the 95-row count but failed at the proposed equality's
`rfl` after 200,000 heartbeats; the displayed `sorryAx` in its error-recovery
report is not a proof. Attempt02 increased the bound to 1,200,000
heartbeats and reached its 180-second wall-clock timeout without producing
an object or completed equality report. The runner records its actual child
exit as `null`. In both attempts direct dependencies and selected provider
guards were unchanged at the recorded checks. Exact compiler logs, source
snapshots, receipts and provider inventories are under `observations/`.
The 3,000 MB Lean setting and point-in-time guard checks are not a continuous
whole-process-tree resource guarantee. This is a failed author-only
exploration, not a paired replay, graph/JSON or PDF byte binding, or iPRA
result. A separate prototype will explore a staged or direct expression
certificate without treating these failed attempts as imports.
