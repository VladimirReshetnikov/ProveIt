# Graph temporal and generic carry: proposed same-side closure

This is a source-only, point-in-time closure plan, not a Lean build or paired replay. It proposes rebuilding seven sources in this topological order: `BandCarryInputs`, `CompactBitRotation`, `ActualTemporalBand`, `FixedGraphTemporal`, `CompactDigitBound`, `CompactHeterogeneousCarry`, `GenericBandCarryFamily`. Exact source commits, hashes, imports and 22 expected axiom-report names are recorded in `scan.json`. Their existing evidence is author-side exploratory, not a same-side pair. The source scan returned exit 0 and rejected optimized mode; it did not run Lean or rerun the parent audit.

The seed is the independently audited graph-band pair `/tmp/ipra-graph-band-pair-01/{author,peer}/lib`, whose audit receipt is pinned by this scan. The inventory records 171 inherited objects per side with hashes and resolved paths, 60 external project companion slots, 140 currently empty target companion slots, and 20 package companion slots. It does not mix objects from the older divergent coefficient-decomposition provider. A prospective replay must rerun the parent audit, preserve same-side overlays, check source/output/direct/package companion identities and exact reports before and after compilation, and receive independent closure and driver review. Package-transitive and dynamic ancestry and point-in-time checks remain separate limitations.

`FixedGraphTemporal.fixed_graph_temporal` assumes positive graph coordinates and literal graph zero for fixed symbolic beta and the distinct `paramKernel rho`. It obtains the same N,w from the graph and replaces `w*C` by a bit-rotated temporal word without requiring radix alignment. The word is bounded by its radix-length and its individual radix-67 digits by the full radix minus one; it does not establish a digit cap of 3 for that temporal word.

`GenericBandCarryFamily.carry_input` is a separate generic externally finite-family result. It assumes a bounded C with digit cap 3, a bounded temporal word with full-radix digit cap, the output bound, a weighted finite-sum congruence, and the explicit weighted cap/mass inequality. It constructs the corresponding model-level heterogeneous `CarryInput` under those hypotheses. This closure does not instantiate that family with the concrete graph bands or derive its weighted congruence and mass inequality. It does not establish a clean predecessor, full graph-column/decoder or machine equivalence, retained K/display byte binding, or internal iPRA provability. Those remain separate obligations.
