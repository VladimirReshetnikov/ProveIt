# Restricted exact-wrapper envelope for the 14-variable document

`envelope.py` checks the complete TeX source against seven frozen, literal wrapper fragments in `envelope.json`, and returns the **actual source text** of six intervening regions: abbreviation block, boxed equation, fixed recipes, tile table, action decoder and decimal seed. It does not return a quoted equation, numerical port tuple, AST or a hash-selected output. A changed expression or seed digit is accepted when it still meets the envelope policy and is returned with the change intact; parsing and semantics of those regions are explicitly future work.

The wrapper includes the exact actual preamble and known definitions of `\sum`, `\fl` and `\rg`; no wrapper edit, addition before the document, or inserted global `\renewcommand` can be accepted. Each exposed mathematical region is scanned for ASCII and a closed TeX control-sequence alphabet, plus balanced allowed environments. A `\setlength` is limited to its exact displayed array-spacing argument. Comments, active `~`, `^^` character-code notation, unlisted controls (including `\def`, `\let`, `\newcommand`, `\renewcommand`, `\catcode`, `\csname`, `\input`) and disallowed environments are rejected. The seed is exactly twelve lines containing only decimal digits followed by `\par`. The actual symbols and domain declaration are in the fixed wrapper. This is an envelope/lexical policy, **not** a proof that every accepted hole is a valid TeX formula or denotes the intended mathematical expression. The unchanged fixed wrapper still relies on the specified interpretation of packages and standard TeX commands. No claim is made about general TeX or PDF rendering.

`specification.py` independently recognizes a proposed `(document, six holes)` relation using a different regular-expression decomposition and control-token scan. The checker confirms the actual page's reconstructed decomposition, compares both implementations on concrete mutations, rejects external and hole-local macro injection (including `^^`), checks seed shape, and demonstrates acceptance and faithful return of changed arithmetic and digits. These controls and two Python implementations do **not** prove a universal equivalence or soundness theorem. The fixed envelope records literal bytes represented in JSON, not a hash-to-equation lookup; the current checker pins the source and those fragments for reproducibility.

A Lean soundness theorem would require a Lean implementation of this exact scanner and an independently defined inductive accepted-envelope relation, followed by a proof that every returned decomposition satisfies the relation. Neither exists in this packet: a lemma about the Python implementation would not typecheck in Lean, and an implementation/specification both defined as the same test would be tautological. Actual recipe parsing, arithmetic parsing, typed recipe evaluation, `linePorts` equality, macro/engine correspondence, source-to-object providers and the PDF association remain separate obligations. No Lean/build/staging or axiom report was performed.
