# Held BFS-compatible trace75 reverse replay template

`run-template.py` is **not runnable as a replay**: both parent receipt hash constants are deliberately non-hash placeholders, checked before any parent file access or Lean invocation. It anticipates the live 31-stage provider's current output path, but its actual terminal result and outer receipt must be verified and pinned only after that run ends. Do not treat the anticipated path as an accepted provider.

The template reconstructs the full selected parent union from the parent's authenticated initial union and 31 stage records, checks every inherited BFS baseline companion, records the four same-hash retained baseline modules, snapshots the source/receipt/log evidence for the 13 source stages, preserves the outside baseline plus a separately captured extra direct outside bundle, and rechecks provider inventories before and after stages. It is intended to rebuild all 13 stages and compare the selected BFS halt-seed and band-carry closures with the parent and captured BFS companions. Header reuse is capture-relative. Its provider logic and policy are unreviewed; a final pinned runner needs explicit preflight, mutation controls, an outer exit-capturing wrapper, and independent prelaunch review before any Lean run.

The intended result would be a reverse-chain replay under the inherited provider and package boundaries, not a completed model equivalence, iPRA proof, full source ancestry, or external equation-file binding. In particular, the four baseline modules inherited from the BFS provider retain their historical source/object ancestry limitation.
