# Restricted four-operation scaled-product screen

[`screen-four-scaled-products.py`](screen-four-scaled-products.py) screens a new local replacement shape in the pinned 87-gate output DAG: two products followed by their sum or difference, then multiplication by an earlier node, i.e. `(x*y ± u*v)*z`. All five operands may be witness inputs, symbolic port inputs, literals 0–4, or earlier rows. It replaces one target row at a time and recomputes output liveness after inserting the four candidate rows. The fixed candidate JSON SHA-256 is `da6b88365da3ec9db6040373c25de20b30baf63edc9fdf742de2aa4b2c06e6e8`.

The screen examines only targets whose ancestor deletion potential, measured by replacing that row with a constant-valued row, is at least four. Four replacement rows add three operations relative to the original row, so deleting fewer than four existing rows cannot reduce this 87-row count. For this candidate the bound selects 18 targets; no target has potential exactly four. The [saved output](screen-four-scaled-products.out) reports zero candidate replacements and 18 skipped zero-divisor cases. Script SHA-256 `7ab8b5d73802ba3a0895311f4706c73137be3df32c3bcf7baced7ec5791a4776`; output SHA-256 `f00054426c5f34a434e91507bdbfe6a5693ea82a4c41d054a4b6d7e586ab6107`.

This is a heuristic screen, not an exhaustion or minimality proof. It uses three pseudorandom evaluations in the prime field modulo `2305843009213693951`, with seed `80281234`; symbolic ports are sampled independently. It skips division by any multiplier with a zero sample and excludes both product intermediates whenever their sample signature matches an existing input or earlier row. Recomputing such an intermediate can change which ancestor gates die, so the exclusion is not covered by the earlier screens. Sample collisions can cause missed or spurious matches. The search excludes every other four-operation shape, simultaneous rewrites of multiple rows, larger replacements, different constants and equations with merely equivalent zero sets. An initial narrower ≥5 run is subsumed by this final ≥4 target bound for this candidate and produced the same output.

From the repository root, run `python3 Computability/DiophantineConsistency/research/adaptive-first-root-factor87/screen-four-scaled-products.py`; the saved output was reproduced with both normal Python and `python3 -O`. Any future candidate would need an exact polynomial identity or zero-set proof, verification of topology and counts, and a Lean binding to the maintained equation before it can be reported as a reduction.
