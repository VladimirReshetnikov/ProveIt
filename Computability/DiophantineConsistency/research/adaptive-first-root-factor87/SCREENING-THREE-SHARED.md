# Three-operation shared-intermediate screening

[`screen-three-shared.py`](screen-three-shared.py) screens a third restricted three-operation replacement shape: the first gate computes an intermediate `x` from two earlier nodes; the second combines `x` with another earlier node; the final gate combines the second result with `x` again. Both subtraction orientations are considered. The script pins the same candidate JSON and uses the three field samples, prime, seed and available literals in [SCREENING.md](SCREENING.md). It checks the same 25 target rows selected by the dead-row potential test described in [SCREENING-THREE.md](SCREENING-THREE.md).

For each target, earlier node and operation pair, the target signature gives a linear or quadratic equation in `x` at each sample. The script enumerates finite-field roots, matches their three-sample tuples to all stored one-operation intermediate representations, inserts the three gates, and recounts the live output DAG. The [saved output](screen-three-shared.out) reports all 25 targets and no candidate with fewer than 87 live operations. Script SHA256 is `8eaadf3bdd07429431f7d8d7cd017c3957304b5abfbfbc50f21025e3345e8200`; output SHA256 is `4868462c44f434c89e86f36854b83d88ea29cc40da83e09ab05864b1bdd941a6`.

This is **heuristic screening**, not an exhaustion or a minimality proof. When a sample equation leaves `x` unconstrained, the script skips that case rather than enumerating the field. It replaces one target row, retains earlier-node order, and considers only the stated shared-intermediate shape and literals. Three modular samples cannot verify a polynomial identity, and the screen does not cover multi-target changes, longer rewrites, other constants or alternative equations. A reported candidate would require exact polynomial and liveness verification and Lean binding. No 86-gate equation is claimed.
