Both compiler execution and `lean --deps` use `owned.py`, with a newly created Linux session. The helper keeps the direct child unreaped while polling via `waitid(..., WNOWAIT)`. It waits for all live processes still in that session before reaping the direct child. Resource-bound signals target the original process group only after matching the unreaped leader's PID, start time, parent, process group, and session. Monitor errors cause a passive wait rather than returning and leaving the child behind; if process visibility cannot be recovered, this may wait indefinitely. Children that change process group but stay in the session are waited for; they are not covered by a signal sent to the original group. Descendants that create a new session, forced termination of the driver, transient observation races and kernel-level failures are outside the guarantee. `/proc` visibility and Linux wait semantics are assumed.

`controls-receipt.json` captures exit and output from non-Lean fixtures: a monitor exception with a descendant in a different group, direct-child reaping, threshold signaling, an identity mismatch that refuses signals, and an unrelated live sentinel. It also records that `--check` refused while the base was RUNNING. These are targeted negative controls, **not** an actual successful extension or proof that all process failure modes are handled. The v2 driver, including its positive build and dependency-resolution path, has not been exercised on Lean. Hashes for all four scripts are recorded in that receipt. No claim is made for package-transitive, dynamically loaded, or transiently modified provider ancestry.
