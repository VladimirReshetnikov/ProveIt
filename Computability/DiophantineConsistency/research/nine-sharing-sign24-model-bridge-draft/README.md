# Sign24-to-sign25 model bridge: source-only draft

`SharingSeed24Octic.lean` is generated by `generate.py` from the pinned,
independently audited sign24 external AST. Its first row is Y and its other 14
rows retain the external order. `check_syntax.py` parses those Lean expressions
back to the candidate AST, checks the coordinate bounds and confirms syntactic
residual degree at most four. This is a source transcription check, not a Lean
degree theorem or proof that the external port bytes equal Lean constants.
The generated syntax retains the 4,000,000-heartbeat option from the sign25
syntax generator; this is not a request to increase any execution limits.

`SharingSign24Squares.lean` adapts the checked generic square decomposition.
`Sign24Coordinate.lean` proposes a lift that inserts
`(beta * (v1 + 1) + 1)^3` in old coordinate 15, drops that coordinate in the
other direction, and extracts its value from sign25 seed zero. Its explicit
`hp0` assumption says that the integer beta port embeds as `ι beta` in the
model; it is essential for a natural lift, and is discharged at the actual
ports by the previously checked `Sign26CurrentHypotheses.port0` theorem.
The source expresses the cube as three multiplications to match the AST.

`generate_transfers.py` drafts all 15 old/new residual identities across
three five-row files. The old q3 first row is removed, so old remaining row
zero corresponds to the new first residual and the remaining rows have index
offset one. `check_transfers.py` parses all drafted old/new expressions and
checks the displayed row-index claims against both pinned candidate ASTs; it
does not elaborate the proposed proofs. Both the row and evaluation identities require Lean
compilation and review. The generated modules all depend on the proposed
coordinate client; any staged build must explicitly provide the audited
sign25 syntax/squares and generic sign33 squares objects, rather than rely on
an unverified search path.

The remaining assembly should prove forward sign24-zero→sign25-zero by
the q3 lift and all 15 transfers, and reverse sign25-zero→sign24-zero by
q3 coordinate recovery and `lift_drop`. Then preserve coordinate zero in the
two maps to derive same-input zero-existence equivalence with explicit hp0.
Specialize to the current represented beta, compose with the checked sign25
bridge, construct the direct 24-coordinate expression, and transport the
existing iPRA derivability theorem. These are distinct obligations. In
particular, successful row identities alone do not prove the assembled bridge
or the iPRA endpoint.

Run from this directory `python3 -I -S -B check_syntax.py` to reproduce
`syntax-result.json` and `python3 -I -S -B check_transfers.py` to reproduce
`transfer-result.json`. The two generators refuse to overwrite existing files;
run them in a fresh research subdirectory to reproduce their respective
sources and receipts. No Lean process has been run for this packet. Every
`.lean` file is an uncompiled proposal; there is no model-bridge or endpoint
claim. Independent review and a guarded build are required.
