# Independent read-only observation audit

The final survey reran successfully and reproduced all recorded `fresh`, `host`, `quoted`, and `union` data at the same Git HEAD; dynamic disk and memory samples are intentionally not compared byte-for-byte. Independent checks verified the 1,000-module base inventory and reported 4,179 direct inputs and 11,050 input-companion guards, 452 host source names (196 already in the base, 256 extra), and 91 host external direct names. The 25 names newly direct relative to the base manifest are not evidence that those packages or their complete transitive dependencies can be rebuilt together.

For the quoted-client trace the audit independently rechecked 238 non-base stage records, their snapshot/object hashes, 476 dependency/compile log hashes and successful exits, and 33,420 recorded companion guards. Seven of those stages came from FAILED parent states: AdaptiveEquationSyntax2011, ArithmeticPellPigeonhole, DiscreteOrderedRingFacts, ModelArithmetic, ModelDifferenceRing, Sign32GenericRemoveInput and WeightedExpressionDegree. Their individual recorded successes do not make the failed parent runs successful. Several historical runs have only the older recorded guard/timeout metadata; this audit does not retrofit the current monitor or authenticate all transitive package ancestry.

The union of the 256 host extras and 238 traced quote names has four shared names and 490 total. The proposed order independently respects every recorded host-source import and quoted direct dependency among those names. For 686 distinct tracked clean paths, the audit additionally read the captured Git HEAD blobs through `git cat-file --batch` and matched their contents to the recorded host/snapshot hashes; this is a point-in-time source check, not a Lean import parser. The source walk recognizes line-start `import` declarations and the quote walk uses previously captured direct edges. Neither observes all dynamically loaded, private-companion or package-transitive dependencies, or protects against changes during a future build.

The rerun observed approximately 5.43 GB free under `/tmp`, only about 0.43 GB above the inherited 5 GB threshold, with about 19.6 GB memory available. These are changing point samples, not a reservation or a sufficient-space estimate for 490 compilations. No Lean process was run. The correct status remains `OBSERVATION_NOT_BUILD_READINESS`; a concrete runner and actual provider/companion/route checks require separate review and execution.
