# Independent review: fixed iPRA closure and historical producer drift

The selected current `Direct80SymbolicFixedIPRA` import closure is **not yet a fully authenticated coherent historical rebuild**. Retained producer records for byte-matching outputs record nine direct dependency hashes that differ from the fixed client's selected closure; thirteen separately peer-matched historical adaptive output records contribute two additional recorded mismatches. The recorded object bytes do not by themselves establish that any such historical record was the unique producer of the selected copy, or that the mathematical theorems are unsound. They do show that identical final-search-path object hashes alone do not verify the dependency bytes recorded for all plausible historical producers.

`closure-audit-output.txt` captures a read-only rerun of `reviews/ten-positive-80-fixed-ipra-serialized-closure/audit.py`. It reconstructs the selected graph from the saved fresh headers and the pinned earlier 90 inventory, re-resolves first project/outside selections, rehashes all selected project candidates, verifies zero differing project-search-path overlaps, and checks recorded companion presence/hashes for reused prior objects. It reports 1,765 project names, 157 fresh headers, 80 outside names, 1,608 matching prior present companion entries. The latter count is `.olean` files: the prior inventory records no other present companions for those selections. Outside dependencies' own transitive imports and companions, fresh object companions, producer-time dependency provenance, package/dynamic behavior, and source-object ancestry are not established by this current-selection check. The fresh headers are captured author data and the reused headers depend on matching older object bytes; this review did not rerun Lean or independently deserialize headers.

The separate `check.py` independently checks the six nine-prefix successful receipt files against the recorded source, log and output object bytes; compares each individual direct-import recorded hash with the currently selected closure object; checks thirteen adaptive output records against the pinned historical author-state and peer receipt; and recomputes reverse reachability from the 11 mismatch records in the captured selected graph. Full old and final hashes and file paths are in `check-output.txt` and the two source reports, whose digests are recorded there. The nine-prefix records contain 9 differing direct-import hashes across 5 module names: `ModelArithmetic`, `ModelExponentialCongruence`, `ModelRatioBounds`, `ArithmeticPellPigeonhole`, and `ModelProductPell`; the sixth compared module has none. The two additional adaptive byte-matched historical records differ for `ArithmeticAdaptivePopulation2011 → ArithmeticHalfBinomial` and `ArithmeticAdaptiveConstructionAuxPhase2011 → ArithmeticPellRecurrence`. Peer-matching confirms the comparison against retained data; it does not establish a unique actual production history or an independently coherent full transitive rebuild.

Independent graph reconstruction gives 114 selected reverse-reachable project modules from the five nine-prefix seeds, and 122 from the combined seven seeds; all 122 have fresh headers and the set includes `Direct80SymbolicFixedIPRA`. This is **plan-only reverse reachability through captured imports**, not proof each module is invalid, a guarantee that 122 rebuilds suffice, or authenticated source selection. Other mismatches can enlarge it. The detailed report has already been used to motivate a coherent fresh-provider reconstruction, not to infer mathematical inconsistency.

The selected closure and matched-producer scans have useful but different scopes: the latter's 126 matched fresh producers, 25 explicit complete direct-pin lists and 31 unmatched objects do not close producer-time ancestry for the remaining objects. No independent Lean replay was performed. The checked fixed client remains a meaningful formally stated result for its selected symbolic graph, but source-to-object lineage, dependency compatibility, the external K0/file identity and the full iPRA endpoint must not be reported as completely settled on this evidence alone.
