the same Laurent generator. It also resolves Lambda to its intended
constant and Phi to the stored intended polynomial even when checking
their own defining expressions. The parser has no preceding context or
dependency validator to exclude those meanings.

Consequently these actual right-hand-side replacements are statically
seen to evade the intended mathematical checks:

- Lambda=Lambda collects to the expected constant despite being circular.
- Phi(x)=Phi(x) collects to the stored expected polynomial despite being
  circular and failing to define a finite constant recipe.
- Replacing x by rho inside Phi produces the same collected polynomial,
  although the resulting function is independent of its argument.
- Using free x instead of rho outside Phi likewise has the same formal
  value, although x is not a fixed integer defined in that context.
