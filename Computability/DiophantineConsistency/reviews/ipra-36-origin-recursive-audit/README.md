# Recursive origin trace for 36 inherited project objects

The reproducible audit resolves all 36 project objects whose actual origins were not established by the 848-ancestor comparison: six originate in the independently passed 41-module provider, 27 in the independently passed 94-module provider, and three in the author-only 848 provider. Starting at each actual resolved object path, it follows original recorded direct project imports to their physical origins, or authenticates the original transitive manifest for reused 848 records. It checks both the original object and the selected fixed-overlay object hashes, rehashes the states/manifests and all examined objects, and records paths and edges. It found 50 explicit provider records, 200 distinct selected project objects and 14 original 848 transitive manifests; all compared project hashes match. It does not resolve the separate two stale ancestor-identical users of `PRAPositiveMapPack`.

All nine recorded direct external occurrences (four distinct modules) in the 41/94 traces are individually rehashed, but the record does not assert a complete package-transitive or dynamically loaded environment. In particular, direct occurrences of `Intuitionistic.Deduction`, `Arithmetic.Basic.Hierarchy` and `Arithmetic.Schemata` were guarded by their original providers but are not all in the fixed endpoint's own direct external inventory; any strengthened replay should carry their actual object and companion guards. The 848 provider remains author-only. This is a historical project-origin audit, not a source-current proof.
