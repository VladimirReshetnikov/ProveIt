# Independent review of the direct-BFS kernel, decoder and mass

The captured receipt audit checks the three selected guarded author runs for
`DirectBFSSymbolicKernel`, `DirectBFSDecoder` and `DirectBFSCoefficientMass`.
It verifies current and archived source, runner, Lean binary, selected provider
and individually listed object hashes; four direct import resolutions; the
shared kernel object; logs, printed axiom targets and 13 sampled resource
observations. All three selected receipts and three retained histories pass
the stated checks. This is **not** an independent Lean replay or a full
transitive serialized, external package, dynamically loaded or historical
source-to-object ancestry audit. Printed Lean axioms are metatheory
dependencies, not object-theory iPRA axioms.

The separate external transcription check parses all 943 tuples from the Lean
source and compares them in order to the pinned direct-index `TILES.json`;
all coordinate widths match. The generator's `--check` reproduces the source.
Isolated controls confirm that it refuses to overwrite an existing source and
rejects a changed table or changed generated Lean text. These checks treat
the JSON as the retained input table: they do not themselves establish its
machine-language or color-conjugacy correctness.

Independently of the author's direct sum, the reviewer parsed the 41 copy
positions, aggregated the bare, reflected selector and reflected copy
coefficients by exponent, and evaluated their radix-`2^67` polynomial by
Horner shifts. Its complete 74,111-byte little-endian representation equals
both the indexed-enumeration and 80-row candidate K payloads, with raw
SHA-256 `0a86821a704294199c2e1a50379d242c96840a3366e9d965689ba3d74605203f`.
The manually transcribed coefficient formula was compared with the pinned
Lean source text, and the separate author byte check was rerun. This is
external finite evidence; it does not execute the Lean definition or prove a
Lean equality between `paramKernel` and a filesystem payload.

The kernel source defines the direct-BFS list and its own `paramKernel r`;
the checked declarations give list length, coordinate bounds and a cast
identity for an arbitrary natural radix in each stated IΣ₁ model. The decoder
works with this same direct table and assumes Boolean selector values and a
copy word below `2^41`; it gives the stated local no-carry iff for either an
empty word or a selected tile with matching payload. It does not derive those
decoder hypotheses from a graph zero.

The mass source computes its selector, copy and stencil sums over this direct
table and proves the listed inequalities. Independently summing the parsed
rows gives selector mass 12,777,109,108,488,111, copy mass
2,251,799,813,684,224 and stencil mass 30,057,817,844,344,676, and verifies
the three stated arithmetic inequalities. These numbers are tied to the
specified sum and should not be identified with differently defined
historical thresholds without an additional argument.

The completed checks do not prove the 80-graph band/carry connection for this
new kernel, the full direct-BFS tile/color conjugacy, machine/controller
calibration, a positive-zero equivalence, external JSON/PDF binding inside
Lean, or an iPRA endpoint.
