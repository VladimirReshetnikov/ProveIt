# Independent scoped prelaunch inspection: 31-stage BFS-compatible runner

This is a static and read-only inspection. No Lean stage or rebuilt closure was run by this reviewer. The reviewed `run.py` SHA-256 is `2ddba90180ad65825b0d77d68f9965f936948c2d5efb7aa9259d7b31d2e25054`; `run-outer.py` is `9974d2d7ed23e87178445cd671c6e18fd17c820c8333355e0117b0cd95610613`. Their packet and receipts are in `research/trace75-bfs-compatible-provider-rebuild/`.

The independently executed read-only preflight of the prior runner (before the source-copy symlink fix) returned exit 0 and reported 1,931 BFS baseline objects, 80 outside objects, 15 supplements and 31 stages. The final runner's pinned preflight receipt reports the same inventory. The fix was exercised independently and by the packet's actual-function control: a copied source replaced by a same-byte symlink is rejected. The 15 policy controls also cover diagnostic/report mutations, a dangling outside shadow, source drift and companion clobbering. The reviewer independently executed the actual copied wrapper in temporary directories and verified rejection of a modified runner, an existing outer observation, and a dangling child observation before child launch.

The runner links the captured baseline, does not overwrite its entries with supplements, checks source/receipt and entire pinned producer logs, checks copies and union bundles before and after stages, and compares the serialized project closures of both selected BFS roots against the captured BFS project companion hashes. It first-resolves captured outside modules and compares their bundles. The reviewer independently compared all 192 modules shared by the two captured header tables with equal object hashes and found their recorded import lists equal. All 31 historical stdout logs were read: each contains the named standard axiom report with `propext`, `Classical.choice`, `Quot.sound`; one module reports two theorem names. No historically recorded diagnostic matched the current rejection pattern.

The revised wrapper pins runner, preflight and policy, captures the actual child exit and before/after hashes, and requires a parseable child result with status PASS. The reviewer exercised its gate with a temporary wrapper copy whose input hashes were adapted to stub children: missing, malformed and FAILED child results were rejected, while a PASS result with child exit 0 was accepted. Post-run review must still check the actual outer exit, child result hash and retained receipts.

This evidence is capture-relative. It does not prove the source ancestry of the four affected modules retained from the BFS baseline, transitive outside/package/dynamic ancestry, build success, or sufficiency for later reverse/model/iPRA clients. The proposed replay remains held for coordinated release; this review does not launch or authorize a run.
