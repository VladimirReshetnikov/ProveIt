# Independent prelaunch review: matching-based word clients

This no-Lean review covers the corrected drivers at commit `6c0618cf46`, after the originals incorrectly interpreted the matching audit's terminal-observation schema. Both corrected drivers accept the actual pinned parent observation and reject twelve missing, conflicting or boolean-exit variants; the unchanged originals demonstrably reject the actual observation. The source and seven exact input pins of each driver, exact axiom report names, common matching-parent receipt, two fake compiler/dependency children per driver and direct companion/interpreter/output guards are checked. The fake loops additionally reject wrong names and axiom sets, warnings, `sorryAx`, extra dependencies, compiler failure, monitor stop, differing peer objects and a changed after-audit. No real paired build was run by this review.

The forward theorem starts from an existing positive cyclic `MarkedWord`, with the original row bounds, marker and east/south matching conditions. It maps each row to a compact row, proving boundedness, explicit exclusion of compact row 1, marker and the same two local matching conditions. It does not prove existence of an initial word, a reverse map, the semantic coding or iPRA provability.

The inverse lookup theorem has a left-inverse result for original indices below 942 and a right-inverse/image result for compact indices below 943 with row 1 explicitly excluded. Its separate `inverseLookup_defined` declaration is a Σ₀-function instance. It does not itself exclude row 1 for arbitrary words, give reverse word transport, establish calibration, or prove an iPRA endpoint. Both drivers inherit the parent provider, external finite-table binding, incomplete axiom-inventory, package-transitive and dynamic-ancestry limitations. The initial loader must be trusted and clean, stable HEAD and sole Lean must be enforced externally, and sampled process/resource monitoring does not cover `--deps` or the parent audit.
