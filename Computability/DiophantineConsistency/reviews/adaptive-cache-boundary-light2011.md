# Cache-boundary source rebuild pilot

A low-priority isolated pilot rebuilt the first five source modules in the seven-module 62ff cache-boundary chain: `BusyBeaver.Core`, `BusyBeaver.ZFC.KZip`, `KDenseBridge`, `KTableCore`, and `KTable215`. All five compiled successfully against the source-guarded composition and the newly rebuilt predecessors. Each output object hash differs from its corresponding inherited 62ff cache object, even though the source hashes match. The reason for the byte differences was not established.

The driver left `KDense215` and `DecimalMachine215` excluded, and did not replace any object in the accepted composition. Because the five object hashes differ, they cannot be substituted into existing consumers without auditing and rebuilding the affected downstream closure. Independent replay at `/tmp/adaptive13-cache-boundary-light-lysi5eaz` passed with all five source, object and complete-log hashes matching the author pilot; it also confirms all five differ from the inherited cache. The driver used idle I/O priority, nice 10, a 3 GB Lean limit, and reauthenticated inherited guards, providers, and all seven source snapshots at the end. The five compiles took 1.2–3.3 seconds each and peaked at approximately 450–485 MB RSS. The existing unused-simp-argument warning in KZip is retained in the full log.
