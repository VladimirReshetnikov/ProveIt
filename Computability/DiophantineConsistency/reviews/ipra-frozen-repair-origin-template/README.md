# Gated fixed-snapshot project-origin repair preparer

This is a **preparer template**, not an executed audit, plan, Lean proof, or source-current claim. Do not execute it until both fixed 13-variable endpoint peers have terminal PASS states. It requires their matching ordered rows, logs, warning lists and direct input hashes; verifies the complete selected project inventory against those rows and prior prefix/base records; and reads only the fixed 1,103-source snapshot. It follows each candidate's physical original provider, source snapshot, compiler log, state and project dependency records. Unknown or mismatched origin data makes the affected current source module dirty rather than authorizing reuse.

The known `PRAPositiveCode` and `PRAPositivePackedNormal` seeds, unknown candidates, source reverse edges and recorded original project-dependency edges are closed monotonically to a fixed point. Historical project dependencies not reached by the target source graph are still traced and pinned when retained. Source snapshots and every dirty source import must be available; failures in the baseline, package resolution, frozen snapshot, or final before/after guard abort plan emission. The result deliberately overapproximates the modules needing rebuilding: any object depending on a dirty object is dirty even if the latter might later recompile byte-for-byte identically.

On successful execution it creates a new `../ipra-frozen-repair-plan/` exactly once, containing captured copies of both the preparer and replay driver, plus a manifest. The plan schema contains `author_state_path/author_state_sha256`, `peer_state_path/peer_state_sha256`, `fixed_manifest_sha256`, all 1,103 `source_sha256`, full `parent_inventory` including present project sidecars, `origin_guard`, dirty `order`, `direct_imports`, `external_files`/`external_absent`, absolute `external_direct_paths`/`external_absent_paths`, `external_resolved_paths`, `external_lookup`, `lean_sha256`, and the replay `driver_sha256`. It additionally preserves `known_seeds`, `unknown_or_mismatched_origins`, traced `origin_nodes` and boundary information. Hash and parse the emitted manifest and driver from single captured bytes before executing two independent peers.

Both package mirror and toolchain presence/absence are guarded for every encountered direct external import; the selected lookup is mirror first and toolchain second. This does not authenticate package-transitive or dynamically loaded ancestry, and the inherited 848-project ancestor is author-only. Workspace drift is intentionally irrelevant to the frozen result and must be addressed in a separate current-source rebase.
