# Independent review: direct-BFS tile fields and block orbit

This review covers the frozen `DirectBFSTileFields.lean` and `DirectBFSBlockOrbit.lean` statements and their accepted author receipts, not a Lean replay. `check.py` compares current source, runner, copied source, output and logs to recorded hashes, checks pre/post pins and direct import snapshots, resolves first direct imports on the recorded `LEAN_PATH`, and checks that their object hashes occur in the runner pin list. Exact paths and hashes appear in `check-output.txt`. The runners construct a path-to-hash map from explicitly pinned objects and resolve/recheck each direct source import before and after Lean. Full transitive selection, source-object ancestry, package and dynamic-library boundaries remain inherited. Both accepted logs report `[propext, Classical.choice, Quot.sound]`; no `sorryAx`, warning or error was found.

`DirectBFSTileFields.tile_fields` is for every `i : Fin 943` in every `IΣ₁` ordered arithmetic model. For the decoder's direct tile value it identifies binary slices `(25,9)`, `(8,9)`, `(17,8)`, `(0,8)` with that same **direct** row's south, north, east and west fields, respectively. The proof applies the direct row bounds and the general payload field/cast theorems. There is no graph-zero hypothesis, but neither does the statement bind an arbitrary graph window to this tile or establish equality/conjugacy with an original table row. Its accepted object is SHA `68fef4ae214e8a9992ef32b9f476da016bc99e73941d9b36bf86f019cd5ede66`; direct inputs are the pinned decoder and `TilePayloadFields`.

`DirectBFSBlockOrbit.SelectedBlock N C h` means existence of a direct index whose selector digit is selected and whose copy word is the corresponding direct tile value. The four printed claims are:

* `decoded_occupied` needs all 41 copy digits at the stated arbitrary `n,C,k,T` bounded by 1 and a copy-word equality to a specified direct tile `i`. It concludes each bit with index `j≥34` is 1 (seven bits, indices 34–40).
* `selected_iff_digit` assumes `h<N` and the **direct decoder conclusion at that block**; then a selected block is equivalent to existence of a model digit index `j<943` whose digit at `8807*h+j` is 1. Its equivalence alone does not establish the decoder conclusion.
* `occupied_successor` assumes `0<N`, `h<N`, the quantified marker equality on positions `k<8807*N` with residue 1073, uniform band inputs **at h**, a selected block **at h**, and the direct decoder conclusion **at `(h+1)%N`**. Only then does it prove selection at that successor.
* `orbit_all` takes `0<N`, a direct decoder conclusion at **every** `h<N`, a selected base block 0, and an independently supplied closure step `SelectedBlock h → SelectedBlock ((h+s)%N)` for every `h<N`. It concludes `Occupied C N s t` for every internal model `t`. The preceding successor theorem only provides the special `s=1` closure under its additional uniform and marker hypotheses; `orbit_all` does not derive its general step from a graph zero.

The accepted block-orbit object is SHA `0faaa0cef80907550b5dcdcf0ac9168c351c6c1d3473f35e0875d90b3c65453b`; its direct imports are the direct uniform decoder and three original arithmetic marker/orbit bridge modules, all individually selected and pinned. The statements do not themselves establish their decoder, marker, base or step assumptions for a graph valuation, lift finite color conjugacy, prove a machine halt/converse, bind JSON or the PDF equation, or produce an internal iPRA proof.
