as an oracle for the displayed mathematics. The map remains useful review

## 3. Exact local-block proof of the entire circuit

A sparse integer polynomial is represented by a dictionary from sorted
symbol/exponent tuples to integer coefficients. Addition, subtraction and
multiplication collect coefficients exactly. Exponentiation is binary
exponentiation with a fixed natural exponent. Zero coefficients are
removed; no randomized, modular or numerical identity test is used.

The validator checks every literal node's kind, binary predecessors and
topological position. A backward traversal from node 463 must visit all
464 nodes, including all nine variables and all eleven fixed leaves.
Counting the actual live operation nodes must give exactly 433 with the
accepted complete breakdown. The domain, output and exact-degree metadata
must be exactly those of the unchanged pinned parent.

The validator then reads all 40 actual displayed definitions, in their
display order. For each definition, earlier checked cuts become formal
indeterminates. The actual parent DAG is recursively evaluated backwards
until those cuts, with its fixed coefficient recipes expanded over all
four formal native ports. The printed right side is parsed independently
into the same free ring. Exact equality proves that complete block.
Afterwards the newly proved cut may itself be used as an indeterminate.

The two large fixed scales are represented temporarily by named formal
atoms only for the literal printed numerals 2^864026 and 2^6480184. Section
5 separately reconstructs their complete integer payloads and all other
fixed leaves. This device neither discards their values nor introduces
unquantified free coefficients into the final equation.

There is one explicit shared-register bridge. The actual source computes

    node375 = node374 - 1 = R.

After the full R block has been proved and that exact literal row has been
checked, node374 may be replaced by R+1. The k block reuses node374 rather
than traversing node375. The bridge is therefore an exact consequence of
the already checked row, not a guessed inverse or numerical observation.

Finally the actual complete boxed expression is parsed and compared with
the DAG tail above the checked Theta, Omega, a0 and a1 cuts. The union of
the local backward evaluations must cover every one of the 464 nodes.
Induction over the 40 checked definitions plus this final identity proves
equality of the entire displayed polynomial and the whole literal parent.
The method avoids expanding a polynomial of degree 1,628,768, while
providing no unaudited gate or interface. The inherited exact degree is
therefore the displayed polynomial's exact degree as well.

## 7. Rendering, PDF text and visual obligations

The renderer reads the frozen equation.tex; it never emits or rewrites
mathematical TeX, a graph, a coefficient payload or a parent artifact. It
uses a fresh temporary directory and the standard TeX packages already
named in the standalone file. Shell escape is disabled. A fixed source
epoch and UTC are used. Full pdflatex stdout/stderr and the full engine
log are retained as normalized text, with only scratch paths, trailing
spaces and the diagnostic wall-clock header normalized.

A successful materialization must have one 612-by-792-point Letter page,
no overfull box, the exact nine-positive signature, printed cost/degree,
the entire alphabet and all 722 literal seed characters. The current
reviewed design uses 9-point arithmetic with 9.0 leading and 8-point seed
text. The old 9.6-leading design is archived with its actual fit failure. An 8-point
arithmetic fallback is NOT silently applied. Failure to fit is an actual
obstacle to report, followed by an explicit layout review and new pins.

The separate validator extracts text from the actual PDF. Every front
variable/operator/coefficient/exponent stream is compared in whole ordered
blocks with the actual TeX: boxed tail, all ratio definitions, both lists
and all three kernels. Delimiter punctuation is ignored in this PDF stream
comparison; it is fully checked by the actual-TeX parser. All seven native
formula blocks have every printed numeral checked in order, with large
sum limits placed in the PDF extractor's upper-before-lower order. The
complete alphabet and seed must be exact in actual extracted text.

Native sum/floor fonts can have extractor-dependent glyph names. Their
exact full operator/variable syntax is proved from actual TeX, while a
SEPARATE visual review of the actual PDF remains mandatory. The programs
do not claim an automated comparison of every native operator glyph or
that no-overflow alone establishes legibility. Full-page and enlarged
visual inspection must verify the dense front, all native formula blocks,
the complete table and seed. This limitation is explicit in the receipt.

Normal and optimized pure rebuilds re-typeset in private scratch and must
compare all five generated artifacts byte for byte: PDF, extracted text,
normalized stdout/stderr, normalized full log and rendering metadata.
Normal/optimized JSON receipts differ only in the declared optimization
flag when they otherwise describe the same command. No reviewed source or
formula file is changed by either materialization or checking.
