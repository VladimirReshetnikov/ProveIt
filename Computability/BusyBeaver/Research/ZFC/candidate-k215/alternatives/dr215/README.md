# DR215: a direct-transfer, reparameterized consistency machine

**A concrete 215-state candidate with a checked ordinary proof of the blank-tape Con(ZFC) equivalence. No 214-state machine was found.**

Read [report/report.pdf](report/report.pdf) for the full mathematical argument, exact dense transition table, formalism experiments, and the remaining one-state problem. Its editable source is [report/report.tex](report/report.tex), with the complete table in `report/machine_table.tex`.

The main result for the exact delivered machine is

```text
ZFC proves: not Halt(DR215, blank) <-> Con(ZFC).
```

This is an ordinary mathematical proof formalizable in ZFC. It uses the repository's inherited numerical-calculus/ZFC calibration and arithmetic macro contracts, together with fresh verification of this source, table, and startup. The different DR215 table has **no newly compiled Lean/Rocq endpoint** in this packet. The primary K215 parent's formal status is not transferred automatically.

## Main candidate

DR215 combines the accepted ST215 direct single-guard transfer with the row-local rho6 parameter symmetry. Both component ideas are inherited; the new contribution is their exact checked composition, repaired proof compiler, and independent source/table/startup binding. It changes the numerical axiom generated by a fixed AX tuple, so it is a source-level alternative rather than just a state renaming.

The direct command is

```text
S(t,w,d,h) = HALT,                           if h = 1;
S(t,w,d,h) = (h, tail(w), d, head(w)),        otherwise.
```

It has 35 primitive source occurrences. The sixth AX row now emits

```text
(Ex_A Q_A B) -> B
```

instead of `(Ex_A Q_A C) -> C`. All parameters range over all natural numbers, so the full axiom family is identical. The revised strong selector is

```text
DISCARD; AX(a; a,v); S^7; H^3
```

for the desired theorem `(Ex_a Q_a v) -> v`. The report proves its exact stack restoration, the strong proof compiler, cofinal successful candidates, and protected-tail soundness.

Only two native transition rows differ from ST215:

| Row | ST215 | DR215 |
|---|---|---|
| 199 / 1 | 1 R 166 | 1 R 12 |
| 206 / 0 | 0 R 186 | 0 R 76 |

The four changed source operands are at zero-based ordinals **958, 963, 1136, 1141**, all changing register 3 to register 5. Every source path, opcode and guarded successor ordinal remains unchanged. The literal macro word changes from `aacQFIQFIcI` to `aabQFIQFIbI`.

## Reproduce the positive results

From the archive's root, using Python 3 with assertions enabled and a fresh output directory:

```sh
python3 -B verify.py --work /tmp/dr215-research-finite
python3 -B verify.py --runtime --work /tmp/dr215-research-full
```

The default replay verifies the top-level hash manifest and runs:

1. Deterministic DR215 reconstruction from pinned ST215 inputs, source census, two complete CFG resolutions, exact closed-macro binding, complete native/dense blank replay, all 177 source-prefix steps, the 3,728-node dominated-row certificate, saved runtime inventory audit, and frozen-corpus comparison.
2. Reconstruction of all four marker tables, their finite all-tape simulation premises, every mapped old-step startup boundary, exact dense relabelings, and an independent auditor that imports no builder code.
3. Rooted/reflected comparison against the frozen corpus and the subsequently added main ZC215 table.

The `--runtime` option additionally **rederives all 6,151 arbitrary-natural primitive contracts**, comparing every fresh case record with the saved record. The full candidate replay was executed successfully during preparation. It used about two minutes in this environment; elapsed time is not a correctness claim. The top-level final replay and original full-runtime receipts are in `evidence/` and `DR215/evidence/`.

No network, external repository checkout, solver, or third-party Python package is needed for these positive checks. The ordinary mathematical soundness arguments and inherited calibration remain explicit proof dependencies; Python verification is not a proof-assistant kernel certificate.

## Formalism experiments

`formalism/` contains the calibrated antecedent-exchange family, exact source variants, portable searches, compact receipts, and an independent DR215 proof review.

The retained dominated propositional basis derives both directions of

```text
X -> (Y -> Z)    <->    Y -> (X -> Z).
```

Exchanging the curried antecedents in any selected subset of rho2, rho3, rho5 and merged G therefore preserves every numerical theorem code. This is stronger than the equiconsistency required by the task. Gates and the set theory bundle remain unchanged.

## The failed 214-state search

`selector_research/` records the attempt to share one physical selector between two marker mergers. It includes exact C++17 scanners, inputs, inventories, receipts, and a relative-path Python wrapper.

The final DR215 census covers 200 disjoint pair combinations from a selected inventory of 21 marker pairs. Its **1,172,377,600 parameter specifications** comprise 707,406,332 individually evaluated cases and 464,971,268 uniformly pruned cases, with no survivors. Radius seven, at most 97 transitions, left-moving exceptional entries, and the prescribed edit shape define its scope. A failing path that never reads the variable selector row justifies pruning all remaining settings of that row. Specifications need not produce distinct machines.

```sh
cd selector_research
python3 -B run_census.py --verify-recorded
python3 -B run_census.py --suite all --output /tmp/dr215-selector-census
```

This establishes a bounded discovery failure, **not** semantic inequivalence of every tested table or a lower bound. An optional synthetic positive control is clearly separated and has no ZFC calibration; no generated control table is presented as a candidate.

The report also explains the failed direct/MP-first allocation: moving a clear routine changes the predecessor context needed by a compressed physical implementation, while early prefix-only allocations missed an arithmetic use of row 134/0. These failures are not accepted machines.

`source_experiments/fused30/` contains a different source-level idea: fuse the cache-to-top copy into the destructive cache-equals-one guard and cleanup. The corrected body has **30 occurrences instead of 35**, but the complete source DAG increases to **208 instead of 201**. Its all-natural source proof, literal recipe, two CFG checks and finite corroboration are included. The initial exploratory continue-depth bug is explicitly corrected (CC3 is required). This is an unallocated source experiment with no binary-state claim. Run `python3 -B source_experiments/fused30/check_fused30.py` for its source-only check.
