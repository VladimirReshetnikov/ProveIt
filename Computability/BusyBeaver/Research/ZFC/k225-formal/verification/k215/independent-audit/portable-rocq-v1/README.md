Lines 109–112 then reuse that record without the assumption gate or saved-log validation. Thus a first run could stop on this assertion and a second run skip it. The successor should record explicit gate success before allowing reuse and verify the exact saved log and assumption reports on the reuse path.
2. **Bind reuse to the toolchain.** Lines 95–101 record the selected compiler and stdlib globally, overwriting the previous toolchain file. Lines 105–112 bind reuse only to canonical source, direct imported objects and output object. A different same-version switch/compiler could reuse old objects while the old toolchain provenance is lost. 3. **Handle SIGTERM explicitly.** The process wrapper handles Python exceptions and KeyboardInterrupt by terminating and waiting for the child group before lock release. Python's default SIGTERM action does not raise such an exception. A SIGTERM handler which raises into this cleanup path is needed for the broader termination-cleanup claim. No uncontrolled interruption of a current proof process is asserted by this review.
