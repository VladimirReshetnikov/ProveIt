\section{Compose Rocq balanced lookup with normalized equality}
Automatic-certificate evidence inspected during this review already combines normalization with inherited balanced certificate blocks on the Lean side. The idea of balancing normalized data is therefore not new in general. The concrete contribution here is an independently checked \emph{Rocq} composition of the new balanced lookup interface with normalized branch equality; the inspected automatic Rocq lane still uses list-based \texttt{NCheck}.

The two archived Rocq refinements address different costs. Normalization removes implicit trailing-zero pointer aliases, reducing correspondence to 1,426 entries. Balanced storage reduces indexed lookup cost. Their existing theorems cannot simply be interchanged: the balanced checker refines literal-path equality, whereas normalized branches require equality of infinite zero-padded paths, \texttt{ibeq}.

The proposed small Rocq glue keeps the existing valid-tree lookup and flattening theorem. It changes only branch/entry wrappers so that a branch checks increment counts and two normalized endpoint equalities. Its key refinement is
\[
 \operatorname{nbcheck}(t_1,t_2,T)
 =\operatorname{ncheck}(t_1,t_2,\operatorname{flatten}T)
 \quad\text{when }T\text{ is valid}.
\]
The source-halting theorem then follows from the existing normalized checker's soundness. No new path semantics, segment evaluator, or simulation induction is needed. The glue, exact identifiers and concrete instance remain \textbf{uncompiled}.

The owned complete finite check parses the current source-tree literals and the archived packed path encoding, checks every index lookup against list lookup, and checks all 2,851 branches including initialization. It obtains:

\section{A guarded 189 node arithmetic interface}
The previous 367-node affine core contains 174 copies of one triangular loop and four conditional-clear loops. Exact recognition and ranked contraction leave 189 nodes: 188 tests and one halt, with 376 edges. Updates are now short ordered programs of affine matrices and guarded summaries, not unrestricted polynomial expressions. The resulting JSON is slightly larger than the preceding affine representation despite fewer control nodes. This is a reusable semantic interface, not byte compression, a smaller Turing machine or a demonstrated faster proof.

\subsection{Triangular recurrence with arbitrary scratch}
Every recognized triangular node tests register $R_6$. Put $x=R_6$, $s=R_1$, $y=R_7$. Its nonzero branch first decrements $x$, then its exact matrix yields
\[
 (x,s,y)\longmapsto(x+s-1,\ 0,\ y+x+s)\qquad(x>0).
\]
All other registers are unchanged. If $x=0$, the body is skipped: scratch $s$ is preserved and nothing is added to $y$. If $x>0$, let $n=x+s>0$. The first iteration clears scratch and adds $n$, leaving $x=n-1$; the remaining iterations add $n-1,n-2,\ldots,1$. Thus the pre-exit summary is
\[
 \begin{cases}
 R\text{ unchanged},&x=0,\\
 R_6=0,\ R_1=0,\ R_7=y+T(x+s),&x>0,
 \end{cases}
 \qquad T(n)=n(n+1)/2.
\]
The zero-exit matrix is applied \emph{after} this summary and may modify any register. The contribution is $T(x+s)$, not $T(x+s)-T(s)$: $x=1,s=5$ adds 21, not 6. At $x=0,s=5$, it adds zero and preserves five. A scratch-zero invariant is neither needed nor assumed.

The universal argument separates the first nonzero iteration from the scratch-zero countdown and uses $T(k+1)=T(k)+k+1$. It consumes exactly $x+s$ nonzero steps and one zero exit when $x>0$, or just the zero exit when $x=0$. A claim that every iteration decreases $R_6$ would be false: the first iteration may increase it when scratch is nonzero.

\subsection{Conditional clear and composition}
The four other loops decrement $R_6$ and clear $R_5$ on each nonzero iteration. Their summary preserves all registers if $R_6=0$; otherwise it sets $R_6=R_5=0$ and preserves the rest. Unconditionally clearing $R_5$ would be wrong on a zero entry. They consume the old $R_6$ nonzero steps and one exit.

Every removed node has a checked rank that strictly decreases when its exit is another removed node; maximum rank is seven. Each retained nonzero branch explicitly decrements its tested register \emph{before} its edge program. Matrices, summaries and zero-exit updates follow their literal order. All local summaries terminate on arbitrary natural registers and consume at least one step; each retained edge also has its own test step. No halt is eliminated. These facts support both halting implications and preservation of final registers, with the original retained initial node and identity entry transform.

For the present pair of identical canonical source graphs, direct normalized or canonical equality is still simpler than this additional contraction pipeline. Use the arithmetic interface when comparing genuinely different loop implementations or sharing a source-level arithmetic proof, not merely because the displayed node count is lower.

\section{Reuse the quotient theorem and the generator}
The existing \texttt{relSat\_congr} duplicates a formula induction even though the same module already proves \texttt{sat\_quotient}. Move congruence after that theorem. Pointwise related environments have equal quotient images by \texttt{mk\_eq\_iff}; function extensionality gives equality of quotient environments. Rewriting both sides through \texttt{sat\_quotient} proves the original congruence statement. Its dependency graph is acyclic: the quotient theorem does not use the congruence being removed.

The proposed parent file drops from 216 to 192 lines. The generated \texttt{KQ1Model} has the same opportunity and also duplicates 54 lines of model-independent syntax and two structural inductions. Replace that block by 17 lines of aliases/wrappers to the existing parent syntax. The generated file drops from 219 to 159 lines; combined Lean-source reduction is 84 lines, not 84 net repository lines, because the generator grows. No object-size or speedup claim follows.

Apply the parent patch, then change the generator and regenerate. The aliases must be inserted \emph{after} its namespace transformation; inserting them earlier would rewrite parent references back to self-referential aliases. The owned tool only rewrites inert text. Neither the received generator nor the proposed modified generator was executed, and the Lean files remain uncompiled. Exact regeneration, idempotence and dependent endpoint compilation are next checks.

A further quotient-core interface needs only reflexivity, symmetry and transitivity of the existing relation; extensionality is added only where used. Larger model hypotheses and a witness remain necessary later for actual model existence and the final consistency theorem. Sharing helpers must not silently remove those endpoint assumptions or change the quotient's domain presentation. A new shared module may also add build dependencies, so fewer source lines need not mean a faster build.

\section{Close the append-zero runtime boundary}
The maintained \texttt{KTape.boxLemmas} already factors its engine through agreement on 44 rows plus an increment-tail contract. ST215 and DR215 agree on all 44 rows, and their two changed decoder rows lie outside that set. This is existing infrastructure, not a new scanning theorem.

There is nevertheless an exact missing premise: maintained \texttt{IncTail} and the concrete box interpretation append spare value one, while ST/DR use the row $198/0=0\mathrm{L}40$ and append zero. Row agreement alone does not instantiate the maintained engine theorem. The earlier dependency checks correctly left box lemmas assumed; they cannot be upgraded to a physical proof by ignoring this difference.

Parameterize the box interpretation and increment postcondition by a fixed Boolean spare value. Generalize the final tail segment once, then thread that parameter through concrete interpretation, oracle/step/executor soundness and the simulation extension witness. Other box contracts are unchanged; arbitrary suffix return lemmas already exist. The ordinary K215 instance uses one and ST/DR use zero. Replacing only the final witness is insufficient because the whole tape interpretation currently fixes the spare value.

An independent six-step local tail check starts at state zero, head at the first of four zero cells, and covers both spare values. Every read stays within that window; it ends at state 40, head back at its first cell, with exact contents $[1,0,1,a]$, preserving arbitrary exterior tape. This isolates a small proof obligation but is not the parameterized kernel theorem. The owned access-logged audit confirms exact symbolic-state and progress-flag equality for 6,012 unchanged guards, freshly checks 139 affected guards, and exercises all 36 oracle interfaces. A generic trace-dependency proof must compare every actual table lookup, including absent-row results and failed-oracle fallbacks, and combine with the correctly parameterized box soundness. Until then, these are conditional reuse opportunities, not a complete DR physical theorem.
