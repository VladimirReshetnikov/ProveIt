# K215 proof transport and the search for 214 states

This packet reviews ProveIt at commit
`b6c7087477e51c017003bd729e712c8969733223` and supplies a small formal
correctness-transfer route for the existing conditional-marker CM215 machine.

**Results:** the literal K215 and CM215 dense machines are proved equivalent
for blank-tape halting in Lean 4.32.0. The underlying local theorem covers
every initial binary tape and head position from control zero. A generic
positive-block theorem is checked in both Lean and Coq. No 214-state machine
was constructed; the completed bounded searches and their exact limits are
included.

Read [the report](report/report.pdf) for the full argument, proof audit,
candidate comparison, search methodology, and further research questions.
Its complete editable source is [report.tex](report/report.tex).

## What is new here

The K215 and CM215 machines, their source program, numerical calculus, and
foundational calibration are inherited from ProveIt. This packet contributes:

1. A three-clause inductive tape invariant and a kernel-checked concrete
   CM215 simulation, preserving the entire tape and head at comparison points.
2. A reusable theorem: terminal agreement plus a positive-block forward
   simulation between deterministic partial systems implies halting
   equivalence. A reverse certificate is unnecessary.
3. A checked adapter to ProveIt's exact `KDense215.machine215` and an actual
   `Machine 215` built from the literal CM215 rows.
4. Structural measurements and a checked finite graph congruence suggesting
   a smaller source certificate: 2,240 zero-offset entries, 32 local signatures
   including halt, and 1,423 stable graph classes.
5. Complete specified reduction searches over fourteen pinned tables, with
   independent positive controls and replayable receipts.

## Strongest freshly checked machine statement

```lean
CM215.CoreBridge.core_blank_halts_iff :
  KDenseBridge.BlankHalts KDense215.machine215 ↔
  KDenseBridge.BlankHalts CM215.CoreBridge.machineCM215
```

Both sides use the repository's actual finite-support dense machine semantics.
The concrete all-tape theorem is `CM215.all_tapes_halts_iff`.
The printed dependencies of the new transport and bridge results are only
`propext` and `Quot.sound`; they contain no `sorryAx` or extra assumption.

The compiled `CM215.CoreBridge.calibration_transfer` takes the established
K215 endpoint as an explicit theorem argument and transports its proposition.
The 30-line `integration/CM215Endpoint.lean` instantiates it with the existing
ZFC refutation theorem. **That integration wrapper itself has not been
compiled in this packet.** The complete 185-module baseline was not rebuilt.
The checked local
transport and exact semantics bridge are complete; the old full calibration
is inherited, and its existing records are not described as freshly rerun.

The generic `PositiveStutter.v` was compiled with **Coq 8.18.0**, and recursive
`coqchk` passed with both public results closed under the global context.
The repository's original full proof uses **Rocq 9.1.0**. This packet does not
claim a new concrete CM215 Rocq endpoint or a Rocq 9.1.0 replay.

## Reproduce

Python 3.10+ and the standard library suffice for the default identity and
local-window audit:

```sh
python3 verify.py --work /tmp/k215-packet-audit
```

Add `--source` to regenerate the source graph analysis. Add `--search` to
compile the C++17 search, rerun all small controls, and replay the primary
all-window inherited-family search. Use `--full-search` to replay all recorded
large searches. All work directories must be new.

Compile the twelve selected Lean modules from fresh source, with Lean 4.32.0:

```sh
python3 build_formal.py --lean /path/to/lean --out /tmp/k215-small-lean
```

The driver records compiler identity, source and object hashes, exact
commands, successful logs, and assumption reports. It uses one worker,
serial compilation, and a 3 GiB Lean memory cap. The smaller 2 GiB cap was
too tight in a clean rebuild of the final table-certificate block; the cap
is configurable with `--lean-memory-mb`. It never imports the full
K215 endpoint or presents the integration wrapper as checked.

For the generic Coq theorem:

```sh
mkdir /tmp/k215-generic-coq
cp formal/PositiveStutter.v /tmp/k215-generic-coq/
cd /tmp/k215-generic-coq
coqc PositiveStutter.v
coqchk PositiveStutter
```

The report builds using two `pdflatex -interaction=nonstopmode
-halt-on-error report.tex` runs from `report/`.

## Search outcome and limits

Family A evaluated 17,708,928 full-table fold specifications across fourteen
inputs and two initial domains. Family B evaluated 159,509,360 individual
branch specifications on primary K215 and CM215 in both domains. The latter
number is **not** a count of distinct machines. Both found zero real-machine
survivors. The radius is seven, and the local join fuel is 97 on each side.

These are finite proof-template searches, not proofs that every rejected
machine is incorrect and not a lower bound of 215 states. The initial-window
abstractions overapproximate reachability. Coordinated edits, longer joins,
new representations, source/compiler changes, and interacting branch
implementations remain outside parts of the search. Full details are in
`reduction_search/README.md`.

## Integration policy

Preserve the existing K215 machine and calibrated theorem. Add CM215 through
the checked transport theorem and run the existing project's full endpoint
audit after integrating the wrapper. Keep source-certificate compression as
a separate proposed refactor until all literal path bindings and the final
endpoint pass through its own checked soundness theorem.

The ordinary mathematical argument transports the repository's ZFC-provable
equivalence. This packet does not construct a new proof encoded in ZFC's own
syntax or close the internal PA formalization milestone.
