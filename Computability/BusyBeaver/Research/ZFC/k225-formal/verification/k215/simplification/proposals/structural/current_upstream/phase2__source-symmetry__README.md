# One source certificate proves both directions

The generic [offset bisimulation proof](../../../../../../../../Lean/BusyBeaver/ZFC/RMOffsetBisim.lean) now proves symmetry by exchanging the two programs and negating the integer register offset. The tested register has offset zero in both directions, and the branch count equation reverses under negation. At the initial offset zero, both halting directions concern the same arbitrary register file. `ocheck_halts_iff` therefore needs only one checked forward certificate.

[KSource215](../../../../../../../../Lean/BusyBeaver/ZFC/KSource215.lean) uses this theorem with the existing forward certificate. Its endpoint statement, both programs, all surviving data declarations, and all 16 forward check files are unchanged. The 16 separate backward check modules and 18 mirrored data declarations are removed. The data module shrinks from 653,569 to 456,548 bytes; this is a mathematical removal of redundant checking, not a different machine or certificate.

The isolated generic proof passed in 0.365 seconds, and the exact forward-only facade passed in 0.415 seconds. Their raw logs report only `propext` and `Quot.sound`. These experiments used the then-current phase-one objects before adoption; the current canonical closure is checked separately in the [phase-two build](../lean/README.md). No complete endpoint rerun is claimed by this feature receipt.

The [independent source peer](evidence/peer/review.json) checks offset negation, both branch cases, and the unchanged initial registers. The [preservation receipt](evidence/candidate-review.json) compares every retained declaration and all forward files; the [preparation receipt](evidence/prepare-regeneration/review.json) shows that the modified preparation script preserves the maintained forward-only generator and reproduces its other six outputs byte-for-byte. Direct source generation also reproduced all 16 forward checks exactly.

The source generator is now maintained directly rather than derived from the old two-direction 219 template. The [generator delta](evidence/candidate.diff) and [adoption ledger](evidence/adoption.json) bind the changes. The first isolated elaboration failure is preserved in `evidence/run1`; it was repaired without changing the mathematical statement or proof limits. The historical runner and staging scripts retain their original scratch paths and are evidence, not portable fresh-build entrypoints. Use the maintained generator and the common phase-two reproduction instructions for the current source.
