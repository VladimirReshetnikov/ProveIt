The complete argument, comparison and limitations are in **report.pdf**, with

## Results

| Component | New verified contribution | Boundary |
| --- | --- | --- |
| `normalized_rocq/` | A 1,426-entry ordinary Rocq source-correspondence checker, its soundness proof, exact all-register theorem, and same-name public facade | Source layer; full binary-to-ZFC endpoint not rebuilt |
| `decoder_lean/` | Arbitrary-tape finite-window refinement and chain composition, instantiated with 281 literal blocks and 234 decoder roles | Local blocks and finite structure; source-path/primitive/return integration outstanding |
| `zero_credit/` | Concrete Cantor codec, parser inverses, strict injective tag lowering, and every finite-prefix credit inequality | Exact scheduler-codec layer; physical ZC215 adapter outstanding |
| `search214/` | Coordinated two-merge/one-selector synthesis across 18 frozen reference tables; independent invariants and controls | 457,682,472 specifications checked; zero accepted 214-state machines |

**This archive contains no verified 214-state ZFC machine.** Its 215-state tables
are frozen reference inputs from existing work, not newly discovered machines.
The synthetic 11-to-10 control validates a local search mechanism only.

The normalized Rocq data plus retained codec occupy **109,958 bytes**, compared
with **173,003** for the incoming ordinary compact presentation and **1,499,170**
for the original offset certificate. The entry count drops from 2,240 to 1,426.
These are source-data measurements, not claims of full-proof size or speed.

For an alternative 215-state proof, M124/FM215 has the smallest inspected local
marker invariant, while CM215 may be quicker to integrate because an incoming
packet already supplies its Core bridge. For a cleaner independent scheduler,
ZC215's zero-credit injection removes the reserve/debt calculation. M124 and
FM215 are distinct literal machines; their exact one-row difference is included.

## Verification performed

* **Normalized source:** Coq 8.18.0; 12 fresh source/dependency compilations;
  separate recursive `coqchk` of the concrete theorem; public facade and typed
  client both compiled; closed assumption reports. Full recursive check exited
  successfully after 521.235 seconds. The focused 12-module compilation took
  80.632 summed compiler seconds. These are observations, not baseline comparisons.
* **Decoder:** Lean 4.32.0; three fresh modules, 41.646 summed compiler seconds;
  all 281 block checks proved in the kernel; semantic results use only standard
  Lean axioms and no `sorryAx` or `native_decide`. An independent Python audit
  binds every literal row, source node, role and expanded occurrence, and checks
  malformed controls.
* **Zero credit:** Coq 8.18.0; fresh compilation and recursive `coqchk`, five closed
  reports. The concrete proof uses only the standard library.
* **Search:** all 18 bounded searches completed; all invariant domains were
  independently checked and regenerated byte-for-byte. The positive and negative
  controls were checked by an independent dictionary-tape simulator.

The production toolchain's complete ZFC endpoint has **not** been rebuilt in this
work. In particular, the local Coq 8.18 compatibility route is not evidence of a
new production Rocq 9.1 build. Every component records its own exact scope.

## Reproduction

Start with the lightweight package audit (Python 3, standard library):

```sh
python3 verify.py
```

This verifies released hashes, incoming identities, saved proof/source bindings,
the normalized certificate, the independent decoder audit, marker comparison,
and search-invariant/control audit. It does not invoke proof assistants or repeat
the exhaustive synthesis. For hashes alone, use `python3 verify.py --hashes-only`.

Replay the formal components and optional full bounded search separately:

```sh
python3 zero_credit/reproduce.py --output /tmp/zc-credit-fresh
python3 decoder_lean/build.py --lean /absolute/path/to/lean --out /tmp/decoder-fresh
python3 search214/verify.py --work /tmp/search-audit
python3 search214/verify.py --work /tmp/search-replay --search
```

For normalized Rocq, run `python3 build.py` then
`python3 complete_interface_audit.py` from `normalized_rocq/`; see its README for
namespaces, version handling, and the explicit upstream integration steps.
Use fresh output directories. Build objects and toolchains are intentionally
excluded; historical logs retain original absolute build paths for provenance.

Rebuild the report with `sh build_report.sh` (pdfLaTeX with standard TeX Live
packages). Generated LaTeX auxiliary files do not belong to the release manifest.

## Attribution and integration

`NOTICE.md` distinguishes new implementation from inherited ideas and data.
Component notices preserve relevant third-party licenses. The full seven
incoming archives are not duplicated here.

The immediate integration recommendation is to preserve the exact accepted
machine and public theorem while replacing its source-correspondence layer.
The facade exports `K215F.Source215.p215_dagPerm` with the same type. After
updating generators and dependency manifests, rebuild `Correct215` and
`CorrectDense215` under the repository toolchain and inspect endpoint assumptions.
The decoder and zero-credit components are foundations for subsequent adapters,
not already-installed replacements for the complete site/runtime proof.
