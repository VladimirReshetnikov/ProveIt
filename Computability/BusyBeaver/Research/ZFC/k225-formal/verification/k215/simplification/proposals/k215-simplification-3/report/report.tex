{\LARGE\bfseries Simplifying the K215 correctness proofs}\par\vspace{8pt}
{\large Two shared commutations, faster checks, and a small transport theorem}\par\vspace{5pt}
{Research contribution for Vladimir Reshetnikov's ProveIt project}\par
{21 October 2026 UTC}

\begin{abstract}
The best next simplifications are in the machine/source correspondence, not another rewrite of the set-theoretic argument. Two independently investigated source programs have identical control-flow topology; their only primitive differences are adjacent independent increments generated by two shared templates. Reversing those two templates makes their complete ordinal control-flow graphs identical. Alternatively, their original increment-count basic-block graphs already agree. This suggests replacing a general 2,240-entry correspondence certificate with a canonical-site checker reusing the existing bisimulation theorem.

There is also a small immediate implementation opportunity: the site checker still uses linear transition lookup, although the repository already proves a fast trie equivalent to that lookup for bootstrap checking. Reusing this equality avoids inventing a new simulator. For a different 215-state candidate, CM215 has the shortest incremental proof route: transport the existing exact-machine theorem through one local invariant and two three-step blocks. This does not remove the inherited proof dependency closure.

The accompanying code verifies concrete data, graph equalities, local simulation obligations and restricted state-reduction searches. Formal refactor drafts are explicitly uncompiled: neither Lean nor Rocq was available in this environment. No new kernel endpoint or calibrated 214-state machine is claimed.
\end{abstract}

\section{Answers and priorities}
The three questions have different answers.
\begin{enumerate}
\item \textbf{How to shorten and simplify the existing proofs?} Separate the small mathematical content from repeated path lookup, certificate indexing, and table evaluation. The strongest new structural observation is that two shared increment-commutation templates explain the entire source discrepancy. The lowest-risk computational change is to use the already proved transition trie in site checks and narrow their imports.
\item \textbf{Is another 215-state candidate easier to prove?} \textbf{CM215 is the best incremental choice.} Its correctness can inherit the existing endpoint through a small TM-level positive-stuttering argument, with no new proof enumerator, axiom recovery, source-runtime theorem or bootstrap run. There is no demonstrated overall winner for a complete proof rebuilt from scratch. The newly reviewed GC-ZC215 architecture simplifies protected-tail accounting, but still needs a new compiler and scheduler proof. Our shared-pop215 is not recommended as the easiest formalization: it adds a new sentinel compiler and a protected-tail theorem.
\item \textbf{Can we presently supply 214 states?} \textbf{No calibrated 214-state construction was obtained.} The restricted searches and invariant analyses below are reproducible negatives, not a general lower bound. A smaller raw allocation is not a consistency machine until its logical compiler and blank initialization are proved.
\end{enumerate}

\section{The source correspondence is almost a structural identity}
\subsection{Exact comparison}
The raw program has 4,751 expanded source leaves. Of these, 1,425 are pure control operations: 98 breaks and 1,327 continues. Resolving them leaves 3,326 register-effect/halt occurrences:
\[
 1,900\ \text{increments}+1,425\ \text{decrements/tests}+1\ \text{halt}.
\]
The two inspected programs have identical occurrence kinds, initial occurrence and successor ordinals. Their labels differ only by 256 adjacent independent-increment swaps:
\[
\begin{array}{c|c|r}
\text{shared structured node}&\text{normalization}&\text{expanded occurrences}\\\hline
188&\operatorname{Inc}(6);\operatorname{Inc}(7)\mapsto
       \operatorname{Inc}(7);\operatorname{Inc}(6)&175\\
190&\operatorname{Inc}(6);\operatorname{Inc}(1)\mapsto
       \operatorname{Inc}(1);\operatorname{Inc}(6)&81
\end{array}
\]
Changing only those two shared nodes makes the \emph{complete ordered ordinal CFG} equal, including all successor edges. No branch enters the second instruction of a swapped pair except through its first instruction. These are independently executed structural checks on both the literal Lean and Rocq data, not conclusions inferred merely from zero offsets.

\subsection{Route A: two local contracts and a canonical CFG theorem}
For distinct registers, increments commute on every natural-valued register file. Lean already has the relevant update-commutation and sequencing lemmas, and \file{RMTransfer.closed_of_contract} can lift one changed node's total contract to root-run equivalence. Apply that machinery twice, preserving the old structured program and its calculus proof.

The remaining reusable theorem should connect an executable source program to its canonical ordinal CFG. It must establish:
\begin{enumerate}
\item exact correspondence of the initial instruction;
\item exact register effects and both decrement branches;
\item termination of each collapsed control-only segment;
\item preservation and reflection of halt;
\item positive concrete progress between semantic boundaries.
\end{enumerate}
Then finite equality of the two canonical graphs completes the source bridge. A generic compiler must reject an unresolved or cyclic control-only segment rather than silently erasing possible divergence. The observed finite graph equality is evidence for this route, \emph{not yet a kernel proof of that generic theorem}.

\subsection{Route B: keep both programs and compare basic blocks}
The original programs already have identical test/halt basic-block graphs when an edge records the multiset of increments before its next test. Thus one can avoid even the two source rewrites. A canonical-row checker can reuse the existing segment-run and increment-count lemmas; a separate basic-block compiler is an alternative, not a prerequisite.

There are only 1,426 canonical test/halt sites. The current 2,240 certificate entries include 814 redundant representations of the same sites, differing in residual path representation. Rocq already has trailing-zero path-equivalence lemmas; Lean exposes the analogous site boundary. A canonical-path checker can use these results, but must prove alias preservation instead of replacing literal path equality by an unchecked heuristic.

The preferred Lean adapter can retain the existing \file{RMBisim.Bisim.halts_iff}. Let the relation hold when both raw paths are consumed by \file{tsite} to a common certified canonical row. A checked row supplies halt or the same tested register and two existing \file{BranchGood} facts. Unpacking that row gives the existing \file{Bisim.step} obligation. Existing segment lemmas already account for increment/control execution. This needs new finite-checker soundness adapters and an initial-row proof, but not an entirely new TM semantics library. Merely deleting aliases from the current raw-path \file{ORel} certificate would be unsound: the relation must change first.

The current general certificate checks 4,479 branches per direction:
\[
 2\cdot2,239+1=4,479,
\]
where the final term is the initial branch. The canonical graph has 2,851 analogous obligations, including its initial edge. This is a reduction in concrete obligations, not a measured kernel runtime improvement.

Further exact labeled-bisimulation minimization reduces the 1,426 canonical sites to only 1,423 classes: three pairs and 1,420 singletons. The quotient preserves the exact tested registers, ordered positive/zero branches, increment-count vectors, and initial edge. This bounded negative favors the simpler canonical-row relation: removing three more rows is unlikely to justify another class-membership layer, while every path still needs binding. It is not a Turing-machine state reduction or a general program-minimality result.

\subsection{A safer intermediate step}
All 2,240 source-certificate offsets are zero. For Rocq, the existing ordinary bisimulation checker has the same path/segment semantics and can avoid the offset extension. For Lean, an older plain decoder supports only 128 iterations while actual certificate paths reach 176 bits. Do not switch to it blindly. Keeping the current 512-iteration forward checker and using its now-implemented signed symmetry is already a safe improvement.

A separate data-tested Rocq prototype stores paths as positive binary integers with a sentinel bit, preserving leading and trailing zeros. It changes the certificate source from 1,499,170 to 178,532 bytes, an 88.09\% reduction. Every one of the 4,480 paths and every successor index round-trips exactly. The ordinary checker was independently replayed in Python in both directions. The proposed Rocq files still require parsing, typechecking, kernel evaluation and endpoint assumption checks.

\section{Reduce repeated computation and unnecessary dependencies}
\subsection{Use the fast table that already exists}
Bootstrap already uses a list zipper and balanced transition trie. Replacing its sparse-list interpreter is therefore not a new opportunity. The site checker, however, still evaluates the linear table at the inspected latest snapshot.

The repository's \file{fast215} theorem already gives pointwise equality between fast lookup and the literal machine table for every natural state and input bit. In Lean, function extensionality turns this into equality of the table functions. Prove the unchanged finite site check using the fast function, then transport the result back using that equality. No new machine semantics, bounded-tape assumption or simulator soundness theorem is necessary. In Rocq, carry pointwise table equality through an evaluator-equivalence induction; do not add a functional-extensionality axiom to endpoints that are currently closed.

Independent linear/trie executions agree throughout all 6,176 guarded site cases and all 2,442,801 symbolic steps in the prototype. They make 1,635,510 table requests. The Python operation model counts 100,886,942 linear list-cell visits versus 13,084,080 trie branches. These are \emph{abstract operation counts}, not Lean benchmark results. The kernel might share or evaluate representations differently; measure actual checking after the small refactor.

The bootstrap was also replayed independently across sparse-list, zipper and bounds-checked bitset models. All 95,714 steps and thirteen exact checkpoints match in state, head and whole-tape support. The observed head range is $[-18,199]$. This confirms the concrete implementation data; it is not a reason to replace an already verified bootstrap implementation unnecessarily.

\subsection{Separate data dependencies from proof dependencies}
All nine \file{KSites215Batch000} through \file{008} import the full source-equivalence proof although their direct reference is only \file{KSource215.t215}. Narrow these imports to the data module and retain the old import at the public facade for compatibility. A static name-use audit and patch are included; no compiled success is claimed.

This does not shorten the clean build by the entire site-check time. It avoids invalidating expensive site checks when only the source-equivalence proof changes. The relevant historical batch work is 1,692.447 seconds. A further split should place stable program/tree definitions separately from changing correspondence-certificate data, so even certificate edits do not invalidate the site batches.

\subsection{Share semantic infrastructure across candidates}
Thirteen K215 calculus files are identical to K217 after changing only import namespaces: 96,926 bytes and 1,803 lines. Seven copies of the offset-bisimulation module are byte-identical. Move these developments into stable shared modules, retaining thin compatibility facades as needed. Also generalize the candidate-specific 155-line dense-state relabel proof and its hard-coded finite case split.

Keep the final endpoint statements and the useful universal-initial-register-file source theorem unchanged. Source shortening should not quietly weaken theorem scope or add axioms. The existing large finite certificates are untrusted producers' output checked by proved mechanisms; compression must preserve that boundary.

\section{CM215 is the easiest next incremental endpoint}
CM215 has 215 working states and changes six rows of the verified native K215. Its native SHA-256 is
\begin{quote}\small\path{e5907f08e0752eada0e25bbf33680341e80e5fe94b52b409aea1ed039edda252}.\end{quote}
Let $K$ be the original machine, $M$ CM215, and
\[
 \phi(q)=\begin{cases}52,&q=176,\\q,&q\ne176.\end{cases}
\]
The old roles 52 and 176 share the new state 52; physical state 176 becomes an intermediate selector. This is why the construction remains 215 rather than 214.

\subsection{Replace history reasoning with a local invariant}
For reference configurations, use
\[
\begin{aligned}
q=52&\implies\tau(h-1)=1,\\
q=156&\implies\tau(h+1)=1,\\
q=176\ \land\ \tau(h)=0&\implies\tau(h-1)=0.
\end{aligned}
\]
The middle clause makes this a one-step inductive invariant. The only predecessor of state 156 writes 1 and moves left. If state 156 subsequently takes its one branch, it returns onto that written 1, so its exceptional transition to state 176 cannot enter the zero branch. The other incoming edges establish the required predecessor markers directly. Control 0 satisfies the invariant on every initial tape.

The new zero-branch blocks are
\[
52\xrightarrow{0L}176\xrightarrow{1R}129\xrightarrow{0R}154,
\qquad
52\xrightarrow{0L}176\xrightarrow{0R}185\xrightarrow{0R}168.
\]
They exactly simulate old state 52/0 and 176/0 respectively. Both restore the inspected cells and end one cell to the right. All other old transitions take one new step under $\phi$.

Our standalone finite checker validates invariant preservation and these global-effect templates on all 6,840 satisfying state/five-cell-window cases. It also synthesizes a stronger radius-one invariant automatically, requiring only 4,444 accepted cases. The synthesis treats every newly exposed exterior bit nondeterministically; it never assumes it remains blank. Its output is an untrusted certificate, not a theorem by itself.

\subsection{The small generic theorem}
\begin{theorem}[Positive stuttering transport]
Suppose machines have total step functions with absorbing halt. Let a source invariant hold initially and be preserved. Assume related configurations have equal heads, extensionally equal tapes, and controls related by a map that preserves and reflects halt. Suppose every source step from a nonhalting configuration is simulated by $k\ge1$ target steps, reaching a related configuration, with no premature internal halt. Then their related initial configurations are equihalting.
\end{theorem}
\begin{proof}
Extend the block schedule at an already halted source by one absorbing target step. Recursively define the target clock $f(0)=0$ and $f(n+1)=f(n)+k_n$. Induction gives related configurations at source time $n$ and target time $f(n)$, and $f(n)\ge n$. Source halting at $n$ yields target halting at $f(n)$. Conversely, if the target halts at $t$, absorption makes it halted at $f(t)$. Reflection of halt then makes the source halted at $t$. Thus no inverse state map or new logical completeness proof is required.
\end{proof}
For CM215, $k\in\{1,3\}$ and the exact clock before halt is $f(n)=n+2v(n)$, where $v(n)$ counts the two modified zero branches.

Two implementation details are essential. First, the finite checker needs a locality theorem: every checked block reads/writes only inside its supplied window and leaves the exterior untouched. Second, Lean's tape is a finite-support list; writing and restoring may change its list order. Use equality of all tape reads, not literal list equality. Native/dense label bridges must bind the certificate to the exact already verified table and the new canonical table.

Zero-duration stuttering is not enough. A permanently looping source can be related to a target about to halt if every source step is matched by zero target steps. Positivity is what closes the converse direction.

\subsection{What this does and does not save}
The new CM215 endpoint can compose the original K215 theorem with the local transport and state-label bridges. It does not need another 95,714-step bootstrap proof, another 6,176-case runtime proof, or another enumeration/calibration development. It still imports the original proof and its dependencies. Therefore this is a claim about \emph{incremental proof effort}, not the smallest possible foundational development.

For proofs from scratch, R41 is a reasonable controlled decoder benchmark: unchanged command semantics and clean initialization, with maximum address depth 47 reduced to 41. ST215 has a 201-node source but introduces a transfer compiler and protected-tail reasoning. Shared-pop215 adds an even more elaborate sentinel compiler and a three/four-head debt theorem. Smaller source counts alone do not make these proofs easier.

\section{Other proof-oriented simplifications}
\subsection{GC-ZC215 simplifies resource accounting}
The independently supplied proof-simplification/GC-ZC215 packet was reviewed as data and mathematical text; none of its executables was run. Its corrected hybrid is an actual 215-working-state candidate with 430 rows, not merely a source proposal. Its native table SHA-256 is
\begin{quote}\small\path{4122c18a347028ee6643428b70a8d5c81218d4937d672be3626981d7b50bf503}.\end{quote}
An owned finite audit checks the packet manifest, exact local transition blocks and a whole-tape blank-prefix replay. The final native start is 74. After 117,004 transitions it reaches the command root with $N=1$, empty residual $L=0$, and opaque tail $W=5$. The earlier 69,143-step frame is only intermediate. Its source has 203 distinct subtrees and 4,752 leaves. The claimed 6,177-case arbitrary-natural runtime derivation was \emph{not} independently rerun, and no Lean/Rocq endpoint was compiled.

The ZC scheduler enumerates every raw candidate from zero. For each NIP occurrence in candidate $n$, replacing that occurrence by DROP and re-encoding gives a strictly earlier candidate $m<n$. Exact parsing preserves the occurrence position; changing that DROP back recovers $n$, giving an injection from pops into earlier pushes. Thus every finite execution prefix has enough protected heads, without an AX batch-size estimate, diagonal-density bound, or positive initial reserve. This is a genuine simplification over the ST/shared-pop resource arguments. It depends on equal push/pop arity, exact monotone encoding, exhaustive increasing enumeration, and preservation of the stack across candidates. The generic uncompiled credit prototype does not discharge those machine-specific premises.

GC additionally changes the ninth AX head's binder source. It removes the counter-loading $J(i)$ step from GEN, but adds a changed AX contract and a gate-nonfalsity obligation. Its marker merge relates the hybrid to a newly allocated 216-state precursor, \emph{not} directly to the verified original K215. Therefore CM215 remains the shortest incremental endpoint. The ZC architecture is a serious proof-oriented alternative, especially for cleaner initialization/resource accounting, but no complete from-scratch proof-size advantage over the original is established.

\paragraph{Attribution and overlap.}
The incoming packet independently proposes offset-bisimulation symmetry, sentinel-bit Rocq path packing, and context-sensitive prefix sharing. These are overlapping prior/parallel contributions, not new discoveries attributable solely to this report. Its 61-line symmetry draft, 190,411-byte compact certificate and 107-line credit prototype are explicitly uncompiled. Lean's signed symmetry is already upstream; our 178,532-byte packing experiment is a separate encoding of the same original certificate. Keep these contributions and their verification status distinct.

\subsection{A fixed successful candidate suffices at the literal cutoff}
A separate simplification applies to the already constructed \emph{common-NIP} command interface, not to GC-ZC215's different opcode assignment. In the completeness direction, assume a finite refutation and let $B_1$ be its compiled word. The established compiler then supplies
\[
 U=\mathrm{STORE}_0;\mathrm{STORE}_0;B_1;R;R,
\]
which halts from every natural command-boundary work-store, possibly before its last command. Its first command is $\mathrm{AX}(0;0,0)$, whose common-NIP opcode is 2. Hence its exact positive-continuation code is $P(2,r)\ge2$ for some natural $r$. The literal initializer leaves next candidate 1 and an empty residual. Ordinary increment-by-one enumeration therefore reaches this one fixed successful candidate unless it has already halted. No varying-parameter $\mathrm{START}_Y$ family, padding construction, or new length lemma is needed for this literal cutoff.

An opcode-independent check uses the already established credit bound $|W(n)|\le n+1$ and the exact codec round trip. Since $|\mathrm{STORE}_0|=10$,
\[
 \operatorname{code}(U)\ge |U|-1=21+|B_1|\ge21.
\]
For arbitrary cutoffs, residual domination and positive continuation yield the generic inequality $\operatorname{code}(v)\ge |v|-1$ for nonempty words. Prefixing a universally halting word by $N$ arbitrary commands then puts its code beyond cutoff $N$, provided each prefix command terminates normally or halts. This does not imply reachability under a skipping scheduler, nor does it replace protected-tail soundness in the opposite direction.

The current phase-four \file{EnumPerm} is a different four-command enumerator and already has a four-line specialized code bound and nine-line general completeness proof. The generic lemma is a reusable abstraction, not a demonstrated reduction in that current file's source, dependency closure or checking time. The detailed ordinary proof and explicitly uncompiled Lean adapter are in \file{enumeration/}; no sealed proof or machine was changed.

\section{The 214-state question}
No calibrated 214-state machine was constructed in this investigation. Two complementary restricted searches were completed.

\paragraph{Local selector synthesis.}
A three-row family contains 5,916,800 candidate tables. The initially conservative left-prefix boundary was subsequently extended using the exact known blank-left tape. All trials are classified, including independently replayed cycles; no step cap remains unresolved. No candidate satisfies the chosen first-right-exit and exact-child-state contract. This excludes only that fixed family and contract, not arbitrary 214-state implementations.

\paragraph{Proof-directed window abstraction.}
For the original K215, CM215, ST215 and shared-pop215, least fixed points were computed at radii 1 through 5, both from blank and arbitrary initial windows. All 40 certificates independently pass initial inclusion, inductive closure and leastness checks. Every abstraction retains all 215 working states and 430 read rows; no direct compatible merger or ordinary step-for-step bisimulation merger appears. The largest domain has 440,320 state/window pairs. These are unbounded inductive overapproximations, not simulations for a bounded number of TM steps; nevertheless their failure to remove a state is not a global lower bound.

A separate 200-node common-rotation source did allocate to 214 states under finite screens, but its inference interface has an adjacency invariant that prevents nontrivial detachment from the intended clean proof store. It is quarantined rather than counted as a result. A mathematically repaired interface costs 202 source nodes in the measured family.

The next disciplined search should synthesize small transition rewrites \emph{together with} finite-window transport certificates. Fix a candidate state identification, bound the changed rows and local simulation length, and solve for a table whose local blocks match the reference under a checked invariant. Every survivor must then pass the generic soundness theorem and exact initial/halting bindings. This keeps proof simplification and state reduction aligned without accepting an uncalibrated small table.

\section{Implementation and validation plan}
\begin{enumerate}
\item Pin the exact input tables, sources and toolchain versions. Keep the original kernel-checked endpoint available as a regression target.
\item Apply import narrowing and the fast-table site-check refactor first. They preserve existing theorem statements and reuse proved equalities. Rebuild affected modules, print endpoint assumptions, and run a clean closure replay before reporting performance.
\item Prefer the narrow canonical-row adapter: define the relation through exact \file{tsite} equations, prove the finite checker produces \file{BranchGood} facts, and reuse existing \file{Bisim.halts_iff}. A separately proved primitive/basic-block CFG compiler is an alternative route. Retain the original certificate as an independent migration cross-check.
\item Keep certificate packing as a low-risk intermediate option, especially for other candidates whose graphs are not structurally identical. The optional decoded-equality audit may be used during migration without remaining in the production import closure.
\item Implement the generic invariant-restricted positive-stuttering theorem and locality checker, then instantiate CM215. Print assumptions and check the \emph{new exact endpoint}; do not attach old kernel receipts to changed tables.
\item Benchmark clean and incremental builds separately, recording compiler versions, cache state, peak memory, source bytes and proof-object size. Python operation counts are useful diagnostics, not kernel performance results.
\end{enumerate}
The included scripts and receipts report exactly what was executed. The Lean/Rocq drafts are marked uncompiled. There is no claimed new trusted axiom, proof-assistant endpoint or 214-state result.
