# Canonical well-formedness by a certified completion fold

Status: mathematical proof and owned finite prototype. The generic Lean fold,
its correctness proof, and the supplied small Lean interface draft have not
been compiled. No production files or earlier sealed evidence were changed.

## Exact proposition preserved

We target the existing `RMEquiv.WF p nn`, not a convenient weaker property.
Its conditions are:

1. `p.root < nn`.
2. At **every** node `n < nn`, both node children lie below `nn`; every break
   and continue leaf has positive level. No register-index bound is required.
3. There exists a natural height `H`, strictly decreasing across every node
   edge and positive at every node, with `H p.root ≤ nn + 1`.
4. There exist natural `B,C`, zero at the root, such that each node `(a,d)`
   satisfies `b(a) ≤ B(n)+1`, `b(d) ≤ B(n)`, `c(a) ≤ C(n)`, and
   `c(d) ≤ C(n)+1`.

Leaf values are exactly the definitions in `RMEquiv`: height zero for every
leaf; break demand one for `decnz`, `k` for `brk k`, zero otherwise; continue
demand `k` for `cont k`, zero otherwise. In particular, a decrement is not a
zero-demand operation. `brk 0` is rejected even though `RMDag.Run.brk0` has a
normal-exit constructor: the existing WF contract deliberately excludes it.

## Canonical recurrence and rank simplification

Once both children of node `n=(a,d)` are complete, define

    B(n) = max (b(a) - 1) b(d)
    C(n) = max c(a) (c(d) - 1)

where subtraction is natural truncated subtraction. These are the least
numbers satisfying that node's break and continue inequalities. The exact
asymmetry matters: CAR consumes one break level, CDR consumes one continue
level. CAR does not consume continue, and CDR does not consume break.

For comparison with the existing data, one can also compute

    Hcanonical(n) = 1 + max h(a) h(d).

But a WF proof does not need this maximum at all. Number completed nodes
`1,...,nn`, and take `H(n)` to be its completion number. A referenced child
must have completed earlier, so its number is strictly smaller; leaf height
is zero; every node number is positive. Every node completes at most once,
so `H(root) ≤ nn`, stronger than the required `≤ nn+1`.

The zero-based variant is the short interface drafted in
`RankScopeContract.uncompiled.lean`. It constructs the existing WF record
from completion-order and canonical-scope invariants, with one final scalar
root-rank bound. It is **not** a proof
of the evaluator and not a replacement proof of the K215 instance.

## Derived-order algorithm, with no supplied certificate

The owned prototype starts a depth-first worklist with every ID in
`range(nn)`. It maintains a three-state memo table: unseen, active, complete.
The numeric IDs are labels, not a topological ordering. Forward references
are allowed; no `child < parent` assumption is made.

- Visiting unseen `n` checks both edges for the exact legality conditions,
  marks `n` active, and schedules its children before its completion.
- Visiting an active node fails: this is a node-edge cycle, not an ordinary
  structured loop expressed by a continue leaf.
- Visiting a complete node reuses its summary. This is essential for shared
  open subtrees; do not expand the DAG into a tree.
- Completing `n` requires both node children already complete. It computes
  the two scope values above and assigns a fresh completion number.
- A success requires all `nn` nodes complete, a valid root, and zero root
  break/continue demand.

The strict all-node requirement is essential. The actual graph has 261
root-reachable nodes and 226 other bounded nodes. A self-cycle inserted at
unreachable node 1 leaves root behavior unchanged but falsifies the original
WF proposition. The prototype rejects this negative control.

There are `nn` initial visits, at most `2*nn` visits generated by node edges,
and exactly `nn` completion jobs on success. Thus the worklist uses at most
`4*nn` pop steps by this counting argument. This argument has not been
formalized. A total Lean evaluator can recurse on a supplied fuel and fail
closed if it expires. K215 used 1,859 of 1,948 steps. This bounds jobs, not
kernel wall time: map access, source-table reduction, arithmetic and term
representation have their own costs.

## Soundness proof to implement once

Maintain an invariant for each complete entry:

1. Its original ID is below `nn`, and its two original `p.nodes` edges are
   legal. Never validate a separate serialized graph without proving its
   equality to the actual `DagPerm.dagPerm` table.
2. Every node child is complete and has a smaller completion number.
3. Its `B,C` fields equal the recurrences using the final values of its
   children. Complete entries are never overwritten.
4. Completion numbers are positive and strictly advance. At acceptance,
   check the one scalar `H(root) ≤ nn+1`. One may later prove the stronger
   automatic bound by the number of distinct completed entries, but the
   first soundness theorem need not include that cardinality argument.

Leaf legality and exact recurrences establish the node case. Preservation
under new completions uses immutability of complete entries. The final
coverage check supplies these facts for every `n<nn`; extending the three
finite maps by arbitrary values outside the interval gives the total
functions required by `WF`. Root checks finish its record. The two max
inequalities and `x-1≤y → x≤y+1` discharge escape fields uniformly; there is
no need to generate/check four fresh scope inequalities at every node.

The first generic soundness statement should be, without a certificate
argument and for **arbitrary fuel**:

    wfBuildCheck p nn fuel = true → RMEquiv.WF p nn.

The concrete theorem still needs a kernel-checked evaluation of
`wfBuildCheck DagPerm.dagPerm 487 1948`. No Python result, generator assertion,
unchecked external execution, or newly postulated lemma can replace that.
Soundness does not need a proof that DFS accepts every acyclic graph, that
the active set exactly represents ancestors, or that `4*nn` always suffices.
Bad bounds, detected cycles, unfinished coverage, and fuel exhaustion all
fail closed. Complete-entry invariants suffice when acceptance occurs.

## Optional mathematical completeness argument

This is useful to characterize the intended checker but is **not required**
for the first certified K215 replacement. Do not make the generic Lean
proof unnecessarily depend on it.

If the original WF holds, its strict height witness precludes any directed
node cycle among the `nn` bounded nodes. Since legal edges stay in this
finite set, the derived traversal terminates and completes every node.
Induction in completion order proves canonical `B(n) ≤ Bgiven(n)` and
canonical `C(n) ≤ Cgiven(n)`: leaf demands agree; truncated subtraction and
max are monotone; the given four inequalities dominate the recurrence.
Consequently the canonical root values are zero. Completion rank supplies
the height bound independently of the supplied `H`.

Thus the derived-order checker is mathematically equivalent to the original
WF condition, not only sound for it, provided the traversal and legality
invariants above are proved. It does not accept semantically harmless but
syntactically ill-formed unreachable cycles or zero-level leaves.

The scope values are least solutions of this *syntactic WF system*, not
necessarily exact attainable runtime exits. For example, a halt in the CAR
can make the CDR unreachable at runtime, but WF still includes its demands.

## Supplied-order fallback is a different proposal

A simpler generic formalization can consume an untrusted 487-entry order
instead of deriving it. Each ID must be in range and fresh, every referenced
node already complete, and the completed set must cover every `n<nn`.
The same two scope recurrences and completion rank then establish WF.

That changes external witness data from 1,461 numbers to 487 IDs, not to
zero. Its bijection/coverage and child-before-parent checks are real new
obligations. Do not silently count this fallback as the certificate-free
derived-order version. Conversely, do not compute B/C in Python and merely
re-run the old eight inequality checks: that is the current design.

## Why current semantic contracts do not provide WF for free

`Dag222`, `Dag219`, `DagDom`, and `DagPerm` define numeric node tables and
overrides, not a proof-carrying builder. `make_dagperm.py` checks the intended
local patches and enumerates sites; it has no Lean construction theorem.
`generate_source215_lean.py:28-59` already computes these exact recurrences
in Python and emits the redundant tables for a later kernel check. The new
idea is to move this deterministic construction under one proved evaluator,
not to discover a different numerical invariant.

`L2RootPerm.root_step`, `root_some`, `root_none`, and `iter_iff` prove
structured execution for encoded enumerator states. They do not quantify
over every arbitrary register file and every unused node in the finite
table, nor do they imply acyclicity. Even universal root semantics would
not establish global WF, as the unreachable-node cycle demonstrates.

Patch inheritance is possible only with extra contracts: replacements must
have verified scope summaries no larger than the replaced subgraphs, rank
decrease across all new dependencies, and all preserved/new nodes must
remain covered. Matching only break/continue effects does not prevent a
cycle. Introducing this proof-carrying construction language across all
four generators is a larger refactor than the small generic evaluator.

## Secondary option: root support rather than all-node WF

There is a valid semantic simplification, but it is not deletion of existing
checks for free. Let `S : Nat → Prop` contain the root and be closed under
node children of nodes in S. Require legality, height decrease and scope
inequalities only for nodes in S; retain the root height fuel bound and
root scope zeros. Inspecting `RMEquiv` shows how to generalize:

- `fol_ok` should produce S-membership for node edges, plus leaf legality.
- `walk_path` uses S-membership instead of `n<nn` for height descent.
- `run_bound` propagates S-membership to child runs.
- `bwd` already obtains its node membership from the root path witness `F`;
  its height induction and `wf_run` need only the supported facts.

One must reprove a supported version of `halts_iff_iterHalts`, not merely
apply the existing theorem after skipping 226 nodes.

A lower-risk alternative preserves the existing RMEquiv theorem. Form `q`
with the same root and the same `p.nodes` on S, and `(halt,halt)` outside S.
Then prove two generic support lemmas:

    support_closed S p ∧ agree_on S p q ∧ S root →
      (Run p (.node root) R x R' ↔ Run q (.node root) R x R').

    support_closed S p ∧ agree_on S p q →
      ∀ fuel n P i, S n →
        walk (ofDag p nn) fuel n P i = walk (ofDag q nn) fuel n P i.

The second lemma proves equal `RegisterPath.walk` results, not literal
program equality. For equal roots in S, it then yields equal
`step`, `run`, `AtHalt`, and `Halts` for the shared root. The first is by
induction on a Run derivation, including the `cdrCont1` recursive run at the
same supported node; it lifts to `IterHalts`. Apply existing WF and the
existing halting equivalence to q, then transport both sides back to p.

The support set itself requires checked root membership and child closure.
The other 226 q nodes are trivially WF with H=1 and B=C=0. This removes their
nontrivial analysis but adds a support certificate/algorithm and semantic
transport. For only 487 nodes, it is secondary to the strict all-node fold.
