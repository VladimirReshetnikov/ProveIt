\section{Reuse local symbolic runs and finish with Home}
The new observation is stronger than merely grouping residual guards. Every selected local control run stops at exactly $(2,\mathrm{true},[],R')$: Home state 2, head on the left, and an \emph{empty explicit left fragment}. The preserved program-counter prefix can therefore be appended after the run. Home then scans that prefix using its existing theorem, beginning at zero. This avoids the boundary-crossing argument that the previous opaque-segment design required.

\subsection{The universal proof has a small explicit boundary}
For a symbolic frame $F$, define
\[
 A_F(q,o,l,r)=(q,o,l\mathbin{+\!+}F,r).
\]
The proposed algebraic lemma states that a successful existing \code{sstep} commutes with $A_F$, preserving its result and progress Boolean, provided the input is not head-on-left with an empty left list. This excluded case is essential: the unframed rule inserts a blank, whereas the framed configuration would read the appended data. Every other successful branch either preserves or moves only an explicit leading segment; the proposed proof splits the original cases and uses append associativity.

A fixed-length \code{runLocal} guards this one unsafe case before each existing step. Induction using the frame lemma and existing \code{sstep\_sound} then gives ordinary \code{Reach} between the framed configurations. The final existing Home theorem supplies \code{Reach1}, so local positive progress is unnecessary. This is a composition of existing semantics, not a new globally trusted executor.

For one candidate template, let $S$ be its nonempty literal input suffix, $E$ its literal output suffix, and $q$ its exact routed primitive state after the explicit native-to-formal label translation. Quantify over every finite prefix $P$ satisfying
\begin{verbatim}
KHome.scanBound 0 (P.reverse.map Seg.bit) = some k
\end{verbatim}
for some $k$, every natural $n$, and every valid register file including its nonempty spare tail. With $g=n+16$, the whole-configuration contract starts with state $q$, left list
$\operatorname{reverse}(P\mathbin{+\!+}\operatorname{init}(S))\mathbin{+\!+}[1]$,
and right list beginning with the final bit of $S$, then $0^g$, the register marker and the register file. It finishes at dispatcher state 84 with left marker $[1]$ and right list
\[
 P\mathbin{+\!+}E\mathbin{+\!+}0^{\,g+|S|-|E|}
 \mathbin{+\!+}[1]\mathbin{+\!+}\operatorname{sepsR}(vs).
\]
The far-left exterior remains blank. No theorem about an arbitrary nonblank exterior, only a local window, or merely equal register values is substituted for this exact tape contract.

At the empty-left endpoint, append $\operatorname{reverse}(P)$ and the existing guard one. Existing \code{scanBound\_sound}, the guard reset and \code{home\_word} suffice. In particular, $P$ need not end in one. Of the 1,422 admitted source occurrences, 721 have prefixes ending in zero. Normalize only the right endpoint with the existing normalizer: applying \code{normL} to an unframed left fragment could erase trailing zeros that become significant after appending the frame.

\section{Share named proofs through formula local capabilities}
Phase 14 already shares a substantial named-calculus interface. The additional proposal finishes sharing the remaining Leibniz induction and specialization argument without giving the restricted calculus unrestricted equality vacuity. It factors the exact resource each proof consumes, rather than adding a stronger global axiom schema.

Write $E_{xy}$ for the object-language equality formula and $T$ for the current theorem predicate. The common Leibniz induction takes the existing propositional and row interfaces, symmetry and transitivity, the original conditions that $x$ and $y$ are not bound in $f$, and only this formula-local capability:
\[
  \forall i,\quad \operatorname{Bound}(i,f)\ \Longrightarrow\
  T\bigl(E_{xy}\Rightarrow\forall i\,E_{xy}\bigr).
\]
Only the quantified case consumes that capability. In the unrestricted calculus, ordinary fresh equality vacuity supplies it. For a quantifier-free formula, there are no bound labels, so the premise is vacuous. The restricted public wrapper still requires both \code{QF} and \code{EqFree}; the proposal deliberately does not broaden its API merely because this particular induction could handle more formulas.

Reflexivity needs even less: one explicit diagonal witness
\[
  T\bigl(E_{xx}\Rightarrow\forall c\,E_{xx}\bigr).
\]
The unrestricted wrapper uses $c=x+1$ with its existing freshness proof. The restricted wrapper uses its existing encoded helper label and \code{helper x x}. No fresh-variable axiom or general equality-vacuity field is added to the restricted interface.

The specialization bridge accepts a forward rewriting proof
$T(E_{xy}\Rightarrow(f\Rightarrow g))$ and the exact elimination proof
$T((\exists x\,g)\Rightarrow g)$. It derives $T((\forall x\,f)\Rightarrow g)$ from the existing rows. Callers retain responsibility for freshness and fragment conditions; the restricted caller still needs equality-freeness to construct its elimination proof. Keeping this boundary prevents the shared induction from silently strengthening the calculus.

This is a maintainability refinement, not a large size win. Counting all new helpers and compatibility wrappers, the three-file proposal changes 780 lines to 775 and 33,252 bytes to 32,595: \textbf{five lines and 657 bytes saved}. The larger per-file reduction in \code{KThmK} must not be reported without the adapter growth elsewhere. The short symmetry and transitivity bodies remain local because sharing them would cost more wrapper code than it removes.

Compile the three candidate files and unchanged restricted/unrestricted clients before adoption. In particular, check exact public signatures, equality-free specialization, helper-only vacuity and all existing assumption reports. The proposed generic statement is not itself a new kernel-checked theorem. Rocq can use the same resource-oriented design when a real duplicate is identified, but this packet does not claim or include a matching new Rocq calculus deletion.

\subsection{Rocq proves each decoded step once}
The maintained Rocq soundness file separately analyzes the opcode in invariant preservation and in the halting case. The proposal proves the complete one-step outcome instead:
\begin{verbatim}
Lemma step_sound s : Inv s ->
  match enum_step s with
  | Some s' => Inv s'
  | None => thm222 1
  end.
\end{verbatim}
\end{samepage}
The existing \code{Inv\_step} and \code{halt\_step} statements become wrappers that rewrite the supplied step equation in this result. The existing \code{Inv\_run} and \code{enum\_sound} proofs stay byte-for-byte unchanged. This shares one concrete opcode analysis, not an abstract scheduler or a replacement completeness argument.

A separate five-line cleanup replaces the custom induction for \code{popn\_S} with \code{Nat.iter\_succ\_r}, leaving the definition of \code{popn} unchanged. The joint-step change saves four lines; together the file decreases from 98 to 89 lines and from 4,005 to 3,648 bytes. Thus the \textbf{nine-line, 357-byte saving} is exact for the uncompiled patch, not a new Rocq receipt. The exact lemma is documented in \href{https://rocq-prover.org/doc/V8.18.0/stdlib/Coq.Arith.PeanoNat.html#Nat.iter_succ_r}{Coq 8.18 PeanoNat}; compile the source and unchanged callers under the intended production toolchain before accepting it.

\section{Further research questions}
\begin{enumerate}
\item Can the frame lemma and fixed-run induction be compiled without changing any existing \code{sstep}, \code{Seg}, normalization or Home definition? This is the decisive first runtime gate, before generating all kernel certificates.
\item Does checking 35 local runs plus exact source instances reduce total kernel time and memory compared with the inherited 6,176 literal outcomes? Measure complete clean builds and object sizes, not just the number of templates. A smaller partition is not automatically faster.
\item Do the shared stack aliases preserve the definitional reductions used by unchanged lower-level clients? Keep the decoder and scheduler untouched until that narrow extraction passes.
\item Does formula-local equality capability sharing meaningfully reduce maintenance effort despite saving only five production lines? Compile the explicit audit clients, including the stronger auxiliary quantifier-free rewrite corollary, without weakening specialization's equality-free requirement.
\item Which already-proposed semantic coverage, direct-seed or quotient adapter is now cheapest to integrate into an unchanged endpoint? Those remain important integration priorities, but are not relabeled as new discoveries here.
\end{enumerate}
