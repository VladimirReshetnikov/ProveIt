\textbf{Result.} No justified machine with fewer than 194 working states
was obtained. The fallback is achieved by two completely specified new
194-state binary, one-tape, blank-start designs, \textbf{PA194OM} and
\textbf{PA194OMF}. They combine interacting reader changes and, in the
second case, a history selector and two guarded accelerations. They are
structurally distinct from all 550 prior 194-state graphs recognized in
the pinned corpus, even under enlarged graph symmetries.

\textbf{Mathematical claim.} The report proves positive, primitive
recursive halting-time transfers between each new table and the exact
revised PA194AX11H. Composing these transfers with that packet's retained
written arithmetic calibration gives
\[
 \iPRA\vdash\neg\Halt(M)\longleftrightarrow\Con(\PA),
 \qquad M\in\{\mathrm{PA194OM},\mathrm{PA194OMF}\}.
\]
The inherited calibration is made explicit and included in the archive.
This is an ordinary written proof with executable finite certificates;
no completed end-to-end Lean proof is asserted.

\textbf{Evidence.} Each new table has 388 transition rows and independently
checked literal contracts for all 4,778 source outcomes, arbitrary primary
register values, arbitrary affine header padding, and a nonempty finite
spare list. Complete blank initializations take 58,014 and 58,010 steps.
The comparison covers 106 prior deliveries and 104 distinct named designs.
A separate exact obstruction covers all 70,035,840 start/allocation choices
for one particular inherited 193-control runtime; its scope is explicitly
limited. A new arbitrary-consequent gate reduces the primitive source to
3,666 sites but its first physical realization still costs 198 states.

\section{Outcome, conventions, and proof status}

The primary optimization target remains open. The deliverable is a new
pair at the existing bound, together with a complete corpus comparison,
a uniform written correctness argument, and reproducible evidence from
the attempts to lower the bound. The component mechanisms have clear
precedents in the supplied packets. The new contribution is their
interaction in these exact complete tables, the fresh physical and source
binding checks, the concrete witness transports, and the additional
negative and semantic research.

All state counts exclude the distinguished halt control. The tape is
two-way infinite, initially entirely zero; the head starts at coordinate
zero. The dense tables have working states $0,\ldots,193$, initial state
0 and halt state 194. Every working state has one row for each scanned
symbol in $\{0,1\}$; each row writes a binary symbol, moves exactly one
cell left or right, and enters its target. The native tables instead use
initial label 74, source-boundary label 84 and terminal label 254.
Native label 194 is an ordinary working state. The supplied label arrays
conjugate the complete native and dense tables.

The exact consistency sentence is the current Foundation PA consistency
predicate fixed by the retained AX11H calibration. This report does not
replace it with consistency of iPRA, a finite fragment of PA, or an
unspecified numerical calculus. The detailed adapter and numerical-calculus
translations remain part of the inherited mathematical dependency.

\subsection{Three kinds of evidence}

\textbf{New relative proof.} Section~\ref{sec:relative-om} proves exact
source-step simulation, whole-tape frame closure, positive duration,
complete initialization, and constructive reflection of physical halting.
It gives polynomial witnesses for positive halting implications in iPRA.
These implications yield nonhalting equivalence by intuitionistic logic.
They do not presuppose the consistency of PA.

\textbf{Inherited absolute calibration.} The revised AX11H packet supplies
the written conversion between its exact machine and $\Con(\PA)$.
Its physical, source, command, proof-translation, Foundation-adapter and
weak-arithmetic transfer arguments were reviewed. No concrete gap was
found in the examined chain. That review does not independently rebuild
every inherited proof recipe or constitute kernel certification.
The ten calibration TeX files retained in the included reference ZIP are
byte-identical to the corresponding files at the pinned current commit;
the binding is recorded in \path{references/current_calibration_binding.json}.

\textbf{Executable finite certificates.} Python checkers bind tables,
source graphs, whole-tape startup, affine source contracts, local selector
invariants, and graph novelty to exact byte identities. Their successful
replays are stronger than finite samples of register values because the
symbolic contracts range over arbitrary natural registers and list tails.
The written induction argument explains how these finite identities yield
uniform iPRA statements. Neither a Python success receipt nor a long
nonhalting simulation is called a Lean proof.

The repository's root PA status and the revised packet must be read at
their respective levels: the machine-specific end-to-end Lean endpoint
remains unfinished, while the revised packet contains a separate written
arithmetic equivalence. The new results preserve that distinction.

\subsection{What determines the state budget}

The designs vary along several genuinely different axes. Changes in the
numerical calculus alter generated axiom heads, coding coefficients,
guards, and parameter interpretation. Command-protocol changes alter
visible versus cached results, stack effects, and the exact all-store
proof compiler. Register placement, reader-tree associations, and known-zero
returns alter how the same primitive process is addressed physically.
History-based sharing changes the transition graph by using bits already
written on the tape to recover a lost control distinction.

These improvements are not additive by default. A changed source tree can
move a relative break to another successor; a reader can have a secondary
entry outside its nominal prefix-code use; a fold that is valid on a
register frame can break the initialization that first constructs that
frame. A four-field AX command cannot be justified by a three-field
compiler, and a cache-only halt test requires a final word exposing the
contradiction in the cache. The present construction therefore compares
the entire resolved instruction graph, checks every full source outcome,
and independently reruns the blank bootstrap after the changes are combined.

The most useful comparison is consequently an interface comparison:
which exact command effect changes, which tape invariant pays for a shared
state, and which proof is required to carry the absolute calibration
through that change. Table~\ref{tab:families-note} summarizes the proof
obligation at each layer. The complete mechanism ledger follows, and the
detailed 104-design roster appears in Appendix~\ref{app:named}.

\section{Construction of the new pair}

PA194OM composes the operand reassociation from PA194ORH with the balanced-to-
right-associated MP reader from PA194AX11HMP. The secondary-entry repair
of the operand reader is retained. The two modifications overlap inside
the MP source, so combining the individual reports is not enough to prove
the combined machine. A fresh source resolution and literal replay establish
the compatibility.

The operand change alone moves 134 primitive addresses. The MP change
moves 87 relative to its unmodified context. Their overlap is 67 addresses,
so the combined change moves exactly
\[
                       134+87-67=154
\]
addresses from the AX11H parent, at zero-based sites 224--290 and
3572--3658. The underlying 3,671 instructions and every successor remain
identical. The maximum address length is 37; the initial site-25 address
is still \texttt{1000000} in a header of base width 48.

PA194OMF adds a history selector and two guarded three-step shortcuts
to this combined reader implementation. Exactly six native rows differ
between OM and OMF, and all six are exercised during OMF's actual blank
initialization. Its separate symbolic replay verifies that the original
entry conditions survive both reassociations. The factor-three direct
simulation proved below supplies an additional relative proof between
the pair, independent of their common logical source.

\subsection{Reconstruction and exact state accounting}

The constructor starts with hash-bound ORH raw rows and source grammar,
applies the MP reader change, optionally applies the six-row variant, and
then performs seven retained context folds. It checks each local fold,
re-resolves the entire source, and computes the complete blank startup.
For each member, the literal accounting is
\[
              135\ \text{fixed controls}
              +66\ \text{axiom-reader controls}
              -7\ \text{folds}=194.
\]
There are 201 distinct raw controls. In particular, the operand-reader
helper is already included in 135; it is not an uncounted extra state.
The terminal control is separate. No state is removed merely because it
was not visited in a bounded run.

The physical permutation of the nine logical registers is
\[
       (K,T,W,A,D,H,X,Y,L)\longmapsto(6,2,0,4,3,7,8,5,1).
\]
The logical seed is $(2,0,0,0,0,0,0,0,0)$ with 26 spare entries equal to 1.
Both new startups end at native state 84 and head coordinate $-2$ with
the exact encoded seed and all other cells zero. The four-step advantage
of OMF is a startup measurement, not a claim that every possible run is
pointwise faster.

The complete dense tables are printed in Appendix~\ref{app:tables} and
provided as plain five-column files. The native tables, raw tables, label
maps, source trees, addresses, instruction arrays and fold receipts are
also included. Thus the designs are concrete machines, not only proposed
edits to a source language.

The construction utilities and independent verifier use separate source
resolvers. The physical verifier starts from the literal transition rows,
derives four block-traversal lemmas, and composes unary-loop and finite-word

\section{Additional physical searches}

The other attempted reductions targeted the reader and emitter grammar.
Five nominated local source-tree rotations at or below the 194-state budget
preserved the resolved instruction graph but failed the complete symbolic
source-interface checks. They therefore supply no acceptable machine.
The candidates and observed failures are retained in the research records.
This is a finite screened neighborhood, not an enumeration of all possible
tree or source changes.

For the new combined OM implementation, a deterministic seeded grammar
search examined 5,000,000 proposals. Its best effective reader cost remained
59, so the total stayed at $135+59=194$; it found no cost-58 candidate.
The checked input seed already realizes that best cost. Grammar fitness is
only a nomination criterion: a promising score would still require literal
reconstruction, all-context validation and a successful blank startup.

An additional semantic change, developed next, required a fresh grammar
search. Its corrected search examined 2,000,000 proposals without improving
the effective cost of 64 for a 134-control fixed runtime, hence 198 total.
An earlier experimental fitness version wrongly assumed an extra reusable
reader label; it was corrected before any count was accepted. Rebuilding
the literal tables exposed that issue. The archive includes the corrected
search and does not present its earlier optimistic score as a result.

No finite search here proves that 194 is optimal. In particular, the
bounded one-row repair screen leaves its cutoff cases unresolved and says
nothing exhaustive about unrestricted changes to multiple rows or about
other encodings.

\section{Lessons from ZFC, DiophantineConsistency and ConciseIPRA}

The ZFC constructions make the distinction between an abstract source
program, its finite physical implementation and an internal arithmetic
theorem particularly useful. Their context-dependent sharing and finite
history mechanisms motivated attempts to compose reader and selector
changes here. The exact interaction matters: the same spare control or
history bit cannot pay independently for two incompatible optimizations.
The OM/OMF composition explicitly verifies that its shared contexts survive.

DiophantineConsistency contributes a suitable proof architecture:
primitive recursive witness maps and model-uniform weak-arithmetic
transfers, with the machine simulation handled separately. It does not
give a state saving merely by making an equation shorter. A blank binary
machine still has to enumerate assignments, evaluate arithmetic, represent
constants, and construct its initial data. Variables, polynomial degree,
arithmetic operations and Turing controls are different optimization
metrics.

ConciseIPRA suggests looking for smaller interderivable proof interfaces.
The arbitrary-consequent gate is an example of applying that idea: an
additional field replaces an existing logical operation, yet its physical
reader cost currently outweighs the five-site source saving. A compact
checker for iPRA cannot simply replace the PA refutation enumerator, because
the requested consistency target is PA. Any replacement must carry explicit
proof translations for that target and account for its literal runtime.

The most concrete remaining opportunities are therefore: a redesigned
bootstrap for a runtime saving that is already sound on initialized frames;
an emitter grammar that realizes the new gate within the bound; or a
different command interface with a smaller complete physical implementation.
They remain research directions, with no promised state reduction.

\section{Reproduction, provenance, and deliverable map}

From the extracted archive's top-level directory, with Python 3.10 or
newer and assertions enabled, run
\begin{verbatim}
python3 -B verify_release.py
\end{verbatim}
The default replay reconstructs both new tables in a temporary directory,
reruns both independent physical checks, verifies the relative-proof
bindings and graph novelty, and replays the exact allocation obstruction
and recorded repair counterchecks. It does not repeat billions of search
transitions and does not claim to check the full inherited arithmetic
calibration. A quick mode uses the retained physical contract files and
reports that it did not freshly regenerate them:
\begin{verbatim}
python3 -B verify_release.py --quick
\end{verbatim}
The separate research folders document how to repeat the longer searches.
They include their seeds, limits and recorded outcomes. The default check
needs no network connection, Git checkout or Lean installation. The optional
C++ grammar and repair searches require a C++17 compiler. The PDF can be
rebuilt with a standard LaTeX installation by running pdfLaTeX twice on
\path{report/report.tex} from its containing directory.
