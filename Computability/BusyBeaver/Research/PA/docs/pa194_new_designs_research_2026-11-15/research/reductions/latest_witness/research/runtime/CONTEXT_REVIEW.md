# Review of the finite-window context collector

Reviewed `research/runtime/collect_box_contexts.py` against the literal symbolic interpreter `research/grammar/verification/reference/symbolic_runtime.py`. The review is about the finite-window overapproximation used by the bounded local-fold search, not a proof of TM minimality.

No underapproximation was found in the reviewed construction:

1. `list_words` enumerates every complete list word shorter than the requested radius and every prefix of exactly that radius in the languages `(01+)^*`, `(101*)^*`, or their reversals. A block length greater than the radius cannot create a new shorter prefix beyond the already truncated long-block case. Reversal reverses each block; arbitrary block order in the closure supplies reversal of the whole finite list as well.
2. `lengths` enumerates all values of an affine nonnegative run length, capped at the requested bound. Each coefficient is added by an independent nonnegative multiplier. The later Cartesian products forget relationships between different runs, lists and tape halves, enlarging the represented window set.
3. For a scan with radius K, capping the scanned run at 2K+1 suffices. A position within K cells of the start keeps its exact consumed length; a position within K cells of the end keeps its exact remaining length; a position far from both ends is represented by the case with at least K written cells behind and K+1 unconsumed cells ahead. The entry state is already included, and the interpreter resumes at the scan's exit.
4. A list traversal is exposed as an arbitrary consumed prefix, one arbitrary current block, and an arbitrary unconsumed suffix. Empty prefixes and suffixes are included by the list language. The converted prefix's orientation is reversed for a right-moving traversal and forward for a left-moving traversal; the unconsumed suffix has the complementary orientation. The current block is followed through literal transitions and accelerated-run interiors until the checked one-block target closes.
5. The fresh current-block variable reuses affine slot 2. This would be unsafe if it merged arithmetically with an independent outside register length. In the reviewed one-block expansion, the explicit prefix/suffix list atoms separate the current block from the outside context, and the generic block proof closes before either outer list is consumed. Thus no such collision was found. If the expansion is later changed to consume an outer list or remove these separators, the variable-isolation argument must be revisited.
6. The original independent literal checker is rerun for every source outcome. The exact blank startup contributes all of its intermediate windows. The final startup state/head assertion is not itself a full tape-frame proof; that stronger binding is supplied by the separate machine verification and should remain a named dependency.

The intended use is the union of these arithmetic-box contexts with the complete non-box contexts, together with the exact startup contexts. The fixed BOX partition and the source-frame invariant are part of that scope. A rejected deletion in this overapproximation is only an obstruction for the explicitly searched finite-radius/fold family. It is not a proof that no different small Turing machine exists, and may include false-negative search outcomes caused by extra unreachable windows in the overapproximation.
