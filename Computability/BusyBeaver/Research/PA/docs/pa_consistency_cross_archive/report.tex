\begin{abstract}
The requested binary Turing machine with fewer than 196 working states
has not been constructed in this investigation. This report states that
limitation explicitly. It compares all 27 incoming archives at ProveIt
commit \file{906367250a7f96c923147b10df392294bced7be5}, including nested
historical inputs, and distinguishes 20 designated 196-state transition
graphs from rejected smaller experiments.

The positive result is a new composition of improvements from different
recent reports. The diagonal-vacuity axiom emitter and its separate-head
variant combine with the shorter cached-head Shift and MP routines.
Two complete 196-state tables have respectively 3,676 and 3,649 source
instructions; both reach the exact clean seed after 57,922 binary steps.
Combining each with the zero-jump optimization gives two further 196-state
tables. The archive contains complete transition tables, source grammars,
symbolic runtime checks, independent source and startup checks, a full
comparison inventory, and further bounded reduction experiments. These
are implementations and mathematical evidence at explicitly stated proof
boundaries, not a new end-to-end Lean verification of the internal
consistency biconditional. No negative search result here is a general
lower bound of 196.
\end{abstract}

\section{The requested result and the actual result}

The target is a concrete machine $K$ such that
\[
 \#\mathrm{WorkingStates}(K)\le195,
 \qquad
 \PA\vdash\bigl(\NH(K)\leftrightarrow\Con(\PA)\bigr).
\]
The machine convention is inherited from the supplied constructions:
one two-way infinite tape, alphabet $\{0,1\}$, all-zero initial tape,
and exactly one-cell left or right moves. A distinguished halting label
is excluded from the working-state count. No alphabet enlargement,
preloaded program tape, stationary move, or change in counting convention
is used to manufacture a reduction.

\textbf{The strict state-count target remains unmet.} The new constructions
in this packet all have 196 working states, except for a further
direct-negation composition with 197. The four 196-state tables are useful
intermediates because they combine previously separate logical and
command-level improvements and are accompanied by complete checks.
They must not be reported as 195-state successes.

The current comparison is pinned to the commit above. The imported
James Chang PA196 and PA209 snapshots are respectively
\file{407cdc356f6b586635e71ac92be394255f4bfea4} and
\file{69d98241a721ead20b4f0b17df9062950b40fbfe}.
The reports supplied inside incoming archives can cite earlier ProveIt
revisions; their exact bytes and ancestry are retained in the inventory.
Thus an older report's assertion about the number of incoming archives is
not silently treated as a statement about this newer snapshot.

\section{The new cross-archive constructions}
\subsection{Why these changes can be composed}

The newest diagonal emitters change the axiom command, retaining the
original 169-site exterior. Combined196 changes the exterior to 145
sites, retaining the original 3,643-site axiom body. These are separate
interfaces. The natural new experiment is to bind each revised axiom body
to the revised exterior and check every resulting control-flow edge,
rather than infer correctness by adding reported savings.

The two grafts use the exact checked diagonal and separate-head
grammars. Their AX bodies have 3,531 and 3,504 primitive sites. Thus
\[
 3,531+145=3,676,\qquad 3,504+145=3,649.
\]
Their physical allocation retains 134 fixed controls, adds 68 AX reader
controls, and performs six simultaneous compatible folds:
\[
                       134+68-6=196.
\]
The shorter expanded source does not remove a reader in this allocation.

In the original diagonal layout the AX prefix is the bit word
\file{10101001}. In the Combined exterior it becomes
\file{100101001}. Every AX leaf is transplanted by replacing the former
prefix by the latter. The remaining 145 leaves come exactly from
Combined196. The independent verifier reconstructs the ordinal graph by
prefix intervals, using neither the construction script nor its symbolic
executor. It checks every exterior instruction and every incoming and
outgoing AX edge under the ordinal shift.

The command return site 3776 in Combined196 becomes site 3664 in the
diagonal graft and site 3637 in the separate-head graft. This check matters:
a table can be total and have an apparently correct AX block yet return
to the wrong command dispatcher.

\subsection{The axiom changes}

The numeric constructors are based on
\[
 p(a,b)=\binom{a+b+1}{2}+b,
 \quad \I(A,B)=4p(A,B),\quad \M(a,b)=4p(a,b)+1,
\]
\[
 \U(a,B)=4p(B,a)+2,
 \qquad \E(a,b)=4p(a,b)+3.
\]
Code 0 denotes truth, code 1 denotes the false target, and
$\N(B)=\I(B,1)$. The quantifier's two pairing arguments are transposed.
Every variable index in the formula decoded from a positive code $B$ is
strictly less than $B$; code 0 has no free variable. Hence
\[
              \Gamma(B)=\I(B,\U(B,B))
\]
is a valid diagonal-vacuity instance: $B\to\forall x_B B$.

The diagonal construction replaces the equality-vacuity component of
the old guarded gate by $\Gamma(c)$. Writing $V$ for the unchanged
membership-vacuity clause and $Q$ for the unchanged quantified
separation clause, its top formula is
\[
              F_\Gamma(a,b,c)=\N\bigl(\I(\Gamma(c),\I(V,Q))\bigr).
\]
The old guard $c\ne a,b$ remains. The separate-head construction emits
$\Gamma(c)$ as an additional stack item and leaves
\[
                      G(a,b,c)=\N(\I(V,Q))
\]
as its guarded top. All six principal heads, the restricted propositional
head, and the generalization item retain their established roles.

These two axiom presentations were proposed in the supplied reports;
their logical simplification is not claimed as a discovery here.
The new result here is their composition with the newer exterior,
its exact physical realization, and its independent binding checks.
The prior diagonal derivation recovers the reverse membership rewrites,
neighborhood equality, and equality witness interfaces used by the PA
refutation compiler \cite{new196}. It explicitly retains membership
vacuity; discarding that clause as well would leave a circular proof.

The free-algebra emitter check compares complete constructor trees,
not a sample of small numeric inputs. The diagonal graft has 191 macro
items and nine pushed stack entries, including the saved top. The
separate-head graft has 190 macro items and ten pushed entries. Its
new head is an implication and therefore is not the literal false code 1.

\subsection{The shorter command exterior}

The Combined exterior changes two commands. Shift clears the old top
$T$, copies the cached head $H$ into $T$, and tests the old value of $H$
against 1. MP's successful branch stores its consequent in $H$, with
$T=D=0$, and does not push an unnecessary zero. Its failed branch retains
the appropriate offset in $D$ and has $T=H=0$.

These changes require a corresponding proof-command compiler; they are
not simple equality of the old and new commands on every store. The
supplied Combined report gives the arithmetic loop invariants and a
compiler adapted to these effects \cite{combined}. Our new source
binding preserves those entire exterior fragments.

For example, the Shift pre-guard transformation
$(T,H,X)=(t,h,0)\mapsto(h,h,0)$ takes $2t+7h+3$ source instructions:
the clearing loop costs $2t+1$, the copying loop costs $4h+1$, and
the restoration loop costs $3h+1$. The successful MP transfer
$(D,H)=(y,0)\mapsto(0,y)$ costs $3y+1$ before its return jump.
Induction on $t,h,y$ establishes these formulas for arbitrary naturals.
They are not estimates based on bounded execution.

The nine-entry and ten-entry stack conventions must be distinguished
when composing the command compiler. The extra diagonal head shifts
the selectors for the old heads by one. The packet's independent review
includes explicit algebra for the two stack lengths. It does not assume
that an old nine-entry selector works unchanged for ten entries.

\section{The zero-jump composition}

The newest zero-jump report replaces the forward jump at source site 26
by a decrement of register 6, which is zero at that site on the reachable
source run \cite{zerojump}. In native table labels its physical change is
\[
       (27,1)\mapsto(0,L,40)
       \quad\hbox{replaced by}\quad
       (27,1)\mapsto(1,R,21).
\]
It does not delete a state. Applied to each new graft, it again has no
state-count saving, but it changes the available local routing and so is
a useful additional search seed.

\begin{lemma}[Zero-decrement replacement]
Suppose an inductive source invariant says register $r$ is zero whenever
control is at site $i$. Replacing an unconditional jump at $i$ by a
decrement of $r$ with the same zero successor preserves the complete
source execution from an invariant-satisfying seed, provided all other
instructions are unchanged.
\end{lemma}
\begin{proof}
At $i$, decrement takes its zero branch and changes no register.
Consequently the old and new next configurations coincide. At other
sites the instruction is identical. Induction on the source-step count
gives equality of the executions and therefore equality of halting.
\end{proof}

The invariant used here tracks a nine-bit positivity mask $m$: bit $r$
is set precisely when register $r$ is positive. Increment sets its bit;
a zero decrement follows the zero branch without change; a positive
decrement follows the positive branch with either a positive or zero
remainder. This nondeterministic remainder is an overapproximation of
all natural values, not an assumption that a positive register equals 1.

The exact clean seed is source site 25 with mask 1, corresponding to
register vector $(2,0,0,0,0,0,0,0,0)$. The two new finite closures contain
265,964 and 263,244 site-mask pairs. Each contains the seed, is closed
under every abstract successor, and has only masks with bit 6 clear at
site 26. Concrete source induction therefore proves the required zero
condition. Because both complete graphs are checked, this argument does
not assume that an invariant computed before the AX change remains valid
afterward.

The changed decrement introduces a further abstract positive branch into
the source specification, explaining the one-case increase in each
uniform physical runtime check. That branch is checked physically too;
the source invariant excludes it only in the equivalence with the
original jump program.

\section{What the checks establish}

\subsection{Literal startup and complete tape equality}

The startup checks execute the literal binary table from its designated
state on a blank tape. At the accepted boundary the head is at position
$-2$, the native control is the source root 84, and the physical register
list is
\[
       [0,0,0,0,0,0,2,0,0]\mathbin{+\!+}[1]^{26}.
\]
The check includes the origin marker, complete source path, padding, file
boundary, every unary register block, and all nonzero tape cells. A
matching prefix or matching logical registers alone would not suffice.
The affine gap starts at 48 and can grow in the runtime representation.

The reported startup durations are exact finite facts about these tables.
They do not prove nonhalting by themselves. Their role is to connect the
blank initial configuration to the hypothesis of the uniform source
simulation.

\subsection{Uniform primitive contracts}

The symbolic executor represents the whole register file and an affine
unbounded gap. Every source instruction is checked; every decrement is
checked in both branches. Unary register operations are summarized only
at the unchanged engine interfaces from the upstream runtime.
The fixed engine rows are retained, so those inherited lemmas still apply.
Symbolic execution verifies the exact successor frame, including the file
effect, rather than merely whether it returns to a plausible control.

The counts 4,784 and 4,749 are source-outcome cases, not a collection of
bounded natural-number test inputs. Conversely, their symbolic step
counts are not literal binary running times. The independent review
binds these source cases to the actual grammar and its resolved control
graph, while a separate check binds dense labels to the native table.

These executable checks are mathematical evidence using an inherited
runtime interface. They are not advertised as a new Lean kernel build.
A hostile mutation test, a long blank prefix, or an implementation's own
assertions alone would be a weaker form of evidence.

\subsection{From positive instruction blocks to halting equivalence}

\begin{lemma}[Positive-block transfer]\label{lem:block}
Suppose a deterministic source machine and a deterministic binary machine
have related initial configurations after a finite startup. Suppose every
nonhalting source step from a related frame has a finite binary simulation
of positive length, with no intermediate halt, ending at the next related
frame. Suppose source halt corresponds to binary halt. Then the two
executions halt together.
\end{lemma}
\begin{proof}
A finite source halt transfers by concatenating its finite simulation
blocks. Conversely, if the binary machine halts after $n$ transitions
following startup, a nonhalting source prefix of $n+1$ steps would transfer
to a nonhalting binary prefix of at least $n+1$ transitions. Determinism
contradicts the alleged earlier halt. Thus a source halt must occur.
\end{proof}

For the internal-PA version, the configuration relations, finite traces,
and block constructors must be arithmetized, and their correctness and
positive lengths must be proved in PA. The argument then uses finite
arithmetic induction; it does not require a truth predicate for arbitrary
formulas. This is the useful distinction between a transferable
mathematical proof and a completed exported formal theorem.

\section{The consistency calibration and its limits}

There are three different questions: whether the table is a correct
implementation of the displayed source, whether source halting is
equivalent to a refutation in the selected numeric calculus, and whether
that refutation condition is PA-provably equivalent to a refutation of
ordinary PA. State counting answers none of the latter two questions.

The inspected imported Lean development exports
\[
             \PA\vdash\NH(M_{196})\to\Con(\PA),
\]
and an external Lean-metatheoretic nonhalting theorem \cite{inventory}.
Its theorem inventory does not export the reverse internal implication.
That observation does not prove the converse false. Several incoming
reports provide ordinary mathematical arguments for it, and the Combined
report supplies especially explicit command and positive-block arguments.
The current packet preserves that distinction.

The new grafts reuse two written calibration components: the diagonal
calculus's refutation translations, and the Combined exterior's command
compiler. The diagonal variant keeps nine stack entries; the separate
variant uses the adjusted ten-entry selectors. The independent binding
proof checks that these are the fragments actually executed. Subject to
those inherited uniform arithmetic proof translations, Lemma~\ref{lem:block}
and the exact startup give the same PA consistency calibration for the
new tables. This packet adds no new closed Lean theorem asserting that
entire biconditional.

The reverse arithmetic direction must be syntactic. Interpreting
membership by a binary-bit relation and saying that every derivable
formula is true in the standard model is not, by itself, an internal PA
proof of $\Halt\to\neg\Con(\PA)$. A sufficient internal construction is:
extract a coded numeric-calculus refutation from a halted finite trace;
translate each axiom and rule by uniformly generated finite PA proofs;
and concatenate them into a PA refutation. Quantifier recoding, freshness,
the code-0 alias, and the zero-alias stack convention $p(0,0)=0$ must all
be handled by that same code-level argument.

The forward refutation-to-halting direction likewise needs an executable
proof-command compiler and exhaustive enumeration. Changing the number
or order of pushed heads affects that compiler even when each emitted
formula is logically harmless. These are the reasons the artifact keeps
source binding, emitter semantics, runtime contracts, and calibration
evidence as separately identified components.

\section{New reduction searches}
\subsection{Joint allocation across recent reports}

The new composition screen reconstructs the two primary grammars and

\subsection{Direct negation with the diagonal calculus}

The new direct-negation composition replaces eight occurrences of the
push-top, increment, cons sequence by an existing arithmetic negation
routine, under its scratch-zero contract. The retained best diagonal
layout has 3,468 source sites and 197 working states; all 4,503 physical
instruction cases pass. Grafting that AX onto the Combined exterior
reduces the source to 3,444 sites with 4,472 passing cases and exact
57,922-step startup, but it still uses 197 states.

Concretely, with $S=R=0$ and $T=t$, increment $R$ twice and execute
the old \file{node64}. Its triangular accumulation followed by fourfold
transfer leaves
\[
 T=4\bigl(2+\operatorname{tri}(t)+t\bigr)
   =4\bigl(\operatorname{tri}(t+1)+1\bigr)=\I(t,1),
 \qquad \operatorname{tri}(t)=t(t+1)/2.
\]
It restores $S=R=0$ and preserves the other registers. Each replacement
saves 29 primitive sites, giving 232 in total. Clean scratch is the
inherited macro interface transported through this composition argument;
the free-constructor check does not track these scratch registers, and
no new formally checked AX plan is asserted. The separate theory packet
in \file{research/theory_study/} records this distinction and the complete
197-state reproduction.

The retained allocation has 68 AX reader nodes and five compatible
folds, yielding $134+68-5=197$. This is a concrete illustration of the
tradeoff: a substantial source reduction loses a sharing opportunity.
The bounded search evaluates 100 initial composed grammars and 38,400
seeded mutation slots. Its negative outcome is restricted to that
experiment. The scratch-zero arithmetic obligation is preserved as an
explicit hypothesis; a uniform physical instruction check does not itself
prove that higher-level macro precondition.

\section{What transfers from ZFC and iPRA}

The useful transferable objects are compiler and proof techniques:
entry-history information stored on tape, shared readers, source
reassociation with explicit jump scopes, symbolic register contracts,
and replacing a primitive schema by a derivable smaller interface.
Those techniques can change the implementation while preserving the
selected searched calculus. Their applicability has to be checked at
the concrete PA source and table \cite{zfc}.

In particular, the ZFC K215 construction combines a command-local field
reader, command ordering, and a partial selector while retaining earlier
marker folds. Those are opportunities to reconsider a runtime interface,
not numerical state savings transferable independently of that interface.
Its compiled external Lean/Rocq endpoint and the separate internal-PA
endpoint for the 240-state table have different scopes; the ZFC directory
explicitly distinguishes them \cite{zfc}.

The final U208 history fold cannot simply be renamed into PA196.
Its parent has a mixed-direction same-target predecessor motif which
the PA196 table does not contain. That is a finite obstruction to that
particular transplant, not an impossibility result for every history
fold. The ZFC construction's theory or a smaller iPRA checker is also not
a substitute for the PA refutation search: consistency of those theories
is a different calibration problem. A replacement needs explicit
PA-provable transformations of refutations in both directions.

The concise-iPRA work is relevant to choosing simple proof formats and
keeping a checker small. Checker source length, source instruction count,
and binary TM state count are three different objectives. None provides
a monotonic bound on either of the others under the present compiler.
Its one-sided transport and merged introduction rules illustrate a useful
method: first prove that a syntactic restriction preserves derivability,
then remove the corresponding checker distinction \cite{ipra}.
For the PA gate restriction below, freshness is proved but the analogous
derivability translation is still missing.
Likewise, merely switching to full intuitionistic arithmetic requires
a negative-translation/refutation argument and a new machine
implementation; it does not yield a state count for free.

\section{Further research questions}

\begin{enumerate}
\item Can whole-instruction equivalence, rather than equivalence of
individual binary steps, expose an engine reduction? A successful
candidate must then be checked over arbitrary register values and a
complete tape relation. The macro searches in this packet explore only
specified finite templates.
\item Can the new 3,649-site source be allocated by a compiler that
jointly chooses the exterior, AX tree, helper controls, and scanner
representation? The current $134+n-f$ accounting fixes a substantial
part of the layout in advance.
\item Can a different representation of the source path distinguish
the origin marker with fewer controls without making instruction
dispatch or blank startup larger? A shortened detector must be correct
on intermediate, partially rewritten paths as well as clean addresses.
\item Can a restricted family of automatically fresh gate instances
replace the present two inequality guards while retaining an explicit
PA refutation compiler? The outstanding logical interface is as
important as the emitter's source cost.
\item Can the entire PA calibration be exported as a uniform coded
refutation translation, with an arbitrary-internal-time tape/source
reflection theorem? This would make future local reductions easier to
certify and would settle the proof-status distinction visible in the
current theorem inventory.
\end{enumerate}

These questions describe the remaining work; they are not claimed
solutions. No lower bound rules out a 195-state machine. The work here
shows exactly which combinations and finite search templates were tried,
and supplies better-bound intermediate implementations for a subsequent
attempt.

\section{Reproduction and artifact guide}

Run \file{python3 verify.py} from the extracted packet root, with assertions
enabled. It checks file integrity, the twenty-table comparison, the four
new tables, their source/runtime/startup contracts, the zero-jump
invariants, and the independent graft review. The optional longer search
commands and their limits are described in the corresponding research
directories. A successful default run does not mean the strict target
was achieved: the machine-readable status explicitly records that it
was not.

The optional command \file{python3 research/verify_direct_negation_combined.py}
replays the 3,444-site, 197-state composition. From
\file{research/theory_study/}, \file{python3 -B verify.py} replays the
3,468-site composition, and \file{python3 -B replay_padded_failure.py}
reproduces the explicitly rejected padding allocation. Recomputing the
entire original archive inventory additionally requires the original
pinned incoming ZIPs; their digests and retrieval locations are supplied.
Exact copies of the 127 prior 196-state tables are included, so the
default positive replay also checks the complete graph novelty comparison
without those original ZIPs.

The packet contains the complete report source and PDF; full literal
machine tables and source grammars; the 27-archive comparison and recursive
inventory; independent binding and graph checks; bounded-search sources,
inputs, and receipts; exact source pins; and retained upstream licenses.
The original repository and its imported publication trees were not
modified.

The executable checkers use Python 3 and its standard library. Repeating
the C++ search screens additionally requires a C++ compiler. Compiling
this report uses an ordinary LaTeX installation with the packages named
in its preamble. No Lean or Rocq build is claimed by this packet.
