RELATED REPOSITORY METHODS
All claims below refer to commit 1c9524d8bf2e0a27b9a16ff622359927f536e663.
These are source inspections, not fresh rebuilds of the optional projects.

1. ZFC machines
Source:
https://github.com/VladimirReshetnikov/ProveIt/blob/1c9524d8bf2e0a27b9a16ff622359927f536e663/Computability/BusyBeaver/Research/ZFC/README.md

The useful transferable techniques are coordinated optimization of source
layout, command ordering, register allocation, and history-sensitive state
folding. K215 combines a command-local field reader/command ordering with a
partial selector. Earlier variants omit a redundant successful-MP zero push;
restrict a dominated propositional interface while preserving theorems;
co-translate formula codes and numeric labels in codec changes; and perform
closed source rotations that expose predecessor-bit folds. These are all
relevant to PA source/decoder optimization, and several already occur in
PA194 families. They are not new discoveries of this report.

The ZFC README distinguishes the exact K215 external Lean/Rocq equivalence
from the internal arithmetic theorem: its internal PA endpoint remains
open there, while an exact 240-state machine has an internal IΣ2/PA result.
Thus transferring an engine optimization does not transfer a stronger
logical calibration. The README also explicitly warns that savings using
the same source roles do not automatically stack and that a promising
runtime core can fail the actual blank startup.

2. DiophantineConsistency
Source:
https://github.com/VladimirReshetnikov/ProveIt/blob/1c9524d8bf2e0a27b9a16ff622359927f536e663/Computability/DiophantineConsistency/README.md
Useful sections: Approach and comparison; Executable construction and
further reductions; current native iPRA proof status.

A reusable methodological point is to retain supplied, data-valued
arithmetic syntax and representation constructors with separate correctness
proofs. A theorem that existentially asserts a program or polynomial does
not by itself provide executable data; unjustified elimination from Prop
to Type is specifically rejected. The finite signed coefficient recipe,
all-model witness transformations, and precise native consistency sentence
must remain bound to the final artifact.

Its direct sealed-ZFC proof checker has explicit primitive-recursive
programs, raw input rejection, backward premise references and numeric
renaming/schema checks. The reported complete literal program has 83,281
nodes, or 76,313 after certified optimization. This is a program-tree size,
not a binary TM state count. Its small Diophantine formulas optimize
variables, degree, arithmetic operations and coefficient size separately.
Searching for their zeros would still require a concrete arithmetic
machine, tuple enumerator and initialization of fixed coefficients. No
sub-194 binary-TM estimate follows from a small polynomial front.

The all-model syntax and proof-code interfaces of this project are already
used by the PA tree's IΣ1-to-iPRA transfer. This is the most direct reuse
for the present proof obligation. The ZFC equations themselves search a
different consistency statement and cannot simply replace a PA enumerator.

3. ConciseIPRA
Source:
https://github.com/VladimirReshetnikov/ProveIt/blob/1c9524d8bf2e0a27b9a16ff622359927f536e663/Logic/PrimitiveRecursiveArithmetic/ConciseIPRA/README.md

Its native scalar core uses variables, zero, successor and an iterator for
terms, with equations and the Q,D closure constructors for formulas.
Logical connectives, ordinary quantifiers and equality laws are derived
from a small core of computation, transport and closure rules. The metric
is the size of a standalone Python proof checker, and the required
mathematical relation is bi-interpretability with iPRA.

Useful ideas are reducing the primitive proof interface, deriving a richer
logic from fixed templates, and restricting a checker to the image of an
explicit translation whose soundness/completeness and round trips are
proved. The project carefully distinguishes equivalence on translated
public sequents from derivability on arbitrary raw syntax. For example its
PGPrf public calculus is complete on the guarded translated image but
strictly weaker on arbitrary sequents; it does not derive raw variable
transitivity in the cited restricted form.

This last distinction is directly relevant to the guard-padding
obstruction proved here: failure to derive the old raw gate rules out one
relative-calculus proof, but does not rule out a wholly different
PA-to-public-image translation. Such a translation would need to be
constructed and checked. The small iPRA checker itself cannot replace the
PA-refutation search: bi-interpretability with iPRA supplies no identification
of Con(iPRA) with Con(PA), and Python checker size supplies no binary-TM
state bound.
