TERMINAL-GRAMMAR SEARCH: UNVERIFIED SOURCE VARIANTS

This directory records an unsuccessful search toward a smaller compiler
allocation. It contains no accepted machine and no semantic preservation theorem
for the source substitutions explored here.

Inputs
------
templates.txt contains 134 fixed native machine controls, followed by six
frozen binary source-tree templates. Each control row specifies the two
transitions using write/direction/target triples; direction is encoded as
zero for left and one for right. After the control rows comes the template
count, then each template's ID, node count, root index, and node records.
A node record with op=0 names a physical macro leaf; op=1 is a binary pair
of earlier tree nodes. The input is read directly by search.cpp.

The six seeds were generated by replacing the AX11 terminal store-push fragment
with a fragment copying one of the D, H or A registers, using two tree
associations. No mapping of seed IDs to those choices is asserted here.
These are experimental source changes: their semantic adequacy was not proved.
leaf_attrs.txt supplies structural attributes for the physical macro leaves.

Search and recorded result
--------------------------
The active mutation replaces binary-tree associations. Parameter renaming is
disabled by the literal if(false) branches in search.cpp. The score is the
number of reader nodes after the local compatible-fold calculation, plus
penalties for structural/scanner constraints. There are 134 fixed controls.
The nomination condition is effective reader count at most 59 and zero penalty;
that would only nominate an allocation of at most 193 states for subsequent
semantic, physical, startup and logical verification.

The 600-second run used random seed 202611142001. It recorded 11,424,577
iterations, 584,235 accepted moves, zero qualifying nominations, and best
penalized score 60. These are iteration counts, not numbers of distinct
grammars or verified machines. At zero penalty, 134+60=194.

run.log is the full progress receipt. run.csv contains the header only,
consistent with zero hits. run.seed0.grammar.json is one terminally retained
grammar sample; it is not a certified machine. The other 29 retained samples
are omitted to avoid multiplying similar speculative outputs.

Reproduction
------------
From this directory, with GNU C++17 available:

  mkdir -p replay
  g++ -O3 -std=c++17 search.cpp -o replay/search
  ./replay/search templates.txt leaf_attrs.txt replay/run 600 202611142001

The program writes output files under the chosen prefix. It uses elapsed time
to stop, so hardware and system load change the exact final iteration count.
The seed and frozen input make the search choices reproducible up to that
machine-dependent cutoff. No Python package is required for this optional run.

Interpretation
--------------
The grammar score is an optimistic compiler-search diagnostic. The search does
not establish that the altered terminal protocol generates exactly the needed
calculus, that every local fold composes with every source operation, or that a
blank startup reaches the required encoded frame. No lower bound on Turing
machines, proof searchers, or other grammars follows from the unsuccessful run.
