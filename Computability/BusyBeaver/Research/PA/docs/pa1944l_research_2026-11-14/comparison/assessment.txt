RESULT AND THE USER'S STRONGER REQUIREMENT

The current repository does not establish the premise that its 194-state
machines already have both consistency directions proved in iPRA. The current
PA/README.md explicitly identifies both machine-specific directions for the
primary PA194, original PA195 and PA196 as open. The recent incoming releases
claim ordinary written PA calibrations and explicitly disclaim a completed
machine-specific iPRA equivalence. This assessment does not conclude that the
claimed equivalence is false or unprovable in iPRA; it identifies what the
supplied evidence actually establishes. A new table that inherits a PA proof
must not silently be promoted to an iPRA result.

There are 72 delivery records: 61 filed research packets and 11 current incoming
ZIPs. The 62 top-level README files for the 61 filed packets are byte-identical
to the readmes recorded by the preceding 66-delivery audit. Their SHA-256 values
were independently rechecked at the current snapshot. Every current incoming
archive was read at least at its main result/construction/proof-status level;
the physical-search failures relevant to the 193-state objects were examined.
The ledger attributes the older mathematical and executable claims; it does
not assert that all historical consistency proofs were independently reproved.

WHAT THE TABLE CENSUS DOES AND DOES NOT MEAN

The fresh scanner reads exact Git blobs at the pinned commit, then recursively
examines distinct ZIP payloads. It recognizes complete numeric five-column
binary L/R transition tables, and explicit JSON encodings including table
text, row arrays, dense action arrays, row objects, numeric-state dictionaries
and transition-key dictionaries. It never executes arbitrary generators or
infers a machine table from prose, TeX or unconstrained program syntax. All
registered deliveries, including those with source-only ideas, remain in the
packet ledger. Table recognition is not a proof of consistency equivalence.

Identity has several levels: raw bytes, a labeled transition function, the
rooted reachable action graph, and a complete action graph with its start
forgotten. The census stores the start convention separately. A dense table
numbered 0 through n-1 does not by itself prove that its declared start is 0;
several historical renumbered native tables require external start metadata.
Tables without a spanning root are kept separately by bytes, because the
largest reachable component cannot identify disconnected remainder states.

The fresh complete scan recognizes 3,444 table occurrences and 780 byte
presentations (including normalized extracted JSON forms). It finds 642
spanning action-graph classes, of which 638 have exactly one terminal label,
and ten nonspanning byte forms. All 535 retained official catalogue classes
and their recorded reachability counts are reproduced. No .tm file fails
parsing and no JSON payload fails decoding. The scan inspects 15,257 relevant
file/member payloads and 25 distinct ZIP payloads. Among spanning physical
tables there are 53 classes at 193 states, 82 at 194, 27 at 195, 105 at 196,
and 142 at 208; small fixtures and other sizes are listed in census/summary.json.

The named 194-state frontier consists of 82 complete graph classes: 40
reported principal constructions, seven supplementary constructions, five
source-validated research rotations, 25 other research auxiliaries, and five
explicitly rejected designs. These are evidence categories, not 82 consistency
theorems and not 82 freshly kernel-checked results. The graph census concerns
all sizes; the 194-class status ledger is an intentionally narrower view.

The official historical catalogue records 7,130 original table occurrences
in 61 delivered packets and 535 classes. Most duplicate files were removed
from the filed tree. Its count is therefore not the number of .tm files now
present. The fresh scan additionally sees table encodings embedded in JSON,
current incoming compositions, search candidates and nested archives.

THE PRINCIPAL DESIGN AXES

1. Logical emitter. The primary 194 construction uses a separate diagonal
   head with a ten-entry AX interface. D variants replace Gamma(A) by Gamma(D).
   Q variants exchange the two curried premises of a universal-distribution
   formula. Radix variants change the multiplier in formula constructors
   from four to five or six. These affect the numerical proof calculus or
   emitted formulas and require explicit proof translations.

2. Command protocol. C sends a successful modus-ponens result to the cache
   and uses cached-only Shift. N omits the dummy-zero stack push and leaves
   the result visible in the top/offset, retaining the original sum guard.
   H combines N's visible no-push result with cached-only Shift. S reverses
   the arguments of the destructive comparison so that a restoration loop
   can be removed. The all-store compiler matters because the scheduler
   carries its store between trials. A deletion that works only from a clean
   store is insufficient. The incoming AX11 changes the AX interface itself:
   all generated heads are stacked, the command falls through to the MP
   operand reader, and an additional operand is genuinely consumed.

3. Source decoder. Primary PA194 uses 134 fixed controls plus 67 readers
   minus seven simultaneous folds. The alternate original layout uses 68
   readers and eight folds. Reassociation can preserve the entire resolved
   source instruction graph while changing the binary addresses, readers,
   fold opportunities, blank startup and literal transition graph. M4R and
   many source rotations are earlier examples. Such a result is a new
   physical decoder layout, not a new proof-search architecture.

4. Known-zero returns and register placement. J/F/A/X/ZR/HAZ and related
   constructions replace a jump by a decrement of a register whose value
   is proved zero at that program point; some combine physical A/D register
   placement. The invariant is essential. Source correctness alone does
   not establish the complete blank-tape initialization. The corpus has
   explicit counterexamples to that shortcut.

The families are largely compositions along these axes. No-push MP, cached
Shift, premise exchange, coefficients five/six and known-zero returns are
already prior ideas. A new composition should identify exactly which recurring
semantics or physical decoder geometry changes, instead of claiming invention
of all its ingredients.

WHY THE 193-STATE FILES ARE NOT ESTABLISHED SOLUTIONS

An older coefficient-three construction implements an inconsistent numerical
calculus. The documented collision between equality and implication codes
allows a derivation of the contradiction code from the unchanged heads/rules.
Its smaller physical table therefore does not validate the intended Con(PA)
calibration. A later report expands the obstruction to every nonnegative
constant equality offset for that specified coefficient-three head/rule
family. This is not an obstruction to every possible coefficient-three
encoding and not a universal lower bound on state count.

The runtime193 marker quotient is a different object. It identifies native
301 with 88 and changes the rows 88/0 and 51/0. The source contracts may pass
on clean frames, but the unchanged blank start enters an outward ray. Current
incoming packets contain many concrete transplants and repairs, so the old
phrase 'two recognized 193-state objects' is no longer a current count.

In particular, the QN6 packet retains 49 exact transplants into earlier
194-state tables. Its physical-search README records all 193 possible starts
for each, giving 9,457 simulations: 100 halts, 9,357 certified outward rays,
zero accepted frames, and zero bounded unresolved runs. It explicitly calls
all these tables research inputs or rejected experiments. The direct quotient
of QN6 has a 92-step ray certificate; the ZFC-style relay trial has a 116-step
ray certificate and also fails nine conditional source contracts. Other pair
repair searches contain bounded runs, which must not be called proofs of
permanent failure.

For an individual blank-start machine with a certified outward ray, its
nonhalting has a short elementary proof. If PA is consistent, such a machine
cannot have a PA-provable equivalence with Con(PA), since that would give PA
a proof of its own consistency. This observation is about those particular
certified-ray starts, not all 193-state machines or all possible repairs.

The current 193-state frontier has 53 classes: 49 runtime-quotient transplants,
one rejected coefficient-three calculus, one direct QN6 quotient, one relay
trial, and one AX11 quotient. These categories are resolved by all source
locators, so repeated copies are counted once.

The complete current graph counts and all recognized 193-state source locators
are provided in the census and frontier193 files. Every such object retains
its rejected, experimental or runtime-only status; none is promoted solely
because its table has 193 rows of state pairs.

IPRA EVIDENCE BOUNDARY

The existing development has substantial pieces: ordinary finite-run parent
quotients, standard source-to-machine simulation, literal arithmetic clocks,
modeled scheduler reasoning, proof-calculus soundness and some model-uniform
arithmetic components. The current README reports an iPRA implication from
Con(PA) to nonhalting of an encoded modeled scheduler. The missing physical
controller connection prevents substituting the literal 194-state table in
that theorem. The reverse direction additionally needs a model-uniform
translation of arbitrary PA refutations into the numerical calculus and its
physical scheduling implementation.

A conditional theorem of the form 'if this table is calibrated, then iPRA
proves the equivalence' does not discharge the calibration hypothesis. The
isigma1-machine endpoint currently exhibits no calibrated concrete table.
Likewise, an external Lean theorem about all standard finite runs does not,
by itself, exhibit an iPRA derivation of the arithmetized equivalence. A
complete ordinary mathematical proof of formalizability could suffice for
the user's request without a new proof-assistant build, but that proof must
actually be supplied; absence of a Lean build is not the sole objection.

The complete current-tree novelty scan examined 15,257 file/archive-member
payloads and 25 distinct ZIP payloads. Among them it recognized 1,051
194-state table occurrences and 145 normalized labeled tables. None matches
PA1944L under arbitrary state renaming, arbitrary root choice, global tape
reflection, global symbol interchange, or ignored final write/move effects.
The rejection filter is invariant under all those transformations, and any
potential match is checked by an explicit bijection of all controls and both
literal transition rows. The result is an exact structural comparison,
not a probabilistic statement based only on hash collisions.

The decoder change preserves the entire 3,673-instruction primary source,
according to the construction agent's separate binding certificate. Thus
this is a new physical decoder implementation. The novelty result does not
prove the consistency calibration, an iPRA endpoint, material algorithmic
novelty, or global priority outside the recognized pinned corpus.
