5. Proof ledger and endpoints

The user asks for PA-provable equivalence. This must be separated from the repository's stronger unfinished iPRA internalization goal. The current PA README explicitly says neither machine-specific direction is yet established inside iPRA for PA194/original PA195/PA196. The imported PA196 formal result gives PA⊢nonhalt→Con(PA), plus standard-model nonhalting in Lean's metatheory. That implication alone does not give the PA biconditional.

The PA194 research packets supply an ordinary mathematical proof of the full PA biconditional. Its logical dependency is coherent in the portions audited here and in the newer independent ordinary-proof audit. It uses primitive-recursive translations of finite refutations, not an internal PA soundness assumption. The source calculus encodes implication,membership,quantification and equality by four tagged Cantor constructors; code0 is truth and code1 is self-membership contradiction. Diagonal freshness replaces equality vacuity, and explicit reverse-congruence/neighborhood derivations restore the interfaces needed by the PA-refutation compiler. Finite binary comprehension for each arithmetic formula supplies the reverse proof translation through a uniform induction-proof template. This is syntactic proof construction, not a uniform arithmetic truth predicate.

The proof-store invariant must annotate both visible fields and every canonical live stack entry. It handles I(0,0)=0 and p(0,0)=0 explicitly. The scheduler carries its store between command words, so completeness needs a halting word valid from every incoming store. Changed head counts, shifted success results, no-push rules, or new Shift tests require adjusted selectors and command compilers. A local source mutation cannot merely inherit these unchanged by name.

For literal refinement, arbitrary-value symbolic contracts require sound symbolic rules, justified unary-loop/list induction, exact full-tape endpoints, positive durations, complete source-graph binding and an exact blank seed. Positive durations allow a PA proof to build source boundary traces longer than any alleged halting time; deterministic transition uniqueness excludes an intermediate halt. Simultaneous contextual folds require all incoming-history conditions and local cases in the final jointly folded machine, not isolated pairwise plausibility.

The newest standard Lean calculus/clock composition proves exact clocks reach1 iff the displayed separate-diagonal numerical calculus has a finite derivation of1. Its README explicitly does not calibrate that calculus to PA, translate PA refutations, or internalize in PRA/iPRA. It retains a pinned Python grammar-translation boundary and was checked using temporary component overlays; a single combined fresh build of the final composition is not supplied. This is substantial formal progress, but does not convert all ordinary packet arguments into an end-to-end kernel theorem.

6. Lessons for the present construction

The state objective is literal binary blank-start controls including initialization, excluding only halt. A source reduction, a runtime-only reduction, a changed numeral encoding or an exact comparison of finite traces cannot silently substitute for that objective. A new194 fallback should change recurring execution or logical interface and admit a new relative preservation theorem; graph novelty alone is weaker. PA194QHS, if selected, occupies a previously absent combination: Q premise exchange+visible-result no-push+symmetrically implemented CACHE guard. PriorQNS uses the SUM guard, while priorQH uses an asymmetric cache guard. Its independent graph fingerprint is absent from all current194 classes; the new contribution must be described as the verified composition, with all component mechanisms credited.

The ZFC work contributes contextual folding, exact initialization, full-store compiler interfaces and positive physical simulations; its stronger calibration cannot simply be reused as Con(PA). ConciseIPRA contributes methods of minimizing proof interfaces and constructing explicit translations, but replacing a PA refutation search with an iPRA checker would change the consistency target. The current bit-comprehension calibration uses full induction for arbitrary arithmetic formulas.
