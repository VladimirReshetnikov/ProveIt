\section{Ideas from ZFC and ConciseIPRA}
\label{sec:related}

\subsection{A protected unsafe tail can replace a completely clean seed}

The ZFC zero-spare alternative changes one write bit and the initial
control of a 215-state parent, appending $B(0)=01$ instead of $B(1)=011$.
It remains a 215-state machine. Its blank run reaches two truth heads
above an unsafe tail; a quantitative debt-two argument proves that the
exact scheduler never exposes that tail. The related zero-spare-transfer
construction has a different seed, eight safe heads and scheduler debt
three. The transferable idea is to prove that a finite protective prefix
suffices, rather than requiring the whole decoded stack to be clean
\cite{z-zero,z-transfer}.

This must be proved for the actual command order. It does not permit an
unsafe formula to be treated as a theorem. The PA append-zero transplant
already rejected in the DHS supplement supplies an obstruction to that
particular direct transfer; this work did not redesign the spare
allocator. Physical spare blocks and logical stack heads are different
resources, so their counts are not interchangeable.

\subsection{A source simplification needs a repaired proof compiler}

The ZFC zero-spare-transfer report already removes the successful-MP
zero push and repairs the major-first proof compiler by reserving a zero
explicitly. Its stack argument uses total Cantor projections and handles
$p(0,0)=0$ without an injective list-length assumption. PA194N and related
branches already incorporate this idea. It is inherited here, not a new
discovery; the ZFC companion language is itself priced at 216 states
despite the shorter source interface \cite{z-transfer}.

The new experiment in this report instead moves the terminal test into
successful MP. The useful invariant is that no stored formula has code
one before halting. The new command compiler and physical implementation
are developed below, with their measured costs. They do not meet the
requested state bound.

\subsection{Exact quotients and contextual simulation have different scopes}

The ZFC exact-quotient criterion preserves write bit, direction and mapped
successor for both read symbols. Its \texttt{NoQuotient254} certificate
proves that such a quotient of one particular 254-state table is injective.
It explicitly leaves open tape-dependent folds, variable-length simulation
and different source programs. Thus it is a useful narrow rejection
criterion, not a lower bound for a consistency problem \cite{z-quotient}.

Our searches use contextual representations, including head displacement
and a changed neighboring bit, rather than transferring that exact-quotient
conclusion. The ZFC two-natural-number tape representation also supplies
a precise arithmetic language for runs, including the final write, move
and tape exterior. It improves proof infrastructure without automatically
removing a physical control \cite{z-arithmetic}.

\subsection{Smaller syntax and alternative pairing need complete costing}

ConciseIPRA's scalar core uses one numerical sort, iterator terms and
unary formula constructors $Q,D$. Its sorted arity codec reuses a raw-tree
grammar for terms and formulas: arity identifies constructors and depth
parity identifies sorts. These devices can merge independent dispatch
and substitution cases. Its article also proves the total pairing
\[
                \operatorname{cp}(a,b)=2^a(2b+1)-1
\]
and total inverse projections. This gives a candidate replacement for
Cantor sequence coding, still with $\operatorname{cp}(0,0)=0$
\cite{concise,c-base,c-codec}.

Any PA-machine transfer must price parity, halving, projection, source
sharing and initialization together. This work did not implement a
complete arity-coded or alternative-pairing PA verifier. The one-subformula
syntax relates binder depth to binder occurrences, but does not bound
iterator-term size, certificate size or the number of decoder subtrees.
Checker-token counts, AST-node counts and bytes are different cost
measures from binary-machine controls \cite{c-depth,c-codec}.

\subsection{Preserve the target theory and proof base}

The ConciseIPRA presentations are calibrated to iPRA. That fact alone
does not calibrate a refutation search to PA. Replacing the PA validator
by a concise iPRA checker would require the missing PA-refutation
translations, including the needed induction, as well as a complete
physical compilation. No such substitution is asserted here \cite{concise}.

The ZFC index separately reports external Lean/Rocq correctness for the
exact K215 table and an open internal PA endpoint for that table; its
240-state internal PA theorem concerns another literal table. A proof
base or machine-specific endpoint cannot be transferred merely because
two machines pursue the same informal goal \cite{z-root}. The present
work keeps the inherited ordinary PA calibration and the new executable
machine evidence explicit.
