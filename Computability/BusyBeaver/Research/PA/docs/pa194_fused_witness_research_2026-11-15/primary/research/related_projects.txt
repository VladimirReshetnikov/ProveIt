ZFC partial-provider/history-marker reductions
---------------------------------------------
Computability/BusyBeaver/Research/ZFC/candidate-k216/proof.md
Git blob: a91d488450c7ef976bff1b8f297dce51adb14f55

Its reparse preserves the same 4,751 ordered primitive operations and 6,175
guarded source edges. Its partial-provider identification (183 -> 164)
uses the predecessor marker and a local one/three-step whole-tape
simulation. The validity domain is entry through the recognized marker
context, not an arbitrary unrecognized configuration inside the pair.
The paper rechecks all 6,176 runtime contracts and the startup boundary.
This is a useful model for proving local state sharing under a precise
invariant. PA194FW uses this general class of history-marker sharing, but
its inherited PA compiler already exploits it; it cannot count the same
optimization twice as a new reduction.

Computability/BusyBeaver/Research/ZFC/candidate-k215/proof.md
Git blob: 5b62cecff23a798a4b34255d1f843e72ad11b623

The command-local field reader, parameter permutation and origin-marker
identifications illustrate a further possibility: a small repair to an
existing arithmetic control state can release one otherwise unreachable
branch for parser work. Its proof of the state-81 repair frees state92's
read-one branch while preserving the used zero branches. That suggests
systematic invariant-aware branch sharing, which was investigated
separately for the PA runtime; it does not itself provide a smaller PA
table. Its source/interface and context proofs are tied to the ZFC source.
The target consistency theory cannot be changed from ZFC to PA merely
by importing the machine's count or an implementation trick.

DiophantineConsistency
---------------------
Computability/DiophantineConsistency/README.md
Git blob: 62b1ce4f0828926ce87cbe48265f87310e09280e

The useful methodological contribution is to fix the exact syntactic
refutation predicate and witness domain, construct explicit witness
maps, and keep the mapped refutation-negation endpoints distinct from
an unsupported positive existential reflection principle. This informed
the PA194FW calibration discussion. A polynomial's degree, variable
count or arithmetic-operation count is not a binary one-tape TM state
count. An actual arithmetic enumerator, representation and clock proof
would be needed before a Diophantine encoding could compete with 194.
No such smaller compiled table was obtained here.

ConciseIPRA
-----------
Logic/PrimitiveRecursiveArithmetic/ConciseIPRA/README.md
Git blob: 8f810145b9ac8502748080a4ec4f15f2ad4c99bb

The project reduces an interface by derived one-context transport,
direct closure and evaluation/discharge fusion, while proving that the
full former interface is still recoverable. This supports the structural
strategy used in PA194FW: combine two exported axiom heads, then provide
uniform constructors in both directions. It is an analogy of proof
engineering, not a numerical cost transfer. Checker token/byte counts
do not measure TM states, and enumerating iPRA proofs instead of PA
proofs would change the consistency predicate sought by the user.
