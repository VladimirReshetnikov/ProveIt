\begin{abstract}
This investigation does not obtain a verified machine with fewer than 194
working states. It constructs two structurally distinct 194-state binary,
blank-start machines, PA194AX11QH4L and PA194AX11QH4R. They implement exactly
the 3,671-instruction source program of the pinned PA194AX11QH parent, but
reassociate all 61 four-increment decoder blocks. Each uses one extra reader
and one extra contextual fold, so its allocation is $135+67-8=194$.
All 4,778 source outcomes pass an independent universal literal-tape audit;
the complete blank startup takes 58,088 transitions for each machine.

The strongest relative conclusion includes explicit halting-time bounds.
Writing $M$ for the parent and $N_L,N_R$ for the new machines, a halting trace
of $M$ of length at most $t$ gives a trace of either new machine of length
at most $2t$. A trace of $N_L$ gives a parent trace no longer than itself;
a trace of $N_R$ gives a parent trace of length at most $2t$. These are ordinary
computer-assisted mathematical results supported by finite certificates
and quantifier-free induction, not newly compiled Lean endpoints.

There is a separate unresolved premise. The current PA project explicitly
states that the absolute machine-specific equivalence with $\Con(\pa)$ in
$\ipra$ is not established. This report does not assume that an older PA
calibration is already an iPRA calibration. Its relative theorems transfer
an eventual calibration; they do not supply it. The archive also contains
a pinned comparison of 95 stored 194-state graph classes, unsuccessful
sub-194 searches with exact scopes, and a finite proof certificate for a
further logically equivalent gate presentation.
\end{abstract}

\section{Outcome, target, and proof status}
\label{sec:status}

The requested primary target is a blank-start machine with fewer than 194
working controls whose nonhalting is provably equivalent to $\Con(\pa)$ in
$\ipra$. The fallback is a materially different 194-state design with that
property. The state reduction was not achieved. The delivered fallback
constructions have a proved relative physical preservation argument; the
absolute consistency calibration remains a separate obligation.

The entire comparison is pinned to repository commit
\begin{center}\small\ttfamily\snapshot\end{center}
of \texttt{VladimirReshetnikov/ProveIt}. The snapshot is essential because
new reports and formalization changes are arriving rapidly. No repository
files were changed, and no commit or pull request was published.

The PA root README states that neither machine-specific direction of the
requested iPRA equivalence has yet been established for the primary PA194,
original PA195, or PA196 candidates~\cite{pa-status}. It distinguishes
standard finite-run results, modeled schedulers, conditional arithmetic
endpoints, and the missing uniform machine/refutation reductions. This
is more than a missing final Lean file. Conversely, lack of a Lean file
alone would not invalidate a complete ordinary mathematical iPRA proof.
The point is to state exactly which argument is supplied.

Start conventions require particular care. The official catalogue omits

not a guess from the numeric labels. Both new tables explicitly start in
state zero and halt at label 194.

\subsection{Why the stored 193-state tables do not meet the target}

The official catalogue contains 53 193-state research classes. Their
existence is not evidence of 53 consistency machines. The coefficient-three
shortcut has a concrete alias: with the supplied pairing and unchanged
tags, $E(1,0)=6=I(0,1)$. The unchanged-head calculus then derives
contradiction. This rejects that particular encoding, not every conceivable
three-residue calculus.

Runtime193 exhibits a different failure. It can pass prepared-frame source
contracts while its inherited blank initialization runs into an outward
ray. The current incoming report supplies nine exact trace types covering
all $9!$ permutations of genuine register-selector targets for one fixed
Runtime193 core; each reaches the certified ray within 93 steps. The core,
permitted edits and initial control are fixed in that statement. It is not
a lower bound on arbitrary Turing machines~\cite{latest-packet}.

The comparison therefore keeps three obligations separate: implementing
the desired source, producing a valid source frame from the blank tape,
and calibrating the source calculus to PA refutation over the claimed base
arithmetic. Success at one level does not remove the other levels.

\section{Materiality and exact novelty}
\label{sec:novelty}

The constructions combine a decoder association with AX11QH that was not a
literal machine in the pinned corpus. Reassociation and predecessor-bit
folding are inherited methods; this report does not claim to have invented
them. Its new artifacts are the two exact compositions and their verified
properties.

In the left variant, 183 of 3,671 source addresses change; in the right
variant, 244 change. Both have 122 addresses lengthened and 61 shortened,
and maximum address length 36. The resolved source graph remains identical.
The added helper participates in 183 distinct universally checked instruction
outcomes for each variant. Thus the change has a recurring decoder role;
it is not established merely by changing an unused transition. This does
not assert that every such site is visited in the actual blank run.

The novelty checker compares complete canonical tuples, not hashes alone.
It tries all roots that reach the entire working graph, arbitrary state
renaming, global left/right reflection, global exchange of read/write bits,
and erasure of the final halt-edge write/move decoration. Bit exchange is
used only as a structural comparison: it does not preserve the all-zero
blank convention. Neither candidate matches any of the 95 historical
classes, and they do not match each other. The disconnected historical
control cannot be isomorphic to either connected candidate.

\section{Attempts to obtain fewer than 194 states}
\label{sec:search}

The search was aimed at a real state reduction, not only at manufacturing
same-size variants. The retained negative results have finite, explicit
scopes and do not prove optimality.

\paragraph{Compatible grammar rotations.}
Three searches on the new decoder kernels made 2,136,175 proposed mutations
and accepted 94,689. Two runs used shared-subtree rotations, on AX11QH4L and
AX11H4L; the third added variable-role permutations of the six ordinary
heads. The best effective count was 59 readers after compatible folds;
with 135 fixed controls this is 194. There were no projected sub-194 hits.
The fixed templates, seeds, C++ sources and logs are included in
\file{construction/research/}.

\paragraph{Local physical state elimination.}
The independent search considered all 18,528 unordered pairs of noninitial
working controls in each 194-state input. A proposed row may write either
bit, move either direction and enter any surviving control. One search
used all immediate incoming-history contexts and windows of five cells,
with up to 19 literal transitions. A stronger version computed an inductive
abstract reachable-window invariant of seven cells and allowed up to 31
new transitions. The accepted invariant is a conservative overapproximation
of complete tapes, not a bounded sample of the blank run.

A further version allowed a new local segment to match any of the first
nine old transitions, rather than just the first old transition, subject
to the same whole-window equality and no exterior reads. The algorithm is
restricted when it returns to the merged control on the opposite bit,
because the two rows are synthesized independently. This restriction must
be stated: the search does not exhaust all two-row programs.

The tested inputs include both new variants, PA194B, B composed with the
primary 4L, and B composed with each new AX11QH variant. No accepted deletion
was found. The logs count roughly fourteen million proposed first-row
actions per run; they do not mean that all pairs of row actions were tested.
Every complete log and the exact code are retained in
\file{research/local/}.

\paragraph{Shared-grammar mixed-integer optimization.}
A separate model represents the 190-token primary emitter by definitions
of repeated substrings, with the existing two- and four-increment macros
available at zero extra reader cost. Each selected rule is a path through
its substring; its cost is the number of right-hand-side chunks minus one.
The model has 5,708 binary variables and 5,565 constraints. At the
180-second limit HiGHS found a feasible cost-67 grammar, with reported
solver dual bound 61 and an unresolved gap. The bound is a solver result
for this particular model, not a machine lower-bound theorem.

Reassociating that grammar in 15,482 sampled binarizations produced a best
projected physical count of 198. This illustrates a concrete tradeoff:
compression of the unfurled decoder and compatibility of history folds
are different objectives. A grammar with few nodes can expose fewer folds
than a slightly larger grammar. The model, solution and sampling log are
in \file{research/grammar/}; reproduction of the optimization additionally
needs SciPy/HiGHS. The delivered machine verifiers use only Python's
standard library.

\paragraph{Logical source changes.}
An independent source investigation considered exchanges inside the
pointed-separation gate. The already explored inner-matrix exchange reached
best projected count 197 in the recorded run. A further outer exchange,
explained next, reached 200 in its recorded family. These are projected
search results, not newly certified blank-start machines. A stronger
freshness guard $c>a+b$ was considered but not promoted to a theorem or a
state-count improvement: both a complete proof translation and a native
implementation benefit would be needed.

\section{A further gate presentation with an explicit proof certificate}
\label{sec:gate}

The source-level mathematical supplement is useful even though it did not
produce a small enough machine. In the existing pointed-separation gate,
write
\[
 Q=U(c,S\to(P\to 1)),\qquad
 G=(V\to Q)\to 1.
\]
Here $1$ is the numerical contradiction code, $U$ is the quantifier
constructor, and $V,S,P$ are exactly the existing gate subformulas.
Replace only the order of the two curried premises in the body of $Q$:
\[
 Q'=U(c,P\to(S\to 1)),\qquad G'=(V\to Q')\to 1.
\]
The numerical guard and the command-stack interface are unchanged.

The elementary exchange principle is
\[
 (A\to(B\to C))\to(B\to(A\to C)).
\]
Use it in both directions, generalize at $c$, and use the retained
universal-distribution head to obtain $Q\to Q'$ and $Q'\to Q$.
Implication composition then gives $V\to Q$ iff $V\to Q'$, and
contravariance of the final implication to $1$ gives $G\to G'$ and
$G'\to G$. This is a uniform finite proof-template argument; it does not
assume arbitrary substitution into a freshness-restricted axiom.

The supplied checker specializes and rechecks the dominated propositional
basis, including its numerical side conditions. The recorded certificate
has 123 outer proof rows and 144 terms, supported by a rechecked 55,585-row
derivation of the required propositional lemmas. Its exact theorem,
provenance, computation and limitations are retained under
\file{research/logical/}. It is a syntactic calculus-level certificate,
not a new Lean build and not an absolute consistency calibration.

The inner $S$-exchange idea was found in prior exploratory inputs during
novelty review and is explicitly attributed as prior work. The outer
$Q$-exchange is distinguished from the shipped Q-family, which exchanges
premises in the sixth ordinary universal-distribution head. No claim is
made that this finite corpus check proves worldwide novelty of a basic
logical equivalence.

\section{What transfers from the related research trees}

The ZFC line provides a valuable architectural lesson: source reductions,
partial selectors, command order, and tape-history folds must be priced in
the complete compiled machine, including initialization. Its documentation
also records folds that cannot simply be added because they occupy the same
source roles~\cite{zfc}. That lesson informs the simultaneous quotient
checks and the B-composition searches here. A smaller ZFC theory machine
cannot simply be relabeled as a PA-consistency machine.

The DiophantineConsistency project gives a useful proof-engineering
comparison: it distinguishes external finite checks of a literal artifact
from native iPRA proof-existence endpoints and their all-model provider
obligations~\cite{dio}. A short equation or circuit does not, by itself,
translate into a small binary blank-start Turing machine. Its proof-boundary
discipline is directly relevant to the present trace certificates.

ConciseIPRA studies complete proof checkers and bi-interpretations for
presentations of iPRA, including a small scalar core and explicit
computation/equality rules~\cite{concise}. It suggests economical ways to
present the elementary induction arguments in the relative simulation.
Bi-interpretability with iPRA does not identify the PA refutation predicate
with that presentation's own refutation predicate, so replacing the target
proof system requires a separate calibration. Python checker size and
literal binary-state count are also different optimization criteria.

\section{Further research questions}
\label{sec:further}

\begin{enumerate}
\item \textbf{Joint local synthesis.} Can the B selector and triple-increment
helper share a state? The seven-cell search excludes opposite-bit recursive
entries. Joint synthesis of both rows should be checked against a complete
finite-context invariant.
\item \textbf{Grammar and folds together.} Can one optimization model price
shared subtrees, incoming histories, and simultaneous fold-provider
dependencies? Minimizing grammar size alone gave poor physical results.
\item \textbf{Gate and operand conventions.} Can the certified outer gate
exchange be paired with a cheaper operand convention while preserving the
actual fourth AX11 operand and the complete command-store invariant?
\item \textbf{A reusable Lean certificate checker.} The delivered literal
tables, 32 fold cases, four list lemmas, affine durations and nonhalting-prefix
invariants are concrete inputs. The relative factor-two theorem needs no new
PA axiom compiler.
\item \textbf{Explicit absolute witness translations.} Complete both the
physical-halting-to-PA-refutation and PA-refutation-to-enumerated-source-proof
reductions, stating the base theory and covering nonstandard codes and every
induction-schema instance.
\item \textbf{Startup and the register engine together.} The Runtime193
obstruction fixes the core and selector rewrite family. A different initializer
or seed invariant remains possible, but must work from the literal blank tape.
\end{enumerate}

\section{Archive contents and reproduction}

The archive is self-contained for reconstruction and the retained universal
checks. It includes both dense and native transition tables, exact parent
inputs, source graphs and paths, label maps, fold data, universal certificates,
comparison representatives, scoped search code, mathematical source and this
compiled PDF. The inherited license and attribution files are preserved.

From the archive directory, the main commands are:
\begin{lstlisting}[basicstyle=\small\ttfamily,breaklines=true]
python3 verify.py --quick
python3 verify.py
pdflatex -interaction=nonstopmode -halt-on-error report.tex
pdflatex -interaction=nonstopmode -halt-on-error report.tex
\end{lstlisting}
The quick command verifies the retained identities, reconstruction and
clock certificates without rerunning the independent universal tape suite.
The full command reruns the new-machine suite and structural novelty checks;
these may take several minutes. Assertions must remain enabled. The proof
status does not change merely because a Python command exits successfully:
the ordinary induction argument and the stated absolute-calibration gap
remain part of the result.
