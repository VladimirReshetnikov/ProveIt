======================================================================

Scope and method
----------------
The current repository has 26 ZIPs directly in docs/incoming. PA/docs files
36 historical packets, preserving delivered file bytes except documented
omissions: copies already in upstream snapshots, byte-identical sibling
archives, and ignored log/manifest files. Twenty-one of the old archives
remain in incoming; five newly added packets give 41 distinct principal
research packets overall. The archive_ledger.csv/json files cover all 41.
Counting current incoming only would omit fifteen older packets now filed
under PA/docs. Counting every filed copy as a new design would overcount.

census.py recursively opens each distinct archive payload once, records all
references to it, and scans direct PA .tm/.txt files and six ZIPs. The numeric
recognizer requires complete five-column binary deterministic transition
rows, two rows per working control, L/R directions, and exactly one undefined
halt control. It excludes arbitrary code/JSON-only machine encodings and
nonhalting synthetic controls with no halt label. Thus its census is scoped,
not a recognizer for every machine described by arbitrary programs. Human
comparison supplements this recognizer using each packet's report/README.

  24458 members of distinct archive payloads
  4417 complete-table occurrences
  620 byte-distinct tables

The graph signature is the lexicographically minimum deterministic BFS
serialization over all controls that reach the full working graph. It keeps
read bits, written bits, directions and the unique halt fixed. It forgets
the selected initial control; different signatures therefore establish a
stronger distinction than inequality of start-rooted graphs. Conversely,
class membership alone does not identify the intended blank start. Every
family actually under consideration uses dense start 0 or native start 74.
Graph signatures say nothing about PA calibration or minimality.

Formalization and logical proof boundary
---------------------------------------
The current PA/README.md explicitly says neither machine-specific
direction of iPRA⊢Con(PA)↔¬Halt(PA194) has been established. The analogous
195/196 endpoints also retain their reductions as hypotheses. This is
not evidence against ordinary mathematical PA proofs in the manuscripts;
it means the words "Lean-checked" or "proved in iPRA" require care.

pa194-dense establishes the 201-parent/194-dense equivalence for all
standard finite executions over complete tapes. The zipper bridges bind
those standard executions to the arithmetic machine representation.
pa194-coverage supplies a conditional source-to-physical coverage theorem
and per-site checking infrastructure; its README calls the full run
in progress. These are not internal PA/PRA/iPRA endpoint proofs.

The imported PA196 contains an internal PA implication from literal
nonhalting to consistency. That does not supply its converse. The later
manuscripts explicitly supply ordinary syntactic calibration arguments:
PA refutation→calculus refutation→command sequence→source halt, and the
reverse by proof annotations and PA-verifiable arithmetic translation of
finite binary-set comprehension. The soundness argument must use proof
transformations, not a uniform truth predicate or PA reflection. It must
handle truth code I(0,0)=0, Cantor-stack pair(0,0)=0, coincident binders and
Gamma freshness. The supplied detailed calibration discusses these points.

For a new source-preserving decoder or register-allocation reduction,
an ordinary mathematical theorem can legitimately cite that inherited
calibration and prove a PA-formalizable finite-trace equivalence. Executable
universal contracts support the new finite machine facts. A report should
state that dependency clearly and should not claim it produced a fresh
end-to-end Lean/Rocq endpoint. Conversely, repeating the repository's
conditional iPRA assembly without establishing its hypotheses does not
by itself solve the requested PA-equivalence construction.

No census count or unsuccessful restricted search establishes a lower
bound of 194. Sub-194 remains a construction problem; the best effective
AX-reader target under the old fixed 134 controls is 59.
