RECOGNITION AND IDENTITY CONVENTIONS

The census recognizes complete numeric five-column tables in .tm, .txt, .tsv
and .csv, traversing nested ZIPs. Comments beginning with # are ignored; rows
must be state/read/write/L-or-R/target, with symbols 0 and 1, unique rows,
and both read cases present for every working state. Eligible action graphs
have exactly one target label without rows and a root reaching every working
state. The halt state is not counted. The data retain starts declared in
comments, or infer start 0 for a dense 0..n-1 table. Rootless diagnostics remain
listed but are not silently treated as complete consistency machines.

Arbitrary source-code generators, JSON-only encodings, and unmaterialized
parameter families are outside the literal-table count. Their named research
contributions remain covered by the packet README ledger. No table census
can establish a global lower bound or semantic inequivalence of two machines.
The comparison is structural novelty within this pinned, explicit corpus.

A rooted deterministic binary graph is put in canonical form by breadth-first
discovery of controls, reading 0 before 1, recording the complete write/move/
target triples. Canonical tuple equality is equivalent to rooted action-graph
isomorphism. Taking the minimum complete tuple over all spanning roots removes
the designated-root choice. Candidate comparison also considers global
left/right reflection and bit exchange (both read and written bits). Equality
is decided with complete tuples, not hashes; digests merely label results.
All exact full canonical tuples are retained in class_canonical.json.

MAIN DESIGN COMPARISON

* Unary-power-cover/U208: a different logical architecture from the numerical
  PA196 line. The repeated principal U208 submissions implement the same
  contextual 172/211 fold; their putative savings cannot be added. Two primary
  graph classes recur, with further auxiliary and helper variants. Later
  attempts below 208 explicitly report failure or rejected 207 candidates.

* PA196 and logical-source variants: source reassociation, diagonal/vacuity
  changes, premise/head permutations, alternate controllers, and direct
  negation. Source compression alone does not predict the physical state
  count; new shorter emitters can lose reusable reader states or require a
  longer scanner. Many named195/196 files are rejected or only experimental.

* PA195/PA194 frontier: separate diagonal-head emitters, reader-tree
  reassociation, and compatible history-sensitive folds give the known
  134+67-7=194 count. A second arrangement obtains134+68-8=194.
  C caches successful-MP results and tests H=1. CS additionally reverses the
  destructive equality operands. N removes the successful-MP dummy push and
  requires a different proof compiler while retaining the t+h=1 Shift guard.
  H/HS combine no-push MP with cache-only Shift. Radices5/6 change formula
  constructors and proof recoding. Q exchanges two curried premises of a
  universal-distribution axiom and already uses C's cached controller.
  D changes the independently emitted diagonal head from Gamma(A) to Gamma(D).
  J/F/A/X/ZR use source invariants to replace jumps by known-zero decrements;
  R combines such a decrement with a distinct decoder arrangement. AD changes
  physical register placement. These are different construction dimensions,
  not independent state savings that can be assumed to compose freely.

PROOF BOUNDARY

The PA subtree README explicitly distinguishes ordinary PA-provability
manuscripts from a complete Lean/iPRA equivalence. The current machine-specific
iPRA reductions remain open. Upstream PA196 exports the formal direction from
nonhalting to Con(PA); neither an executable symbolic certificate nor a
standard-finite-run equivalence alone fills all internal arithmetic obligations.
A new construction should explicitly compose its own source/physical proof
with the inherited syntactic PA calibration, without claiming a newly compiled
end-to-end Lean or Rocq theorem.
