1. Scope and fresh measurements

The comparison accounts for all 100 filed PA research packets and all six
current incoming ZIP archives: 106 deliveries. The packet ledger preserves
each filed packet's placement summary, its original table occurrences, the
first appearance of named graph classes, and the distinction between a
packet's own proposals and named machines copied into its comparison data.
The incoming summaries were read directly from the six delivered packages.
The 91 previously named positive-claim classes were rebound to current
literal tables, and the 13 newly delivered named tables were added, giving
104 named classes. These labels describe what the reports propose; they
are not 104 freshly re-proved absolute consistency theorems.

The current Git tree supplies 16,568 selected direct blobs in PA and
docs/incoming with extensions .tm, .txt, .json, .csv, .tsv, or .zip. Every
selected blob was read and checked against its pinned Git object identity.
The recognizer inspected 23,540 payloads, traversing 40 ZIP references and
23 distinct ZIP byte payloads. Identical nested ZIP bytes are inspected
once globally. The base scan recognized 7,340 complete binary-table
occurrences and 1,380 normalized labeled table identities. A subsequent
coverage audit scanned 14,182 JSON payload occurrences and examined 2,965
unique payloads beyond the original fast screen, adding two 194-control
occurrences and one normalized labeling. Both are Boolean-direction
matrices at $/primary and $/permuted in the P5 local-reductions data.json;
both exactly match existing action-graph classes. The combined census is
therefore 7,342 complete-table occurrences and 1,381 normalized labeled
identities, with all graph counts unchanged. The supplement is scoped to
complete 193/194-control JSON matrices, with False=L and True=R. No scan
executes an arbitrary generator or infers a machine from prose. Thus the
coverage claim concerns the recognized explicit formats and all named
delivered tables, not every machine that every search script could generate.

There are 548 spanning 194-control action-graph classes and two additional
nonspanning 194-control diagnostic identities. All 528 classes in the
filed 194-state catalog were recovered. The current incoming material adds
13 named designs and seven other spanning 194-control research classes.
The fresh scan also recognizes 61 spanning 193-control research classes;
all 55 filed 193-state catalog classes were recovered. None of the six
incoming reports claims an accepted blank-start machine below 194 states.

The 194-class identity preserves read bits, writes, moves, and terminal
actions, and allows arbitrary control renaming and arbitrary graph root.
It is based on complete canonical transition tuples. Nonspanning tables
are kept apart because taking only the largest reachable component would
not classify their whole graphs. The final novelty test is deliberately
stronger: it additionally allows tape reflection, global bit exchange,
and ignored write/move decorations on entry to halt. Global bit exchange
is a structural test here; it does not preserve the all-zero blank tape.

All 548 spanning 194-state graphs have 194 classes under ordinary
action/target partition refinement, both with exact final actions and
with final actions ignored. This excludes a nontrivial quotient within
that narrow, context-insensitive one-step congruence family. It does not
exclude a tape-context fold, a stuttering simulation, a different source
program, or a different consistency construction.

2. The six architectural dimensions

SOURCE CALCULUS.
The oldest frontier uses numerical formulas built from Cantor pairing,
with implication, quantification, equality, a contradiction code, and a
finite list of axiom heads. Coefficients four, five, and six alter the
formula coding. Such changes need hereditary recoding of proofs; preserving
only the visible outer constructor is insufficient because arbitrary
formula codes and the zero alias are part of the numerical interface.

The Q families exchange the curried premises of the distribution head.
The diagonal families change which available argument feeds Gamma. The
GD families make the generalization binder and the diagonal parameter
independent. These are changes in emitted formulas, not mere register
renamings, and need uniform proof translations or a new all-store compiler.

The witness families are the most recent substantive logical change.
H5X replaces the consequent 1 in the witness head by an independent
argument A. Specializing A to 1 recovers the previous head; the reverse
translation uses the calculus's explosion derivation. JH5X also replaces
the first head (X -> 1) -> H by (X -> H) -> H. Its cited proof bootstraps
explosion separately before translating that first head, avoiding circular
use of the very principle being replaced. The delivered certificate
lengths and source-token savings describe those finite constructions;
they do not by themselves reduce the physical control count. The 188-
and 189-token emitters still require 194-state implementations in the
accepted deliveries. A still shorter emitter can need more distinct
reader subtrees.

COMMAND INTERFACE.
The main differences are the ten-entry versus eleven-entry AX interface,
the actual number and order of continuation operands, the treatment of
successful modus ponens, and the halting detector. The AX11 families
preserve an additional generated guard on the stack and run the full MP
operand reader. Its fourth operand is real: setting it silently to zero
would change the machine and invalidate the proof-word interpretation.

Cached MP, visible no-push MP, and the original dummy-push MP require
different stack invariants and proof-word compilers. Likewise the original
sum test t+h=1 and the cache-only test h=1 are not interchangeable without
adjusting the final contradiction detector. The H families need the
appropriate final Pop operation. Direct-binder G variants compute U(c,h)
from the command field instead of U(d,h) from an accumulated offset; their
forward compilation must supply that field, and their reverse invariant
must permit every field the scheduler can actually enumerate.

SOURCE TREE AND READER SHARING.
Different associations of the same macro word can change reader sharing
without changing the resolved primitive instruction graph. The relevant
comparison is the full instruction-and-successor graph, not only a
flattened sequence of opcode names. Source addresses, conditional branch
targets, and continuation returns all matter.

The ORH/OR incoming packet reassociates the operand reader and changes
134 source addresses. The new MP packet reassociates the MP body from
((A,B),(C,D)) to (A,(B,(C,D)), changing 87 addresses. Both preserve their
parent's resolved primitive instruction graph. Their separately accepted
tables still have 194 controls. Combining those independent regions is a
well-motivated construction to test: it changes recurring source routing
while retaining a single calibrated command program. The proposed ORMP
and ORMP-LC3 machines were supplied by the structural-reduction subtask
and are outside this prior-corpus census.

PHYSICAL REGISTER LAYOUT.
The AD, TDY, P5, HX, HR, HC4, and C32 families permute logical registers
among physical unary blocks and retarget selectors. Their mathematics
is a conjugacy of the register-frame representation. The allocation must
be used consistently by every arithmetic entry and every source frame.
An especially short blank startup is a time improvement, not a state-count
improvement. HC4 changes six selector rows on the revised AX11H source;
C32 changes seven rows on the original primary source. Their reported
startup lengths are 57,406 and 56,250 respectively, and both were freshly
replayed against the complete seed tape in this audit.

PHYSICAL RUNTIME.
The fold families use entry history or an already known tape bit to share
controls. The selector families preserve distinctions that a naive
control identification would erase. Exact acceleration families replace
guarded three-step paths by one transition, and the loop-continuation
families reassociate recurring constructor continuations. A transformation
must account for every entry into a reused control, including entries
that are not visible in the high-level macro tree.

The rejected OR193 example is a precise warning. It preserves the resolved
source instructions and passes local reader-fold checks, but fails 30
universal source outcomes because native control 213 is also reached as
a history selector through 69/read0. Its extra 194th repair control is
not merely dispensable bookkeeping. Similarly, marker/history separation
in the MF and MS families removes one reader and introduces a necessary
selector, so the total remains 194.

INITIALIZATION.
All accepted target specifications require a single two-way binary tape
that is entirely zero, head coordinate zero, and a counted start control.
A well-formed runtime frame is not an external input the construction may
assume. Native label 74 becomes dense start 0; native 254 is the terminal
label. Native label 194 is often an ordinary working control.

The recurring 301-to-88 runtime fold illustrates the bootstrap obstacle.
On an already formed first-register marker, the next bit is known to be
1, and two alternative continuations agree there. During blank startup
the same routine is called on an unfinished zero suffix, where the two
continuations differ. The incoming symmetric-witness study records the
first failure at transition 86 and an outward state-35 ray by time 92.
Shorter headers, a different start control, and small multirow patches
have been screened extensively, but no valid complete initializer is
provided for the 193-state cores in the current corpus. Search limits
are inconclusive, and these failed families are not a general lower bound.

3. Current incoming designs and what they add

PA194ORH and PA194OR add repaired operand-reader reassociation. ORH retains
the revised AX11H command source; OR retains the older primary source.
Their complete startup lengths are 57,942 and 58,170. The absolute iPRA
calibration in the first case is an identified inherited written theorem.
For the companion OR construction, this audit records its relative
transfer and the older primary PA calibration without silently promoting
that older calibration to iPRA.

PA194AX11HC4 and PA194C32 add the four-cycle and composed physical register
allocations above. Their new positive claims concern different parents:
the revised AX11H source for HC4 and the primary source for C32. The same
distinction about absolute arithmetic strength applies.

PA194LCSF3 adds the third guarded physical return shortcut to the
selector-bearing LC_AX11H source. It changes a recurring return used by
61 source sites, with positive witness bounds t and 3t. PA194AX11HMP adds
the MP reassociation, with a written common positive bound
58066 + 9*t^2 + 685*t. Its complete blank startup is 58,066.

PA194GD_SF, PA194GDH_SF, and PA194GDHS_SF combine an entry-history selector
and two guarded accelerations with the GD, GDH, and GDHS command sources.
The six changed rows are used during startup; the packages give relative
iPRA witness bounds 3t in both directions. Their startup lengths are
58,150, 57,918, and 57,760.

PA194H5X_MF and PA194JH5X_MF combine the witness calculi with two physical
shortcuts and marker/history separation. They introduce and remove one
control each, retaining 194. Their written relative bounds are 5t from
the parent to the child and 3t in the reverse direction; both initialize
in 57,970 transitions.

PA194H5XS and PA194JH5XS preserve the witness emitters and reverse the
cached equality comparison in Shift. This removes a restoration loop;
an additional contextual fold pays for the additional controller. The
source-step savings depend on the cache value, so a semantic source
argument is required in addition to a graph comparison. Both initialize
in 57,768 transitions.

All 13 incoming dense tables were independently parsed and checked to
have 194 working states, 388 complete binary rows, start 0, terminal 194,
and all controls graph-reachable from the start. A fresh literal simulator
then checked every one of their complete blank startups at the reported
times, including every one-cell and the zero exterior. This finite check
does not replace the universal symbolic contracts or the unbounded
written arithmetic proof.

4. Proof status and suitable baselines

There are at least four distinct evidence levels in this corpus:
(a) a numerical state count or a bounded experiment;
(b) a checked literal/source simulation certificate;
(c) an ordinary mathematical argument internalizable in a stated base
theory, with explicitly inherited calibration dependencies;
(d) a completed kernel-checked theorem about the exact blank-start table
and the fixed PA-refutation predicate.

The current PA root README says that the machine-specific Lean/iPRA
assembly is incomplete. It documents standard finite-run bridges,
model-level scheduler work, startup theorems, proof-compilation components,
and remaining physical-machine or compilation obligations. This does not
negate the existence of a later packet's ordinary written proof. Conversely,
a checked standard-model source run or a conditional Lean theorem does
not itself supply an internal proof in iPRA.

The revised packet pa194_ax11h_research_2026-11-14_2 is the most useful
common calibration baseline for a source-preserving physical change.
Its retained archive identity is
93ee082ef035b2d32e71d6af5239b25b4bea1773f03bea4d2c39810a7fe15075.
The newer reports cite its expanded written proof components: uniform
physical/source simulation, exact command semantics and four-field
scheduling, the forward numerical proof compiler, reverse soundness,
the current Foundation adapter, and weak-arithmetic transfer. The precise
endpoint is DiophantineConsistency.IPRAPA196Consistency.nativePAConsistency.
No proof-assistant completion is asserted for that package or the incoming
offspring. The comparison records the inherited argument and its claimed
strength; it does not claim to have independently rebuilt every transitive
proof-generating leaf of all 104 named designs.

For the new ORMP constructions, source-preserving physical simulation
offers a cleaner dependency chain than changing the calculus again:
exact parent table -> positive PR halting-witness transport -> negation
equivalence -> the parent's explicitly identified written calibration.
The arithmetic argument must still deal with arbitrary intermediate
halting times. Positive segment durations and an absorbing total run
function support this step without assuming that a nonstandard time lies
in the externally visible sequence of standard checkpoints.
