DESIGN TAXONOMY
The corpus is a family built on a shared enumerating register machine,
unary register-file implementation, binary source decoder, and proof-calculus
compiler. Its genuinely relevant distinctions occur in the following layers.

1. Logical heads and formula arithmetic.
The primary 194 construction separates a diagonal-vacuity head from the
other emitted heads. D changes its parameter from Gamma(A) to Gamma(D),
requiring different selectors. Q exchanges the curried premises in one
universal-distribution head, with explicit K/S/MP proof translations. Radix
five and six change every formula constructor and MP arithmetic and need
the corresponding recoding theorem. These are logical-interface changes,
not control renamings.

2. Command protocol and proof-store behavior.
The original controller tests t+h=1 at Shift and pushes a dummy zero on
successful modus ponens. C returns the consequent in the cache, clears top
and offset, and tests cache h=1 at Shift. N returns a visible consequent
(b,w,b,0) without the dummy push, retaining the original sum test. H combines
N's no-push MP with cache-only Shift. The all-store proof compiler changes
with these contracts: a top value equal to contradiction is not sufficient
to force an H machine to halt until it reaches the cache. The reports use
reserved zeros and explicit Pop operations to meet these requirements.
Merely deleting a physical push while retaining the old proof words does
not establish completeness.

3. Source implementation and decoder allocation.
S exchanges the arguments of the destructive equality routine and removes
a restoration loop. SUMS preserves the original sum guard; NS has been
used as a name both for a sum-guard design and for a cache-only HS design.
Decoder reassociation preserves the resolved primitive-instruction graph
while changing addresses and opportunities for local history-sensitive
folds. Primary PA194 uses 134 fixed controls + 67 raw readers - 7 folds;
the alternate PA194 uses 134 + 68 - 8. R and M4R are further decoder
associations. Source-instruction savings and tape-step savings are different
claims; a removed source loop is not itself a uniform literal-TM speedup.

4. Return conventions and startup.
J, F, A, X/CSZ, ZR, HA/HAZ replace selected unconditional returns by
decrements of registers proved zero at those sites. These rely on inductive
source invariants. A/D and H/X are physical register placements. These
edits can preserve source execution yet break the physical initialization;
the corpus contains an example halting after 1,361 blank steps despite
source-equivalent return behavior. A complete blank-frame check is an
independent obligation, not a consequence of a source invariant.

LARGER PREDECESSORS
The U208/PA209 and PA196 work supplies the underlying numerical-calculus,
proof compilation and contextual-fold lineage. Later 195 designs refine
the emitted heads, add the cached command protocol, separate diagonal
vacuity, or shorten scanners. They include rejected 195 candidates as well
as claimed calibrated constructions. A file's numerical name is therefore
not a proof-status designation. Historical 196 designs include register
placements, reassociated decoders, zero-return variants, and combinations
of logical/source modifications. The packet ledger and complete class
census preserve them without counting repeated tables as new designs.

RECENT INCOMING RESULTS
QH composes the Q head exchange with H's no-push visible-result MP and
cache-only Shift. QHS adds symmetric comparison, removing a source
restoration loop. H5, QH5, QN5 and QN6 are coefficient/controller
compositions. All remain at 194 working states; their ingredients are
credited to earlier packets. The latest H5 report expressly distinguishes
structural graph novelty from a materially new proof-search architecture.

AX11 makes a different recurring command-interface change. AX pushes its
final guarded head as well and falls into MP, consuming another operand z.
Its completed command has an eleven-item stored prefix, zero top/cache,
and offset z. The completeness compiler selects z=0; soundness allows
arbitrary z. This changes command parsing and proof-word compilation while
retaining the old logical head set. It should not be described merely as
another radix choice.

MP196 immediately checks successful MP's consequent for code one and
otherwise returns the visible consequent while clearing the offset. Its
command invariant differs from the existing Shift-only halting designs,
but the supplied literal implementation costs 196 states.

PA195EvenHX visits candidate codes 4,6,8,... while retaining all finite
command words as possible prefixes. Its parity-prefix proof and physical
H/X placement are substantial scheduler work, but the table has 195
working states. The first unswapped sparse trial halts and is not a valid
substitute. The report gives a complete 44,094-step blank startup to
source site 40 and an additional bridge to the clean site-25 scheduler.

WHY THE EXISTING 193-STATE OBJECTS ARE NOT SOLUTIONS
The current commit contains 53 recognized 193-state graph classes, not the
two found in older packet censuses. The extra objects are concrete physical
search transplants and runtime compositions in the newest incoming packets.
There are 49 transplanted tables (including the original runtime193 and
its append-zero version), plus the AX11 core, QN6 core, marker-relay core,
and the coefficient-three logical counterexample.

Fresh independent literal replay now covers all 52 physical classes at
every one of their 193 working controls as the all-zero blank initial state.
All 10,036 cases resolve in at most 117 transitions: 106 literal halts and
9,930 outward self-loop rays. No run reaches the 200,000-step cutoff; no
bounded nonhalting run is being mislabeled as a rejection. Each ray's
state, head, one-support, direction and write bit are retained. The
self-loop always moves into the blank exterior, proving its indefinite
continuation by elementary induction. The source tables, independent
checker, per-class certificates and complete ledger are supplied in
classify_193.py, rejections193/, and frontier193_current.csv/.json.
The coefficient-three rejection is the separate inherited logical result
described next; its large primitive refutation was not rerun by this audit.

The coefficient-three candidate in pa194nq/search/rejected193 has a smaller
physical realization but implements the wrong logical calculus. Its
equality/implication collision derives contradiction; the supplied primitive
refutation is part of the packet. Later research proves failure for every
nonnegative constant equality offset within a specified unchanged-head
coefficient-three family. This is a theorem about that encoding family,
not about all 193-state machines.

The runtime193 construction instead saves a state in the tape engine:
merge native control 301 into 88, redirect its incoming edges, and set
(88,0) to (0,L,51) and (51,0) to (0,R,122). Its 4,780 source outcomes have
certificates. The source runtime is the successful part; blank startup is
the failure. The table hash is
50f7be44afb63293365270a83111299247d12d140614e4b4c9a52786163acb53.
The original start enters an outward ray. The 1,158 elementary cases cover
all 193 controls from blank and from one marked bit with the head one cell
on either side, for both tested append variants. Thus a fresh one-transition
bootstrap state cannot repair this unchanged core by simply placing one bit.
The later QH5 packet also records bounded compound neutral-row startup
searches. These failures do not exclude a different multi-step initializer,
a coordinated tape convention, or a different source engine.

An exact rational dual certificate in a different incoming study bounds
the saving at seven within a fixed direct-selector/disjoint-reader family
of a fixed 201-state parent. Changed grammar, overlapping folds, helpers
targeting helpers, and longer detours are outside its stated theorem.
It must not be promoted to a universal lower bound of 194.

PROOF STATUS
The main PA README explicitly separates ordinary mathematical packet
calibration claims from the unfinished machine-specific iPRA formalization.
It states that neither machine-specific direction has yet been completed
in iPRA for the pinned PA194/PA195/PA196 targets. Many important Lean
components are present: exact finite-run quotient and source simulations,
arithmetic machine codes, scheduler and target-calculus arguments, and
partial proof translations. Their conjunction is not automatically the
missing end-to-end theorem.

The user's request is the ordinary PA-provability statement. An ordinary
proof can meet that request without a newly compiled Lean endpoint, but
the inherited numerical-calculus calibration remains a mathematical proof
dependency that must be stated and examined. Finite simulation establishes
only the observed finite startup. It does not establish infinite nonhalting
or either consistency reduction. Structural graph novelty likewise says
nothing about proof strength or correct blank initialization.
