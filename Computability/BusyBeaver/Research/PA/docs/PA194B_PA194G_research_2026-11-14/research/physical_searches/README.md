# Optional follow-on reduction searches

These are new searches performed on PA194B and on the earlier, rejected
Runtime193 core. They produced no accepted machine with fewer than 194
working states. They are optional research artifacts, separate from the
verification of the delivered machine. No negative result below is a lower
bound for arbitrary Turing machines.

## Portable replay

Python 3.10+ is sufficient for the tail experiment. The other suites also
require a C++17 compiler, named `g++` by default; set `CXX` to another compiler
executable if needed. Run Python without `-O` or `PYTHONOPTIMIZE` because the
inherited symbolic executor uses assertions. No network, repository checkout,
third-party Python package, or proof assistant is required.

Choose one suite explicitly:

```sh
python3 -B run_searches.py --suite radius4 --output /tmp/pa194b-radius4
python3 -B run_searches.py --suite radius6 --output /tmp/pa194b-radius6
python3 -B run_searches.py --suite heuristic --output /tmp/pa194b-heuristic
python3 -B run_searches.py --suite tail --output /tmp/pa194b-tail
```

Or request all four:

```sh
python3 -B run_searches.py --suite all --output /tmp/pa194b-all-searches
```

The wrapper compares deterministic contexts, hit sets, and search counters
with the recorded runs. It ignores elapsed-time differences. Compiled
executables exist only in a temporary directory and are removed at exit.
The `--output` directory receives freshly generated results. Existing
context files there are reused only after comparison with the supplied
recorded context hashes. Use a fresh directory for a complete regeneration.

## 1. Radius-4 and radius-6 two-row quotient search

Input: the complete native PA194B table, primary source paths, and the exact
resolved source instructions. All 4,780 source outcomes are first checked by
the inherited symbolic executor. Its arithmetic-box contracts remain
hypotheses, justified separately by the unchanged engine rows.

The corrected source-context collector observes the interior positions of
accelerated constant-symbol self-loops. It collects an overapproximation of
the finite windows at every non-box control, excluding startup. Correlations
between external symbolic stream lengths are discarded. For arithmetic-box
controls, the merger retains its default finite-window abstraction propagated
from the all-zero tape; it does not replace these with sampled source windows.

For every unordered pair of the 194 working controls, the synthesizer removes
the smaller-numbered control and retains the larger. Incoming targets to the
removed control are redirected. It assigns each read-bit row of the retained
control any write bit, direction, and target among the remaining working
controls. Both new rows may be visited repeatedly. Each test must reproduce
the old control's single-transition endpoint, including the complete window,
within 100 transitions, without reading outside the chosen radius.

The radius is 4 or 6 cells on each side of the head. The exact counts were:

| Radius | Source windows | Unordered pairs | Candidate row actions | Joint row pairs | Hits |
|---:|---:|---:|---:|---:|---:|
| 4 | 8,379 | 18,721 | 23,474,976 | 134,240 | 0 |
| 6 | 29,458 | 18,721 | 25,531,584 | 196,736 | 0 |

These tests could reject a valid reduction outside their template: longer
detours, wider windows, simultaneous changes to additional controls, a
different relation between simulated configurations, or a different source
program. This is not an optimality theorem. No candidate reached the stage
of a new universal proof or blank-initialization verification.

`src/joint_return_merge.cpp` is the unchanged inherited synthesizer.
`src/collect_source_contexts.py` changes only how it locates its runtime
dependency. `PROVENANCE.json` gives exact packet paths and hashes.

## 2. Additional heuristic engine-window search

This experiment deliberately narrows the engine-control windows using
concrete source frames. Its purpose is to discover candidate merges that
the conservative engine abstraction above might suppress.

For each of the 3,673 source addresses, it constructs a normal tape frame
with 12 physical registers. It tests 79 register vectors:

- Five constant vectors, with every value respectively 0, 1, 2, 3, or 8.
- For each value 1, 2, or 8 and each of the first nine positions, one vector
  containing that value only at the chosen position, and one constant vector
  of that value except for zero at the chosen position: 54 vectors.
- Twenty vectors generated by the standard C++ `mt19937` engine seeded with
  193, with each entry equal to the next engine output modulo 10.

Each source frame is simulated until its first return to control 84 or halt,
with a 200,000-step cap. This first return can be an intermediate controller
return within a source instruction. The experiment therefore samples prefixes,
not necessarily complete primitive-instruction executions. Source paths, tape width, and register vectors are
literal supplied inputs. The collector also includes all engine windows of
the exact 58,242-transition blank initialization. Radius 4 is used throughout.
The 1,474 sampled engine windows are combined with the symbolic source
windows for non-box controls.

Observed run: 290,167 source-frame prefixes; 30,301,733 literal transitions including
startup; maximum sampled prefix duration 132; 1,474 engine windows. The merge
search checked 18,721 pairs, 23,989,900 candidate row actions, and 141,014
joint row pairs, with no hits.

This sampled engine envelope is not a proof that a proposed merge would
preserve arbitrary register computations. Any hit would require a separate
unbounded engine lemma, complete source binding, and exact startup check.
No such hit occurred.

## 3. Alternative spare-tail actions for Runtime193

Runtime193 is the inherited rejected core obtained by borrowing skip control
51 as a history selector. Its symbolic source contracts pass, but its blank
initialization does not establish a consistency machine. The input here is
explicitly `inputs/runtime193.native.tm`, not PA194B.

This new experiment permits a more general spare-tail effect than fixing the
increment's appended spare to 0 or 1. It replaces row `198/0` with each of the
772 possible actions: two writes, two moves, and one of 193 working targets.
All other rows remain fixed.

Each candidate starts in state 198 at cell 0, with ones at positions -3 and
-1, and zeros elsewhere to the right. The prefix left of -3 is arbitrary;
reading it is forbidden. Acceptance requires returning to control 40 at
position -3 while preserving its 1 and leaving to its right a finite unary
register-list encoding: each nonnegative register is a zero delimiter
followed by one or more ones. No remote one may remain outside that list.

The search uses `range(100)`: only a return detected at a step strictly below
100 is accepted. It also rejects any head position greater than 100 or less
than -3 before the next transition, and rejects a halt. Exact repeated finite
configurations are detected. The status `bound` means only that no accepted
return was detected within that finite bound, not that it cannot occur later.
The status `outside` combines the head restrictions and halt cases.

Recorded classification: 772 actions, 668 bounded, 97 outside, and seven valid
local tails. The seven successful actions are:

| Write | Move | Target | Local steps | Appended register values |
|---:|:---:|---:|---:|---|
| 0 | L | 40 | 3 | `[0]` |
| 1 | L | 40 | 3 | `[1]` |
| 0 | L | 54 | 3 | `[0]` |
| 1 | L | 54 | 3 | `[1]` |
| 1 | R | 54 | 5 | `[1]` |
| 0 | L | 66 | 3 | `[0]` |
| 1 | L | 66 | 3 | `[1]` |

All seven local effects therefore reduce to append-zero or append-one; the
search found no new finite appended-list pattern. These local tail checks
are not a proof of a repaired blank initialization.

## Contents and evidence boundaries

`inputs/` contains all exact machine and source inputs. `recorded/` contains
the completed logs, context sets, receipts, and empty hit files. `src/` and
`vendor/` contain all required code. `licenses/` and `PROVENANCE.json` retain
the inherited attributions.

The run times in historical logs describe the original execution. The
replay checks deterministic outputs and counts, not timing. This directory
provides reproducible finite research evidence; PA194B's correctness comes
from its separate two-cell simulation proof and verification.
