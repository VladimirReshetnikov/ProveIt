\begin{abstract}
This report supplies two materially different 194-state alternatives.
No reduction below 194 was established. Both are complete, one-tape,
two-symbol Turing machines on a blank two-way tape, with 194 working states
and a separate halt label. PA194B changes the recurring physical decoder by joining
two history-distinguished readers and using their freed slot for a dedicated
history selector. A four-case, two-cell argument proves exact halting
equivalence to the pinned primary PA194 machine on every tape started in
its initial control. Each old step takes between one and five new steps.
This transfer is formalizable in PA and, composed with the inherited
written PA calibration, gives
\(\PA\vdash\neg\Halt(\mathrm{PA194B},\mathrm{blank})
\leftrightarrow\Con(\PA)\).

PA194G changes the generalization head from $U(d,h)$ to $U(c,h)$, using
the explicit AX parameter instead of the carried numerical offset. A new
all-store proof compiler establishes the same PA consistency equivalence.
Its generalization word is shorter by one command, and its literal
implementation has 3,654 source sites and 4,755 verified symbolic outcomes.

The comparison covers all 61 filed research packets and 11 current incoming
archives at the pinned repository revision. A fresh literal and explicit-JSON
census finds 638 graph classes, including 82 at 194 states and 53 rejected
or uncalibrated classes at 193. Every prior 194-state graph has 21 self-loop
transitions; PA194B has 22. This proves that the new graph is not any prior
one under control renaming, root changes, tape reflection, or global symbol
exchange. PA194G is separately distinguished by its 88 controls of indegree
one; no prior graph has that count. Both exact blank initializations pass,
as do all 4,780 PA194B arbitrary-register source outcomes. No new end-to-end Lean, Rocq, or iPRA consistency
formalization is claimed. The archive includes the full table, constructors,
two verification routes, the comparison data, and the inherited mathematical
dependencies.
\end{abstract}

\subsection{Why the 193-state files are not a solved result}
The 53 recognized 193-state classes include the coefficient-three logical
shortcut, the primary runtime quotient, its AX11 and QN6 compositions,
append-zero and marker-relay experiments, and 47 distinct graphs among 49
transplants of the runtime quotient to existing 194-state variants.
The machine-readable ledger records each class and its source.

There are two particularly decisive obstructions. First, replacing
\(I(a,b)=4p(a,b)\) by \(3p(a,b)\) while retaining the corresponding fifth
head causes \(E(1,0)=I(0,1)=6\). The incoming refutation certificate derives
literal contradiction code one using the retained restricted implication
basis, generalization, and that fifth head. It includes a primitive-rule
expansion of 73,393 lines. This is an inconsistency of that modified
calculus, not merely a missing interpretation proof \cite{negative}.

Second, the primary Runtime193 rewrite replaces
\(\delta(51,0)=(0,R,16)\) by \((0,R,122)\).
On a valid register frame, the next cell is one and the successors agree:
\(\delta(16,1)=\delta(122,1)=(0,L,1)\). During blank initialization,
however, the next cell can be zero. The two successors then differ. From
the inherited start, the failed runtime reaches control 35 after 92 steps
and writes indefinitely into untouched blank cells. The prior packet
classifies every unchanged existing start as a finite halt or an outward
ray. The later QN6 collection reports 9,457 startup tests across 49
transplants, yielding 100 halts and 9,357 certified outward rays
\cite{runtime193,qn6}.

These are exact reasons to reject those constructions. They do not prove
that every 193-state binary machine must fail, and none of the unsuccessful
searches is used here as a global lower bound.

\section{The inherited PA calibration and its precise role}
\label{sec:calibration}
\subsection{The numerical calculus remains unchanged}
The construction changes the physical decoder only. Its source program,
command language, arithmetic coding, axiom instances, scheduler, and
designated contradiction are exactly those of the primary PA194 packet.
For completeness, the principal ingredients are displayed here.

For \(p(a,b)=(a+b)(a+b+1)/2+b\), write
\[
 I(A,B)=4p(A,B),\quad M(a,b)=4p(a,b)+1,\quad
 U(a,B)=4p(B,a)+2,\quad E(a,b)=4p(a,b)+3.
\]
Code zero denotes truth and code one is the designated contradiction
\(M(0,0)\). Use \(A\to B=I(A,B)\), \(N(A)=I(A,1)\),
\(A\wedge B=N(I(A,N(B)))\), and \(\exists_a A=N(U(a,N(A)))\).
The six ordinary axiom heads are
\begin{align*}
 h_1(D,H)&=(\exists_D U(D,H))\to H,\\
 h_2(D,A,H)&=U(D,U(A,H))\to U(A,U(D,H)),\\
 h_3(D,A,H)&=M(H,D)\to(E(H,A)\to M(A,D)),\\
 h_4(D,A,H)&=E(H,D)\to(M(A,H)\to M(A,D)),\\
 h_5(D,H)&=\exists_D E(H,D),\\
 h_6(D,A,H)&=U(D,A)\to(U(D,A\to H)\to U(D,H)).
\end{align*}
The restricted implication head is
\[
 \rho_8(D,A,H,u)=((H\to u)\to D)\to((D\to H)\to(A\to H)),
 \qquad u\le D.
\]
There are also the diagonal head \(\Gamma(B)=I(B,U(B,B))\)
and the guarded gate \(G(a,b,c)\), for \(c\ne a,b\), defined by
\begin{align*}
 V(a,b,c)&=M(a,b)\to U(c,M(a,b)),\\
 P(a,b,c)&=c\to M(c,b),\\
 S(a,b,c)&=U\bigl(b,(M(a,b)\to P(a,b,c))
                         \wedge(M(c,b)\to c)\bigr),\\
 Q(a,b,c)&=U(c,S(a,b,c)\to N(P(a,b,c))),\\
 G(a,b,c)&=N(V(a,b,c)\to Q(a,b,c)).
\end{align*}
The primitive rules are modus ponens and theorem generalization
\(B\mapsto U(i,B)\). There are no undischarged assumptions in a numerical
derivation, although displayed labels can be free.

Two details are necessary. The equation \(I(0,0)=0\) is a real numerical
alias, so the constructors are not treated as disjoint at zero. Also the
guard permits \(a=b\); excluding the equality case would silently change
the calculus. PA194B alters neither detail.

\subsection{From source halting to a PA refutation}
Interpret membership by the finite binary relation
\[
 \operatorname{Bit}(s,z)\;\equiv\;
 \exists u,v\,[s=(2u+1)2^z+v\ \wedge\ v<2^z],
\]
equality by arithmetic equality, and universal constructors by first-order
universal quantification. PA proves \(\operatorname{Bit}(s,z)\to z<s\),
and hence refutes the interpretation of code one,
\(\operatorname{Bit}(x_0,x_0)\).

Every variable label in a nonzero decoded formula is strictly below the
formula code. Induction on its decoding proves the component bounds; the
zero case is truth. Thus the variable \(x_B\) is absent from the formula
with code \(B\), and \(\Gamma(B)\) has a uniform first-order proof.
The zero alias is handled by a fixed proof of
\(\top\leftrightarrow(\top\to\top)\).

For each arithmetic formula \(\theta\), PA proves finite binary
comprehension by induction on the finite bound. In the successor step it
retains the previous binary number or adds \(2^n\), according to
\(\theta(n)\). Substitution of the formula syntax into this fixed
induction-proof pattern is a primitive-recursive proof-producing operation.
For the separation gate the matrix is
\((\operatorname{Bit}(x_a,z)\lor z=x_b)\wedge\theta[z/x_b]\)
when \(a\ne b\), and \((z=x_b)\wedge\theta[z/x_b]\) when \(a=b\).
In the latter case, the membership antecedent bound by the repeated label
is \(\operatorname{Bit}(z,z)\), which PA refutes. This distinction is
essential to the inherited proof.

The source store carries its visible theorem, cached theorem, and Cantor
stack between trials. Annotate each live entry with a PA proof of its
interpretation. AX supplies the corresponding proof templates, successful
MP combines two annotations, unsuccessful commands supply the fixed proof
of truth, and Shift moves annotated entries. Since the original halt test
is \(t+h=1\), both visible values require annotations. Popping numerical
zero uses the fixed truth proof; the identity \(p(0,0)=0\) does not create
a fictitious stack cell. A halt therefore constructs a PA refutation.
This is a syntactic proof transformation, not a claim that PA proves its
own soundness.

\subsection{From a PA refutation to source halting}
The inherited compiler uses two-way membership rewriting, the neighborhood
equality interface, and an equality witness. The diagonal-vacuity
replacement supplies the interfaces formerly obtained from equality
vacuity. For a reverse rewrite, take the fresh separator label to be the
code of the negation of the entire desired conclusion. Pointed separation,
the retained direct rewrites, and membership-only vacuity yield a
contradiction under that negation. Its diagonal instance allows the final
generalization. The arithmetic code bounds supply the required freshness
without a semantic substitution assumption.

For neighborhood equality, first use the fresh binder given by the code of
\(E(a,b)\). Two-way membership rewriting and the diagonal head give the
neighborhood assertion at this binder. The equality witness and
membership-only vacuity transport it to each other allowed binder. These
are finite proof templates, and their construction and verification are
arithmetizable in PA. The detailed inherited arguments are included in
\file{references/diagonal_calculus.tex} and
\file{references/original_pa195_calibration.tex}; the separate-head
adaptation and primary calibration are also retained.

The separate diagonal AX command pushes ten entries. Its stack words must
therefore be the adjusted ones, including
\[
 \mathsf{Pop}=\mathsf{AX}(0,0,0)\mathsf S^{11},\qquad
 \mathsf{Push}=\mathsf{AX}(0,0,0)\mathsf S^9\mathsf{MP}(0).
\]
The proof compiler works from every carried store after its explicit
normalizing prefix. The scheduler enumerates a cofinal family of encodings
of each resulting finite halting command word. Positive continuation codes
strictly decrease until the next fresh trial. This argument does not assume
that unsuccessful trials reset the store. A finite PA refutation thus
produces a finite halting source execution.

\subsection{Composition with the new physical theorem}
The primary packet's source contracts and exact initialization identify its
blank computation with that source. Its inherited syntactic translations
give the ordinary mathematical statement
\[
 \PA\vdash\left(\Halt(M,\mathrm{blank})\leftrightarrow
       \exists e\,\Prf_{\PA}(e,\ulcorner0=1\urcorner)\right).
 \tag{1}
\]
The new two-cell proof, including its finite-run induction, gives
\[
 \PA\vdash\left(\Halt(\BB,\mathrm{blank})
                    \leftrightarrow\Halt(M,\mathrm{blank})\right).
 \tag{2}
\]
Consequently the composed result is

\begin{minipage}{\linewidth}
\begin{theorem}[PA194B consistency calibration]
Using the inherited written PA194 calibration (1),
\[
 \boxed{\displaystyle
 \PA\vdash\bigl(\neg\Halt(\mathrm{PA194B},\mathrm{blank})
                       \leftrightarrow\Con(\PA)\bigr).}
\]
\end{theorem}
\begin{proof}
Compose (2) and (1), then negate the PA-refutation predicate.
\end{proof}
\end{minipage}

This isolates the trust boundary: the new physical theorem has a small
exhaustive certificate and a direct proof; the arithmetic consistency
calibration is inherited and identified. The present result neither
completes the existing iPRA formalization nor replaces its open obligations
with a Python run.

\section{Verification, novelty, and reproducibility}
\label{sec:verification}
\subsection{Independent verification routes}
The PA194B builder \file{verify_build.py} reconstructs the new table from the
pinned native input, checks its local cases, reruns the complete symbolic
source interface, and compares the entire finite-support tape at the
initial clean source frame. The separate
\file{verification/check_transfer.py} imports neither the builder nor the
symbolic runtime. It uses strict table parsing, checks all 384 ordinary
transition cases under the map \(301\mapsto88\), and checks the four
exceptional cases on a partial tape that forbids reads outside the two
specified cells. It also checks the dense/native bijection and the novelty
invariant against all 82 included 194-state representatives.

\input{verification_table.tex}

The exact local theorem is sufficient to transfer the baseline behavior
without relying on the source's arithmetic-box oracle. The full symbolic
source rerun is additional implementation evidence. Its 4,780 outcomes
quantify over arbitrary natural register values, both decrement outcomes,
an arbitrary affine header gap, and an arbitrary nonempty finite spare
list. Its iteration counts are symbolic-rewrite counts, not a finite bound
on the actual runtime of arbitrary register operations.

The startup result is an exact finite computation. At the clean source
frame the head is at \(-2\), the native control is 84, the logical registers
are \((2,0,0,0,0,0,0,0,0)\), and the spare list consists of 26 values equal
to one. All markers, encoded source bits, register blocks, spare blocks,
and the blank exterior are compared. The old startup visits old row 88/0
22 times and old row 301/0 11 times, accounting for precisely
\(2\cdot22+4\cdot11=88\) extra transitions.

PA194G has separate construction, command-algebra, and literal-tape
verification routes. The construction checks 3,654 source sites and all
4,755 outcomes in 1,477,258 symbolic steps. The independent tape checker
checks the same outcomes in 1,078,742 symbolic steps, with maximum 379
and minimum positive duration constant 3. It derives four register-list
induction lemmas from the actual transition rows, compares two source
resolvers, and verifies dense/native conjugacy and graph reachability.
Its exact startup takes 58,154 transitions and reaches the same specified
register frame. The free-constructor emitter check identifies the new
head as $U(c,h)$ with the incoming cache $h$, not its incremented value
$H=h+y$. An independent algebra review of the complete proof compiler is
included in \file{comparison/pa194G_command_review.md}.

\subsection{A short proof of graph novelty}
All 82 recognized earlier 194-state graphs have 21 self-loop transitions
on 21 distinct controls. PA194B has 22 on 22 controls. The extra loop is
the new selector's \(301/1\) row. Therefore no prior graph is PA194B under
any control renaming. Changing the initial root, reflecting left and right,
exchanging symbols, and ignoring terminal halt-edge actions all preserve
the number of self loops, so these identifications cannot erase the
difference either. The stronger canonical comparison was also performed
and found no match.

This establishes novelty within the pinned recognized corpus. It is not a
claim about all unpublished machines or every possible generator output.
More substantively, the new architecture decouples history selection from
the register marker that invalidated Runtime193. Its selector is visited
55 times during startup and is used in the recurring decoder. Thus the
new loop is operationally meaningful, rather than an unreachable addition.

PA194G has 88 working controls of indegree one, counting the two read-symbol
edges with multiplicity. The corresponding count among the 82 prior graphs
is one of $87,89,90,91,92,93,94$; none has 88. This scalar invariant proves
PA194G's novelty under the same identifications. The complete canonical
comparison likewise found no match. PA194G has 21 self loops, so the
self-loop invariant separately distinguishes the two new designs.

The command change is also observable before physical compilation. With
$c=1$, $d=0$, and incoming cache $h=0$, the new ninth AX head is
$U(1,0)=10$, whereas the old one is $U(0,0)=2$. Both are valid theorem
generalizations, but the choice of binder now follows the command operand.
This gives the shorter generalization word proved in
Section~\ref{sec:pa194g}; it does not itself save a machine state.

slots across four runs, with 39,536,998 scoring evaluations and 5,478,786

so these counters do not partition the main-loop slots. No projected
state score below 194 was found. Separately, 1,233 archived 190-token
associations were screened after the explicit-parameter generalization
change. That screen supplied PA194G's candidate association. A projected
score was not accepted as a physical state count: the initially selected
maximum matching contained incompatible contextual folds. A different
seven-fold set passed all 28 simultaneous local cases and the subsequent
source and startup checks. Exact inputs, seeds, budgets, and completed
receipts are included in \file{generalizer/search/} and explained in
\file{generalizer/SEARCH.md}.

The relevant prior negative results were checked before allocating further
searches. In particular, the incoming startup work already explores large
pools of source-neutral row changes and their pairs/triples. The failure
of those pools was not treated as a reason to call an uninitialized runtime
an answer. The searches reported here have finite, explicit domains. They
do not establish an optimal state count, a lower bound for the compiler, or
an impossibility of sub-194 PA-consistency machines.

\section{What transfers from ZFC and ConciseIPRA}
The useful ZFC idea is history-sensitive sharing \cite{zfc}: an immediately preceding
written tape symbol can distinguish logical roles that otherwise require
separate controls. The difficulty is preserving its context at every entry,
including the blank startup and arithmetic boundaries. PA194B keeps that
idea but supplies a dedicated selector instead of changing the register
marker. Its correctness is consequently an unrestricted tape identity
under a mechanically checked incoming-edge condition.

ConciseIPRA contributes a different methodological lesson: reducing the
logical interface and proving derived operations can simplify a complete
checker. The inherited diagonal-vacuity PA construction already uses a
related strategy. However, directly replacing the searched theory with an
iPRA calculus would change the consistency target. No Con(PA) calibration
follows merely from a shorter iPRA presentation. Likewise, a smaller Python
checker is not a smaller binary single-tape TM until an explicit compilation,
state count, initialization, and semantic proof are supplied \cite{concise}.
PA194G applies this lesson locally: changing the proof-search command
interface shortens a derived operation while retaining an explicit compiler
for all proofs of the same theory. The independently counted physical
result, rather than the shorter command word alone, determines its state
count.

\section{Further research questions}
\begin{enumerate}[leftmargin=*]
\item \textbf{Can one dedicated selector serve two or more reader pairs?}
The present factoring removes one old role and spends one control on its
selector. Sharing that selector across a second pair would be a concrete
route to a net saving. Search the actual entry-history languages and
two-cell identities, rather than counting apparent common descendants.

\item \textbf{Can the runtime quotient be initialized after a semantic
change to the spare-list allocator?} Existing experiments cover the
ordinary append-zero/append-one variants and large neutral-edit pools. A
different valid allocator tail or a globally different frame representation
could alter the startup constraint. It must have an arbitrary-prefix
arithmetic lemma as well as a literal blank computation.

\item \textbf{Can the source protocol and reader allocation be optimized
together?} AX11 illustrates that a terminal return can become a useful
command continuation. The value of such a change is a verified literal
count, including all parameter readers and stack-management costs. A new
candidate should carry a complete all-store command compiler from the start.

\item \textbf{Can a different atom/quantifier coding save one control
without invalidating self-indexed binders?} Recoding a formula changes its
numeric code, while a gate uses that code as a variable label. A proof
conjugacy must reconcile the resulting freshness and guard conditions.
Simply substituting a new constructor coefficient is demonstrably unsafe.

\item \textbf{Can the small physical transfer be formalized once as a
reusable bounded-segment theorem?} The four-case certificate, predecessor
history rule, and factor-five time bound are much smaller than the full
PA calibration. A kernel-checked theorem parameterized by a finite local
certificate would support many future changes. It would be a useful formal
result even while the independent arithmetic/compiler obligations remain.
\end{enumerate}
