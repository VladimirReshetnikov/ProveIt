\begin{abstract}
No valid blank-start machine with fewer than 194 working states was obtained. The principal fallback is PA194AX11HC4, a new physical implementation of the calibrated AX11H source. It has 194 working states and 388 binary transitions. A four-cycle in the placement of registers changes six selector rows, all exercised during initialization. Its exact blank startup takes 57,406 steps, and all 4,778 symbolic source outcomes pass. The source program and arithmetic blocks are unchanged. A positive-duration simulation transfers the supplied written iPRA calibration to this literal table. A companion, PA194C32, preserves the original primary PA194 source, changes seven selector rows, passes all 4,780 outcomes, and initializes in 56,250 steps.

The fresh comparison recognizes 526 spanning 194-state table classes in the six current incoming archives, including all 139 historical catalog classes. Both new tables are distinct from that corpus under control renaming, choice of root, reflection, bit exchange, and ignored halt-entry decorations. These are new concrete register allocations within an existing method, not a new logical calculus. A new two-edit bootstrap screen for a 193-state runtime core tests 22,575,210 blank starts without finding a complete source frame within its stated bounds. A separate source-compression experiment shortens the axiom word to 189 macro tokens but compiles to 196 states.

The iPRA result is an ordinary mathematical transfer from the supplied written AX11H calibration. This release does not claim a completed end-to-end Lean or Rocq proof.
\end{abstract}

\subsection{Structural comparison and exact starts}

For a spanning deterministic labeled transition graph, choose a root and traverse outgoing read-$0$ then read-$1$ edges. Replace state names by discovery indices. This produces a complete canonical tuple for a rooted graph. Comparing the candidate with every possible prior root removes dependence on native state names and on the prior chosen initial state. Equality is checked on transition tuples, rather than inferred only from matching hashes.

For each new table, the novelty test makes
\[
       526\cdot194\cdot4=408{,}176
\]
comparisons. The four orientations allow or disallow a global left/right reflection and a global exchange of $0$ and $1$. Write and move decorations on edges into halt are ignored. No match is found. Positive controls test that the implementation recognizes its permitted transformations. The two new tables also differ from one another under the same equivalences.

Bit exchange is included only to strengthen this structural novelty test. Exchanging bits while keeping the initial tape all zero is not in general a blank-start computation equivalence. \subsection{Mechanisms shared by the existing designs}

The physical core performs unary register selection, marking, increment, decrement and return. A compressed tree decodes the axiom-emitter program. History-sensitive folds share readers by recovering a bit from a nearby tape cell and returning through an existing helper. The original primary accounting is
\[
       134\text{ fixed controls}+67\text{ raw readers}-7\text{ folds}=194.
\]
Several other packets realize the same frontier with different raw-reader and fold counts. Those allocations are properties of a specified compiler and grammar, not lower bounds on arbitrary consistency machines.

The important source changes fall into four broad groups. Formula-coding changes alter constructor coefficients or axiom heads and require proof translations. Store changes alter the placement of modus-ponens results, pushes, cache tests and halting guards; their completeness proofs must work for arbitrary carried stores. Decoder and continuation changes preserve a source graph only after checking structured jump destinations, not merely the expanded word. Physical transformations change reader folds, register selectors or guarded paths; their obligations include the entire blank initializer.

\section{Why the transformations preserve halting in iPRA}
\subsection{A precise simulation statement}

The distinction between a standard finite-run argument and an internal weak-arithmetic proof matters here. The new transfer uses primitive-recursive encodings, positive segment durations, and quantifier-free induction. It does not infer iPRA provability merely from a Python pass or from the existence of a PA proof.

Let $F$ be an augmented source-step function. Its coded state includes the source program counter, logical registers, padding and spare-list data required by the physical frame, including the head coordinate as ghost data. Its projection to the calibrated logical source commutes with steps and preserves halt flags by quantifier-free induction. This bookkeeping changes no physical machine control. Let $G$ be the literal machine step on a canonical finite-support tape code. When the literal control enters halt, replace the entire physical configuration by a single code $H$, and put $G(H)=H$. Likewise put $F(H)=H$ and $E_\pi(H)=H$, and include $H$ among valid coded states. This canonicalization preserves halting times and introduces no new physical working state. Both $F$ and $G$, their iteration functions, and their Boolean halt tests $h_F,h_G$ are primitive recursive.

Let $P$ be the primitive-recursive frame-validity predicate and $E_\pi$ its physical encoding under allocation $\pi$. The local proof obligations, uniformly for every coded valid source state $c$, are
\begin{align}
 P(c_0)&=1, & P(c)=1&\ \Longrightarrow\ P(F(c))=1,\\
 1&\le\tau_\pi(c), &
 G^{\tau_\pi(c)}(E_\pi(c))&=E_\pi(F(c)),\label{eq:local}\\
 h_G(E_\pi(c))&=h_F(c), &
 G^{d_\pi}(b_0)&=E_\pi(c_0).\label{eq:startup}
\end{align}
The equations restricted to valid frames have primitive-recursive Boolean hypotheses. The duration $\tau_\pi$ is a specified primitive-recursive function; its existence is not inferred by an unbounded search for the end of a macro. On the absorbing source halt, use duration one.

\begin{lemma}[Positive-duration transport]\label{lem:transport}
If the displayed obligations and the absorbing halt-flag law are theorems of iPRA, then iPRA proves source halting equivalent to blank target halting, and hence their nonhalting sentences equivalent.
\end{lemma}
\begin{proof}
Define the primitive-recursive cumulative duration
\[
 T_\pi(0)=0,\qquad T_\pi(n+1)=T_\pi(n)+\tau_\pi(F^n(c_0)).
\]
Quantifier-free induction proves frame validity, $T_\pi(n)\ge n$, and the iterated endpoint equality
\[
       G^{d_\pi+T_\pi(n)}(b_0)=E_\pi(F^n(c_0)).\tag{*}
\]
For a source-halting witness $n$, equation (*) supplies target witness $d_\pi+T_\pi(n)$. Conversely, if the physical machine has halted at time $t$, its absorbing flag is still set at $d_\pi+T_\pi(t)\ge t$. Applying (*) and halt-flag agreement yields $h_F(F^t(c_0))=1$. Thus $t$ itself is a source-halting witness. No least-boundary search, Markov principle, or excluded middle for an arbitrary formula is used. Intuitionistic logic then gives equivalence of the negations.
\end{proof}

This proof is included to identify the role of positivity. Without it, checking isolated endpoints need not account for all target times. A fixed duration-zero encoding could match every source endpoint while the target leaves that endpoint and halts. All accepted nonhalting source segments here have positive physical duration.

\subsection{Discharging the physical obligations}

The supplied AX11H physical audit proves arithmetic soundness of literal transitions, affine scans and four generic unary-list sweep lemmas by quantifier-free induction~\cite{physical,transport}. It also includes variable list width, spare growth, frame validity, exact startup and primitive-recursive clocks. Those are the inherited physical facts used here.

For the new allocation, replace the occurrence of $\pi_0(r)$ by $\pi(r)$ in the frame definition and selector target. A scan selects the new block position, while the same arithmetic lemma increments or decrements its arbitrary natural value. The finite decoder path and the logical successor instruction are unchanged. The independent source resolution and every zero/positive outcome check establish the finite bindings to the exact new rows. This supplies the same finite family of arithmetic derivations with changed register indices. It does not require new arithmetic-box axioms.

The initial ghost data are head $-2$, gap parameter $n=0$, and spare list $Q$ consisting of 26 ones. An increment appends one to $Q$; a positive decrement replaces $n$ by $n+1$; other live steps preserve these data. Every nonhalting local endpoint has zero head displacement, as checked in the full contract arrays.\par

The duration is constructed from the physical trace certificate, summing the primitive-recursive literal and scan/list-sweep durations. Its input contains the whole finite register/spare list, so an unbounded future spare width is not frozen at the startup value. The local rule proofs and the finite source graph establish closure and the endpoint equations in every required internal frame, including nonstandard frames in the model-based presentation. The fixed startup equalities are closed primitive-recursive computations checked against the complete tape. Hence Lemma~\ref{lem:transport} applies to each accepted allocation.

The corresponding nonhalting equivalences follow intuitionistically.

\section{The inherited PA consistency calibration}

The repository's main PA README records an incomplete end-to-end Lean development~\cite{pareadme}. The later revised AX11H packet separately supplies a written mathematical iPRA calibration with explicit primitive-recursive constructions~\cite{ax11hclaim,ax11hfinal}. These statements concern different proof statuses. An incomplete Lean proof does not by itself negate the written argument, and a written argument does not constitute a completed Lean build.

The revised calibration has five essential connections. A current Foundation PA refutation is transformed to the ordinary PA-with-equality presentation. A syntax-directed numerical proof compiler translates that proof into the numerical calculus. An all-store command-word compiler and a fair four-field scheduler expose a refutation even with an arbitrary carried store. Exact source and physical clocks implement that scheduler. In the other direction, proof annotations maintained by the scheduler turn a halt into a numerical refutation and then into a PA refutation.

The forward compiler's weak-base proof is substantive. It bounds a finite-demand tree of rank $r$ by $2^{r+2}-1$, computes child parameters from syntax before returned proofs, separates same-family rank decreases from calls to lower families, and verifies reverse evaluation with Boolean invariants. Its induction-axiom supplier and logical proof compiler are included in the supplied written argument~\cite{forward}. The physical and scheduler proofs similarly give explicit clocks and cofinality bounds, rather than appealing only to standard termination.

More concretely, the parent proof uses an all-store word $V_e$ compiled from a numerical refutation $e$, a raw candidate $N_e$, a command bound $K(e)=(N_e+2)^2$, a cumulative source clock $B$, and a cumulative physical clock $\tau$ (distinct from the local duration $\tau_\pi(c)$ above). Its displayed halting witness is
\[
       57922+\tau\bigl(B(K(e))\bigr).
\]
For AX11HC4 the identical logical and source constructions are retained, while the last expression becomes
\[
       \boxed{57406+T_{\pi_4}\bigl(B(K(e))\bigr).}
\]
The positive absorbing continuation used for $T_{\pi_4}$ may increase a time after halt; it remains a valid halting witness. The reverse annotation argument is unchanged. The supplied all-model $\mathrm I\Sigma_1$ reductions are passed through the pinned conservation and negative-translation endpoints. This proves the desired negative equivalence without inferring a positive existential from its double negation~\cite{ax11hfinal}.

\begin{theorem}[Principal consistency result]
Using the supplied revised AX11H written calibration, the delivered literal principal machine satisfies
\[
       \boxed{\ipra\ \vdash\
       \Con(\PA)\ \longleftrightarrow\ \neg\Ht_{\mathrm{blank}}(\Mmain).}
\]
Here $\Con(\PA)$ is the negation of the fixed current Foundation PA-refutation predicate used in that calibration. No assumption of PA consistency is used to prove the equivalence.
\end{theorem}
\begin{proof}
Compose the principal physical equivalence with the written AX11H consistency equivalence. Equivalently, use the changed exact physical clock in the displayed witness construction and retain the reverse annotation argument. Both routes use the same literal machine table and the same arithmetized PA-refutation predicate.
\end{proof}

The new work does not independently rebuild the complete transitive Foundation proof compiler or complete the Lean/Rocq formalization. The mathematical calibration dependency is explicit and its ten supplied source fragments are included for inspection. The new checked contributions are the literal transformed tables, exact source bindings, complete startups, universal local replays, and the allocation transfer above.

\section{The attempt to obtain 193 states}
\subsection{A runtime core that does not initialize correctly}

An existing 193-state core identifies native control $301$ with $88$, redirects incoming references accordingly, and uses
\[
       (88,0)\mapsto(0,L,51),\qquad
       (51,0)\mapsto(0,R,122).
\]
It can simulate the prescribed runtime frames but its unchanged blank initialization fails~\cite{runtime193}. Therefore the number 193 on that table is not a solution to the present problem. The tape must reach a complete calibrated source frame from blank; a runtime equivalence theorem alone is insufficient.

The prior package supplies 327 outside-box proposed neutral rewrites after removing nine erroneous boundary-only candidates, plus 19 speculative arithmetic-box rewrites. The latter are only search proposals: their semantics require separate validation. This release tests every pair affecting distinct rows in the combined 346-edit pool, with each of the 193 working controls as the initial state. It repeats the test for both append-bit conventions at native row $(198,0)$.

\subsection{New exhaustive finite screen}

There are 58,485 eligible pairs. Each append convention therefore gives 11,287,605 runs. A run is allowed 200,000 transitions and absolute head displacement below 20,000. Acceptance checks the entire finite tape support against a source frame at any site 25 through 44, allows arbitrary values in all nine registers, any translation, padding at least 48, and any finite nonempty spare tail. This deliberately permissive physical target is stronger than searching only the clean seed; a hit would still need logical seed and runtime proofs.

\input{search_results.tex}

No frame was found. The screen covers 22,575,210 starts and 4,167,291,032 literal transitions. The outward-ray classification has a finite certificate: once outside the support, a closed zero-reading control cycle moves monotonically away, so it cannot return. A run stopped by fuel or head bounds is left unresolved. In particular, the 20,202 bounded outcomes are not certified divergent, and the result is not a lower bound on possible 193-state machines.

The complete finite pool, the two runtime tables, source-frame templates, C++ screen and receipts are supplied. The numerical result is reproducible offline with a C++17 compiler. \subsection{Other investigated reductions}

Fresh local contraction searches on the primary PA194 table and on AX11HC4 use sound finite-window overapproximations and compare finite old/new macro endpoints. At radius six, the closure contains respectively 267,827 and 267,311 abstract windows. In each machine, all $\binom{194}{2}=18,721$ pairs are examined, including pairs involving the initial control. For each read symbol the search enumerates all 776 retained-state actions, allows at most 32 old and 32 new transitions, and requires identical tape, head and renamed control at a positive-length match. A new detour cannot revisit the retained control before matching, so its validity does not depend on the other proposed read action. There are 264 and 263 successful one-branch proposals, respectively, but no compatible two-branch contraction. The complete code, method and logs are included.

The finite-window closure admits either value of every newly exposed exterior bit. It therefore overapproximates all actual blank-run windows, including some that are not concretely reachable. This makes a successful local witness sound but may hide a valid optimization. The bounded detour, unchanged tape representation and one-pair contraction requirements also restrict the search. Earlier neutral-row and layout explorations are described in the method note; interrupted exploratory scans are not presented as completed certificates.

There is no evidence here that all possible local changes, alternative tape encodings, proof calculi or initializers have been exhausted. The successful same-size allocations also show why register reordering requires a full bootstrap check: the C32 allocation works for the primary source but the identical allocation on AX11H fails the tested initializer. The accepted AX11H four-cycle was checked separately.

\section{A new source experiment and the requested cross-connections}
\subsection{A parameterized generalizer}

A further experiment changes the recurring AX command by parsing an extra operand $a$ and first changing $d$ to $d+a$. Write the old command as $\mathsf{AX}_{c,x,y}$. The proposed command has the semantic identity
\[
 \mathsf{AX}'_{c,a,x,y}(t,w,d,h)
       =\mathsf{AX}_{c,x,y}(t,w,d+a,h).
\]
Choosing $a=0$ reproduces every old command exactly. For arbitrary $a$, the generalization binder remains an admissible natural parameter; the old dominated-parameter argument continues with the new offset. The source proof therefore provides a conservative command extension, with an explicit zero-field embedding for completeness.

At the macro level, the prefix
\[
 (\texttt{copyH},\texttt{copyD},\texttt{cons},\texttt{inc},\texttt{inc})
\]
is replaced by
\[
 (\texttt{copyH},\texttt{node75},\texttt{inc},\texttt{inc}),
\]
reusing the existing operand-reader/add-and-cons macro. The axiom word decreases from 190 to 189 macro tokens. However, the checked grammar requires 69 readers and seven folds, so its actual cost is
\[
             134+69-7=196.
\]
All 4,799 symbolic outcomes of its 3,687-site source pass, and its blank startup is checked at 58,154 steps. It is included as a new research direction and a concrete example of why a shorter source word need not give fewer physical states. It is not a sub-194 result or an accepted 194-state fallback.

\subsection{ZFC machinery}

The ZFC program supplies relevant ideas in command-local field parsing, history-sensitive folds, helper reuse and register allocation~\cite{zfc}. Several are already present in the PA frontier. Their use must preserve the full source graph and initialization, and compatible folds must be checked simultaneously. The new allocations use this general physical methodology; the new generalizer experiment tests command-local operand reuse. A ZFC-calibrated enumerator cannot simply replace a PA-calibrated one without changing the consistency target.

\subsection{Diophantine consistency}

The Diophantine project distinguishes equation size, arithmetic-circuit size, coefficient coding and weak-arithmetic verification~\cite{dioph}. That distinction is directly useful here. A compact equation or a short encoded coefficient does not imply a small binary TM until the constant loader, arithmetic interpreter and enumeration are compiled and counted. Its model-uniform arithmetic and proof-certificate methodology is relevant to the iPRA proof boundary. No smaller fully priced Diophantine-based PA machine is supplied by the present work.

\subsection{Concise iPRA}

The concise-iPRA project unifies logical rules and binder/term syntax and measures complete proof-checker size~\cite{concise}. Such unification may help a new source calculus or interpreter, but the metatheory and the theory being searched must remain distinct. Replacing PA-refutation search by iPRA-refutation search would change the target consistency statement. The remaining opportunity is a small interpreter for an explicitly PA-calibrated presentation, priced with its loader and all syntax operations. The new 189-token experiment illustrates the need to measure physical compiler output rather than text length alone.

\section{Reproduction, attribution, and further questions}

The package root README gives exact commands. The accepted construction is self-contained for the main table, source-graph and startup checks. Python 3.10 or later suffices for the primary replay; Node.js runs the separately implemented symbolic check; C++17 is needed only for the optional 193-state search. Run Python with assertions enabled. The PDF rebuild uses ordinary pdfLaTeX and the packages listed in this source. Check \file{SHA256SUMS} before regenerating evidence.

The new physical construction is credited as an allocation of supplied machinery. The imported unary runtime, original programs, proof fragments and licenses retain their original provenance. Source manifests identify exact Git blobs and the pinned repository snapshot. Current reports are indexed by mechanism and concrete table identity so that renamed, copied, auxiliary and rejected designs remain distinguishable.

The most useful next questions are concrete:
\begin{enumerate}
\item Can the 193-state runtime merge be paired with a different initializer, tape phase or multi-row change whose complete source-frame proof survives? The new pair screen narrows one supplied finite family, not this general question.
\item Can the 189-token command extension be represented with fewer distinct reader subtrees or with additional compatible folds? Its current obstacle is the compiled 69-reader allocation, despite shorter source text.
\item Can the register-permutation transfer be formalized once, parametrically in $\pi$, leaving each future allocation only finite row checks and a closed startup theorem? This would reuse the common arithmetic engine and reduce repeated proof work.
\item Can the revised written AX11H weak-base compiler and its literal physical clocks be joined to the ongoing Lean development without enlarging the trusted assumptions? This is separate from obtaining another small transition table.
\end{enumerate}
