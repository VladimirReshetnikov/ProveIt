# Internal converse for PA196: proof obligation and construction

Inspected source: jamesyc/BusyBeaver commit 407cdc356f6b586635e71ac92be394255f4bfea4.
The exact formally exported theorem is `PA196.Arithmetic.pa_proves_nonhalting_consistency`, i.e. PA proves N_196 -> Con(PA). Neither README nor docs/result.md asserts PA proves the converse. `PA196/Logic/Soundness.lean` explicitly describes its soundness as external, with HF-list semantics in Lean. A reduction must not silently relabel this as a completed Lean proof of an internal biconditional.

A standard syntactic proof of the missing direction can be made, without uniform truth or reflection, as follows.

1. Translate numeric formula codes to ordinary PA formulas. Interpret M(a,b) as bit(x_a,x_b)=1, meaning the x_b-th bit of x_a is 1; interpret E(a,b) as x_a=x_b, U(a,B) as forall x_a B*, I as implication, code 0 as truth. The interpretation of code 1=M(0,0) is false in PA because a set bit at position n implies 2^n <= n, impossible for natural n. Numeric constructor degeneracy I(0,0)=0 causes no issue: provide an explicit fixed PA derivation of truth iff (truth -> truth).

2. Every fixed calculus axiom instance has an effectively constructed PA proof. Quantifier laws, equality congruences and equality witnesses use ordinary logical proof templates. The restricted propositional head is a tautology even without its numeric restriction. Freshness c not in names(decode(c)) follows from strict descent of components in the Cantor coding.

3. For the gate, the only nonlogical work is pointed finite separation. Given an arbitrary translated formula phi(x,parameters), PA proves
  exists s forall x [bit(s,x) <-> ((bit(a,x) or x=b) and phi(x))].
Use full induction on m to prove existence of a binary code for the selected part below m. The induction formula may contain phi and has no boundedness restriction. Choose m greater than a and b. The proof of this instance is generated by substituting phi into a fixed induction-proof template. Its correctness is a claim about proof codes and is proved by syntactic induction in PA; it is not a uniform truth predicate. This is precisely why consistency of iPRA cannot simply substitute for consistency of PA in this construction.

4. Translate each finite derivation in the PA196 numeric calculus into a PA proof. This is primitive recursive on derivation codes. PA proves: Derivation196(d,1) -> Proof_PA(translate(d), contradiction). Modus ponens and generalization map to ordinary proof constructors. Proof generation for the gate uses the syntax-dependent induction instance in step 3. The theorem concerns derivation and proof predicates, not truth of arbitrary formulas.

5. Extract a finite derivation of code 1 from any halting command/source trace, maintaining proof witnesses for the sound store. Commands preserve this witness invariant. The Shift halt test can succeed only when the top's witness is a derivation of code 1. This is a syntactic version of the external store-invariant argument in PA196/Logic/CommandSoundness.lean.

6. Extract a source halt from a literal machine halt. The existing source-to-machine simulation plus determinism and positivity suffices: start after the verified startup; if t literal transitions reach halt and the source has not halted within t source instructions, composing the positive instruction simulations gives a nonhalting literal prefix longer than t, contradiction. This bounded induction is formalizable in PA. A machine halt before the fixed startup endpoint is ruled out by its finite trace certificate.

Steps 4-6 give PA |- H_196 -> Prov_PA(contradiction). Together with the published internal refutation-to-halting direction, PA |- H_196 iff not Con(PA), equivalently N_196 iff Con(PA). This supplies a mathematical construction of the internal converse, but a concrete implementation of the PA proof translator or a Lean theorem for the converse has not been produced during this audit.

Membership orientation matters: repository HF.mem a b means b is a child of a, so M(a,b) is x_b in x_a, not x_a in x_b.
