# Independent literal-tape verification

This checker verifies the supplied 194-state transition tables directly. It imports neither the construction compiler nor its symbolic arithmetic-box oracle. Python's standard library is sufficient. Assertions must remain enabled: do not use `-O` or `PYTHONOPTIMIZE`.

From the package root, verify the primary machine with:

```sh
python3 -B verification/independent/check.py --family PA194 --output /tmp/pa194-independent
```

Omitting `--family` checks both the primary `PA194` and the companion `PA194_AD`. A fresh temporary output directory is used if `--output` is omitted. The companion can also be checked on its own by passing `--family PA194_AD`. Family identifiers are case sensitive; the transition-table filenames themselves are lowercase.

## Exactly what is checked

1. Each literal machine has 194 working controls, 388 rows, binary alphabet, only left/right moves, one terminal halt label, and an exact native/dense state bijection. The dense presentation starts at 0 and halts at 194; native start/halt are 74/254. The native clean-frame control 84 is dense control 24.
2. Two independent source control-flow resolvers agree, and their entire opcode/register/successor sequence equals the frozen source instructions from the supplied 195S archive. Both machines retain exactly the same 3,673-site separate-head program.
3. Four generic unary-list sweep lemmas are reconstructed from the new table's actual rows. The proof checks a symbolic arbitrary one-block case in arbitrary surrounding contexts and obtains the finite-list case by concatenation. No engine contract is merely assumed by state name.
4. Every one of the 4,780 primitive source outcomes executes to its exact expected full-tape frame, or to the halt control. Nine independent natural register values, both decrement outcomes, and an arbitrary finite nonempty spare list are represented symbolically. The header distance is **48 + n**, for arbitrary natural `n`; after source path `p`, the zero run has length **48 + n - |p|**. All source paths have length at most 48. Each physical duration is affine with nonnegative coefficients and strictly positive constant. All physical tape operations are literal transitions, self-loop induction, proved list traversals, or exact word identities.
5. A separate bytearray simulator executes the entire blank initialization and checks every cell against the expected frame. The source seed is site 25, native control 84, head -2, logical registers `[2,0,0,0,0,0,0,0,0]`, 26 one-valued spares, and header distance 48. For the A/D companion, logical A and D occupy physical blocks 3 and 4 instead of 4 and 3. Both initially contain zero, so the physical seed vector is unchanged. Primary startup takes 58,154 physical steps; companion startup takes 58,122.
6. The table's canonical control graph is compared with every recognized table of the same size in the pinned corpus. There are no previous 194-state tables in that recognized corpus. All 14 byte forms of its nine existing 195-state classes are also bound by SHA-256 and checked. Canonicalization minimizes a read-0-before-read-1 graph traversal over every possible control from which all working controls are reachable, preserving read bits, write bits, directions, and halt. Every working control reaches the complete graph, and all 194 controls are distinguished by ordinary action bisimulation. These are graph checks, not a minimality theorem.

To reproduce the additional comparison between the primary and companion:

```sh
python3 -B verification/independent/compare_pair.py --output /tmp/pa194-pair.json
```

Their root-free canonical graph serializations differ, so an arbitrary finite-control relabeling or start-control choice does not identify them. A global left/right reflection is also excluded: it reverses the overall counts of left and right transitions, which differ. The designated blank symbol 0 is fixed, so swapping alphabet symbols is not a blank-preserving alphabet isomorphism.

Imported verifier files, provenance, and licenses are under `reference/`.

## Evidence boundary

These executable finite and symbolic certificates support the mathematical positive-simulation argument in the report. They do not themselves constitute a newly exported Lean or Rocq theorem, a PA proof-code compiler, or a proof that any finite blank-run prefix continues forever. The logical consistency calibration is a separate mathematical argument inherited from the supplied source program and preserved by the verified simulations. In particular, the two successful startup traces are initialization checks, not evidence sufficient on their own for non-halting.
