INDEPENDENT REVIEW OF MEMBERSHIP/EQUALITY TRANSPOSITION SEARCH

Run with Python 3.10 or later:

    python3 verify_membership_score.py

This portable review needs no repository checkout, network, C++ compiler,
or third-party Python package. Its reference/ directory contains the minimal
attributed supplied layout implementation and the original source inputs.

CONSTRUCTOR MODES

Mode 0: original equality and membership orientations.
Mode 1: transpose the two equality arguments.
Mode 2: transpose the two membership arguments.
Mode 3: transpose both equality and membership arguments.

Bit zero controls equality (constructor tag 3); bit one controls membership
(constructor tag 1). Implication, quantifier coding, arithmetic primitives,
and the original emitter prefix are unchanged. The C++ witness field named
flip holds this two-bit mode number; the audit calls it mode.

INDEPENDENT INPUT CHECKS

The original symbols, prefix and suffix are checked byte-for-data against
the supplied configuration. Modes 0 and 1 retain its exact head families,
and their eight gate words agree with the preceding gate-spelling study.

The checker implements a separate free-constructor stack interpreter. It
decodes every emitted head/gate macro word into a tagged AST, including the
constant and constructor-tag increments, and checks that exactly the stated
arguments are transposed. All 248 mode/option comparisons are exact syntax
identities. They are not selected numeric samples. The retained source-word
generator file is also bound by its SHA-256. This checks transcription and
constructor orientation; it does not construct an internal PA proof-code
translation between the different encoding conventions.

WITNESS CHECKS

For the baseline and every saved witness, the checker verifies distinct,
reachable, topologically ordered productions and the exact selected
201-token macro word. It independently expands primitive source paths,
reconstructs the physical reader table with the Python layout builder,
compares fast and exhaustive helper-edge enumeration, and recomputes the
maximum matching and discovery score. The baseline source CFG is checked
against the published program. Other witnesses' branch counts are counted
from their primitive expansions; no physical instruction proof is run.

The baseline is 68 reader nodes minus six matched pairs, giving score 62
and nominal total 196 after adding the fixed 134-state term. AX subtree
height and complete-program path length are reported separately. Witnesses
outside the imposed six-zero/AX-height filter receive penalty scores and
have null nominal state counts in the audit.

MODEL AND REPORTING LIMITS

Disjoint matched pairs can still interfere through shared helper roles or
changed incoming contexts. A syntactic matching score is therefore not a
proof that simultaneous physical folds work. No new arbitrary-register
contracts, blank initialization, or PA consistency endpoint are established
by this review.

The delivered C++ run records seeding scores and every restart assignment
and repair score, and uses all 32 mode/gate pools. Replaying the same fixed
iteration budget and random seed preserves all 32 final grammar witnesses
byte for byte. replay_stability.json records the independent comparison;
search_summary.json contains the corrected counters. The actual C++ header
is parsed independently and all nine arrays/scalars are compared to the
JSON configuration. The delivered witnesses come from that audited replay.

Final saved invalid seeds can still differ from raw observed penalty minima
because invalid main-loop proposals are excluded from the eligible witness
pools. Such diagnostic minima are not physical machine state counts.
