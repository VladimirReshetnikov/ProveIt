\section{Problem, conventions, and reproducibility}

The requested target is an explicit deterministic, single-tape, two-symbol
Turing machine with fewer than 196 working states such that
\[
   \PA\vdash\Nonhalt(M)\longleftrightarrow\Con(\PA).
\]
The tape is two-way infinite and initially zero everywhere. A transition
reads one symbol, writes one symbol, moves one cell left or right, and enters
the indicated control. The separate halting label is not a working state.
For a table with $n$ working states there must be precisely $2n$ rows.
Changing the alphabet, supplying a prewritten tape, or counting a grammar
nonterminal as if it were a physical control would change the problem.

All comparisons refer to the immutable ProveIt commit \pin~\cite{repo,incoming}. The PA subtree
is \file{dc4d1ed9027c2b251ee751679d2690c6b1265b03}, and the incoming subtree
is \file{19b0b7e26f84a3ebac927e8768c7a21067d03a06}. The archive manifest
records the exact Git blob identities and SHA-256 hashes. This pins a finite
collection; later changes to the repository are outside the audit.

The most useful separation is between four proof obligations:
\begin{enumerate}
\item The numerical calculus must be calibrated to ordinary PA, in both
  refutation directions when an internal biconditional is claimed.
\item The register program must implement a complete search of that calculus.
\item The literal transition table must simulate every relevant register
  instruction for arbitrary register values and arbitrary admissible tape gap.
\item The same table, started on a blank tape, must reach the specified
  invariant and source configuration.
\end{enumerate}
Each obligation is necessary. A long nonhalting test of one blank run does
not prove the third; the third does not prove the fourth. A correct local
fold of an incorrectly patched parent does not establish the first two.

The package contains readable five-column transition tables, portable
Python checkers, C++ search sources where relevant, machine-readable
receipts, the archive census, this \LaTeX{} source and the compiled PDF.
The small verification entry points are described in \file{README.md}.
No fresh complete Lean build of the upstream project is claimed. The report
distinguishes inherited formal results, ordinary mathematical arguments,
fresh finite certificates, and experimental constructions.

\subsection{Why PA196 improves on PA209}

Let $p(a,b)=(a+b)(a+b+1)/2+b$. PA196 uses
\[
 I(a,b)=4p(a,b),\quad M(a,b)=4p(a,b)+1,\quad
 U(a,B)=4p(B,a)+2,\quad E(a,b)=4p(a,b)+3.
\]
Code 0 is truth and code 1 is the designated contradiction. The universal
constructor reverses the pair components. The revised axiom emitter removes
the old seventh equality head, places guarded equality vacuity in the gate,
and changes head and antecedent order. Its 201 macro-token AX word has 68
binary grammar nodes. Six contextual reader folds reduce its physical body
reader count to 62. Those six savings are already included in 196.

The complete source has 3,812 sites, compared with PA209's 3,948. The
construction retains the command-search architecture and changes the
emitter and its representation. The logical change is substantive:
dropping an axiom without supplying its required consequences would
invalidate the PA refutation compiler, even if every tape instruction
continued to work.

The original U208 fold identifies its native controls 172 and 211. Its
four exceptional local simulations have lengths 7, 1, 3, and 1, yielding
\[
 T_{208}=T_{209}+6N(172,0)+2N(211,0)
\]
at aligned execution boundaries. The exact mixed-entry motif has no direct
renaming into PA196: PA196 has no control whose two actions are
$0Lq$ and $1Rq$ to the same working target. This rejects that direct motif,
not every history-based reduction of PA196.

\section{New zero-register jump specializations}
\label{sec:jumps}

\subsection{The inductive source invariant}

Represent a register file by a nine-bit mask, whose bit $r$ is set exactly
when register $r$ is positive. An increment sets its bit. At a zero
decrement, the zero successor is taken without changing the mask. At a
positive decrement, the positive successor is taken and its bit may remain
set or become zero. A jump preserves the mask. These rules overapproximate
the ordinary natural-number source execution.

Start the finite analysis at site 25 with mask 1, corresponding to
$(2,0,0,0,0,0,0,0,0)$. Closing under the abstract transitions gives
274,880 site/mask pairs and 3,810 reachable sites. The two absent sites
are 3774 and 3775. The checker explicitly verifies initial inclusion and
closure after fixed-point discovery. Thus ordinary induction proves that
every concrete source execution from the seed remains in the invariant.
This is a finite inductive certificate, not a sampled run.

At fourteen unconditional forward-jump sites, at least one register is
forced to zero. There are 43 individual choices of a register proved zero
at such a site. Replacing the forward jump by the source decrement with
the same zero successor preserves source execution at that boundary.
Some isolated substitutions increase source DAG size; their counts are
recorded as source counts rather than physical-state claims.

Only three whole physical reader rows can be changed uniformly using the
common zero information in their represented occurrences:
\begin{center}\small
\begin{tabular}{@{}lll@{}}
\toprule
Native row & Source sites & Common zero registers\\
\midrule
$(27,1)$ & 26 & $3,6,7$\\
$(103,1)$ & $3,9,3665,3671,3683,3689,3766,3772$ & $3,6$\\
$(1365,1)$ & 3692 & $3,4,5,6,7$\\
\bottomrule
\end{tabular}
\end{center}
The distinction between an individual source occurrence and every context
represented by one physical row is essential. A safe substitution at one
source site does not authorize a global change to a row used elsewhere.

\begin{proposition}[Zero-jump specialization]
Suppose the checked mask invariant forces register $r$ to zero at a
source jump site $i$. Suppose the replacement decrement has the old jump
destination as its zero successor. Replacing any collection of such sites
does not change the sequence of source configurations reachable from the
clean seed, apart from the names of the executed instructions.
\end{proposition}
\begin{proof}
Use induction on source steps. At an unchanged site the step is identical.
At a changed site the invariant gives $R_r=0$, so the replacement takes
its zero branch, leaves the whole register file unchanged, and reaches
the old jump destination. The new and old configurations therefore agree,
and membership in the original invariant is preserved. All ingredients
are finite syntax and elementary arithmetic, so the same argument can be
arithmetized in PA.
\end{proof}

\subsection{A complete same-size machine}

Changing only native row $(27,1)$ of PA196 to
\[
             (1,R,21)
\]
implements the zero-decrement of logical register 6 at source site 26.
In dense labels this is also $(27,1)\mapsto(1,R,21)$ for the pinned
conjugacy. The source invariant forces that register to zero there.
All 4,959 uniform instruction contracts pass when the changed site uses
its certified zero precondition. The delivered table has SHA-256
\begin{quote}\small
\nolinkurl{2c1a736399e0f32304ed18d6a439dc8d4fdd82f2ad103cdfc6851c0f4ae1e4af}.
\end{quote}
Its rooted graph is distinct from all eighteen designated 196-state
tables in the comparison catalogue. The unchanged arithmetic-engine rows
continue to justify the register-box summaries. An exact literal blank
simulation reaches the clean seed after 58,402 transitions.

Consequently this is a concrete new 196-state implementation of the same
source search. Combining the mathematical source equivalence with the
usual PA196 calibration transfers the intended consistency property at
the ordinary proof level. This report does not identify a new exported
Lean biconditional for this table.

\subsection{Synthesis at the actual entry context}

For each of the three rows, the search tries every write bit, both move
directions, and every existing control or halt target. Each trial is
checked against complete symbolic source contracts for the affected
occurrences, with only the proved zero conditions added. It yields twelve
valid actions for native $(27,1)$, six for $(103,1)$, and thirteen for
$(1365,1)$. The twelve source-26 actions also have exact clean-seed
startups, ranging from 58,114 to 58,474 steps.

One-row validity does not imply joint validity: a replacement action may
route through another row that a second replacement changes. Therefore
the Cartesian product of the three action families is checked again at
the whole-instruction level before attempting a fold. The final search
receipt supplies the exact number of interacting combinations rejected
and retained; no combination is called valid merely because its components
were individually valid.

A separate, broader fold screen was run on the complete source-26 CD6
parent: all 38,220 ordered drop/keep pairs with two arbitrary retained
rows, using five-cell windows and at most sixteen child steps per parent
step. The global window abstraction gave no survivor. Intersecting it

and exactly the same 2,221-window file. Residual correlations between uncertain registers are still overapproximated.
The equality of the resulting window files was checked by SHA-256, so another

\subsection{An exact rejection of a tempting 195-state table}

A preliminary patch sent native $(27,1)$ to $(1,R,62)$, on the assumption
that control 62 was a context-independent decrement-7 entry. In that
patched parent, native 27 and 46 can be merged while changing the retained
zero row to $(0,L,81)$. A local history-based check validates this fold
relative to the patched parent. It does not validate the parent itself.

The complete source contract exposes the error. Control 62 is sensitive
to the entry geometry: at source site 26 the proposed row implements the
wrong operation. With path \texttt{100001}, gap 48, all nine registers
zero and one spare of value zero, the original machine reaches the intended
site 34 after 120 steps. Both the patched 196 parent and its 195 child
reach site 27 after 558 steps, with register 6 equal to one and an extra
spare. These are exact comparisons of finite tape configurations.

The included rejected table is therefore labelled as rejected, and its
counterexample is independently replayable. In a focused repair attempt,
48 non-engine rows on the failing trace were allowed one arbitrary changed
action. Of 37,584 actions tested, 153 repaired this single source contract,
but none retained all other 4,958 contracts. This is a negative result for
that repair family, not a nonexistence theorem about 195-state machines.
A further targeted interaction changed the retained one-row and one row
of each of five possible left-reading helpers. Of 15,680 alternatives,
113 repaired source 26, and none retained all 4,959 source contracts.

Nor can the wrong operation be silently accepted as a harmless change to
word enumeration. In its altered scheduler, a positive continuation adds
the candidate counter before decoding the next command. If a fresh
candidate $n=p(0,b)$ starts with Shift and $b>0$, the next decoded number
is $n+b=p(2,b-1)$. Its selector is therefore 2, an AX selector, rather than
0, a Shift selector. Thus no such fresh candidate starts with the old
command prefix Shift--Shift. The inherited universal-word prefix lemma
fails already at this short example. This does not rule out a different
compiler for that scheduler, but no such compiler or admissible blank
initializer has been supplied.

\section{Other concrete approaches investigated}

\subsection{Shorter scanner and source-tree geometry}

One supplied exact original-source representation has 159 internal nodes,
maximum path 37, and maximum zero run five. It moves the seed path from
\texttt{100000} to \texttt{10100000}. A smaller marker detector is attractive,
but instruction selection temporarily changes address bits; a static
zero-run bound alone does not prove that the dynamic scanner can be shortened.
Some reader aliases are also lost when paths change.

In the focused scanner experiment included here, folding the extra scanner
control into any retained control failed within the checked five-cell,
16-step and nine-cell, 32-step local simulation families. The broader
family tested 195 retained controls, 869,456 first-row actions and
67,725,840 second-row actions. These numbers describe the implemented
template; they neither bound the smallest TM nor exclude a redesigned
frame convention. Source-DAG savings and a scanner-state saving cannot be
added without validating their combined tape invariant and initializer.

\subsection{A fully integrated base-eight parity runtime}

A parity acceptance test is cheaper to express than an exact test for code
one only if the coding makes every accepted odd formula refutable in PA.
The ordinary base-four tags do not have that property: equality atoms have
odd tag three and can be theorems. A parity test on the old coding is not
a sound optimization.

The integrated prototype in this package instead uses base eight with
tags $I=0$, $M=1$, $U=2$, $E=4$. Its constructor multiplier and all five
equality-tag emissions are changed consistently. The Shift sum stays in
the scratch register used by the parity guard, and the guard is matched
to that revised source. This corrects the mismatch between a changed
guard and an unchanged formula encoder.

The resulting AX word has 206 macro tokens. The integrated source has
4,062 sites. The raw table has 207 working states; five compatible reader
folds give 202. Both tables pass all 5,205 uniform symbolic source
contracts. The folded table digest is
\begin{quote}\small
\nolinkurl{d9a0256666bbd6e5cad616e5b2df7f56b2773b86df75842fd2ba17ccb45a3f76}.
\end{quote}
These are instruction-runtime checks, not a proof of the revised command
arithmetic or logical proof compiler. The included structural audit
confirms that MP reconstructs its implication with the altered multiplier;
a complete command-calibration theorem remains a separate obligation.
This is a verified runtime implementation, not a completed blank-start
consistency machine: no certified sound scheduler seed was obtained from
its blank run. A finite failure to find a seed is not a theorem that no
such seed ever occurs. In any event, 202 is above the requested threshold.

\subsection{What can be borrowed from ZFC and ConciseIPRA}

The ZFC K215 material~\cite{zfc} gives useful implementation methods: command-local
field readers, partial selectors, folds using the preceding tape bit, and
explicit local stuttering simulations. Its independent runtime and startup
obligations are particularly relevant to the source-26 error above.
However, its 215-state table implements a different numerical program and
calculus. An optimization of its decoder is not automatically available
in PA196 merely because native control numbers coincide.

ConciseIPRA~\cite{ipra} separates a concise scalar syntax and a normalized proof
checker from their arithmetical interpretation. That is a useful design
principle for a replacement proof-search architecture. It does not justify
substituting consistency of iPRA for consistency of PA. A smaller checker
would need explicit PA-refutation translation in both directions and a
complete binary tape implementation. No unproved equality of theory
strength is used in this report.

\section{The exact consistency statement and proof levels}
\label{sec:prooflevels}

The imported PA196 endpoint explicitly proves
\[
        \PA\vdash\Nonhalt(M_{196})\longrightarrow\Con(\PA).
\]
It also establishes external nonhalting and independence in the Lean
metatheory. An external soundness theorem does not, solely by its existence,
supply the reverse implication inside PA. Two-sided independence of a
sentence likewise does not determine its equivalence class over PA.

The incoming manuscripts contain more than an unsupported assertion of the
reverse direction. They describe a syntactic interpretation of membership
as binary-bit membership, primitive equality as equality, and the
transposed universal code as the corresponding quantifier. Their finite
comprehension proof uses one PA induction instance formed from the input
formula. They handle the code-zero truth alias and the special case where
the two labels in the guarded gate coincide. These are mathematical
arguments that can be evaluated independently of whether a new Lean
endpoint has been compiled.

The essential proof-producing statement has the form
\[
 \PA\vdash \Prf_C(p,1)\longrightarrow
       \Prf_{\PA}\bigl(F(p),\ulcorner\bot\urcorner\bigr),
\]
where $F$ translates a finite numerical-calculus derivation into a PA
refutation. A proof certificate is carried with each live formula and
each stack entry. AX introduces certified axioms, MP combines certificates,
generalization constructs its proof, and stack underflow returns certified
truth. At the original Shift halt, $t+h=1$, so one certified live formula
has code one.

To pass from an actual tape halt to this certificate, use the exact finite
startup and total positive-length instruction simulations. Determinism
aligns the literal trace with the source run. A halting trace of length
$N$ cannot contain more than $N$ completed source instructions. Internal
engine paths must have their specified total exits and no unexpected halt.
This yields a bounded trace extraction followed by the proof translation.
The argument uses syntactic proof construction, not a uniform PA truth
predicate or an assumed PA reflection principle.

The current repository's \file{reverse-cert-stack/} files add actual
standard-natural-number certificate-stack and native-checker bindings.
They address real parts of the proof, including zero aliases and ordering
of the imported command heads. They do not yet export the all-model
literal-trace bridge and the exact model-valued checker binding needed
for a closed formal internal biconditional. The \file{ipra/} bridge is
also conditional on the machine-specific reductions.

For a literal new table, a mathematically complete claim therefore requires
both the syntactic consistency calibration and the full source/tape/startup
transport. A missing Lean endpoint is a formalization limitation; a failed
tape contract is a mathematical failure of the proposed construction.
The package does not blur these two cases.

\section{Reproduction, provenance, and limits}

The archive preserves attribution to James Chang and to the ProveIt and
incoming research sources. The original tables and proof files are inputs,
not new results of this investigation. New scripts and receipts are
identified separately. SHA-256 checks protect the exact transition tables,
source program and archive members; the final package manifest records
the files delivered here.

The default verification commands check the curated graph comparison,
the zero-register source invariant, the chosen complete 196-state jump
variant, its exact startup, the finite rejection witness, and the base-eight
runtime integration. Larger finite search replays are separate because
their running times and compiler availability differ. Search receipts
record their actual scope, parameters and result counts.

The inventory does not execute arbitrary submitted archive code. It parses
files and validates table structure and graph identities. The new source
and runtime checks use the explicitly packaged code and pinned inputs.
No negative result in this report is asserted to exhaust all binary
Turing machines, all state encodings, all source transformations, or all
possible mathematical consistency encodings.
