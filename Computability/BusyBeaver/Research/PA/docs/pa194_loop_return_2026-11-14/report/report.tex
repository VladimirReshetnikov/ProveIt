\begin{abstract}
No verified blank-start machine with fewer than 194 working states was
obtained. The fallback construction supplies two new 194-state machines,
PA194LCG and PA194LCGS. They combine the current eleven-entry axiom
interface and explicit-generalization controller with a reassociated
constructor loop and three exact physical shortcuts. One shortcut,
$190/1\mapsto0L42$ in native numbering, is new to this construction and is
proved from a one-predecessor tape invariant. The machines preserve the
complete resolved source graphs of the specified AX11GH/GHS parents.
Independent literal-tape checks establish all 4,778 and 4,774 parametric
source outcomes, and the complete blank initializations are verified.

A written iPRA proof gives explicit polynomial witness transformations
between each new table and its parent. Composing this relative theorem
with the identified, audited inherited written PA calibration gives the
Con(PA) equivalence. The full arithmetic compiler remains an inherited
mathematical dependency; no new end-to-end Lean or Rocq kernel proof is
claimed. The comparison covers 93 delivered research packets and identifies
74 distinct named 194-state constructions in 26 mechanism families.
The archive includes exact transition tables, deterministic builders,
independent checkers, finite receipts, comparison data, failed-search
artifacts, and this report's complete LaTeX source.
\end{abstract}

\subsection{What is proved here, and what is inherited}
Three levels should be kept distinct.
\begin{enumerate}
\item The new local shortcut and the relative halting/nonhalting theorems
are proved here, with all finite table premises and complete source-frame
bindings checked. These proofs use primitive recursion, finite case
analysis and quantifier-free induction.
\item The absolute PA calibration is the later AX11H/QAX11H written
mathematical theorem, together with the current GH/GHS command-protocol
proof. The exact proof sources and audit receipts are included. Their
weak-induction method, current Foundation adapter, command identities and
composition interfaces were examined; no specific defect was found in
those examined arguments.
\item The repository's end-to-end Lean development remains incomplete.
Executable certificates and a written proof do not imply that a Lean kernel
has checked the full consistency equivalence. This report supplies no such
new kernel theorem and does not independently reconstruct every inherited
arithmetic proof compiler.
\end{enumerate}
Accordingly, the absolute result is stated as a corollary importing an
identified written theorem, not as a claim that the finite runtime checker
proves PA calibration by itself.

\section{Machine conventions and complete specification}
Each machine is deterministic, has one head on one two-way infinite tape,
and uses alphabet $\{0,1\}$ with blank symbol zero. Initially all tape cells
are zero and the head is at coordinate zero. Every transition moves one
cell left or right. There is no stay-put move and no external initializer.

The delivered dense tables use working states $0,\ldots,193$, start state
0, and terminal label 194, excluded from the count. A row
\[
\texttt{q\ b\ w\ D\ n}
\]
means: in control $q$ reading $b$, write $w$, move in direction $D$, and
enter $n$. Native tables retain the inherited control names: start 74,
frame dispatcher 84, and halt 254. The label arrays give exact bijections
between native and dense numbering. Native control 194 is an ordinary
working control; the numerical coincidence with the dense halt label
must not be confused.

\subsection{Architectural differences that matter}
The variations fall into several real design choices, rather than one
uniform sequence of cosmetic improvements.
\begin{itemize}
\item \textbf{Formula constructors and axioms.} Coefficients four, five
and six change hereditary formula coding. Q exchanges curried premises
of universal distribution. Diagonal variants alter which operand supplies
the fresh diagonal label. These require proof transport, not just a table
isomorphism.
\item \textbf{Store and halt protocol.} Cached MP, visible no-push MP,
cache-only Shift, and sum-guard Shift differ on actual stores. A contradiction
in the visible top is not necessarily detected by one cache-only Shift.
The all-store refutation compiler must use the appropriate Pop word and
must account for the reserved zero below MP premises.
\item \textbf{Axiom interface.} AX11 pushes eleven entries and falls
through the complete MP operand reader. It has four operands. Treating it
as the older three-operand command changes the decoded continuation and
invalidates the compiler.
\item \textbf{Physical implementation.} Register permutations, history
folds, loop reassociation and exact tape shortcuts can preserve the source
program while changing recurring execution. Their proof obligations are
complete frame preservation, positive clocks and exact blank startup.
\end{itemize}

The six latest incoming archives contain repeated AX11GH/GHS presentations,
their two faster F variants, five loop-continuation alternatives, the
history-selector design SEL, and the AX11HR register-placement variant.
These were included before claiming the two present tables new.
Appendix~\ref{app:named} lists all 74 named designs; the full descriptions,
aliases, exact starts and packet-specific proof status are in
\file{comparison/named_194_designs.csv}. The family comparison is below.

\subsection{Reassociate the repeated constructor loop}
Let $i$ be increment of logical register 1. The original source subtree is
\[
\bigl(((i,i),(i,i)),\operatorname{continueTo}(2)\bigr).
\]
Replace it by
\[
\bigl((i,i),((i,i),\operatorname{continueTo}(3))\bigr).
\]
The continuation depth changes because the binary syntax path changes.
It still returns to the same resolved loop head. This transformation was
introduced in the incoming loop-continuation packet; its use here is
credited as an ingredient, not claimed as a newly invented reassociation.

The builder independently resolves every source successor before and after
the substitution. The instruction arrays agree exactly, including every
opcode, register operand, branch target and halt site. The 61 occurrences
change five addresses each, totaling 305. Native state 190 ceases to be
the four-increment macro alias and becomes part of the continuation reader.
The existing contextual folds remain valid in the changed raw table.

\subsection{Apply the three tape shortcuts}
After reassociation, apply the two incoming F shortcuts and the new
continuation shortcut proved in Section~\ref{sec:shortcut}. There are
exactly five changed native rows relative to each GH/GHS parent:
\begin{center}
\begin{tabular}{rrll}
\toprule
Control & Read & Parent action & Delivered action\\
\midrule
26 & 1 & $1R42$ & $1R91$\\
101 & 0 & $0L26$ & $0R17$\\
139 & 0 & $0R190$ & $0R99$\\
139 & 1 & $0L16$ & $1R190$\\
190 & 1 & $1R99$ & $0L42$\\
\bottomrule

The last row combines the reassociation's intermediate action $1L73$
with the new three-to-one identity. All other rows of the parent table
are retained. The compiler's pure source representation is preserved
separately from these physical accelerations.

The resulting loop executes four more physical transitions per complete
constructor iteration than the corresponding GH/GHS loop, whereas the
unaccelerated reassociation costs six more. The new shortcut removes the
two-step difference. The independent duration vectors verify this at all
61 occurrences for arbitrary symbolic registers and spare files. The
machines are therefore alternatives at the same state count, not a claim
of uniformly faster execution than their original parents. Other source
outcomes become shorter through the retained F shortcuts.

\label{sec:calibration}

\file{pa194_ax11h_research_2026-11-14_2}, not an earlier conditional AX11H
report with a similar name \cite{ax11h,incoming}. Its exact target is the repository's current

\file{nativePARefutation}, at the documented Foundation revision
\nolinkurl{32e1a0956a8622fad067328ca1959729a7634428}.
The Foundation false-formula code 13 and numerical-calculus false code 1

\subsection{The mathematical interfaces examined}
The audit compared ten inherited proof files in the GH/GHS packet with the
current revised AX11H files; all were byte-identical. It also checked 490
source-manifest entries, covering 441 distinct paths, against the pinned
Git blobs and actual cached source bytes. These are source-identity checks,
not claims that hashing a proof establishes its theorem.

The forward proof replaces induction over all environments by finite trees
of the requests actually used. Each same-stratum child has smaller rank;
its parameters are computed before its proof output is returned. A bounded
forward construction of requests and reverse evaluation of proof outputs
have Boolean table invariants suitable for weak induction. Calls on larger
substituted terms are made into already completed lower strata. The
Foundation adapter separately accounts for finite axioms, opening and
closing, substitution, and canonical induction matrices. This is a
substantive written completion, not merely a claim that a full-PA induction
can be reused unchanged in iPRA.

The GH/GHS command interface then aligns with the exchanged-distribution
calculus $\mathcal C_4^Q$. Its explicit generalization head is $U(c,h)$,
using the incoming cache, not $U(c,h+y)$. Let
$A=\mathsf{AX}(0,0,0,0)$ and $S=\mathsf{Shift}$. The audited words include
\[
\mathsf{Push}=A;S^{10};\mathsf{MP}(0),\qquad
\mathsf{Pop}=A;S^{12},
\]
\[
\mathsf{Gen}_i=\mathsf{Push};S;\mathsf{AX}(i,0,0,0);S^{11}.
\]
The Pop word detects a contradictory saved top; generalization also handles
a contradictory premise without falsely assuming it never occurs. The
MP compiler reserves a zero below its two premises. The fourth AX operand
is explicitly included in the word encoding. Fresh independent source
checks matched all 190 AX tokens, 947/945 arithmetic-template blocks, and
all 3,671/3,668 primitive instruction rows and outgoing edges.

The final transfer uses the identified model-uniform refutation/run
implications and the repository's one-way conservation and negative-
translation endpoints. It does not extract an unbounded positive
existential from double negation. The detailed scope review and finite
source-binding receipts are in \file{verification/calibration_audit/}.
No concrete defect was found in the examined interfaces or weak-induction
arguments. The review sampled cited Lean recipes and did not reconstruct
or kernel-check every inherited compiler proof.

\begin{corollary}[Inherited absolute corollary]
Adopt the revised AX11H/QAX11H written PA calibration and the specified
GH/GHS source-protocol equivalences described above. For each of the two
literal tables $N$ delivered here,
\[
\ipra\vdash\Con(\PA)\ \longleftrightarrow\
              \neg\operatorname{Halt}_{\mathrm{blank}}(N).
\]
\end{corollary}
\begin{proof}
The inherited argument gives the displayed equivalence for the appropriate
GH/GHS parent. Section~\ref{sec:relative} supplies, inside iPRA, the parent's
halting and nonhalting equivalence with $N$. Compose the negative equivalence
with the inherited calibration using intuitionistic propositional logic.
\end{proof}

The corollary states exactly where the complete PA calibration is used.
The new relative theorem remains valid independently of that dependency.
The continuing incompleteness of the Lean development is therefore fully
compatible with presenting this written mathematical corollary, while it
would be incorrect to describe it as a new completed Lean verification.

\section{Transfer from the other requested research programs}
The ZFC program contributes a useful implementation methodology: make a
command's live inputs explicit, factor repeated tree structure, exploit a
bit written by the previous transition to share control, and check the
complete initializer against the runtime invariant \cite{zfc}. The new continuation
identity is an instance of that last kind of local history proof. Importing
a ZFC consistency-search machine itself would change the target theorem;
its nonhalting is not a substitute for the specified Con(PA) statement.

The DiophantineConsistency material is particularly relevant to proof
boundaries: a standard-model computation identity, a uniform all-model
coding theorem, and an internal weak-arithmetic implication are separate
obligations \cite{dio}. A lower variable count or smaller coefficient description in
a Diophantine formula does not automatically reduce the binary TM. The
coefficient printer, arithmetic evaluator, enumeration scheduler and blank
initializer all contribute working controls. Its Con(ZFC) constructions
also require a separate target change before they can be used here.

ConciseIPRA supplies ideas for combining evaluation and proof checking,
and for measuring an actual checker rather than the visual length of
axioms. Its bi-interpretability result concerns iPRA \cite{concise}. It does not identify
iPRA with PA or license replacing Con(PA) by Con(iPRA). A shorter Python
checker or fewer rule families still require a literal single-tape binary
compilation. The sourced transfer assessment, with exact repository paths
and blob identities, is included in \file{verification/calibration_audit/}.

\section{Further research questions}
\begin{enumerate}
\item Can the new literal arithmetic-context envelope support a larger
simultaneous state elimination, beyond the bounded one-state and pair
searches completed here? Its coverage of intermediate sweep positions
provides information that the generic tape-window closure discards.
\item Can the 193-state runtime's initializer be redesigned jointly with
its representation invariant? The existing failure is an initialization
failure; searching additional raw starts in the same bad table does not
repair it. A successful redesign needs a complete blank-to-frame proof.
\item Can the new direct continuation return enable a multi-control
quotient after a different loop association or register allocation? The
present transformation makes the two read-one returns at 190 and 83 agree,
but their read-zero behavior and allowed contexts still differ. Equality
of only one transition is insufficient for a merger.
\item Can source compression optimize semantic interfaces jointly with
reader sharing, instead of only shortening a macro word? The 67-reader
plateau and different fold budgets show that fewer source instructions
need not mean fewer machine states.
\item Is there a smaller complete PA-equivalent numerical calculus whose
freshness and substitution requirements remain cheap in this unary
register representation? Removing a witness or strengthening a guard
requires a recovery proof for all uses in the PA compiler.
\item Which inherited written proof constructors should be formalized
next to close the Lean endpoint? The finite-request compiler, the current
Foundation adapter and the arbitrary-length physical/source composition
have explicit mathematical interfaces suitable for separate formal work.
\end{enumerate}

\section{Reproduction and artifact map}
Python 3.10 or later with its standard library suffices to rebuild the two
machines and run the included finite verifiers. Assertions must be enabled.
No network, repository checkout or proof assistant is needed for these
checks. The optional reduction-search program additionally uses a C++17
compiler. From the unpacked archive run
\begin{verbatim}
python3 -B reproduce.py --out replay
python3 -B reproduce.py --full --out full-replay
\end{verbatim}
The first command rebuilds both tables, checks source agreement, fold and
shortcut premises, complete startup, frozen literal-certificate bindings,
frame closure, the polynomial clock envelope, and novelty. The second also
regenerates every independent literal source contract. It takes several
minutes. Neither command claims to check the entire inherited arithmetic
compiler or to run the unfinished end-to-end Lean development.
