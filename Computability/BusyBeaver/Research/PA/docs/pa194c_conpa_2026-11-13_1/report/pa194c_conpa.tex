\begin{abstract}
We construct an explicit deterministic, binary, single-tape machine with
194 working states whose blank-tape nonhalting is provably equivalent in
PA to $\Con(\PA)$. The construction meets the requested alternative of a
materially different 194-state design. No machine with fewer than 194
states is established by this investigation.

PA194C combines the supplied 67-reader/seven-fold PA194 allocation with
the Combined command controller previously implemented at 195 states.
Six native transition rows change. The resulting source has 3,649
primitive instructions, compared with the existing PA194's 3,673, and its
entire resolved instruction graph equals the previously calibrated PA195C
source. The count is $134+67-7=194$. Its transition graph is distinct from
all supplied 194-state graphs even after arbitrary state renaming,
forgetting the initial state, reflecting the tape, and exchanging symbols.

All 4,749 arbitrary-register source outcomes pass for both the raw and
final tables. A separate literal-tape checker rederives four generic list
lemmas and verifies the final table without arithmetic-box oracles.
Exact blank execution reaches the complete source frame after 57,922
transitions. We compare all 36 incoming archives at a pinned repository
revision, distinguish supported constructions from failed diagnostics,
and record the unsuccessful searches below 194. The proof is ordinary
mathematics with executable supporting certificates; a new end-to-end
Lean or Rocq theorem is not claimed.
\end{abstract}

\section{Result, conventions, and scope}
\label{sec:result}

The definitive table is \file{construction/tables/pa194c.tm}. It has
working states $0,\ldots,193$, start state $0$, and the distinct terminal
label $194$. Its two-way infinite tape has alphabet $\{0,1\}$, is initially
zero everywhere, and starts with its head at position zero. Every transition
writes one symbol and moves exactly one cell left or right. Each working
state has exactly two rows, so the table has 388 rows. The halt label has
no outgoing rows and is not included in the working-state count.

\begin{theorem}[Main result]
Let $H_{\MC}$ be the usual arithmetical sentence asserting that a finite
halting trace exists for this exact table from its specified blank start.
Then
\[
 \boxed{\PA\vdash\bigl(\neg H_{\MC}\leftrightarrow\Con(\PA)\bigr).}
\]
\end{theorem}

The theorem is an assertion of PA-provability and does not assume
$\Con(\PA)$ as an axiom. Actual nonhalting follows if PA is consistent.
The source-calibration argument and physical proof are developed below.

The literal dense table has SHA-256
\begin{quote}\small
\nolinkurl{d759313c03b515293fe06b12769fa1771d3829a2bad89febaa9b4391990f3a4b}.
\end{quote}
The native table starts in 74, halts at 254, and has SHA-256
\begin{quote}\small
\nolinkurl{b35d80b01ce9c2e95c8b29222881f40928247cdeffac322e4643f4f6694cd33c}.
\end{quote}
The supplied label list conjugates every row of these two presentations.
All 194 working states are reachable in the pointed transition graph.
This graph fact does not assert that every state occurs in the actual
blank execution. Appendix~\ref{app:table} prints the complete dense table.

\subsection{What has and has not been established}

The strict target was fewer than 194 states. The successful deliverable is
the explicitly permitted same-size alternative. Its novelty is relative
to the inspected, pinned corpus, not a claim about every unpublished
machine. Neither the failed searches nor the current best construction
establish a lower bound of 194.

The proof status has three separate parts. The literal tables, exact source
binding, finite local quotients, and symbolic execution certificates are
reproducibly checked by the included programs. The logical calibration is
an ordinary syntactic proof in the supplied research, with the changed
controller's proof compiler exhibited here. The repository's relevant
machine-specific formal Lean and iPRA endpoints have additional unfinished
obligations. Those endpoints
are not used as if they were completed theorems.

\subsection{Larger machines and formalization layers}

The U208 family develops contextual and finite-history folds, source
reassociation, and exact physical return interfaces. Several early
archives repeat the same two U208 graphs; later helper-layout work contains
additional graphs. The James Chang PA196 design replaces much of the
larger axiom implementation with a compact numerical source. Subsequent
196-state investigations vary its axiom gate, parameter choices,
register positions, command controller, source association, and return
scanner. These provide the ingredients used by the positive 195 and
194 families.

Two comparisons prevent misleading claims. A shorter expanded source
does not automatically use fewer physical states: the supplied 3,441-site
short-negation implementation still has 197 states. Conversely, a larger
reader tree can be competitive if it supports more compatible folds, as
PA194-68 demonstrates. The relevant objective is the completed physical
allocation with every interface checked.

The direct PA repository also contains many proof layers for the original
195-state quotient and arithmetic endpoints. They are not independent
machine designs. At the pinned revision, the PA README and
\file{pa194/ipra/README.md} explicitly retain both machine-specific
iPRA reductions as assumptions. An ordinary PA proof, a standard-model
simulation theorem, and an internally proved iPRA equivalence are distinct
claims. This work asserts the first and supplies executable physical
evidence; it does not silently promote the conditional formal endpoint.

All native working controls remain present. These are semantic controller
changes, not six arbitrary search mutations. At source level they replace
\begin{align*}
 \texttt{node163}&=(\texttt{node6},\texttt{node55})
       &&\text{by }(\texttt{node6},\texttt{node147}),\\

       &&\text{by }((\texttt{node36},(\texttt{node167},\texttt{node145})),

\end{align*}
The changed MP-success tail transfers its result into the cached formula;
the changed Shift tests that cache and then performs the stack transfer.
Section~\ref{sec:pa194c-calibration} states their exact numerical semantics.

The new source has 3,649 sites. Its first 3,634 instructions agree with
the old source after relocating the three outgoing references at sites
48, 3,553, and 3,633. Its final fifteen instructions implement the changed
controller. The builder checks every instruction and every ordinal target,
including both decrement branches. More strongly, the entire array is
equal to the frozen source array extracted from the current PA195C packet.
Both the main builder and the independent checker assert that equality.

\subsection{The unchanged decoder quotient}

The fixed source macros and runtime use 134 controls. The selected binary
association of the 190-token AX word uses 67 raw reader controls, so the
unfolded machine has 201 controls. The seven disjoint identifications are
\[
\begin{gathered}
2016\mapsto2052,\quad2018\mapsto2027,\quad2022\mapsto2032,\quad
2024\mapsto2046,\\
2037\mapsto2015,\quad2055\mapsto2019,\quad2060\mapsto2014.
\end{gathered}
\]
They are the inherited PA194-67 identifications. For each pair, incoming
rows establish a different previous tape bit for its two members. The
shared state can inspect that bit and use an existing helper to recover
the appropriate action. Every incoming target is projected through the
same seven identifications. The final count is
\[
                    134+67-7=194.
\]
No extra startup control, hidden marker symbol, stationary move, or
nonblank initial input is introduced.

The checker exhausts the four previous-bit/current-bit combinations per
pair against the \emph{final simultaneously folded table}. This gives
28 exact local cases. It checks the complete two-cell tape, displacement,
projected destination, and that no unspecified exterior cell is read.
It also checks all incoming rows establishing the context. Thus changing
the controller cannot invalidate a helper merely because the old pair
was once individually valid.

\begin{lemma}[Positive quotient simulation]
The raw 201-control machine and the final 194-control native machine have
equivalent halting behavior from native state 74 on every coded initial
tape. Each raw step has a positive finite simulation in the folded machine.
\end{lemma}
\begin{proof}
At ordinary controls, the two transitions commute with the projection.
At an exceptional control, its incoming row supplies the previous bit,
and the corresponding checked two-cell trace supplies the simulation.
The start is not exceptional. Induct on the raw trace length, preserving
the complete tape and head at the endpoints. Positivity prevents an
infinite raw computation from being compressed into finitely many folded
steps. More concretely, if the folded table first halted after $T$ steps
while the raw table had $T+1$ nonhalting steps, their positive simulations
and determinism would contradict that first halt. All cases and this
finite induction are available in PA.
\end{proof}

\section{Physical correctness and its verification boundary}
\label{sec:physical}

The source uses nine natural-number registers. The physical file represents
a value $v$ by $0\,1^{v+1}$, followed by an arbitrary finite nonempty spare
list. Its complete source frame has a left sentinel, a binary instruction
path, a zero gap, a right delimiter, and this register file. The base
header length is 48; the gap may grow during computation. The symbolic
contracts quantify over the gap and register values instead of choosing
a finite collection of sample numbers.

For an increment site, the certificate reaches the next source frame
with precisely the selected register incremented. For a decrement site,
it separately checks the zero and positive cases, including the right
successor and the changed register value. Jumps preserve the register
file and change the code path; the halt primitive reaches native label
254. The complete instruction graph fixes every such destination.

The first checker uses the inherited generic arithmetic-block lemmas and
verifies all 4,749 outcomes for both the raw 201-control and final
194-control tables. The second checker uses a separate literal-tape
representation and derives four generic list-sweep lemmas from the actual
transition rows. It then checks every final-table source outcome without
calling the first checker's arithmetic-box oracle. It independently resolves
the source graph, verifies the dense/native conjugacy, and checks the
entire finite-support blank-start tape.

The symbolic step totals count proof-execution operations, including
generic sweep steps; they are not uniform literal running-time bounds for
arbitrary unary register values. The finite local fold traces, by contrast,
are literal transition sequences on their stated finite window.

At the startup endpoint the native state is 84, the dense state is 24,
and the head is at $-2$. The first nine physical values are
$(0,0,0,0,0,0,2,0,0)$ and the spare list has 26 entries equal to one.
There are 66 one-cells in the entire tape; every other cell is zero.
The machine-readable startup certificate lists all 66 coordinates. Equality
is checked for the whole finite-support tape, not only a displayed window.

\begin{proposition}[Source/physical halting equivalence]
PA proves that the delivered blank-tape machine halts if and only if the
exact Combined source program halts from its certified clean seed.
\end{proposition}
\begin{proof}
Execute the fixed startup trace. Compose the positive primitive simulations
using induction on the source trace. The frame invariant preserves the representation
of the evolving register store, the complete tape, and the nonempty spare list.
For the converse, suppose the physical table first halts at time $T$.
If the source has not halted, its total primitive step function generates
$T+1$ further source steps. Their positive simulations give a nonhalting
physical prefix longer than $T$, contradicting determinism. Fixed local
cases are finite arithmetic facts; unary and finite-list sweeps are proved
by induction. Hence the argument concerns coded finite traces inside PA.
Compose it with the source calibration in
Section~\ref{sec:pa194c-calibration} to obtain the main theorem.
\end{proof}

The two executable checkers are supporting proof artifacts, not two
independent foundational proof kernels. They use related source encodings
and ordinary Python. The second removes the first one's arithmetic-oracle
dependency and checks the generic sweeps directly, which addresses a
specific possible blind spot. No claim of a new fully elaborated Lean or
Rocq endpoint is made.

\section{Material difference and exact graph comparison}
\label{sec:novelty}

The controller changes what commands do: successful MP stores the
conclusion in a different component, and Shift has a different halt test.
The expanded source loses 24 instructions. Thus the distinction is
observable before physical state allocation. The numerical example in
Section~\ref{sec:pa194c-calibration} exhibits the different store results.

The physical distinction is separately certified. The corpus contains
seven exact 194-state byte forms, representing four prior action-labeled
graphs: three positive designs and the rejected scanner quotient. For each
table the graph checker starts a deterministic breadth-first numbering
from every working state, following the read-zero edge before the read-one
edge. Every one of the 194 possible roots spans the whole graph. It compares
the resulting canonical transition vectors directly, taking the least
over all roots; equality therefore characterizes graph isomorphism for
these tables without relying on the given start state.

The same calculation is repeated under left/right reflection and global
bit exchange. PA194C differs from every previous graph under all these
symmetries. Bit exchange is only an extra structural comparison---the
actual construction retains blank symbol zero. The comparison does not
claim that graph nonisomorphism by itself proves a different algorithm;
the changed command semantics and full source graph provide that evidence.

\section{Reproduction and delivered artifacts}
\label{sec:reproduction}

Run the main acceptance checks from the unpacked archive root:
\begin{quote}\ttfamily\small
python3 -B reproduce.py
\end{quote}
The wrapper runs deterministic construction and source binding, both
symbolic physical passes, the independent final-table audit, the
symbolic command-algebra audit, and the complete existing-194 novelty check.
Python 3 and its standard library are sufficient. Run with assertions
enabled; optimization mode is rejected. The main checks do not need the
repository checkout, internet access, a solver, or a proof assistant.

The optional discovery searches are separate. Their C++ sources and
frozen inputs are included with the run records, but replaying heuristic
search is not required to reconstruct or verify the delivered machine.
The complete corpus census requires the pinned repository because the
large incoming corpus is identified by hashes rather than duplicated.
