1. Conditional origin information can replace control states.
   Source:Computability/BusyBeaver/Research/ZFC/candidate-k215/alternatives/conditional-marker/README.md
   CM215 merges two reader roles whose zero transitions differ, recovering
   the origin from the preceding tape bit only when the present bit is zero.
   An apparently ambiguous incoming path forces the present bit to one, so
   it cannot violate that conditional invariant. Its state-neutral result
   uses the freed label as a selector, showing that a role merger saves a
   physical state only if the selector is already available or can be shared.
   Its proof compares entire tapes, not merely the small inspected windows.
   This is the same useful optimization paradigm as the PA reader folds.
   The borrowed idea is the proof method, not an independently stackable
   deletion: different PA source associations have different predecessor
   histories, and simultaneous folds must be checked on the final table.

2. Command-local parameter reading and command order can reduce total cost.
   Source:Computability/BusyBeaver/Research/ZFC/README.md;
          Computability/BusyBeaver/Research/ZFC/candidate-k215/README.md.
   The accepted K215 construction combines command-local field reading,
   reordered commands and a partial selector, with two earlier marker folds
   retained. Its source and physical allocation are jointly designed.
   The PA Combined controller follows the same architectural principle:
   a stronger cached-head invariant lets Shift inspect h, while successful
   MP leaves the consequence directly in H, avoiding the old dummy push.
   This is a genuine command-interface change requiring a new proof-word
   compiler. It is not derivable just by comparing the state counts.

3. A parameter-free MP compiler is useful but can cost more machine states.
   Source:Computability/BusyBeaver/Research/ZFC/k215-residual-parameter/README.md
   and proof.md. The residual construction uses a preserving zero-setter
   and a three-AX RESET, allowing additive AX with A=oldD+x and retaining
   the dominated-rho8 calibration. It removes MP's numeric parameter read.
   Reported source variants have 207/210 DAG nodes and conservative physical
   allocations234/237 states versus the accepted215. A206-DAG rotated
   source costs240 under the stated allocation policy. This gives a concrete
   warning against equating shorter source code with fewer controls.
   The incoming PA_consistency_TM_research_2026-11-13.zip already explores
   this parameter-free MP approach; it does not supply a sub196 realization.

4. Restricting axiom parameters is safe only with complete proof transport.
   Source:Computability/BusyBeaver/Research/ZFC/candidate-k218/alternatives/dominated/README.md
   and the ZFC main README. The dominated-rho8 route preserves native
   theorem derivability while reducing source sharing cost. The corresponding
   idea is already present in the PA line. Restrictions which simplify the
   emitter can destroy logical strength; the ZFC finite-matrix countermodels
   show why some superficially similar restrictions fail. The role of a
   restricted emitter must be judged using an exact syntactic compiler,
   not by finite samples or by assuming arbitrary parameters remain available.

5. ConciseIPRA offers calculus/interface ideas, not a ready PA refutation engine.
   Source:Logic/PrimitiveRecursiveArithmetic/ConciseIPRA/README.md.
   Its native scalar core uses 0,S and a unary iterator; formulas are equations
   with Q and D operators. Ordinary intuitionistic connectives and quantifiers
   are derived macros. Later clause presentations remove Q from formulas,
   move assumptions into single-body clauses, and fuse evaluation with
   discharge. This demonstrates how checker input and derived logic can be
   redesigned together. Its metric, however, is normalized Python tokens,
   AST nodes and bytes of a complete proof checker, not binary TM controls.
   It presents iPRA, whereas the current target is PA-refutation search.
   Compiling its checker without a separate uniform finite-refutation bridge
   does not establish the requested Con(PA) equivalence. Adding full PA
   induction, representing proof contexts and iterators, and including blank
   initialization would have to be priced in a complete binary machine.
   The immediate reusable ideas are uniform rule interfaces, explicit proof
   transformations, derivable connectives and shifting administrative work
   from control states into data; no new literal sub194 machine follows from
   the small Python figures alone.

Consequences for this attempt
-----------------------------
The target price is the complete blank-start binary machine. In the present
PA emitter architecture this is
 fixed engine + reader controls - compatible identifications + scanner cost.
The successful194 parents have respectively134+67-7 and134+68-8.
Changing source association can alter all three latter terms. Prior source
pruning and NEG18 examples show that even hundreds fewer primitive occurrences
may increase the physical state count. The Combined194 construction uses a
command change already calibrated in the PA line while retaining a separately
certified194 reader implementation. It is justified by exact source binding
and complete primitive contracts, rather than an additive state-saving claim.
