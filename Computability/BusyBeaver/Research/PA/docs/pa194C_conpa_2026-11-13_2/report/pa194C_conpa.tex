\begin{abstract}
The strict state-reduction target was not attained in this investigation.
The delivered alternative, PA194C, is a complete blank-start, binary,
one-tape machine with 194 working controls, for which the mathematical
argument establishes
\[
 \PA\vdash\bigl(\neg\Halt(\MC,\mathrm{blank})\leftrightarrow\Con(\PA)\bigr).
\]
It composes the 67-reader, seven-fold PA194 decoder with the previously
calibrated Combined command controller. Six native transition rows change;
the source has 3,649 primitive instruction sites instead of 3,673.
The command behavior changes substantially: Shift tests the cached head
alone, and successful modus ponens returns its conclusion in that cache.
A fresh census of all 36 incoming archives and the direct PA tables finds
no previous 194-state implementation of this controller, including under
state relabeling and tape reflection. All 4,749 source branch contracts
are checked symbolically for arbitrary registers, with a separate literal-tape
implementation rederiving the required list lemmas. Exact blank initialization
uses 57,922 transitions. The proof is an ordinary mathematical statement of
PA-provability with executable supporting certificates; it is not a newly
elaborated end-to-end Lean or Rocq proof. No optimality or lower-bound claim
is made.
\end{abstract}

\section{Outcome, machine convention, and exact deliverable}

The requested fallback is achieved. The new construction is PA194C, whose
literal table is \file{construction/output/pa194C.tm}. Its conventions are:
working states $0,\ldots,193$, initial state $0$, separate halt label $194$,
one two-way infinite tape over $\{0,1\}$, all cells initially zero, and
initial head coordinate zero. Each of the 388 rows writes one bit and
moves exactly one cell left or right. There are no stationary moves,
preloaded program symbols, extra tracks, or counted-away startup controls.
Appendix~\ref{app:table} gives the entire transition function.

The authoritative dense table has SHA-256
\begin{quote}\small\ttfamily
 d759313c03b515293fe06b12769fa1771d3829a2bad89febaa9b4391990f3a4b
\end{quote}
Every working control is reachable
in the directed transition graph. This graph property does not assert
that every control occurs in the actual blank run.

Fix a conventional primitive-recursive proof predicate
$\operatorname{Prf}_{\PA}$ for first-order PA with full induction and set
\[
 \Con(\PA)\equiv\neg\exists p\,
       \operatorname{Prf}_{\PA}(p,\code{0=1}).
\]
Let $\Halt(\MC,\mathrm{blank})$ be the usual existential assertion that
there is a finite valid transition trace from the specified blank
configuration to the halt label. The principal claim is an internal
biconditional of PA, not merely a metatheoretic statement conditional on
standard-model soundness. Its proof composes syntactic refutation
translations, a command compiler, and positive physical simulations.
The detailed logical argument appears in Section~\ref{cal:section}.
Actual nonhalting follows if PA is consistent; that consistency assumption
is not added as an axiom when proving the biconditional.

\subsection{What is new}

The diagonal-vacuity calculus, the separated ten-entry emitter, the
Combined controller, and the seven-reader fold technique are all credited
prior components. The new result is their literal 194-state composition,
its complete source and physical binding, its independent replay, and its
comparison against the current corpus. Previously supplied 195C uses the
Combined controller with a decoder costing 61 effective reader controls.
The new decoder costs 60. Previously supplied PA194 tables use the original
controller. Thus this is a new combination with an actual command-level
difference, rather than an attempt to count an old saving twice.

\subsection{Every existing 194-state class}

The census contains seven 194-state byte forms belonging to four action
graph classes. Three are supported written constructions; the fourth is
explicitly rejected.

\begin{enumerate}
\item \textbf{Primary PA194.} It uses $134+67-7=194$ controls: 134 fixed
controls, 67 raw AX readers, and seven compatible contextual folds. Its
source has 3,673 sites and 4,780 branch contracts. The dense table begins
with hash \file{4bfea62b17aad7d8} and is in the first PA194 archive
\cite{pa194a}.
\item \textbf{PA194\_AD.} The first archive also exchanges physical A and D
register positions, retaining the same logical source and command protocol.
Its dense hash begins \file{27613aa92da79ba2}. This is a different physical
graph but the same logical algorithm.
\item \textbf{Second PA194.} The second archive uses $134+68-8=194$ controls,
the same 190-token word, and 3,673 sites. Its dense hash begins
\file{9087d70fc0e1878c}. Its 32 local fold cases include a seven-step
simulation \cite{pa194b}. One more raw reader enables two more compatible
folds, so minimizing raw decoder nodes alone is the wrong objective.
\item \textbf{Rejected scanner-194.} The follow-up packet's native hash
begins \file{c48d6711e9c73366}. Its local 202-to-194 quotient is valid,
but its source contains a seven-zero address run which the old scanner
mistakes for a separator. The first failed contract is source ordinal
1003, the zero branch on logical register 1. The repaired machine adds a
scanner control and has 195 states. A valid local quotient of an invalid
source implementation does not establish a consistency machine.
\end{enumerate}

All four existing native 194-state graphs have the original six-row
controller fingerprint. None uses the Combined command behavior. The
comparison includes the rejected graph to avoid treating an earlier failed
experiment as new.

\subsection{Other lower-state candidates and proof layers}

At 195 states the census has 82 occurrences, 25 byte forms, and 15 graph
classes. Positive reported families include original PA195, separate-head
195S and 195C, diagonal Combined PA195DC, and repaired-scanner M195S8.
Additional packets contain the rho-parameter variant PA195R, negative
diagonal PA195N, bounded local-quotient outputs, and rejected diagnostics.
Their distinct evidence status is retained in the catalogue, rather than
classifying every 195-state file as a proved construction.

The direct PA tree's numerous \file{pa195-*} directories are mainly proof
layers for existing tables. The quotient/dense/ordinary/zipper developments
prove substantial ordinary run equivalences. Runtime, site binding,
symbolic batches, and source iteration establish other parts of the
compiler chain. The arithmetic endpoints still have machine-specific
reduction obligations. In particular, the PA README explicitly does not
claim the complete iPRA endpoint. This missing formalization is different
from a counterexample to a mathematical proof of PA-provability.

The supplied NEG18 macro is an instructive negative comparison: it reduces
3,673 source instructions to 3,441, but its best audited physical allocation
costs 197 states. It loses useful source sharing and contextual folds.
Likewise, a small source DAG does not imply a small blank-start machine
when an extra scanner, return control, or initializer must be included.

\label{sec:physical}

We retain the primary PA194 grammar and all seven folds. Before folding,
the new machine has 201 controls: the same 67 reader nodes and 134 fixed
controls, with six fixed transitions modified. Native labels are used in
this section because they identify inherited control roles directly.
Native start and halt are 74 and 254; the exported table is a deterministic
breadth-first renumbering with start 0 and halt 194.

\subsection{The source tail and changed command effects}

With zero-based source ordinals, the MP-success tail begins at $E=3634$,
its fetch return is $F=3637$, and Shift preparation begins at $S=3638$.
The complete 15-instruction tail is supplied in the build receipt. Its MP
loop transfers the successful consequent from D to H while clearing D;
its Shift loop first discards T, copies H to T and scratch, restores H,
and enters the inherited equality-to-one guard. The rest of the source
prefix is unchanged except for three retargeted exits at ordinals 48,
3553, and 3633. These are checked by explicit ordinal relocation.

For a command store $(t,w,d,h)$, the new Shift halts if and only if $h=1$.
Original Shift tested $t+h=1$. For example, $(t,h)=(1,0)$ causes an original
halt but continues under the new command; $(t,h)=(2,1)$ does the reverse.
The command compilers account for this change. Successful MP now returns
its consequent in H, clears T and D, and leaves the stack unchanged.
Original MP returned the consequent in T, retained its accumulated D value,
and pushed a zero. Thus PA194C changes the actual proof-search controller.

\subsection{Compatible history folds}

The seven retained native pairs are
\[
 (2016,2052),\ (2018,2027),\ (2022,2032),\ (2024,2046),\
 (2037,2015),\ (2055,2019),\ (2060,2014),
\]
where the first member is redirected to the second. An incoming raw
transition to a first member writes 0 and moves right; an incoming
transition to its partner writes 1 and moves right. None of these states
is initial. Hence the left neighbor identifies the incoming role when
a decoder action needs it. The retained state can move left, dispatch
through an already available reader, return, and complete the old action.

For each pair and each current read symbol, the local certificate checks
both possible predecessor bits. It verifies restoration of every touched
cell, the exact final head coordinate, and the projected successor control.
All 28 cases are checked in the \emph{final simultaneously folded table},
so a helper affected by another fold cannot silently invalidate a case.
The incoming-row census has 23 rows. Each local simulation has positive
length, and only the current cell and its immediate left neighbor are
inspected. Arbitrary outside-tape extensions therefore preserve the proof.
Every other row commutes with the control projection in one step.

\begin{lemma}[Local quotient transfer]
On every raw run satisfying the incoming-history invariant, one raw step
has a finite nonempty simulation in PA194C with exactly the projected
control, original head position after that step, and original entire tape.
The invariant holds at the initial configuration and at every relevant
raw entry. The construction and its correctness are provable in PA.
\end{lemma}
\begin{proof}
Nonfolded controls use their unchanged action with its target projected.
For a folded control, its immediately preceding raw transition supplies
the history bit, and one of the finitely many certified two-cell traces
applies. Each trace is checked by direct substitution in the literal
table. All outgoing raw steps again meet the same incoming-row condition
when they enter a folded role. Induction on the raw trace composes these
finite positive blocks. All premises are finite table facts, so PA proves
them by evaluating their closed arithmetic encodings and then using
induction on the trace length.
\end{proof}

The new controller edits do not touch the AX reader states, but this alone
would not justify reusing fold certificates: the complete final table is
still reconstructed and all local cases are rerun. The resulting count is
\[
 \boxed{134+67-7=194.}
\]

\subsection{Universal whole-tape source contracts}

A clean source frame contains the current source path, an affine zero gap
before its header, nine arbitrary natural-valued unary registers, and an
arbitrary finite nonempty spare list. The frame domain has header distance
$48+n$ for arbitrary $n\in\mathbb N$; after source path $p$, the gap is
$48+n-|p|$. The two outcomes of each decrement are treated separately.
The contract changes only the prescribed register, source path, and any
specified frame displacement. It compares the complete tape and head.

The builder's symbolic register implementation checks all 4,749 branch
contracts. A second checker uses literal tape runs and four inductively
proved list traversals, rederived from the actual rows of the delivered
machine. It does not call an arithmetic-register oracle. Both source graph
resolvers independently agree on every instruction destination. Every
nonhalt outcome has a finite positive-duration physical simulation; the
independent check's duration polynomial has nonnegative coefficients and
a positive constant term.

\subsection{Exact blank initialization}

Starting with the literal blank configuration, 57,922 transitions reach
native control 84, head coordinate $-2$, source site 25, logical register
vector $(2,0,0,0,0,0,0,0,0)$, and 26 spare blocks of value one. The header
distance is 48 (the arbitrary gap offset $n$ is zero). The final tape has
66 one-cells; both checkers compare
the complete finite support and assert zero on the entire exterior.
The exact one-cell coordinates are in
\file{construction/independent/blank_seed.json}.

This startup is 232 transitions shorter than primary PA194's 58,154-step
startup. It is an initialization result only. There is no claim of a
uniform speed improvement for arbitrary proofs, source states, or inputs.

\section{Search below 194 and what the negative results mean}
\label{sec:search}

The strict target was a verified machine with at most 193 working controls.
The investigated families were chosen from the actual state accounting:
reduce the 134-control fixed part, reduce the decoder's raw node count,
increase its simultaneously compatible fold count, or change the source
and its macro interface while preserving its calibration.

\input{search_summary.tex}

The generic physical searches considered history windows, local detours,
common future configurations, and removal of a state by rewriting its
incoming transitions. Symbolic contexts cover complete source contracts,
including arithmetic-list behavior where available. Register permutations
were also screened. None of those bounded families produced an accepted
193-state table. The constraints and explored budgets are evidence about
these searches only; they do not prove a state lower bound.

The grammar searches started from both accepted 194-state allocations.
They used whole shared-subtree rotations and individual occurrence
rotations, scoring raw reader controls minus simultaneously valid folds.
A second search opened the copying macros into push and additive-copy
subblocks. A third exposed additional closed subblocks and recognized
existing fixed reader pairs. The distinction between source tokens and
physical labels is essential: two source subblocks can share a physical
control only because their surrounding path bits differ. An early
experimental expansion incorrectly conflated such source tokens; it was
rejected, corrected to preserve token identities, and excluded from every
construction claim. Finalists must pass full source-graph, scanner,
startup, and universal-runtime checks, not just a numerical search score.

The search failure leaves the 194-state alternative as the completed
result. In particular, the manuscript does not use an absent failed
counterexample, bounded blank simulation, or an unverified allocator
prediction as a proof of correctness.

\section{Useful ideas from ZFC and ConciseIPRA}

The linked ZFC work contributes methods which can be transplanted only
with their invariants. Its conditional-marker constructions replace a
control distinction by information in nearby tape cells; an ambiguous
incoming role may be harmless if the current symbol excludes the branch
where the distinction is needed. Its accepted K215 line jointly designs
command-local parameter reading, command order, and selectors. These ideas
motivate the local context searches and the explicit command/decoder
composition in PA194C \cite{zfcmarker,zfc215}.

A selector still costs a state unless an existing reader implements it.
Consequently an individually valid role merger need not reduce the total.
The ZFC residual-parameter construction also illustrates that eliminating
an MP parameter can reduce source administration while increasing the
physical allocation. The analogous PA route already occurs in the incoming
corpus without a sub-196 result. Its state saving cannot be inferred by
comparing source expression lengths \cite{residual}.

ConciseIPRA offers a different conceptual lesson: choose a small set of
primitive proof-checker interfaces and derive ordinary logical structure.
Its scalar core and clause variants make administrative choices visible
in the complete checker. The optimization metric there is Python tokens,
AST nodes, and bytes, not complete binary-TM controls \cite{ipra}.
More fundamentally, searching iPRA proofs does not by itself implement
PA-refutation search. The present soundness calibration uses finite binary
comprehension for an arbitrary formula, supplied by full PA induction.
A replacement theory would require explicit proof translations in both
directions and a complete compiler, including proof representation and
blank initialization. No claim that $\Con(\mathrm{iPRA})$ may simply replace
$\Con(\PA)$ is used here.

\section{Novelty check and reproducibility}

The new dense graph is compared against all four prior 194-state graph
classes, including the A/D variant and the rejected scanner experiment.
The comparison allows every initial root reaching the full graph,
arbitrary control renaming, global left/right reflection, and simultaneous
read/write bit complementation. All four orientations of PA194C have
canonical hashes absent from the old corpus. Symbol complementation is
included only to exclude cosmetic novelty; by itself it changes the blank
symbol and need not preserve blank-zero semantics.

The unreflected, uncomplemented root-free graph hash is
\begin{quote}\small\ttfamily
 b79f4d344740679b87dace02fe3f211565c2cd4513f346812570d90caa3d9a3f
\end{quote}
The receipt records all four comparisons. This nonisomorphism is additional
evidence for a different machine, while the changed command semantics
establish the substantive algorithmic difference. Neither graph novelty
nor a smaller source alone establishes the consistency theorem.

From the package root, Python 3.10 or later with its standard library
suffices for the primary checks:
\begin{quote}\small

\file{PYTHONOPTIMIZE}. The complete universal checks are the defaults.

for verification. Neither the optional searches nor a proof-assistant
installation is needed to reconstruct the machine and replay its finite
and symbolic certificates.

\subsection{Proof and trust boundary}

There are three distinct kinds of evidence. Literal table census,
conjugacy, complete startup, source graph equality, and finite fold traces
are finite facts checked by executable programs. Universal unary and list
contracts use explicit symbolic identities and inductive loop arguments.
The PA consistency equivalence additionally uses the mathematical
proof-producing translations and command compiler of
Section~\ref{cal:section}. Python execution is not presented as a proof
kernel certifying that entire PA theorem.

The inherited Lean files are provenance and further-formalization
references. This release does not claim an end-to-end Lean or Rocq
elaboration, and does not promote the repository's conditional iPRA
endpoint to a completed theorem. No global minimum state count is proved.
