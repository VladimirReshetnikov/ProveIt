# Atomic Sinc-Product Splines Beyond the Binary Point

This package contains a 35-page English translation, mathematical reconstruction,
and repository-relative research expansion of the attached Russian Chapter 3 on
Rvachev atomic functions.  The report is written in the notation and editorial
style of Vladimir Reshetnikov's `ProveIt/Analysis/FabiusFunction` corpus.

Repository/source snapshot date: **2026-08-28**.

## Main deliverables

- `atomic_sinc_splines_report.pdf` - compiled 35-page report.
- `atomic_sinc_splines_report.tex` - complete LaTeX source.
- `numerics.py` - deterministic exact and FFT-based experiments, with detailed
  comments and no Monte Carlo simulation.
- `figures/` - four report figures generated by `numerics.py`.
- `data/` - exact moment, weighted-Prouhet, and finite-product convergence tables.
- `corpus_audit.txt` - scope and limitations of the recursive repository audit.
- `requirements.txt` - Python dependencies.
- `SHA256SUMS` - checksums for every packaged file other than the checksum file.

## Status labels used in the report

- `[S]`: translated or reconstructed from the attached Russian source.
- `[R]`: already present in the living repository documentation or its
  formalization crosswalk.
- `[N]`: derived in this report and apparently absent from the audited repository
  corpus.  This is a repository-relative novelty label, not a claim of worldwide
  priority.
- `[C]`: conjectural, heuristic, or programmatic.

The labels are deliberately conservative.  Numerical evidence is never used as a
substitute for proof, and statements not formalized in Lean remain outside the
repository's trusted theorem boundary.

## Reproduce the numerical outputs

Create a Python environment, install the dependencies, and run:

```bash
python -m pip install -r requirements.txt
python numerics.py
```

The script writes:

```text
figures/family_profiles.png
figures/scaled_prefix_error_a22.png
figures/fourier_envelope_a22.png
figures/cantor_gap_atlas_a3.png
data/moments.csv
data/prouhet_checks.csv
data/prefix_errors.csv
```

The symbolic computations use exact SymPy rational arithmetic.  Fourier
inversions use deterministic FFT evaluation of the explicit sinc products.  No
network access or random sampling is required.

## Compile the report

From the package directory, run:

```bash
latexmk -pdf -interaction=nonstopmode -halt-on-error \
  atomic_sinc_splines_report.tex
```

The source is set for A4 paper, 11-point type, and 27 mm margins.  It uses
Libertinus when available and falls back to Latin Modern.  A reasonably complete
TeX Live installation is expected, including `amsmath`, `amsthm`, `mathtools`,
`booktabs`, `longtable`, `tabularx`, `tcolorbox`, `listings`, `hyperref`, and
`cleveref`.

The supplied PDF was built and visually checked page by page.  It has 35 A4
pages, embedded fonts, 72 outline entries, no encryption, no clipped or
overlapping content, no undefined references, and no overfull boxes.  The build
has one harmless underfull-box warning in the source concordance table.

## Source condition

The task supplied two files:

- `rvachev.tex`: a 1,267-line OCR transcription containing Chapter 3 through
  equation (3.100), where Section 5 stops in midstream.
- `rvachev.pdf`: eleven printed pages, 116-126, beginning in the middle of
  Section 2.

The PDF images were treated as authoritative wherever they resolve the OCR.
Elsewhere, formulas were reconstructed only when adjacent identities,
normalizations, and the source's proof determine the correction.  The report
never silently completes text beyond the surviving endpoint.

## Repository audit and non-duplication boundary

The current living `.tex` documents under
`Analysis/FabiusFunction/docs`, together with the recursive archive inventory,
were used to align notation and to avoid re-presenting binary Fabius/Rvachev
results as new.  The archive is explicitly a frozen historical record, and
byte-identical current copies are pruned there, so archived versions were used
for provenance and gap checking rather than counted as independent mathematical
claims.  See `corpus_audit.txt` for exact paths, method, and limitations.

The execution environment did not provide a local Git checkout.  The audit used
the public GitHub tree, raw canonical source files, and the archive manifest and
README.  Therefore it is a substantive mathematical non-duplication audit, not a
claim of an exact byte-level census of every historical `.tex` object.
