# Exact finite verification

Run from this article directory with Python 3.10 or later:

    python3 code/verify_exact.py --output data/verification_results.json

The program uses only the Python standard library and exact rational arithmetic.
It exits with an exception on the first failed check. The JSON receipt is
deterministic and can be regenerated independently.

The optional sampling illustration is regenerated by:

    python3 code/make_sampling_figure.py

That script additionally requires Matplotlib. It produces
`figures/signed_block_sampling.pdf` and `figures/signed_block_sampling.png`.
Sequence values and selected indices are computed with exact fractions before
they are converted to plotting coordinates.

## What is checked

| Component | Independent comparison or invariant |
|---|---|
| Seven recurrence examples | Direct scalar recursion against exact complex powers, an explicit repeated-root formula, rising-factorial products, the Catalan binomial formula, or the explicit Legendre coefficient formula |
| Rational state formula | Direct recursion against the product of polynomial matrices divided by the product of leading recurrence coefficients |
| Signed sampling | First block crossings, the strict lower annulus inequality, finite index bounds, separation of signed scalar samples, and distinct original indices |
| Periodic grid addresses | Actual exact cell keys for the center and selected signed samples |
| Half-open boundary conventions | Exact boundary, left-neighbor, and right-neighbor keys, including integer wrap and negative coordinates |
| Clearing denominators | Signs of direct rational comparisons versus polynomial expressions after multiplication by the squared denominator, including negative denominators and boundary equalities |
| Preorder windows | Recursively generated edge windows against the closed span formula and the local edge–subtree span bound |
| Conditional routing probability | Exhaustive enumeration of selector configurations and addressed terminal outcomes, with center entries exposed and distinct noncenter addresses |
| Necessary distinctness condition | A deliberate shared-terminal variant yields a different exact probability |

The receipt contains the exact sampled values and indices for each example.
The periodic-zero example reaches threshold equalities exactly, which exercises
the boundary convention. The negative-denominator example tests sign clearing
without assuming a positive denominator.

## Scope of the routing enumeration

The finite local model has two nondefault children, two samples per child, and
a further adaptive three-way routing choice below each child. Root selector
entries at the center are fixed to zero. Every sample consults a different
unexposed entry; different samples reaching the same terminal leaf retain
different terminal keys.

There are 4,096 selector configurations and 16 terminal assignments per
configuration, for 65,536 exact event cases. Terminal probability is \(p=1/3\).
The measured local failure probability is exactly

\[
(1-p/2)^4=(5/6)^4=625/1296.
\]

A separate enumeration deliberately gives two samples the same terminal
address. Its failure probability is \(9/16\), so the independence calculation
correctly rejects that altered geometry.

The address model verifies the conditional probability mechanism; the separate
window and signed-sampling checks exercise the geometry used to obtain the
required addresses in the proof.

## Limits of the computation

These computations do not instantiate the universal avoiding set, check every
real parameter, prove the infinite theorems, or implement real quantifier
elimination. The all-parameter and infinite assertions are established by the
article's proofs. The finite enumeration verifies the inherited routing
identity in an explicit conditional probability space; the other checks
corroborate the newly used recurrence and signed-sampling mechanics.
