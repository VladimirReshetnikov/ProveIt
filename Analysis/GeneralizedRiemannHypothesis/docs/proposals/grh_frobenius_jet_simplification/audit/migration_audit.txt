## The architectural change

Keep the already constructed integral one-variable exponent \(\Xi\), the exact theta factorization, and its finite resolution sum
\[
\Psi=\sum_i m_i\,\Xi(L_i).
\]
Supply two consequences of this exponent directly:

1. **Null-substitution integrality:** its reduction vanishes through degree \(B\) when the relevant coupling moments vanish.
2. **Inert sharpness:** selected restricted first derivatives have their prescribed lowest pure prime-power terms with unit coefficient.

The finite Frobenius pairing identity proves the first statement without identifying a double infinite expansion. Differentiating the raw formal-parameter relation proves the second statement without differentiating that expansion.

In particular, the change removes the obligation to construct and manipulate
\[
\sum_{e,j}\lambda_{e,j}\Gamma_e^{p^j}.
\]
This is a change in what is proved at the interface, not merely a replacement of \(\operatorname{tsum}\) notation by a finite sum.

The raw exponent is allowed to depend on the chosen resolution. The scale \(\varpi\), the one-curve exponent \(\Xi\), and its unit scalar \(\lambda\) are chosen uniformly first. Existing consumers do not compare exponents from different resolutions.

The generic cancelling-product derivative recurrence only uses first derivatives of \(\Psi\) after residue reduction, because its error terms have a factor \(\kappa^{-1}\) in the maximal ideal. Repeated multiplicities \(j_\tau\) therefore do **not** force repeated differentiation of finite jets. For the selected degree \(p^e\) gradient term, work in degree \(p^e+1\) before taking one derivative.

The unit condition on \(W\) in sharpness also survives directly: Sharpness/Couplings.lean:455, CMLattice.isUnit_of_rescale_thetaProd_eq, already accepts an arbitrary exponent with zero constant term and proves \(W(0)=1\) from the normalized theta product. No unit claim about the extra factor in the more general divisibility input is needed.

## Scalar transport: preserve the useful contracts

For an integral scalar \(\alpha\), replace \(W(z),\Psi(z)\) by \(W(\alpha z),\Psi(\alpha z)\). Null moments are multiplied by \(\alpha^{p^e+1}\), so null-substitution integrality survives even when \(\alpha\) is a nonunit. Gradient units survive when \(\alpha\) is a unit, as required in sharpness.

If \(\varpi'=\alpha\varpi\) has the same norm, take \(\alpha\) a unit and
\[
c'=\alpha^{p+1}c,\qquad
\Psi'(z)=\alpha^{-(p+1)}\Psi(\alpha z).
\]
Then the degree-\(p^e\) gradient coefficient is multiplied by \(\alpha^{p^e-p}\), still a unit.

Do **not** unnecessarily demand that the resolvent, normalized by division by \(\alpha\), retain the identical equation. If \(Y-Y^q=L\), then \(Y(\alpha z)/\alpha\) satisfies a twisted equation with coefficient \(\alpha^{q-1}\). The consumer certificates transport directly, so this introduces no extra proof obligation. Alternatively, retain \(Y(\alpha z)\) and the scaled linear form \(\alpha L(z)\) without normalizing \(Y\).

## Implementation boundaries and success criterion

A sensible port has three small phases:

1. Add the finite Frobenius pairing/resolvent core and prove the raw one-curve certificate using the existing integral parameter and raw exponent lemmas.
2. Expose finite null-substitution integrality and selected lowest-gradient terms; migrate both existing consumers, including nonunit versus unit rescaling.
3. Remove the now-unreferenced double-series machinery, build the project, and report the actual diff and build diagnostics.

There is no need to introduce a broad finite-jet framework if the existing power-series order and coefficient API can express truncation more economically. The mathematical quotient argument is a proof specification; a Lean implementation may use order inequalities and coefficientwise finite precision.

Success requires the same coefficient bounds, factorial losses, local sharpness rate, and final arithmetic main term. A shorter-looking exponent formula alone would not be enough. The proposed core is sufficient for those invariants, and the source audit locates all remaining integration obligations.
